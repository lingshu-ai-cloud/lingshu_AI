# 数字人三语成片授权与本地渲染恢复

## 目标

中、英、西三条成片必须作为一个批次授权：服务端先完整验证三份冻结 `RenderSpec`，然后一次性预留 3 次渲染额度。任何一种语言或证据不合法，都不会部分扣额度或部分创建任务。

## 授权合同

`POST /api/overseas/studio/render/authorizations/trilingual`

```json
{
  "batchKey": "p1-render:<stable-sha256>",
  "sourceProjectId": "studio-project-id",
  "renders": [
    { "language": "zh", "spec": {} },
    { "language": "en", "spec": {} },
    { "language": "es", "spec": {} }
  ]
}
```

服务端严格要求：

- 数量恰好为 3，语言恰好为 `zh/en/es` 且不重复。
- 三条均绑定同一个租户自有 `sourceProjectId`，比例和总时长相同。
- 每个数字人片段都由服务端重新核对 Worker 完成任务，包括人物、语言、所属项目、动作配方、手势、输入签名和输出 SHA256。
- `batchKey` 幂等：请求丢失后使用相同 key 和相同输入重试，不重复扣额度；相同 key 但输入变化时返回冲突。

## 持久化证据

授权后会同时写入：

- `render-authorizations.json`：冻结 manifest、manifest SHA256、租户和授权过期时间。
- `studio-render-jobs.json`：冻结 manifest、源项目、语言、batch key/fingerprint、数字人时间轴证据、最终输出 SHA256 和质检报告。

这两个文件必须放在服务器持久化数据卷中。服务重启后，尚未过期的短令牌仍会以持久化快照验真；已过期时，用原 `batchKey` 重新授权可换取新令牌，不再扣额度。

## 本地渲染与恢复

`/render/local` 使用带 `startedAt/leaseId/leaseUntil/attemptCount` 的渲染租约。有效租约会拒绝重复执行；过期租约可被新尝试接管。每次尝试在独立 `.attempts/<job>/<lease>` 目录中合成和质检，只有当前租约持有者才能将合格文件移入最终路径，旧进程无法覆盖新结果。

## 安全执行命令

编排器只生成授权回执，不执行渲染。授权回执与结果回执均必须位于仓库外：

```powershell
npm run consume:digital-human-render-batch -- `
  --authorization D:\secure\render-authorizations.jsonl `
  --output D:\secure\render-results.jsonl `
  --apply --confirm-render-execution
```

消费器在第一次 HTTP 请求前会一次性校验 exactly-3、语言唯一、项目一致和令牌未过期，然后按 `zh/en/es` 顺序调用本地渲染。短令牌只存在输入回执中，不写入结果 JSONL，不打印到终端。

## 环境变量

```dotenv
RENDER_AUTHORIZATIONS_FILE=/app/data/render-authorizations.json
STUDIO_RENDER_JOBS_FILE=/app/data/studio-render-jobs.json
STUDIO_RENDER_LEASE_MINUTES=45
STUDIO_RENDER_BATCH_TOKEN_TTL_SECONDS=3600
```

`STUDIO_RENDER_BATCH_TOKEN_TTL_SECONDS` 默认 3600 秒（限制在 15 分钟至 4 小时），同批资产签名使用相同 TTL，避免顺序渲染到第二、三种语言时资产已过期。
