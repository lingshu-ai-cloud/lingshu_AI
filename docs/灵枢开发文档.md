## 3. Agent 职责与整体交接流程

核心为经营 Agent、编导 Agent、内容 Agent。采集、分析、媒体检测、发布与指标 Worker 执行具体工作。Apify Actor 是采集工具，不是另一个数字员工；定时任务也不承担内容方向决策。

```mermaid
flowchart TD
    A[企业事实、产品、目标市场] --> B[经营 Agent：目标、账号、计划、预算]
    B --> C[编导 Agent：发现计划 DiscoveryBrief]
    C --> D[调度器与 Apify：采集]
    D --> E[分析能力：候选证据与分析等级]
    E --> F[灵感交接包 InspirationHandoff]
    F --> G[编导 Agent：参考分析、爆点规格、DirectorBrief]
    G --> H[内容 Agent：ContentExecutionPlan]
    H --> I{编导审核执行方案}
    I -->|退回并说明原因| H
    I -->|通过| J[内容 Agent：逐镜制作、技术质检]
    J --> K[独立媒体评估 Worker]
    K --> L{编导最终表达验收}
    L -->|局部返工| H
    L -->|通过| M[用户验收与授权发布]
    M --> N[平台回执、指标回收]
    N --> B
    N --> C
```

### 3.1 各角色的决定权

| 角色 | 负责决定或产出 | 不应越权决定 |
| --- | --- | --- |
| 经营 Agent | 为什么做、做多少、目标产品与受众、账号平台、CTA、预算、节奏、成功标准 | 具体镜头、素材片段、模型与供应商 |
| 编导 Agent | 发现方向、参考选择、爆点因素与置信度、钩子、叙事、逐镜效果、事实边界、验收标准和最终表达放行 | 擅自改变经营目标，提前锁死具体素材或技术路线 |
| 内容 Agent | 候选素材、片段、模型、供应商、数字人、配音、字幕、剪辑、渲染、技术质检与修复 | 改写事实、叙事与关键验收标准，自行批准最终创意质量 |
| 采集与分析能力 | 按范围采集、保存来源与费用、输出分析证据与缺失项 | 自行扩大市场、预算、授权范围或决定生产采用 |
| 媒体评估 Worker | 按冻结规格检测并记录证据、失败项和风险 | 修改导演目标、放宽权重或自行发布 |
| 平台与指标 Worker | 发布执行、真实回执、账号基线和指标快照 | 将相关性认定为因果，擅自更改账号策略 |

核心边界：编导定义“要达到什么效果”，内容 Agent 决定“具体怎么做”。

### 3.2 每一步传递什么

| 交接 | 正式交付内容 | 接收方动作与门槛 |
| --- | --- | --- |
| 经营 → 编导 | 目标、事实来源、账号、受众、CTA、预算、截止时间、成功标准；`WeeklyContentPackage` 或 `AdHocBusinessContext` | 决定表达与参考方向，不擅自改变经营目标 |
| 编导 → 采集执行器 | `DiscoveryBrief`：平台、词簇、账号、时间范围、数量、费用和停止条件 | 先查库存，必要时按批准范围补采；任务临时扩词不得静默写回长期策略 |
| 采集／分析 → 编导 | `CollectionRunResult`、`CandidateEvidence`、来源、费用、分析版本、缺失项与权利边界 | 分别判断相关性、平台内表现、可迁移性，选择参考 |
| 灵感中心 → 编导 | `InspirationHandoff`：为何选、可借鉴内容、必须替换内容、证据、风险与就绪等级 | 根据等级用于选题、结构参考或逐镜设计 |
| 编导 → 内容 | `DirectorBrief`；裂变任务另附 `ReferenceAnalysis` 与 `ReplicationFactorSpec` | 选择具体素材、时间片段、模型、供应商、成本与备选路线 |
| 内容 → 编导 | `ContentExecutionPlan`：逐镜候选、成本、耗时、可行性、权利、来源与 fallback | 生成 `ExecutionPlanReview`；明确失败条件、原因码、修改要求及目标影响 |
| 审核通过 → 内容执行 | 已锁定的导演与执行方案版本 | 制作、技术质检；失败按受影响镜头修复，往返受预算、次数和期限限制 |
| 制作／评估 → 编导 | `ProductionResult`、技术质检、独立 `ReplicationEvaluation` 及原始证据 | 最终表达验收，通过或局部退回；不能用生成模型自评替代独立检测 |
| 用户验收 → 发布执行 | 已验收成片、发布包、目标账号及独立发布授权 | 按权限审批执行，保存真实平台回执；确认制作计划不等于授权发布 |
| 发布／指标 → 经营与编导 | 自有账号表现、发布时间与指标范围、采用／放弃反馈 | 调整计划、来源优先级和因素证据；外部高播放不等于自有业务效果 |

### 3.3 交接对象应如何关联

目标方案要求通过可保存、可追溯的结构化对象交接，不只传聊天记录或脚本文字。

- 绑定同一经营项目、目标账号、内容任务和版本引用。
- 下游明确引用上游版本，审核结果对应具体执行方案版本。
- 企业事实、参考视频、分析、素材与成片保留来源关系。
- 参考或导演方案变更产生新版本，按影响范围使下游结果失效或重做。
- 单视频高保真任务冻结唯一主参考；其他参考只能补充约定角色。
- 新任务以统一对象为主数据，旧任务只读适配，是需求目标；当前尚不能认定此迁移全部完成。

### 3.4 灵感的三级生产门槛

| 等级 | 使用范围 | 不能据此承诺 |
| --- | --- | --- |
| `discovery_reference` | 选题探索、继续查找参考 | 已能生成可靠逐镜方案 |
| `strategy_reference` | 钩子、结构、证明顺序、节奏与 CTA 参考 | 已具备完整精确镜头证据 |
| `production_reference` | 连续逐镜分析足够完整，辅助精确分镜设计 | 自动获得原素材下载、改编或发布权利 |

关键时间线缺失、来源失效、权利不明或关键观察证据不足时，不应作为生产级参考。事实和身份元素仍须替换为已确认的企业信息。

### 3.5 DirectorBrief 的逐镜内容

每镜至少应包含：叙事作用、目标视觉、必须证据、动作开始／路径／结束状态、景别与机位、空间连续性、声音层、时间范围、真实性与权利边界、允许变化、引用的爆点规格、可观察的验收条件。

具体 `assetId`、素材片段、模型、供应商、提示词、重试策略由内容 Agent 的执行计划管理。不能以“高级感”“爆款感”等抽象描述独立充当验收条件。

## 5. 四个关键断点及代码依据

### 5.1 保存发现范围与实际采集口径尚未统一

发现范围保存于独立集合；关键词采集函数仍调用 `resolveCrawlStrategy`，从企业资料与任务关键词重建策略。页面确认范围与执行口径存在不一致风险。

依据：[发现范围存储](../server/routes/socialDiscovery.ts)、[采集调度 executeVideoKeywordCrawl](../server/routes/scheduler.ts)。

### 5.2 Agent 对象展示不等于独立、持久化的交接

`buildSocialAgentWorkflow` 一次构建发现计划、导演方案、执行计划和审核结果；任务读取时从旧任务、参考分析和素材计划生成这些对象。执行计划主要由已有 `AssetSupplyPlan` 转换。

已有结构与规则不等于完成“各方独立保存版本 → 退回修改 → 锁定执行”。

依据：[工作流构建](../server/starter198/socialContentAgentWorkflow.ts)、[任务读取适配](../server/starter198/socialContentRecords.ts)。

### 5.3 新经营主链尚未完整连接原生产主链

新服务可以保存月周计划，但周计划编辑器尚未完成。当前主要生产读取路径未显式传入完整新经营上下文；账号、Playbook、周任务与成片的版本关系仍需贯通。

依据：[计划页面](../src/components/socialProgram/SocialPlanningPage.tsx)、[经营项目服务](../server/socialPrograms/service.ts)。

### 5.4 评估框架已能识别缺证据，检测证据的生产链尚未齐备

评估器主要消费检测结果。当前生产调用仅显式传入输出文案，未提供完整因素检测、身份替换和复用风险证据。最终创意审核主要检查方案通过、镜头存在、验收条件存在，不能等同于独立编导逐镜查看成片。

准确状态：已建立评估与拦截框架，尚未完成 PRD 所述独立成片检测与表达验收。

依据：[生产评估调用](../server/starter198/socialContentAutoProduction.ts)、[评估适配器](../server/starter198/replicationEvaluationAdapter.ts)、[证据评估器](../server/lib/replicationEvaluation.ts)。

## 6. 待讨论的整合建议

以下来自本次分析，尚不标记为用户已确认的产品决策。

1. **按参考模式确定保真范围。** 采集策略偏向迁移钩子、结构和节奏；新版 PRD 扩展至动作、环境、物体状态等有证据的保真。建议普通灵感迁移结构，单视频高保真冻结逐镜因素，避免所有参考采用同一标准。
2. **按自动化模式决定采用权限。** 建议模式由用户选择；协作模式保留关键确认；托管模式在批准范围内自动采用。统一文档中“默认自动选择”与模式差异的关系。
3. **优先验证一个完整经营任务。** 从周任务读取已保存范围，召回一条参考，完成版本化交接、制作、独立检测、验收与结果回流，再扩大多平台和账号自动积累。尚未据此启动实施或付费实测。

## 11. 经营 Agent 与编导 Agent 技术栈、决策路径核查（2026-09-25）

### 11.1 结论

两个 Agent 的**产品职责、数据对象和理想决策顺序基本清楚**，但还不能说“所有技术栈和决策路径都已清晰并跑通”。

- 经营 Agent：领域对象和阶段门槛清楚，真正的诊断、策略生成、计划生成和结果复盘引擎不清楚，当前更接近版本化经营配置与状态机。
- 编导 Agent：输入输出契约、逐镜字段、参考门槛、审核规则和责任边界较清楚，是内容 Agent 之前最成熟的一层；但自主发现、候选选择、创作推理、独立版本存储及最终成片表达判断仍未完整落地。
- 当前 `buildSocialAgentWorkflow` 会在一次函数调用中同时派生经营上下文、发现计划、导演方案、内容执行计划和编导审核。它能证明契约可组装，不能证明三个 Agent 已经各自独立运行、持久化交接并完成自动往返。

### 11.2 经营 Agent

#### 已清楚的部分

经营 Agent 的主路径已被定义为：

```text
企业与产品事实
  → 选择从零搭建或账号修复
  → 对标研究／账号诊断
  → 确认获客入口与 CTA
  → 建立 AccountPlaybook
  → 激活月计划
  → 生成并激活周计划
  → 形成 WeeklyContentPackage 或 AdHocBusinessContext
  → 交给编导 Agent
  → 回收发布结果并进入复盘
```

当前已有：

- `SocialProgram` 阶段状态机与 readiness 门槛；
- `OwnedSocialAccount`、版本化 `AccountPlaybook`、获客路径和 CTA；
- `SocialMonthlyPlan`、`SocialWeeklyPlan`、预算、成功标准和版本引用；
- 周任务与即时任务的经营上下文契约；
- 服务端并发版本校验和计划激活门槛。

#### 尚不清楚或未接通的部分

1. **没有明确的经营决策引擎。** 代码能保存用户输入和检查必填项，但没有完整实现“账号诊断 → 对标差距 → 栏目组合 → 数量与预算分配 → 月计划 → 周任务”的可解释决策器。
2. **阶段 readiness 可被输入更新，但证据生成链不足。** `diagnosisComplete`、`benchmarkRoundComplete`、`conversionRouteConfirmed` 等状态有定义，尚需规定由哪个 Worker／Agent 根据什么证据推进，哪些必须人工确认。
3. **周计划生成器和前端尚未完成。** 服务端可以保存周计划，页面明确说明周计划编辑器仍在后续里程碑；未看到活动周计划自动创建统一社媒生产任务的完整桥接。
4. **成功标准没有计算口径。** 当前 `successCriteria` 和 `metricTargets` 多为文字；需要指标名称、来源、时间窗、基线、目标值、归因限制和异常处理。
5. **复盘闭环未形成决策。** 发布与指标对象存在，但未看到它们稳定更新 AccountPlaybook、内容组合、实验变量、预算分配和下一周计划。
6. **“技术栈”缺少显式编排层。** 尚未明确经营 Agent 使用哪个模型、哪些确定性规则、哪些检索工具、如何记录推理依据、如何评估建议质量和防止无证据策略漂移。

因此经营 Agent 的准确状态是：**经营领域模型和流程骨架清楚，智能决策技术栈与闭环尚未定型。**

### 11.3 编导 Agent

#### 已清楚的部分

编导 Agent 的理想决策路径已较完整：

```text
接收经营目标与事实边界
  → 形成 DiscoveryBrief
  → 优先检索库存，不足时任务级补采
  → 比较 CandidateEvidence
  → 生成 InspirationHandoff
  → 检查参考就绪等级与权利边界
  → 形成 ReferenceAnalysis
  → 裂变任务冻结 ReplicationFactorSpec
  → 生成逐镜 DirectorBrief
  → 审核 ContentExecutionPlan
  → 读取独立媒体检测证据
  → 最终表达放行或局部返工
```

当前已有：

- `DiscoveryBrief`、`CandidateEvidence`、`InspirationHandoff`；
- L1／L2／L3 与三级参考就绪门槛；
- 参考时间线、镜头观察、权利与迁移边界；
- `ReplicationJob`、`TimelineBeat`、`ReplicationFactorSpec`；
- 逐镜 `DirectorBrief` 的目标、动作、连续性、声音、事实边界、允许变化和验收条件；
- `ExecutionPlanReview` 的逐镜失败原因、修改要求、预算／事实／权利阻断；
- `ReplicationEvaluation` 的独立评估契约和不允许内容 Agent 自我放行的责任边界。

#### 12.25.1 Agent 信息传递与工作交接

当前主链按结构化业务对象交接，不依靠下一个 Agent 重新阅读整段对话：

1. **灵感中心／素材入口 → 内容 Agent**：传递租户、来源素材、参考视频分析、业务目标、产品与客户信息、使用授权和来源版本。外部爆款素材只可作为结构与表达参考；客户素材和企业素材按各自权利范围进入后续生产。
2. **内容 Agent → 编导 Agent**：内容 Agent 形成已确认事实、内容目标和口播草稿；编导 Agent 将其拆成逐镜方案，写明镜头类型、口播、时长、人物或非人物、所需素材及验收要求。事实证据不足时必须停在确认门禁，不能由后续 Agent 猜测补全。
3. **编导 Agent → 分镜制作工作台**：以项目、装配版本和分镜 ID 为索引传递人物镜头分类、构图簇、源首帧、人物资产版本、授权范围、保留约束和预算。人物缺失时在当前分镜补齐，保存后写入企业人物库并自动回填原分镜。
4. **分镜工作台 → 生成适配层**：人物镜头按“可选千问构图草稿 → Seedream 正式首帧 → Seedance 逐句视频”执行；非人物镜头选择企业素材并进入本地裁切／拼接。所有外部调用先经过 readiness、授权、预算、幂等和可访问地址检查。
5. **生成适配层 → 质检与返工**：每个镜头保存供应商、模型、请求 ID、输入版本、对象版本、估算费用、产物和检测证据。技术检测、可选独立语义检测和人工逐项验收共同形成 `failedCueIds`；缺少独立证据的项目保持待验收。
6. **质检 → 装配与成片**：仅将已确认候选写回分镜装配。局部返工只重新生成失败人物镜头，其余镜头必须有通过证据和可读取素材才能复用，最后由本地 FFmpeg 完成混合拼接。

交接中的共同主键为 `tenantId → projectId → assemblyId → shotId/cueId`。人物、素材、授权、生成回执和质检证据分别版本化；任何 Agent 都不能用自然语言结论覆盖这些权威记录。

| `IMG_2090` 人物 | 已清洗并本地入库，人物准入状态可追踪 | 仍缺可留档的主体同意凭证，且图片资产尚未取得 Active `asset://`，禁止真实外发 |

| HeyGen | 数字人口播桥接、预算／授权／幂等／入库约束已实现 | 缺本项目内可复核的真实人物任务、下载产物和整链验收证据 |
| Runway Act-Two | 规划、能力检查和 Provider readiness 已保留 | 真实生成凭据、启用配置、成本参数和真实任务验收未完成，当前不能标记可生产 |

#### 12.25.4 仍需实施与验收

按依赖顺序继续：

1. **修复内容任务的事实确认闭环**：把用户输入的产品、客户和业务信息显示为可逐项确认的事实，或在“缺少最少必要事实”阻断卡片内提供原位补齐操作。当前真实点击已证明内容 Agent 和编导 Agent 能生成 4 个分镜，但新任务会在此门禁停住，因此尚未完成从内容草稿到 Studio 的真实页面全链。
2. **补齐人物外部前置条件**：取得 `IMG_2090` 对应真人的可留档同意凭证，在同一方舟账号完成首次认证并取得 Active 图片型 `asset://`。这是人物数据外发和真实付费验收的硬条件。
3. **完成浏览器文件上传验收**：使用支持原生文件选择器的浏览器自动化或人工测试，从真实任务进入当前分镜，上传人物图、保存、刷新并确认自动回填。现有自动化只验证到表单与方舟控件，最终原生文件选择尚未实点。
4. **执行单条视频受控联合验收**：冻结参考片、人物、2–3 个首帧构图、费用上限和验收项后，真实执行 Seedream → Seedance → 下载 → Local／COS 入库 → 逐镜质检 → 局部返工 → FFmpeg 成片，并回写实际费用与失败记录。该步骤会外发真人数据并产生费用，必须在授权和付费窗口满足后执行。
5. **增强口型自动检测**：接入音素级口型／发音同步检测；在此之前，音画结构检查不能替代口型语义结论，相关项目继续人工验收。
6. **生产迁移准备**：部署前配置并验收腾讯云 COS、HTTPS 访问、密钥托管、回调和监控；生产部署需用户在对应任务中另行明确授权。
7. **按业务优先级验收备用供应商**：若仍需 HeyGen 或 Runway，分别完成单镜头真实任务、产物下载、对象入库、费用和质检闭环；未完成前不得在产品上宣称生产可用。

当前总体判断：**核心代码链已达到可进行受控单条联合验收的阶段，但尚未达到全量生产闭环标准**。主要阻断集中在上游事实确认体验、真人同意与方舟 Active 图片资产、真实页面文件上传验收和付费联合验收，而不是基础路由、存储抽象、幂等、预算或局部返工代码。

## 13. 《灵感大屏行业采集与编导交接策略》对经营与编导开发的指导（2026-09-26，待讨论）

本节记录继续讨论的分析，不把原文中的产品建议自动视为已确认开发指令。

### 13.1 总判断

该文档对编导 Agent 提供了较完整的“发现与参考决策协议”，对经营 Agent 提供了重要的事实、市场、角色和反馈输入，但没有完整覆盖账号经营诊断、Playbook、月周计划和预算分配。因此可作为编导 Agent 的核心设计输入，也可作为经营 Agent 的“市场发现子域”输入，不能单独充当经营 Agent 全部规格。

### 13.2 建议的权责切分

| 决策 | 经营 Agent | 编导 Agent |
| --- | --- | --- |
| 企业角色、目标市场、目标受众、账号与产品优先级 | 负责并冻结 | 读取，不擅自修改 |
| 经营目标、CTA、预算、内容数量、成功标准 | 负责并冻结 | 在边界内制定表达方案 |
| 长期发现范围是否启用、预算上限与平台范围 | 负责批准 | 根据生产缺口提出范围建议 |
| 任务级发现需求 | 提供业务目标和限制 | 负责生成 `DiscoveryBrief` |
| 采集执行 | 不直接执行 | 不直接执行；交给调度器／Apify |
| 候选内容与账号是否值得研究 | 提供账号经营适配条件 | 根据证据作出采用、试采、跟踪或停止建议 |
| 参考如何进入创作 | 不决定镜头 | 负责 `InspirationHandoff`、参考角色和 `DirectorBrief` |
| 具体素材、模型与供应商 | 不负责 | 不提前锁死；交给内容 Agent |
| 发布后经营结果 | 负责解释业务目标是否改善 | 只更新参考与表达因素证据，不把相关性直接写成因果 |

### 13.3 经营 Agent 可直接吸收的设计

1. 用“企业角色 × 沟通对象 × 目标市场 × 搜索意图”代替写死行业模板。
2. 企业事实、客户原话、竞品差距和模型扩展词分别保存来源；模型只能改写或扩展，不能发明企业事实。
3. 长期发现范围使用版本化 `MarketKeywordSet`，任务级临时补采不得静默污染长期策略。
4. 经营 Agent 批准平台、市场、预算、账号范围和自动化等级，编导 Agent在批准范围内执行发现决策。
5. 外部内容高表现只提高研究优先级；只有企业自己的发布结果和人工采用反馈，才能验证是否适合该企业。
6. 反馈漏斗应保存“采集 → 有效候选 → 打开／收藏 → 加入任务 → 编导采用 → 成片 → 自有表现”，而不是用播放量直接强化采集策略。

文档没有解决的经营 Agent 内容仍需另行设计：账号诊断、AccountPlaybook 生成、月目标拆解、周任务组合、资源与预算分配、指标基线和复盘决策。

### 13.4 编导 Agent 可直接吸收的决策链

```text
读取 BusinessContentGoal 与已批准发现范围
  → 检索现有灵感库存
  → 判断库存是否满足任务缺口
  → 必要时生成任务级 DiscoveryBrief
  → 调度器执行采集并返回 CollectionRunResult
  → 分析能力生成 CandidateEvidence
  → 编导进行候选排序与参考角色分配
  → 生成 InspirationHandoff
  → 按就绪等级决定只能发散、可借结构或可做逐镜参考
  → 结合企业事实生成 DirectorBrief
  → 内容 Agent 生成 ContentExecutionPlan
  → 编导按验收条件审核、退回或放行
```

需要保持的硬边界：

- 灵感中心只生成 `InspirationHandoff`，不生成 `DirectorBrief`。
- `discovery_reference`、`strategy_reference`、`production_reference` 具有不同使用权限。
- 多条参考必须标记唯一用途；同一角色默认只有一个主参考。
- 外部视频默认 `reference_only`，采集成功不代表获得下载、商用或二创权。
- 编导只能迁移结构、镜头作用、证明顺序和表达方式，不能迁移对方的产品事实。
- 编导输出目标、证据和验收条件，不选择具体 `assetId`、模型或供应商。

### 13.5 编导 Agent 建议拆成的内部能力

用户仍只看到一个编导 Agent，内部可拆成可审计步骤：

1. `DiscoveryPlanner`：把经营目标转换为库存查询和 `DiscoveryBrief`。
2. `CandidateRanker`：分别计算相关性、平台内表现、可迁移性、证据、权利、重复和成本，不先压成一个不可解释总分。
3. `ReferenceSelector`：选择少量主参考并标记 `primary_structure`、`proof_reference`、`visual_rhythm`、`cta_reference`。
4. `ReadinessGate`：执行三级参考准入与分析升级。
5. `ReferenceInterpreter`：形成可观察事实、模型推断、迁移边界和证据引用。
6. `DirectorBriefBuilder`：先生成视频层方案，再生成逐镜目标和验收条件。
7. `ExecutionPlanReviewer`：审核内容 Agent 的候选、事实、权利、预算和因素承接。
8. `FinalExpressionReviewer`：结合独立检测证据和人工复核决定放行或局部返工。

### 13.6 首期开发建议（待确认）

先围绕一类真实经营关系跑通纵向切片，例如“工厂 → 海外品牌采购”：

1. 经营 Agent 冻结产品、市场、采购受众、账号、CTA、预算和成功标准。
2. 建立一个版本化 `MarketKeywordSet`，只包含少量真实产品事实、客户问题和用户确认竞品。
3. 编导 Agent 查询库存，不足时提交一个有数量、时间和费用上限的 `DiscoveryBrief`。
4. L0／L1 生成候选；只将少量候选升级到 L2／L3。
5. `CandidateEvidence → InspirationHandoff → DirectorBrief` 分别持久化并保留版本引用。
6. 内容 Agent 生产一条视频，编导完成执行方案审核和最终表达验收。
7. 保存采用、放弃原因和自有发布结果，再决定是否调整词簇或跟踪账号。

这个切片能够同时验证经营 Agent 的边界、编导 Agent 的自主决策、Agent 间持久化交接和反馈闭环。账号自动晋级、评论 Actor、多平台扩张和大规模深度分析应在该切片通过后逐步增加。

### 13.7 建议确认的功能清单

经营 Agent：

1. 经营画像：企业角色、产品、市场、语言和目标受众。
2. 账号策略：账号定位、受众承诺、栏目、证据规则与获客入口。
3. 指标契约：CTA、基线、目标值、时间窗与最小样本量。
4. 资源约束：月周预算、内容数量、账号分配和截止时间。
5. 长期发现边界：市场、平台、竞品、`MarketKeywordSet` 与成本上限。
6. 自动化权限：建议、协作、托管模式的行为边界。
7. 月周计划分解：月目标如何生成版本化周任务。
8. 经营复盘：哪些自有结果可以更新 Playbook、预算和下一周计划。

编导 Agent：

1. 库存优先，只有出现任务生产缺口时才发起有限补采。
2. 候选证据按相关性、表现、迁移性、权利、重复和成本分开判断。
3. 多参考角色及同角色唯一主参考规则。
4. `discovery_reference`、`strategy_reference`、`production_reference` 的使用权限。
5. 可借鉴、必须替换和禁止复用的迁移边界。
6. `DirectorBrief` 的逐镜必填字段与完成门槛。
7. `ContentExecutionPlan` 的事实、权利、预算、能力和因素承接审核。
8. 最终表达放行必须使用独立证据，并支持失败镜头局部返工。

### 13.8 三份文档的矛盾与统一结论

对照范围：本文档、PRD v3.5、《灵感大屏行业采集与编导交接策略 v1》。发现两处实质口径冲突、两处需补充定义，其余核心方向兼容。

| 主题 | 差异 | 统一建议 |
| --- | --- | --- |
| Agent 全局顺序 | 本文档数字人子流程曾写“内容 Agent 形成草稿 → 编导拆镜”；PRD 和交接策略的责任顺序是“经营 → 编导 → 内容” | 全局采用“经营 → 编导 → 内容”；Studio 前置草稿改名为内容需求／脚本草稿能力，不能覆盖 DirectorBrief |
| 参考复用深度 | 交接策略强调复用钩子、顺序、证明和节奏；PRD 的单视频高保真还冻结动作、环境、物体状态、光线、构图和音画关系 | 只保留两种模式：普通灵感迁移结构，`single_source_fidelity` 冻结逐镜因素；不建设账号形式系列模式 |
| 自动选择权限 | 交接策略一处写默认自动选择少量主参考，另一处区分建议／协作／托管模式 | 以自动化模式为最终权限来源；只有托管模式可在已批准范围内自动采用 |
| 发现范围所有权 | 交接策略写编导制定发现范围与采集计划；经营 Agent 又应控制市场、账号、预算和长期策略 | 经营 Agent 批准长期边界和预算；编导 Agent 生成具体建议与任务级 `DiscoveryBrief` |
| 灵感中心边界 | 三份文档均把灵感中心定位为发现、分析和交接，不负责正式脚本和分镜 | 保持 `InspirationHandoff` 为边界 |
| 爆款公式 | PRD 明确删除公式；交接策略使用单条证据和可迁移机制 | 新链禁止写入公式对象，历史公式只读适配 |
| 权利和事实 | 三份文档均要求来源事实、模型推断和授权状态分开 | 继续使用证据、置信度、权利状态和版本引用 |

上述统一建议已于 2026-09-26 获用户确认。Agent 全局顺序是现有 PRD 的权责基线，后续代码和页面命名应避免再次产生反向理解。

### 13.9 已确认的上游决策规则（2026-09-26）

#### 参考模式只保留两种

1. **普通灵感**：可组合多条灵感，但每条必须标记用途。只迁移选题角度、钩子类型、信息顺序、证明位置、节奏、情绪推进和 CTA 位置；产品、人物、品牌、台词、案例、参数、认证和独特表达必须替换。普通灵感不要求逐镜高保真。
2. **单视频高保真**（`single_source_fidelity`）：必须冻结唯一主参考。编导 Agent 基于证据形成逐镜 `ReplicationFactorSpec`，明确锁定、功能等价、有限变化、身份替换和禁止复用因素，再由独立检测与编导验收共同放行。

不再保留或新建“账号形式系列”（`account_format_series`）参考模式。账号研究仍可用于经营诊断、账号 Playbook 和普通灵感召回，但不作为单独的生产参考模式。现有代码和历史数据中的该枚举值后续需要制定兼容迁移策略，不能直接破坏旧任务读取。

#### 三类上游选择由经营目标与预算共同决定

经营 Agent 拥有长期发现范围的最终批准权，并根据经营目标、预算和当前证据共同决定：

- 长期发现范围：市场、语言、平台、产品、受众、竞品账号、场景簇、采集频率和成本上限；
- 自动化模式：建议、协作或托管；
- 参考深度：普通灵感或单视频高保真。

建议采用以下决策顺序：

```text
经营目标与成功标准
  → 账号与受众适配
  → 可用预算、期限与内容数量
  → 企业事实、素材和权利完备度
  → 当前灵感库存与参考证据等级
  → 自动化模式 + 参考模式 + 发现范围
```

经营 Agent 的决定不是只由金额阈值触发。目标要求高还原、存在唯一参考且预算和证据足够时，才可选择单视频高保真；需要持续供给、多样化选题或预算较低时，优先普通灵感。事实、权利或素材不足时，即使预算充足也不得选择不可兑现的高保真承诺。

#### 三种自动化模式的确认权限

| 模式 | 经营 Agent／系统可自动完成 | 用户保留的决定 |
| --- | --- | --- |
| 建议 | 生成长期发现范围、自动化和参考模式建议，展示成本与理由 | 确认发现范围、启动采集、选择参考及生产 |
| 协作 | 在已确认范围和预算内自动采集、分析、试采账号并推荐参考 | 确认长期账号晋级／停用、主参考采用、越界预算与重要生产变更 |
| 托管 | 在已批准目标、市场、平台、预算和权利范围内自动采集、选择少量参考并推进生产 | 处理事实不足、权利不明、成本超限、目标实质降级和最终发布授权 |

用户手动添加、固定、移除或屏蔽的关键词、账号和参考优先级最高。新增平台、改变市场／受众、扩大预算、使用未确认竞品或改变权利边界，任何模式都必须形成可见变更；用户确认制作计划不等于授权发布。

#### 经营 Agent 与编导 Agent 的交接

经营 Agent 输出版本化 `BusinessContentGoal`（或对应的周／即时上下文），至少包含经营目标、目标账号、产品、受众、市场、CTA、预算、期限、成功标准、批准的发现范围、自动化模式和参考模式。

编导 Agent 只能在这些边界内：

- 查询灵感库存；
- 提出词簇、账号和任务级补采建议；
- 生成 `DiscoveryBrief`；
- 选择参考并生成 `InspirationHandoff`、`ReplicationFactorSpec` 和 `DirectorBrief`；
- 因证据不足、预算不足或权利不足，将任务退回经营 Agent 重新决策。

编导 Agent 不得静默扩大长期范围、预算或自动化权限。任务级补采结果也不能自动写回长期 `MarketKeywordSet`，必须经过经营 Agent 的下一次策略判断。

## 14. 每日爆款裂变与数据追踪经营流水线（2026-09-26，讨论稿）

### 14.1 当前设想

经营 Agent 每日形成约 15 条有效爆款参考，15 条全部在当天完成分析、裂变／复刻、分发，并进入发布后数据追踪：

```text
爆款采集
  → 爆款逐镜与链路拆解
  → 客户版本裂变／复刻
  → 平台分发
  → 平台回填客户作品跑量数据
  → 爆款链路证据更新
  → 表现好的链路进入下一周内容包／周任务包
```

“15 条”暂按 15 条去重后、满足生产准入的主参考视频和 15 条对应的客户版主成片理解。一个主成片分发到多个平台时，会产生更多 `PublicationTask`；最终需要确认 15 条指主成片数还是所有平台帖子的总数。

### 14.2 Agent 责任分配

| 阶段 | 经营 Agent | 编导 Agent | 内容 Agent／Worker |
| --- | --- | --- | --- |
| 每日任务 | 决定账号、产品、市场、预算、15 条配额、平台矩阵和成功标准 | 读取任务边界 | 不参与经营目标变更 |
| 爆款采集 | 批准长期发现范围与账号池 | 生成每日 `DiscoveryBrief`，筛选候选与参考 | 调度器／Apify 执行采集和基础分析 |
| 爆款拆解 | 提供账号定位、客户事实与转化目标 | 拆解前三秒钩子、叙事链、逐镜作用、证明和 CTA | 视频理解、ASR、OCR、镜头检测提供证据 |
| 客户版复刻 | 约束预算、产量和发布时间 | 形成 `ReplicationFactorSpec` 与 `DirectorBrief` | 选择素材、数字人、生成模型、剪辑和特效并执行 |
| 审核与分发 | 确认发布策略和账号风险边界 | 审核执行方案与最终表达 | 独立检测 Worker、发布 Worker 执行并保存回执 |
| 数据追踪 | 定义账号内基线、时间窗和起量判定 | 解释客户作品中的哪些结构与因素值得继续验证 | 指标 Worker 回收客户作品发布实例的真实平台数据，不追踪原爆款的后续表现，不作因果结论 |
| 周包晋级 | 决定表现良好的链路是否进入下一周内容包／周任务包及其数量和预算 | 更新链路证据、置信度、适用条件和下一轮实验变量 | 只执行被周包引用的新版本，不自行复用旧结构 |

### 14.3 两层拆解对象

#### 镜头层：前三秒钩子及逐镜执行规格

每条参考需要形成可观察的镜头证据：

- 前三秒开始状态、第一视觉主体、信息揭示时点和停留机制；
- 景别、机位、运镜、构图、人物入镜方式和空间关系；
- 口播／对白、字幕、环境声、音乐、音效与画面动作的时间配合；
- 可控动效、转场、速度变化和节奏；
- 产品、人物、工厂、资质与证明镜头分别承担什么作用；
- 必须锁定、功能等价、允许变化、身份替换和禁止复用的因素；
- 对客户版成片可执行的检测方法和验收条件。

#### 链路层：从钩子到 CTA 的爆款叙事链

示例链路：

```text
真人实拍钩子
  → D to C 产品／场景镜头
  → 工厂实拍
  → 产品拍摄与加工能力
  → 工厂资质／证明
  → 真人口播 CTA
```

链路层保存每一段的叙事作用、进入和退出条件、所需证据、适用账号／受众／产品、可替换范围、成本和失败原因。它不能只保存镜头顺序名称，也不能被描述为已经验证的“必爆公式”。

### 14.4 爆款链路沉淀方式

PRD 已删除人工维护的“爆款公式”。因此每次复刻后的链路建议保存为带证据的 `CreativePatternMemory`／`ReplicationPatternEvidence`，而不是无条件复用模板。原爆款视频只保留为参考来源及分析证据；经营反馈只读取客户版作品发布后的真实平台数据：

- `sourceReferenceIds`：来自哪些真实参考及其分析版本；
- `derivedWorkIds`：产生了哪些客户版作品；
- `accountPlaybookRef`：在哪个账号定位下使用；
- `businessContext`：产品、市场、受众、CTA 和发布时间；
- `hookSpec`：前三秒钩子的结构与逐镜因素；
- `narrativeChain`：整条链路的功能节点；
- `publicationRefs`：真实平台帖子与回执；
- `metricSnapshots`：客户版作品在统一时间窗内的账号内相对表现；
- `experimentVariables`：本轮相对上次只改变了什么；
- `evidenceStatus`：观察、候选、重复验证、暂时有效或失效；
- `weeklyPromotionDecision`：不晋级、继续观察、进入下一周内容包、进入下一周周任务包、调整后复测或停止；
- `confidence`、`limitations` 和 `decisionReason`。

同一爆款链路的每次客户版复刻形成新的实验版本，不能覆盖历史结果。只有客户版作品在账号内相对基线、相近发布条件和足够样本下表现良好，才提高证据等级。原爆款后续是否继续起量不参与该链路的经营晋级。单条客户作品起量可以让链路进入下一周包继续验证，但不能证明链路具有稳定因果效果。

### 14.5 三秒钩子素材的复用边界

需要区分“复用钩子结构”和“复用媒体文件”：“前三秒构图、动作、节奏与音画关系”可以作为结构证据复用；外部参考视频的原始三秒媒体默认 `reference_only`，不能直接剪入新作品。

只有以下钩子媒体可以作为后续生产素材复用：

- 客户自有并确认权利的实拍；
- 灵枢为该客户生成、且供应商条款与企业授权允许重复使用的产物；
- 有明确商业授权、用途范围和期限记录的素材；
- 已通过人物、品牌、音乐、文字和平台权利检查的版本。

后续复用仍需绑定素材版本、授权引用和适用账号。原参考的产品、人物、品牌、台词、声音、资质与独特美术资产不能因“已经起量”而自动获得复用权。

### 14.6 客户作品发布数据追踪与周包晋级

追踪主键必须从客户版成片延伸到每一个平台发布实例：

```text
sourceReferenceId（原爆款，仅作参考）
  → replicationJobId
  → productionResultId（客户版主成片）
  → publicationId（账号 × 平台 × 发布时间）
  → metricSnapshotId（平台回填的时间窗数据）
  → patternEvidenceVersion
  → nextWeeklyPackageItemId（若晋级）
```

每个客户作品的发布实例至少在统一时间窗保存真实平台回执和指标快照。建议首期支持 1 小时、6 小时、24 小时、72 小时和 7 天快照，但具体窗口需要按平台能力确认。原爆款参考的公开指标只用于采集与初始研究优先级，不进入客户作品的跑量追踪链。

起量判断不能只用绝对播放量，应优先使用同账号、同平台、相近发布时段和内容类型的相对基线：

- 播放／曝光速度；
- 前三秒或可获得的留存指标；
- 完播率或平均观看时长；
- 有效互动率与互动质量；
- 主页访问、私信、链接点击或经营目标动作；
- 发布状态、限流／审核状态和指标完整性；
- 与账号近期基线相比的提升区间。

指标 Worker 只保存客户作品对应的平台回填数据、时间范围和账号基线计算；经营 Agent 决定链路是否晋级下一周内容包／周任务包及投入多少资源，编导 Agent 决定下一周保留哪些钩子、结构因素和实验变量。多变量同时变化或缺少数据时，结果标记为不可归因，但仍可作为下一周受控复测候选。

下一周包不能只保存“复用这个爆款链路”。每个晋级项至少需要：上一周客户作品与发布实例、跑量证据、适用账号和产品、保留因素、下一轮允许改变的单一或少量变量、目标指标、预算、生产数量和停止条件。

### 14.7 与此前采集方案的变化

此前文档按 300—600 条月有效素材中仅 15%—25% 进入 L2、5%—10% 进入 L3 估算。当前设想要求每天 15 条全部进入复刻与发布，相当于每月约 450 条生产任务都需要接近 L3 的分析与执行，成本和吞吐量不再适用原估算。

上线前必须重新计算：

- 15 条生产级参考需要抓取多少原始候选；
- 每条 L2／L3 分析、素材生成、数字人、渲染和质检成本；
- 当日分析、生产、审核和发布的并发与截止时间；
- 15 条主成片乘以平台矩阵后的实际发布任务数；
- 单账号每日发布容量、内容重复风险和失败回退；
- 人工介入量以及建议／协作／托管模式下能否在当天完成。

因此“每天 15 条全部复刻并发布”应先作为经营目标和容量规划基准，通过小批量真实运行校准，不能沿用原灵感池成本区间直接承诺。

### 14.8 待确认事项

1. 15 条指 15 条客户版主成片，还是跨平台合计 15 条帖子；当前暂按前者记录。
2. 15 条是否分配到多个账号；每个账号、平台每天的目标数量是多少。
3. “当天完成”是自然日还是任务 SLA，例如采集后 24 小时内。
4. 15 条是否全部使用单视频高保真；若是，必须重新定义 L3 分析与预算容量。
5. 每个平台允许自动发布还是需要发布前审批；用户确认制作不等于发布授权。
6. 起量的账号内相对阈值、观测窗口和最低样本量。
7. 客户作品起量后复用的是结构、生成后的客户自有钩子素材，还是两者；外部参考原媒体不得默认复用。
8. 单条客户作品达到什么账号内相对表现可以进入下一周包；扩大复用还需要几次、几个账号或多少样本。
9. “进入下一周内容包”和“进入下一周周任务包”是否为同一对象的不同状态，还是两个独立对象；建议统一为周包内的版本化任务项，避免双轨。

## 15. 经营—编导—内容—发布—复盘全局开发规划（2026-09-26，待确认）

### 15.1 规划原则

本轮不从“每天 15 条采集”“指标回填”或“钩子复用”任一单点直接开发。先建立贯穿经营目标、参考、生产、发布、指标和下一周计划的统一数据主线，再逐层接入 Agent 决策。

每个阶段必须同时满足：

- 输入、输出和上游版本引用明确；
- 决策者、执行者和审核者明确；
- 事实、模型推断、平台回执和人工确认分开保存；
- 同一业务对象使用稳定 ID，新版本不得覆盖历史；
- 预算、权利、租户、幂等和发布授权贯穿全链；
- 缺数据时保存 `unknown`／`not_attributable`，不能补写成功结论；
- 旧链只读兼容，新任务只写统一对象，避免长期双写。

### 15.2 目标全局主线

```text
SocialProgram
  → AccountPlaybookVersion
  → BusinessContentGoal
  → WeeklyPackageVersion
  → DailyReplicationBatch
  → DiscoveryBrief
  → SourceReference + ReferenceAnalysis
  → InspirationHandoff
  → ReplicationJob + ReplicationFactorSpec
  → DirectorBrief
  → ContentExecutionPlan + ExecutionPlanReview
  → ProductionResult
  → PublicationAssignment / PublicationReceipt
  → MetricSnapshot
  → PatternEvidenceVersion
  → WeeklyPromotionDecision
  → NextWeeklyPackageVersion
```

统一关联主键建议为：

```text
tenantId
  → programId
  → accountId + accountPlaybookVersion
  → businessGoalId
  → weeklyPackageId + version
  → batchId
  → taskId
  → replicationJobId
  → productionResultId
  → publicationId
  → metricSnapshotId
  → patternEvidenceId + version
```

所有交接对象必须显式保存直接上游引用，不能只依赖标题、自然语言或时间推测关系。

### 15.3 第一阶段：冻结统一领域合同和口径

目标：先解决“继承什么、交接什么、判断什么”。

开发内容：

1. 统一 `BusinessContentGoal`、`WeeklyPackageVersion` 和 `DailyReplicationBatch`，消除新 `socialPrograms` 与旧 Starter198 周任务的重复语义。
2. 定义两种参考模式：`standard_inspiration` 与 `single_source_fidelity`；历史 `account_format_series` 只读兼容并迁移为普通灵感及账号证据。
3. 定义 `DecisionRecord` 公共字段：决策类型、输入版本、证据引用、规则版本、模型版本、置信度、限制、操作者、时间和替代方案。
4. 定义全链状态机及允许的转换，包括退回、局部失效、重试、暂停和恢复。
5. 定义权利与事实引用协议，禁止外部参考媒体因分析或起量而变成生产素材。
6. 定义事件合同：对象创建、版本锁定、生产完成、发布回执、指标回填、周包晋级。

交付物：共享合同、状态机、事件 schema、迁移映射、契约测试。

验收：使用纯本地夹具可重放一条任务从周包到下一周晋级的所有对象，任何节点都能追溯直接上游及版本。

### 15.4 第二阶段：经营 Agent 决策内核

目标：让经营 Agent 真正决定经营边界，而不只是保存表单。

内部能力：

1. `BusinessGoalBuilder`：将企业事实、账号、产品、市场和目标转成版本化经营目标。
2. `CapacityPlanner`：根据预算、期限、可执行内容能力、账号矩阵和平台发布容量形成每日生产配额。
3. `DiscoveryScopeApprover`：批准长期发现范围、平台、竞品、频率和成本上限。
4. `AutomationPolicyResolver`：选择建议／协作／托管模式，并输出人工门槛。
5. `ReferenceModeResolver`：在普通灵感和单视频高保真之间选择；事实、权利和生产能力不足时失败关闭。
6. `WeeklyPlanner`：将月目标和上一周期结果拆成版本化周包与每日批次。
7. `PromotionAllocator`：根据客户作品跑量证据，把链路加入下一周包并分配数量、预算与实验变量。

规则优先确定性实现；模型只用于生成候选建议和解释，不直接越过预算、权利、事实和发布限制。

验收：相同输入和规则版本产生相同边界；每个选择都能说明经营目标、预算和证据；未知信息会阻断或降级，不自动猜测。

### 15.5 第三阶段：发现与编导 Agent 编排

目标：打通库存、补采、候选判断、参考采用和 DirectorBrief。

内部能力：

1. `DiscoveryPlanner` 先查询库存，再根据缺口生成任务级 `DiscoveryBrief`。
2. 调度器只执行批准的平台、账号、查询、数量、时间和费用，不改变策略。
3. `CandidateEvidenceBuilder` 分别保存相关性、表现、迁移性、权利、重复、完整度和成本。
4. `ReferenceSelector` 选择参考及用途；普通灵感可多参考，单视频高保真必须唯一主参考。
5. `ReadinessGate` 执行 L0—L3 和三级参考使用权限。
6. `FactorSpecBuilder` 仅为单视频高保真生成逐镜规格；可观察事实与因果推断分开。
7. `DirectorBriefBuilder` 生成逐镜目标、事实边界、连续性、声音与验收条件，不提前指定素材和供应商。
8. 编导输出独立持久化，修改参考或经营目标时按影响范围使下游版本失效。

验收：从一个经营目标可产生有证据的参考选择和 DirectorBrief；库存不足时可补采并恢复；范围、预算或权利越界时退回经营 Agent。

### 15.6 第四阶段：内容生产与独立验收接轨

目标：复用当前已较成熟的内容 Agent 和数字人技术栈，纳入统一版本主线。

开发内容：

1. `ContentExecutionPlan` 必须引用冻结的 DirectorBrief 和因素版本。
2. 运行时能力真值决定候选供应商；不可用能力不进入方案。
3. `ExecutionPlanReview` 逐镜审核事实、权利、预算、能力、素材来源和因素承接。
4. 生产结果保存逐镜 provenance、供应商任务、成本、输入输出版本和失败回退。
5. 技术检测、语义检测、身份／产品检测和人工复核分开保存。
6. 编导最终表达放行只消费独立证据；失败镜头局部返工并产生新 attempt。

验收：一条普通灵感任务和一条单视频高保真任务分别完成本地／Mock 全链；缺证据时不能发布。

### 15.7 第五阶段：发布与平台指标回填

目标：确保追踪的是客户作品发布实例，而非原爆款视频。

开发内容：

1. 每个平台帖子建立独立 `PublicationAssignment` 和 `PublicationReceipt`。
2. 用户制作确认与发布授权分离；按账号和平台执行审批策略。
3. `MetricWorker` 按平台能力回收客户作品指标，并保存原始值、时间窗、来源和完整度。
4. 统一指标字典映射平台字段，但保留原始字段；不支持的指标为 `unavailable`。
5. 建立同账号、同平台、相近发布时间和内容类型的滚动基线。
6. 发布失败、平台审核、删除、限流疑似和连接失效进入独立状态，不伪装为低表现。

验收：同一主成片分发到多个平台后，各发布实例的数据不会混合；重复拉取幂等；回填错误可恢复；原爆款指标不会进入客户作品经营判断。

### 15.8 第六阶段：链路证据与周包晋级

目标：将跑量好的客户作品链路变成下一周可执行任务，而不是无证据模板。

开发内容：

1. `PatternEvidenceVersion` 保存参考来源、客户作品、账号上下文、钩子、叙事链、实验变量和发布证据。
2. `PerformanceEvaluator` 根据账号内相对基线输出：数据不足、不可归因、未晋级、继续观察、进入下一周复测或扩大复用候选。
3. `WeeklyPromotionDecision` 由经营 Agent拥有，保存预算、数量、账号和停止条件。
4. 编导 Agent为晋级链路生成下一版保留因素与实验变量。
5. 下一周包引用证据版本，不复制自由文本；每次复用创建新实验版本。
6. 周包执行完成后继续回流，形成可重放的多周期链路。

验收：客户作品跑量达到配置条件时可进入下一周包；数据不足、多变量混杂或平台回填失败不会被标记为稳定有效；所有晋级均可追溯到发布实例和指标快照。

### 15.9 第七阶段：影子运行与逐步放量

1. 先使用 1 个企业、1 个账号、1 个平台、每天 1—3 条进行影子运行，不自动发布。
2. 对比 Agent 建议与人工决策，校准候选排序、成本、分析时间和晋级规则。
3. 进入协作模式，真实发布但保留主参考、发布和周包晋级确认。
4. 达到质量、成本、成功率和人工介入门槛后，再扩大到每日 5、10、15 条。
5. 托管模式最后开放，且始终保留预算、权利、事实、目标降级和发布授权门槛。

不建议直接以每天 15 条作为首个真实验收规模；15 条是目标容量，开发验收应逐级证明。

### 15.10 横向工程要求

- **版本与失效**：上游对象变化时，明确哪些下游对象需要重算、复审或保持有效。
- **幂等与恢复**：采集、生成、发布、指标回填均有稳定幂等键和不确定状态恢复。
- **租户与权限**：所有对象、素材、人物、账号和回执按租户隔离。
- **预算账本**：采集、分析、生成、数字人、存储和发布相关费用分项记录。
- **可观察性**：每个 Agent 决策、Worker 调用、失败和人工介入可查询。
- **评估集**：经营建议、参考选择、分镜质量、检测准确率和周包晋级建立固定回归集。
- **迁移**：旧公式、旧导演方案、旧周任务和历史发布只读映射，逐步停止新写入。

### 15.11 开发前需要确认的问题

现有信息足够冻结总体架构，以下问题会影响 schema、状态机、容量和验收，进入对应阶段前需要确认：

#### 业务与容量

1. 每日 15 条是 15 条主成片，还是所有账号／平台合计 15 条帖子？
2. 15 条如何分配到不同账号、产品、市场和平台；是否允许同一主成片跨平台适配？
3. “当天完成”按自然日、采集后 24 小时，还是固定发布时间 SLA？
4. 首期真实验收从每天几条开始，达到什么指标后扩大到 15 条？

#### 参考与生产

5. 15 条是否全部为单视频高保真，还是经营 Agent 可按预算分配普通灵感与高保真数量？
6. 生产级参考的最低条件是什么：L3 完整度、权利状态、媒体可访问性和账号适配分别达到什么门槛？
7. 同一天不同作品能否复用客户已生成的钩子素材；素材复用频率和平台重复风险由什么规则限制？

#### 发布与授权

8. 哪些账号／平台允许自动发布，哪些必须逐条或批次审批？
9. 同一作品跨平台是自动适配后发布，还是每个平台都需要编导复审？
10. 平台连接失效、审核中、疑似限流或删除时，是否自动补发、换时段或停止？

#### 指标与晋级

11. 首期平台能够稳定回填哪些指标；哪些指标是晋级必需，哪些可缺失？
12. 账号基线使用最近多少条、多少天，并如何排除置顶、广告投放和异常作品？
13. 单条客户作品达到什么相对表现可以进入下一周复测？
14. 从“继续复测”升级为“扩大复用”需要几次、多少作品或多少账号的证据？
15. 下一周内容包和周任务包是否统一为同一版本化对象及其任务项？

#### Agent 权限

16. 建议／协作／托管模式下，主参考采用、发布和周包晋级分别由谁确认？
17. 经营 Agent 可以自动调整哪些预算和数量；超过多少变化必须用户批准？
18. 用户手动固定的链路与数据表现冲突时，是继续执行、降低配额还是强制提示复核？
