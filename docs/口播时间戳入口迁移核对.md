# 口播时间戳入口迁移核对

更新日期：2026-10-10。本文核对的是代码入口及兼容范围；真实本地验收样本视频的验收结论以本次验收报告和 `<local-acceptance-dir>/` 产物为准。

## 当前正式链路

```text
源视频下载/本地原片/上传视频/爬虫回传
  → analyzeDownloadedVideoWithFallback
  → prepareReferenceNarration
  → ffmpeg 源音轨转单声道 16k PCM WAV（不改变速度）
  → transcribeWordAudioWithQwen
  → qwen3-asr-flash-filetrans 异步任务，enable_words=true
  → qwenMeasuredWordTimeline 校验真实词边界
  → lockReferenceSpeechTimeline
  → alignReferenceWordsToShots
  → audioTranscript + dialogue/audio + 分镜/beat speechAlignment
  → trend_videos.aiAnalysis.gemini 落库
```

模型提供的是毫秒编码的词级时间戳。`timestampResolutionMs: 1` 表示编码单位，不表示误差只有 1 毫秒，也不能宣称逐帧实测精度。未提供的时钟准确度及 ASR 置信度保留为 `null`。帧区间只是将测得的时间按原视频 fps 映射，不能增加原始 ASR 的精度。

供应商依据：[阿里云 Qwen ASR API](https://help.aliyun.com/en/model-studio/qwen-asr-api-reference) 的 `enable_words` 参数及 `sentences[].words[]` 字段；[非实时语音识别说明](https://www.alibabacloud.com/help/en/model-studio/non-realtime-speech-recognition-user-guide) 明确 OpenAI 兼容 ASR 调用不返回时间戳。词时间戳支持中文、英语等十种语言，其他语言不能套用同等精度声明。

## 已核对的正式分析入口

| 业务入口 | 真实代码路径 | 共享入口/保存行为 |
| --- | --- | --- |
| 灵感大屏源 URL 的同步或异步分析 | `handleAnalyzeSource → queueAnalyzeSource/analyzeSourceVideoJob → analyzeSourceVideoJobInner` | 下载后调用 `analyzeDownloadedVideoWithFallback`，以 `videoLevelSuccessPatch` 写入 `gemini` |
| 新爬取素材进入分析队列 | `enqueueCrawledRecordsForAnalysis → queueAnalyzeSource` | 共享源 URL 分析任务 |
| 内容 Agent 请求对标完整分析 | `socialContentScriptResolvers → queueExactSourceAnalysisForTenant` | 共享精确分析队列；没有另一套 ASR 分镜逻辑 |
| 已下载素材、本地保留原片重分析 | `analyzeDownloadedMaterial` / `startQueuedLocalAnalysis` | 调用共享下载视频分析入口，完整写入分析结果 |
| 手动补充缺失源视频、已存视频队列 | `attachManualVideoUploadAndQueue → triggerVideoAnalysis` | 取到源视频字节后调用共享入口 |
| 爬虫控制服务回传视频 | `analyzeOpsVideo` | 回传字节落本地临时文件后调用共享入口 |
| 本地整条视频验收脚本 | `scripts/run-integrated-flow-20261008.ts` | 调用同一 `analyzeDownloadedVideoWithFallback`；`--accept-analysis` 是复用验收产物，不能证明重新跑过 ASR |
| 批量补充美妆对标样片 | `scripts/refresh-beauty-short-benchmarks.ts` | 调用 `analyzeSourceVideoJob`，继承共享入口 |
| 现有分镜只重算音频对齐 | `scripts/regenerate-current-narration.ts` | 调用 `prepareReferenceNarration + lockReferenceSpeechTimeline`，并保存/复读逐镜及 beat 对齐结构 |
| 灵感大屏只重算音频对齐接口 | `POST /api/overseas/videos/:id/align-speech` | 调用共享词级转写及映射，复用原分镜视觉结果 |

`analyzeDownloadedVideoWithFallback` 的 Qwen、原生 Gemini、归一化视频 Gemini 三个成功出口都应用相同的音频锁定函数。归一化视频仅用于视觉模型兼容；口播仍从原始 `opts.filePath` 音轨测量，避免视觉转码造成音频时钟漂移。

YouTube 直接 URL 的 Gemini 分析、纯标题/元数据降级没有可供 ffmpeg 抽取的本地源视频，不能建立源词级对齐证据。只有走实际视频下载路径后，才能进入上面的音频链路。这类结果必须保持对齐不可用，不能让模型猜测台词充当源词时间戳。

## 替换内容与缓存

- 参考视频入口不再使用 `qwen3-asr-flash` 的 OpenAI 兼容调用返回的整条文本/`0,0` segment 来生成分镜时间戳。
- 不再按句数均分视频时长，也不把 3 秒抽音窗口分出的句子当成真实词时间码。
- 不再通过 `objectStorageEnabled && process.env.DASHSCOPE_API_KEY` 判断能否对齐。本地密钥文件按服务统一读取；源音频通过供应商临时上传接口交付。
- 不再使用旧 `verifiedAudioCues` 的句子返回作为“words”。参考链路直接读取 `sentences[].words[]`。
- `data/analysis-output/narration-cache/` 中参考视频缓存版本升为 2，以租户、源视频 SHA256 和版本隔离。旧校对文本及均分时间的缓存不升级为真实对齐。
- 缓存键包含抽音时钟策略 `media-origin-first-pts-zero-no-stretch-v1`。使用 `-copyts -start_at_zero` 对齐媒体零点，`aresample=16000:async=0:first_pts=0` 仅在音轨开始补静音或截去负起点样本；不动态拉伸口播。解析原音轨 `ashowinfo` 校验连续性，发现累计音频时钟偏移超过 10ms 则在本地失败，不调用付费 ASR。策略依据：[FFmpeg resampler 的 first_pts 与 async 定义](https://ffmpeg.org/ffmpeg-resampler.html)。复杂不连续时钟及 VFR 的逐帧时钟未承诺已验证。
- filetrans 任务保存于 `data/analysis-output/qwen-word-asr-v1/<tenant>/<audioSHA256>.json`。提交前保存状态；拿到任务 ID 后持久化；后续调用只轮询或使用完成结果。
- 未知状态、已失败任务不自动重新提交，避免重复扣费。人工确认不是链路节点；这里保存失败信息并由产品的重试/恢复逻辑处理。

每条不同的源音频首次需要一次 filetrans 转写；相同源音频复用缓存，不重复付费。抽音、分镜映射、时间到帧编号换算在本地完成，不需要逐镜再调用 ASR。文字校对不能覆盖真实词原文或创造时码。本次不触发视频生成费用。

本地验收样本原片更新抽音策略前后的 WAV SHA256 均为 `<redacted-sha256>`，字节完全一致，可以继续复用已经完成的供应商任务。该源片媒体起点和首音轨 PTS 都是 0，音频时钟累计偏差最大约 0.118ms。比较只做本地抽音，没有付费请求；证据为 `<local-acceptance-dir>/audio-clock-policy-check.json`。

| `server/integrations/qwenAlignment.ts`、`studio.ts:alignTtsAudio` | 已合成音频与指定文稿对齐 | 保留原有句级优先返回，不承诺参考镜头词级证据 |

## 再生成脚本

```sh
pnpm exec tsx scripts/regenerate-current-narration.ts \
  --tenant-id "$TENANT_ID" \
  --id "$SOURCE_ID" \
  --video /absolute/path/to/original.mp4

# 核对 preflight 输出无误后，才允许发起付费 ASR：
pnpm exec tsx scripts/regenerate-current-narration.ts \
  --tenant-id "$TENANT_ID" \
  --id "$SOURCE_ID" \
  --video /absolute/path/to/original.mp4 \
  --execute-paid \
  --authorization-evidence "$AUTHORIZATION_EVIDENCE_REFERENCE"
```

脚本不再内置客户、租户或素材标识。默认只做 preflight，不提交供应商任务、不修改记录；只有同时提供 `--execute-paid` 和非空 `--authorization-evidence` 才能发起正式词级服务。默认输出位于系统临时目录，也可用 `--output` 指定已受本地忽略策略保护的目录。脚本先检查租户归属和源视频哈希（记录存在 `contentSha256` 时必须一致），从 ffmpeg 源元数据读取实际小数时长及 fps。任务完成后再读最新记录，保留其他并发修改，再整体写入 `gemini`。执行模式会保留 `reference-before.json`、`source-probe.log`、授权凭据哈希、`measured-narration.json`、`reference-after.json`，并复读确认时间戳任务和逐镜对齐字段已保存；不会把授权凭据原文写入报告。

## 回归核对

```sh
pnpm exec tsx --test \
  server/lib/qwenAsr.test.ts \
  server/lib/referenceSpeechEntryPoints.test.ts \
  server/lib/referenceSourceClock.test.ts \
  server/lib/referenceWordAlignment.test.ts \
  server/integrations/qwenAlignment.test.ts \
  src/lib/narrationAlignment.test.ts
pnpm exec tsc --noEmit
```

`qwenAsr.test.ts` 检查供应商请求确实开启词时间戳、自动路径没有 Studio 确认、首次提交一次及持续轮询、缺失/空/倒序/越界词拒绝、零时长弱词按原测得边界保留、英语标点不重复。

`referenceSpeechEntryPoints.test.ts` 核对下载视频分析的三个成功出口都锁定源词证据，四类分析/队列 wrapper 共享入口，参考入口不能重新使用旧 ASR、均分时长或句子冒充词，重生成脚本必须写回完整逐镜证据。

`referenceWordAlignment.test.ts` 验证真实词和镜头窗口的交集、跨切点词的归属、静音镜头及零时长点；原词边界仍保存，不能通过复制完整句子造成连续镜头台词重复。

`referenceSourceClock.test.ts` 生成真实 FFmpeg fixture：音轨晚于视频 0.4 秒、整个媒体起点为 0 或 5 秒两种情况。检查抽音结果前 6400 个采样为静音，后续口播 PCM 与原抽音逐字节一致，视频事件和声音都在媒体 0.4 秒发生；另验证音轨内部 0.2 秒时钟跳变会失败。该测试不调用 ASR、不花供应商费用。

这些本地测试证明代码契约，不能替代实际源视频、供应商 ASR、落库和接口复读的端到端验收。
