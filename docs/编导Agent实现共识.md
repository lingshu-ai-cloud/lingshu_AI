# 编导 Agent 实现共识

更新日期：2026-09-23  
文档状态：目标架构与安全合并共识，供产品、设计和研发评审  
当前代码基线：`6c8f97b` 及本地工作区  
对照开发版本：`097212095d108e7787461360d5bea3750d4e1e81`（分支：`吴小姐命令AI做爆款复刻`）

## 1. 文档目的与最终结论

本文综合两套思路：

- 当前讨论形成的“经营 Agent → 编导 Agent → 内容 Agent”完整编排；
- 对照分支已经实现的“素材加工 / 爆款裂变、参考视频分析、素材供给策略、生产执行”能力。

合并后的产品方向是：**保留对照分支可运行的生产能力，把它接入三 Agent 的统一任务链；同时重新划清编导与内容的交接边界。** 不直接整分支覆盖，也不把其中所有对象都视为最终架构。

最终确认以下原则：

1. 经营 Agent 决定经营目标、周内容组合、平台账号与资源边界。
2. 编导 Agent 决定每条视频为什么这样表达，以及每个分镜要实现的理想效果。
3. 内容 Agent 决定用哪些素材、模型和第三方能力实现这些分镜。
4. 脚本继续存在，但不再是编导与内容之间唯一、也不是最主要的交接物；正式交接物是结构化 `DirectorBrief`。
5. 对照分支的真值边界、功能等价替换、供应商适配器、执行溯源和零素材入口应保留。
6. 素材来源和具体片段由内容 Agent 求解，不在编导阶段提前写死。
7. 不建设一套由人维护、强约束生成的“爆款公式库”；系统内部可以沉淀由多个样本和真实结果支持的“创作模式记忆”。
8. 没有客户素材不等于一定能无损生产。系统必须明确区分完整实现、功能等价实现、目标降级和不可生产。

本文中的“目标设计”代表后续实现方向；“代码现状”只描述已经存在的能力，不代表端到端链路已经完成。

## 2. 两类入口，共用一条生产链

产品需要同时支持计划型生产和即时生产。

### 2.1 经营驱动的周计划入口

适合持续经营的企业用户：

```text
用户经营目标
  → 经营 Agent 生成周任务包
  → 编导 Agent 规划本周选题与发布安排
  → 经营 Agent 自动检查并确认
  → 编导 Agent 生成单条视频的导演方案
  → 内容 Agent 形成制作方案
  → 编导 Agent 自动审核制作方案
  → 内容 Agent 执行与技术质检
  → 编导 Agent 验收表达效果
  → 经营 Agent 进入发布与复盘
```

### 2.2 即时任务入口

吸收对照分支的双入口设计：

- **素材加工**：用户已经有素材，希望快速加工成内容。
- **爆款裂变**：用户提供参考视频或选择灵感视频，希望复用其有效结构。

即时任务可选择素材状态：`ready`、`limited`、`none`；默认使用“一键托管”，高级用户可以展开更多配置。

即时任务不能形成另一套孤立工作流。系统在收集最少必要信息后，同样生成 `DirectorBrief`，再进入内容 Agent 的规划、审核和生产链。缺少经营周任务时，系统建立轻量 `AdHocBusinessContext`，记录目标、平台、账号、预算与事实来源。

## 3. 三 Agent 的职责与决策边界

| Agent | 回答的问题 | 拥有的决策权 | 不应越过的边界 |
| --- | --- | --- | --- |
| 经营 Agent | 为什么做、这周做什么、投向哪里 | 经营目标、产品重点、受众、平台、账号、原创数量、分发数量、节奏、预算、优先级和成功标准 | 不直接指定镜头、素材片段或模型 |
| 编导 Agent | 这条视频如何表达、每个分镜应达到什么效果 | 选题、叙事结构、钩子、核心口播、分镜目标、事实约束、连续性和表达验收标准 | 不擅自改变经营目标；不提前锁死素材和技术供应商 |
| 内容 Agent | 如何把分镜目标做出来 | 候选素材、素材组合、数字人或生成模型、第三方 API、配音、字幕、剪辑、混音、渲染和技术质检 | 不擅自改变事实、卖点、叙事逻辑、必需证据和验收标准 |

### 3.1 默认审核与用户介入

- 编导 Agent 提出选题和发布安排，由经营 Agent 自动核对周目标、预算和账号节奏。
- 内容 Agent 提交 `ContentExecutionPlan`，由编导 Agent 自动审核。
- 技术质检由内容 Agent 完成；表达效果由编导 Agent 验收。
- 默认一键托管，不要求用户逐条确认钩子、素材或模型。
- 只有以下情况需要用户处理：事实或权利信息缺失、目标发生实质降级、预算或外部授权超出既定范围、达到自动重试上限、最终成片验收或发布规则要求人工确认。
- 计划确认不等于发布授权；对外发布仍遵守账号授权和发布审批规则。

## 4. 经营 Agent → 编导 Agent：`WeeklyContentPackage`

周任务包是结构化上游契约，至少包含：

| 类别 | 必要内容 |
| --- | --- |
| 经营目标 | 获客、信任建设、新品推广、询盘或转化等 |
| 内容重点 | 产品、卖点、受众、市场、语言和事实来源 |
| 内容产能 | 原创内容数量、改编版本数量、截止时间 |
| 发布矩阵 | 平台、账号、账号定位、内容与发布时间窗口 |
| 资源约束 | 周预算、单条预算、现有素材、可补拍能力、可用技术 |
| 优先级 | 必做、可延后、实验任务及顺序 |
| 成功标准 | 希望用户理解什么、采取什么行动、观察哪些业务指标 |

“原创视频数量”和“发布任务数量”必须分开。例如两条原创内容适配三个平台六个账号，仍然是两条原创内容和六个发布任务。

编导将周任务包转化为选题、内容形态和发布安排。经营 Agent 负责确认它们是否覆盖目标与资源约束。素材或产能不足时，编导必须显式提出调整，不能静默减少交付。

## 5. 参考视频分析与创作模式记忆

### 5.1 科学分析链路

灵感视频按成本逐层分析：

| 层级 | 处理内容 | 用途 |
| --- | --- | --- |
| L0 元数据 | 平台、账号、时间、播放互动、标题、封面、时长 | 去重和优先级 |
| L1 快速理解 | ASR、OCR、抽帧、镜头切分、主体和场景粗标签 | 低成本筛选 |
| L2 全片策略 | 钩子、信息顺序、证据位置、节奏、情绪、CTA、全片粗结构 | 判断结构是否值得迁移 |
| L3 精确分镜 | 连续时间线、镜头、动作起止、空间连续性、画面层和声音层 | 支持可执行导演方案 |
| L4 反馈校正 | 误识别、权利风险、不可复用点和实际制作结果 | 提升后续检索与判断 |

前 15 秒可以做更高精度分析，但不能把“前 15 秒分析的结束时间”当成整条视频时长。长视频必须同时保留全片粗结构，并明确精确分析覆盖范围。

分析结果必须通过以下校验：

- 时间线连续且覆盖声明的分析区间；过滤低置信度镜头后不得留下未标注空档。
- 一个动作要描述开始状态、动作路径、结束状态和必要的空间关系。
- 镜头大小、机位角度、运镜和构图分别记录。
- 人声、字幕、环境声、音乐和音效分别记录。
- 口播字数与分镜时长匹配。
- 明确区分可观察事实、推断意图和因剪辑造成的因果缺口。

不得凭空补充对白、品牌、价格、型号、认证、左右手方向或未出现的动作。平台 UI、贴纸和字幕按后期叠加层处理，不能被误识别为物理场景。

### 5.2 从“爆款公式库”调整为 `CreativePatternMemory`

对照分支取消了独立的公式管理页，并对每个参考视频单独分析；这个方向应保留。单个参考视频首先产生独立、可溯源的 `ReferenceAnalysis`。

系统内部可以在多个参考样本和实际发布结果之间沉淀 `CreativePatternMemory`，内容包括钩子类型、揭示顺序、证据位置、节奏、情绪变化、CTA 位置、适用行业和失效条件。它用于召回和辅助规划，不对编导形成硬规则，也不能覆盖参考视频的精确分析或企业事实。

对外产品语言可以继续使用“爆款思路”或“结构借鉴”，但研发对象统一使用“创作模式记忆”，避免用户误以为存在可机械套用、保证爆款的公式。

复用参考视频时，只复用结构、节奏、证据顺序和可迁移的镜头语法。品牌身份、原话、产品事实和具有明显独创性的表达必须替换。

## 6. 编导 Agent 的正式输出：`DirectorBrief`

脚本只是导演方案的一部分。`DirectorBrief` 包含视频层和分镜层两类信息。

### 6.1 视频层

- 来源：`weeklyPackageId` 或 `adHocBusinessContextId`；
- 选题、受众、目标平台与账号；
- 创作意图、叙事结构、钩子、核心卖点、CTA；
- 总时长、画幅、语言、节奏和品牌要求；
- 事实来源、权利约束、预算和截止时间；
- 所采用参考证据及可迁移/不可迁移部分。

### 6.2 分镜层

每个分镜至少包含：

| 字段 | 含义 |
| --- | --- |
| `purpose` | 该分镜在叙事中的作用 |
| `targetVisual` | 理想视觉与观众应感知到的效果 |
| `requiredEvidence` | 必须出现的主体、事实、动作或证明 |
| `action` | 开始状态、动作路径、结束状态 |
| `shotLanguage` | 景别、机位、运镜、构图 |
| `spaceAndContinuity` | 空间关系、人物/产品状态和前后镜衔接 |
| `audioLayers` | 口播、对白、字幕意图、环境声、音乐、音效 |
| `duration` | 开始时间、结束时间和目标时长 |
| `truthBoundary` | 真实性、合规、品牌和权利边界 |
| `allowedVariation` | 内容 Agent 可以改变的执行方式 |
| `acceptanceCriteria` | 可观察、可自动或人工检查的验收条件 |

示例：

| 字段 | 内容 |
| --- | --- |
| 分镜作用 | 开头建立真实工厂可信度 |
| 理想视觉 | 从车间空间切到设备加工近景，让观众同时看到规模和加工过程 |
| 必须证据 | 本企业真实工厂；与本产品相关的设备或加工动作 |
| 动作 | 全景建立空间，镜头沿生产线移动，落到设备加工细节 |
| 口播 | 从打样到批量生产，我们都在自己的工厂完成 |
| 允许变化 | 可以使用一个连续镜头，或组合两至三个连续性良好的片段 |
| 禁止事项 | 不用其他工厂冒充；不把生成画面作为真实产能证据 |
| 验收条件 | 观众能看到生产环境和加工动作，画面足以支持口播事实 |

“高级感”“爆款感”“突出实力”只能表示方向，不能单独作为验收条件。

## 7. 内容 Agent 的正式输出：`ContentExecutionPlan`

内容 Agent 接到 `DirectorBrief` 后先规划、再执行。它为每个分镜：

1. 检索约 10–20 个素材片段或可用能力作为候选；数量是召回目标，不是硬性门槛。
2. 按企业归属、语义相关性、证据强度、动作与景别、画质、时长、权利状态、重复度排序。
3. 形成一个推荐组合和少量备选组合。
4. 在本地素材、授权共享素材、安全图形、数字人、图片/视频生成、补拍或混合方案中选择路线。
5. 给出成本、耗时、成功概率、数据出境和权利风险。
6. 标注每个候选和产物的来源、供应商、输入、版本、授权和执行记录。
7. 提交给编导 Agent 自动审核；通过后才锁定并执行。

具体的 `assetId`、`clipId`、时间片段、模型、供应商、提示词和重试策略属于 `ContentExecutionPlan`，不属于 `DirectorBrief`。

对照分支中的 `SocialAssetSupplyPlan`、`SocialShotMaterialMapEntry`、provider adapter、attempt 和 provenance 是这一层的良好基础，但需要从导演输出中迁移到内容 Agent 的执行计划中。

### 7.1 能力注册表

内容 Agent 通过统一能力注册表选择本地技术和第三方 API。每项能力至少记录：

- 能做什么和明确不能做什么；
- 输入要求、输出规格与质量区间；
- 成本、典型耗时、并发和速率限制；
- 可用状态、授权范围、数据传输限制；
- 失败后的备选路线；
- 历史成功率及适用场景。

供应商的能力描述不能直接替代实际验收数据。

## 8. 真值边界、零素材与功能等价替换

对照分支的 `SocialShotTruthBoundary` 和 `SocialFunctionalEquivalentReplacement` 应作为正式能力保留。每个分镜先判断它承担的是事实证明、产品展示、抽象说明还是氛围表达，再决定允许使用的素材来源。

以下内容属于高真值敏感对象：真实工厂、真实案例、产品效果、认证、参数、客户反馈和人物身份。生成内容不得被呈现为这些事实的真实证据。

当用户没有素材时，内容 Agent 可以提出功能等价替换，但必须给出明确可行性等级：

| 等级 | 含义 | 默认处理 |
| --- | --- | --- |
| `full_fidelity` | 目标和证据均可完整实现 | 自动继续 |
| `functional_equivalent` | 表达方式变化，但原目标和事实强度保持 | 编导自动审核后继续 |
| `goal_degraded` | 核心证明或表达强度下降 | 编导确认；影响周目标时回到经营 Agent；通常提示用户 |
| `blocked_for_facts_or_rights` | 缺少事实、授权或不可替代证据 | 停止相关分镜并请求必要信息 |

因此，`canProduceWithoutCustomerShoot = true` 不能作为全局承诺。是否无需补拍必须按分镜判断，并把降级情况显式传回上游。

## 9. 审核、重试、状态和版本

### 9.1 编导对制作方案的自动审核

编导 Agent 输出结构化 `ExecutionPlanReview`：

- `approved`：是否通过；
- `sceneResults`：逐分镜结论；
- `failedCriteria`：未满足的验收条件；
- `requiredRevision`：需要替换的素材或技术路线；
- `goalImpact`：是否影响视频或周经营目标；
- `reasonCode`：素材不足、事实缺失、授权不足、预算超限、能力不匹配、时长不适配、生成失败或表达失败等。

不得只返回“效果不好”。自动往返要有最大次数、预算和截止时间；达到阈值后进入待处理状态。

### 9.2 推荐状态机

```text
planned
  → reference_ready
  → director_ready
  → execution_planning
  → director_review
  → producing
  → technical_review
  → creative_review
  → asset_review
  → ready_to_publish
```

任一步都可进入 `needs_facts`、`needs_rights`、`needs_budget`、`goal_degraded` 或 `failed_recoverable` 等待处理状态。

### 9.3 任务链与版本

```text
weeklyPackageId / adHocBusinessContextId
  → contentPlanId
  → videoTaskId
  → referenceAnalysisId + version
  → directorBriefId + version
  → sceneId
  → contentExecutionPlanId + version
  → executionPlanReviewId
  → artifactId
  → creativeReviewId
  → publishAssignmentId
```

版本不能使用固定字面值。任何上游变更都应计算影响范围：发布时间变更通常只影响发布任务；素材失效只重规划引用它的分镜；产品事实改变才使相关导演方案和成片失效。

第三方付费调用必须使用幂等键并记录执行。单分镜失败只重做受影响部分。

## 10. 灵感采集策略

灵感中心的内容来源由经营目标、行业和账号策略共同决定。编导 Agent 负责规划关键词、对标账号、平台配额、刷新频率和停止条件；经营 Agent 提供本周目标、产品、市场和账号矩阵。

关键词至少分为行业词、产品/工艺词、购买意图词、内容结构词、趋势/竞品词。对标账号至少区分头部/达人、垂类专业、商家自营、小白或低基线账号。

视频排序使用两个独立指标：

1. **来源优先级**：平台、账号权重、账号类型、行业相关度和采集策略命中。
2. **内容机会分**：相对账号基线的异常增长、互动质量、新鲜度、周任务相关度、结构可迁移性和证据质量。

```text
相对表现 = 当前视频表现 ÷ 该账号同平台近期内容基线
```

绝对播放量不能跨平台、跨账号直接比较。小账号显著超过自身基线的内容，可能比头部账号的普通高播放更值得研究。

行业策略首期至少覆盖以下差异：

| 行业 | 优先内容与证据 | 重点风险 |
| --- | --- | --- |
| 精密制造 | 工艺、设备、精度、质检、交付；真实车间、加工与测量 | 不虚构认证、精度、产能；生成画面不冒充工厂证据 |
| 运动健康 | 动作、训练场景、使用方法；正确动作和适用人群 | 避免不实健康功效和危险动作；保持人物连续性 |
| 美妆个护 | 质地、使用过程、效果对比、成分与场景 | 避免夸大；包装、肤色、产品状态和对比必须可信 |

Geo 暂不作为首期阻塞项，但数据结构应预留市场、语言、文化、季节和地区平台权重。

## 11. 页面地图与用户动线

| 页面 | 主要 Agent | 生产对象 | 目标能力 |
| --- | --- | --- | --- |
| 智能经营 / 周计划 | 经营 Agent | `WeeklyContentPackage`、选题矩阵、排期 | 管理目标、预算、原创数量、发布数量和优先级 |
| 即时内容入口 | 经营上下文 + 编导 Agent | 素材加工、爆款裂变任务 | 选择入口、素材状态和托管模式，快速进入统一链路 |
| 灵感采集策略 | 编导 Agent | `CrawlStrategy` | 管理行业策略、关键词、对标账号、平台配额和采集健康度 |
| 灵感中心 | 编导 Agent | `ReferenceAnalysis`、`CreativePatternMemory` | 比较相对表现、分析可信度与可迁移结构，选入任务 |
| 视频策划 / 导演台 | 编导 Agent | `DirectorBrief`、`ExecutionPlanReview` | 查看经营来源、参考证据、逐镜目标，审核内容方案 |
| 内容生产现场 | 内容 Agent | `ContentExecutionPlan`、候选素材、分镜产物 | 查看推荐组合、技术路线、成本耗时、分镜状态和局部重做 |
| 发布与复盘 | 经营 Agent | 平台版本、账号任务、回执和效果 | 发布审批、分发、结果回流和模式效果更新 |
| Agent 运行监控 | 运维/高级用户 | 运行、事件、重试和业务回写 | 排查断链，不承载日常创作决策 |

默认用户主线：

```text
确认周计划或创建即时任务
  → 可选查看灵感依据
  → 异常或需要编辑时进入导演台
  → 查看分镜生产进度与预览
  → 验收成片
  → 发布与复盘
```

爬虫策略、10–20 个候选素材、模型日志和 Agent 内部消息默认收起。用户提出“把这个镜头换成真实车间”时，系统应自动判断这是执行方案替换还是导演目标变更。

## 12. 对照分支的吸收、调整与暂不合并

### 12.1 直接吸收的能力

- “素材加工 / 爆款裂变”双入口和 `ready / limited / none` 素材状态。
- 一键托管与高级模式的分层体验。
- `SocialReferenceVideoAnalysis`、三秒钩子和参考分镜分析的基本数据结构。
- `SocialShotTruthBoundary` 与功能等价替换。
- `SocialAssetSupplyPlan`、provider adapter、执行 attempt、provenance 和 fallback 机制。
- 参考画面与客户画面、保留点与变化点、真实性提示的展示方式。

### 12.2 调整后吸收的能力

| 对照分支做法 | 合并后的做法 |
| --- | --- |
| 编导输出中包含素材来源策略、fallback 和具体供给计划 | 迁移到 `ContentExecutionPlan`；编导只给真值约束与验收标准 |
| 单次分析结果直接生成复刻脚本 | 先形成可溯源 `ReferenceAnalysis`，再结合经营上下文和企业事实生成 `DirectorBrief` |
| 过滤 `needsReview` 镜头后继续生成 | 保留空档并标记待确认，或补充分析；禁止形成伪连续时间线 |
| 使用前 15 秒结束点推断整片时长 | 区分全片粗分析与前 15 秒精确分析的覆盖范围 |
| 固定版本 `'1'` | 使用真实递增版本与影响范围失效机制 |
| 用户逐条确认钩子后继续 | 一键托管默认自动选择；高级模式或高风险任务再要求确认 |
| 没有客户素材也声明可生产 | 输出四级可行性，不能静默降低事实或业务目标 |

### 12.3 不直接合并的部分

- 与三 Agent 链路无关的大量账号中心、启动页等改动，应拆分评审。
- 不恢复独立、人工维护的公式管理页。
- 不保留“编导预先决定所有素材来源，内容 Agent 只执行”的职责划分。
- 不把通用模板钩子、按镜头序号循环分配事实等占位逻辑视为正式生成逻辑。
- 不在未验证完整时间线、动作、空间连续性和音频层的情况下宣称已完成精确分镜分析。

## 14. 安全合并顺序

“安全合并”指先合并数据契约和可复用服务，再迁移页面与任务，始终保留旧链路可读，不直接把 122 个文件整体并入当前版本。

### 阶段 1：固定契约和兼容层

1. 定义并版本化 `WeeklyContentPackage`、`ReferenceAnalysis`、`DirectorBrief`、`ContentExecutionPlan`、`ExecutionPlanReview` 和 `ProductionResult`。
2. 为旧 `StoredSocialDirectorPlan` 提供读取适配器；已有任务不批量重写。
3. 把 truth boundary、functional equivalent、provenance 和 provider attempt 迁入新契约。
4. 建立稳定的任务 ID、版本和原因码。

验收：旧任务仍可查看；新任务可以明确看到每个对象由哪个 Agent 生成和审核。

### 阶段 2：先打通一条最小闭环

1. 选择一个行业、一个周任务包和一条视频。
2. 先支持真实本地素材的片段检索、候选组合和成片。
3. 接入内容方案 → 编导自动审核 → 局部重做。
4. 验证成本、耗时、幂等和版本失效。

验收：任一分镜都能追溯经营目标、参考依据、导演目标、素材来源、审核结果和最终产物。

### 阶段 3：迁移对照分支的生产能力

1. 接入素材加工 / 爆款裂变双入口。
2. 将素材供给执行器接入能力注册表。
3. 补全零素材四级可行性与功能等价替换审核。
4. 再逐步接入授权共享库、安全图形、数字人、图像与视频生成。

验收：不同技术路线可以替换，但都受到同一 `DirectorBrief` 和真值边界约束。

### 阶段 4：完善灵感与页面

1. 建立行业、平台、账号和关键词采集策略。
2. 完成全片粗分析 + 重点区间精确分析与连续性校验。
3. 重构导演台和内容生产现场。
4. 将发布结果回流到账号基线、创作模式和技术成功率。

验收：推荐理由可以追溯，响应时间可控，用户只在真正需要决策时介入。

## 15. 工程与产品验收标准

完成目标架构至少应满足：

- 三个 Agent 对同一对象没有重叠写权限，所有越界变更都有显式退回。
- 脚本、素材计划和成片之间有稳定 ID 与版本链。
- 任一生成画面不会被系统当作真实工厂、案例、认证或效果证明。
- 参考分析注明全片时长、分析覆盖范围、时间线空档和置信度。
- 内容 Agent 能提供推荐方案、备选方案、成本、耗时、成功率和来源记录。
- 编导 Agent 能按逐镜验收条件返回可执行修订意见。
- 自动重试受次数、预算和时间限制，付费调用具备幂等性。
- 默认流程保持一键托管，用户无需理解内部 Agent 消息或供应商名称。
- 周计划入口和即时入口最终进入同一任务、审核、生产和复盘链。
- 旧任务可继续读取；迁移失败不会阻断现有生产。
