# 灵枢销售 Agent：智能报价能力包最终方案 v1.0

更新日期：2026-09-12（上线候选版）

## 1. 产品定位

智能报价不是独立页面，而是嵌入“我的会话”的销售 Agent Skill。它把客户聊天中的 RFQ 整理成可核验的内部报价草稿，调用企业产品目录和报价规则，并在人工确认后生成客户回复。首版不自动发送正式报价。

## 2. 竞品结论

- Paperless Parts 的重点是把邮件和附件自动整理成 RFQ、识别关键要求、按零件协作并跟踪任务；灵枢应复用其“先整理要求、再估价”的顺序，但不复制独立工作台。
- Xometry 让材料、工艺、数量和交期变化即时反馈价格，同时把非标准材料、复杂要求转人工；灵枢应明确自动草拟范围和人工报价边界。
- Salesforce Revenue Management 把报价绑定客户/商机，并支持 Agent 创建、修改和总结报价；这验证了“会话内能力、统一产品目录、统一交易上下文”的方向。
- HubSpot 与 Salesforce 都把条件审批和审计作为报价核心能力；灵枢所有价格、折扣、付款和交期承诺均保持 L4 风险。

## 3. 页面动线

```text
我的会话
  → Agent 检测到报价意图
  → 会话顶部显示“智能报价能力包”提示卡
  → 点击“整理报价”
  → 缺信息：插入澄清问题到回复框
  → 信息齐全：显示内部报价草稿卡
  → 员工编辑数量、材料、单价、交货地点/港口、贸易术语、交期与付款条款
  → 人工确认
  → 生成英文报价回复到当前输入框
  → 员工再次核对并使用原渠道发送
```

不增加报价中心、报价列表或新的侧栏导航。管理员继续在企业知识库维护产品和经营规则。

## 4. 会话内交互

报价卡显示产品、SKU、数量、材料、币种、建议单价、小计、参考交期、交货地点/港口、贸易术语、包装、图纸版本、付款条款、价格来源、缺失字段和阻断项。产品、数量、材料、有效单价、交货地点/港口、贸易术语、交期和付款条款均是正式报价确认门槛。没有可靠目录价时显示“待人工填写”，不得生成虚构价格。价格区间不能被当成确定单价；只有唯一且可核验的目录价格才能自动带入。

报价卡包含四个动作：整理报价、插入澄清问题、人工确认报价、生成客户回复。生成回复只写入输入框，不调用发送接口。

## 5. 技术架构

- `server/quoteSkill/engine.ts`：纯函数领域引擎，负责意图识别、字段提取、产品匹配、金额计算和回复组织。
- `server/routes/quoteSkill.ts`：租户隔离 API，复用现有 `requireAuth`、DataStore 和企业档案。
- `quote_skill_drafts`：持久化会话报价草稿，按租户和客户索引。
- `quote_skill_events`：追加式审计事件，记录创建、修改、确认和回复生成，不保存客户回复正文。
- `server/knowledge/packs/manufacturing/quote-skill.json`：报价学习包定义、澄清模板和安全边界。
- `QuoteSkillCard.tsx`：嵌入会话流的报价卡片，不引入新页面。
- 现有 `formal_quote`、`discount`、`payment_terms`、`delivery_promise` L4 规则继续作为自动发送阻断。

## 6. 数据与学习策略

首版直接读取企业档案中的产品目录和经营规则。报价草稿记录字段证据、目录匹配、人工覆盖和确认人。历史报价不得自动变成企业规则；只有客户接受、转订单或人工修改后的记录才进入学习候选，并由管理员审核后提升为知识。

每个客户的报价按 V1、V2 递增；确认后的版本不可覆盖，新报价通过 `supersedesId` 关联上一版本。草稿更新和确认必须提交 `revision`，版本冲突返回 409 并要求客户端刷新，防止多人同时改价时静默覆盖。

## 7. 上线验收

- 报价意图能触发会话内卡片，不出现独立报价导航。
- 产品和数量能够从对话提取，产品能够匹配企业目录。
- 缺字段时能够生成澄清问题。
- 没有价格来源时不能确认报价。
- 人工补价后重新计算小计。
- 未确认报价不能生成对外回复。
- 确认后的报价不能原地覆盖。
- 所有草稿按 `tenant_id` 隔离。
- 只有超级管理员、管理员和客服角色可以完成人工确认；社媒运营与支持代管身份不能确认报价。
- 报价回复只进入输入框，不能自动发送。
- 生产环境默认关闭；`QUOTE_SKILL_ENABLED=true` 打开总闸，`QUOTE_SKILL_TENANT_ALLOWLIST` 支持按租户灰度和快速回退（留空才表示全部租户）。
