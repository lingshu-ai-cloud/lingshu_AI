# 智能报价能力包上线运行手册

更新日期：2026-09-12

## 发布范围

能力只出现在“我的会话”中，不新增报价中心或侧栏入口。生产环境默认关闭：`QUOTE_SKILL_ENABLED=true` 打开总闸，`QUOTE_SKILL_TENANT_ALLOWLIST` 控制允许使用的租户；前端登录后读取当前租户的可用状态并隐藏或显示报价卡。

## 上线前检查

1. 确认目标 CloudBase Run 服务、正式域名和正式 PocketBase 实例。
2. 先执行现有正式数据备份流程：`npm run backup:production-data`。
3. 核对 PocketBase 管理凭据只存在于 CloudBase 环境变量，不进入仓库。
4. 企业产品资料中的确定单价应填写为单一数值，例如 `USD 42.50`；`USD 5-50` 之类区间只作为人工参考，不会自动报价。
5. 首次灰度同时设置 `QUOTE_SKILL_ENABLED=true` 和 `QUOTE_SKILL_TENANT_ALLOWLIST=<内部测试租户 ID>`；多个租户用逗号分隔，留空表示对全部租户开放。能力始终要求人工确认且不会自动发送。
6. 产品目录批量导入仅接受 `.xlsx` 和 `.csv`。旧式 `.xls` 需先另存为 `.xlsx`，避免使用无安全修复版本的旧解析链路。

## 构建与数据结构

仓库根目录 Dockerfile 会依次执行：

```bash
npm ci
npm run build
```

容器启动时执行：

```bash
npm run setup:pb
npm run start
```

`setup:pb` 是幂等操作，会创建或补齐：

- `quote_skill_drafts`
- `quote_skill_events`
- 两张表的租户、客户、报价版本查询索引

## 发布后冒烟测试

1. 请求 `/api/overseas/health`，确认 `status=ok` 且 `featureLocks.quoteSkill=false`，表示报价总闸已打开。
2. 登录内部测试租户后请求 `/api/overseas/quote-skill/availability`，确认返回 `enabled=true`；再用非白名单租户确认返回 `enabled=false`，且报价接口返回 404。
3. 用内部测试租户进入“我的会话”，输入包含产品、数量、材质、交期的询价。
4. 点击“整理报价”，确认卡片显示在当前会话中。
5. 对无确定目录价的产品确认系统显示待人工填写，且不能直接确认。
6. 人工填写币种、单价、交货地点/港口、贸易术语、交期和付款条款，确认小计正确；缺少任一正式报价必填项时必须保持不可确认。
7. 完成人工确认，确认原版本不可再次编辑。
   使用社媒运营角色复测一次，确认其收到 403 且不能确认正式报价。
8. 生成客户回复，确认内容仅进入输入框，没有自动发送。
9. 新建报价版本，确认显示 V2 且 V1 仍保持不可变。
10. 在 PocketBase 检查 `quote_skill_events` 出现 created、updated、confirmed、reply_generated 事件，且事件不含回复正文。

## 监控与回退

- 关注服务日志中的 `[quote-skill] request failed` 和 `audit write failed`。
- 单租户异常时，从 `QUOTE_SKILL_TENANT_ALLOWLIST` 移除该租户并重启服务；全局异常时将 `QUOTE_SKILL_ENABLED=false` 并重启。健康检查反映总闸状态，租户可用性由登录后的 `/availability` 接口反映。
- 回退开关不会删除已生成的报价草稿或审计记录。
- 不建议回滚 PocketBase 集合；保留数据，修复后再开启能力。

发布前必须通过：

```bash

npm test
npm run build

git diff --check
```
