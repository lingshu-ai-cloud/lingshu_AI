# 数字员工内容生产链路修复指导

> 日期：2026-10-12，2026-10-13 补充单条内容制作底座审计与本地修复
> 适用范围：智能经营 → 数字员工 → 周任务、员工排期、发布日历、单条内容制作、内容制作进度、灵小枢
> 设计依据：`docs/product/PRD-灵枢AI全系统UI设计规范-v2-2026-10-09.md`
> 本轮边界：只做本地开发、测试与验收；不部署、不发布、不主动调用付费供应商。

## 1. 先说结论

当前系统不是完全不能生产，而是“能创建周运行”和“能稳定产出完整成片”之间仍有断层。前面的阻塞会遮住后面的错误，不同节点又可能用不同口径解释同一份脚本、分镜、素材和数字人状态，所以页面会出现“已启动”“17%”“等待外部服务”等看似明确、实际无法回答用户下一步的问题。

修复后的理想链路只有一条：

1. 周任务启动只检查归属、版本、计划结构、预算边界和幂等，确保用户能进入生产队列。
2. 每条内容进入队列后，按同一份冻结逐镜清单依次完成爆款分析、脚本适配、素材路由、口播、数字人、合成和质检。
3. 普通缺口由 Agent 自己换路线或重试；只有确实需要用户提供的硬资料才暂停当前内容，不暂停整周。
4. 页面进度只认真实产物和真实回执，不根据模板工时或任务已创建来估算完成度。
5. 灵小枢始终知道用户当前看的周、任务和内容，只承接一个最重要的决定，并把复杂操作带到正确页面。
6. 只有拿到可播放成片、逐镜来源、供应商回执和质检结果，才宣布生产链通过。

## 2. 本次发现的问题

### 2.1 生产前的问题

| 问题 | 用户看到的现象 | 根因 | 严重程度 |
| --- | --- | --- | --- |
| 爆款分析口径不一致 | 灵感中心像是分析完成，进入生产后又提示镜头类型、时间线或复核缺失 | 上游只检查“有时间和画面”，生产门禁检查物理镜头、分类依据、全片覆盖和复核状态 | P0 |
| 预检出现得太晚 | 开始后才知道缺数字人、产品身份或素材 | 资料检查与逐镜执行没有使用同一份冻结清单 | P0 |
| 周任务门槛与单条内容门槛混在一起 | 一个镜头缺资料可能让用户以为整周不能开始 | 周启动、内容生产、正式发布三种门禁没有分层表达 | P0 |
| 数字人提示不完整 | 到数字人步骤才停，但灵小枢没有直接告诉用户去哪里录入和授权 | 后端能识别缺口，页面上下文和决策卡没有稳定绑定到当前内容 | P0 |
| 预算口径分裂 | 周预算、逐镜估算和供应商预占金额对不上 | 规划常量、执行报价和预算账本没有统一成一次冻结报价 | P1 |

### 2.2 正式生产后的问题

| 问题 | 用户看到的现象 | 根因 | 严重程度 |
| --- | --- | --- | --- |
| 进度可能失真 | 一个粗粒度 video 状态同时把口播、数字人和渲染画成完成 | 手动/直连内容沿用旧队列状态，没有逐阶段真实证据 | P0 |
| 暂停或人工接管不彻底 | 页面显示暂停，但后台执行任务仍可能继续，甚至产生费用 | 工作流运行和持久化执行任务是两套状态，缺少先封闭运行、再暂停任务的统一控制协议 | P0 |
| 卡点恢复不明确 | 页面停在一个节点，人工接管不可点或重试后重复建任务 | 没有记录“谁暂停、暂停了哪些任务、从哪个检查点恢复” | P0 |
| 中转页和重复进度界面 | 日历详情、数据复盘和内容制作各显示一套进度 | 缺少单一生产进度模型和统一深链 | P1 |
| Agent 协作断层 | 编导确认的是新逐镜方案，预算或素材执行却回读旧字段 | 上下游未共享冻结的生产清单和版本号 | P0 |

### 2.3 灵小枢的问题

| 问题 | 用户看到的现象 | 根因 | 严重程度 |
| --- | --- | --- | --- |
| 不知道当前任务 | 用户切到某条内容后，灵小枢仍回答最新目标或旧任务 | 数字员工页面只传了页面名，没有传 goal/run/task/content 身份 | P0 |
| 待办不随页面更新 | 收起再打开、切换内容后仍显示旧提示 | 关闭状态没有轻量刷新真实待办 | P1 |
| 只能提示，不能承接 | 缺数字人时没有“去录入数字人”的唯一动作 | 决策中心虽能生成企业资料深链，但前端没有稳定使用当前内容上下文 | P0 |
| 操作结果不闭环 | 点击开始后旧卡不消失，也没有准确结果提示 | 动作成功、运行状态刷新和待办刷新未绑定同一回执 | P0 |

## 3. 三层门禁，不能再混用

### 3.1 第一层：开始周任务

目标是让用户顺利进入真实生产队列，只检查：

- 当前租户和目标归属正确；
- 周计划版本没有过期；
- 至少存在可执行的内容结构；
- 预算有明确上限且不会隐式加额；
- 同一目标不会重复创建运行。

爆款分析、素材匹配、口播、数字人、合成和质检都不是整周启动门槛。缺其中一项时，周任务仍可启动，但对应内容必须显示真实的“待处理”节点。

### 3.2 第二层：单条内容调用供应商前

这是严格门禁，也是防止浪费费用的关键。每条内容按逐镜清单检查：

- 参考片已完成全片精确分析；
- 每镜有真实起止时间、镜头类型、叙事作用、分类依据和画面证据；
- 分析没有待复核镜头，时间线覆盖整段原片；
- 脚本版本、分镜版本和产品身份已冻结；
- 每镜已选可用素材、可执行 AIGC 路线或明确代拍；
- 数字人口播镜头已绑定租户内已授权、已发布、版本不可变的人物资产；
- 供应商能力可用，报价和本次预算预占已确定；
- 稳定请求键已生成，未知状态不得换键重复付费。

未通过时只暂停当前内容。页面和灵小枢必须用一句话说明“缺什么、去哪里补、补完后如何继续”。

### 3.3 第三层：正式发布前

生产完成不代表可以发布。发布前另行检查：

- 真实成片已经质检通过；
- 发布账号和渠道能力可用；
- 文案、内容版本和成片哈希没有变化；
- 用户或授权策略允许这次真实发布；
- 发布预算、排期和平台限制满足要求。

降低生产门槛不能绕过发布授权。

## 4. 唯一生产事实：冻结逐镜清单

所有 Agent 和执行器必须读取同一份、带版本号的生产清单，禁止各自回读旧脚本字段。最低字段如下：

| 范围 | 必须冻结的内容 |
| --- | --- |
| 内容身份 | tenantId、goalId、runId、taskId、contentId、familyId、平台版本 |
| 参考证据 | referenceId、analysisRunId、evidenceRevision、完整时间线 |
| 脚本 | 原片口播、企业适配口播、允许替换项、语言、版本 |
| 逐镜 | sceneId、referenceShotId、起止时间、画面证据、镜头类型、叙事作用、验收标准 |
| 产品 | productId、产品版本、身份参考图、不可伪造事实 |
| 素材路线 | 已选素材 ID / 数字人 / 产品 AIGC / 普通 AIGC / 代拍，及选择理由 |
| 数字人 | presenterId、publishedVersionId、授权状态、供应商映射、使用范围 |
| 执行 | provider、能力版本、稳定请求键、报价、预算预占、状态、真实回执 |
| 结果 | 产物 ID、哈希、时长、逐镜来源、质检回执、失败检查点 |

任何会改变脚本、核心画面、产品事实、预算或授权的修改都必须生成新版本；普通重试复用原运行、原产物和原请求键。

## 5. 分里程碑修复

### M0：冻结基线与问题证据

目标：先证明问题，不边猜边改。

- 固定一条真实内容作为验收任务，记录目标、运行、内容、逐镜、预算和产物 ID。
- 保存每个节点的输入摘要、输出摘要、耗时、责任 Agent、失败原因和下一步。
- 给已发现问题分配稳定编号，区分“旧问题被后续节点暴露”和“本次改动新引入”。
- 不再把 TypeScript、单元测试或“任务运行中”当作完整生产证明。

完成标准：同一任务可从日志和页面追到每个检查点，任一失败都能指出第一条不满足的合同。

### M1：先保证暂停、接管和费用安全

目标：用户点暂停或人工接管后，后台确实停止继续执行。

- 暂停工作流时，先将 run 置为禁止新调用的 fail-closed 状态，再逐个暂停该 run 的可执行任务。这不是跨存储原子事务；中途失败时依靠幂等重放收敛。
- `waiting_human`、人工控制器和暂停状态全部进入供应商调用总门禁。
- 记录由本次操作暂停的任务集合；恢复时只恢复这些任务，不误启动原本就暂停的任务。
- 同一 run 只允许一个活动人工接管；兼容历史重复接管数据时，只有最后一个活动接管归还后才恢复 run 和任务。
- 暂停、恢复、人工接管和 Agent 归还全部幂等。
- 已有供应商请求状态未知时保留请求键，先查回执，不重新提交。

本轮实现的 run 锁是单进程锁，可防止当前本地实例内的并发双接管，但还不是多实例数据库互斥。部署到多实例前必须增加数据库唯一约束或事务锁；“归还 Agent”也必须补上接管人/有权操作者校验，不能只靠租户、任务和活动 handoff 上下文。

完成标准：单实例内并发点击和重复请求不会多建任务；暂停后不出现新的付费调用；恢复从原检查点继续。多实例唯一性和归还权限完成后，M1 才能整体关闭。

### M2：统一生产前证据和数字人条件

目标：在进入付费阶段前一次性暴露当前内容的真实缺口。

- 爆款分析完成判断与生产准入复用同一个 `productionReferenceAdmission` 规则。
- 未确认镜头类型、观察窗口、待复核、时间线不完整或分析未完成，都不能标为“爆款分析完成”。
- 素材只读取本任务逐镜可能消费的候选，不扫描全租户全部文件。
- 数字人仅在真实人物口播/身份连续性镜头需要；普通 B-roll 不被误判为数字人。
- 缺数字人时给出唯一动作：“企业资料 → 人物与出镜 → 人物与音色资产 → 添加授权人物”，补完后从数字人节点继续。
- 数字人只有在已授权、存在已发布不可变版本、完成供应商映射、且当前用途落在授权范围内时，才算“可生产”；只上传一张人物图不算完成。
- 报价在供应商调用前冻结并汇总，超过周预算时只请求一次确认，不自动加额。

完成标准：开始周任务不被普通资料缺口卡住；进入供应商前能一次列出当前内容全部硬缺口，其他内容继续运行。

### M3：真实进度与 Agent 协作

目标：任何进度都能指向产物或回执。

当前页面统一为 7 个节点：

1. 爆款脚本分析；
2. 脚本确认；
3. 素材匹配；
4. 口播与字幕；
5. 数字人生成（不需要时明确“不适用”）；
6. 视频合成；
7. 成片质检。

参考来源、产品身份和授权不是被删除，而是作为分析、素材或数字人节点的准入证据与阻塞原因展示。内部运行态固定为 `pending / ready / running / waiting / blocked / completed / not_applicable / unavailable`，页面分别显示“未开始 / 已就绪 / 进行中 / 等待中 / 需处理 / 已完成 / 不适用 / 待同步”。

节点在当前界面只显示上述 8 种状态；底层队列的排队、等待外部服务、等待用户、暂停和失败必须映射成“已就绪 / 等待中 / 需处理 / 待同步”之一，并在节点说明中保留具体原因，不能另造一个与真实执行脱节的进度体系。节点完成必须满足：

- 分析：严格准入结果 ready；
- 脚本：冻结版本存在；
- 素材：逐镜路由和可消费资产存在；
- 口播：音频或可核验配音回执存在；
- 数字人：产物或供应商成功回执存在；
- 合成：真实可解码视频文件存在；
- 质检：质量检查回执通过。

禁止把一个粗粒度 `video=completed` 同时复制给口播、数字人和合成。进度百分比按适用节点的真实完成数计算，不适用节点排除分母。

Agent 边界：经营 Agent 管目标和预算；编导 Agent 管表达、脚本、分镜和验收标准；内容 Agent 管素材/能力路由和制作；客服 Agent 只承接用户沟通与补资料，不改制作事实。

完成标准：日历侧栏、内容制作页和 Agent 排期读取同一进度；刷新页面后状态不倒退、不跳步、不伪完成。

### M4：灵小枢承接当前任务

目标：用户走到哪里，灵小枢都知道当前对象和唯一下一步。

- 数字员工页面持续传递 page、goalId、runId、taskId、contentId、当前子视图。
- 用户点击日历内容时立即更新上下文；关闭侧栏后保留当前内容身份。
- 决策中心优先查询当前任务，不再默认取“最近一条目标”。
- 面板关闭时只做轻量待办刷新，用角标提示，不拉取执行日志。
- 缺数字人时显示简短说明和“去录入数字人”；缺预算时显示完整报价和“确认预算”；缺素材时进入当前内容的制作进度。
- 轻量动作成功后移除旧待办，出现一次准确结果气泡；等待、失败、暂停不能统称“正在生产”。
- 复杂逐镜编辑、素材挑选和授权仍在标准工作台完成，灵小枢只提供深链。

完成标准：连续切换两条内容，灵小枢的标题、原因和动作随当前内容变化；动作后旧卡不残留。

### M5：固定真实任务全链验收

目标：用一个真实任务证明整条链，而不是只证明模块能运行。

验收顺序：

1. 创建或复用一条周任务，确认只产生一个运行 ID；
2. 检查爆款分析、逐镜合同、产品、素材和数字人硬条件；
3. 让 Agent 自主完成脚本、路由和预算预检；
4. 在用户确认预算后才允许真实供应商调用；
5. 观察暂停、恢复、失败重试和未知回执恢复；
6. 生成可播放 MP4；
7. 核对时长、音轨、字幕、逐镜来源、哈希和质检回执；
8. 日历侧栏与灵小枢显示同一结果；
9. 不做真实发布，除非用户在当前任务另行明确授权。

完成标准：一次运行产生一份可播放成片，所有节点有真实证据，未重复付费，页面可从成片追溯到冻结清单。

## 6. 高频问题及系统应该怎样处理

| 高频问题 | 系统自动处理 | 需要用户时的唯一提示 |
| --- | --- | --- |
| 爆款分析缺镜头类型或时间线 | 回到同一参考片继续精确分析，不重建周目标 | “参考片还有 N 个镜头待确认，去完成分析” |
| 库内素材不够 | 按逐镜尝试产品 AIGC、普通 AIGC 或代拍，不暂停其他内容 | “当前 N 镜需要补素材，查看逐镜方案” |
| 未录入数字人 | 非人物内容继续；只暂停需要企业人物的内容 | “缺少已授权数字人形象，去企业资料新增并授权” |
| 数字人已录入但未发布/未授权 | 保留人物资产，不调用供应商 | “请发布并确认该数字人的制作授权” |
| 预算不足 | 保留已有产物，给完整增量报价，不自动加额 | “还需 ¥X，查看报价并确认” |
| 供应商超时 | 用稳定请求键查询原请求，禁止立刻换供应商重复提交 | “供应商状态待确认，系统正在查询原任务” |
| 参考片缺真实 ASR 口播 | 先用原请求键自动重试语音识别；确实无口播的镜头标为无对白继续，不伪造原片口播 | “该镜头有对白但仍无法识别，请补录原文后从口播确认继续” |
| 单镜失败 | 重试当前镜头或换等价路线，其他镜头继续 | “第 N 镜失败，可从当前节点继续” |
| 人工接管 | 停止当前运行的可执行任务并保留检查点 | “已暂停，不会继续产生新费用” |
| 后端暂时不可用 | 保留最后确认状态和页面，不把缓存冒充最新结果 | “服务暂不可用，已保留现有结果，重试连接” |

## 7. 自动化与人工验收矩阵

| 能力 | 自动化证明 | 页面证明 | 真实运行证明 |
| --- | --- | --- | --- |
| 分析准入一致 | 同一分析分别经过上游完成判断和生产准入，结果一致 | 未确认镜头显示待处理和补齐入口 | 精确分析完成后不再在生产阶段重复报相同缺口 |
| 周任务轻门槛 | 缺数字人的一条内容不阻止运行创建 | 周状态为执行中，当前内容为等待用户 | 其他不依赖数字人的内容继续推进 |
| 暂停/接管 | run 先 fail-closed、jobs 再逐项暂停，中断可幂等重放 | 按钮状态和节点状态即时一致 | 暂停后无新 provider 请求和费用 |

## 12. 2026-10-13：单条内容制作底座结论

数字员工不是一套独立的视频工厂，它最终仍会进入单条内容制作的脚本、分镜、素材、数字人、渲染和质检能力。因此，只修数字员工页面会把同样的问题推迟到制作工作台再次暴露。

本次代码审计确认，单条内容链路当前还不能判定为“已闭环”：

1. 浏览器仍在充当生产调度器。页面依次调用多个局部接口，批次结果和部分执行状态只存在当前页面；刷新、断网或服务重启后，不能保证从同一检查点恢复。
2. 同一份制作数据存在重复副本。脚本、分镜绑定、剪辑参数、口播和逐镜生产结果同时保存在项目顶层和 `analysisResults`，不同模块可能读取不同版本。
3. 爆款分析有两套判断。灵感中心已有规范化逐镜证据和严格准入规则，但制作工作台过去主要依赖旧的 `details` 数组再次自行判断。
4. 素材库读取夹带执行。过去仅打开素材库就可能触发本地全库视频分析，产生延迟、供应商调用和预算风险。
5. 部分镜头仍按数组位置绑定素材。分镜排序或插入后，素材可能落到错误镜头。
6. 数字人条件已经存在，但发现太晚。授权、发布版本、账号人物锁、声音和供应商能力都有代码合同，实际执行却可能到付费阶段前才统一抛错，并把非人物镜头一起停住。
7. 页面进度主要是推导状态，不是运行证据。节点缺少统一的输入/输出哈希、真实开始结束时间、尝试次数、供应商回执和费用证据。
8. 最终“完成”仍未绑定可播放成片的完整证据。当前主要检查路径和文件存在，尚未统一校验输出哈希、`ffprobe`、音视频流、时长、解码和预览结果。
9. 执行集合的数据库定义没有统一。部分数字人、逐句和首帧任务只出现在本地 setup 逻辑，PocketBase migration 未完整覆盖；全新环境可能直到运行到该节点才发现 collection 缺失。
10. 一部分回归测试只检查源码中是否存在某段文字或参数，能防止误删合同，但不能证明数据库、重启恢复、供应商、预算和媒体文件真实可用。

因此，修复原则不是继续在每个页面加判断，而是让数字员工和单条制作共享同一份冻结输入、同一条持久运行、同一套节点证据和同一个补资料入口。

## 13. 单条内容制作的目标结构

### 13.1 一份冻结输入

正式执行前生成 `ProductionPlan v1`，最低包含：

- 任务、项目、租户、脚本、分镜和素材的稳定 ID 与版本；
- 参考片分析修订、逐镜边界、镜头类型、分类依据和证据；
- 产品身份、产品图、人物资产、声音、授权范围和供应商映射；
- 逐镜来源路线、预算报价、供应商选择和项目 revision；
- 输入清单哈希，后续任一输入变化都必须重新预检，不能复用旧产物。

项目顶层是当前 Studio 编辑态的唯一事实；`analysisResults` 仅保留为兼容快照，不能再被预算、渲染或恢复逻辑当作第二事实来源。数字员工的冻结内容订单仍由服务端拥有，客户端不能改写。

### 13.2 一条持久运行

新增服务端持有的 `single_content_run`，固定节点为：

`preflight → reference/script → material analysis/match → first frames → presenter/AIGC → shot QA/adoption → render → final media QA → delivery`

每个节点必须记录：

- 输入哈希、输出哈希和项目 revision；
- 状态、责任 Agent、开始/结束时间、耗时、尝试次数和失败码；
- 供应商请求键、任务 ID、不可变回执和费用；
- 阻塞原因、受影响镜头、唯一补资料入口和恢复节点。

请求键由服务端按 `run + plan hash + node + shot + attempt` 生成。浏览器只展示和发命令，不再拥有批次身份或决定下一节点。

### 13.3 一次完整预检

任何付费调用前，一次性返回所有缺项，并区分：

- **硬阻塞**：产品身份、权利、冻结脚本、逐镜证据或预算授权缺失；
- **局部暂停**：某些人物镜头缺数字人或能力，非人物镜头继续；
- **可稍后补**：发布账号、排期等只在发布前处理的条件。

预检失败时供应商调用数必须为 0。补齐资料后回到同一 run、同一镜头、同一节点，不重建任务、不重复收费。

### 13.4 一份真实成片证据

渲染完成后保存输出 SHA-256、字节数、`ffprobe`、时长、音视频流和预览结果。只有成片绑定项目成功后，渲染任务才能标记完成。人工验收和最终质量记录必须绑定 `outputSha256 + input/manifest hash`，不能只绑定文件路径。

### 14.2 代码复核后的四项补强

第一版实现完成后又做了一轮反向复核，发现并修正了四个容易“看起来修好、实际仍会串链”的问题：

1. 旧草稿只有兼容快照、root 字段缺失时，不能直接盖上新合同标记。现在只从已知 `studio-analysis.v1` 的白名单字段迁移，随后统一从 root 反向派生快照；未知 schema 不迁移，也不能保留客户端 authority marker。
2. 参考原片镜头 ID 与企业改编后的制作镜头 ID 不是同一件事。现在素材和数字人绑定使用 `replicationScript.shots[].shotId`，参考镜头 ID 只用于来源证据；不再把两者混为一谈。
3. 数字员工进入 Studio 时过去只交接旧 `details`，会绕过严格准入。现在社媒任务合同可携带冻结 `benchmarkAnalysis`；历史任务缺失时明确进入待补分析状态，不自行猜镜头类型和叙事作用。
4. 过去冻结脚本校验的是完整正文，返回给生产的却可能是截断到 30,000 字符的另一份正文。现在超过上限直接阻断，合法正文则原样完整交接。

这四项均有针对性行为测试；不能只以源码包含某个字段作为验收。

## 15. 后续里程碑与实施顺序

### S0：固定真实任务和证据包

- 固定一条约 38 秒的真实任务、素材版本和预期质量标准。
- 把每个节点的输入、输出、耗时、失败原因和供应商调用记录到同一证据包。
- 区分“旧错误直到后续节点才暴露”和“本次修改新引入”的问题。

完成标准：任何失败都能指向第一条不满足的合同，不能只凭日志停留位置猜根因。

### S1：完成单一事实收口

- 所有预算、素材、渲染和恢复消费者改读同一个冻结计划或明确的项目顶层字段。
- 逐镜、素材、产品和参考片全部使用稳定 ID、版本和内容哈希。
- 禁止按显示名找素材、按数组位置找镜头、按旧脚本字段重新预算。

完成标准：故意制造顶层与兼容快照冲突时，所有入口都在付费前拒绝执行。

### S2：权威预检与结构化 blocker

- 服务端统一检查参考分析、产品、素材覆盖、数字人、权利、供应商能力、预算和发布账号。
- blocker 保留 `code / message / affectedSceneIds / actionTarget / resumeNodeId`，禁止压成通用“需处理”。
- 数字人只阻塞人物镜头，非人物镜头继续；授权或能力不满足时仍必须在付费前失败关闭。
- 建立唯一深链：产品到企业产品、数字人到人物与音色、参考分析到对应原片、预算到当前方案、质量到失败镜头。

完成标准：缺少多项资料时一次全部列出；每项只有一个可执行入口；补齐后返回同一任务和节点。

### S3：服务端持久运行与恢复

- 复用 `server/contentExecution` 已有的幂等队列、lease、checkpoint、人工边界、输入哈希和供应商 write-ahead receipt。
- 所有 `running / analyzing / submitting / processing` 状态使用租约，进程重启后自动回收或核对。
- 供应商已接单但本地未落库时进入 `reconciling`，只查询原任务，不盲目重发。
- 所有单条制作路线统一走持久渲染任务。

完成标准：分别在提交前、供应商接单后和成片写盘后杀进程，重启后均能恢复且不重复扣费。

### S4：真实进度、Agent 协作和人工接管

- 页面直接读取当前 run 的节点投影，不再从任务状态或中文 activity 猜 Agent、百分比和镜头完成数。
- 节点没有回执不能标完成；总量未知时只显示当前节点和进行中状态，不显示伪百分比。
- 增加版本化、幂等的 `take_over / release / resume`，记录控制人和租约；接管后停止自动写入当前节点。
- 数字员工日历侧栏、单条制作工作台和灵小枢读取同一节点投影。

完成标准：刷新、重启、暂停、接管和恢复后进度不倒退、不跳步、不重复计费。

### S5：成片验真与不可变验收

- 渲染后执行媒体完整性、时长、音视频流、解码、哈希和预览检查。
- 项目 revision 或素材字节变化后拒绝复用旧 checkpoint 和旧验收。
- 删除或损坏 MP4 后，质检、交付和发布必须全部失败。

完成标准：只在同一冻结任务产出可播放、可追溯并通过媒体校验的成片后，才标记完成。

### S6：灵小枢承接全过程

- App 和单条工作区持续传递 `taskId / taskVersion / runId / nodeId / viewKey`。
- 单条 runtime blocker 进入真实待办；打开产品、参考片或数字人页面时仍保留原任务上下文。
- 数字人保存成功后重新预检原任务，提供“返回并继续”，但不自动确认预算或触发付费。

完成标准：用户切换页面和内容后，灵小枢始终显示当前任务、真实原因和唯一下一步；动作成功后旧卡消失。

## 16. 需要新增的真实验收

固定一个临时数据库、确定性素材、真实 `ffmpeg` 和模拟异步供应商的约 38 秒任务，至少验证：

1. 预检一次返回全部缺项，供应商调用数为 0；
2. 并发重复启动只产生一个 run，每个节点只产生一次供应商请求；
3. 分别在三个关键窗口杀进程并重启，原 run 可恢复且不重复扣费；
4. 遗留执行态能自动转为重试或核对，不会永久显示“运行中”；
5. 暂停保留已接单回执，不启动下一节点；恢复只继续未完成节点；
6. 浏览器刷新后恢复同一 run 和真实节点；
7. 素材字节、项目 revision 或计划哈希变化后拒绝复用旧产物；
8. 数字人缺失时非人物镜头完成，人物镜头暂停；补齐后从原镜头恢复；
9. 输出 MP4 非空、SHA 匹配、可解码、时长在容差内，并具有所需音视频流；
10. 全新数据库迁移环境包含所有 job、plan、execution、receipt 和唯一索引。

源码字符串断言、TypeScript 通过、页面显示“进行中”和测试数量都不能替代上述证据。

## 18. 2026-10-13 数字人已添加但灵小枢仍提示添加

### 问题和根因

灵小枢原先只读取旧制作项目里的“缺数字人”快照，没有在生成待办前重新核对企业当前的数字人资产；数字人保存成功后也只能等定时刷新。因此旧卡会反复出现，而且把“已添加但尚缺当前制作路线的条件”错说成“还没添加”。

### 本地修复

- 灵小枢在生成数字人待办前，使用和真实逐镜执行器相同的准入规则读取当前企业资产。
- 将状态明确分为：未添加、未授权、已添加但制作条件未齐、可用四种，不再用一张“请添加”卡混用。
- 数字人保存、导入或绑定声音成功后，立即让所有已打开的灵小枢重新读取服务端真实状态，不再等轮询。
- 已就绪时，旧卡更换为“数字人已就绪，请继续生产”；已添加但缺少当前逐镜人物替换条件时，只提示补齐人物参考图、人物替换授权和 Active 方舟图片资产。
- 旧项目中的人物镜头软阻塞会在数字人真正就绪后重新建立为可执行镜头，保留已有镜头、回执和付费进度，并从原节点继续。

### 本次数据的准确状态

当前本地已存在一个已授权的口播数字人，因此“请添加数字人”是错误提示。但当前周任务的参考镜头人物替换路线还要求绑定可用人物参考图、人物替换用途授权和 Active 方舟图片资产。在这三项补齐前，系统应该显示“补齐制作条件”，不能假装已可进入人物生成。

## 19. 2026-10-13 灵小枢不随用户行为更新

根因不是单个数字人按钮，而是各页面各自发刷新事件，灵小枢详情形态又没有定时与服务端对账。它可能错过一次事件后长期显示旧卡。

本轮建立统一的“业务状态已变更”通知：

- 人物与方舟资产、内容制作、周任务和社媒内容写入成功后，只通知“哪个业务域变了”，不把页面的临时状态当成真实结果。
- 所有已打开的灵小枢收到通知后都重新读取服务端待办；跨标签页也只传递不含业务资料的版本通知。
- 灵小枢气泡每 15 秒对账，打开的详情每 5 秒对账；窗口重新获得焦点或从后台返回时立即对账。
- “补齐制作条件”会直接定位到当前默认人物的编辑区，不再只打开人物列表。
- URL 中空的 `presenterConsentReturn=` 不再被当作有效授权回跳，避免无故重新打开人物导入弹窗。

本次现场数据仍显示：默认人物 `Dante Office 2` 已有 HeyGen 口播权限，但人物参考资产未绑定、人物替换用途授权未记录、方舟图片资产未达到 Active。因此当前提示应继续存在，但必须定位到该人物的未完成项；三项真正写入后，旧卡应在 5 秒内自动更换。

## 20. 2026-10-13 数字人配置入口统一

### 问题

数字人配置曾分散在三个位置：新手引导只接 HeyGen，方舟认证藏在制作页和企业资料高级表单，灵小枢又把用户带回企业资料。用户无法判断同一个人物还缺哪一步，也会在多个页面重复配置。

### 本地修复

- 数字员工新手引导第 4 步统一为“数字人接入”，HeyGen 口播接入和方舟人物认证处于同一层级。
- HeyGen 负责人物、声音和本人授权；方舟认证复用同一个默认人物，上传本人照片与视频并绑定图片资产。
- 灵小枢发现缺少数字人或人物替换条件时，直接打开新手引导第 4 步，不再跳到企业资料中的旧配置区。
- 企业资料“人物与出镜”不再承载供应商、声音、布局、素材、授权证据、方舟控制台和渠道策略配置。
- 已有人物时，企业资料只显示授权状态，以及“修改人物”和“取消授权”两个操作；没有人物时才提供进入新手引导的入口。
- “取消授权”是租户隔离、可重复执行的服务端命令：人物会立即退出默认人物和路由，但保留不可变的取消授权审计记录，不删除供应商原始资产。
- 人物新增、修改、取消或认证完成后都会通知灵小枢重新读取真实状态，避免继续显示旧待办。

### 验收规则

1. 新手引导同屏显示 HeyGen 和方舟，两者的完成状态分别可见；未完成 HeyGen 时方舟不能误绑其他人物。
2. 从灵小枢“补数字人”进入后直接落在第 4 步，不要求重走公司、产品和阶段问题。
3. 企业资料有已授权人物时，页面不能出现新增人物、声音、布局、素材、方舟控制台或渠道策略配置。
4. 修改名称后列表和灵小枢立即更新；取消授权后人物退出可用列表和默认路由，重复点击不会产生第二次业务副作用。
5. 取消授权不能跨租户，也不能删除供应商账户里的原始数字人资产。

### 当前验证证据

- 数字人统一接入、灵小枢深链、企业精简页、取消授权租户隔离及幂等行为共 45 项针对性测试通过。
- 页面合同明确隐藏“人物与出镜”中的企业完整度、通用保存按钮和解释卡，避免把企业资料补齐与数字人授权混成同一任务。
- 本轮只统一入口和授权管理，不代表真实供应商已经完成一次新授权；真实 HeyGen / 方舟回执仍需在联调环境各跑一人验收。

## 21. 2026-10-13 人物资料一次录入与创建预算修复

### 现场问题

新手引导虽然把 HeyGen 和方舟放在同一步，但仍要求用户分别上传人物素材。人物创建弹层还固定读取照片人物预算；用户选择 Digital Twin 视频时，页面可能继续显示照片预算状态。当前本地实例没有人物创建预算变量，因此前端把整套录入表单禁用并显示“人物创建预算尚未配置”。

### 本地修复

- 新手引导改成一个“人物、声音与本人认证”入口，不再把 HeyGen 和方舟显示成两个需要分别配置的表单。
- 录入新人物时一次提交清晰正面照片和本人视频。视频用于 HeyGen Digital Twin，照片和同一段视频同时安全入库，供方舟本人认证复用。
- HeyGen 创建任务持久保存方舟资料 ID；经过官方授权跳转、状态刷新和声音保存后，这组关联仍然存在，不依赖浏览器临时文件。
- 保存默认人物后，系统先把照片和视频绑定到同一个企业人物，再自动启动方舟认证。方舟能力尚未配置时，已入库资料继续保留，后续只需继续认证，不要求重新上传。
- 方舟认证面板收到统一接入资料时隐藏重复上传控件，并明确显示“已复用”。历史人物没有这组资料时，才补录一次照片和视频。
- 前端根据实际选择的照片或视频读取对应预算和预留额；不再用照片预算错误控制 Digital Twin 表单。
- 本地开发实例配置人物创建总安全额度 ¥10、照片人物预留 ¥2、Digital Twin 预留 ¥10，已用金额从 ¥0 开始。该数字是失败关闭的本地安全上限，不是供应商正式报价；生产环境仍必须显式配置，不能继承开发默认值。

### 安全与验收边界

1. 复用到方舟的照片、视频必须是当前租户自己的私有素材，并且类型匹配；仅靠前端传 ID 不能建立关联。
2. 相同人物视频被再次提交时复用原 HeyGen 付费任务，同时补写最新方舟准备资料，不重复创建付费人物。
3. 预算仍在供应商调用前预留；额度缺失、无效或不足时继续失败关闭。修复没有绕过预算校验。
4. 本轮自动完成的是资料复用与任务衔接；方舟服务密钥、公网 HTTPS 素材交付和本人验证回跳地址缺失时，仍会明确暂停在认证步骤。
5. 真实验收必须使用一套本人照片与 30 秒以上视频，证明只上传一次即可完成 HeyGen 授权回跳、声音保存、方舟本人验证和最终 Active 图片资产。
