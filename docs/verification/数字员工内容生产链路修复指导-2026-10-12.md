# 数字员工内容生产链路修复指导

> 日期：2026-10-12
> 适用范围：智能经营 → 数字员工 → 周任务、员工排期、发布日历、内容制作进度、灵小枢
> 设计依据：`docs/product/PRD-灵枢AI全系统UI设计规范-v2-2026-10-09.md`
> 本轮边界：只做本地开发、测试与验收；不部署、不发布、不主动调用付费供应商。

## 1. 先说结论

当前系统不是完全不能生产，而是“能创建周运行”和“能稳定产出完整成片”之间仍有断层。前面的阻塞会遮住后面的错误，不同节点又可能用不同口径解释同一份脚本、分镜、素材和数字人状态，所以页面会出现“已启动”“17%”“等待外部服务”等看似明确、实际无法回答用户下一步的问题。

修复后的理想链路只有一条：

1. 周任务启动只检查归属、版本、计划结构、预算边界和幂等，确保用户能进入生产队列。
2. 每条内容进入队列后，按同一份冻结逐镜清单依次完成爆款分析、脚本适配、素材路由、口播、数字人、合成和质检。
3. 普通缺口由 Agent 自己换路线或重试；只有确实需要用户提供的硬资料才暂停当前内容，不暂停整周。
4. 页面进度只认真实产物和真实回执，不根据模板工时或任务已创建来估算完成度。
5. 灵小枢始终知道用户当前看的周、任务和内容，只承接一个最重要的决定，并把复杂操作带到正确页面。
6. 只有拿到可播放成片、逐镜来源、供应商回执和质检结果，才宣布生产链通过。

## 2. 本次发现的问题

### 2.1 生产前的问题

| 问题 | 用户看到的现象 | 根因 | 严重程度 |
| --- | --- | --- | --- |
| 爆款分析口径不一致 | 灵感中心像是分析完成，进入生产后又提示镜头类型、时间线或复核缺失 | 上游只检查“有时间和画面”，生产门禁检查物理镜头、分类依据、全片覆盖和复核状态 | P0 |
| 预检出现得太晚 | 开始后才知道缺数字人、产品身份或素材 | 资料检查与逐镜执行没有使用同一份冻结清单 | P0 |
| 周任务门槛与单条内容门槛混在一起 | 一个镜头缺资料可能让用户以为整周不能开始 | 周启动、内容生产、正式发布三种门禁没有分层表达 | P0 |
| 数字人提示不完整 | 到数字人步骤才停，但灵小枢没有直接告诉用户去哪里录入和授权 | 后端能识别缺口，页面上下文和决策卡没有稳定绑定到当前内容 | P0 |
| 预算口径分裂 | 周预算、逐镜估算和供应商预占金额对不上 | 规划常量、执行报价和预算账本没有统一成一次冻结报价 | P1 |

### 2.2 正式生产后的问题

| 问题 | 用户看到的现象 | 根因 | 严重程度 |
| --- | --- | --- | --- |
| 进度可能失真 | 一个粗粒度 video 状态同时把口播、数字人和渲染画成完成 | 手动/直连内容沿用旧队列状态，没有逐阶段真实证据 | P0 |
| 暂停或人工接管不彻底 | 页面显示暂停，但后台执行任务仍可能继续，甚至产生费用 | 工作流运行和持久化执行任务是两套状态，缺少先封闭运行、再暂停任务的统一控制协议 | P0 |
| 卡点恢复不明确 | 页面停在一个节点，人工接管不可点或重试后重复建任务 | 没有记录“谁暂停、暂停了哪些任务、从哪个检查点恢复” | P0 |
| 中转页和重复进度界面 | 日历详情、数据复盘和内容制作各显示一套进度 | 缺少单一生产进度模型和统一深链 | P1 |
| Agent 协作断层 | 编导确认的是新逐镜方案，预算或素材执行却回读旧字段 | 上下游未共享冻结的生产清单和版本号 | P0 |

### 2.3 灵小枢的问题

| 问题 | 用户看到的现象 | 根因 | 严重程度 |
| --- | --- | --- | --- |
| 不知道当前任务 | 用户切到某条内容后，灵小枢仍回答最新目标或旧任务 | 数字员工页面只传了页面名，没有传 goal/run/task/content 身份 | P0 |
| 待办不随页面更新 | 收起再打开、切换内容后仍显示旧提示 | 关闭状态没有轻量刷新真实待办 | P1 |
| 只能提示，不能承接 | 缺数字人时没有“去录入数字人”的唯一动作 | 决策中心虽能生成企业资料深链，但前端没有稳定使用当前内容上下文 | P0 |
| 操作结果不闭环 | 点击开始后旧卡不消失，也没有准确结果提示 | 动作成功、运行状态刷新和待办刷新未绑定同一回执 | P0 |

## 3. 三层门禁，不能再混用

### 3.1 第一层：开始周任务

目标是让用户顺利进入真实生产队列，只检查：

- 当前租户和目标归属正确；
- 周计划版本没有过期；
- 至少存在可执行的内容结构；
- 预算有明确上限且不会隐式加额；
- 同一目标不会重复创建运行。

爆款分析、素材匹配、口播、数字人、合成和质检都不是整周启动门槛。缺其中一项时，周任务仍可启动，但对应内容必须显示真实的“待处理”节点。

### 3.2 第二层：单条内容调用供应商前

这是严格门禁，也是防止浪费费用的关键。每条内容按逐镜清单检查：

- 参考片已完成全片精确分析；
- 每镜有真实起止时间、镜头类型、叙事作用、分类依据和画面证据；
- 分析没有待复核镜头，时间线覆盖整段原片；
- 脚本版本、分镜版本和产品身份已冻结；
- 每镜已选可用素材、可执行 AIGC 路线或明确代拍；
- 数字人口播镜头已绑定租户内已授权、已发布、版本不可变的人物资产；
- 供应商能力可用，报价和本次预算预占已确定；
- 稳定请求键已生成，未知状态不得换键重复付费。

未通过时只暂停当前内容。页面和灵小枢必须用一句话说明“缺什么、去哪里补、补完后如何继续”。

### 3.3 第三层：正式发布前

生产完成不代表可以发布。发布前另行检查：

- 真实成片已经质检通过；
- 发布账号和渠道能力可用；
- 文案、内容版本和成片哈希没有变化；
- 用户或授权策略允许这次真实发布；
- 发布预算、排期和平台限制满足要求。

降低生产门槛不能绕过发布授权。

## 4. 唯一生产事实：冻结逐镜清单

所有 Agent 和执行器必须读取同一份、带版本号的生产清单，禁止各自回读旧脚本字段。最低字段如下：

| 范围 | 必须冻结的内容 |
| --- | --- |
| 内容身份 | tenantId、goalId、runId、taskId、contentId、familyId、平台版本 |
| 参考证据 | referenceId、analysisRunId、evidenceRevision、完整时间线 |
| 脚本 | 原片口播、企业适配口播、允许替换项、语言、版本 |
| 逐镜 | sceneId、referenceShotId、起止时间、画面证据、镜头类型、叙事作用、验收标准 |
| 产品 | productId、产品版本、身份参考图、不可伪造事实 |
| 素材路线 | 已选素材 ID / 数字人 / 产品 AIGC / 普通 AIGC / 代拍，及选择理由 |
| 数字人 | presenterId、publishedVersionId、授权状态、供应商映射、使用范围 |
| 执行 | provider、能力版本、稳定请求键、报价、预算预占、状态、真实回执 |
| 结果 | 产物 ID、哈希、时长、逐镜来源、质检回执、失败检查点 |

任何会改变脚本、核心画面、产品事实、预算或授权的修改都必须生成新版本；普通重试复用原运行、原产物和原请求键。

## 5. 分里程碑修复

### M0：冻结基线与问题证据

目标：先证明问题，不边猜边改。

- 固定一条真实内容作为验收任务，记录目标、运行、内容、逐镜、预算和产物 ID。
- 保存每个节点的输入摘要、输出摘要、耗时、责任 Agent、失败原因和下一步。
- 给已发现问题分配稳定编号，区分“旧问题被后续节点暴露”和“本次改动新引入”。
- 不再把 TypeScript、单元测试或“任务运行中”当作完整生产证明。

完成标准：同一任务可从日志和页面追到每个检查点，任一失败都能指出第一条不满足的合同。

### M1：先保证暂停、接管和费用安全

目标：用户点暂停或人工接管后，后台确实停止继续执行。

- 暂停工作流时，先将 run 置为禁止新调用的 fail-closed 状态，再逐个暂停该 run 的可执行任务。这不是跨存储原子事务；中途失败时依靠幂等重放收敛。
- `waiting_human`、人工控制器和暂停状态全部进入供应商调用总门禁。
- 记录由本次操作暂停的任务集合；恢复时只恢复这些任务，不误启动原本就暂停的任务。
- 同一 run 只允许一个活动人工接管；兼容历史重复接管数据时，只有最后一个活动接管归还后才恢复 run 和任务。
- 暂停、恢复、人工接管和 Agent 归还全部幂等。
- 已有供应商请求状态未知时保留请求键，先查回执，不重新提交。

本轮实现的 run 锁是单进程锁，可防止当前本地实例内的并发双接管，但还不是多实例数据库互斥。部署到多实例前必须增加数据库唯一约束或事务锁；“归还 Agent”也必须补上接管人/有权操作者校验，不能只靠租户、任务和活动 handoff 上下文。

完成标准：单实例内并发点击和重复请求不会多建任务；暂停后不出现新的付费调用；恢复从原检查点继续。多实例唯一性和归还权限完成后，M1 才能整体关闭。

### M2：统一生产前证据和数字人条件

目标：在进入付费阶段前一次性暴露当前内容的真实缺口。

- 爆款分析完成判断与生产准入复用同一个 `productionReferenceAdmission` 规则。
- 未确认镜头类型、观察窗口、待复核、时间线不完整或分析未完成，都不能标为“爆款分析完成”。
- 素材只读取本任务逐镜可能消费的候选，不扫描全租户全部文件。
- 数字人仅在真实人物口播/身份连续性镜头需要；普通 B-roll 不被误判为数字人。
- 缺数字人时给出唯一动作：“企业资料 → 人物与出镜 → 人物与音色资产 → 添加授权人物”，补完后从数字人节点继续。
- 数字人只有在已授权、存在已发布不可变版本、完成供应商映射、且当前用途落在授权范围内时，才算“可生产”；只上传一张人物图不算完成。
- 报价在供应商调用前冻结并汇总，超过周预算时只请求一次确认，不自动加额。

完成标准：开始周任务不被普通资料缺口卡住；进入供应商前能一次列出当前内容全部硬缺口，其他内容继续运行。

### M3：真实进度与 Agent 协作

目标：任何进度都能指向产物或回执。

当前页面统一为 7 个节点：

1. 爆款脚本分析；
2. 脚本确认；
3. 素材匹配；
4. 口播与字幕；
5. 数字人生成（不需要时明确“不适用”）；
6. 视频合成；
7. 成片质检。

参考来源、产品身份和授权不是被删除，而是作为分析、素材或数字人节点的准入证据与阻塞原因展示。内部运行态固定为 `pending / ready / running / waiting / blocked / completed / not_applicable / unavailable`，页面分别显示“未开始 / 已就绪 / 进行中 / 等待中 / 需处理 / 已完成 / 不适用 / 待同步”。

节点在当前界面只显示上述 8 种状态；底层队列的排队、等待外部服务、等待用户、暂停和失败必须映射成“已就绪 / 等待中 / 需处理 / 待同步”之一，并在节点说明中保留具体原因，不能另造一个与真实执行脱节的进度体系。节点完成必须满足：

- 分析：严格准入结果 ready；
- 脚本：冻结版本存在；
- 素材：逐镜路由和可消费资产存在；
- 口播：音频或可核验配音回执存在；
- 数字人：产物或供应商成功回执存在；
- 合成：真实可解码视频文件存在；
- 质检：质量检查回执通过。

禁止把一个粗粒度 `video=completed` 同时复制给口播、数字人和合成。进度百分比按适用节点的真实完成数计算，不适用节点排除分母。

Agent 边界：经营 Agent 管目标和预算；编导 Agent 管表达、脚本、分镜和验收标准；内容 Agent 管素材/能力路由和制作；客服 Agent 只承接用户沟通与补资料，不改制作事实。

完成标准：日历侧栏、内容制作页和 Agent 排期读取同一进度；刷新页面后状态不倒退、不跳步、不伪完成。

### M4：灵小枢承接当前任务

目标：用户走到哪里，灵小枢都知道当前对象和唯一下一步。

- 数字员工页面持续传递 page、goalId、runId、taskId、contentId、当前子视图。
- 用户点击日历内容时立即更新上下文；关闭侧栏后保留当前内容身份。
- 决策中心优先查询当前任务，不再默认取“最近一条目标”。
- 面板关闭时只做轻量待办刷新，用角标提示，不拉取执行日志。
- 缺数字人时显示简短说明和“去录入数字人”；缺预算时显示完整报价和“确认预算”；缺素材时进入当前内容的制作进度。
- 轻量动作成功后移除旧待办，出现一次准确结果气泡；等待、失败、暂停不能统称“正在生产”。
- 复杂逐镜编辑、素材挑选和授权仍在标准工作台完成，灵小枢只提供深链。

完成标准：连续切换两条内容，灵小枢的标题、原因和动作随当前内容变化；动作后旧卡不残留。

### M5：固定真实任务全链验收

目标：用一个真实任务证明整条链，而不是只证明模块能运行。

验收顺序：

1. 创建或复用一条周任务，确认只产生一个运行 ID；
2. 检查爆款分析、逐镜合同、产品、素材和数字人硬条件；
3. 让 Agent 自主完成脚本、路由和预算预检；
4. 在用户确认预算后才允许真实供应商调用；
5. 观察暂停、恢复、失败重试和未知回执恢复；
6. 生成可播放 MP4；
7. 核对时长、音轨、字幕、逐镜来源、哈希和质检回执；
8. 日历侧栏与灵小枢显示同一结果；
9. 不做真实发布，除非用户在当前任务另行明确授权。

完成标准：一次运行产生一份可播放成片，所有节点有真实证据，未重复付费，页面可从成片追溯到冻结清单。

## 6. 高频问题及系统应该怎样处理

| 高频问题 | 系统自动处理 | 需要用户时的唯一提示 |
| --- | --- | --- |
| 爆款分析缺镜头类型或时间线 | 回到同一参考片继续精确分析，不重建周目标 | “参考片还有 N 个镜头待确认，去完成分析” |
| 库内素材不够 | 按逐镜尝试产品 AIGC、普通 AIGC 或代拍，不暂停其他内容 | “当前 N 镜需要补素材，查看逐镜方案” |
| 未录入数字人 | 非人物内容继续；只暂停需要企业人物的内容 | “缺少已授权数字人形象，去企业资料新增并授权” |
| 数字人已录入但未发布/未授权 | 保留人物资产，不调用供应商 | “请发布并确认该数字人的制作授权” |
| 预算不足 | 保留已有产物，给完整增量报价，不自动加额 | “还需 ¥X，查看报价并确认” |
| 供应商超时 | 用稳定请求键查询原请求，禁止立刻换供应商重复提交 | “供应商状态待确认，系统正在查询原任务” |
| 参考片缺真实 ASR 口播 | 先用原请求键自动重试语音识别；确实无口播的镜头标为无对白继续，不伪造原片口播 | “该镜头有对白但仍无法识别，请补录原文后从口播确认继续” |
| 单镜失败 | 重试当前镜头或换等价路线，其他镜头继续 | “第 N 镜失败，可从当前节点继续” |
| 人工接管 | 停止当前运行的可执行任务并保留检查点 | “已暂停，不会继续产生新费用” |
| 后端暂时不可用 | 保留最后确认状态和页面，不把缓存冒充最新结果 | “服务暂不可用，已保留现有结果，重试连接” |

## 7. 自动化与人工验收矩阵

| 能力 | 自动化证明 | 页面证明 | 真实运行证明 |
| --- | --- | --- | --- |
| 分析准入一致 | 同一分析分别经过上游完成判断和生产准入，结果一致 | 未确认镜头显示待处理和补齐入口 | 精确分析完成后不再在生产阶段重复报相同缺口 |
| 周任务轻门槛 | 缺数字人的一条内容不阻止运行创建 | 周状态为执行中，当前内容为等待用户 | 其他不依赖数字人的内容继续推进 |
| 暂停/接管 | run 先 fail-closed、jobs 再逐项暂停，中断可幂等重放 | 按钮状态和节点状态即时一致 | 暂停后无新 provider 请求和费用 |
| 真实进度 | 每节点需对应产物/回执；不适用排除分母 | 三个入口显示同一节点和原因 | 刷新与重启后进度保持一致 |

### 8.1 ASR 失败的恢复规则

1. 先对同一参考片、同一版本、同一请求键重试 ASR，不重建周任务。
2. 证据表明原片无对白时，将镜头标记为“无对白”并继续分镜，不生成假口播。
3. 原片有对白且自动重试仍失败时，才进入“人工补录原文”。“人工接管”和“返回口播确认”必须可点。
4. 补录或确认后从原检查点继续，不回到第一步，不重复创建供应商任务。
