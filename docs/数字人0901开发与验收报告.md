# 数字人0901开发与验收报告

日期：2026-09-01
结论：**代码验收通过；数字人成片内部商业技术门禁通过；商品替换仅为受控MVP技术通过。**

## 1. 本轮完成

- 接收并审计测试服数字人口播闭环成果。
- 建立 `数字人0901` 远端交付分支的本地提交基线。
- 新增统一创作/替换协议：口播、换脸、换头、换整人、换商品和结构复刻。

- 新增换脸、换头、完整人物和局部商品的兼容性评估。
- 新增商业数字人二级门禁：极速模式与质量模式使用不同阈值。

- 新增H.264/AAC、嘴部稳定、清晰度、官方SyncNet和响度复验。

## 2. 指定任务成果验收

测试服原任务结果：SyncNet置信度4.862、音画偏移2帧、人脸跟踪100%、嘴部P95跳变0.0711，H.264 + AAC，6.173秒。

判断：适合作为极速模式/工程闭环验证，但低于本项目质量模式标准（SyncNet ≥7、偏移绝对值≤1帧），不得自动标记为高质量正式成片。本轮已在服务端增加二次商业门禁，避免底层Worker使用宽松阈值直接写回可发布素材。

该结果只证明轨迹、透明合成和编码链路可用。真实口红换眉刷仍需要经授权真人素材、新商品多角度资产、关键帧校正，以及原商品残留、手指遮挡、接触点、反光和品牌外观人工验收。

## 5. 已定位卡点及处理

| 卡点 | 根因 | 处理 |
|---|---|---|
| 测试服成片被宽松门禁放行 | Worker阈值3.0/3帧，业务层信任 `passed` | 业务层增加 `commercial-v1` 二次门禁 |
| 旧高同步成片嘴部跳变/模糊 | 口型生成与多次压缩 | 光流中间帧、有限时序平滑、锐化与低损重编码 |
| 字幕重编码后P95由0.0828升至0.0854 | CRF 16造成细节损失和关键点微抖 | 改用CRF 10慢速编码，最终0.0847 |
| D盘工作树运行Windows Node/tsx崩溃 | 当前Windows Node从该D盘路径执行出现原生异常 | TypeScript完成静态检查；纯策略测试编译后复制到C盘临时目录执行 |
| C盘仅余约23.8GB | 多模型与历史资产占用 | 后续代码、测试数据和成片全部迁移D盘，不删除其他任务资产 |
| GitHub推送连接长时间无数据 | 当前Git HTTPS链路阻塞 | 保留完整本地提交与分支，后续重试同一远端，不改写历史 |
