# S7：三渠道真实发送与异常恢复

本轮完成 WhatsApp 周跟进的指定真人回执恢复，以及 Messenger、Instagram 私信发送前的持久请求与防重发。未执行真实客户消息发送。

## WhatsApp 周任务

异常来源必须是实际已绑定运营周、原客服运行、已审批批次及条目。人工请求明确负责人、带时区截止、审批版本与内容哈希、消费者和本次发送标识；界面仅返回发送标识哈希与收件人尾号。

只有租户已验签 Webhook、实际业务账号与号码匹配、当前 claim 对应的每个消息序号均有真实终态回执，指定真人才能恢复原跟进任务。旧审批、错收件人、错误请求标识、部分消息、无签名或未知结果均不能完成。恢复只对账已发送消息，不发送、不推进整个运行。读取已恢复请求时重新核验实际原任务及完整批次消息，返回当前 `resolvedProof`，历史 `resolvedAt` 不能永久证明完成。

## Messenger 与 Instagram

实际私信端口在供应商调用之前保存请求，冻结租户、真实成员、渠道、客户、实际账号原生身份、收件人、正文哈希与请求 ID。相同 ID 重放已接受请求时返回原回执；本地历史缺失可以仅使用原回执和冻结正文补写。

查未决意图、首次登记和供应商回执保存共用持久租约。`sending` 或 `unknown` 请求保留持久意图屏障，租约过期或换新请求 ID 都不能再次发送同一未决内容。真实已接受回执保存后释放该屏障，用户明确的新意图可以再次发送同样正文，不把所有历史相同文本永久去重。

只读上下文接口返回实际租户、成员、客户、渠道、账号与原生身份哈希。已接受表示供应商接受，不能等同投递或已读。对账只允许已知真实供应商 MID、原生账号与收件人精确匹配的租户已验签事件；只有时间水印或相同正文不能猜测请求身份。无 MID 的超时保持 `provider_identity_gap`，不自动重发。

## 保留缺口

- 直接 M/IG 私信请求尚未声明或核验运营周、逐客审批与冻结周任务消费者，不能把直接发送成功计为周任务完成。后续须接实际渠道成员选择、批次审批及专用周派单。
- 无供应商 MID 的未知 M/IG 发送不能靠当前回执模型确定是哪次请求；需要可核验的供应商请求身份或明确的平台对账能力。
- 知识缺口、报价承诺、寄样或会议处理是其它 S7 子链路。本模块不凭人工描述生成企业事实，不以转人工或任务标题代表业务处理完成。

## 验证边界

测试使用实际持久结构、已有租约与回执导入模块；供应商调用使用无外发的受控测试端口。覆盖同 ID、不同新 ID 并发、租约过期、未知结果、旧审批、错误身份、部分消息、历史补写与当前回执重验。测试证明本地防重复和凭据边界，不代表对真实客户已发送或完成运营任务。

## 周经营 Messenger / Instagram 显式发送

`weeklyNativeFollowupDispatch` 读取实际周绑定、最新分群、指定消费者、渠道选择回执及原审批版本/全批次哈希；人工动作复核原单条已批准状态、逐客发送时间、时区工作窗口、24小时消息窗口和渠道授权。真人接管权限使用同一真实会话的持久门禁。发送由原生端口登记 durable 请求，并冻结周经营 authority；直接私信的普通 MID 不能完成周任务。

原 WhatsApp 批量 worker 不发送 Messenger / Instagram 条目。周经营回核逐项读取实际 ledger；全部当前消费者证据齐全后，仅结算原 followup_dispatch 任务，不推进整 run。平台已接受而任务结算写失败时，人工重入只核原凭据及修复投影，零重复发送。accepted 与 delivered/read 保持区分；无 MID 或未知结果保留原请求，不文本猜测。

本轮测试使用真实存储/选择/审批/ledger 逻辑和受控供应商端口，不进行外部消息发送。原生周发送的 unknown 仍需已验签平台回执及明确真人处置；无 MID 不自动恢复。客服知识、报价审批等其它 S7 子链不因这一发送闭环被视为完成。

## 原生渠道发送异常的指定真人任务

`weeklyNativeSendRecovery` 将真实周经营账本请求转为独立持久任务，冻结原 requestId、原发送人、经营周/原运行/原派发任务、审批与选择哈希，并记录指定负责人、明确时区截止和原因。来源与任务读取权限核验实际租户用户角色，恢复动作仅指定负责人可执行。保存后的截止不会因为逾期或重试重置。

unknown/sending 无平台 MID 不能输入 MID、截图或相似文本核销；创建任务也不会清除原发送防重围栏。accepted 回核依然使用原发送 actor 和原 requestId，确认历史已写回、平台没有已知失败、所有当前批次凭据真实通过后，仅修复原任务投影，零发送、零 run 推进。独立安全/真人处理阻断不会被发送回核清空。

恢复命令使用持久 lease，完成后版本递增；未知网络响应后应读取实际任务和动态 resolvedProof。该 proof 每次重新检查原任务身份、完整当前批次与原渠道请求，并返回实际批次凭据快照哈希。原任务替换、审批/来源漂移或凭据缺失不能视为完成。对于没有 MID 的未知请求，本轮提供真实人工待核对任务，但仍不宣称已解决平台身份缺口。
