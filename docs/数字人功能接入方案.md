# 灵枢数字人功能接入方案

> 本文保留数字人第一版的接入背景与基础架构。脚本驱动表情、动作和场景的后续开发，以 [《表现型数字人 V2 产品与开发规划》](./表现型数字人V2产品与开发规划.md) 为当前执行基线。

## 1. 结论

数字人不应作为独立工具页接入，而应成为「社媒 / AI 生成内容」工作台的一种人物素材生产能力：

`脚本与声音 → 数字人口播生成 → 回填真人口播素材库 → 分镜选材 → BGM / 字幕 / 封面 → 成片 → 发布`

现有系统已经拥有脚本、TTS、字幕对齐、素材库、分镜匹配、桌面/服务端 FFmpeg 渲染、草稿、版本和发布能力。数字人模块只负责生成“带正确口型和人物动作的透明业务素材”，不重复建设后续剪辑链路。

## 2. 当前代码现状

- 前端入口位于 `src/components/AiCreateStudio.tsx` 的「真人口播」素材文件夹。
- `generateDigitalHumanPresenter()` 当前只下载原视频并重新上传，实际没有执行数字人生成。
- 系统已经具备：
  - AI/上传配音与多语言版本；
  - TTS 字幕对齐；
  - `studio_projects` 草稿持久化；
  - 租户隔离的素材存储及对象存储；
  - 本地和服务端 FFmpeg 成片；
  - 分镜脚本质量检查和视频版本管理。
- 当前缺少：数字人模板、异步任务、驱动引擎、任务进度、失败重试、人物专项质量报告和生成授权记录。

## 3. 用户交互

### 3.1 创作入口

在「分镜与声音」中，用户生成或上传配音后选择画面人物模式：

1. 不使用人物；
2. 使用真人原片；
3. 生成数字人口播。

选择数字人口播后展示：

- 数字人形象：从企业数字人库选择；
- 驱动声音：默认使用当前语言已确认配音；
- 表现风格：专业讲解 / 热情带货 / 沉稳可信 / 自定义；
- 景别：近景 / 半身；
- 背景：保留原背景 / 绿幕 / 透明通道（引擎支持时）；
- 生成模式：极速 / 高质量；
- 预计时长、资源消耗和素材授权提示。

点击生成后不阻塞页面，用户可继续编辑其他分镜。

### 3.2 任务状态

在人物卡片和全局任务中心显示：

`排队 → 预处理 → 人物驱动 → 口型同步 → 包装 → 质量检测 → 待审核 / 已完成`

失败时必须显示具体阶段，并允许从失败阶段重试。质量未通过的结果不能自动进入正式成片，但可以作为“需复核版本”预览。

### 3.3 结果回流

合格结果自动保存至「真人口播」文件夹并自动选中，素材应带有：

- `sourceType = digital-human`；
- 形象、声音、脚本和引擎版本；
- 口型、画面、响度、授权状态；
- 父素材和父任务；
- 生成时间及版本号。

之后完全复用现有分镜匹配、字幕、BGM、封面、渲染与发布流程。

## 4. 后端架构

### 4.1 驱动接口

建立统一 `DigitalHumanProvider`，避免 UI 与具体模型绑定：

```ts
interface DigitalHumanProvider {
  id: 'latentsync' | 'liveportrait-latentsync' | 'cloud-avatar';
  capabilities(): Promise<DigitalHumanCapabilities>;
  submit(input: DigitalHumanInput): Promise<{ providerTaskId: string }>;
  poll(providerTaskId: string): Promise<DigitalHumanProviderStatus>;
  cancel?(providerTaskId: string): Promise<void>;
}
```

建议供应策略：

- 极速模式：现有母片 + LatentSync，保证身份稳定和低失败率；
- 增强模式：LivePortrait 表情/头部驱动 + LatentSync 口型；
- 高质量模式：云 GPU 上的生成式 Avatar，引擎成熟后再开放。

### 4.2 API

新增路由 `server/routes/digitalHuman.ts`：

- `GET /studio/digital-human/avatars`：列出当前租户可用形象；
- `POST /studio/digital-human/avatars`：创建形象模板并执行母片预检；
- `POST /studio/digital-human/jobs`：提交脚本、音频、形象和表现参数；
- `GET /studio/digital-human/jobs/:id`：任务状态、进度和质量结果；
- `POST /studio/digital-human/jobs/:id/retry`：从允许的阶段重试；
- `POST /studio/digital-human/jobs/:id/cancel`：取消排队或运行任务；
- `GET /studio/digital-human/jobs/:id/versions`：查看和选择生成版本。

服务端负责鉴权、租户隔离、配额、素材签名和结果入库。Python/GPU 进程只接收短期签名输入并回传任务结果，不能直接访问整个租户目录。

### 4.3 数据模型

新增 PocketBase 集合：

#### `digital_human_avatars`

- `tenant_id`
- `name`
- `source_material_id`
- `thumbnail_file_id`
- `consent_status`
- `commercial_rights_status`
- `preflight_report`
- `status`
- `created_at`, `updated_at`

#### `digital_human_jobs`

- `tenant_id`, `project_id`, `avatar_id`
- `language`, `script_snapshot`, `voiceover_material_id`
- `provider`, `provider_version`, `mode`
- `status`, `stage`, `progress`, `error_code`, `error_message`
- `input_snapshot`, `quality_report`
- `output_material_id`, `parent_job_id`, `version_number`
- `created_at`, `started_at`, `completed_at`

任务输入必须保存快照，避免用户修改脚本或配音后生成结果无法追溯。

## 5. 与现有模块的具体连接

### 脚本和TTS

- 使用当前 `voiceDrafts` 与 `voiceoverAudios`，禁止数字人模块再次独立生成一套配音。
- 音频或脚本改变后，将关联的数字人结果标记为 `stale`，提示重新生成。
- 当前语言切换时切换对应数字人版本；未生成的语言显示待生成状态。

### 素材库

- 生成结果继续使用现有 `Material`，避免下游识别两套资产类型。
- 扩展 `Material` 的可选 `generation` 字段，或通过 `digital_human_jobs.output_material_id` 关联元数据。
- 人物母片、驱动音频和生成结果均走现有租户私有对象存储。

### 分镜与成片

- 数字人口播首先是一条人物视频素材，可以分配给一个或多个完整语义镜头。
- 不要把一条完整数字人视频重复裁成多个不连续人物镜头，否则动作会跳变。
- 正式成片仍由现有 `RenderManifest` 和 `desktop/render.cjs` 负责；后续将已验证的字幕层级、人物画面保护和 EBU 音频规范迁入该渲染器。

### 草稿和版本

- `StudioProject.spec` 保存选中形象、任务和各语言数字人版本。
- 新脚本/新声音生成新任务版本，旧版本可回看，不覆盖。
- 现有 `video-versions` 负责最终成片版本；数字人任务版本只负责人物素材版本，两者不要混成一张表。

### 发布与合规

- `commercial_rights_status !== cleared` 时禁止进入正式发布，只允许内部预览。
- 首次创建人物形象必须记录肖像授权和用途范围。
- AI 生成人物内容应保留可追溯标记、模型版本和输入快照。

## 6. 质量门槛

自动检测：

- 输入画幅、帧率、人脸完整度和遮挡；
- 双嘴、嘴部几何异常和人脸漂移；
- 音画偏移和口型置信度；
- 眨眼、视线、头部运动和静止时长；
- 黑帧、冻结、重复范围；
- EBU R128 响度和真峰值；
- 输出时长、分辨率和编码；
- 字幕安全区及人物脸部遮挡。

人工审核仍需确认：身份一致、牙齿和手部、声音与人物匹配、动作是否符合语义、商业观感和授权。

## 7. 开发阶段

### P0：替换假入口

- 新增任务 API 和前端任务卡；
- 接入现有 LatentSync 本地服务；
- 绑定当前语言真实配音；
- 输出回填素材库；
- 保存质量报告；
- 删除“复制原视频即生成成功”的现有行为。

### P1：产品化

- 数字人形象库、母片预检和授权状态；
- 多语言批量生成；
- 失败重试、取消、版本选择和配额；
- 草稿恢复和任务中心；
- 迁入已验证的字幕/音频/人物保护渲染规范。

### P2：自然度突破

- 接入 LivePortrait + LatentSync 增强驱动；
- 建立专业讲解、强调、疑问和 CTA 动作模板；
- 同脚本 A/B 对比不同驱动引擎；
- 云 GPU 高质量生成式 Avatar 灰度测试。

## 8. 第一版验收条件

1. 用户从已确认配音一键提交数字人任务；
2. 页面刷新后任务仍存在并可继续查看；
3. 任务完成后自动出现于租户「真人口播」素材库；
4. 可直接用于当前分镜、字幕、BGM、封面和成片渲染；
5. 脚本或配音变化后旧结果明确失效；
6. 质量未通过或授权不完整时不能发布；
7. 任一租户无法访问其他租户的形象、音频、任务和输出。
