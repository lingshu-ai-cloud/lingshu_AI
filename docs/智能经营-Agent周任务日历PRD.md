# 智能经营：Agent 周任务日历 PRD

版本：v1.11 · 2026-10-10

状态：两套 B2B 主副链路及排期正在联调；真实执行、成片和生产环境验收尚未完成。

依据：[产品开发文档（PRD）框架，4.9–4.11](https://chatgpt.com/space/page_97692079ed2881919045cccffb5d0bd9)。本文件描述目标产品行为，不表示所有行为已接入真实后端。现有不同任务链保留自己的身份、状态、版本及执行边界。

## 1. 目标与交付步骤

用户打开智能经营页面 2，按周一至周日查看每天最终交付什么以及哪个 Agent 对结果主负责。内部倒排、开始时间和多 Agent 协作节点默认收在任务详情中，不把每个生产步骤都拆成日历卡。只有系统无法自主解决且确实需要用户提供真实素材、授权或关键确认时，才显示人工异常任务。

三层工作：①确认职责、产物和主副链路；②确认七天排期、画像策略、卡片与交接规则；③实现前端并验收。每层完成后由用户确认。当前先实现前端；真实生产场景跳转在前端验收后单独接入。

### 1.1 新手初始化与首次推荐计划

首次使用只要求完成三步必要配置，减少用户在尚未看到经营结果前填写大量表单：

1. **公司与品牌**：录入公司名、品牌名。系统创建企业主体，允许两者相同。
2. **产品识别与主推确认**：录入或导入产品信息后，系统展示“识别到 X 个产品，推荐其中 2 个作为本期主推”。用户确认或修改主推产品即可继续。缺失的规格、证据、企业事实或素材明确提示“稍后可在「灵小枢 > 企业信息」补充”，除非缺口会导致当前计划无法合规执行，否则不阻断首次计划生成。
3. **数字人形象**：从已授权企业数字人、系统可用数字人或创建入口中选择默认形象。真人口播镜头默认使用所选 AIGC 数字人；没有可用或可授权数字人时，计划明确标出缺口和替代方案。

第三步完成后直接弹出**推荐计划**，不要求用户先进入复杂设置页。推荐计划至少展示：

- 主推产品、目标市场和内容语言；
- 建议经营平台与具体账号，以及每个账号本周发布数量；
- 以最终产出为中心的 Agent 周排期；
- 预计费用范围、预算上限和预计交付时间；
- 两个操作：**“确认计划并开始制作”**、**“调整计划”**。

“确认计划并开始制作”一次性确认当前计划版本、预算上限和自动生产范围，并启动满足条件的数字员工任务流；它不等于提前确认尚未生成的成片，也不自动授权尚未绑定账号的真实发布。“调整计划”允许修改主推产品、市场、语言、平台、账号、数量、预算和交付时间，修改后重新计算产能与排期。

系统根据现有账号及历史内容识别 B2B 零基础或 B2B 有基础。用户可以在推荐计划中修正画像：

- **B2B 零基础**：首周参考来源为外部 100%，直接生成冷启动计划。
- **B2B 有基础**：增加一个可选步骤，允许一次录入各平台历史账号。账号信息入库后立即发起历史内容及播放、点赞、转发、评论数据采集，用于调性提取和自有／外部来源配额建议。此处允许只做采集，不强制完成发布授权。
- **延后绑定发布账号**：当成片已经制作并即将进入发布准备，而目标账号仍未绑定时，系统生成一张明确的人工“绑定发布账号”异常卡。绑定完成后恢复原发布任务，不重复制作成片。用户也可在初始化时直接绑定，避免临近发布再处理。

首次推荐计划要区分“可立即自动执行”“制作可执行但发布待绑定”“缺少必要输入”三种状态。历史账号采集凭据、平台发布授权和客服渠道授权分别管理，不能因为允许历史采集就推断已经允许发布或发送消息。

## 2. 四个 Agent

| Agent | 责任 | 核心产物 |
| --- | --- | --- |
| 经营 | 目标拆解、对标需求、预算与账号产量、详细排期、派单、发布及复盘 | 周任务骨架、确认排期、派单、发布审批与真实回执、经营复盘 |
| 编导 | 参考采集与分析、选题依据、脚本分镜、执行方案复核及内容审核 | 对标证据、脚本、逐镜目标、验收要求、复核与返工结论 |
| 内容 | 素材与逐镜执行方案、数字人/生成路线、制作与质检 | 执行方案、逐镜结果、成片、音轨字幕、封面、平台版本、检测与交付包 |
| 客服 | 询盘处理、来源归因、分层、回复与跟进、转人工 | 客户快照、逐客草稿、审批批次、发送回执、转人工与客户结果 |

统筹、Worker 和调度不是第五个业务 Agent。技术质检属于内容能力；编导负责相应内容审核。经营提出对标需求，编导完成对标分析，经营将结论转成计划。

### 2.1 编导与内容的逐镜交接边界

每个镜头以同一个不可重复 `sceneId` 贯通编导需求、内容执行方案、审核、真实执行与证据。编导定义表达目的、画面主体/主题、主体动作、景别、机位、运镜、时长、口播/字幕、必须出现的产品细节、事实/语气边界和创意验收条件。内容读取这些要求后决定素材来源范围、实际检索条件、候选与最终素材、匹配/AIGC/数字人/混合路线、具体模型与输入参数、预计成本和耗时，并保存执行与技术证据。

编导不能在创作需求里指定具体素材库记录、供应商或模型；可声明必须使用企业素材、真实证据、授权人物等必要边界。内容先提交逐镜素材与技术方案，编导只在需要的节点审核创意适配；素材不足时内容返回具体缺口。任何影响核心表达、企业事实、权利或已确认预算的变化均进入修订/授权链，不能静默降级，也不能把通用或合成素材标成企业实证。缺失、重复或找不到的 `sceneId/referenceShotId` 一律阻塞对应镜头，禁止按数组顺序借用其他镜头。

### 2.2 素材分类权威

用户素材筛选沿用现有主题 ID：`talking_head`（人物口播）、`factory`（工厂实况）、`product`（产品实拍）、`consumer_demo`（`DtoC`）；来源沿用 `local_upload`、`official_import`、`user_generated`。逐镜中的 `factory/customer_case/product/person_usage/presenter/environment/general` 是制作角色维度，不能另建一套同名主题或擅自改写 `DtoC`。保存的主题、来源、分类状态、分类来源与证据必须原样读回；人工选择标签只证明标签被选择，不自动证明事实、权利或画面质量已核验。

## 3. B2B 零基础：外部参考冷启动链路

目标：建立可验证的企业表达、首批自有内容和询盘承接。首周所有内容 Agent 待复刻参考均来自外部；不要求用户具备历史视频、历史询盘或既有调性。

### 3.1 八个主环节

| --- | --- | --- | --- |
| Z-M1 建立经营基础与对标需求 | 经营读取产品事实、市场、目标买家、预算和账号；客服协助确认承接知识 | 首周任务骨架、企业资料缺口、账号/承接就绪清单、外部对标需求 | 对标需求交 Z-M2；配置与事实补齐可并行，缺账号授权阻止发布而非全部分析 |

| Z-M8 冷启动复盘与下周建议 | 经营汇总内容与客户结果，编导提供内容总结 | 首批真实基线、有效询盘、卡点、调性初稿、模板候选与下周建议 | 未成熟数据保留待观察；本周新产物不改变已确认的外部参考订单 |

| Z-S7 首批客户转人工/发送异常 | 客服发现知识缺口、报价承诺、部分发送或未知结果；交草稿/原因，由指定人处理 | 核验后恢复 Z-M7；知识沉淀回企业资料 |

| Z-S9 跨周延续与画像升级建议 | 经营保留未结拍摄/制作/数据观察任务；编导整理首批合格自有参考 | 原任务延续且去重；有足够自有证据后提出混合来源建议，由用户确认后生效 |

## 4. B2B 有基础：历史迭代＋外部探索链路

目标：保留本账号有效调性和销售承接，同时验证外部新方向。先审计历史及可用证据；自有/外部母版配额由经营建议、用户确认。任务来源相同并不代表原始素材、历史权利或数据一定就绪。

### 有基础用户的来源配额规则

比例顺序统一为“本账号自有历史参考／外部参考”，按待制作母版任务数量计算，平台版本不重复计入。

| 账号情况 | 自有／外部 | 每周 10 条母版示例 | 确认状态 |
| --- | --- | --- | --- |
| 历史内容持续带来合格询盘 | 70%／30% | 7 条自有迭代＋3 条外部探索 | 产品建议，待用户确认 |
| 调性清晰，但获客效果一般或增长停滞 | 40%／60% | 4 条自有迭代＋6 条外部探索 | 用户已确定 |
| 有历史视频，但可用素材不足，或播放量及赞转评表现较弱 | 20%／80% | 2 条自有迭代＋8 条外部探索 | 用户已确定 |

该档位依据历史视频的播放量、点赞数、转发数和评论数判断，不使用“有效消耗”。经营 Agent 保存可用素材情况及上述指标，编导结合具体视频判断可复用价值。比较需保留平台、发布时间和观察窗口；各指标阈值与组合规则待定义，缺数据标为未知，不自动归为表现弱。该来源档位判断与后续有效询盘、销售推进的业务复盘分别记录。

经营 Agent 按适用档位生成具体条数，编导审核合格参考能否支持这些任务。建议整数分配采用四舍五入计算自有条数，外部条数等于总母版数减自有条数；小批量显示实际比例，并避免为凑比例新增制作量。素材或参考缺口触发 H-S1/H-S2，不以比例配置代替就绪检查。

上述档位决定初始建议，后续修改按确认和修订流程处理。外部比例提高时，仍沿用本账号调性规范；不是按比例放弃品牌表达。

## 4.4 共用技术与不同业务边界

两类共用参考分析、版本化脚本/逐镜方案、素材匹配、数字人/生成、渲染质检、审批发布、真实回执和持久恢复；业务任务、输入门槛和复盘产物按 Z/H 链分别定义。

交接关联租户、目标、计划版本、run/task、视频/客户批次、参考来源、分析版本、产物及上游依赖。每环节执行任务指定一个主负责 Agent，协作 Agent 分别交付子任务；链路表多人协作不意味着无人主负责。

首周冷启动不因没有历史数据生成历史审计/自有迭代任务；有基础不省略历史审计、调性提取、双来源配额或老客跟进。画像缺口不能被前端模板填充为虚假已完成状态。

## 5. 七天日历与卡片

仅设时间横轴，周一至周日，无 Agent 纵轴。每天按**计划完成时间**展示最终产出卡；卡片所在时间点默认表示产出完成时点，不表示任务开始时间。用户只需看到“周三完成视频 A 成片”，无需在日历上看到周一素材盘点、周二分镜和周三质检等过程卡。

一项可独立验收的最终产出只显示一张卡，例如成片、正式发布、周经营方案、周复盘或客户承接结果。卡片展示标题、计划完成时间、主负责 Agent、最终交付物、状态和必要异常提示。协作 Agent、内部开始时间、依赖、成本、逐镜状态和执行证据收在详情中。

例：`周三 15:00 · 完成产品 A 安装视频 · 主负责：内容 Agent · 交付：1 条母版与 2 个平台版本`。用户点击后查看经营、编导、素材、内容、审核和发布准备等内部节点。避免用“内容 Agent 今天工作”代替可验收任务，也避免把每个节点拆成占满日历的卡片。

卡片详情中的内部任务流可以由多个 Agent 分别负责，但共同服务于同一个产出：经营 Agent 定义目标与交付时间；编导 Agent 分析参考、脚本和分镜；内容 Agent 完成素材路由、数字人、AIGC、剪辑和技术质检；编导 Agent 自动完成创意验收；发布 Agent 能力由经营 Agent 统筹。内部节点保存自己的计划起止时间、输入、输出、责任 Agent 和状态，用于调度与追责，不默认出现在周日历。

只有同时满足以下任一条件，才另建用户可见卡片：①它本身是用户关心的独立经营成果；②它必须由用户完成；③它是会影响交付的异常且系统没有自动替代路线。普通素材盘点、逐镜生成、自动质检和数字员工审核都属于内部节点。

计数分开显示母版、平台版本、发布次数、客户跟进数；1 条母版发 3 个平台不是 3 条原创。预计工时不冒充实耗，平台回执不与规划数量混算。

初步周节奏：周一骨架/首批对标/素材准备；周二详细排期/脚本/首批制作；周三至周六滚动制作、审核、发布、客服跟进与数据追踪；周日复盘及下周首批准备。稳定运行可衔接上周已验收库存；首周无库存则不承诺周一即发布。

均衡按各 Agent 容量和工时排布，不能靠每天固定四张卡伪造均衡。七天都有可交付工作不等于真人必须七天上班；真人非工作日和客户当地工作时段必须进入排期约束。

点击卡片先打开任务详情；存在真实生产对象时显示“进入生产实况”。深链按具体对象定位到编导分析/脚本、内容生产/逐镜匹配/数字人/渲染、经营发布/复盘或客服会话/跟进批次，并自动选中当前节点或受阻镜头。返回后恢复原周、日期和卡片位置。预览数据只展示详情，不能冒充已经接入真实生产现场；页面进度只读取真实执行证据。

## 5.1 按发布目标倒排与可达性

两类 B2B 共用时间约束：先确定每个账号、平台、视频的实际发布时间；成片、质检、所需用户验收和发布准备最晚在发布前一天完成。周一发布须在上周完成准备，不得把周一首次配置和当天新视频发布同时承诺为可达。

经营定义目标与发布窗口；编导逐条预判脚本、必需素材和替代边界；内容提供阶段估时、并发和素材生成/真人上传需求。以发布为终点倒排审批、质检返工、渲染、逐镜执行、脚本和素材截止，预留明确缓冲。共用素材只创建一个任务，关联所有消费者，截止取最早消费者开始使用前的时间。

计划必须核验预算、执行能力、Agent/供应商并发、人工工作时段、上传及审批容量。产能冲突须前移准备或提交目标/窗口调整，不能仅平移时间制造表面可达。发布数量、母版数量和平台版本数量独立统计。

零基础：外部参考分析与企业事实/首批素材就绪是冷启动输入；提前启动到上周，无库存或必要资料不足时明确风险。已有基础：先审计合格库存、自有素材和历史参考，按双来源配额分别倒排；库存发布不计新增母版，历史素材仍需核验权利与适用性。

新增明确内部节点类型：目标可达性检查、参考与脚本锁定、共用素材准备、自动审核、发布准入、库存准备、依赖变化影响评估。这些节点分别归入对应 Z/H 主副链路，非新增 Agent，也不默认投影为用户日历卡。只有真实发布授权、关键事实确认等必须由用户决定的例外才设置人工截止。

任何截止、素材或参考变化都重新沿依赖评估：受影响视频、平台发布、剩余可达数量、追加成本及补救选择。上传逾期标红；未逾期但已不足制作与验收时间时提前标发布风险。替代素材、库存、制作重排或发布修订需保留证据与确认，不自动改变冻结来源或绕过验收。

### 5.1.1 倒排的显示边界

倒排会生成可执行的内部节点和调度时间，不等于给用户生成同等数量的日历卡。以“周三 15:00 完成视频 A”为例，系统可以在后台依次安排经营目标冻结、编导分析、素材盘点、数字人及关键镜头生成、剪辑、自动质检和编导验收，但日历仍只显示周三的成片产出卡。

内部节点由独立 Agent 负责，并记录最晚完成时间；产出卡的主负责 Agent 对最终交付负责。共享素材如果由数字员工自动检索或生成，作为多个视频任务共同引用的内部资产任务存在，不单独占用用户日历。只有需要用户拍摄、上传或授权时，才投影为人工异常卡。

### 5.1.2 素材盘点、共享判定与分层生产路由

内容制作前必须先做本地企业素材库盘点。系统读取真实文件、产品和人物关联、来源、授权范围、画幅、时长、质量检测和历史使用记录；不能只根据文件名或用户选择过某个标签就判断可用。

共享素材按“同一主体、动作、场景、证据要求、规格和授权范围”判定。只有这些条件一致，且同一素材可以满足所有目标视频的逐镜要求时，才合并为一个共享资产任务并绑定多个消费者。不同产品批次、客户案例、检测结果、人物授权或构图要求不得为了减少任务而强行合并。

编导 Agent 在参考分析阶段先为每个镜头标注叙事角色，再由内容 Agent 选择生产路线：

1. **真人口播**：必须调用已授权的 AIGC 数字人素材。编导给出人物功能、情绪、动作、景别、视线、语速和口播节奏；内容 Agent 选择企业默认数字人并生成。指定真人真实性或授权无法满足时进入异常链，不以普通人物库存替代。
2. **关键非数字人镜头**：开场钩子、关键产品动作、结果揭示、核心转折、音画强同步镜头和主要事实证明镜头，优先使用 AIGC 或基于企业真实素材的受控生成，高程度还原参考镜头的构图、主体动作、景别、运镜和节奏。不能用同题材通用库存素材简单补位。涉及真实能力、检测结果、客户案例或产品功能时，必须绑定可验证企业素材，不得生成不存在的事实。
3. **普通支撑镜头**：环境、氛围、转场和说明性 B-roll 采用“素材库精准匹配 → 素材库近似匹配 → AIGC 生成”的自动路线。

编导 Agent 对参考视频前五秒逐镜分析，至少输出：第一个有效画面的出现时间、前三秒镜头数、主体类型、冲击来源、人物是否直视镜头、首句口播起点、字幕/音效/音乐重拍与切镜关系，以及移除该镜头是否明显削弱开场。开场进一步分为：

| 开场类型 | 判定特征 | 默认生产方式 |
| --- | --- | --- |
| 冲击人物口播 | 人物快速入场、直视镜头、强问题或强结论 | AIGC 数字人复刻人物表达和时间节奏 |
| 产品动作钩子 | 产品操作、拆解、测试或结果立即出现 | AIGC 高还原镜头；事实性内容绑定真实产品证据 |
| 强节奏快切 | 多个短镜头与音乐、音效或字幕卡点 | 逐镜生成或真实素材重构，复刻剪辑时间结构 |
| 结果先行 | 先呈现前后对比、效果或最终成果 | 使用可验证结果素材；证据不足时改写表达 |

只有开场吸引力主要来自通用题材，不依赖特定主体、构图、动作或音画节奏时，才允许素材库直接替代。关键镜头生成后自动检查首帧冲击、主体一致、动作连续、产品身份、音画同步和事实边界；失败时逐镜重做并继续同一生产任务。

默认由数字员工完成素材识别、授权字段检查、逐镜适配、生成和质量门禁，不设置常规“人工素材核验”卡，也不把人工点击作为后续任务的必要前置。系统无法自动确认的真实授权、指定真人或关键事实才生成异常任务；其余视频继续执行。

### 5.2 贯穿主副链路的调度交付

以下任务归入已有八个主环节和九类副链路，不增加业务 Agent。每项有独立任务身份、输入版本、负责人、截止及交付证据；计划卡不等于执行完成。

| 调度链路 | 主负责与交付 | 零基础 Z | 有基础 H |
|---|---|---|---|
| 发布目标倒排与可执行性检查 | 经营交逐条发布时间、前置截止、缓冲、可达数量和缺口；编导及内容提供依赖与估时 | M1/M3；首次资料准备计入工期，无库存不能承诺当天发布 | M1/M3；先核验库存，再分别核验自有与外部路线 |
| 共享素材准备与消费解锁 | 内容交核验通过的素材版本及消费者清单；编导交必需镜头要求 | S1/S2；企业基础素材先于最早消费任务完成 | S1/S2；先查合格历史资产，缺口才新增拍摄或生成 |
| 自动审核与例外人工处理 | 编导/内容 Agent 自动交事实边界、创意和技术检查结论；只有无法自动确认的授权或关键事实才指定人工负责人 | M4/M5/S2；默认自动通过可验证规则，例外进入人工异常链 | M4/M5/S2；自动核对历史调性与创新边界，例外进入人工异常链 |

#### 触发、截止与恢复规则

1. 发布承接检查绑定具体发布 CTA；必需承接失败阻塞该发布，非必需渠道缺口单独提示。检查必须早于发布准入截止；入口、产品资料或接待人改变后重新核验，已发布历史记录不被覆盖。
2. 素材上传是用户提交事件，提交后由系统自动读取文件、授权字段和逐镜适配结果并继续原任务，不生成独立人工核验卡。机器无法确认的真实权利或关键事实转为明确异常；每条视频仍自动检查该素材是否满足自己的镜头要求。
3. 剩余制作、质检、返工和审批时间不足时，立即生成补救评估卡，无须等到素材逾期。评估必须读取剩余预算、实际并发和人工工作时段；提出方案不等于修订已生效。影响只沿真实依赖传播。
4. 发布未知结果保持待对账；保存平台请求身份和每次查询证据。只有可确定未发布且允许安全重试时才重试；重复回执只更新同一任务，不新增发布数量。
5. 销售交接分为待领取、处理中、待反馈、已处理、需补资料。已转人工不等于客户推进成功；未领取或未反馈按各自截止提示。报价、寄样和会议安排按真实结果分别记录，预约不等于已经完成。未知发送结果先对账，避免重复联系。
6. 客户反馈必须关联真实客户/会话证据；来源未知如实保存。编导提出选题后，还需参考、事实、素材和产能核验，经下周计划确认才派制作任务，不直接绕过排期生产。
7. 跨周沿用原任务 ID、输入版本和已完成产物；当前日待处理区引用原卡并去重。周一发布的前置制作和验收展示在上周，不通过复制卡片掩盖逾期。变更方案保存新版本及原任务关联。

#### 补充验收场景

- 视频 CTA 的规格表不可访问时，生成修复卡并阻塞对应发布；不影响无此依赖的发布。
- 同一素材用于五条视频：只建立一个共享资产身份并绑定五个消费者；自动检查后只恢复满足镜头要求的任务，不为每个消费者建立人工核验卡。
- 素材尚未逾期但剩余时间已不足：显示发布风险并生成补救评估；未经确认不替换来源或发布日。
- 平台发布超时后查询发现已发布：回填原任务链接，发布数量为一次，不重发。
- 销售已领取但未反馈：交接任务仍未完成；真实报价或预约回流后记录对应结果和下一步。
- 无询盘时不生成虚构客户问题；跨周同一客户、素材或制作任务不重复派单和计费。

### 5.4 受阻任务定位与随时间推进的交付约束

2026-10-09 用户补充确认。本节为新增产品要求，文档更新不代表实现或验收完成。

智能经营 Agent 周任务排期是统一状态入口：卡片展示主负责、实际阶段、规定完成时间、真实完成状态、受阻原因摘要及下游影响。生产细节与处理操作放在对应已有生产页面，不另建脱离任务的通用异常页面。

点击任意受阻任务的“查看详情／去处理”，必须按实际任务身份进入对应生产场景并定位问题对象。分镜匹配或镜头重试问题进入该视频对应的三栏式内容创作页面，自动选中具体分镜；同步展示本镜头脚本与要求、素材或生成结果、质检／失败原因及可执行操作。携带真实项目、周包版本、执行任务、内容任务及分镜身份，不能仅打开通用工作区或默认最近视频。账号授权、素材补交、客服会话或审批问题分别进入其实际配置、素材任务、会话或审批批次。对象尚未创建或已失效时明确显示缺口并定位真实上游处理入口，不伪造对象或链接。

七天排期必须随时间推进执行：规定时间之前应完成对应可验收交付，不能只把任务卡放在日期下而不执行。满足授权、输入、依赖和运行条件的 Agent 任务按真实计划启动／继续；人工任务按负责人及截止提示，不能自动代替真人确认。到达截止仍未交付的任务明确显示逾期、负责人、实际状态、原因、逾期时长和受影响发布；正在运行或等待人工不等于按时完成。提前识别剩余时间不足并生成补救评估，而非等到发布时间才发现缺口。

时间经过不会使卡片自动完成：完成必须有本任务作用域内的真实交付与核验凭据。原计划日保留未完成／晚完成记录，当前待处理区引用同一任务并去重；展示实际完成时间及是否按时。延期或重排需明确操作和新版本记录，不能静默移动卡片、重置截止或抹掉违约历史。上游恢复后更新原任务及真实下游，重试沿用明确执行身份，避免重复付费或重复发布。

成片类任务必须逐卡传递同一个版本化产物引用。质量卡发生局部返工时，返工子成片须携带可核验父子关系并重新取得自己的逐镜 G4 与独立 G5；完成质量卡、条件返工卡和用户审批时，分别读取上游真实结果中的同一子成片，不能按创建时间改选“最新成片”、回选旧母片或借用旧审核。目标产物失效、被退回或版本变化时保持阻塞并引导到该产物处理入口；不能自动另起生产来掩盖断链。

验收：①点击第3镜受阻卡进入正确视频三栏页面并选中第3镜；②第3镜处理后凭实际结果更新原卡，其余已通过镜头保留；③截止经过但任务仍在执行时显示逾期，不自动完成；④同一逾期任务跨日引用不重复计数；⑤明确延期保留原截止与历史；⑥依赖尚未齐备时显示阻塞及影响，不能为了按时完成绕过审核或授权。

### 5.5 制作前准备与分镜后消费核验

适用于 Z、H 两套任务链。明确排期后，生产任务顺序为：经营排期确认 → 制作前素材准备 → 脚本 → 分镜 → 素材消费核验 → 资产生成 → 成片与审核。制作前准备属于现有主环节的子步骤，不新增 Agent 或副链路数量。

制作前素材准备必须进入真实任务图，但作为成片产出卡内部节点存在。内容 Agent 冻结所需产品身份、事实、来源与授权条件；可生成素材走已接入的生成或素材供给环节，需真人提供的素材才形成用户可见的提交异常卡，提交后的文件检查由系统自动执行。准备步骤不能仅凭要求文本宣告素材已就绪。共享素材在最早需要它的内部生产节点前完成，不能使用较晚的分镜消费时间倒排上传截止。

分镜后的素材消费核验保留：复用同一真实素材申请、提交版本和消费者核验结论，并检查该视频实际绑定的素材字节与版本。不得重建申请、重复要求真人署名或把前置核验记录当作另一条已完成视频。来源、事实、授权或原运行发生变化时按实际差异重新处理，不静默替换来源。

任务依赖也约束真实生产进度。脚本任务开工不能让整条视频流水线提前执行尚未就绪的资产生成；脚本和分镜交付持久保存后，可分别据真实证据完成对应卡片。后续素材核验及制作任务尚未可执行时，原生产任务等待相应阶段，展示所等待的真实前置。依赖通过后继续同一生产任务和原作业，供应商调用前重新核验素材与授权；不得重新创建运行、重复付费，或把等待阶段误报为制作失败。结果未知的供应商作业先对账，不能借阶段继续重新提交。

新任务图必须冻结图版本。新建或明确修订的周包采用含制作前准备的新版本；已有周版本、历史运行及已有任务的依赖关系保留原记录。旧图需要改造时引导明确修订，不在后台悄悄添加前驱、改依赖或伪造上游成功。本节为真实图缺口的目标修复要求，完整前驱执行验收尚未完成。

### 5.6 新周版本的容量确认

首次新周排期也必须有容量确认入口。经营 Agent 根据逐条发布时间、前一天成片截止及完整依赖图生成任务时间建议；建议工时明确标为估计。用户或有权经营配置提供逐任务剩余工时、缓冲、费用、可开始时间、资源并发及工作窗口后，系统核验并冻结实际可执行排期。不能把创建日期堆排、七列日历或截止风险提示当作已完成均衡排期；没有容量证据时列出具体待补项。

首次确认仅用于未执行、未授权真实发布、尚未确认容量的周草稿，不要求用户先撤回另一周。确认使用新不可变周版本及持久回执，重试返回同一结果；提交时必须再次核验草稿未被激活或执行。已执行周包走正式计划修订，保留原作业和回执。确认容量不等于激活、授权发布或启动生产。

异常补救排期必须先展示将要创建的新周版本完整任务图，包括旧版本没有的制作前素材准备。新增任务标注“新增前置，尚未执行”，不显示为历史已完成任务；旧任务保留来源关联。查看方案不创建生产任务、不启动制作、不撤销原授权。

用户逐项明确剩余工时、缓冲、费用、可开始时间及实际产能工作窗口；允许明确填写零费用，但不能默认免费、复制其他制作任务的费用或把缺失估时视为零。缺少任一必要准备任务的容量条件时，不允许确认完整排期。新增准备必须在脚本开始前完成，成片与审批仍须满足发布前一天的交付要求；缺口只反映在对应依赖及发布目标上。

确认前重新核验当前周包、真实任务、所需素材、账号条件、队列容量及完整目标图。输入变化时要求重新生成方案，不能按过期图创建新版本。完整新图无法落地时，不冻结仍可执行的旧版本。成功确认创建新草稿，保留旧任务与实际运行记录；原发布授权撤销，新草稿需明确激活及授权，确认排期本身不代表任何生产任务已经完成。

页面切换周包、退出登录或更换账号后，旧请求不得更新新页面，也不得继续提交旧方案。验收同时检查真实新版本任务的起止时间和依赖，不能只依据界面上的建议时间判定排期生效。本节实现仍需完整有效经营规划下的正向确认与生产运行验收。

## 6. 例外人工任务与逾期标红

数字员工应在无人插手的情况下完成常规素材盘点、AIGC 生产、逐镜检查、成片审核和任务推进。人工任务不是主链固定环节，只在系统无法通过素材库、数字人、AIGC、替代分镜或自动检查解决问题时出现，包括：必须真实拍摄/上传、缺少不可推断的授权、敏感关键事实确认，以及成片待发布但目标账号尚未绑定。

人工异常任务字段：任务 ID、异常类型、关联产出与镜头、发起 Agent、指定真人及联系方式显示权限、要求、文件类型/数量或账号、截止时间与时区、提交状态、提交版本、自动检查结果和受影响下游。

人工异常卡状态：待提交→已提交→系统检查中→已采用；检查失败或无法确认→需补交/需授权。取消和豁免需有明确记录。系统检查是同一任务的自动节点，不生成另一张人工卡；能够通过自动检查的提交直接恢复相关生产节点。

当前时间超过截止、仍有必需文件未提交、账号未绑定或需补交且对应期限已过：卡片红边/红底提示，按类型明确“人工上传已逾期”或“发布账号绑定已逾期”，并展示负责人、逾期时长、缺失项目和受影响发布。提交齐全后立即进入系统自动检查，不继续显示为用户未提交。

补交和延期有新截止及操作记录，不能静默抹掉历史逾期。跨日逾期在原计划日期保留并在当前日待处理区引用同一任务，计数去重。

系统先尝试替代分镜和可合规的 AIGC 路线；只有确无替代方案时，相关内部节点显示等待人工输入。其它视频和其它独立节点继续。自动检查采用后恢复原制作或发布任务，已有结果保留。通知仅在相应提醒功能和权限被配置后发送；前端标红不代表已经通知。

初始化时选择延后绑定发布账号的有基础用户，允许先完成历史账号采集、计划和内容制作。发布准备节点到来且账号仍未绑定时才生成一次人工绑定任务；同一账号服务多条待发布视频时复用该任务并列出全部消费者。绑定失败或授权失效不触发重新制作成片。

## 7. 初始配置的三类画像

画像值：B2B 零基础、B2B 有基础、B2C。自选画像与实际账号/素材/客户/数据检查共同确定推荐，不用粉丝数单独判断。

首次共同配置只包含公司/品牌、产品识别与主推确认、数字人形象三步；目标市场、语言、平台、账号产量、预算和交付时间由推荐计划提出，用户在“确认计划并开始制作”前确认或调整。其它企业事实、素材、授权、承接和高级经营信息在系统能够自动识别时直接复用，缺失时引导稍后在“灵小枢 > 企业信息”补充。B2B 有基础可选录入全部历史平台账号并立即发起历史内容及播放、点赞、转发、评论采集；B2C 的价格、库存、配送、退换和购买路径进入其后续专属计划配置。

以下数量为可调初始产品建议，不是行业固定标准或效果承诺；必须受预算、素材和审核容量约束。

| 项目 | B2B 零基础 | B2B 有基础 | B2C |
| --- | --- | --- | --- |
| 首期目标 | 建立可信身份、产品证据和可用询盘承接，验证买家需求 | 识别高质量获客结构，扩大有效询盘及销售推进 | 验证消费场景、购买意愿及交易路径 |
| 初始渠道 | 先 1–2 个买家实际使用的平台 | 优先已有有效询盘的平台，受控拓展一个渠道 | 优先目标消费者使用且可承接购买的平台 |
| 首周母版建议 | 3 条；就绪后发布，建设任务先行 | 保留历史可靠产量，无基线可从 5 条起评估 | 可从 7 条短视频母版起评估，容量不足降低 |
| 内容方向 | 真实产品演示、工厂/质量证据、采购 FAQ | 采购异议、案例证据、应用比较、复用已验证结构 | 使用场景、效果演示、评价/UGC、购买异议 |
| CTA | 目录、规格表、样品/报价咨询 | 按购买阶段分目录、咨询、样品、会面/报价 | 商品详情、购买、加购或合法促销 |
| 客服 | 建知识与回复草稿；无客户如实 no_data | 既有客群分层、个性化跟进和销售交接 | 高频售前、订单/配送/退换问题，售后转人工 |
| 指标 | 链路就绪、目标买家互动、有效询盘及回复质量 | 有效询盘率、报价/样品/会面推进与可归因商机 | 商品点击、加购/订单、转化与售后负担 |

B2B 零基础首周优先补企业与产品事实、可信证据、账号及承接，不先铺满大量低证据视频。B2B 有基础先审计历史，并行复用与小样本新方向测试；不把有账号但无可靠数据误当成熟基础。B2C 更多围绕即时使用价值与交易摩擦，但高客单或长决策品类仍需教育与信任内容。

B2B 对标筛选：目标买家、行业/应用、市场语言、采购阶段、产品证据、可复用结构与权利边界。优先解决采购风险、规格适配、交期、质量与服务问题；不能仅按播放量排行。多买家角色需要各自证据，不能只对单一联系人表达。

平台能力边界：本项目当前支持的发布渠道以实际连接和后端能力为准。LinkedIn 可作为 B2B 选渠参考；未接入时不得在计划里伪造可执行发布任务。

## 7.1 画像与链路路由

- B2B 零基础首周执行第 3 节 Z 链；全部待复刻母版参考来自外部。
- B2B 有基础执行第 4 节 H 链；本账号历史迭代与外部探索分别编排，配额由用户确认。
- 本账号历史不足或不可访问，显示 H-S2 证据补齐任务，用户决定补资料/降量/修改配额或画像；不自动改成 Z 链。
- 冷启动积累自有数据后，经营提出升级建议，经确认在后续周执行 H 链，原周版本保留。
- B2C 初始配置建议保留在第 7 节；其专属主副链路尚未在本次 B2B 拆分中定义，不直接套用 Z/H。

来源配额以母版计；平台适配版本继承来源。参考用于复用结构，制作素材另核验企业归属、事实和权利。自有其它账号参考单独标跨账号，不冒充本账号历史。编导和内容消费同一冻结参考；任何换参考都走修订。所有数据观察保留来源、平台、窗口和证据缺口。

## 8. 运营依据与产品判断

LinkedIn 的 B2B 研究强调大量潜在买家并不处于即时采购期，因此 B2B 要兼顾长期认知与当前需求承接，不用第一周订单判断全部价值；95–5 是研究框架，不能机械作为每个行业精确比例。[95–5 Rule](https://business.linkedin.com/advertise/resources/b2b-institute/b2b-research/trends/95-5-rule)

B2B 采购涉及多种角色，内容应为不同成员提供信任和判断依据。[Buying Committees](https://www.linkedin.com/business/marketing/blog/content-marketing/how-to-market-to-buying-committees)

首周产量、三类画像差异、工时均衡和卡片规则是基于业务约束提出的产品建议，不是上述来源的规定频次。

## 9. 验收条件

### 客服 Agent 的三渠道范围

客服 Agent 同时承接 WhatsApp、Messenger 和 Instagram 后台私信。周任务、会话归因、人工交接及发送异常恢复必须携带真实渠道、企业账号、客户与会话身份；不能仅接通 WhatsApp 就核销客服主链与副链。

三个渠道均须覆盖：接收真实私信、结合企业知识生成回复建议、依照实际授权发送、人工接管、询盘转销售、回执观察及未知发送结果恢复。渠道发送权限、会话窗口、消息格式与回执结构分别使用现有对应平台端口，不套用 WhatsApp 模板或号码规则。

任务卡以具体会话处理结果为交付，标明主负责客服 Agent、渠道及实际账号；点击进入对应真实私信工作区。需要人工时，显示指定负责人、截止、处理原因和原会话。发送结果未知时保留原请求，只能依真实平台回执对账，不自动重发；缺少平台证据继续显示待核验。

验收须分别取得三个渠道的真实接收、回复、人工交接与回执恢复证据；某渠道未授权或无真实会话时显示缺口，不能用其他渠道的数据替代。

1. 七天时间横轴，无 Agent 纵轴；按完成日展示具体交付。
2. 四个 Agent 与真人任务有明确责任，每环节可追溯输入、产物及下游。
3. Z/H 两套各八个主环节、九类副链路覆盖；按画像、证据与实际触发条件生成，不用同一套卡片只换来源标签。
4. 常规素材检查由数字员工自动完成且不生成单独人工卡；只有不可自动解决的上传、授权或账号绑定形成异常卡，逾期标红。齐全提交进入同一任务的系统检查节点，采用后恢复原下游。
5. 首期建议随画像、实际基础、预算、产能变化；母版/版本/发布次数分开计数。
6. 示例数据显式标注；缺数据不伪造进度、成本、回执或业务成功。
7. 跨周未结事项去重，实际外部效果和未知回执保留。
8. 前端验收后再接真实生产场景，按任务身份定位；构建成功不能代替浏览器与真实业务验收。

9. B2B 零基础首周待复刻母版参考全部来自外部；有基础排期明确包含本账号历史迭代与外部探索，配额经用户确认。
10. 编导与内容引用一致的参考及分析版本，平台版本继承来源；未取得合格自有证据不能伪造历史爆款或静默替换来源。
11. 初始化只要求公司/品牌、产品主推确认和数字人三步，随后直接弹出包含市场、语言、平台账号数量、Agent 排期、费用范围、预算上限与交付时间的推荐计划。
12. 有基础用户可先授权历史账号采集而延后绑定发布账号；发布前只生成一次账号绑定异常任务，不因绑定缺口重复制作成片。
13. 日历按最终产出完成时点显示，一条视频对应一张成片卡；多 Agent 倒排节点只在详情和生产实况中展示。
14. 真人口播使用 AIGC 数字人；关键钩子和音画强同步镜头按编导分析走高还原生成，普通支撑镜头才允许优先复用素材库。

## 10. 账号打法与原生产版本

账号打法属于 Z-M1/Z-S2 的经营基础配置、H-M1/H-S2 的现有规则核验。它与参考来源比例分开：Z 首周全部外部参考仍须按本企业的买家、产品事实和咨询承接表达；H 的 40/60、20/80 来源配额不改变目标账号的表达规则。

- 用户可编辑目标买家、内容支柱、事实证据规则及咨询入口，分别明确选择保存草稿或保存并启用。草稿不能成为可执行周任务的已批准打法；经营 Agent 可提出建议，不能替用户自动启用。
- 编导分析按每个目标账号冻结实际账号版本、已启用打法版本及完整规则内容的哈希。多账号母版逐账号对应，不能将第一个账号的规则用于其他账号；无已启用打法时明确展示前置缺口。
- 详细排期与派单沿用同一冻结引用。用户确认后规则发生变化，原任务停止新生产并提示明确修订、重新确认；既有派发任务不能自动借最新规则补齐缺失字段。
- 生产要实际应用买家、内容支柱、证据与承接约束，并在审核中给出逐项结论。引用非空或保存了规则元数据，不等于已应用规则。
- 启动时冻结原运行的复刻来源链、规则内容哈希和实质输入。恢复供应商结果、继续原作业及历史成片追溯均引用原版本；缺原凭据不得从当前最新规则补签，也不得重新付费提交以替代原任务。
- 产品身份图片等必需输入在创建生产运行前由系统检查。库存图片须有真实入库来源、字节、产品对应及可读取授权信息，普通权利标签不足以通过。缺口先尝试可合规生成或替代分镜；确需用户输入时形成具体异常要求。用户提交后由系统自动检查并明确绑定，沿原待启动内容任务继续，不创建独立人工核验卡，也不先创建无法补齐输入的运行。
- 验收覆盖多账号映射、草稿拒绝、重复记录、跨租户、版本/内容漂移、恢复期间规则变化，以及缺规则时用户能从真实页面补齐。需以实际启动、规则应用和成片核验证明执行闭环；本节是目标行为，当前实现仍在联调。
