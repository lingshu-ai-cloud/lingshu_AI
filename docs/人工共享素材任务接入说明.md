# 人工共享素材任务接入说明

## 已实现

独立持久服务 `server/socialPrograms/weeklyMaterialRequests.ts` 使用 `social_weekly_material_requests` 保存指定提交真人、指定核验真人、上传截止及 IANA 时区、可选核验截止、共享消费者、提交版本、逐消费者事实/权利/画面检查及变更记录。

任务身份按租户、经营项目和共享需求 key 稳定生成，不包含周号；跨周追加消费者沿用原任务 ID，需要显式修订及原因。延期保留原上传/核验截止，核验历史不会被静默擦除。已提交待核验不再标上传逾期；未明确核验截止时提示缺口，不伪造核验逾期。

`get` 和 `list` 校验当前租户真实 users 的角色和禁用状态。提交只能由指定提交人执行，核验只能由指定核验人执行。单人企业默认允许同一指定用户分别提交及检查；仅明确配置 `allowSelfReview:false` 时执行职责分离。上传不构成核验通过。

素材引用既有 canonical `materials` record ID。默认复用 `getOwnedCloudMaterialRecord`、`cloudMaterialView` 及 `materializeSocialContentCloudMaterial`，验证租户、自有生产使用边界、实际字节、MIME/魔数、长度和 SHA-256，临时下载文件在 finally 清理。没有新增文件上传服务器。演示、占位及仅供参考素材不被接受。

## 路由挂接

`createSocialWeeklyMaterialRequestsRouter(store, ports?)` 使用 `Router({mergeParams:true})`，由已鉴权父路由挂在 `/:programId/material-requests`。

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | / | 读取真实素材任务列表 |
| GET | /:requestId | 读取指定任务 |
| POST | / | 创建指定真人共享素材任务 |
| POST | /:requestId/submissions | 引用真实素材，要求 expectedSubmissionVersion |
| POST | /:requestId/reviews | 核验当前 submissionVersion，逐消费者记录事实/权利/镜头结论 |
| POST | /:requestId/revisions | 显式截止或消费者调整，保留原因和历史 |
| POST | /:requestId/cancellation | 指定核验人显式取消并保留证据 |

身份只取服务端 AuthLocals，不能由 body 替换。顶层非法 JSON 类型及非白名单字段被拒绝。消费者必须是同项目、准确周包版本、真实视频关联的 content/adaptation 生产步骤，不接受发布/客服或不存在的任务。

## 生产挂接边界

展示可用 `materialRequestAcceptedConsumers`；生产准入必须调用 `acceptedForConsumer`，重新核验消费者和被冻结素材字节版本，再把返回的具体 material ID/hash 绑定到既有生产输入。它不把执行任务标为成功，也不绕过内容生产自身的事实、权利、逐镜质检和全部其他必需输入检查。

当前 `review` 保存的是指定真人做出的逐项人工核验；实际核验人明确记为该真人。内容 Agent 自动事实/权利/视觉核验尚未接入此服务，不应把人工提交视为内容 Agent 自动核验完成。任务日历映射、原有制作输入绑定及执行器恢复由共享集成继续完成。

新增 schema 迁移 `1791072020_create_social_weekly_material_requests.js` 采用 server-only null 规则和租户/项目/需求唯一索引。未运行数据库迁移；仓库完整性及真实 PocketBase 新建/升级仍需单独验证。

## 冻结必需素材生产准入

生产 adapter 在启动前读取冻结合同，核验对应版本唯一的真实 `material_readiness` 消费者；全部通过后通过既有 `addSocialTaskSource` 绑定实际库选项的 `sourceVersion`。运行中缺绑定或版本漂移只阻塞，不替换来源或重新启动付费任务。结果验证器再次核验合同、真实字节及持久来源，不能仅用通用内容就绪核销素材准备任务。

无需共享人工素材的视频使用独立 `starter_social_content_material_demand` 结果：冻结实际原始需求数组与服务端自动素材计划，要求明确无必需人工依赖、企业事实完整、画面不伪造客户实证，数字人必须同账号实际授权锁。需求内容、账号锁或冻结哈希变化使凭据失效。它不能覆盖 `materialRequirement.required:true` 的人工依赖。该凭据已接结果验证器和实际内容日历入口；完整生产运行仍需验收。

`weeklyRequiredMaterialAdmission.ts` 接收冻结的 `required/requestIds` 和当前准确版本的 material_readiness 消费者任务身份。没有冻结合同返回 `legacy_unhandled`，不能解释为素材已齐全；明确 required=true 却没有 request IDs 返回阻塞。每个冻结请求都调用 `acceptedForConsumer`，取消、未核验、版本漂移或当前消费者未通过都会产生缺口。相同 canonical material ID 的 hash/type/byteSize 冲突也阻塞，失败时不向生产返回部分素材。只有全部实际重验证通过才返回真实素材版本和已核验提交版本。

经营原发起人可显式追加消费者、调整截止，仍需真实租户成员身份、原因和记录；无关第三方不能操作。原发起人由不可改的 created 历史事件确定。
