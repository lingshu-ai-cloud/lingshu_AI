# 周质量审核核销：真实证据边界

## 适用范围

本轮补齐周任务 `quality_check`、`rework` 和库存源读取中的待核验成片路径。成片的 `productionResult.technicalReview.approved`、`creativeReview.approved` 和原自动审核标记保持不可变；新的审核不把这些旧标记改成 `true`。

## 待核验标记与实际失败

旧标记为 `false` 并不能单独证明当前检测已经失败，也不能证明已经通过。必须读同一成片的冻结 `technicalQualityReport`：已检测到画面失败、音轨失败、镜头问题或明确失败项时，要求实际修复并产生新的成片，不能用人工勾选覆盖。已保存但无法识别的检测报告也不能按“未知”放行。

缺少自动检查结论的项目，可以走显式审核，但必须同时满足：

1. 原周任务与真实内容生产任务绑定一致；成片版本、内容哈希、实际媒体字节、镜头缓存和运行血缘可核验。
2. 同一成片的每个镜头最新 G4 收据全部通过。人工收据需读取不可变审核记录，复查指定审核人、七项检查、镜头和完整媒体哈希；实际硬失败不可覆盖。
3. 同一运行、成片、交接版本、生产结果和媒体引用的最新独立 G5 审核通过。编导 Agent 实际运行和显式人工备用审核分别记录，不互相冒充。
4. G4 不替代 G5；G4、G5 都不替代最终用户审批。

周质量任务核销只表示该生产节点的真实审核证据齐备，不表示已经发布。

## 库存与待发布包

库存仍要求原成片已获真实最终用户审批。旧审核标记为 `false` 的成片，需要在转换前重新读取原审批任务和最新 G4、G5 证据；实际 G5 审核与收据引用进入冻结库存来源。来源变更或审核降级会阻塞后续读取。

该转换不会再次生成视频，不会触发发布，也不会把旧用户审批当成目标周的新审批。目标周仍需独立用户审批。

## 保留的旧自动路径

原有 `true` 自动标记路径仍保留原行为。初产标记为绿色，不证明本轮新增的独立逐镜 G4 与完整 G5 审核已实际执行。该旧路径的独立 G4/G5 适用、来源迁移及验收收紧属于后续审计项，不能据此宣称完整整片审核已经贯通。

## 实现位置

- `server/runtime/weeklyContentQualityAudit.ts`：同源质量审核核验。
- `server/runtime/socialWeeklyResultValidation.ts`：周质量任务结果核销。
- `server/starter198/socialDirectorG5ReviewService.ts`：独立 G5 审核记录与真实核验。
- `server/publishing/weeklyPublicationWorker.ts`：已审核周成片的安全转换。
- `server/socialPrograms/weeklyInventoryReuse.ts`：库存来源读取与冻结。

实际外发、付费调用、部署和生产迁移不属于本轮验证动作。

## 已验证的持久化链

`weeklyContentQualityAudit.integration.test.ts` 使用本地生成的真实 MP4、实际归属文件和 SHA、持久逐镜人工 G4 与独立人工备用 G5 记录。默认生产适配器读取真实内容详情并保存真实血缘，不替换审核或血缘保存端口。最终用户通过真实周任务审批入口确认原成片；下一周再显式确认库存来源、生成新周版本、执行库存经营前置任务并重新人工审批，才创建同一原生产结果的唯一发布包。整个过程保持原摘要标记为 `false`，没有重新生成、供应商调用或平台发布。

同一成片的 G5 记录被篡改、当前企业事实发生变化或前置任务未完成时，真实核验和库存发布包准备均拒绝继续。该集成证明人工审核证据与周任务消费者的真实持久化衔接；不代表已向实际模型供应商提交审核，也不代表浏览器或平台发布验收已完成。

## 原周质量任务恢复（2026-10-10，本地）

生产页现通过真实成片的任务、来源 run 与 artifact 查询原周 quality_check / rework 消费者，用户明确选择原任务。服务重新读取同源 G4/G5 凭据、企业事实与原周绑定，只删除 `weekly_production_quality_review_required`，保留其他自身阻塞及实际未完成依赖。不会将任务直接核销成功，不修改成片摘要，不启动生产或发布。

恢复请求先保存稳定 requestId 与原 contextHash；服务将同源审核 SHA、操作者及原任务身份写入该执行任务的 JSON 恢复历史。丢失响应后只能按原 requestId 查询。重复同一请求不增加恢复记录。任务仍有租约、原周停用/撤回/被新版本替代、身份错误或审核证据漂移时，不允许恢复。

本地真实服务与 HTTP/API 联调 7 项通过：缺审核拒绝、真实审核后排队、其他阻塞保留、重启读取原回执、同 ID 幂等、来源/租约/终态/撤回拒绝、前端原回执查询。构建通过；完整真实租户视觉验收及实际供应商端到端仍未完成。G6 独立发布预检继续开发，不能将本入口视为发布许可。
