# 脚本与口播生成逻辑审查

日期：2026-09-05。范围：当前本地工作区，包含未提交改动。结论不代表线上部署版本，也不代表全部历史成稿的质量统计。本次未修改业务代码。

## 结论

当前质量问题有可复现的代码原因，优先修复生成分支、事实来源和版本一致性，再做模型与创作提示词对比。主要矛盾是：产品路径经常跳过完整创作规则；安全修复会把脚本替换为固定空泛文案；多套生成入口的质量检查不同；配音阶段会再次改稿，最终声音与原分镜不再属于同一版本。

已有的封闭事实约束、分轨字段、质量告警、翻译完整性检查和音频过期状态值得保留。需要把它们接到所有实际执行路径，并用成稿质量测试验证。

## 现有数据链路

### 工作台

1. 企业产品选择 → `formatSelectedProductInfo` 把选定产品拼成文本；`activeProductInfo` 优先使用选定产品，空时使用旧的 `productInfo`。
2. 素材选择 → `buildMaterialInfosForScript` 把片段观察、OCR、机位、时长和“待人工复核”标记拼成字符串。请求主要用素材名称关联，未携带稳定的分段证据 ID、置信度或独立审核状态。
3. 前端把产品、素材、主题、受众、合作路线、CTA、语言和时长发往 `POST /studio/script`。当前工作台文本生成强制使用 Qwen，传入的 provider 不改变这个选择。
4. 产品路径：先生成/选取锁定口播，再生成/选取画面。两者数量相等时直接序列化，不执行完整创作提示词，也不执行模型修稿循环。
5. 素材和对标路径：通常使用长提示词生成文本 → 正则清理 → 最多一次模型修复 → 可能替换为保守模板 → 质量检查。
6. 前端继续用 `sanitizeStoryboardScript` 改写和清理文本，保存脚本、多个方案及质量结果。
7. 提取口播 → 多语种翻译 → TTS。TTS 可再做目标语言修复、超长口播改写和第二次合成。返回文本写入 `voiceDrafts`，原脚本没有随之统一修订。
8. 字幕优先使用供应商原生时间；`/tts/align` 当前忽略音频 URL，只按文字比例分配时间。项目整体存入 `studio_projects.spec`。

主要位置：`src/components/AiCreateStudio.tsx:2633、4260、5457、5553、5838、6984、7047`；`server/routes/studio.ts:2134、2416、2589、6214、6330、6880`。

### 另外两套入口

- `server/routes/scripts.ts:20` 的历史脚本接口调用 `server/agents/gemini.ts`，使用 JSON 合同，独立保存至 `scripts`；本次在当前前端源码中未检索到直接调用该生成接口，不能据此认定它是当前主入口。
- `server/digitalEmployees/contentProduction.ts:762` 的数字员工有自己的提示词和降级逻辑，固定要求中文、5 段、20 秒；之后调用 `assessScriptQualityV2` 再合成中文口播。它没有复用工作台完整的语速、表达、主题和对标约束。

## 按优先级排列的问题

### P0：特定产品模板覆盖语言、受众和真实规格

位置：`server/routes/studio.ts:1433、1492、2418、2445、2464、2592`。

- 润唇膏分支直接使用固定中文口播与固定画面，模板不接收目标语言。
- 模板中硬编码“乌兹别克斯坦消费者”、4.5g、浅米色、白管、牛皮纸外盒等具体信息。
- 即使未调用模型，成功结果仍返回 `source: ai`，无法区分真实生成与模板降级。
- 完整的主题、自然表达、多版本提示词在锁定稿分支不会执行；只改这些提示词无法改善该分支。

隔离复现：输入英文、5g 润唇膏、消费者路线，返回 HTTP 200 / warning；前三句是中文，首句包含未输入的国家，模型调用 0 次。40 秒经销路线固定生成 4.5g，被最后的数字检查拒绝。这里的拒绝是模板自造错误导致的。

建议：移除以产品名称命中特定业务文案的生产分支。所有品类共用显式输入合同；模板只定义叙事结构。失败返回可解释的待修订状态，不把模板标成 AI 成稿。行业外观和使用动作必须来自已确认产品事实或素材证据。

### P0：质量状态有检查豁免，目标时长没有统一约束

位置：`server/routes/studio.ts:1407、2836、2861、2958`。

- 锁定稿将 `speechIssues` 直接设为空，因此 `dialogueFits: true` 不代表实际检查过。
- 锁定稿时长计算与普通语速检查使用不同算法，中英混排会产生差异。
- 当自然口播超过目标时长，序列化直接扩展时间轴，没有统一的目标时长容差校验。
- 产品路径的素材和时间依据检查并未执行，却返回 `materialGrounded: true`、`timelineGrounded: true`。

隔离复现：10 秒目标返回 16.9 秒；混排探针的单段被分配 5.2 秒，而系统自己的另一语速检查估计需 7.8 秒。

建议：统一时长计算函数和最终检查，无论模型生成还是模板构建都执行。质量字段使用 `passed / failed / not_checked`，避免用空错误数组表达“已通过”。将文字长度、实际音频时长、镜头时长分别保存并检查。目标时长不够时删减完整语义单元，或明确返回时长冲突。

### P0：事实校验丢失主语和字段含义

位置：`server/lib/studioScriptQualityV2.ts:109`；`server/routes/studio.ts:661、2226、2463`；`server/routes/enterprise.ts:1223`。

- 数字检查主要验证整段产品资料里存在同数值、同单位；没有绑定产品、属性、条件。
- 多选产品的资料被合并，可能让 A 产品的数字被用于 B 产品。
- 附件名称或文件已上传只证明文件存在，不证明正文、画面动作、OCR、认证有效性。
- 产品资料在 brief 中被整体放入一个 `approvedFacts` 元素，没有逐条事实来源；同时 system prompt 注入整个企业资料和其他产品，扩大事实污染范围。
- 待复核观察与已确认观察仍共同作为素材文本参与生成和检查。

隔离复现：资料只有“质保：30天；交期：待确认”，`hardScriptSafetyIssues('台词：30天交付。', facts)` 返回空数组。

建议：使用 `factId + productId + attribute + value + unit + conditions + sourceId + reviewStatus`；脚本主张引用 factId。MOQ、交期、容量、质保等不得互借。视觉使用 `materialId + segmentId + sourceStart/sourceEnd + observedFacts + confidence + reviewStatus`。未经核实内容可以成为待拍建议，不能充当证据。

### P1：配音阶段再次改稿，破坏已确认的内容版本

位置：`server/routes/studio.ts:6220、6330、6413、6503`；`src/components/AiCreateStudio.tsx:2892、5553、6998、7047、7066`。

- TTS 发现音频过长后，重新调用模型改写整段口播；请求只有文本，没有逐镜事实映射和锁定版本。
- 前端把 TTS 返回文本写入语种草稿，但没有同步更新分镜台词、分镜字幕、其他语言版本和质量报告。
- 配音前去掉时间戳；TTS 返回的纯文本写回后，原有逐镜关联进一步丢失。
- `voiceoverDraftCoversSource` 只比时间标签：相同时间轴但内容已变更的旧译文，仍可能被认为覆盖源稿。`genTts` 复用草稿的分支未检查 `voiceDraftStaleLangs`；渲染入口另有过期保护，不能视为配音复用已正确。
- 批量 TTS 对输入直接 `slice(0, 1500)`，长文本可能被静默截断。
- `/tts/align` 当前是按字数分配，不是音频强制对齐；供应商已有原生时间时另当别论。

建议：脚本确认产生 `contentRevision`，每条口播保留 sceneId。翻译记录 sourceRevision；TTS 记录 textHash、translationRevision、voiceConfigHash。文本更新即失效下游。配音只读锁定稿；超时需要改稿时产生新候选修订，再统一更新分镜、字幕和译文。使用逐句音频/原生时间或真实强制对齐；超长输入分块或显式拒绝。

### P1：固定修复规则将不同产品改成同一类空泛文案

位置：`server/routes/studio.ts:1148、1179、1308、2732`；`server/lib/studioScriptQualityV2.ts:207`。

- 通用修稿提示中无条件写着“当前产品资料只支持无品牌瓶器、标签和外盒样品”，并非根据本次产品计算。
- 保守口播出现“确认资料支持的第二项证据”“核对可见证据”等后台表达。
- 非中文 fallback 主要输出英文，事实行保持原语言；德语等输出可能混入英文和中文。
- 素材安全修复会把多个镜头改成“原样展示已选素材”，但没有重新构建有效的证明顺序。
- 对标 fallback 只保留时间，重设景别、运镜和镜头功能；最终强制添加 CTA，与“原片无 CTA 不新增”的规则冲突。

建议：分离硬事实检查与创作品质修订。修稿上下文只包含本次事实、问题位置和需保留的内容计划；局部修正失败字段。素材不足时标记缺口，不把“无法判断”润色成买家台词。对标用显式的可保留/可重建字段，保留参考口播位和 CTA 位置约束。

### P1：多版本排重没有接通产品和素材路径

位置：`src/components/AiCreateStudio.tsx:5385、5485、5652`；`server/routes/studio.ts:2407、2427、2870`。

- 产品和素材的批量请求没有传 `existingScripts`、`variantSeed`；对标路径才有传。
- 产品的锁定口播阶段没收到此前版本、创意种子或完整主题内容计划；固定场景也不使用这些信息。
- 重复仅作为 non-blocking warning；提示“已切换差异化版本”并不对应实际完成的版本替换。

隔离复现：润唇膏同一输入改变 tone 和 variantSeed，成稿完全一致；两次模型调用均为 0。

建议：三种路径统一传版本历史和内容计划指纹。先选择不同的钩子机制、证据顺序或叙述视角，再写口播。相似度只比买家可见文案和镜头语义，排除固定字段名与必要产品事实；重复返回 `duplicate` 并有限重写。

### P1：自动生产与交互生产执行不同质量标准

位置：`server/digitalEmployees/contentProduction.ts:762、910、934`；`server/lib/studioScriptQualityV2.ts:415`。

- 自动生产固定中文、5 段、20 秒，对标又要求遵守原片时间，两者可能冲突。
- V2 主要检查少量事实词组、数字和素材覆盖，未执行工作台 `storyboardSpeechIssues`、主题兑现和自然表达检查。
- `primaryCta` 和 `targetBuyerText` 被传给 V2，但当前函数不消费它们。

本地已有验收样本 `data/release-verification/2026-09-05/attempt-1/artifacts/projects.json` 的第一条已进入 render：五段画面均被改成相同保守描述；四段口播按工作台检查超出各自 4 秒镜头。这是本地验收数据，不是线上用户成稿统计。

建议：抽取统一 `generateScript / validateScript / localizeNarration / synthesizeNarration` 服务。工作台、历史接口、数字员工各自组装输入，复用同一事实和质量合同。自动任务也必须继承明确语言、时长和对标策略。

### P2：测试成功尚不能证明成稿优秀

位置：`server/strategy/scriptGenerationMatrix.test.ts:80`；`server/routes/studioQualityRouteV2.test.ts`。

27 格矩阵测试验证的是策略对象和五个内容节拍，不是 27 条真实模型成稿。路由测试只覆盖一个素材不足的 mock 场景。静态源码契约、格式测试很有用，但无法发现上述语言、固定模板、修稿语义和 TTS 版本问题。

建议：保留现有回归，新增模式×语言×产品×证据完整度的可复现实例集。硬检查覆盖：事实归属、错误语言、超时、字幕一致、静默模板、重复、待复核素材。对实际模型输出再盲评：前3秒是否具体、正文是否兑现钩子、两项证据是否有买家意义、口播是否能自然说出、结尾是否一个可执行行动。

## 建议的统一生成流程

```text
结构化产品事实 + 素材分段证据 + 受众/语言/时长/主题
  → 输入完整性与主题适配检查
  → 内容计划：一个买家问题、1–2个可证明点、一个CTA
  → 2–3个不同钩子候选，选择后写完整口播
  → 事实归属、自然表达、目标语言、逐句时长校验
  → 按口播和真实素材编排分镜；缺素材明确标记
  → 所有来源统一执行最终检查
  → 保存结构化 ScriptDocument 和质量报告
  → 按版本生成译文、配音、真实字幕时间
```

`ScriptDocument` 至少包含：`id、revision、generationMode、language、targetDuration、inputSnapshotId、scenes[]、generationTrace、qualityReport`。scene 包含稳定 id、起止时间、功能、voiceover、caption、factRefs、materialRefs 和拍摄/素材缺口。文本编辑视图由 JSON 派生，避免在前后端重复正则改稿。

质量结果分为事实正确、表达质量、画面可执行、时间匹配四项；保存每次修订原因。将“可编辑草稿”和“可配音/可渲染”分开，不把所有创作建议都变成阻断，也不把未检查内容算作通过。

## 实施顺序和验收

| 顺序 | 改动 | 验收重点 |
| --- | --- | --- |
| 第一批 | 移除产品硬编码、修复语言分支、取消质量豁免、通用修稿按实际产品、接通排重 | 5g 不出现 4.5g；英文/德语不混语言；无输入国家不出现国家；10秒不静默变16.9秒；模板来源可识别 |
| 第二批 | 统一事实与脚本 JSON 合同；三入口复用检查；素材分段证据结构化 | 质保不能充当交期；A产品事实不能用于B；待复核观察不当作已确认；对标没有口播位时不强加口播 |
| 第三批 | 锁定内容版本、译文/TTS依赖失效、统一字幕时间 | 改一个源句立即失效对应译文/音频；TTS不静默改稿；每镜口播、字幕和音频对应 |
| 第四批 | 真实输出样本盲评和模型 A/B | 固定相同输入比较事实率、自然度、重复率、首次可用率、延迟和成本；再决定模型配置 |
