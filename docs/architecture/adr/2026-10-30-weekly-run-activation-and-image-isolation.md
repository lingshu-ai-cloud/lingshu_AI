# 周任务先启动、图片逐项隔离

日期：2026-10-30

## 决定

用户确认周计划后，归属、计划版本、结构、内容生成授权和必要的费用确认仍是启动事务的前提；脚本、素材、数字人、参考图片分析及供应商就绪不是整周启动门槛。先批准计划、激活周目标并持久化运行与任务，再在已启动的运行中逐项核验。

周计划图片沿用既有图文内容任务、图片生产任务和持久化执行队列。每个原始图片位有确定性任务身份，不与视频或其他图片共用失败状态。同一周计划一次只准入一张图片；上一张成功或进入待处理后，后台才准入下一张。某张图片的参考或产品有问题时保留该张任务及证据，其他图片和视频分支继续。周计划只有全部图片及其他必需任务完成后才可完成。

图片参考缺少当前版本的生产标签时，复用现有图文分析队列自动重分析；持久化的排队、开始、未知和失败状态决定恢复，不因请求重放而重复调用供应商。自动重分析不等于自动放宽产品存在判断、费用边界或发布许可。

## 边界与验证

启动由 `goalActivationApplication` 持有；图片逐项准入由 `weeklyImageQueueBridge` 持有；既有图片分析队列与内容执行 Worker 仍各自拥有实际调用。运行调度器只做恢复和下一张准入，前端不建立平行队列。运行状态与各图片回执分别展示；源码测试仅证明状态与排队行为，不证明真实供应商已成功出图。
