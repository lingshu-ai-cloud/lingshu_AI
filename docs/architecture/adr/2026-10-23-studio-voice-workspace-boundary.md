## 所有权

| 模块 | 完整职责 |
| --- | --- |
| `useStudioVoiceState.ts` | 音色、语言与翻译状态、配音结果、每语言 TTS 设置、请求身份、输入/播放器 Ref、字幕设置；有依赖的状态组仍在原位置调用 |
| `useStudioVoiceModel.ts` | 主语言/完整口播、活动配音、每语言声音读取、草稿陈旧性及语言准备度 |
| `studioVoiceTranslationActions.ts` | 提取口播、批量翻译与既有单语言重试、恢复代际检查、语言添加/删除及关联结果清理 |
| `studioVoiceSynthesisActions.ts` | 清除配音、口播/音色上传、完整多语言翻译准入、配音任务分组、原声镜头排除、结果接受与对齐 |
| `studioVoicePlayback.ts` | 语言试听动作、活动音频同步、时间高亮事件和离开步骤停止试听 |
| `useStudioSubtitleReview.ts` | 字幕生成、预览、完整口播/分镜对齐与审阅投影、文本编辑及渲染失效、双语翻译与预览下标约束 |
| `studioVoiceSoundtrack.ts` | 曲库及配乐状态、列表读取、上传/选择、试听、收藏持久化、装配/语言版本绑定与渲染失效 |
| `useStudioVoiceLifecycle.ts` | 音色能力/样本读取、参考声音策略、原片无声选择、翻译离开清理 |
| `studioVoiceLifecyclePorts.ts` | 122 个只读类型端口；每个消费者只接收其使用的 `Pick` 字段 |

## 跨领域依赖与时序

项目回填和声音动作共享原 `voiceDraftAbortRef`、`studioSpecEpochRef`、`ttsRequestRef`：恢复后的翻译重试不得回写，旧 TTS 响应不得覆盖新结果或清除新加载状态。语言删除仍取消当前翻译，保留原文，并清理被删语言和原有渲染输出。配乐变化继续使相关渲染结果失效。

所有状态 Hook、`useMemo` 和 Effect 保留原调用位置和注册顺序。内部 getter 读取同一渲染闭包，五个动作工厂在构造时不访问未来绑定；回调内的读取仍延迟到回调调用。字幕审阅的渲染失效动作原本定义在后部，现在也不会提前读取。没有可变全局端口或复制状态的缓存层。这些接线仍是后续页面装配需要收敛的依赖面，不能将迁出函数等同于控制器已完成治理。

TTS 保留原有事实边界：实测 cue 存放在音频结果中，独立字幕生成动作管理可编辑字幕草稿；比例对齐没有实测证据时仍标记 `pending_alignment`。本批不改变原供应商调用语义、自动重试次数或失败处理。

九个生产模块逐进程独立加载成功，运行时静态依赖图没有反向加载 `AiCreateStudio.tsx` 的路径。实际生成的视图 chunk 也不直接或间接回导主页面。主页面 chunk 为 **356,669/485,000 字节**，较上批增加；不据文件缩短宣称性能改善。
