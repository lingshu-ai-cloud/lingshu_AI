# 实际口播驱动固定分镜槽，复用既有生产链

日期：2026-10-28。状态：MVP 续修源码与受控回归通过，非真实整链产品验收通过。

产品规则以 [开发文档](../../development/视频口播驱动与时间线衔接开发方案-20261028.md) 为准。用户已授权在 `1028视频联调` 并发开发。

## 决定

- 新计划显式使用 `type-aware.v3`；历史冻结 v1/v2 保留原身份和恢复路径。仅前向新建或明确修改计划采用新策略，不静默迁移已付费任务。
- 对标槽数、顺序及口播关系固定，按标签选择真人口播或非真人主题素材。主题匹配不追加旧动作、构图、人物或SKU视觉相似门槛。
- 实际语音及校准是定时依据。真实cue边界和锚点间的参考节奏推导分别记录，禁止把估算伪装成实测。下游仍使用现有计划、切片、manifest与渲染。
- 新成片manifest记录 `videoWorkflowPolicy: voice-driven-slots.v1`。新质量报告绑定实际成片哈希，检查0.3秒同步及字幕样式2/3抽样；不能仅有策略标记就绕过质量证据。旧检查不适用时明确标注，不能伪造旧评估通过。
- 复用整片费用账本及血缘；新策略自动额度为整片15元、时长30秒，返工与未知费用继续占用原额度。客户端自报更高额度不是用户追加费用的证明。
- 不新建队列、素材库或平行执行系统。确定性操作由既有Worker负责，业务决策由编导/内容职责承担，当前成片接受仍归用户。

## 实施边界

第一批是节点衔接与可测试策略，不宣称真人时长报价重规划、生产像素识别、用户确认恢复或真实E2E已完成。检测器缺失时保留 unknown，历史结果不重写。后续每批按开发文档的最小缺口继续，并记录产品入口证据。


## 第二批：人物供给在实测语音后冻结

新建 v3 人物任务采用 `voice-driven-budget-stages.v1`：开始前只读报价整链，前置阶段仅预留来源素材和语音操作；校准完成后投影固定槽时间，重新冻结人物首帧和母段，再在原整片 scope 追加人物预留。这样避免给旧参考时长的首帧或视频付费后再更改合同。

原 `scope.planHash`、费用血缘和来源/语音操作身份保持不变。`social.whole_film_budget` 保存阶段、原计划证明和实测证据绑定；预留后检查点写入前中断，以相同操作身份恢复。旧冻结任务不自动升级，也不虚构拒绝回执释放预算。图中的语音节点先完成自身检查点，人物节点再处理人物准备与费用阻塞。


## 第三批：非人物本地素材窗口的派生执行计划

真实语音校准后，非人物主题素材优先在原已分析段内裁短或扩展，不足才按现有主题匹配器换源。重选只进入免费本地供给适配器，原付费scope与source checkpoint不改。`social.measured_local_materials` 保存原plan hash、语音hash、实测槽位、当前候选及源字节证据、派生窗口与本地回执；编辑/Director新版本消费派生源，参考来源时间仍保留。

窗口不足、来源版本或字节无法核验时，其他ready本地槽仍执行并保存结果，缺失槽转原任务受阻状态。恢复重新读取当前权限与版本，不以旧completed checkpoint跳过。可信实测编辑计划依据固定槽完整覆盖判断，不再强加两镜/5.5秒要求；历史计划检查不变。待补用户提交和独立付费槽并行调度尚未实现。

## MVP 续修：原权威与运行期派生结果分开验证

- 标签补齐使用现有模型分类器、原成片账本及付费许可。原分析与冻结 Graph 继续作为业务权威；仅持久化绑定原观察哈希和槽位映射的运行期标签 overlay。Graph 阶段先补输入，再消费既有构建器重新计算且通过的执行审核；排队本身不等于审核通过。
- 初始补料只解封既有恢复检查点明确选择并重新核验的素材来源。原库存/Graph 身份保持冻结，派生计划和审核绑定同一运行及原选择证据。初始业务计划哈希排除库存扫描时间和生命周期投影戳；真实路线、来源、窗口和权利仍在身份中。API 当前版本校验保留，待拍证据沿其原创建版本验证，不随状态投影改写。
- 真人局部返工沿用原全轨语音与真实校准，复用既有 whole-track HeyGen bridge。每个新付费操作使用原整片 scope 的 canonical intent；多槽预留与超额决定在同一账本锁内原子处理，不另建聚合费用。未知费用保留占用，未知原请求不重复提交。
- 字幕未配置可信像素识别器时保留 unknown。人工可针对当前成片明确接受未知项或确认字幕样式受阻；已测音画同步失败仍不可放行。验片节点确认与最终成片接受分别保留，不由 Agent 代替用户验收。

本节是源码衔接及隔离验证边界，不代表真实供应商、完整业务链路或发布验收通过。具体命令与结果见开发文档第 18 节。
