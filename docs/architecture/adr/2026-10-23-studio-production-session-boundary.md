## 完整职责边界

`studioProductionSession.ts` 集中处理普通数字人任务的方案保存、草稿保存后的提交、未结束任务去重、未知结果请求 ID 保留、手动/自动刷新、项目任务读取恢复、参考人物任务取消、费用回执核对和采用回执。这些 API、去重 Ref、请求身份与任务/方案/执行记录属于同一个会话，不另建提交链或将原回执当作失败后自动重提。

页面通过原 CAS 入口延迟采集草稿，并保留选中镜头、叙事/人物/保存准入检查、指纹规则及共享镜头/素材写回。完整回包触发同步写回回调，回调仍负责完整片长、正常速度和候选采用；不是先提前写入成功再等待网络结果。共同的忙碌、错误和通知仍与句级生产事务共享同一组页面状态，未复制状态。

三组记录 Hook、刷新去重 Hook、请求身份 Hook及两个恢复 Effect 保留原注册位置。项目/声音已有领域及句级/批量事务没有在本批重新拆分。输入是明确的任务、草稿范围能力和必要反馈回调，没有新增 getter 字典或入口反向依赖。

主页面 **7,155→7,076 行**，新会话模块 **254 行**。净降行数不是验收标准；本批价值是七个页面任务动作和相关读取/自动恢复共用可独立验证的完整会话，以及实际修复项目切换时的写回安全问题。

## 必要的行为修复

新增延迟回包测试在拆分后的保留原语义实现中复现四个既有缺口：旧草稿回包后仍可继续提交；旧采用回执允许页面写回；执行详情在切换项目后仍可覆盖列表；旧 CAS 保存结果覆盖新编辑器版本信息。它们直接影响用户明确要求保护的请求/项目边界，属于既定验收的必要修复，不是扩展功能。

- 草稿桥绑定发起时的页面项目身份；自身首次保存取得的新项目 ID 可以继续同一事务，切到其他项目则失效。
- 提交、方案保存和采用在每个相关异步边界检查范围，旧响应不能继续供应商提交、覆盖当前记录或授权当前镜头写回；旧异常不覆盖新项目错误。
- 已知的供应商回执仍留在原项目服务端记录，已确认响应可以释放该请求 ID；未知提交仍保留原请求 ID，不自动重试或取消任务。
- 刷新在执行详情查询后补充项目检查；版本化保存返回原服务端结果，但跨项目时不采用旧编辑器版本或弹出旧冲突提示。

这不是所有保留业务跨项目并发问题已被全面修复的声明；保护范围以本批实际测试场景为准。
