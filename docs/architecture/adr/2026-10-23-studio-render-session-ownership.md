## 问题与边界

`AiCreateStudio.tsx` 既组织分镜、字幕、配音、封面和多版本参数，又直接持有渲染状态、任务代次、桌面进度订阅、持久任务轮询、项目恢复及输出历史。同一渲染生命周期分散在状态区、恢复 Effect、`goPreview` 和语言版本动作中。

本批新增 `src/components/studio/studioRenderSession.ts`，拥有十组渲染状态、两个内部 Ref，以及以下完整流程：

- 封面请求及结果写回后，调用同步的 `prepareSpec(coverUrl)` 取得既有成片参数；参数验证失败走同一个渲染失败出口。
- 桌面短期授权、原生渲染、进度订阅及 `finally` 释放；浏览器自由创作的持久任务提交、轮询和输出写回；其他网页工作流的短期授权、本地同步渲染及进度定时器释放。
- 请求代次保护，防止旧请求进度、封面和成片完成结果覆盖新请求；保留原有错误传播。没有新增服务端取消接口，也不把忽略旧结果称为取消服务端任务。
- 单个选定语言版本的忙碌状态、当前组合、成功/失败输出及代次历史写回。
- 项目刷新恢复的查询、定时轮询、完成/失败写回及 Effect 退出后的迟到响应保护。

页面保留跨领域就绪检查、步骤导航、版本选择以及分镜/字幕/配音/封面/特效的完整 `RenderSpec` 组装。组装逻辑通过同步回调在原来的封面完成时机运行，保留原点击闭包；持久项目 ID 通过窄解析能力在原提交时机读取。这是调用参数，不是把整页状态作为动态 getter 字典交给新模块。没有新增 getter 接线或页面反向依赖。

## 兼容与依赖

沿用 `studioApi`、`RenderSpec`、`LanguageRenderOutput` 和 `LanguageRenderGeneration`，没有新增 HTTP、供应商或数据库合同。页面项目恢复/共享编辑失效和既有视图通过同一组状态读值/必要 setter 接入，不复制输出或状态。

本批把渲染状态集中到一个 Hook，初始值不变；Hook 注册顺序有调整，不宣称整个页面 Hook 顺序或热更新中的在途状态完全一致。项目恢复 Effect 仍位于原注册点，依赖仍是自由创作开关和项目 ID。生产的持久请求、轮询间隔、错误文案、授权选择及写回顺序保持原规则，不在结构拆分中扩展并发控制策略。

主页面从 7,526 行变为 7,394 行；渲染模块 225 行。源码总行数包含明确请求合同和可验证的生命周期所有权，不能只以净减行数判断拆分是否成立。主页面可以超过 800 行，仍须继续审查分镜生产、质检及交付等实际职责，不因本批完成而宣布最后一个原始大文件治理结束。
