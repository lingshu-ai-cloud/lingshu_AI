# ADR：数字员工任务纠偏的应用与 HTTP 边界

- 日期：2026-10-23
- 状态：已接受

## 问题

主路由同时实现任务纠偏状态机、编导决策、租户业务证据校验和 HTTP 协议，助手与移动端也必须复用同一纠偏入口。仅将端点代码换文件不能建立独立可验证的应用边界，复制纠偏则会分裂授权、审计和下游失效规则。

## 决策

`createTaskInterventionApplication` 是重试、跳过、人工完成、重规划、编导决策和证据补充的共享应用装配入口。它接受明确类型的租户读取、存储、业务观察、事件/审计、运行继续和下游失效端口，不依赖 Express、请求、响应或具体存储后端。

应用用例在原 run 锁内复核任务、任务版本、运行状态、人工接管、审批限制、精确分析覆盖和真实回执，再写纠偏记录及任务状态。规则候选保留人工审阅状态，不自动成为长期规则。证据在当前租户中解析，补充成功后去重并使相应下游审批重新预检；不因文件迁移扩大证据资格。

编导继续保留周授权，调整/放弃仍通过已审计的任务纠偏重建内容路由；尚未应用纠偏的失败恢复原计划。应用完成后 HTTP 适配读取经营总览，展示读取不属于业务状态变更端口。

`registerTaskInterventionRoutes` 负责 HTTP 输入、状态/错误映射和请求完成后的总览投影。身份来自上层认证上下文；主路由的认证和支持会话只读门禁必须先于挂载。制作预算路由仍在原注册位置接入既有服务，不复制预算逻辑。

主路由保留兼容的 `retryDigitalEmployeeTask` 导出，助手请求处理器使用同一个应用实例。普通运行的依赖失效与纠偏均调用原 `taskCorrectionSupersession`，并复用现有持久队列控制。不存在新增供应商请求、付费许可签发器或自动重试通道。

## 验证与限制

- 独立应用行为测试覆盖纠偏写入、版本/租户拒绝、审批与回执保护、精确覆盖、重规划、证据补充和编导回滚。
- 本地临时 HTTP 服务测试覆盖认证身份传递、快捷与详细操作共用应用入口、参数拒绝、错误状态/细节及继续运行的调用边界。
- 原数字员工领域组、租户隔离、TypeScript、架构 ratchet、迁移清单只读检查及生产构建分别验证；这些不代替真实供应商、数据库部署或登录后浏览器验收。
- 主路由仍有执行协调、审批及周计划职责待拆分；本 ADR 不将行数预算通过定义为架构完成。
