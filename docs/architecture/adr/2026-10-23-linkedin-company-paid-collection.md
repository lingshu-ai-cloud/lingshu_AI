# ADR：LinkedIn 公司帖付费采集按逐任务许可开放

- 日期：2026-10-23
- 状态：分阶段实施；当前未签发生产许可，入口默认关闭

## 决策

LinkedIn 公司帖只接受规范的公司主页 URL 和账户模式。服务端冻结租户、发现 run、主页、日期窗口、最多 30 条及 Actor 输入摘要；普通 HTTP 参数不能签发付费许可。采集调用必须先取得与该冻结范围、Actor 和输入摘要完全一致的服务端许可。

复用现有 Apify 异步运行传输：提交前先将唯一操作持久转为 `submitted_unknown`；POST 回执必须记录 run ID 与 dataset ID。若提交响应丢失，不自动重发。后续仅以原 run GET 恢复，校验 Actor 费用上限和已结算用量；数据集 GET 还需独立覆盖读取/传输费用的许可。供应商异常不得被图文采集的“零结果”降级捕获。图文和视频入库仍使用现有租户记录路径与来源解析。

## 当前实施范围

`linkedinCompanyPostPaidCollection.ts` 已实现冻结输入、许可范围校验、受控 Apify 传输和纯来源解析；视频与图文内部采集函数仅在受信任调用者提供许可时进入这条路径，原手工 HTTP 入口仍不接收 LinkedIn。`linkedinCompanyCollectionApproval.ts` 和对应迁移新增了私有、不可更新的逐 run 批准与撤销记录；批准绑定当前发现范围版本/摘要、租户公司账号、冻结 Actor 输入及 CNY 上限。重复批准由数据库唯一索引仲裁，读取时重新检查当前范围和账号。新增 store-backed 的批准断言，受控传输在 Actor 提交前及数据集读取前各再次核验撤销与范围变化；撤销无法取消已提交的 Actor，但会阻止尚未提交的请求和后续读取。该记录本身不是付费许可，也没有挂接普通发现 worker。当前仍缺可验证的 Apify 账号价格与汇率/非 Actor 费用凭据、跨实例唯一许可签发器和运行回执链，因此生产入口仍默认报 `linkedin_company_paid_collection_permit_required`。接口形状及模拟测试不等于真实付费门禁已经完整接线，更不授权真实 Actor 调用。

下一阶段必须将已落库的逐任务批准和 CNY 上限，与 Actor USD 上限、独立数据集/传输费用、账号/Token 指纹、唯一操作认领和原始运行回执绑定到耐久权威记录；在真实目标存储上只读验证跨实例唯一写入能力，并做离线断连、恢复及租户隔离测试。未满足这些条件时不得通过前端请求标志或环境变量绕开默认拒绝。

## 原始响应回执边界（2026-10-23 增量）

受控 LinkedIn 许可现在必须提供原始回执持久化回调；共用 Apify 传输在 Actor POST、run GET 和 dataset GET 收到 HTTP 响应后，先等待该回调，再解析响应或更新运行终态。新增 `linkedinCompanyReceiptStore.ts` 以批准记录哈希、租户/run、Actor、冻结输入、操作和 Token 指纹绑定只写一次的原始状态码与正文；共享根目录缺失、回执冲突或超大响应时失败关闭。Actor POST 响应已到达但回执未落盘时仍保持 `submitted_unknown`，不得重发。现有 TikTok 传输未强制新回调，维持其已有许可边界。

这只补齐回执存储原语和 LinkedIn 路径的必要接口；尚未建立可信账号价格/汇率与非 Actor 费用报价、跨实例预算预约和唯一许可签发器，也未在目标部署验证共享卷。模拟回调不构成生产许可。真实 LinkedIn Actor 请求及数据集 GET 继续默认关闭。

## 原始响应流式上限（2026-10-23 增量）

要求原始回执的受控 Apify 请求在读取响应正文时采用与回执存储相同的 8 MiB 字节上限；超限即停止继续读取，不能先将无界正文加载到内存再由存储层拒绝。Actor POST 已提交而响应超限时保留 `submitted_unknown`，禁止自动重发。这个上限只限制应用接收与保存的原始正文，不是供应商传输费用上限，也不能替代非 Actor 费用预算或生产许可签发器。

## 人民币最坏情况报价准备（2026-10-23 增量）

`linkedinCompanyCollectionQuote.ts` 在已落库的逐 run 批准仍有效时，向受信任服务端端口读取账号/Token 指纹及账号专属费用证据。报价同时包含 Actor 美元上限乘以经验证的人民币汇率上界，以及数据集读取、存储、传输等所有非 Actor 费用的独立人民币上界；缺少任一费用证明、账号绑定不符、证据过期或总额超批准上限均拒绝。输出固定操作标识、批准哈希、Actor 输入哈希、证据哈希和总预留微元，来源在报价前后各复核一次。离线测试覆盖账户变更、漏报费用、超预算和报价过程中来源撤销。

报价端口尚无目标 Apify 账号费率、汇率及非 Actor 费用的真实权威实现；报价结果本身不落账、不认领操作，也不是付费许可。下方增量补了离线可验证的预约、唯一提交和回执状态核对，但仍需在目标共享卷和存储上验证，才可能把内部采集接到普通发现 worker。真实付费入口继续关闭。

## 持久唯一认领与许可账本（2026-10-23 增量）

`linkedinCompanyCollectionPermit.ts` 现在只从服务端可信报价端口重新计算报价，再核验当前逐 run 批准、账号/Token 指纹、费用证据与人民币上限；共享目录中按批准和操作标识持久预约最坏费用。Actor POST 前在现有付费操作锁下唯一转为 `submitted_unknown`，同一任务无法再次 POST；原始 Actor 响应与 run GET 回执校验后才记录运行身份及结算用量。数据集 GET 另行唯一认领，原始响应保存后才记录完成回执。许可实际传输前核对当前 Token 的冻结指纹，报价变化、撤销、回执缺失和结果未知均失败关闭。离线集成测试仅以 Mock HTTP 模拟传输与重启后的禁重发。

该账本仍不是生产开放证据：可信 Apify 账号价格、汇率和非 Actor 费用端口尚未接到真实权威来源；目标部署的共享卷/跨实例锁语义未验证；普通发现 worker 没有许可签发接线。没有这些条件，不给内部采集函数传入许可，也不执行真实 Actor 或数据集请求。若 POST 已提交而回执未知，只能人工核对原 Apify run，不自动重发。
