# ADR：LinkedIn 公司帖付费采集按逐任务许可开放

- 日期：2026-10-23
- 状态：分阶段实施；当前未签发生产许可，入口默认关闭

## 决策

LinkedIn 公司帖只接受规范的公司主页 URL 和账户模式。服务端冻结租户、发现 run、主页、日期窗口、最多 30 条及 Actor 输入摘要；普通 HTTP 参数不能签发付费许可。采集调用必须先取得与该冻结范围、Actor 和输入摘要完全一致的服务端许可。

复用现有 Apify 异步运行传输：提交前先将唯一操作持久转为 `submitted_unknown`；POST 回执必须记录 run ID 与 dataset ID。若提交响应丢失，不自动重发。后续仅以原 run GET 恢复，校验 Actor 费用上限和已结算用量；数据集 GET 还需独立覆盖读取/传输费用的许可。供应商异常不得被图文采集的“零结果”降级捕获。图文和视频入库仍使用现有租户记录路径与来源解析。

## 当前实施范围

`linkedinCompanyPostPaidCollection.ts` 已实现冻结输入、许可范围校验、受控 Apify 传输和纯来源解析；视频与图文内部采集函数仅在受信任调用者提供许可时进入这条路径，原手工 HTTP 入口仍不接收 LinkedIn。现阶段没有 LinkedIn 专用的耐久批准记录、可验证 Apify 账号价格与汇率/非 Actor 费用凭据、跨实例唯一许可签发器，因此普通发现 worker 不能构造许可，生产入口仍默认报 `linkedin_company_paid_collection_permit_required`。接口形状及模拟测试不等于真实付费门禁已经完整接线，更不授权真实 Actor 调用。

下一阶段必须将用户逐任务批准、CNY 上限、Actor USD 上限、独立数据集/传输费用、账号/Token 指纹、唯一操作认领和原始运行回执绑定到耐久权威记录；在真实目标存储上只读验证跨实例唯一写入能力，并做离线并发、断连、恢复及租户隔离测试。未满足这些条件时不得通过前端请求标志或环境变量绕开默认拒绝。
