# 图文复刻接入统一持久化执行队列

## 问题与范围

功能分支 `feature/image-text-viral-creation-20261026` 从源码检查点 `907e74d1476d96a4ea65b5eadfa76e375da2235b` 开发。原流程仅创建 ContentTask 和图文子运行，随后依靠浏览器连续请求；详情页又套用视频进度，无法证明入队或恢复。

本次只解决单张产品海报的图文爆款复刻调度，不扩展轮播、GIF、发布和供应商重试。默认集成基线不变。

## 决定

- 使用现有 `content_execution_jobs`、DurableContentExecutionWorker、租约、并发限制及检查点。增加 `social_image_replication` 执行类型，由原内容生产 Worker 分派，视频执行路径保持原有运行身份。
- ContentTask 的视频 `run_id` 不写入图片 ID；图文使用原 `studio_projects` 子运行。通用执行上下文验证租户、ContentTask、图片运行及确认检查点，再允许工作。不伪造 workflow_runs。
- 最终对话确认调用鉴权、订阅门禁后的入队命令，HTTP 202 只在持久记录存在后返回。同一运行重复确认返回原回执；不会自动重启 blocked/succeeded 任务。
- 提交时校验快照与当前任务版本，冻结输入 hash。每个执行边界重新核验身份、版本、取消状态与输入。`dispatch` 校验允许未核验素材的任务进入准备阶段，原付费准入继续要求 business_context 等完整证据。
- 素材核验、分层渲染、质检和策划从 HTTP 回调迁至领域命令，HTTP 与 Worker 复用。Worker 使用已认证任务身份进行订阅/试用配额检查，不保存或重放浏览器令牌。
- 策划调用前持久化检查点；结果未落库时停止人工核对。视觉质检继续使用既有 CAS 和 outcome_unknown 规则，不自动重付。质量或编导未通过会阻塞，已有图片保留，用户验收不会被自动完成。
- 页面只提交和轮询，详情页使用真实图文节点、调度回执与图文状态，不再显示口播、分镜等视频节点。通过 ContentTask 可恢复详情，无需保留浏览器一次性启动标记。

## 验证边界

新增调度/HTTP/租户/版本/取消/重放/Worker 重建测试；离线媒体测试使用真实本地像素渲染和明确的视觉 QA 替身，不代表真实模型质检。另运行原图文管线、原队列领域回归、6 个隔离 UI 场景、TypeScript、架构和构建。

本地预览目前为 HTTP-only web 角色；源码接入不自动开启全局 Worker，也不领取其他历史任务。真实供应商联调仍遵循外部 E2E 手册，不能以入队和离线测试代替付费生成验收。
