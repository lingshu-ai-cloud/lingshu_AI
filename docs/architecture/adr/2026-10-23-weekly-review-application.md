# ADR：周复盘到下一周期的应用边界

- 日期：2026-10-23
- 状态：已接受

## 问题

数字员工主路由同时负责业务数据复盘、定时生成标记、复盘待办分配和托管周期续接。正常执行收尾、手动刷新和后台调度都需要这些规则；只拆单个端点会留下跨入口的重复实现风险。

## 决策

`createWeeklyReviewApplication` 是该完整职责组的共享装配入口。应用接受明确类型的存储、租户读取、业务快照、事件/审计、有效配置、事实重建状态和周目标批准端口。主路由只提供这些依赖并保留原有后台公开导出，应用不导入 Express 或主路由。

复盘聚合仍按租户及运行/任务血缘筛选记录，读取实际业务快照，保留资料缺口、内容反馈、矩阵与下一轮建议。复盘记录写入失败必须抛错；生成报告不负责将活跃运行标记完成。摘要纯投影下沉至 `weeklyReviewProjection`，原导出路径兼容转发。

手动生成和定时生成共用 `generateRunReview`。定时入口继续按租户/运行串行执行，并在报告生成之后写入 `review.scheduled` 时段标记。此既有进程内队列加持久标记不等于跨实例的原子认领，本批不扩大其并发保证。

复盘待办分配复用主路由的启动队列，避免与直接批准建立两个互不协调的启动锁。原目标/计划复用、任务要求去重、计划 CAS、事实重建门禁及失败后的草稿链接保持原流程。实际启动继续调用同一 `approveGoalForReview`；不为复盘待办设置旁路。

托管续接保留数据库租约、源运行/复盘/授权检查、跨页查找已保存目标、计划来源绑定、写入后再次检查授权及原批准入口。复盘建议不会自行提高周期预算、恢复撤销许可或重发结果不明的供应商请求。

`digitalEmployeeWeeklyReviewRoutes` 只处理 HTTP 身份、参数、错误和总览响应。待办读写与派发仍委托现有 `ReviewTodoService`，其修订号与用户授权规则不复制到新模块。所有端点必须在父路由认证与支持会话只读门禁后注册。

## 验证与后续

- 独立应用测试覆盖持久复盘、刷新、租户拒绝、定时时段去重、失败无成功标记、待办源权限和租约释放。
- 本地 HTTP 测试覆盖两种生成入口、错误状态、可信身份、待办修订号及共享分配器。
- 既有待办完整集成验证部分写入恢复与不重复建运行；托管组继续验证租约、授权续期/过期/撤销、预算和来源恢复，测试中禁止真实供应商请求。
- 数字员工主路由仍有执行协调、周计划与审批等职责；其他四个超限文件也未因此完成拆分。行数预算仅用于阻止债务增长，不是结构验收标准。
