# ADR：AIGC 合并边界

- 日期：2026-10-21
- 状态：已接受（阶段性）

## 背景

AIGC 分支与集成基线同时演进。图片生成路由包含较新的租户素材、安全和供应商预算边界；整体覆盖会丢失这些基线改进。自动合并无法安全判断两侧行为。

## 决策

优先选择性合入任务合同、关键词策划、参考文案传递、固定图层能力、确定性预检与多模态复核，并保留集成基线的租户和素材准入路径。单图生成使用 GPT Image 2 的质量参数并将默认值设为 Low。

轮播与 GIF 保持未开放：在生成路由支持多输出持久化、幂等恢复、媒体编码与质量审查前，不声称它们已集成，不启用对应 UI。

## 后果

- 保留了集成基线安全边界，但本次不是 AIGC 全功能合入。
- 后续需在独立变更中完成多输出 route/task/API，并覆盖重复请求、部分失败、恢复和租户隔离测试后，才可启用轮播/GIF。
- 不执行真实付费供应商调用；需另行授权真实联调。

## 2026-10-22：图片证据复核增量边界

已合入 Qwen 结果的纯复核信号和 GPT 图片证据适配器，但未将适配器接入爬取或重分析路由。原分支会在 Qwen 失败或低置信度时直接发起第二次付费请求；集成基线的爬取入口有些在记录落库前运行，无法证明该请求已有逐记录授权、全量预算预留与结果不明恢复，因此不直接合并这一自动回退行为。

适配器仅接受已由可信任务计划生成的付费许可：计划必须冻结模型、图片、提示词及完整请求哈希，可信计量器给出同一请求的多模态输入上界，许可在网络调用前持久标记结果不明。供应商响应须先持久化原始回执，再将操作标记完成；传输、回执或解析失败均不得自动重发。下一阶段须为图片记录建立独立的授权、报价/预留、持久回执读取及只读恢复流程，并调整爬取顺序，测试重复请求、租户隔离和崩溃恢复后才允许路由调用适配器。真实供应商联调仍需单独授权。

## 2026-10-22：复用现有付费账本的逐记录上下文

图片记录在远端 PocketBase 存储没有可证明的原子 CAS，故其普通 `update` 不能承担唯一付费认领。复核上下文改用现有社媒付费账本和共享卷一次性许可，冻结租户、记录 ID、记录快照、完整供应商请求哈希、单项已批准计划和经过验证的账号报价；实际发送前还要核对端点与密钥指纹对应的账号。缺任一条件均拒绝提交。原始 HTTP 响应按同一身份以不可覆盖文件持久化，并可在重新构建上下文后只读恢复。记录在供应商飞行期间变化时，仍先保留响应回执；预算结算可能保持结果不明，需人工核对，绝不因此重发。

这仍是可复用的服务层边界，不是自动回退已开放：还需为 `trend_videos` 建立独立的持久人工批准记录、可信多模态输入上界计量与账号报价接线，调整爬取先落库的顺序，完成路由/租户/并发/崩溃测试，并证明部署中 Web 与 worker 共享相同持久卷。未做真实供应商调用。

## 2026-10-22：图片爬取分析职责迁移

公开图片读取、Qwen 主分析、现有 Gemini 降级和延迟分析写回从 `videos.ts` 迁至 `server/socialDiscovery/imagePostEvidenceAnalysis.ts`；路由保留租户鉴权、源记录创建和采集编排。此批保持旧调用时机与结果写入行为，未接入 GPT 复核。现有 Gemini 自动降级仍未经过新建的逐记录预算许可；在迁移到批准后复核或去除旧降级之前，不能将整个图片分析链称为付费治理完成。下一阶段需调整新记录先落库再冻结快照，并对爬取、重分析和延迟队列共用同一批准/恢复边界。

## 2026-10-22：新增图文先持久化再分析

新增图文的记录创建与来源图片持久化收敛到 `server/socialDiscovery/imagePostImport.ts`。租户记录和来源图片写入成功后，才运行现有视觉分析或安排延迟任务；写入失败不启动分析。这里仅建立未来逐记录批准所需的记录身份与来源前置条件，未授权或接入 GPT 图片复核。既有记录刷新、显式重分析和延迟执行仍需统一冻结快照、批准、预算和只读恢复；现有 Gemini 自动降级也仍未纳入新边界。

## 2026-10-22：既有图文刷新先写来源

既有图文的来源更新和视觉分析拆到 `server/socialDiscovery/imagePostRefresh.ts`，并改为先持久化新图片来源及 `pending` 状态，再调用现有分析器；持久化失败不分析、不入延迟队列。已有分析的延迟采集仍按旧策略同步重分析，未改变其调用选择。显式重分析和延迟任务实际执行尚未共用该流程，GPT 复核与 Gemini 自动降级也仍未通过逐记录许可。
