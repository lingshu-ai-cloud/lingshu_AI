# 客服契约与可恢复批量管理

- 日期：2026-10-22
- 状态：客服独立分支实施，等待集成
- 源码起点：43892e74

## 决策

复用 customer_segments、customer_segment_members、followup_batches、followup_batch_items、现有审批和渠道发送账本。批量筛选不另建群发路径；筛选目的与执行动作分别记录。screen 只保存筛选结果，draft 继续使用原有草稿、审批、模板及派发链。

共享 Zod 契约定义筛选和草稿输入，拒绝未知字段和错误取值；能力发现接口返回 JSON Schema、操作入口、渠道边界和状态。原分群入口也执行同一条件校验。业务提示和机器错误码分别表达，前端不能把服务失败替换成没有标记的成功文案。

交互草稿、逐客跟进生成及标签分类共用 customer_reply_requests 请求账本。唯一请求身份绑定租户、操作者及输入摘要。结果写入后才回成功；超时或写回不确定保留原请求，只查询原结果，不自动再次调用供应商。模型输出本身不可恢复时保持明确未知，不伪造成功，也不宣称已经取回原供应商结果。

分群和批次先保存完整冻结计划，以 building 状态逐条写成员或明细。重启后按确定性子记录 ID 补齐原计划，不改用最新会话或重新生成正文。JSON 哈希采用已有规范化实现，不依赖数据库对象字段顺序。只有成员完整且校验通过后才发布 generated/draft。

分类来源绑定当前账号和已准入买家会话指纹。允许恢复有当前消息证据的业务标签；不恢复未经证明的旧聚合画像。退订、禁止联系和人工处理等限制保守保留。人工确认语言、时区和新询盘关系需要当前消息指纹及操作者留痕；已有往来不等于付款，成交筛选明确使用订单台账记录，不声称核验了支付网关。

预览返回逐客纳入、排除、待核实原因和买家证据；冻结要求同一个 previewHash，来源或客群变化即拒绝。资料未知和渠道范围未确认，不能被转为成功空批次。重复冻结同一已完成范围不重置后续执行；新范围使旧批次和审批失效，存在发送痕迹时拒绝重新分群覆盖。

Messenger 持续校验实时权限证明有效期，但业务身份哈希只覆盖租户、账号、Page、应用、权限和凭据，排除证明刷新时间。正常刷新不再使新冻结范围失效；权限、凭据及账号变化仍然阻断。旧版本哈希产生的历史范围可能需要通过原流程重新核验，不能自动改写已批准证据。

企业微信复用现有签名、解密、回调持久化和处理服务。正式父服务挂载客服路由和签名回调；回调先落库再 ACK，重复回调不重复处理，处理失败沿用已有恢复入口。

## 保留的执行边界

正式 WhatsApp 入站仍负责保存消息与资质更新。状态接口和能力发现明确说明这个边界，不再声称当前正式入口已经接通自动发送。工作台草稿和已审批周跟进继续可用。

Messenger、Instagram 的周派发仍要求原有具体会话选择凭据。未选择的客户可以筛选和归类，不能凭标签绕过选择凭据进入派发。WhatsApp 超窗必须使用正式审核模板，所有渠道仍受人工接管、退订、版本、频率、排期和真实回执约束。
