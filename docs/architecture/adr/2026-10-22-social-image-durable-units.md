# ADR：图片多输出的耐久单元与付费边界

- 日期：2026-10-22
- 状态：待实现；此文件不授权启用轮播/GIF 或真实供应商调用

## 当前证据

图片工作台先由浏览器将 `generationJobs` 写入 `studio_projects.spec.socialImageTask`，再直接调用 `/studio/fb-poster/render`。该路由只返回单张图片；OpenAI 图片生成器虽接收 `idempotencyKey` 参数来计算本地请求标识，但未将其作为供应商保证的幂等键提交。供应商回执仅在 `runWithContentExecutionContext` 内写入耐久队列，普通 Studio 请求并未进入该上下文。断网、超时或服务进程退出后，客户端无法以任务状态证明供应商是否已收费或产物是否已落库。

`DataStore.supportsAtomicCompareAndSwap()` 在本地回退存储和 Postgres cutover 可为真，远端 PocketBase 当前报告为假；不能把其兼容层的读写接口当作跨实例原子认领依据。单靠浏览器按钮禁用也不是服务端幂等保证。

## 实现边界

1. 每个轮播页或 GIF 底图有确定性 `taskId + planVersion + unitIndex + inputHash`；服务端保存完整计划、素材版本和逐单元状态。计划变化必须生成新版本，不复用旧请求键。
2. 付费请求前必须由服务端原子认领对应单元，写入提交前状态和不可变请求摘要；没有经验证的原子存储能力时拒绝新付费单元，而非降级为进程内锁或普通 read/update。
3. 一旦进入“可能已提交”，超时、断连、5xx 或进程崩溃均保持 `outcome_unknown`，不得自动再调供应商。确定未提交的准入失败可释放单元；有供应商任务 ID 或可取回结果时先对账。
4. 成功媒体先写入租户隔离的耐久素材库，再原子关联单元输出与回执。若素材已落库而任务写回失败，依据素材来源键和内容哈希对账，不重发付费请求。
5. 四个轮播页必须逐页持久化并能在刷新后显示已完成、待运行、待对账状态；GIF 只能在各底图均有可核对产物时执行固定图层合成和编码。质量检查/人工审阅与生成状态分开记录。
6. 测试必须覆盖并发双提交、同键重复请求、换输入碰撞、首张成功后第二张失败、写素材后写任务失败、供应商结果未知、进程恢复、跨租户访问及无原子能力时拒绝调用。真实供应商端到端验收需独立预算与授权。

## 本轮决策

继续保持轮播/GIF UI 不可选。已有单图浏览器门禁只减少误操作，不能替代本 ADR 的服务端耐久边界。后续先实现有原子能力后端的逐单元认领、写前回执和对账测试，再评估远端 PocketBase 的迁移或经验证的唯一约束方案；未完成前不声称图片 AIGC 全功能已合并。
