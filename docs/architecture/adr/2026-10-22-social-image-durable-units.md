# ADR：图片多输出的耐久单元与付费边界

- 日期：2026-10-22
- 状态：阶段记录；现行源码可选，但本文不授权真实供应商调用、生产迁移或部署

## 当前证据

图片工作台先由浏览器将 `generationJobs` 写入 `studio_projects.spec.socialImageTask`，再直接调用 `/studio/fb-poster/render`。该路由只返回单张图片；OpenAI 图片生成器虽接收 `idempotencyKey` 参数来计算本地请求标识，但未将其作为供应商保证的幂等键提交。供应商回执仅在 `runWithContentExecutionContext` 内写入耐久队列，普通 Studio 请求并未进入该上下文。断网、超时或服务进程退出后，客户端无法以任务状态证明供应商是否已收费或产物是否已落库。

`DataStore.supportsAtomicCompareAndSwap()` 在本地回退存储和 Postgres cutover 可为真，远端 PocketBase 的全局能力仍报告为假；不能把其兼容层的读写接口当作跨实例原子认领依据。单靠浏览器按钮禁用也不是服务端幂等保证。

## 实现边界

1. 每个轮播页或 GIF 底图有确定性 `taskId + planVersion + unitIndex + inputHash`；服务端保存完整计划、素材版本和逐单元状态。计划变化必须生成新版本，不复用旧请求键。
2. 付费请求前必须由服务端原子认领对应单元，写入提交前状态和不可变请求摘要；没有经验证的原子存储能力时拒绝新付费单元，而非降级为进程内锁或普通 read/update。
3. 一旦进入“可能已提交”，超时、断连、5xx 或进程崩溃均保持 `outcome_unknown`，不得自动再调供应商。确定未提交的准入失败可释放单元；有供应商任务 ID 或可取回结果时先对账。
4. 成功媒体先写入租户隔离的耐久素材库，再原子关联单元输出与回执。若素材已落库而任务写回失败，依据素材来源键和内容哈希对账，不重发付费请求。
5. 四个轮播页必须逐页持久化并能在刷新后显示已完成、待运行、待对账状态；GIF 只能在各底图均有可核对产物时执行固定图层合成和编码。质量检查/人工审阅与生成状态分开记录。
6. 测试必须覆盖并发双提交、同键重复请求、换输入碰撞、首张成功后第二张失败、写素材后写任务失败、供应商结果未知、进程恢复、跨租户访问及无原子能力时拒绝调用。真实供应商端到端验收需独立预算与授权。

## 已落实的单图边界

单图工作台现以 `queued` 状态入队；服务端在供应商调用前以原子 CAS 认领，将输入哈希冻结在 Job 上。无经验证的原子能力即拒绝调用。成功图片先落租户素材库，再由服务端把 `materialId` 与输出节点关联到 Job；重复认领被拒绝，未知结果不自动重发。通用任务 PATCH 只能追加新的排队 Job，不能删改既有付费记录，也不能在单元未解决时改写生成输入。素材来源记录包含任务 ID、Job ID 和输入哈希以供人工对账。

供应商返回明确的未接受请求（当前图片适配器的 `ImageProviderRejectedError`）时，Job 记录为可修正的 `failed`；超时、断连、5xx 与其他无法证明未收费的异常继续记录为 `outcome_unknown`。只有前者可在修改输入后开启新单元，不能把两类失败混用。

远端 PocketBase 现仅对 `studio_projects` 图片任务增加只读、逐次的 CAS claim 结构核验：必须能以管理员身份读取 `datastore_cas_claims` 的私有规则、必需字段与 `target_key` 唯一索引元数据，才能认领付费 Job。缺凭据、请求失败或结构不符均拒绝供应商调用；全局 CAS 能力不因此放开。代码与模拟测试不能证明目标 PocketBase 已应用迁移，本轮没有访问真实远端，也没有执行迁移。

单图现提供不付费的 `POST /social-images/tasks/:id/jobs/:jobId/reconcile-material`：服务端只从当前可读取的租户素材目录中查找与任务 ID、Job ID、冻结输入哈希一致的生成记录；须唯一匹配、租户存储定位正确、字节 SHA 一致且图片可解码，才通过原子 CAS 将素材关联到 Job。无匹配、有歧义、目录不完整或字节损坏都不会触发供应商请求。任务历史中的新单图素材使用稳定的受保护路径，不保存会过期的签名 URL。

该入口只能恢复**已落库且当前服务端可读取**的素材，尚不能凭供应商回执取回未落库输出，也不提供后台自动轮询或跨实例素材目录保证。因此供应商回执自动对账、完整断点恢复、逐页轮播及 GIF 编码的生产交付仍未完成。服务端明确拒绝把多输出类型误送入单图链路。

## 本轮决策

继续保持轮播/GIF UI 不可选。后续需在目标 PocketBase 上只读核验迁移状态、做不付费的跨实例故障注入，再完成供应商回执对账与人工恢复工具；未完成前不声称图片 AIGC 全功能已合并。

## 多输出计划持久化进展（2026-10-22）

新增服务端 `POST /social-images/tasks/:id/plan-units`：只有经过验证的原子存储能力才允许把轮播四页或 GIF 多底图的确定性计划、版本、输入摘要、各单元 Job ID 和幂等键一次写入任务。相同输入重放返回既有计划；过期版本、跨租户或尚有未解决 Job 时拒绝重新规划。通用 PATCH 不能伪造计划或服务端单元元数据，未解决单元期间也不能改写生成输入。审阅发布门禁要求计划内全部单元有已批准的素材输出，GIF 还要求最终动图素材。

这一步仅冻结耐久计划，**不启用多输出付费认领或调用**：现有 `claimSocialImagePaidJob` 仍拒绝轮播/GIF，UI 仍不可选。后续须实现逐单元请求、产物落库与回执、失败/未知状态恢复、GIF 编码交付及完整故障注入，才可开放入口。

## 后续实现状态修正（2026-10-22）

上文“UI 不可选”“仅冻结计划”是该阶段的历史判断，已被后续选择性集成取代。当前源码为轮播与 GIF 提供工作台选项、冻结的服务端逐单元输入与原子认领、已存素材的同租户只读恢复、结果不明停止自动提交，以及 GIF 底图齐备后的固定图层合成和动图登记。GIF 付费底图请求只传背景意图，产品素材用于后续本地合成；未冻结或产品字节漂移时拒绝供应商提交。

本次重验 `pnpm run test:social-image-pipeline`：图片领域 55/55、隔离 HTTP 1/1、路由/工作台合同与治理工作流测试通过；`pnpm run test:social-image-gif-browser` 在静态任务与拦截 API 的隔离页面验证了 GIF 可选择、付费确认取消零写入、刷新后成片和合成帧可见。它们不证明真实供应商付费结果、目标 PocketBase 的唯一索引或跨实例素材共享，也不证明登录真实账号的交付、生产迁移和部署。结果不明的供应商原始回执人工核对仍是发布前缺口；不得将源码可选等同生产就绪。
