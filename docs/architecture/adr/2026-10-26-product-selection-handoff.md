# 产品选择在现有草稿与任务中的交接

状态：已采纳；日期：2026-10-26（Asia/Shanghai）。来源：用户要求修复八类审计问题，并限定基于真实代码的最小修改。

## 原状与问题

产品档案和我的素材已有稳定身份；项目已经保存 `selected`、分镜和版本；社交任务已有 brief、素材 sources、版本及幂等操作。缺口是部分消费者仍用名称型 ID，自动选择的归属只在 Hook 内存中，单条/批量/续接和项目恢复未完整交接。

## 决定

- 扩展现有简报的可选 `productIds`、`productMaterialSelection`，不新建选择服务、数据库表、路由或持久化流程。状态类型从已有客户端模块移至现有共享任务契约，客户端重新导出，保持单一定义。
- 项目沿原 snapshot/restoration 保存和恢复选中、自动归属及取消记录；任务沿原 create/update brief 和 add/remove source 完成同样交接。认证范围、原版本校验和幂等机制保留。
- 素材关联全部成功后才提交新选择和素材就绪状态。失败保留旧归属供原请求重试；批量逐项完成关联后才确认该项回执，已有完成项不重复创建。
- 仅删除旧选择状态明确管理过的产品素材 source，不推测独立手选、参考或历史未知来源的归属。旧草稿缺少选择状态时保守保留，不能伪造自动/手动历史。
- 复用现有产品 ID 解析和 guided 多产品事实、候选、身份分组函数，修正既有调用点；不复制新的素材准入、文案生成或生产管线。明确 ID 失效需重新确认，纯名称旧记录仍仅允许唯一匹配。

## 约束与验证

共享字段缺省时保持旧简报形状；写入多产品 ID 必须通过当前租户档案校验。元数据只决定选择归属，不提供素材授权或执行许可。冻结项目保持原只读规则。

验证以实际补图回调、项目恢复、选择 JSON 往返、任务创建回读、部分失败重试及领域回归为证据；本地 Mock 浏览器仅验证交互，不代表真实供应商生产验收。详细命令及结果记录在 `docs/qa/product-material-selection-2026-10-26.md`。
