# Meta 三种获客目标复用现有投流执行链

日期：2026-10-25；源码起点 dfc9b0c8，分支 feature/platform-ads-20261025。

## 决策

新增三个明确目标，不重用“获取线索或转化”这个 Google 目标：

- 获取消息会话：OUTCOME_ENGAGEMENT / CONVERSATIONS；单一 WhatsApp、Messenger 或 Instagram 私信目的地。
- 获取Meta表单线索：OUTCOME_LEADS / LEAD_GENERATION / ON_AD；关联主页已发布的即时表单。
- 获取独立站询盘：OUTCOME_LEADS / OFFSITE_CONVERSIONS / WEBSITE；关联账户 Pixel，事件固定 LEAD。

共享目标映射驱动能力声明、执行参数和结果口径。继续使用现有人工/审批/托管流程、租户隔离、任务版本、租约、预算限额、发布策略、四层暂停创建、不可变执行快照及未知结果恢复。不新增独立执行器或数据库集合；既有 JSON payload 保存新增资产字段。

在线执行在第一次创建前核对表单属于主页且为 ACTIVE、Pixel 属于账户、WhatsApp/Instagram 与主页的关联；无对应授权或资产时明确失败，不切换目标或目的地。读回还要核对目标、优化方式、目的地、promoted_object 及 CTA，字段变化继续 UNKNOWN，禁止重建。

## 边界

不自动创建表单、接受 Meta 条款、配置网站追踪、修改主页关联、申请额外 OAuth 权限或启用广告。用户先完成对应资产设置。网站 Lead 是否真实回传及 Meta 账户是否允许该配置需真实验收，模拟通过不代表供应商 Ready。当前预览仍只允许 Meta GET，不开放真实创建。

## 获客承接确认（历史方案，已按用户要求撤回）

三类获客目标共用 `AdLeadHandoff` 契约：负责人、实际接收入口、回访渠道与企业回访账号，以及联系字段匹配、已测试接收、再次确认三个显式布尔值。本地草稿允许信息不齐；真实创建、审批载荷和托管创建准备均必须经同一个边界校验，缺项返回 `LEAD_HANDOFF_REQUIRED`。信息只进入本地审批/启动/执行快照，不发送给 Meta，也不替代 Meta 表单问题、隐私说明或完成页。

确认代表用户人工声明的业务承接准备，不是系统验证过的客资送达。Meta 表单明细尚未自动同步到灵枢客户会话，界面必须显示这一限制。主页、表单、消息目的地、网站地址、任务版本或承接信息改变时清除旧勾选，保留仍有用的填写值。使用原始创建快照核对启动/恢复所需的承接记录，旧获客创建回执缺少确认时阻断，不能自动补成已确认；暂停与预算操作不额外引入该确认。

## 当前决定：后续联系由客户自行安排（2026-10-25）

用户明确该部分无需在产品侧发送、收集或作为必要门禁。撤回上述承接方案：删除负责人、接收入口、回访渠道、回访账号及人工测试/二次确认的产品收集与共享契约；不在执行载荷、审批或托管配置中新写入这些字段，不再要求创建、启用或恢复具备承接确认。旧客户端提交的该额外字段由现有边界解析丢弃，不作为规则输入。

获客后的联系由客户自行安排。界面只保留广告目标所需的 Meta 主页、有效已发布表单、消息资产、Pixel/Lead、素材、预算、权限与平台预检。表单完成页可按需填写提示和按钮，产品不规定谁来联系、通过什么方式联系。三类目标及截图右栏保留；历史执行记录不清理，也不伪造承接验收。

### 2026-10-25：获客资产自动关联

用户确认：平台资源编号由产品解析和关联，不要求经营者查找或手填表单 ID、Instagram 账户 ID、Pixel ID。新增已认证、租户隔离的只读获客资产目录，按所选账户及可推广主页取交集，再以主页令牌读取有效表单或消息资产。网站数据源只读所选账户资产，不索取表单读取权限。目录失败不当作空列表，不返回令牌或原始供应商对象。

唯一可用表单/数据源自动关联；多个候选按名称和语言确认业务对象，不猜测最新表单就是适用表单。主页优先已保存默认项，完整目录仅一项时自动匹配。切换账户、主页、目标或读取失败清空旧获客引用；执行仍复核归属与 ACTIVE 状态。已有相同账户、同素材指纹、当前计划版本的 ready 绑定，重新打开时自动验证源并复用视频与封面。

缺少已发布表单不伪造成功；本轮不新增平台表单创建器，不自动接受条款，不生成未经确认的企业隐私政策。首次表单内容、隐私说明和无授权资产仍是未完成条件，不能把目录自动关联写成端到端获客已打通。

### 2026-10-25：五个 Meta 目标统一业务确认

- 目标流程合同集中在 `shared/metaAdJourney.ts`；前端右侧示例和执行区共用“用户确认 / 系统处理 / 客户体验 / 验收标准”。不新增跟进联系人、联系渠道或试联系门禁；点击创建确认当前页面业务值，不增加重复确认框。
- `configuration` 增加可兼容旧记录的 `countries`、`adMessage`、`landingPageUrl`，沿用既有 JSON 配置存储，无新迁移。国家显式选择，日预算仅复用已保存值，移除美国和 10 的隐式默认。网站字段仅出现在两个网站目标，换目标清除不适用网址。
- 所有 Meta 目标共用可推广主页与用户授权交集，不把“个人可读主页”当成账户可用于广告的主页。没有合法主页时保留业务输入，显示资产问题并禁用创建。
- 草稿允许业务信息未完整时保存；创建前由现有预检与前端完整性检查阻止不明确国家、预算、素材或目的地。旧计划缺结构化国家时不解析自然语言猜测，需一次明确确认。
- 当前实际定向仅为国家、18 岁以上及所选平台自动版位。人群/版位自由文本降为明确不执行的策略备注，防止保存备注被误解为平台已经按该人群投放。
- 联调发现本地 PocketBase 写入报 `unable to open database file (14)`，一致性快照后按原参数重启本地库恢复，未迁移/清库/改凭据。企业 context 读取失败处理补为稳定 503，避免异步异常导致 Web 进程退出；不填充假企业资料。
