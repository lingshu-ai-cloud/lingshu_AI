# 腾讯云海外后端与对象存储治理 v1

## 决策

- 当前两台服务器是腾讯云轻量应用服务器，地域为新加坡。
- 可以使用腾讯云 PostgreSQL、COS、Redis/BullMQ，但轻量应用服务器默认不能直接以内网访问普通云数据库。正式环境应二选一：
  1. 将 API/Worker 迁到新加坡 VPC 内的 CVM，通过内网访问 PostgreSQL 和 Redis；
  2. 保留轻量应用服务器，并用腾讯云云联网打通轻量网络与数据库 VPC。
- 不把 PostgreSQL 或 Redis 直接开放到公网作为正式连接方式。
- COS 与轻量应用服务器同地域时可走腾讯云内网；应用配置使用 `ap-singapore`，存储桶也应位于新加坡。

## 当前机器分工建议

| 资源 | 建议职责 | 不建议承担 |
| --- | --- | --- |
| 外部展示 2核2G / 50GB | Caddy、前端、轻量 API | PostgreSQL、Redis、SAM/Paddle、视频转码 |
| 对内开发调试 2核4G / 70GB | 开发测试、低并发 Worker | 正式数据库、并行 FFmpeg、SAM 2 推理 |
| 托管 PostgreSQL | 用户、租户、任务、审批、成本账本、素材元数据 | 视频二进制 |
| 托管 Redis + BullMQ | 长任务排队、重试、延时任务、短租约 | 最终业务事实 |
| COS | 原素材、清洗结果、代理文件、成片和封面 | 查询型业务元数据 |
| 独立媒体 Worker | OCR、SAM 2、FFmpeg、渲染 | 对外 Web 流量 |

SAM 2、PaddleOCR 和并行 FFmpeg 不应运行在 2GB/4GB 的 Web 节点。媒体 Worker 应独立扩容，并通过 BullMQ 领取任务。

## COS 不是本地磁盘

COS 是腾讯云远程对象存储。`LOCAL_OBJECT_STORAGE_ROOT` 才是本地开发用的对象存储目录。当前代码使用或将使用的主要前缀包括：

- `materials/tenants/`：租户素材原文件；
- `material-posters/tenants/`：素材封面；
- `tts/tenants/`、`voice-samples/tenants/`：语音和人声样本；
- `runway-reference/tenants/`：人物替换参考片段；
- `first-frames/tenants/`：生成首帧；
- `bgm/tenants/`、`bgm/shared/`：私有和共享配乐；
- 采集原片、分析片段、成片及历史迁移对象。

资源包页面只能说明已计费容量，不能说明每一类对象占用。使用以下命令生成只读清单：

```bash
pnpm run storage:inventory
pnpm run storage:inventory -- --prefix=materials/tenants/
```

该命令没有删除能力，只输出对象数、字节数、一级前缀汇总和最大的 20 个对象。

## 已实施的安全规则

1. 新上传的云端素材采用内容哈希键，同一租户的相同字节只上传一次。
2. 新文件进入对象存储；PocketBase 只保存元数据、对象键和 ETag。旧的 PocketBase 文件仍兼容读取，不自动迁移或删除。
3. 超过阈值的文件自动使用 COS 分块上传；捕获到失败时主动终止分块。
4. 上传完成必须通过 `HEAD` 核对文件大小后才能登记素材。
5. 后台每 6 小时检查一次操作系统临时目录，只删除超过 24 小时且名称带固定灵枢前缀的工作目录。
6. 本版本不删除、不迁移、不改写 COS 现有对象，也不下发 COS 生命周期规则。

PostgreSQL、Redis/BullMQ 与 PocketBase 数据迁移的执行顺序、双重写入门禁和回滚规则见
《腾讯云PostgreSQL-COS-Redis迁移运行手册》。

## 后续启用 COS 回收前的门禁

必须先完成以下步骤，才允许启用云端自动删除：

1. 导出完整对象清单，并按前缀、租户、大小、最后修改时间汇总；
2. 从 PostgreSQL/PocketBase、发布记录、项目、任务和成片引用中生成“仍被引用”的对象集合；
3. 未引用对象先进入至少 30 天的待删除清单，不直接删除；
4. 由管理员审核清单，并保存执行批次、对象键、大小和 SHA-256；
5. 先处理未完成分块和明确的临时前缀，再处理业务对象；
6. 每批删除后抽查素材播放、爆款原片、历史作品和下载链路。

在这些门禁完成前，不应对整个桶使用“清空”或宽泛的生命周期删除规则。
