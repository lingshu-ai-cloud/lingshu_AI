# 数字人三语成片批量验收

该工具只分析已导出的 zh/en/es 三个最终 MP4，不会启动或重启 GPU Worker，也不会执行数字人推理。生产上线结论必须使用服务端可信模式；本地 manifest 模式仅供内部诊断，总结会明确标记 `untrusted_offline` / `internal_only`，不会输出上线通过。

## 生产可信模式

```powershell
$env:DIGITAL_HUMAN_ACCEPTANCE_TOKEN = '<current-user-bearer-token>'
npx tsx scripts/validate-digital-human-trilingual.ts --server-batch-id '<server-batch-id>' --base-url 'https://lingshu.example' --output '.\acceptance.json'
```

该模式只读取服务端从持久化任务、冻结时间线、最终质检和成片实际 SHA256 重建的签名验收清单。只有同一项目的 zh/en/es 恰好三条已完成可下载成片才能返回清单。

## 准备验收清单

复制 [digital-human-trilingual-acceptance.example.json](./examples/digital-human-trilingual-acceptance.example.json)，为 zh、en、es 分别填写：

- `video`：该语言真正的最终 15 秒 MP4；
- `performanceManifest`：该语言的表现力时间锚点清单，必须与实际配音节奏一致；
- `digitalHumanSegments`：可选的服务端冻结数字人出镜区间，每段为 `{ "start": 秒, "end": 秒 }`；
- `chromaKey`：`yes` / `no` / `auto`；
- `humanReview`：可选，仅用于内部诊断。记录必须含 `reviewer`、`reviewerId`、`reviewedAt`、`sourceJobId`、与成片一致的 `outputSha256`，并分别给出 `doubleMouth` / `complexHands` / `voiceMatch` 结论。

路径相对于该验收清单所在目录解析。清单必须且只能包含 zh/en/es 各1条；缺失、重复或语言错配会直接失败。

### 数字人区间合同

`digitalHumanSegments` 使用最终 MP4 时间轴的秒数，区间语义为 `[start, end)`。提供时必须满足：

- 至少 3 段；
- `start` 和 `end` 必须为 JSON number 且有限，`start >= 0`、`end > start`；
- 必须按时间升序且不重叠，区间可相接；
- 每段 `end` 不得超过 ffprobe 实测成片时长；
- zh/en/es 必须分别使用对应配音和剪辑时间轴生成，不得直接复制另一语种的边界。

区间间隙即合法的 B-roll/空镜。验收脚本只读取命令行指定的本地清单，不读取浏览器状态，也不接受前端声称的“已通过”质量结果。生产清单应由服务端从已冻结的渲染时间轴导出；当前离线 CLI 只能校验本地清单的结构和时间边界，不会伪造服务端来源证明。

为兼容已有纯数字人整片清单，缺少 `digitalHumanSegments` 时会继续将整条视频送入 MediaPipe 和 SyncNet。混剪成片不得利用该兼容路径，否则 B-roll 会被当作数字人画面严格验收。

## 执行

Windows 本机使用当前 MuseTalk WSL 环境：

```powershell
npm run validate:digital-human-trilingual -- "D:\path\trilingual.json" "D:\path\trilingual-acceptance-report.json"
```

也可直接使用带参数名的形式：

```powershell
npx tsx scripts/validate-digital-human-trilingual.ts --manifest "D:\path\trilingual.json" --output "D:\path\trilingual-acceptance-report.json"
```

默认使用：

- WSL 发行版 `Ubuntu-22.04`；
- Python `/root/digital-human-lab/repos/MuseTalk/.venv/bin/python`；
- SyncNet `/syncnet_python`。

可通过 `DIGITAL_HUMAN_VALIDATOR_WSL_DISTRO`、`DIGITAL_HUMAN_VALIDATOR_WSL_USER`、`DIGITAL_HUMAN_VALIDATOR_PYTHON`、`DIGITAL_HUMAN_SYNCNET_DIR` 覆盖。

## 自动验收内容

每种语言顺序执行：

1. ffprobe 检查 1080x1920、MP4、H.264、AAC 和 14.5–15.5 秒时长；
2. ffmpeg 完整解码视频轨与音轨；
3. 若声明 `digitalHumanSegments`，用 ffmpeg 对每个数字人画面与音轨做同边界精确裁切；
4. `validate-digital-human.py` 对每个数字人区间分别实测人脸覆盖、嘴部开合、跳变、清晰度和活动对齐；
5. 官方 SyncNet 对每个数字人区间分别使用置信度 `>= 3.0`、音画偏移 `<= 3` 帧的严格门槛；
6. 现有 `validate-digital-human-performance.py` 仍对完整成片实测语义段落、手势、表情、动作重复、静止时长、场景/构图和动作对齐；
7. ffmpeg `freezedetect` 仍对完整成片独立统计真实冻结片段；
8. 计算每个最终 MP4 的 SHA256，产生三语汇总。

每段的 MediaPipe 与 SyncNet 都必须独立通过，任一片段失败就会使该语种成片失败，不使用平均分掩盖失败片段。聚合报告保留最差指标和逐段结果。

汇总文件旁会生成 `<报告名>.items/zh|en|es/`，内含 ffprobe、解码、口型、SyncNet、表现力、freezedetect 和单语摘要报告。混剪清单还会生成 `digital-human-segments/segment-01|02|.../`逐段原始报告。

## 结果语义

- `passed`：三条自动门禁全部通过，且三条的真实人工复核也通过。
- `requires_human_review`：自动门禁通过，但双嘴、复杂手部或声音与人物匹配尚未被真实审核人确认。
- `failed`：任一自动门禁失败或必填指标缺失/NaN。

脚本内部退出码分别为 0、3、2；部分 npm/npx/Windows 组合会把非零子进程状态统一显示为 1，CI 应以报告内的 `validationStatus` 和 `passed` 为准。工具不会生成 `approved` 决定，也不会因自动指标正常就宣称排除双嘴、复杂手指或声线与人物不匹配。
