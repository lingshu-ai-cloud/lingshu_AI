# 数字人分镜面板：产品定义补充

日期：2026-09-24（按 2026-09-25 当前代码与联调状态更新）

本文是数字人分镜面板的产品定义和实施状态。数字人不是与「视频／图文」并列的入口，而是内容制作、爆款裂变和素材加工中，由分镜按需调用的能力。

## 一、核心决策

将现有 HeyGen 面板升级为「数字人分镜面板」，承接可以被内容 Agent 灵活调用的人物视频技术栈。

保留现有企业人物口播能力，在已有面板基础上扩展；用户不需要先进入单独的数字人创作区，也不需要理解或选择供应商、模型和资产 ID。

数字人只出现在需要人物出镜的分镜中。工厂、产品、B-roll 等非人物镜头优先使用原素材剪辑、授权素材引用或 AI 补镜，不进入人物视频链路。

## 二、两类制作能力

| 能力 | 驱动方式 | 面板重点 | 当前执行技术栈 |
| --- | --- | --- | --- |
| 企业人物口播 | 人物资产 + 口播内容驱动 | 人物、声音、口播文案、语言 | 方舟实时数字人／HeyGen 类人物视频能力 |
| 参考视频人物复刻 | 爆款视频逐句复刻 + 人物资产驱动 | 原片语句与对应分镜、目标人物、动作／场景、需保留元素 | 源句首帧提取 → 千问换人首帧 → Seedance 逐句视频 → FFmpeg 合成 |

两类能力都服务于数字人视频制作，在同一个分镜面板中使用，由内容 Agent 根据镜头需求选择和组织调用。

### 企业人物口播

用户选定企业人物资产并确认口播内容，系统生成目标人物讲述该段文案的视频。首次使用真实人物时，方舟要求该人物在手机端完成一次真人认证；灵枢负责发起、跟踪、同步并绑定认证后的资产，不能以后台接口绕过本人认证。

### 参考视频人物复刻

以爆款视频的逐句复刻结果和目标人物资产为输入。系统从每句对应的原片时间段提取源首帧，以千问生成保留背景、构图、产品和动作语境的目标人物首帧，再由 Seedance 生成该句的目标人物口播片段，最后按句合成。

这不是“获得原片人物授权才可生成”的链路：需要的是参考视频在当前业务中的可用权利，以及目标人物本人的授权和可信人物资产。复刻默认替换人物并尽量保留原镜头画面；若保真条件不满足，系统必须说明会降级为重新演绎，不能静默切换。

Runway、SD、Kling 属于后续可接入的候选能力，不是当前默认生产链路，也不应在前台作为用户必选项。

## 三、用户与内容 Agent 的分工

用户在面板内确认：

- 使用哪个人物。
- 镜头要表达的内容与口播。
- 参考视频及对应语句、镜头。
- 动作、场景和必须保留的画面要求。
- 生成候选是否可采用。

内容 Agent 负责：

- 先判断镜头是否需要人物出镜；不需要则路由到原素材、引用素材或 AI 补镜。
- 对人物镜头判断是企业人物口播、参考复刻，还是需要补充资料后再制作。
- 检查人物授权、可信资产、参考句段和首帧等输入是否完整，提示补充缺失项。
- 组织生成步骤并反馈任务状态。
- 将生成候选返回当前分镜，供用户预览、重做和确认填入。

供应商和模型信息只在技术详情或运维排查中可见，不是普通用户的必选步骤。

## 四、统一交互

共同动线：进入内容制作／爆款裂变／素材加工 → 生成或编辑分镜 → 判断该镜头是否有人物出镜 → 选择或补齐人物和镜头资料 → 生成预览 → 检查候选 → 确认填入分镜。

面板按镜头需要展示设置：企业人物口播突出文案、声音和语言；参考复刻突出原片逐句对照、目标人物、动作与画面保留要求。非人物镜头不展示数字人设置。

人物卡片统一使用以下业务状态：`人物资料待补齐`、`等待本人认证`、`人物可用于制作`、`该镜头正在生成`。统一展示生成进度、候选视频、失败原因、重做与采用操作。

同一条视频允许混用能力：讲解镜头可用企业人物口播，爆款中的人物镜头可用逐句复刻，产品与环境镜头沿用素材或补镜链路。

## 五、已完成的基础建设与明确边界

以下事项已经完成代码建设，或已经作为不可变更的产品边界确定：

- 已建立分镜路由合同和前端路由建议：先区分人物／非人物镜头，再为人物镜头给出企业口播、参考复刻或补资料的建议。
- 已建立统一制作任务、人物资产、镜头默认值和任务状态的共享结构，整段口播与单镜头面板可使用同一人物及任务记录。
- 已接入千问图片生成，用于目标人物首帧；一条首帧任务最多使用三张参考图。
- 已实现参考复刻的服务端生产骨架：逐句素材、源首帧、目标首帧、Seedance 片段任务和 FFmpeg 合成均有对应任务与错误处理。
- 已建立对象存储抽象、素材可信度校验、人物授权／认证字段，以及 Seedance 所需可信人物资产的校验逻辑。
- 已接入方舟 Assets 的只读校验客户端，可按项目、资产组和图片资产验证资产状态；它不会也不能绕过本人手机端认证或代替本人上传。
- 已确认当前默认技术栈为「千问换人首帧 + Seedance 逐句视频 + FFmpeg 合成」。Runway、SD、Kling 仅保留为后续能力候选，前台不能把它们表现为已经可用的生成入口。
- 已确认不新增数字人顶层入口；完整人物资产库、费用管理等周边产品不因本面板自动进入当前范围。

## 六、已确定方案、仍需实施的运行闭环

原先“实施前需明确”的问题已完成产品决策，剩余是按这些决策完成运行闭环，而不是重新讨论方向。

| 已确定事项 | 执行规则 | 仍需实施／验证 |
| --- | --- | --- |
| 人物、口播与任务状态如何共享 | 人物资产、口播片段、分镜和制作任务以统一制作记录为唯一来源；整段口播与单镜头只引用该记录，不各自复制状态。 | 补齐各页面对同一任务的实时刷新、断点恢复和采用结果回写验证。 |
| 原片语句、时间段、分镜和动作缺失怎么办 | 参考复刻必须有句段及对应时间范围；系统从该范围提取首帧。缺少句段、目标人物或关键保留要求时，阻断“保留画面换人”的生成并要求补齐，不能凭空补造来源镜头。 | 将缺失项做成面板内逐项补齐与可见的阻断提示；联调不同清晰度、多人和转场镜头的提取质量。 |
| 人物资产格式、保真边界和生成条件 | 企业口播使用完成本人认证并处于可用状态的可信人物资产。参考复刻使用目标人物资产、源首帧和千问目标首帧；Seedance 使用可外网访问的签名对象存储 URL。保留背景、产品和构图是目标，不承诺所有镜头逐像素一致。 | 将方舟手机端认证发起、二维码／跳转承接、资产组图片自动发现和自动绑定做完；完善人物素材质量检查与复刻保真评分。 |
| Agent 如何路由和处理失败 | 规则先行：镜头分类、素材完整性和合规校验是硬门槛；Agent 在门槛之上根据人物出镜、参考来源、口播意图和画面要求提出路线。路线变化、降级和失败必须展示原因并允许用户重做或改选。 | 实现 Agent 的语义判镜、证据输出、置信度／质量阈值和人工覆盖；把失败重试、降级与人工接管完整接入前端。 |
| 外部服务如何具备可运行条件 | 千问负责首帧，Seedance 负责逐句视频，COS／兼容对象存储负责给 Seedance 提供 HTTPS 签名素材 URL，方舟只在本人认证完成后提供真实人物资产。 | 在开发环境配置 DashScope、Seedance、对象存储和方舟 AK／SK；开启逐句任务开关，使用已认证的可信图片资产跑通浏览器真实点击的端到端链路。 |

当前不能把“有前端入口”或“服务端任务已创建”视为完成。只有用户从分镜卡片发起，系统拿到已认证人物资产、生成并回填逐句候选视频，且用户能预览并采用到分镜，才算参考复刻闭环完成。
