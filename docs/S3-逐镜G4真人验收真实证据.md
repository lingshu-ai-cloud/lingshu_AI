# S3 逐镜 G4 真人验收

当真实检测尚未覆盖字幕、敏感数据、格式或音画同步时，原镜头仍为 `review_required`。本入口保存指定真人的逐项观察记录，不将其标记为自动技术检测。

实际入口：`/api/overseas/starter-198/social-content/tasks/:taskId/runs/:runId/artifacts/:artifactId/g4-reviews`。读取实际成片预览、文件 SHA、镜头 SHA、原 handoff 与最新 G4。审核者为真实任务创建者；创建者不是启用的实际企业成员时，需管理员明确指定审核者，持久保存该指派。既有指派不可悄悄替换。

七项：格式、时长、音画同步、字幕、素材关联、渲染、敏感数据。每项需明确通过／失败／未核验并写观察说明；任何未核验项保持待审核，真实失败项保持失败。提交冻结租户、任务、run、成片、实际镜头、来源与文件字节、指定人和最新回执上下文。每次人工审核追加新 G4 attempt，不修改旧自动检测记录或成片 productionResult。

请求具有稳定 requestId。网络未知仅 GET 原请求查回；已保存真人记录而回执投影失败时，仅原审核者可显式恢复原投影，不重新审核、重新渲染或付费。来源或最新上下文变化阻止恢复。

真人 G4 已接实际缓存、返工准入、库存资格以及生产回执保存／读取和产物核销：必须重新核验完整人工记录、实际指定人权限、成片 SHA、镜头 SHA 与源身份。仅 `human_reviewer` 标签不构成通过。未选择镜头全部真实通过后，原返工入口才可接受失败镜头的明确返工请求。G4 不替代编导 G5、经营 G6、最终成片审批、授权、预算或发布许可。

迁移 `1791072044` 仅声明私有审核存储，未执行生产迁移。缺旧逐镜缓存的历史成片不能从最终 MP4 猜造逐镜供给或审核来源；需真实缓存来源后才能进入本入口。

## quality_check 后续边界

首产 `technicalReview.approved` 来自实际视觉、逐镜抽帧及音轨解码检测；false 表示这些检测失败，不能把它解释为字幕等未核验项。返工成片的该摘要固定 false，并同时记录真实失败和待核验项目，应读取冻结 `technicalQualityReport` 分别判断。真人 G4 不得将该冻结报告中的视觉失败、音轨失败或对应镜头检测失败核销为 passed；这些需要真正修复形成新产物。

现有 G5 具备回执构造与持久保存能力，但未发现非测试的编导 G5 写入口或执行者。生产状态接口为只读，计算所得 `creativeReview` 摘要不等于新增独立 G5 回执。因此当前不能从 G4 人工通过自动推导返工整片 `quality_check` 成功；后续须接真实编导 G5 证据及最终审批。
