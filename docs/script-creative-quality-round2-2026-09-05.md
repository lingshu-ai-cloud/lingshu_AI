# 脚本创作质量第二轮调整

范围：产品模式的口播与分镜生成。保持 Qwen、已有 Studio API、前端字段与存储合同。仅本地修改，未部署。

## 数据逻辑变化

此前 `factBasis` 只写在模型响应里，没有参与后续生成。本轮让它成为口播改写与分镜的共同输入：

1. 生成创意初稿，输出选中事实、受众问题、表达切口和台词。
2. 将选中事实与产品原文匹配，保留完整来源行，避免遗漏“可配置”等条件。匹配失败或旧响应未提供该字段时，兼容回退到本次产品资料，不使用模型自造事实。
3. 增加一次短口播改写：围绕选中事实兑现开头、解释一个具体选择、控制总字数。该步骤失败则返回错误，不把未改写初稿直接送往分镜。
4. 分镜只使用改写后台词与同一组事实，后期文字承接台词。没有实拍依据时只给取景与信息呈现建议，不把功能描述扩写成设备运行结果。

六条核心创作要求保留，增加两个工业/消费品的短示例，示范“事实→观看理由→具体选择”。没有新增评分器或审批流程。每条产品口播稿从两次模型调用增加到三次；耗时、token 成本和任一调用失败的概率都会相应增加。

产品生成阶段不再附带整份企业背景，以免混入其他产品事实；本次选中的产品资料、受众、风格、语言、主题和 CTA 仍由请求提供。素材与对标路径未增加改写调用。

## 试跑发现与调整

- run-6：短说明示例仍出现“这两项不支持就进不了追溯系统”等无依据必要条件。
- run-7：完整示例改善句式，仍出现“每条曲线自动比对标准形态”。
- run-8：增加口播改写，功能扩写减少；但第二版重新堆叠卖点，时间轴到 23.3 秒。
- run-9：使用选中事实及总字数预算，前两版口播收敛；分镜仍夹带其他卖点和二维码。
- run-10：分镜复用选中事实，并限定后期文案与行动提示。原始结果和逐版评价见同目录 reports 中 round-2-comparison.md。

所有模型原稿均保留，未以人工编修内容替换测试结果。

## 验证范围

回归覆盖三阶段顺序、分镜使用改写稿、改写失败不能退回初稿、事实选择保留来源条件、旧格式兼容、已有稿排重、英文产品稿及对标模式的原有行为。测试只能证明这些代码行为，不能证明自然语言事实绝对正确或实际传播表现。

尚未进行真实 TTS、视频生成或投放测试。没有真实素材时，分镜中的拍摄对象与可见结构仍需根据实物核对。时间轴由现有算法估算，目标时长不是实际配音测量值。
