# 四平台首版预发布验收与运行手册

## 1. 范围与结论口径

首版同时覆盖 TikTok、Facebook、Instagram、YouTube。数字人成片与图片、普通视频、文本内容使用同一套素材读取权限、版本冻结、内容审批和发布授权；`kind=digital_human` 只描述素材类型，不产生额外权限分支，也不能绕过既有审批链。

本手册只用于本地和预发布验收。执行命令不得发布真实内容、推送代码或部署生产环境。证据文件返回 `preReleaseEvidenceReady=true` 只代表现场证据内部一致；判定器固定返回 `releaseReady=false`，不能单独授权上线。授权负责人还须复核原始请求、PocketBase 记录和 Chrome 现场记录，才能记录“预发布验收通过”。本地模拟、手工填写 JSON、缺登录态、缺平台 ID 或未知回执都不能写成通过。

## 2. 下阶段发布规划

| 阶段 | 目标 | 依赖 | 退出标准 |
| --- | --- | --- | --- |
| A. 本地合同门禁 | 固化四平台、统一审批血缘、未知状态恢复、租户隔离和吊销失败关闭 | Node/pnpm；仓库依赖；PocketBase 0.39.5 | release harness 通过；本判定器测试通过；无真实平台外呼 |
| B. 隔离 PocketBase 演练 | 在一次性真实 PocketBase 上核验迁移、持久化、并发/失败恢复和租户边界 | `PB_BIN` 指向 0.39.5；临时数据目录 | `scripts/social-operating-release.integration.ts` 通过；临时实例销毁；无生产数据 |
| C. 四平台账号/API 预检 | 用户在 Chrome 分别登录四个平台，并核验应用 OAuth/API 绑定、发布目标和 scope | 4 个获授权测试账号；YouTube 频道；Facebook Page；应用预发布会话；测试租户 | 四个平台会话、OAuth/API 授权和目标 ID 均有证据；未点击最终发布 |
| D. 预发布只读/受控演练 | 用冻结素材与已批准版本验证表单、回执查询、未知状态恢复、跨租户拒绝和吊销 | C 完成；批准记录；可恢复的隔离发布尝试证据 | 四平台各一条真实 provider receipt/post ID；或未知状态安全阻断并等待，不盲重发；隔离和吊销检查通过 |
| E. 上线决策 | 汇总证据、风险和回滚负责人 | A–D 全部完成 | 判定器 `overall=passed` 且 `preReleaseEvidenceReady=true`；负责人复核原始证据并签字；另行取得生产部署/发帖授权 |

任何平台不能满足退出标准时，四平台首版整体保持阻断。不能将三个平台通过写成“四平台上线完成”。

## 3. 本地门禁

先运行现有真实 PocketBase release E2E，再运行本任务的纯判定测试：

```bash
pnpm exec tsx scripts/social-operating-release.integration.ts
pnpm exec tsx --test scripts/four-platform-release-acceptance.test.ts
```

第一条命令启动一次性 PocketBase 和本地 mock provider，覆盖生产存储边界，但不会连接真实社媒平台。第二条命令验证结论口径。若 PocketBase 二进制或固定版本缺失，应记录为“环境阻断”，不可跳过后宣称通过。

## 4. 预发布证据采集

### 4.2 统一来源与审批链

每个平台回执必须与下列字段完全相同：

- `tenantId`
- `artifactId`
- `artifactVersion`
- `contentHash`
- `approvalId`

数字人成片填写 `sourceArtifact.kind=digital_human`，仍执行相同五字段比较。审批为 `revoked`/`expired`、内容被编辑或哈希变化时，旧审批立即失效。

### 4.3 发布回执与未知状态恢复

“已发布”必须同时存在平台返回的 `providerReceiptId` 和 `providerPostId`。HTTP 2xx、页面跳转、任务已入队或本地日历状态都不是最终回执。

遇到超时、断网或平台返回处理中时：

1. 保留原 attempt/account/内容哈希和审批 ID；
2. 设置 `state=unknown` 或 `processing`；
3. 通过平台查询接口或历史页恢复，不创建第二次发布尝试；
4. 记录 `queriedAt` 和 `resendSuppressed=true`；
5. 未取得最终 ID 前保持阻断。确认失败后是否重试，必须新建明确的发布尝试并重新检查审批是否仍有效。

当前恢复边界必须按以下规则记录：

- YouTube 或 Meta 上传请求未返回平台对象 ID 时，结果记为 `unknown`；没有可查询 ID 时系统不能自动证明成功或失败，也不得自动重发。
- Instagram 已创建媒体容器但容器 ID 未持久化时，同样记为 `unknown`；不能重新创建容器来冒充恢复，否则可能造成重复发布。
- `unknown` 只能通过原平台账号的发布历史、内容库、Studio/Page/Business Suite 等现场人工核验，或通过可关联的幂等键、目标账号、内容哈希和时间窗口取得唯一平台记录后，转为明确的 `published`/`failed`。
- 四个平台进入上线决策前，每个平台必须处于已知最终状态；若自动恢复条件不足，必须完成人工核验并记录操作人、时间、目标账号、平台对象 ID 或“未发现发布”的查询证据。任一平台仍为 `unknown`，整批四平台保持阻断。

### 4.4 租户隔离与权限吊销

使用第二个隔离测试租户读取和修改当前租户证据，预期均被拒绝，`leakedRecordIds=[]`。随后吊销审批或发布权限，再调用本地/预发布受控入口；预期在 provider 调用前拒绝，`providerNetworkCalls=0`。不要用真实平台发帖测试吊销。

## 5. 运行判定器

```bash
pnpm exec tsx scripts/four-platform-release-acceptance.ts \
  --evidence /absolute/path/four-platform-evidence.json \
  > /absolute/path/four-platform-release-report.json
```

退出码：`0` 表示现场证据一致性检查通过，`2` 表示真实性或安全检查失败，`3` 表示证据仍阻断。退出码 0 不授权上线或真实发帖。报告中的 `truthfulness` 必须原样进入验收记录。没有凭据时，`authenticated_evidence` 必须为 `blocked`；没有实际请求、数据库回执或 Chrome 现场记录时，`live_evidence_source` 必须为 `blocked`。

## 6. 预发布演练顺序

1. 冻结一个已获授权的测试素材版本，记录哈希；数字人成片不另建权限。
2. 由有审批权的测试成员批准，记录审批 ID 和时间。
3. 对四个平台分别核验测试账号登录态及账号 ID。
4. 读取已有的隔离发布尝试/回执，或在另行取得真实发帖授权后进行受控尝试。本手册本身不授权发帖。
5. 注入一次回执查询超时，确认状态为 unknown、重发受抑制，恢复查询后仍沿用同一 attempt。
6. 用第二租户执行读写拒绝检查。
7. 吊销审批并确认 provider 外呼为 0。
8. 填写证据 JSON、运行判定器并存档报告。任何人工“看起来成功”不得覆盖机器判定结果。

## 7. 回滚与停止条件

出现串租户、吊销后仍外呼、内容哈希与审批不一致、重复发布风险或无法确认平台最终状态时，立即停止该平台及整批四平台发布：

1. 禁用预发布发布 Worker/调度开关，保留原始回执和日志；
2. 将待处理记录标为暂停/未知，不把 unknown 改写为 failed 后自动重发；
3. 吊销本轮发布授权和审批，轮换已疑似泄漏的凭据；
4. 对已经取得 `providerPostId` 的测试内容，由账号负责人按平台记录逐条处理；是否删除属于外部破坏性操作，需要单独批准；
5. 恢复到上一个已验证版本，重跑本地 PocketBase 门禁和预发布证据判定；
6. 只有根因、影响范围、平台侧最终状态和防重复证据全部明确后才能重新进入阶段 C。
