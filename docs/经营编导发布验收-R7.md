# 经营编导链 R7 发布验收与整合清单

## 边界

- R7 基线固定为 `9a9e12b`，只负责 CI、迁移演练、运行时 readiness、Worker 心跳、可观测信号与 E2E harness。
- 不替代经营目标、周任务包、发现、生产、发布、复盘等领域实现。
- Mock 只允许位于外部 provider HTTP 边界；内部链路必须使用真实 PocketBase、真实 HTTP 路由、真实 Worker 子进程和数据库唯一租约。
- 本清单和测试不包含部署、推送或生产数据操作。

## 唯一质量门

```bash
PB_BIN=/absolute/path/to/pocketbase pnpm run quality
```

`quality` 内的 `test:gap-v1-release` 是经营编导链唯一发布级门禁。旧的 `FakeApp` 迁移模拟和内存 `Map` 全链测试已移除。CI 固定安装与镜像一致的 PocketBase `0.39.5` 后执行同一条 `pnpm run quality`，不再另行拼装一套宽松的 CI 测试序列。

## 自动演练覆盖

- fresh：空数据目录执行全部 PocketBase migrations，并通过管理 API核对经营编导必需集合。
- upgrade：先运行不含 R7 最新迁移的基线，写入历史业务哨兵数据，再升级并验证数据保留。
- rollback：真实执行最近三份 migration down（运行时集合、规则兼容修复、Gap-V1 证据集合），确认只移除新集合且保留既有业务数据，然后重新升级。
- backup/restore：停库后复制隔离数据目录，制造备份后写入，再恢复备份并验证恢复点前数据保留、恢复点后数据消失。
- HTTP 与双租户：真实 PocketBase 用户登录后，经生产 `requireAuth`、`createSocialProgramsRouter` 与 `pbStore` 走真实 TCP；租户 B 读取租户 A 的项目必须得到 404。
- Worker 与并发：两个独立 Node Worker 同时争抢真实 PocketBase 唯一租约，外部 provider 只能收到一次请求。
- 重启与失败恢复：provider 首次 503 后任务保持 `collecting`；新 Worker 进程接管后完成；PocketBase 重启后 HTTP 业务读取恢复。
- 安全边界：预算为零不调用 provider；周任务包撤回后真实发布授权失效；未知回执不被自动重发。

## 本地验证状态（2026-09-26）

使用官方 PocketBase `0.39.5` 的本地隔离实例，`test:gap-v1-release` 已完整通过，包含上述 fresh、upgrade、rollback、backup/restore 和真实 HTTP/Worker 演练。类型检查、迁移完整性及迁移门禁测试、readiness 契约也已通过。

演练发现两份既有迁移的 `&& false` 规则在 PocketBase `0.39.5` 和 `0.39.9` 均无法应用，且 gap task 的零预算、零消耗与空证据数组被 `required` 误拒绝。为兼容 fresh install，历史迁移只作这些精确修复；迁移完整性门禁仅对固定旧/新 SHA-256 允许这两项修复，其他历史改写仍拒绝。`1790985601_lock_social_operating_rules.js` 为已有安装前向修复规则和字段约束。`null` 规则保持 superuser-only 锁定访问。

完整 `quality` 尚未通过：现有架构门禁在多个基线文件上报告行数超预算和依赖方向违规（例如 `src/App.tsx`、`shared/contracts/socialReview.ts`）。不得为通过发布门而提高预算或跳过该检查；这些问题需要在整合后单独修复并重跑完整门禁。

## readiness 与运维信号

`/api/overseas/ready` 除原有 PocketBase 健康和 Starter 集合外，还核对：

- `social_programs`
- `social_weekly_operating_packages`
- `social_business_content_goals`
- `social_operating_decisions`
- `social_candidate_evidence`
- `social_reference_selections`
- `social_discovery_gap_tasks`
- `social_weekly_review_snapshots`
- `social_operating_worker_heartbeats`

readiness 返回 `socialOperating`，包含：

- `queueBacklog`：仍在采集的生产缺口任务数及最老时间；
- `unknownReceipts`：最近发布记录中结果不明、禁止盲重试的回执数；
- `exhaustedBudgets`：预算耗尽并阻断的任务数；
- `invalidAuthorizations`：已撤销、过期或活动但未获真实发布授权的周包数；
- `worker`：一体化进程使用本地启动状态，拆分 Web 进程使用 PocketBase 最近心跳。

Worker 不 ready 会令 readiness 降级；其他四类为业务告警信号，不把已有待处理事项误判为基础设施不可用。
