# 外部 E2E 准入与恢复手册

更新时间：2026-10-21（Asia/Shanghai）

## 双泳道

1. 产品开发泳道：使用 fixtures/mock 与可重复测试，不调用真实付费服务、不写入黄金运行数据。
2. 黄金联调泳道：只验证已合并且冻结的源码、数据 store、服务实例与 run/package/version；现场发现的问题记录为缺陷，修复回产品开发泳道完成后再重新联调。

## 开始前检查

- [ ] 源码分支、commit、工作区状态已写入 `docs/governance/BASELINE.md`。
- [ ] Web 与 worker 使用同一明确的持久化 store 和版本。
- [ ] 对标素材可读且来源/授权明确；产品图绑定到权威企业资产版本。
- [ ] 人物、声音、Logo 等资产授权和可用范围已确认。
- [ ] 供应商账号、模型、区域、配额及能力已验证。
- [ ] 预算已由责任人显式批准；执行会话唯一且具备审计回执。
- [ ] 已记录 run/package/version、输入指纹和恢复点。

任一前置条件缺失时停止外部 E2E，登记外部阻塞项；不通过新增门禁、扩大重试、切换供应商或重复付费调用绕过。

## 执行与恢复

- 一次会话只验证一个冻结目标和一个唯一 run。
- 超时或结果未知时先查询供应商/任务回执，禁止盲目重提付费请求。
- 只保存最小复现、相关日志标识和具体状态，不把未验证推断写成产品规则。
- 验收后分别记录源码、数据、服务和供应商状态；不得仅以源码提交宣称黄金链路通过。

## 会话交接

交接至少包含：目标、基线 commit、改动文件、验证命令/结果、剩余风险、唯一下一步。开发会话范围控制在一个目标、约 10–20 个文件；达到 2–4 小时或一次上下文压缩后应评估冻结并交接，不自动扩张任务。
