## 已发现并修复的代码断点

原先 HeyGen 返回 completed 后，服务端直接读取响应中的 Worker quality 字段。HeyGen 不提供这份报告，导致任务进入 review，不能自动进入素材库。

现在服务端对下载的视频执行音频提取、MediaPipe 视觉检测、官方 SyncNet 和 FFmpeg 冻结检测，绑定实际文件 SHA256，再进入现有商业门禁。检测程序失败或未配置仍进入 review，不填充虚假通过值。待复核视频保存在私有 Worker 上传目录的 `<jobId>.review.mp4`，没有自动加入可发布素材。

新增 `scripts/verify-heygen-live.ts` 用于显式真实验证：首次 `--create` 允许一条付费任务；任务号写入被 Git 忽略的 `data/heygen-live-20260905/task.json`，后续复用任务查询。密钥只从环境变量或显式 `--clipboard` 读取，不写入文件；签名下载地址不保存。

## 同事需要提供的运行配置

在内部服务器 `/opt/lingshu/internal/.env.runtime` 中配置，真实密钥只在服务器保存，不通过 Git 或日志传递：

```dotenv
DIGITAL_HUMAN_COMPUTE_TARGET=auto
HEYGEN_API_KEY=<通过安全渠道配置>
HEYGEN_API_BASE_URL=https://api.heygen.com
HEYGEN_CONSENT_VIDEO_UPLOAD_ENABLED=false
HEYGEN_VALIDATOR_PYTHON=<应用容器内可执行的Python绝对路径>
DIGITAL_HUMAN_SYNCNET_DIR=<应用容器内官方SyncNet源码和权重路径>
DIGITAL_HUMAN_FFPROBE_PATH=<应用容器内ffprobe绝对路径>
```

注意：主机有 Python 不等于应用容器可用。当前镜像没有完整的 MediaPipe/SyncNet 环境；需准备经过验证的容器运行时或独立质检服务，再进行真实验收。现有本地 Worker 校验脚本通过 Windows WSL 调用，不能原样当成 Linux 云端质检运行时。

Python 环境需能运行仓库的 `scripts/validate-digital-human.py` 与 `scripts/validate-syncnet.py`，具备 OpenCV、MediaPipe（支持 solutions.face_mesh）、NumPy、soundfile，以及官方 SyncNet 所需依赖、人脸检测权重和 `data/syncnet_v2.model`。Python 子进程 PATH 也须能找到 FFmpeg/ffprobe。官方 SyncNet 的执行设备兼容性必须实际验证，不能假设 Mac 或无 GPU 容器可运行。

`auto` 保留质量模式走 HeyGen、极速模式走本地 GPU。`local-pull` 会强制两个模式都走本地 GPU。企业人物授权开关只在服务商实际开通权限后启用；本次公共人物测试不能作为企业母片训练验收。
