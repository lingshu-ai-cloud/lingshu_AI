# 非数字人分镜素材生成与匹配路径

> 工作基线：`local-preview-1002`
>
> 文档状态：讨论稿。后续围绕非数字人分镜素材方案的讨论与决策持续记录在本文档中。

## 1. 适用范围

本文档说明“内容制作 → 成片制作”中非数字人分镜的素材来源、匹配方式，以及素材库无可用素材时的智能生成技术路径。

当前主要覆盖以下题材：

- 工厂场景（当前 UI 名称为“工厂实拍”）
- 产品实拍
- D2C 使用场景
- 包装、细节和通用 B-roll

## 2. 当前可用的四条素材路径

| 路径 | 当前能力 | 适用场景 |
| --- | --- | --- |
| 素材库自动匹配 | 点击“快速本地匹配全部空分镜”，按分镜语义、素材标签、片段分析、有效时长和画幅匹配企业素材；低匹配素材不会强行填入 | 产品实拍、工厂、包装、细节、通用 B-roll |
| 素材库手动匹配 | 每个分镜可从推荐候选中手选，也可拖入素材；支持图片和视频，并自动裁切到分镜时长 | 自动匹配不准或需要人工指定画面 |
| AI 智能生成 | 先生成目标首帧，确认后生成视频；视频生成成功后直接回填当前分镜，并自动进入 AI 素材库 | 缺少现成素材的产品、工厂、使用场景和通用创意画面 |
| 安排实拍后回填 | 创建拍摄任务，上传拍摄结果作为候选，再检查时长、方向和旁白配置后采用 | 证书、检测、操作、安装、客户案例等必须有真实证据的镜头 |

可归纳为：

```text
非数字人分镜
├─ 有真实素材 → 自动匹配 / 手动匹配
├─ 有参考素材但不够用 → 融合生成
├─ 没有素材但允许创意表达 → 纯 AI 生成
└─ 必须提供真实证据 → 安排实拍并回填
```

## 3. 素材匹配路径

### 3.1 整片一键匹配

“快速本地匹配全部空分镜”处理所有未锁定、尚未选择 AI 生成的空分镜。

匹配不是简单依赖文件名，主要依据：

- 素材分析后得到的可定位视频片段
- 视觉主题和表达目的
- 产品外观、包装、颜色和材质证据
- 工厂主体、设备或工序
- 分镜目标时长与素材可用时长
- 横竖画幅
- 同一人物跨镜头的连续性

对于爆款复刻任务，素材需要具备可定位、经过分析验证的片段证据。系统会保留锁定镜头，也不会覆盖已选择 AI 或融合生成的镜头。

### 3.2 单镜候选匹配

系统为当前分镜遍历可用于生产的图片和视频，根据匹配分数排序，最多展示 6 条候选。用户可以手动选择候选或拖入素材。

选择素材后，系统会记录：

- 匹配分数
- 匹配原因
- 与分镜要求的差异
- `direct`、`review` 或 `missing` 匹配等级
- 当前分镜裁切起止时间

### 3.3 无可靠匹配时的处理

低于可靠阈值的素材只可视为视觉占位，不能作为可信匹配结果。企业素材库中没有通过逐片段画面校验的高匹配素材时，镜头保持为空，并等待：

- 上传素材
- 安排拍摄
- 手动指定
- 进入 AI 智能生成

系统不会用低相关素材自动填满分镜。

## 4. AI 智能生成的总体技术链路

素材库没有可用素材时，当前实现采用两阶段生成，而不是直接从文本生成整段视频：

```text
分镜结构化
    ↓
Qwen Image 生成首帧
    ↓
用户确认首帧
    ↓
Seedance 以首帧为约束生成 4～15 秒视频
    ↓
Qwen VL 对视频抽帧质检
    ↓
回填当前分镜 + 自动进入 AI 素材库
```

### 4.1 当前使用的模型

| 阶段 | 当前默认模型 | 调用方式 |
| --- | --- | --- |
| 多产品自动匹配 | `qwen-plus` | 文本模型，从本片已选产品中判断当前分镜对应的产品 |
| 首帧生成 | `qwen-image-3.0` | 阿里百炼 OpenAI 兼容接口 `/images/generations` |
| 视频生成 | `doubao-seedance-2-0-fast-260128` | 火山方舟 `/contents/generations/tasks` |
| 生成结果质检 | Qwen VL；精确视觉检查默认 `qwen3-vl-flash` | 对生成视频抽帧后，以多图输入检查产品、场景、动作、文字和物理错误 |

模型可通过以下环境变量覆盖：

- `QWEN_IMAGE_MODEL`
- `SEEDANCE_MODEL`
- `QWEN_VL_MODEL`
- `QWEN_EXACT_VL_MODEL`

当前 `local-preview-1002/.env.local` 没有覆盖上述模型名称，因此本文按代码默认值说明。

## 5. 分镜结构化与模型输入

前端向 `/api/overseas/studio/storyboard-first-frame` 提交的核心字段如下：

```ts
{
  projectId,
  requestId,
  shotId,
  mode: "free_creation" | "replication",
  sceneType: "product" | "factory" | "usage" | "general",
  shotDescription,
  startSeconds,
  endSeconds,
  ratio,
  productIds,
  productName,
  productImageUrl,
  environmentMaterialId,
  characterMaterialId,
  sourceFirstFrameUrl,
  layout: {
    subject,
    environment,
    cameraAngle,
    productPosition,
    scale,
    contactSurface
  },
  action: {
    startState,
    beats,
    endState,
    cameraMotion
  },
  keyStates
}
```

字段来源和作用：

- `shotDescription`：当前分镜时间、标题和详细画面说明。
- `productIds`：优先采用用户为该镜头指定的产品。
- `environmentMaterialId`：可选的工厂或场景参考图。
- `characterMaterialId`：可选且已授权的企业人物参考图；本文所述非数字人场景通常不需要。
- `sourceFirstFrameUrl`：主要用于爆款复刻，提供参考视频原镜头构图。
- `layout`：主体、环境、机位、产品位置、比例和接触面。
- `action`：动作开始状态、顺序步骤、结束状态及运镜。
- `keyStates`：长动作分段生成所需的中间稳定状态。

本片选择多个产品但没有为当前镜头明确指定产品时，系统调用 `qwen-plus`，根据分镜描述在已选产品中匹配。匹配置信度低于 `0.7` 时需要人工确认。

## 6. Qwen Image 首帧生成

### 6.1 提示词结构

服务端根据分镜类型生成英文提示词，核心结构如下：

```text
Create exactly one photorealistic 9:16 first-frame still
for a short continuous video shot.

Shot requirement:
[当前分镜完整画面描述]

Target enterprise products:
[产品名称]

Reference image 1:
[参考视频原首帧，只借构图和位置]

Reference image 2:
[企业产品图，锁定形状、颜色、包装和品牌]

Reference image 3:
[可选工厂环境图或人物图]

Scene-specific requirement:
[产品 / 工厂 / 使用场景 / 通用场景的约束]

Layout contract:
[产品位置、比例、接触面、镜头关系]

START state:
[动作开始状态]

Later motion beats:
[后续动作步骤，但首帧不能提前显示动作已完成]

Do not add extra products, fingers, hands, floating objects,
captions, watermarks, random text or unsupported business claims.
```

### 6.2 请求格式

实际发给 Qwen Image 的请求近似如下：

```json
{
  "model": "qwen-image-3.0",
  "prompt": "完整首帧提示词",
  "image": [
    "data:image/jpeg;base64,...",
    "data:image/png;base64,..."
  ],
  "n": 1,
  "size": "1024*1792"
}
```

尺寸映射：

- `9:16` → `1024*1792`
- `16:9` → `1792*1024`
- `1:1` → `1024*1024`

Qwen Image 最多输入 3 张有顺序的参考图。多产品或多角度产品图会先拼成 contact sheet，再作为一张参考图输入。

### 6.3 首帧确认门槛

首帧生成后不会立即提交视频模型。用户需要先核对：

- 产品是否正确
- 包装、颜色和形状是否稳定
- 手持、桌面或设备接触是否合理
- 工厂设备和空间是否合理
- 是否出现错误文字、Logo 或多余物体

确认首帧后才能生成视频。

## 7. Seedance 图生视频

### 7.1 请求格式

确认首帧后，前端调用 `/api/overseas/studio/seedance-video`。服务端向火山方舟提交近似请求：

```json
{
  "model": "doubao-seedance-2-0-fast-260128",
  "content": [
    {
      "type": "text",
      "text": "视频动作提示词"
    },
    {
      "type": "image_url",
      "image_url": {
        "url": "已签名的首帧地址"
      },
      "role": "first_frame"
    }
  ],
  "ratio": "9:16",
  "duration": 5,
  "resolution": "480p",
  "generate_audio": false,
  "watermark": false
}
```

默认接口：

```text
POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks
GET  https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks/{taskId}
```

### 7.2 视频提示词结构

```text
Single continuous N-second [scene type] storyboard shot.

Visual requirement:
[分镜画面要求]

START state:
[确认首帧的开始状态]

Perform in exact temporal order:
1. [动作步骤 1]
2. [动作步骤 2]

END state:
[最终必须看见的状态]

Camera motion:
[运镜要求]

Identity and physical constraints:
[产品身份、物理接触、人物身份或环境身份约束]

Maintain the confirmed first frame composition and subject identity.

Do not add captions, labels, watermarks,
extra products, people or tools.
```

系统同时加入以下约束：

- 非数字人 B-roll 不生成口播、对白或声音。
- 保持产品形状、颜色和可见包装一致。
- 不改变场景，不增加未经要求的物体。
- 不生成字幕、UI、水印或虚构标签。
- 一个镜头只完成一个清晰动作。
- 请求参数使用 `generate_audio: false`。

## 8. 各题材的具体生成路径

### 8.1 产品实拍型

模型输入：

- 企业中心产品 ID 和产品名称
- 一张或多张产品图
- 产品多角度图
- 分镜构图
- 产品在画面中的位置和比例
- 桌面、手或传送带等接触关系
- 动作开始和结束状态

技术重点是产品身份锁定：

- 产品图作为 Qwen Image 的参考图。
- 多角度图会拼成一张多视图参考表。
- 提示词要求保持产品形状、颜色、包装和品牌。
- 只有单角度图时，禁止模型展示未知背面、侧面或隐藏包装文字。
- 首帧确认后，由 Seedance 生成镜头运动和产品动作。

该路径生成的是拟真产品画面，不能作为真实检测、真实效果或真实客户案例的事实证据。

### 8.2 工厂场景型

如果素材库没有工厂素材，当前系统可以生成“工厂场景”，不能生成可作为企业事实证据的“真实工厂实拍”。

模型输入：

- 分镜要求，例如灌装、质检、传送带或包装
- 可选的企业工厂环境图
- 产品参考图
- 设备、工位、工人、传送方向和运镜要求
- 产品与设备或工作台的位置关系

提示词要求：

- 工厂空间和工位保持连贯。
- 设备、传送方向和人员位置合理。
- 不生成可读的设备标签。
- 环境参考图只证明可见外观，不能证明企业拥有该工厂、设备、产能或认证。

需要明确区分：

- 有企业工厂参考图：可以做“基于企业环境参考的生成镜头”。
- 完全没有工厂素材：只能做“通用拟真工厂场景”。
- 真实工厂、真实产线、质检过程和产能证明仍必须走实拍上传路径。

当前 UI 使用“工厂实拍”作为题材名称，但在无素材 AI 路径中实际产物不是实拍，这是产品表达上的风险点。

### 8.3 D2C 使用场景型

D2C 使用场景在代码中主要映射为 `sceneType: "usage"`，部分氛围镜头映射为 `general` 或 `product`。

模型输入：

- 产品图和产品身份
- 消费者或手部与产品的起始接触关系
- 使用环境，例如浴室、厨房、卧室或户外
- 动作开始状态
- 有顺序的使用步骤
- 最终状态
- 镜头运动和时长

示例：

```text
START:
产品放在洗手台，手尚未接触泵头。

BEATS:
1. 手握住瓶身
2. 食指按压泵头
3. 产品从泵口释出到掌心

END:
手掌中可见少量产品，瓶身仍直立于洗手台。

CAMERA:
稳定近景，轻微向前推进。
```

首帧只生成 `START` 状态，不能提前显示最终结果。Seedance 再按照动作步骤生成视频。

单镜超过 15 秒时，系统要求：

- 至少两个明确动作步骤
- 明确开始状态
- 明确最终状态
- 每个动作步骤之间有稳定关键状态

满足这些条件后，系统拆分为多个 4～15 秒片段顺序生成，并以前一段末帧约束下一段。

## 9. 生成后的质量检查

Seedance 生成完成后，系统抽取多个时间点的画面帧并交给 Qwen VL 检查：

- 产品外观、颜色和包装是否一致
- 是否出现错误文字或 Logo
- 人脸、手指和物理接触是否异常
- 是否存在黑帧、闪烁和画面跳变
- 动作是否符合分镜
- 是否出现缺乏依据的工厂、认证或效果声明
- 开始状态、动作步骤和结束状态是否完整
- 工厂环境是否偏离指定参考图

普通镜头通过阈值约为 75 分，关键真实性镜头约为 85 分。质检结果作为生成结果的质量记录和问题提示，不增加“采用候选”步骤；视频生成成功后直接回填当前分镜并进入 AI 素材库。

## 10. 当前结论

1002 的无素材生成主链路为：

```text
Qwen Image 3.0 首帧
    +
Seedance 2.0 Fast 图生视频
    +
Qwen VL 抽帧质检
```

产品和 D2C 场景可以直接使用这条路径。完全没有企业环境依据的“工厂实拍”只能生成通用拟真工厂场景，不能被当作企业真实工厂证据。

## 13. 参考素材的统一上传与持久化要求

### 13.1 用户入口

非数字人智能生成所需的产品、工厂、场景和背景参考素材，应支持从两个入口上传：

1. **内容制作工作台直接上传**：用户制作当前内容时，在分镜或素材选择区直接上传图片或视频。
2. **企业知识库上传**：用户提前录入产品、工厂、场景和企业背景资料。

两个入口只代表不同的用户操作位置，底层必须汇入同一套租户级资产系统。任何一个入口上传成功后，素材都应：

- 永久保存在服务器对象存储中，而不是只作为当前草稿的临时文件。
- 在“我的素材”中可见、可搜索、可管理和可复用。
- 与企业知识库中的产品、工厂、场景或企业实体建立关联。
- 带有租户、来源、原文件、清洗版本、内容哈希、授权范围和创建时间等来源记录。
- 可被内容 Agent、分镜匹配和智能生成直接调用。

目标关系如下：

```text
内容工作台上传 ─┐
                ├─→ 统一素材接入服务 → 清洗/分析 → 对象存储 + 资产记录
企业知识库上传 ─┘                              ├─→ 企业知识库关联
                                                ├─→ 我的素材
                                                └─→ 内容 Agent / 分镜生成
```

### 13.2 产品资料录入

产品资料入口需要支持：

- Excel：`.xlsx`、`.xls`
- CSV
- Word：`.docx`，必要时兼容 `.doc`
- PDF

文档中可能同时包含：

- 产品名称、SKU、类目、规格、价格、MOQ、材质和卖点
- 每个产品对应的一张或多张图片
- 包装图、细节图和多角度图
- 工厂背景、电商背景、使用场景和品牌视觉
- 证书、检测报告等事实凭证

导入后不能只保存文档附件。系统需要把文档解析为结构化产品记录，并将其中的嵌入图片或有效图片链接提取为独立资产，与对应产品建立稳定关联。

产品图片、包装图、细节图和场景图在导入后还必须同步进入“我的素材”，作为永久资产供后续分镜匹配和生成使用。证书和检测报告可以保留为事实凭证，但不能默认作为创意画面素材。

### 13.3 工厂和环境资料录入

工厂资料可以从企业知识库或内容制作工作台上传，支持：

- 工厂、车间、生产线、工位、仓储和设备照片
- 工厂、生产流程、包装、质检和物流视频
- D2C、电商、居家、浴室、厨房、户外等环境参考图或视频

上传时应允许用户绑定：

- 企业或工厂实体
- 产品或产品系列
- 场景类别
- 可证明的事实范围
- 仅作视觉参考还是可以作为事实证据

工厂图片只能证明图片中直接可见的内容。只有完成来源和事实范围确认的企业自有素材，才能用于“真实工厂”“真实产线”“真实质检”等声明。普通背景图只作为视觉参考。

### 13.4 媒体和文档清洗

这里所说的本地 FF/MPG 等处理能力，建议统一定义为**媒体与文档清洗管线**。实现可以使用 FFmpeg、文档解析器、图片处理库及必要的插件，但对上层暴露一致的干净资产格式。

视频清洗至少包括：

- 使用 FFmpeg/ffprobe 探测真实格式、编码、时长、分辨率、帧率、旋转信息和音轨。
- 转码为系统支持的标准格式，例如 H.264/AAC MP4。
- 修正旋转、时间基和损坏索引，生成可网页预览的版本。
- 提取封面和关键帧，执行镜头切分与视觉分析。
- 记录原文件与清洗版本的哈希和派生关系。

图片清洗至少包括：

- 解码校验和真实 MIME 检测。
- EXIF 方向修正、色彩空间归一化和尺寸限制。
- 保留原图，同时生成标准预览图和模型输入版本。
- 必要时生成产品透明底图、主体裁切和多角度联系表。
- 去除无关页面边框或扫描噪声时，不得修改产品身份和包装事实。

文档清洗至少包括：

- 安全解析 Excel、Word 和 PDF，拒绝宏、外部执行内容和危险嵌入对象。
- 提取表格、段落、产品字段、嵌入图片和图片与产品行/章节的对应关系。
- 对扫描 PDF 执行 OCR，并保留页码和区域来源。
- 对外链图片执行下载、格式验证、租户内持久化，不能长期依赖外部临时链接。
- 对无法可靠关联到具体产品的图片标记为待确认，不自动绑定。

### 13.5 建议的统一资产记录

每个清洗后的资产至少应包含：

```ts
{
  id,
  tenantId,
  objectKey,
  originalObjectKey,
  sourceEntry: "enterprise" | "content_workbench" | "document_import",
  sourceDocumentId,
  sourcePageOrSheet,
  sourceRowOrRegion,
  mediaType: "image" | "video" | "document",
  assetRole: "product" | "packaging" | "factory" | "environment" | "certificate" | "general",
  productIds,
  enterpriseEntityIds,
  contentSha256,
  cleanedContentSha256,
  width,
  height,
  duration,
  analysisStatus,
  rightsStatus,
  evidenceScope,
  createdAt,
  updatedAt
}
```

企业知识库保存结构化事实和实体关系，“我的素材”提供统一的媒体资产视图；两者引用同一份底层资产记录，不复制两套相互漂移的数据。这里的“统一资产”是后端数据层，不新增名为“统一资产中心”的用户页面。

## 14. 当前实现与目标要求的差距

截至 `local-preview-1002` 当前代码：

- 内容工作台上传的图片和视频写入 Studio/PocketBase 素材记录，并可进入“我的素材”。
- 企业知识库上传走独立的 `/enterprise/assets` 存储路径。
- 两个入口还没有完整汇入同一份资产记录；企业资产不会自动成为“我的素材”中的标准素材记录。
- 企业中心产品表入口目前主要支持 `.xlsx` 和 `.csv`；数字员工页面另有 `.xls` 支持。
- Word/PDF 可以作为产品资料或资质附件上传，但当前并未形成统一的“解析产品字段 + 提取嵌入图片 + 自动绑定产品 + 同步到我的素材”管线。
- Excel 产品导入当前主要读取单元格字段和图片链接，不能视为已经完整支持所有文档中的嵌入产品图片。
- 服务端已经有对象存储、素材哈希、视频分析、封面和片段分析等基础能力，但企业资产与 Studio 素材的持久化模型仍然分离。

因此，“两个入口都可上传、统一清洗、永久存储、同时进入企业知识库和我的素材、供内容 Agent 直接调用”应作为下一阶段的明确架构目标，而不是当前已完全实现的能力。

## 15. 首帧模型分叉与已确认决策

### 15.1 当前代码中并存的三种实现

当前 1002 并没有统一使用一个首帧方案：

1. **内容制作工作台的分镜首帧**：调用 `generatePosterImage`，实际模型默认是 `qwen-image-3.0`。
2. **内容 Agent 的产品场景链路**：曾使用 `SeedreamFirstFrameGenerator` 生成产品场景首帧；这是此前“Seedream 生首帧”方案实际落地的位置。
3. **当前 Seedance 2.x 全模态产品场景链路**：在模型名匹配 Seedance 2.0/2.5 时，会跳过 Seedream 生成，直接使用参考视频构图帧、精确产品像素合成和产品参考图输入 Seedance；只有不支持全模态参考的旧路径才回退到 Seedream。

数字人目标首帧和逐句复刻的部分链路仍在使用 Seedream，但不属于本文讨论的非数字人素材主链路。

### 15.2 为什么当前内容工作台会显示为 Qwen Image

原因不是业务层重新确认了“改用千问”，而是内容工作台的 `/storyboard-first-frame` 路由后来形成了独立实现，复用了海报生图的 `generatePosterImage` 封装。该封装只调用 Qwen Image。它没有复用此前产品场景中的 `FirstFrameGenerator`/`SeedreamFirstFrameGenerator` 抽象，因此造成了技术路径分叉。

从 Git 历史看，提交 `ad354ef` 已经为产品场景落地过 Seedream 首帧生成。后续代码又为 Seedance 2.x 增加了全模态直传和精确产品像素合成。这说明“Seedream 生首帧”的既有决定确实存在，但没有统一覆盖内容工作台的分镜首帧接口。

### 15.3 已确认的目标决策

基于当前讨论，目标规则确定为：

- **没有可靠构图首帧、需要从分镜描述新建场景时**：使用 Seedream 生成首帧。
- **已有可靠构图帧，且 Seedance 2.x 可同时接收构图、产品图和参考视频时**：直接使用构图帧 + 精确产品合成 + Seedance 全模态输入，避免额外生成一次首帧造成产品或场景漂移。
- **内容工作台不得继续因为复用海报接口而默认选择 Qwen Image**；如果仍保留 Qwen，应作为明确配置的备选供应商，而不是隐式默认值。
- 无论首帧由 Seedream 生成还是使用真实构图帧，都必须进入同一套版本、预算和质量检查流程；首帧保留生成前确认，视频生成成功后直接回填分镜。

该方案已经确认。后续开发应把模型选择收敛到统一首帧生成网关，并将第 4、6、10 节描述的 Qwen Image 工作台现状迁移为上述目标路由。

## 16. “我的素材”中的资产所有权边界

“我的素材”是素材使用界面，不等于其中所有内容都是企业资产。素材必须按来源和所有权明确分成两类。

### 16.1 灵枢云爆款素材

灵枢工作人员上传并向多个客户开放的云爆款素材属于平台公共素材或共享素材，不属于当前企业。

处理规则：

- 可以出现在“我的素材”的“云爆款 / 公共素材 / 平台素材”分类中。
- 不进入任何租户的企业知识库。
- 不得自动绑定为企业产品、企业工厂、企业案例、企业客户或企业资质。
- 不得作为“这是本企业真实产品、真实工厂、真实产线、真实客户案例”的事实证据。
- 只能在授权范围内用于结构参考、创意参考、通用背景、通用 B-roll 或明确许可的成片剪辑。
- 如果作为生成参考，模型提示词必须明确它只提供构图、节奏、运镜或通用场景参考，必须移除原产品、品牌、Logo、人物身份和水印。
- 企业用户不能修改平台原资产，只能在自己的项目中引用；如允许派生编辑，派生产物需要单独记录来源与授权，不能反向污染公共原素材。
- 平台工作人员负责公共素材的上架、授权范围、下架和版本管理。

### 16.2 用户或企业自行上传的素材

用户从内容工作台、企业知识库或其他企业入口上传的工厂、产品、包装、场景、品牌、人物等素材，属于当前租户的企业资产。

处理规则：

- 永久写入当前租户的私有对象存储和统一资产记录。
- 在“我的素材”的“企业上传素材”Tab 中可见。
- 根据素材类型和用户确认结果，进入企业知识库并关联产品、工厂、场景、品牌、人物或其他企业实体。
- 可以作为内容 Agent、素材匹配和智能生成的企业参考输入。
- 只有来源、授权和事实范围得到确认后，才能作为企业事实证据。
- 企业用户可以管理、补充标签、修改关联或删除自己的素材；删除时需要检查是否仍被产品、项目、成片或生成任务引用。

### 16.3 两类素材的能力矩阵

| 能力 | 灵枢云爆款素材 | 用户/企业上传素材 |
| --- | --- | --- |
| 出现在“我的素材” | 可以，显示在云爆款素材分类 | 可以，统一显示在企业上传素材 Tab |
| 进入企业知识库 | 不可以 | 应进入或关联企业知识库 |
| 归属当前企业 | 否 | 是 |
| 跨租户共享 | 可以，取决于平台授权 | 默认不可以 |
| 作为企业事实证据 | 不可以 | 完成来源和事实范围确认后可以 |
| 用于构图、节奏或运镜参考 | 可以 | 可以 |
| 用于产品身份锁定 | 不可以 | 已绑定到对应产品后可以 |
| 用于工厂身份或产能证明 | 不可以 | 企业确认且证据范围匹配时可以 |
| 用户修改原资产 | 不可以 | 可以管理企业自己的资产记录 |
| 用户删除原资产 | 不可以 | 可以，但需经过引用检查 |

### 16.4 统一资产模型需要增加的字段

为了避免把公共素材误当成企业资产，资产记录至少要明确：

```ts
{
  ownership: "platform" | "tenant",
  visibility: "shared" | "tenant_private",
  sourceEntry: "platform_curated" | "enterprise" | "content_workbench" | "document_import",
  tenantId: string | null,
  ownerTenantId: string | null,
  knowledgeEligible: boolean,
  evidenceEligible: boolean,
  evidenceScope: string[],
  usageRights: {
    editing: boolean,
    generationReference: boolean,
    finalRender: boolean,
    expiresAt?: string
  },
  derivedFromAssetIds: string[]
}
```

必须满足以下不变量：

```text
ownership = platform
→ knowledgeEligible = false
→ evidenceEligible = false
→ 不允许写入租户企业知识库

ownership = tenant
→ tenantId 和 ownerTenantId 必须是当前租户
→ 可以进入企业知识库关联流程
→ 是否可作事实证据仍需独立确认
```

### 16.5 上传入口的归属判定

归属不能根据文件内容猜测，应根据经过鉴权的上传入口和操作者角色确定：

- 灵枢运营后台的公共素材上传入口 → `ownership: platform`、`visibility: shared`。
- 企业知识库上传入口 → `ownership: tenant`、`visibility: tenant_private`。
- 内容制作工作台上传入口 → `ownership: tenant`、`visibility: tenant_private`。
- 从企业文档中提取的图片 → 继承该文档的租户所有权，并记录 `sourceDocumentId`。
- 对公共爆款素材产生的裁切、分析和临时预览 → 仍继承平台所有权，不能因为某个租户使用过就变成企业资产。
- 使用公共素材结构和企业私有产品生成的新候选 → 新候选归当前租户所有，但必须保留公共参考素材与企业输入素材的完整派生关系。

企业知识库上传和内容制作工作台上传只是两个操作入口，不形成两个素材分类。两者完成上传和清洗后，都写入同一套租户企业资产，并统一显示在“企业上传素材”Tab。系统可以在资产详情中保留 `sourceEntry`，用于追溯最初从哪个入口上传，但该字段不影响前端所属 Tab。

### 16.6 在内容制作中的展示要求

“我的素材”前端需要明确展示来源徽标，至少区分：

- `云爆款`：平台公共素材
- `企业上传素材`：用户从企业知识库或内容工作台上传的租户企业资产
- `AI 素材库`：当前企业生成的工厂、产品、D2C 或其他非数字人素材；生成成功后自动入库

筛选器、素材详情和分镜候选中都应展示该来源。涉及产品、工厂、资质和客户案例等真实性镜头时，匹配引擎必须排除 `ownership: platform` 的素材；公共素材只能用于不承担企业事实证明的镜头。

### 16.7 “我的素材”最终 Tab 结构

根据当前产品决策，“我的素材”采用以下一级分类：

```text
我的素材
├─ 企业上传素材
│  ├─ 从企业知识库上传
│  └─ 从内容制作工作台上传
├─ AI 素材库
└─ 云爆款素材
```

其中“从企业知识库上传”和“从内容制作工作台上传”只作为资产来源记录或二级筛选条件，不是两个独立 Tab。企业上传素材可以继续按产品、工厂、场景、包装、人物等资产角色筛选。

## 17. 已确认的产品决策

### 17.1 页面与数据层

- 不新增名为“统一资产中心”的页面。
- 后端采用一份统一资产数据；企业知识库保存实体、事实及资产关系，“我的素材”展示和管理媒体资产。
- 企业知识库和内容工作台是两个上传入口，上传结果统一进入“企业上传素材”Tab。

### 17.2 工作台上传后的知识库关联

- 内容工作台上传成功后，素材立即成为当前租户的企业私有资产并进入“企业上传素材”。
- 系统可以推荐产品、工厂或场景关联。
- 用户确认后建立企业知识库实体关系。
- 未完成关联的素材仍可保存在企业上传素材中，后续继续补充关联。

### 17.3 文档导入确认

- Excel、Word、PDF 等文档完成解析后，以弹窗形式展示导入结果。
- 弹窗用于确认识别出的产品字段、产品与图片对应关系、无法归属的图片、OCR 字段以及外链图片转存结果。
- 用户确认后再正式写入产品记录和资产关联，避免自动解析结果污染企业知识库。

### 17.4 首帧模型路由

- 没有可靠构图首帧、需要新建场景时，使用 Seedream 生成首帧。
- 已有可靠构图帧且 Seedance 2.x 支持全模态参考时，使用真实构图帧、精确产品合成和 Seedance 全模态输入。
- Qwen Image 不作为内容工作台默认首帧模型；如保留，只能作为显式配置的备选供应商。
- 收费模型失败时不自动切换到另一收费模型，避免重复费用和不可预期的结果变化。

### 17.5 不设置禁止 AI 生成的分镜类型

- 产品侧不维护“禁止 AI 生成”的分镜类型清单。
- 工厂、产品、D2C 及其他非数字人分镜都可以进入 AI 生成路径。
- 系统通过素材来源和 `AI 素材库` 标识区分生成内容与企业上传内容，不在生成入口做类型阻断。

### 17.6 删除与引用

- “解除企业知识库关联”和“删除底层文件”分开处理。
- 正在被项目、分镜、成片或生成记录引用的资产不能直接物理删除。
- 删除先进入回收站；确认无引用或满足清理条件后再物理删除。
- 已完成成片保留必要的来源与版本快照。

### 17.7 AI 生成后的处理

AI 生成流程保持简单：

```text
确认首帧
→ 生成视频
→ 生成成功后直接回填当前分镜
→ 同时自动写入“AI 素材库”
```

- 不增加“候选区 → 人工采用 → 正式素材”的额外流程。
- 工厂素材、产品素材、D2C 素材及其他非数字人生成结果采用相同处理方式。
- AI 素材记录自动关联当前租户、项目、分镜、素材类型、输入参考资产、模型和生成时间。
- 重新生成会产生新的素材版本，并直接替换当前分镜引用；历史版本仍保留在该分镜的版本记录中，便于恢复。
- 自动质检可以继续执行并记录结果，但不阻塞生成结果进入分镜和 AI 素材库。
