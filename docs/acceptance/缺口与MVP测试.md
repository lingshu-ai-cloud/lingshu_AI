# 缺口与 MVP 测试

更新日期：2026-10-11
适用范围：B2B 社媒经营 Agent、爆款复刻内容生产、单条真实成片 MVP、生产接入准备

## 1. 这份文档解决什么问题

当前系统已经完成大量本地流程、受控供应商、任务恢复和页面跳转测试，但“测试通过”包含不同层次，不能混为一谈：

1. 任务编排能够运行；
2. 本地能够生成可播放 MP4；
3. 成片达到爆款复刻的创意要求；
4. 真实数字人和真实 AIGC 供应商调用成功；
5. 真实社媒账号发布并取得平台回执；
6. 生产数据库、队列、鉴权和 Worker 已经可用。

现阶段不继续用“一周生成 5 条”代表完整上线。为了尽快完成 MVP，先用 **1 条视频**验证真实端到端闭环；通过后再扩展到整周母版和多平台发布量。

## 2. 数量口径共识

正式经营排期按每个账号每周计算：

| 平台 | 每周发布量 |
| --- | ---: |
| Facebook | 5 条 |
| TikTok | 5 条 |
| Instagram | 3 条 |
| YouTube | 3 条 |
| 合计 | 16 个平台发布任务 |

“5 条视频”指前期用于验证生产能力的 5 个内容母版，不等于完整周发布量。一个母版可以生成多个平台适配版本，但每个平台版本必须分别处理画幅、时长、字幕安全区、封面、标题、文案、标签和发布要求。同一母版不适合某个平台时，应生成平台专属版本，不能强行复用。

## 3. 已经完成并有证据的部分

### 3.1 单条真实 MP4

已经做过一次本地爆款复刻完整链路实测：外部参考视频进入系统，经过分析、脚本、素材确认、生产和质检，最终生成一条 **8.56 秒、720×1280、H.264/AAC** 的可播放 MP4。

这条视频使用授权产品图片、本地动效、字幕、口播和配乐完成合成。技术检查通过，创意检查未通过，系统最终显示“需要修改、不可发布”。这个结果证明本地生产链能够产出真实文件，也证明创意门禁没有把不合格内容包装成可发布成片。

### 3.2 周任务与工程可靠性

本地受控测试已经覆盖：

- B2B 零基础：外部参考 5 条；
- B2B 有基础 40/60：自有参考 2 条、外部参考 3 条；
- B2B 有基础 20/80：自有参考 1 条、外部参考 4 条；
- 脚本、分镜、素材准备、视频合成、质量节点、受控发布、复盘和模板提取；
- 重复执行、任务恢复、跨租户、跨账号、发布结果 unknown 和历史回执读取；
- 任务卡进入已有生产页面，以及企业事实、渠道授权、素材、发布、客服等任务身份传递。

这些结果证明工程编排和受控合同，不证明真实供应商质量、真实平台能力或生产环境已经接通。

## 4. 尚未完成的关键缺口

### 4.1 爆款复刻质量缺口

- 尚未证明前三秒钩子的镜头、节奏、构图和声音能够达到可接受的复刻程度；
- 尚未形成经业务确认的“复刻相似度、钩子强度、口播说服力、品牌一致性”验收标准；
- 现有真实 MP4 主要使用静态产品图片，无法等价复刻原视频中的工厂运动镜头；
- 现有口播偏合规说明，缺少经品牌确认的强卖点，因此创意门禁没有放行。

### 4.2 数字人缺口

- 现有真实 MP4 测试没有实际调用 HeyGen 或其他数字人供应商；
- 尚未验证用户选择的数字人形象、真实音色、口型同步、人物稳定性和跨镜头一致性；
- 尚未验证数字人失败后的局部重试、费用对账和恢复不会重复扣费。

### 4.3 非数字人 AIGC 素材缺口

- 现有真实 MP4 测试没有实际调用 Seedance、Seedream 等生成关键镜头；
- 尚未验证关键钩子镜头会优先高相似度生成，而不是被通用库存素材替代；
- 尚未验证产品、工厂和客户证据等事实镜头在缺素材时能够 fail closed，而不是生成虚假事实；
- 尚未验证生成失败时只返工失败镜头，不重复生成其他已通过镜头。

### 4.4 真实发布与数据闭环缺口

- 尚未用一个真实测试账号完成单平台发布并取得原始平台回执；
- 尚未验证发布结果 unknown 时查询原 attempt、禁止盲目重发；
- 尚未采集真实播放、点赞、评论和转发数据；
- 尚未用真实数据生成复盘结论和下一轮候选任务。

### 4.5 生产环境缺口

当前生产 readiness 仍为 `ready: false`，存在九项明确门禁：

1. PostgreSQL 业务存储未配置；
2. 发布原子租约存储不可用；
3. Redis/BullMQ 持久队列未配置；
4. 生产鉴权仍允许本地 fallback；
5. Meta Social OAuth 未配置；
6. Instagram Login OAuth 未配置；
7. Instagram 发布能力未启用；
8. TikTok Direct Post 未通过平台审批；
9. Worker 队列连接不可用。

此外，公网 `/api/overseas/ready` 当前返回 SPA HTML，不能作为 readiness 证据；已记录的生产主机 SSH 握手超时，因此尚不能核验远端代码、数据库、队列、Worker、备份和平台配置。

## 5. 单条视频 MVP 的测试范围

MVP 只验收 **1 条视频、1 个测试账号、1 个发布平台**。这条视频必须覆盖主要生产技术栈，不能用占位图、假成功状态或手工填写回执代替。

### 5.1 推荐测试样本

- 用户类型：B2B 零基础；
- 参考来源：1 条外部爆款；
- 产品：资料和授权素材相对完整的主推产品；
- 视频结构：至少包含一段数字人口播和一个非数字人关键 AIGC 镜头；
- 发布平台：从已经具备测试账号和可用发布权限的平台中选择一个；
- 视频长度：以能够覆盖完整钩子、核心卖点和行动指令为准，不为追求时长而增加无效镜头。

### 5.2 必须跑通的真实链路

1. **爆款输入与冻结**：保存参考视频来源、文件或可访问地址、版本、分析快照和使用边界。
2. **编导分析**：识别前三秒钩子，拆解脚本、分镜、节奏、字幕、口播和行动指令。
3. **镜头分类**：明确哪些是数字人镜头、关键 AIGC 镜头、可复用企业素材和事实证据镜头。
4. **数字人真实生成**：调用真实供应商，生成口播音频和数字人视频；保存供应商任务 ID、费用和结果文件。
5. **关键镜头真实生成**：调用真实图片或视频 AIGC 供应商生成至少一个关键镜头；不能用无关通用素材替代。
6. **其他素材匹配**：从企业素材库选择有授权且语义匹配的素材；事实性素材不足时明确阻塞。
7. **成片合成**：合成数字人、AIGC 镜头、企业素材、字幕、配音、BGM 和转场，输出真实 MP4。
8. **技术质检**：检查文件、画幅、时长、编码、音画、字幕、黑帧、静音和素材完整性。
9. **创意质检**：检查钩子还原、节奏、卖点、品牌一致性、数字人观感和关键镜头表达。
10. **页面验收**：智能经营任务卡进入已有三栏内容工作台，展示该任务真实脚本、分镜、口播、素材、进度、费用和成片。
11. **单平台真实发布**：使用明确批准的测试账号发布一次，保存原始发布 attempt、平台任务 ID 和最终回执。
12. **指标与复盘**：读取真实播放、点赞、评论和转发；无数据时保持“暂无数据”；生成复盘结论和下周候选任务。

## 6. MVP 通过标准

以下条件必须同时满足：

- 参考视频、脚本、分镜、素材和成片属于同一租户、任务和版本；
- 数字人由真实供应商生成，人物、声音和口型达到人工验收标准；
- 至少一个关键非数字人镜头由真实 AIGC 技术栈生成，并通过复刻质量验收；
- 没有事实编造、无授权素材或静默降级；
- 生成真实可播放 MP4，技术质检通过；
- 创意质检结论为“可发布”，人工验收确认达到本次 MVP 目标；
- 页面能够查看真实过程与产物，费用显示预估和实际两种口径；
- 真实测试账号只发布一次，平台回执可追溯；
- 超时或 unknown 不产生第二次发布和第二次付费生成；
- 真实指标能够回收，尚无指标时不补零、不伪造；
- 失败后能够从原任务继续，已通过镜头不重复生成或扣费。

任何一项缺少权威证据，都只能标记为“未完成”或“阻塞”，不能写成通过。

## 7. MVP 暂不要求的内容

为了尽快闭环，本轮暂不要求：

- 一次完成 Facebook 5 条、TikTok 5 条、Instagram 3 条、YouTube 3 条；
- 同时验收多个账号或多个语言；
- 一次验证三种用户画像的完整真实生产周；
- 用真实账号批量发布；
- 以单条 MVP 成功替代生产基础设施、平台审批和整周容量验收。

单条 MVP 通过后，再扩展为 5 个内容母版和每周 16 个平台发布任务。

## 8. 建议的并行执行拆分

主会话应协调多个独立会话，每个会话再协调多个子 Agent；各会话使用同一权威工作区，但必须独立提交负责文件，避免交叉覆盖。

执行时遵循第 11 节的人机决策边界和第 12 节的重规划要求。A–E 是执行分工，不是五套独立业务方案；必须先冻结同一 MVP 身份和制作方案，再执行有依赖的真实动作。

### 会话 A：真实数字人与口播

- 核对数字人供应商、人物资产、音色和密钥配置；
- 跑一次真实数字人生成；
- 验证口型、人物一致性、费用、失败恢复和幂等；
- 输出可供成片合成的真实视频片段和证据。

### 会话 B：关键非数字人 AIGC 镜头

- 选择需要高相似度复刻的钩子或产品关键镜头；
- 跑一次真实图片或视频生成；
- 验证提示词、参考图、镜头结构、费用和局部返工；
- 禁止以通用素材或说明图代替关键镜头。

### 会话 C：单条成片、页面和创意验收

- 把真实数字人、真实 AIGC 镜头和企业素材合成为 MP4；
- 完成技术质检与人工创意验收；
- 核对任务卡进入既有三栏工作台，并展示真实任务数据；
- 形成一份普通用户可理解的验收报告。

### 会话 D：单平台真实发布与指标闭环

- 选择一个已获批准的测试平台和测试账号；
- 核对 OAuth、账号归属、发布能力、预算和明确授权；
- 发布一次并保存原 attempt 与平台回执；
- 回收真实指标并生成复盘；
- 测试 unknown 查询恢复和禁止重复发布。

### 会话 E：生产基础设施与上线门禁

- 核对可达的生产 SSH、远端分支与提交；
- 核对 PostgreSQL、Redis/BullMQ、Worker、鉴权、对象存储和备份；
- 修复 `/api/overseas/ready` 返回 HTML 的问题；
- 收集生产 readiness 和六类真实运行证据；
- 不在缺少用户授权、真实凭据或平台审批时执行发布、迁移或部署。

## 9. 主会话汇报口径

主会话每次汇报必须分别说明：

- 本地受控合同是否通过；
- 是否生成真实媒体文件；
- 是否调用真实付费供应商；
- 创意质量是否通过；
- 是否真实发布；
- 是否取得真实平台回执；
- 是否回收真实指标；
- 生产 readiness 是否为 `ready: true`。

不得使用“链路跑通”“发布通过”这种笼统说法覆盖上述差别。

## 11. 人与 Agent 的决策边界

客户决定经营目标、预算和关键品牌偏好，并授予账号使用、素材及必要的外部动作权限。系统在已授权范围内自主完成选择、制作、检查和恢复，不将供应商、模型、提示词、每张首帧等内部决策逐项交给客户。授权、内部制作决策、人工质量验收必须分别记录，不能互相替代。

### 11.1 唯一决策负责人

| 范围 | Agent 自主决策及负责人 | 人的决定 | 升级给人的条件 |
| --- | --- | --- | --- |
| MVP 总体 | 经营 Agent 冻结账号、产品、目标客户、企业事实、租户/task/run/version；主会话协调 A–E 和预算分配 | 经营目标、总预算、账号使用和发布范围授权 | 权威记录存在内部无法消解的业务冲突，或需扩大授权 |
| A 数字人与口播 | 编导 Agent 决定镜头、人物、音色和台词；数字人制作 Agent 查询价格、选供应商、估价、执行与恢复 | 品牌指定偏好、肖像/声音及必要用途授权 | 缺必要授权、超预算，或改变客户明确的品牌要求 |
| B 关键 AIGC 镜头 | 编导 Agent 决定符合复刻目标的改编；素材 Agent 选择模型、提示词、首帧、生成路径和局部返工 | 提供或确认无法从权威资料核实的产品事实及必要权利授权 | 产品身份/事实不能核实，改编改变核心卖点，或超预算 |
| C 合成与验收 | 合成 Agent 完成组装；质检 Agent 独立技术检查、创意初审并驱动返工；编导承担制作方案责任 | 本次 MVP 最终人工创意验收，可由有权限的内部业务审核员完成 | 首次最终验收或品牌判断争议；普通技术失败先自行修复 |
| D 发布与指标 | 发布 Agent 在批准的账号、平台、数量、期限与内容限制内执行，恢复原 attempt；数据 Agent 采集指标并复盘 | 授权账号、公开发布范围、可见性和推广预算 | 未获发布授权、扩大发布范围或增加推广支出 |
| E 基础设施 | 运维 Agent 诊断、准备修复、执行本地测试和已授权只读核验 | 有权限的管理员批准部署、迁移、生产恢复及其他生产变更 | 需要生产变更授权或管理员访问权限，不让普通客户决定技术方案 |

编导是制作决策负责人，经营 Agent 是业务范围负责人；专业执行 Agent 和独立门禁不得因负责人批准而绕过事实、权利、预算、幂等或发布条件。Agent 不能自行创造授权、事实或平台审批。

### 11.2 一次授权与例外处理

- 将授权保存在可追溯记录中：授权人、租户、任务/内容范围、账号、允许动作、预算币种与上限、发布数量、期限、品牌限制、撤销状态及来源。执行前核验授权仍有效；同一范围内不重复询问。
- 制作 Agent 自动查询当前账号价格和可用余额，保存计价依据；无法取得时交管理员处理。不能要求客户承担供应商技术调研，也不能使用猜测价格继续付费。
- 2026-10-11 客户在会话 A 给出的 **¥5** 是本条数字人口播费用上限；不是 B、整条 MVP 或推广预算，也不自动等于公开发布/生产变更授权。主会话记录该边界，区分费用上限与执行授权，不重复询问已确认的金额。
- 在已具备必要执行授权且总费用可控时，Agent 可自主选择预算内方案并留存调用计划。原测试委派明确要求的具体付费前审查，在本轮仍需满足；主会话应统一收束成具体审批，避免 A/B 对同一范围反复请求。后续产品采用范围授权，不将本轮测试审批模式固化为每次客户操作。
- 重试费用计入同一预算，换输入版本或 requestId 不重置预算；unknown 只恢复原任务，禁止通过新提交规避门禁。明确无法保证不重复扣费时，交执行/运维负责人核账。
- 技术故障交执行 Agent；凭据、账户计价和账单交管理员；业务事实冲突交业务负责人；只有客户才能决定的问题才升级客户。问题应说明已核验的证据、剩余冲突、推荐方案和所需决定，尽量一次收束。
- 人工验收不等于客户逐镜点击。当前 MVP 保留最终人工创意验收；未来自动放行必须另有经验证的标准，不能由 Agent 自填 humanConfirmed 或伪造审核人。

## 12. 按新边界重新规划并执行 MVP 测试

### 12.1 主会话先统一输入和授权

现有报告中 A 候选项目为 `studio_projects_b251759707fa43a499a5dc48f070843f`、产品 `GUIANFA-RS-001`；B 候选项目为 `studio_projects_1f987e702c8e4e4e8b40e6432b80ae32`、产品 `GUIANFA-RS-014`。A 还存在护肤品产品与“宏昱智能光学照明”账号标签的冲突。主会话应安排经营 Agent 从权威业务记录排查并选定唯一 MVP，不能让客户协调子会话，不能将两套候选直接拼接，也不能凭共用参考认定同任务。

### 12.3 补充人机边界测试

除第 5–6 节真实链路外，必须验证以下行为并留存决策记录：

- 同一有效授权范围内，供应商/模型/人物/音色/提示词选择由对应 Agent 决定，不产生重复客户审批；内部编导批准不能被记作客户授权。
- A/B 输入、产品、任务或版本不一致时，先由经营/编导 Agent 修复；无法从权威记录解冲突才升级业务负责人，禁止自动拼接。
- 超预算、授权过期/撤销、跨账号或新增用途时拦截动作；客户已给的 A ¥5 上限不能被 B 消耗或因返工重置。
- 查询失败、unknown、下载失败及局部返工走原任务恢复；确认已通过的镜头不再生成，真实费用与预占分别显示。
- 普通技术故障自动修复或交内部负责人；缺事实/权利不能由生成模型补造；人工质量验收不能被自动化冒签。
- 发布与生产变更权限独立；制作授权不自动允许发布，发布授权不自动允许部署。范围发布授权已有效时不重复索要同一权限。
