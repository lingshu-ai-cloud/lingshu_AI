# 灵感大屏竞品调研：发现、理解、二创、生产与效果迭代

调研日期：2026-09-23。用途：为后续产品讨论提供证据，不是已确认 PRD，也不代表相关能力已经实现。

本轮覆盖腾讯妙思、TikTok Creative Center／Symphony、Foreplay、Topview、BigSpy、飞瓜、Brandwatch Listen。妙思做了未登录状态下的实际浏览，其余主要核对厂商公开帮助文档与产品页面；未购买套餐、接入账号或执行付费生成。

证据分级：**实测**为本轮浏览器可见界面；**官方文档**为厂商披露；**二手资料**用于补充历史变化；**研究判断**是对灵枢的启示，不等同于竞品内部实现。

## 1. 本轮修正的产品前提

用户明确要求：生产页面既支持 Agent 编排，也支持完整的人工浏览和页面操作。人工不能只有查看状态、审批和处理异常的权限；应能主动发现、组织参考、发起分析、选择产品、编辑方案并推进制作。

用户进一步明确：灵感大屏与灵感页属于同类产品，都为人和 AI 创作提供灵感、跑量案例及可以二创的素材。因此本报告的主体是完整创作链路；采集机制只是其中一项基础能力，不能把灵感大屏收窄为爬虫控制台。

对标主线为：**发现跑量内容 → 理解有效表达 → 收藏和组织 → 选择二创方式 → 编辑脚本／素材／分镜 → 生成和批量衍生 → 交付与效果回流。**

### 1.1 综合比较：应该分别向谁借鉴

| 研究环节 | 重点竞品 | 已有证据中的具体能力 | 对灵枢的研究判断 |
| --- | --- | --- | --- |
| 灵感发现与分类 | 妙思、TikTok、BigSpy、飞瓜 | 案例榜单、创意标签、脚本公式、行业与题材检索 | 人可以随意浏览，AI 也可以按任务检索 |
| 理解为什么值得参考 | 妙思、TikTok、Foreplay | 内容标签、逐秒表现、主题及版本比较 | 给出可用证据和复用方向，避免只写长摘要 |
| 灵感组织与协作 | Foreplay | 收藏板、品牌资料、参考附件、创作 Brief | 收藏应能发展成有产品和目标的创作项目 |
| 从案例进入二创 | Topview、妙思 | 可复制案例工程；妙思公开存在爆款裂变／混剪入口 | 二创入口要保留参考上下文并明确下一步输入 |
| 人工与 AI 共同编辑 | Topview、Foreplay、Symphony | 画布编辑、脚本分镜、预览后修改配音音乐等 | 自动生成之后仍能编辑，也能把人工方案交回 AI |
| 多版本生产 | Foreplay、Symphony、Topview | 钩子／CTA 版本、现有资产 remix、语言和形式适配 | 区分创意变化与平台适配，保留版本关系 |
| 效果回到创意 | Foreplay Lens、妙思 | 自有广告表现、主题分析及广告效果维度 | 把结果关联到实际使用的参考、结构和版本 |
| 内容供给与更新 | Brandwatch、Foreplay、BigSpy | 持续监测、来源管理、观察时间 | 服务上面各步，不代替灵感产品本身 |

来源和能力边界见下文各产品章节。这个表不表示每个平台都已被本轮端到端实测，也不表示它们具有相同的产能或效果。

此前提出的“持续跟踪／本周专项／探索”等划分只是设计设想，未经过竞品或数据验证。本轮不为它们分配固定比例、爬取数量和刷新周期。

调研首先区分四件事：

| 层次 | 所解决的问题 | 不能据此推断什么 |
| --- | --- | --- |
| 数据接入 | 数据从平台内部、授权 API、公开来源还是用户收藏进入 | 有搜索框不代表搜索时实时爬网 |
| 持续监测 | 哪些账号、主题或广告需要保持更新 | 产品宣传“全天跟踪”不等于披露精确抓取周期 |
| 内容理解 | 如何识别品牌、产品、场景、钩子、脚本结构 | AI 标签不等于真实受众或效果事实 |
| 前台检索与推荐 | 如何让用户找到已有内容 | 筛选维度、榜单时间窗口不等于采集触发条件 |

## 3. 腾讯妙思：实际页面与历史资料分开看

### 3.1 本轮实测的页面结构

当前主导航包含首页、灵感、资产、画布、图片、视频、数字人、全部。灵感内部有四个标签页：

| 标签页 | 本轮看到的组织方式 |
| --- | --- |
| AI 灵感 | 图片／视频切换、搜索、推荐排序、收藏；更多内容要求登录 |
| 创意榜单 | 视频号、朋友圈九图、视频、图片、游戏试玩；公共卡片显示综合得分及视频时长 |
| 标签榜单 | 视频／图片；行业／类目维度切换；开场钩子、制作形式、场景背景；年龄、性别与时间条件 |
| 脚本榜单 | 脚本公式、总曝光量、点击率、视频预览；时间与曝光排序 |

标签榜单的列包含排名、创意标签、核心人群、曝光量、点击率、点击转化率、3 秒完播率和素材预览。未登录时没有取得完整行业／商品类目枚举，不应自行补齐其分类树。[实测入口](https://admuse.qq.com/#/idea)、[标签榜单](https://admuse.qq.com/?ideatab=tag#/idea)、[脚本榜单](https://admuse.qq.com/?ideatab=script#/idea)。

这表明妙思把用户研究对象拆成了三个层次：一条创意、跨创意的内容元素、一种脚本公式。它们适合不同研究起点；不能把所有层次压进单一视频瀑布流。

### 3.2 实测的视频详情动线

本轮从创意榜单的视频卡片进入了公开视频详情。布局为左侧播放器、右侧分析，具有返回、收藏与分享入口。右侧包括：

- 核心数据：曝光、点击与转化相关指标、3 秒完播率、平均播放时长，部分指标以区间或行业分位呈现。
- 人群分析：性别与年龄特征。
- 创意标签：开场／结尾钩子、制作形式、内容情绪、场景背景、背景风格，以及适用场景、营销属性和适用人群。

页面将“人群分析”和创意内容中的“适用人群”分开，这是重要的数据语义区别：前者是页面呈现的受众分析，后者是对表达对象的内容标签。不能把 AI 推断的适用人群标成真实观看人群。[本轮实测案例](https://admuse.qq.com/#/idea/detail/video/137513464422)。

本次案例没有验证“制作相似”的完整执行过程，因此不能声称当前所有案例都支持一键生产。

补充实测：首页公开展示“爆款裂变”和“爆款混剪”。点击“爆款裂变”后弹出登录要求，因此本轮确认到了入口及访问边界，没有确认登录后的工程编辑与批量生成细节。[妙思首页](https://admuse.qq.com/#/index)。

### 3.3 分析到制作的证据

腾讯广告 2024 年官方培训材料展示了灵感、生成、二次编辑、素材库和投放之间的连接，可证明其产品链路方向，不能替代当前页面验收。[腾讯广告官方培训 PDF](https://training.tencentads.com/uploads/202409/ABjmxInf_A1pYpq.pdf)。

2025 年代理商操作说明记载了行业与版位筛选、结构时间戳解析、视频互动分析，以及把参考结构带入混剪脚本的流程。这是**二手历史资料**；适用行业和具体入口可能已经变化。[代理商操作说明](https://www.teng-ad.com/jd/3281.html)。

### 3.4 后台采集：能确认与不能确认的部分

可以确认：页面使用腾讯广告投放版位、曝光、点击、转化与完播等业务维度组织内容。

研究判断：对灵枢而言，它更适合被理解为“广告数据与创意理解相连接”的参照。现有证据不足以证明它通过公开网络爬虫取得这些数据。

本轮未查到妙思公开披露以下内容：外部平台覆盖、爬虫种子、账号抓取配额、抓取频率、增量游标、重试策略、视频去重算法、综合得分公式、分析队列优先级。前台“近 7 天”筛选和综合得分，不能用于反推这些机制。

## 4. TikTok Creative Center：可解释的发现与分析

Top Ads 的前台流程是搜索／筛选、预览、收藏至 Collection、进入 Analytics，再查看逐秒相对表现。可用条件包括地区、行业、广告目标、时间、语言和格式；官方说明桌面端支持更丰富的排序项。[官方操作指南](https://ads.tiktok.com/help/article/how-to-use-the-top-ads-dashboard?lang=en)。

其数据来源有明确证据：Top Ads 是满足表现条件并经广告主授权的真实广告。逐秒图采用相对指数，不能当作该秒的原始点击次数。[官方 Top Ads 说明](https://ads.tiktok.com/business/library/NA_Creative_Center_Top_Ads_One_Pager.pdf)。授权文档也说明入选素材已用于广告活动，展示授权不等于向浏览者提供下载权限。[官方素材授权说明](https://ads.tiktok.com/resources/help/article/asset-authorization-top-ads?lang=nl-NL)。

2026 年 7 月的官方 Creative Center 说明把灵感、趋势和创作工具分开，并列出 Symphony 创作与自动化能力；这只能证明产品模块关联，不能证明任意 Top Ad 都能无缝自动变成成片。[当前官方概览](https://ads.tiktok.com/resources/help/article/creative-center)。

**对灵枢的启示：**列表负责发现，详情负责理解，收藏负责稍后继续。逐秒曲线只有取得相应数据时才能展示，不能用 AI 对画面精彩程度的判断代替观看行为数据。

### 4.1 补充：Symphony 如何承接实际二创

官方介绍的 Generate & Remix 动线是：输入产品／品牌信息或链接 → 设置视频要求 → 生成多个预览 → 选择一个继续编辑 → 调整脚本、数字人、音乐及其他资产 → 下载或送到 Ads Manager。还支持对已有视频换钩子、音乐，或翻译配音生成不同版本。[官方流程说明](https://ads.tiktok.com/business/library/Symphony_Creative_Studio_OnePager_External.pdf)。

这提供了“先生成候选、人工挑选、继续编辑”的完整链路参考。它既支持从产品开始，也支持已有素材再创作，并不要求用户先理解分析报告。此处没有证据证明任意 Top Ads 案例都能直接作为其可编辑源工程。

## 5. Foreplay：最接近人工与 Agent 共用的工作流

官方将能力拆成 Discovery 搜索、Swipe File 收藏组织、Spyder 竞品跟踪、Briefs 创作方案和 Lens 自有创意分析。[官方帮助中心](https://help.foreplay.co/)。

### 5.1 分类与人工动线

筛选包括收藏板、品牌、格式、平台、语言、在投状态和细分领域；Discovery 还区分内容风格与 B2B／B2C。排序包含新旧与投放时长。[官方筛选说明](https://help.foreplay.co/help/articles/6557654-filters-and-sorting)。

人工可以从 Discovery 打开品牌，再直接加入 Spyder 跟踪；也可以搜索品牌或粘贴 Facebook Ad Library 品牌链接，并选择文件夹。厂商称新增手动跟踪品牌后，当前活跃广告通常需 5–10 分钟载入；这不是以后每次刷新的周期承诺。[官方跟踪流程](https://help.foreplay.co/help/articles/1041267-track-competitor-with-spyder)。

Briefs 支持脚本与分镜；厂商的产品更新记录展示卡片、表格、脚本三种分镜编辑视图。说明“可生产方案”也可以有面向人工的可编辑界面。[官方分镜编辑说明](https://www.foreplay.co/post/october-001)。

### 5.2 数据与 Agent 的连接

Discovery 存在用户保存的社区广告来源；Spyder 则承担指定品牌的持续广告跟踪，二者不应混同为统一的全网爬取。官方 MCP 文档说明 AI 可以访问广告创意、文案、CTA、落地页、转录、状态、投放时长，以及用户自己的收藏板；连接 Lens 后还可访问相应自有广告数据。[MCP 官方说明](https://help.foreplay.co/articles/0009441-what-is-the-foreplay-mcp)。

**对灵枢的启示：**人通过列表、收藏板、编辑器工作，Agent 通过结构化接口使用同一批对象。这是产品架构上的借鉴，并非本轮已经验证两者使用完全相同的内部数据库或权限实现。

### 5.3 对“爆款判断”的提醒

Spyder 的 Creative Tests 按上线日期组织广告并观察在投状态；官方说明，当一组中仅剩一条活跃广告时，会打上 Winner Identified 标记。这是明确的启发式判定，不能替代真实 ROI 或因果实验。[官方判定说明](https://help.foreplay.co/articles/6786319-competitor-creative-tests)。

灵枢可以展示“持续投放／疑似保留版本”，但不应仅凭同类信号宣称转化最优。

### 5.4 补充：从灵感到生产交付与效果回流

Briefs 官方产品页进一步披露：可以附加竞品或自有参考、复用品牌资料、生成脚本和分镜、按钩子与 CTA 建立版本，设定截止时间，并收集创作者提交的资产。这让参考、生产要求和素材交付处于同一个工作对象中。[Briefs 官方产品页](https://www.foreplay.co/briefs)。

Lens 的重点则是创意测试、分组比较和趋势，支持自动内容标签与人工标记；它用于观察哪些主题或钩子值得继续使用。[Lens 官方产品页](https://www.foreplay.co/lens-creative-analytics)。

可借鉴之处是“参考 → 方案 → 交付 → 结果”的对象关联。Foreplay Briefs 主要服务制作前的方案与协作，本轮没有证据把它描述为全自动成片渲染系统。

## 5A. Topview：灵感案例可以直接成为创作起点

官方案例页展示成品视频、参考输入、提示词和查看画布入口。“Use this case”的公开流程说明为：查看案例 → 登录后复制案例工程 → 在自己的 Canvas 中修改场景、资产或模型。[官方案例：Clone Viral Product Ad](https://www.topview.ai/featured-cases/clone-viral-product-ad)。

它值得借鉴的是“看完一个案例就能继续做”的衔接方式。灵感的交付对象不仅可以是视频链接，也可以是包含输入和结构的可编辑工程。

Topview 的另一官方页面将使用方式分为即时生成、引导式调整和参考克隆，输入可以是产品链接、图片、文字或参考视频。[官方产品说明](https://www.topview.ai/ai-short-video-generator)。本轮没有执行生成，不采信其模板数量、生成耗时和爆款成功率等营销数字为已验证结论。

**对灵枢的启示：**二创可以有多种承接方式：参考结构重写、替换产品重新生成、复用模板工程、使用可用片段混剪、从已有作品衍生版本。用户选择的是创作目的，具体技术可以由内容 Agent 配置；同时给人工保留编辑入口。

## 6. BigSpy：分类、时间口径与去重

2026 年 7 月官方指南区分电商、游戏和工具三个行业入口，行业变化会影响细分类目与筛选项。支持广告信息、特征描述和视觉搜索，以及保存筛选。去重也有广告、相似创意、广告主三种粒度。[官方广告库指南](https://bigspy.com/tutorial/ad-library-user-guide)。

这份指南明确区分首次发现、最近观察、持续投放与新广告；曝光排序使用估算值。它为“榜单究竟按什么时间、什么数据排序”提供了比单一热度分更清楚的产品表达。具体抓取架构与估算公式没有在该指南公开。

广告主页面另有账号创建时间、投放活动时间、地区、近期广告量和趋势，并可进入广告主详情。[官方广告主页面指南](https://bigspy.com/tutorial/ad-pages-user-guide)。

**对灵枢的启示：**产品行业与视频表达形式应分开；同一创意被多账号、平台或广告重复使用时，可以聚合展示，但要保留各来源记录。保存筛选本身不等于建立持续采集任务。

## 7. 飞瓜：补足自然内容、达人与商业关系

广告库不能完全代表自然内容运营，因此补充飞瓜作为对标。其抖音版官方帮助页区分热门视频、带货视频和种草视频，支持达人行业、带货品类、商品和品牌等筛选，并披露通过口播、文案及购物车中的品牌提及识别种草视频。[抖音视频库官方说明](https://dy3.feigua.cn/help/detail/17/36.html)。

快手版帮助页展示另一条人工路径：按热词、账号类别、互动、时长、商品关联及观众画像检索，随后播放、收藏或进入指数与观众分析；热词还可继续进入相关视频。[快手热门素材官方说明](https://ks.feigua.cn/help/detail/1101/9.html)、[官方操作流程](https://ks.feigua.cn/help/detail/1101/12.html)。

以上是各版本公开文档中的功能；本轮没有登录验证完整覆盖。文档中的“近 6 小时”是内容筛选窗口，不能写成“每 6 小时抓取一次”；也不能把厂商“全网”宣传词当作可验证的全量覆盖。

**对灵枢的启示：**需要同时保存内容题材、账号属性和商品／品牌关系。跨行业借鉴时，可按开头、演示、对比等表达方式寻找参考，随后再核对产品事实与生产条件，而非只按相同行业找视频。

## 8. Brandwatch Listen：把监测条件与数据来源产品化

### 8.1 人工先验证搜索，再转为持续监测

Listen 支持直接关键词、引导式条件与布尔查询。用户先通过 Quick Search 看样本、调整包含与排除条件，再保存搜索，填写名称、团队、开始日期和内容源。这套流程降低了错误条件长期运行的风险。[官方创建与保存搜索指南](https://social-media-management-help.brandwatch.com/en/articles/12767965-creating-and-saving-searches)。

保存搜索后，可分别设置新增内容摘要或提及量增长提醒。**通知频率是通知配置，不能当作采集频率。**[官方提醒说明](https://social-media-management-help.brandwatch.com/en/articles/12767967-creating-and-managing-listen-email-alerts)。

### 8.2 能核实到实际数据接入限制

官方内容源文档区分自有账号、非自有账号和标签，并展示名称、归属、跟踪起始时间与状态。授权后可采集什么，因来源而异。例如其 LinkedIn 数据来自 API，仅支持具备相应管理员授权的公司主页，文档写明约每两小时更新；TikTok 相关数据又有单独的对象与数量范围。以上周期只适用于文档指定来源，不能推广到其他平台。[官方内容源文档](https://social-media-management-help.brandwatch.com/en/articles/12767962-tracking-content-sources-in-listen)。

文档对历史回填存在口径差异：当前专项内容源页列出多种来源的历史范围与例外，而 FAQ 仍保留“仅保证添加后数据”的较保守说法。因此本报告不采用统一历史年限，接入时应逐源验证。[官方 FAQ](https://social-media-management-help.brandwatch.com/en/articles/12767989-faq-listen)。

**对灵枢的启示：**先有“数据源能力表”，再生成采集策略；不能先承诺全平台、全历史、实时更新，再要求工程补齐。

## 10. 对灵枢的讨论建议：以创作任务串联页面

以下均为**研究建议，待产品讨论**。

### 10.0 灵感大屏在整体系统中的边界

灵感大屏只维护一种核心对象：**灵感条目**。条目可以来自外部跑量内容、人工上传的参考或企业自己的优秀作品。视频、图片、脚本和模板是内容形态或来源属性，不在灵感大屏中被设计成多套独立生产资源。

每条灵感只需要承载三层信息：

| 层次 | 页面内容 | 用途 |
| --- | --- | --- |
| 原始内容 | 视频／图片预览、来源、作者、平台与可用权限 | 让人和 AI 知道参考对象是什么 |
| 灵感解读 | 表现依据、内容标签、钩子、结构和适用方向 | 帮助浏览、搜索、比较和借鉴 |
| 使用关系 | 收藏状态、所属灵感集、关联任务、是否已经使用 | 让灵感可以进入后续生产并能追溯 |

脚本公式、分镜拆解和片段提示都是灵感条目的分析结果。用户决定使用一条灵感后，系统只把参考 ID、分析版本、允许的使用方式和用户备注交给编导 Agent。导演方案、素材匹配、具体分镜、版本实验和成片生产由后续生产页面负责。

因此，灵感大屏提供“查看详情、收藏／整理、加入任务、开始借鉴”这几个核心动作即可。版权或授权允许直接使用的内容，可以标注为“允许使用素材”；其他内容默认作为表达参考。页面不承担复杂的画布编辑、批量生产、素材交付和效果实验管理。

### 10.1 分类至少要区分这些语义

| 维度 | 示例 | 对标依据 |
| --- | --- | --- |
| 产品与业务 | 行业、商品类目、产品、B2B／B2C | 妙思、BigSpy、Foreplay |
| 来源与形态 | 平台、广告／自然内容、版位、视频／图片 | TikTok、妙思、飞瓜 |
| 内容表达 | 开场钩子、演示方式、场景、情绪、脚本结构 | 妙思、Foreplay |
| 账号与关系 | 自有／非自有、品牌关联、商品关联 | Brandwatch、飞瓜 |
| 市场与人群 | 地区、语言、实际受众、推断适用人群 | TikTok、妙思 |
| 时间与证据 | 发布时间、首次发现、最近更新、原始／估算指标 | BigSpy、Brandwatch |
| 工作状态 | 已收藏、待分析、已加入选题、已用于生产 | 灵枢自身流程需要 |

可以支持“制造业产品寻找其他行业的演示结构”，但不能把参考中的品牌事实、人物表现和广告效果直接迁移到制造业任务。完整枚举和跨平台映射需另行定稿。

### 10.2 人工至少需要四条完整动线

| 场景 | 页面内动线 | 要保存的上下文 |
| --- | --- | --- |
| 随便找灵感 | 浏览／搜索 → 筛选 → 预览 → 详情 → 收藏到项目 → 返回继续浏览 | 搜索词、筛选、滚动位置、收藏归属 |
| 带着任务找参考 | 选择现有任务或产品 → 找参考 → 选择可用结构 → 创建／编辑导演方案 → 送入制作 | 产品、任务、参考 ID 与版本、用户选择 |
| 持续研究竞品 | 视频进入账号 → 查看历史内容 → 选择跟踪范围 → 预览样本 → 保存监测 → 查看新增与异常 | 数据源、账号、条件、覆盖与更新时间 |
| 从成果继续迭代 | 打开成片 → 回看参考与方案 → 查看可用结果数据 → 建立新版本 → 修订并制作 | 成片、方案、实验差异、已有资产 |

此外应支持一条轻量的跨页面二创路径：**浏览灵感 → 查看解读 → 点击开始借鉴 → 选择现有任务或新建任务 → 携带参考进入编导生产页面。**脚本、分镜、替换素材、样片和衍生版本都在生产页面继续处理。返回灵感大屏时，原来的搜索条件和浏览位置应被保留。

未绑定周任务的用户也应能开始研究或创建临时任务。遇到空结果、分析失败、来源失效、素材缺口或预算不足时，应提供返回、修改条件、替换参考、补资料、重试或保存稍后继续的动作，不能只显示 Agent 日志。

### 10.3 人工与 Agent 操作同一套生产对象

人工在页面创建的收藏、监测和导演方案，应能交给 Agent 继续；Agent 生成的选题与方案，也应能由人工打开、编辑和接管。需要明确当前执行者、版本、修改记录及下一步动作。人工修改执行中的方案时，应标记受影响内容，避免后台沿旧版本继续生产。

这不是照搬某个竞品的实现，而是结合用户要求与 Foreplay 的页面／接口共存方式提出的产品原则。

### 10.4 下一步讨论应先明确的三个问题

1. 首屏如何让用户快速找到合适的灵感条目，并在详情中理解它为什么值得参考？
2. 从“开始借鉴”进入编导生产页面时，最少需要携带哪些分析和用户选择，才能避免用户重新填写？
3. 如何将作品、变体和效果回流到灵感与公式，再由实际内容需求决定供给范围和采集策略？

本轮仅新增调研文档；没有修改产品代码、既有共识或部署环境。
