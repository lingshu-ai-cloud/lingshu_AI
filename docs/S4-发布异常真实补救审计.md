# S4 发布异常真实补救审计

## 原技术栈与缺口

PRD Z-S4/H-S4 要求经营核对原账号、审批、版本及平台结果；未知结果先对账。原 `weeklyPublicationAdapter` 已复用持久 `social_publication_assignments` 与 `social_publication_attempts`：attempt 先存后 effect，unknown/in_flight 仅状态查询；failed 被永久阻断。缺少指定真人、截止、持久任务与原任务恢复入口。legacy `receiptRecovery` 属于 posts/YouTube 路径，不能取代本周 assignment/attempt 的母版、变体和验收血缘。

## 本轮已接闭环

`weeklyPublicationRecovery` 读取真实周包与唯一 publishing 任务、派单、发布包、生产验收产物、账号与原 attempt。创建任务冻结 publication/task 输入 SHA、母版/变体身份、派单与 manifest 哈希、账号身份、原 attempt/provider/开始时间；指定实际同租户经营角色真人和明确时区截止。

显式恢复动作只调用官方适配器的 reconcile，不调用 publish。账号、输入、原 receipt、源版本或审批不符不能核销。无 receipt 保留 identity gap，不能通过用户输入 post ID/receipt 成功。对账成功后，经过原 scope 结果 validator 才精确清除发布类 own blocker；独立安全/人工阻断保留。任务领取与修订使用同周持久 gate，恢复记录另有持久 lease 与版本检查。

恢复回包为 `resume_requested`，不是完成。原 worker 后续读取已 published 的同一 attempt，才正常结算原任务；动态 completionProof 要求原任务 succeeded、零阻断、原真实 actualStartedAt/actualFinishedAt，完成时间不早于原 attempt 开始及回执落盘时间，且不在服务器未来。resumedAt、verifiedAt 都不冒充完成时间。截止不因重试或逾期重置。

真实存储测试复用生产验收文件、验收记录、官方派单/manifest 构建与 persist-before-effect attempt；供应商端口受控，不进行真实发布。覆盖 0 新发布、scope/账号/母版/变体/receipt 漂移、独立阻断保留、无身份拒绝和完成时间核验。

## 明确保留的缺口

- failed 的安全重试尚未实现：不能删除原失败 attempt 或改成 unknown 让原 POST 再跑。
- 未开始发布、缺完整验收/派单的权限与审批缺口，不由本轮“原 attempt”恢复任务冒充处理完成。
- 无 provider receipt 的未知请求仍不能核销。需要平台提供可与原 attempt 精确匹配的可信查询证据。
- YouTube 原账号记录没有统一持久 channel ID；本轮保守冻结实际账号/客户端和 refresh-credential hash，凭据更换需重新处理，不能当同一原账号成功。
- 被修订冻结、撤回或停用的周包不能藉由恢复入口重新领取原任务；真实平台状态可保留，对后续版本的承接另走既有版本协议。

新增 migration 2040 只保存源码与 checksum，未执行数据库迁移；未部署或推送。
