# 连贯口播第三轮修订

本轮继续修改产品脚本生成逻辑。目标是让讲述像一个熟悉产品的人，帮买家想清楚一个具体选择，同时保留原有脚本、字幕、时长和素材/对标接口。

## 当前保留的实现

1. 先选事实，再创作全文。第一步只选择一项原始事实，不生成技术解释、预设答案或初稿，以免错误推论成为后续写作的前提。
2. 写稿步骤只接收本条事实的原始完整分句，不再次灌入整行其他卖点。原文中有跨分句适用条件时保留整行；多产品输入保留事实归属，口播称呼对应事实所属产品。
3. 先写完整口播，再由程序在句号、问号、逗号等停顿处组合分镜。分段不改字，不强行凑四句；没有足够自然切点时减少镜头数量，画面数量同步调整。旧 `lines` 解析仍兼容。
4. 创作要求集中在一个买家问题、具体细节、解释承接和自然收尾；观看稿不默认增加私信，询盘稿承接已有行动意图。只有原文明确提供的英文型号前缀才用作短称，不编造中文简称。
5. 新版优先选择旧口播没有直接提到的事实，识别“与、和、及、and”等并列写法；这是选题提示，不保证语义上的完全去重。可用事实已用完时重新使用原始范围。
6. 时长以实际生成文字预估。超长最多一次缩写，仍超长则明确返回失败，不静默拉长到目标时长以外。估算不等于 TTS 测量。

曾试验将事实通过占位符机械插入口播，但破坏语法且不能防止周围文字继续推论，已撤回。当前没有事实占位符插句，也没有人工成稿作为模型返回的后备结果。

## 模型与兼容性

默认仍为 Qwen；没有修改既有 Key、全局模型默认值或部署环境。新增服务端显式开关 `STUDIO_SCRIPT_BACKEND=gemini` 仅用于产品模式对照；素材与对标仍走原有实现。该开关当前没有启用，也没有作为质量修复方案验收。

本地预览支持 `PREVIEW_QWEN_MODEL`、`PREVIEW_QWEN_THINKING` 和 `PREVIEW_SCRIPT_BACKEND`，不会写入配置文件。预览记录输入、原始返回、请求提示词、状态与耗时；不记录 Key、请求头或模型内部思考内容。发生传输超时也保存失败版本，再继续剩余案例。预览不启动业务 worker、不写业务数据库、不发布内容。

## 验证与实际限制

已执行脚本路由回归、27种模式/主题组合、TypeScript 检查，以及数字员工内容生产与前端工作流/脚本清理回归。新增覆盖：分段文字完整保留、中英文及其他语言的标点分段、短稿减少镜头、原文适用条件、多产品事实归属、并列卖点排重、错误结构返回、无口播对标和超长处理。

真实测试始终使用 LX-Press 演示资料；并非真实客户资质证明。最终对比改为同一产品、同一受众、全部30秒，两版询盘稿、一版观看稿。详见 `reports/script-creative-preview-2026-09-05/natural-round3-review.md`。

代码回归通过不能证明口播质量合格。多轮 Qwen 原始返回仍出现自动识别、接口/协议要求、未提供的绑定关系和服务承诺；默认引擎尚未证明可以稳定生成可交付口播。Qwen 不同型号/思考设置的本地对照未解决此问题；一次较慢的模型对照超过预览时限。Gemini 对照三次均返回429，原因是上游预付额度耗尽，无法比较其生成效果。

本轮没有 TTS 音频试读、实际投放、提交、推送或部署。需要继续验证生成模型的事实遵循与真实口语效果，不能据此声称“爆款质量已提升”或将自动通过状态视为内容验收。
