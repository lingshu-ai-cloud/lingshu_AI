# 数字人第一版验收报告

验收日期：2026-09-01
范围：企业人物资产、逐分镜数字人口播、本地 GPU 推理、质量门禁、服务器回流与 9:16 成片导出。

## 验收结论

第一版端到端链路已跑通。客户在网页选择数字人口播后，服务器创建租户隔离任务；本地 GPU Worker 可使用直连模式或主动拉取模式完成 MuseTalk v1.5 推理、质量检测和结果回传。只有通过商业质量门禁的结果会写回素材库并进入分镜与成片。

## 实测输入与合法性边界

- 人物来源：Codex 任务 `01a03d99-37ba-79f1-9ea4-4d2d31ff5aee` 中的项目内部测试素材。
- 已生成口播视频仅保存为 `generated_clip` 来源记录，不允许再次作为人物母片，避免二次口型叠加。
- 实际生成改用同一任务的原始人物母片，标记 `avatar_master / internal_test`。
- 本次素材只证明项目内部本地测试授权，不自动推定为公开商用授权；正式客户必须上传自有或明确取得商业授权的母片。

- 模型：MuseTalk v1.5，本地 NVIDIA GPU。
- 分辨率：1080×1920，9:16。
- 编码：H.264 High + AAC LC。
- 帧率：25 fps。
- 时长：6.016 秒，音画时长差 0。
- SyncNet 置信度：4.310（MuseTalk 高质量校准门槛 4.0）。
- 音画偏移：1 帧。
- 人脸检测率：100%。
- 嘴部帧间跳变 P95：0.0727（门槛 0.085）。
- 冻结异常：0。
- 输出：`output/数字人第一版_高质量竖屏成片.mp4`。

## 纠偏记录

1. 直接把已生成口播视频再次作为母片时，嘴部跳变升至 0.0939，质量门禁拒绝回流。
2. 改用原始人物母片后，嘴部跳变降至 0.0776；由 SyncNet 接管音画同步硬门禁，移除不可靠的能量包络重复拦截。
3. 商业门禁按模型族校准：MuseTalk 质量模式要求 SyncNet ≥4.0，LatentSync 类模型仍保留 ≥7.0；不使用统一但失真的阈值。
4. 16:9 测试母片通过暗化同源背景合成为 9:16。最终可交付，但理想商用效果仍应从原生 9:16、胸部以上中近景母片开始。
5. 第三次推理遇到显存不足；确认无活动推理进程后重试成功，没有关闭其他 Codex 任务或用户应用。

## 生产部署架构（本次未部署）

- 推荐启用 `DIGITAL_HUMAN_PULL_WORKER_ENABLED=true`。
- 服务器保留客户任务和素材权限，本地 Worker 只用独立密钥主动领取单条租约任务。
- Worker 下载短期签名输入，生成后上传 MP4 与真实质量报告。
- 服务器再次执行商业门禁后写入租户素材库。
- 本地机器无需公网入站端口，客户凭据不会下发到 Worker。

本地已实测：创建排队任务 → Worker 密钥领取 → 进度上报 → 合格 MP4 回传 → 服务器门禁 → 租户素材回流，状态最终为 `completed`。

## 距离理想质量仍有的差距

- 当前指定母片为横屏且人物是库存测试形象，竖屏背景需要补画，构图不如原生竖屏母片自然。
- 当前声音沿用任务原始测试音频，尚未形成企业人物绑定音色和多情绪语音资产。
- MuseTalk 能稳定完成口型替换，但牙齿细节、极端音素和大角度转头仍弱于高质量 LatentSync/商业模型。
- 下一阶段应增加原生 9:16 人物母片预检、人物与音色绑定、身份相似度模型和人工抽检台。
