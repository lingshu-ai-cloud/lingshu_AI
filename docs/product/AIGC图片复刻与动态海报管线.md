# AIGC 图片复刻与动态海报管线

## 产品边界

图片模式嵌入现有内容制作工作台，不增加新的用户页面。用户只经过三个可来回切换、状态不丢失的步骤：

1. 内容与资产：选择企业产品和参考作品；系统自动判断单图、GIF 或轮播图。
2. 生成首版：后台完成参考拆解、图文合同、企业资产绑定和首版生成。
3. 审阅交付：切换生成结果与原对标，播放 GIF/轮播，使用自然语言局部修改并下载。

不支持把产品海报、品牌新闻等题材做成首页模式列表；它们是后台内容合同。轮播或 GIF 超过四个作品单元时，首版默认还原前四个。

## 后台结构合同

爆款复刻不是一次自由生图。后台生成统一的 `SocialImageReplicationRecipe`，记录：

- 原始画布像素与宽高比；
- 背景场景及透视；
- 单品、组合或套组数量、占比和视觉重心；
- 左上角标、底栏、标题区、留白区和安全区；
- 标题、副标题、说明文字的层级、对齐和换行；
- 固定层、动态层及 GIF 动效机制；
- 必须替换的品牌、产品、商业事实和联系方式。

结构合同只在后台使用，不增加前端配置负担。GPT Image 2 负责语义场景和首版视觉，确定性合成负责需要严格保持的产品身份、固定 UI、文字和画布。

## 生产方式

### 单图

- 从原对标读取精确画布；输出必须保持相同像素比例。
- 最多使用一张原对标和两张企业资产作为有序参考。
- 题材由用户输入及企业事实决定，不能从对标图臆造合作新闻。
- 产品包装、瓶盖/泵头、品牌名和主标签是保护区域。

### 轮播图

- 默认生成前四页。
- 第 1 页负责吸引注意，第 2 页解释价值，第 3 页提供证据，第 4 页承接 CTA。
- 每页分别生成，但共享同一帖子级事实、品牌系统和叙事合同。

### GIF

- 参考 GIF 最多抽取前四个代表状态。
- GPT Image 2 只生成变化的背景板；产品、标题、角标、内容模块和底栏由程序固定合成。
- 成片动效是底图切换，不使用单张底图缩放冒充动效。
- 输出循环 GIF，并保持参考画布尺寸。

## 质量与修订

确定性预检负责事实状态、产品绑定和文字容量；多模态质检对照生成结果、企业产品资产和可读取的原对标，检查：

- 产品身份；
- 包装、瓶盖/泵头和标签可见性；
- 主体是否被文字或 UI 遮挡；
- OCR 与企业产品标签一致性；
- 图文、品牌和配色一致性；
- 文字溢出、安全区和参考结构相似度。

没有像素证据的检查只能是 `uncertain`，不能伪造通过；确定性失败不能被视觉模型覆盖。失败项在后台形成局部修复建议，不增加用户步骤。

用户输入自然语言修改后，系统先判断背景、产品、Logo、文字或整体合成目标，保留其他区域和原画布，只对目标层生成新版本。首版与修订均在服务端响应浏览器之前持久化；刷新、关闭或超时后工作台恢复同一任务，不重复发起付费请求。

## 技术栈与运行配置

- 生成：OpenAI `gpt-image-2`，默认 `low`，用户可升级 `medium` 或 `high`。
- 视觉质检：Qwen VL；不可用时质量项保持 `uncertain` 并阻止自动批准。
- 图像处理：Sharp；GIF 编码：FFmpeg。
- 数据：复用 `studio_projects` 保存任务、版本、生成作业、质量证据和修订记录；生成文件进入企业素材库。
- 前端：React + TypeScript + Ant Design，沿用内容制作工作台三栏布局。

部署环境必须安全注入 `OPENAI_API_KEY`；自动视觉质检还需要 `DASHSCOPE_API_KEY` 或本机 Qwen 密钥文件。密钥不得写入仓库、任务记录、日志或浏览器存储。

## 上线门槛

- 图片专项测试、TypeScript 检查和生产构建通过；
- 使用真实 `gpt-image-2` Low 完成一次生成；
- 单图、四页轮播、四状态 GIF 和自然语言修订能够持久化与刷新恢复；
- 所有硬质量项通过后才允许批准；`fail` 或 `uncertain` 不得伪装为可发布；
- 供应商结果未知时禁止自动重复付费请求，只允许读取原任务恢复；
- 远端部署环境配置 OpenAI 与视觉质检凭证并完成健康检查。
