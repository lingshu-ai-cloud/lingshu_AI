# 灵枢社媒视频生成技术栈质量分析

版本：2026-09-27  
范围：仅包含社媒短视频的脚本、素材、编导、内容制作、配音、字幕、动效、渲染和成片质检。  
明确不包含：客服、销售、报价、询盘、客户跟进和其他非视频业务模块。

## 1. 执行结论

本轮修改以后，社媒视频链路已经从“多个 Agent 各自生成结果、渲染阶段再临时推断”提升为“有版本、有哈希、有逐镜来源、有失败门禁的受控生产链”。代码、架构门禁、契约测试和本地真实 FFmpeg 合成测试均已通过。

但目前不能宣称“各环节均达到成熟生产水平”。更准确的判断是：

- 工程稳定性：强 Beta，可进入受控客户试运行。
- Agent 协作和可追溯性：强 Beta，主链路接近生产级，但仍存在新旧两套生产运行时。
- 素材匹配、裁切、动效和口播内容质量：Beta，需要真实供应商和人工金标验收才能提升到成熟级。
- 全自动无人审核交付：暂不建议。正式成片仍应保留用户/编导最终批准门槛。

本轮没有部署、发布或修改生产环境。

## 2. 当前社媒视频技术栈

| 层级 | 当前实现 | 主要职责 |
|---|---|---|
| Agent 契约 | TypeScript 共享合同、DirectorBrief、ContentExecutionPlan、ExecutionPlanReview | 明确编导要求、内容执行方案和逐镜审核 |
| 主生产链 | `server/starter198` | 社媒任务、素材选择、最终锁定、制作、质量检查和产物归档 |
| 兼容生产链 | `server/digitalEmployees/contentProduction.ts` | 历史数字员工视频任务的脚本、素材、配音、渲染和恢复 |
| 素材理解 | Qwen 视觉分析，Gemini 可选路径，FFmpeg 抽帧代理 | 可见事实、镜头区间、动作区间和安全剪口分析 |
| 素材索引 | `MaterialScriptAnalysis v2` | 入库时一次分析，后续按主体、动作、环境、镜头语言和功能复用 |
| 文案生成 | Qwen/视频模型、参考视频结构、抽象口播风格指纹 | 生成受事实边界约束的社媒口播和字幕 |
| 配音 | MiniMax、Qwen TTS，本地能力只作非生产兜底 | 情绪化配音、音色、句级/供应商时间轴 |
| 配音质检 | FFmpeg PCM 检查、Qwen ASR 回听 | 响度、削波、静音、异常长停顿和文本一致度 |
| 动效 | `EffectPlanV1`、确定性意图规则、桌面 FFmpeg 渲染器 | 运镜、色彩、转场、叠加层和音效的白名单执行 |
| 视频渲染 | `desktop/render.cjs`、FFmpeg、Sharp | 画面裁切、变速、字幕、配音、BGM、动效和封面 |
| 成片质检 | 全片抽帧、逐镜检查、音轨解码、重复/空白/模糊检测 | 阻止技术损坏、素材重复和明显不可交付成片 |
| 存储和追踪 | 任务记录、版本集合、文件注册、对象存储/PocketBase 适配 | 保存素材来源、计划版本、哈希、质检报告和最终文件 |

## 3. Agent 协作现状

### 3.1 当前主链路

1. 编导 Agent 生成 `DirectorBrief`：只定义主题、叙事结构、镜头目的、视觉要求、事实边界和验收标准，不直接拥有具体素材选择。
2. 内容 Agent 生成 `ContentExecutionPlan`：选择执行路线、候选能力、预算、供应商和素材策略。
3. 编导 Agent 生成 `ExecutionPlanReview`：逐镜审核可行性、事实、授权、预算、时长和表达目标。
4. 内容 Agent 对实际素材进行视觉分析、语义匹配和裁切选择。
5. 系统生成最终素材选择哈希，记录 `selectedBy=content_agent`、`reviewedBy=director_agent`。
6. 编导 Agent 形成最终不可变执行锁：脚本、口播、字幕、素材区间、BGM、封面、输出规格和动效计划一起进入 lineage hash。
7. 内容 Agent 只能按锁定交接物执行。运行时如果改变交接内容，handoff hash 校验会失败。
8. 成片后保存逐镜 lineage：DirectorBrief scene、ContentExecutionPlan scene、审核结果、最终 scene、assetId 和 clipId 一一关联。

### 3.2 本轮修复的协作问题

- 最终渲染不再临时生成一份未进入交接哈希的动效计划。
- 最终字幕不再只按素材时长比例猜测，而是映射到 TTS 返回的供应商/实测句级时间轴。
- 最终画面节奏与字幕使用同一套语音边界，避免口播已经进入下一句但画面仍停留在上一镜。
- 最终镜头数必须同时与 DirectorBrief、ContentExecutionPlan 和逐镜审核数量一致；否则停止提交。
- 最终产物保存 Agent 协作引用、最终 selection hash、handoff hash、动效计划和声音质检报告。
- 旧计划没有显式 `EffectPlan` 时继续无动效；重新渲染或修订不会静默套用新动效。

### 3.3 仍然存在的协作债务

1. 系统仍有 Starter198 主链路和 DigitalEmployee 兼容链路。两者已经共享素材证据、动效合同、声音质检和部分口播能力，但还不是同一个执行图。
2. `StoredSocialDirectorPlan` 是历史名称。它现在实际代表“内容 Agent 已选择、编导 Agent 已复核的最终执行锁”，名称仍容易让开发者误解为具体素材由编导独立选择。
3. 初始 `ContentExecutionPlan` 主要描述候选路线；真正的 assetId、clipId 和剪口在素材分析后写入最终选择哈希。链路已可追踪，但未来应把这份最终选择升级为独立、版本化的 `ContentExecutionPlan` 修订，而不是继续依附在最终 Director lock 中。
4. 成片后的编导质量判断目前以结构门禁、逐镜数量和独立媒体检测为主，还没有可替代真人审片的视觉语义模型评分。

## 4. 内容质量分析

### 4.1 素材入库分析

本轮结果：可用 Beta。

已具备：

- 视频只在素材进入系统或版本变化时分析一次，制作任务复用结果。
- 索引版本升级为 `material-script-analysis.v2`。
- 保存主体、动作、环境、景别、角度、运镜、构图、运动强度和脚本功能。
- 保存 actionStart/actionPeak/actionEnd、cleanStart/cleanEnd、cleanEntry/cleanExit。
- 事实可信度和剪口可信度已经分离；旧数据缺少剪口证据时 `boundaryConfidence=0`，不会再把事实识别分数误当成安全剪口分数。
- Qwen 视频采样预算从最多 36 帧提高到最多 48 帧，并且短视频按约 2 帧/秒采样。

剩余问题：

- 仍然是抽帧视觉推断，不是逐帧镜头边界检测。
- 没有光流、镜头切换检测、动作骨架或声画联合分析。
- 长视频达到 48 帧上限后，时间精度会下降。
- 没有对素材原声的噪声、音乐、对白和版权可用性做完整分析。

### 4.2 素材召回和匹配

本轮结果：中等 Beta。

已具备：

- Starter 主链路已经使用入库索引，不再只依赖 `visualObservations`。
- 排序同时考虑可见事实、主体、动作、环境、镜头语言、镜头角色、边界可信度、动作完整度、干净进出点、时长和素材置信度。
- 增加了常用中英文视觉概念归一，例如 `open the box` 可以匹配“打开盒盖”。
- 镜头功能标签不会单独作为视觉事实，避免“都是 hook”就错误匹配。
- 设置最低语义分数，弱词碰撞不能直接进入最终选择。
- 同一真实分析镜头切出的多个窗口仍视为同一个 evidence shot，不能虚增素材覆盖率。

剩余问题：

- 当前跨语言能力是受控概念表和字面特征，不是向量召回或跨模态 reranker。
- 没有行业同义词库、型号实体归一和负面约束模型。
- 没有“被人工判定为好/坏匹配”的线上样本回流和离线 NDCG/Recall 基准。
- 用户明确关联素材只能证明允许使用，不能证明画面内容；系统仍会将其标记为低置信度待复核。

### 4.3 素材裁切

本轮结果：中等 Beta。

已具备：

- 只有 `boundaryConfidence >= 0.6` 且 cleanEntry、cleanExit 同时成立时，系统才使用模型给出的安全剪口。
- 动作起止存在时，优先选择可以完整包含动作的窗口，而不是只围绕动作峰值居中。
- 人工或旧计划如果越过高置信安全区间，会被重新匹配门禁拒绝。
- 成片逐镜检测会拦截空白、模糊、无法解码、截断和重复画面，并支持局部镜头修复。

剩余问题：

- 没有逐帧 scene-cut、光流和动作完整度检测，因此不能承诺帧级最佳剪点。
- 成片检查能识别技术性坏镜头，但不能可靠判断“动作是否在最舒服的节奏点结束”。
- 对快速运动、遮挡和复杂多人动作仍需要人工复核。

### 4.4 动效匹配

本轮结果：基础 Beta。

已具备：

- `EffectPlanV1` 是显式、白名单、版本化合同，任意 FFmpeg 表达式不能进入渲染器。
- 动效依据 hook、proof、demonstration、transition、CTA、节奏和技术类主题确定，不再按镜头序号轮换模板。
- 新任务的动效计划在最终交接前生成并进入 lineage hash。
- 旧任务没有动效计划时保持硬切/无动效。
- 真实产品、Logo、人物或文字区域在没有空间掩码时强制保留原色且不加装饰叠层。
- `beatSync=false`，系统没有真实节拍点时不会假装已经卡点。

剩余问题：

- 当前仍是确定性规则，不是理解画面主体和动作轨迹的动效模型。
- 没有人物、商品、Logo 和字幕的像素级 mask；因此保护策略只能保守地关闭部分效果。
- 没有音乐 beat/phrase 检测，不能提供真正的卡点剪辑。
- 没有人工审美评分集，无法证明动效“好看”，只能证明安全、稳定和可复现。

### 4.5 口播文案

本轮结果：中等 Beta。

已具备：

- 参考视频只提取抽象风格：钩子类型、节奏、人称、问句比例、句长、连接方式和 CTA 类型；不保存或复用原句。
- Starter 参考视频链路已经使用抽象口播风格调整开场和句长。
- 租户级风格学习至少需要两个独立样本；单个视频不能直接成为全局风格。
- 有事实时自然表达事实，不反复朗读“已确认资料显示”等审稿话术。
- 没有事实时的兜底文案不再声称画面中存在动作、主体、环境或“真实细节”。
- 无治理公式时不再自动添加“私信、联系我们、把需求发来”等营销 CTA。
- 口播仍需通过语言、长度、事实、自然度和最终复审门禁。

剩余问题：

- 风格样本还没有按行业、平台、产品、受众、语言和实际转化结果分层。
- 没有人工标注的“营销自然度、人物感、可信度、重复度”评分集。
- 没有线上 A/B 结果回流，因此当前学习的是表达模式，不是被证明有效的营销策略。
- 安全兜底比以前真实，但在没有企业事实时只能生成判断方法型内容，营销强度必然受限。

### 4.6 声音和字幕

本轮结果：中上 Beta。

已具备：

- 正式自动成片只接受 MiniMax、Qwen TTS；开发环境可以使用本地音色测试，但不能伪装成正式声音。
- 短社媒脚本优先一次连续合成，减少逐句合成造成的音高和情绪重置。
- FFmpeg 统一执行高通、响度标准化、峰值限制和短尾静音。
- 声音质检检查实际时长、峰值、RMS、削波、静音比例和异常长停顿。
- 正式环境要求 ASR 回听，文本一致度低于 90% 会失败。
- ASR 配置同时支持 `DASHSCOPE_API_KEY` 和 `DASHSCOPE_API_KEY_FILE`。
- TTS 缓存键包含供应商策略版本、供应商可用性和偏好，改变策略后不会误用旧供应商缓存。
- 最终产物保存 provider、alignmentSource 和完整 voice quality report。
- Starter 字幕按 TTS cue 映射到各场景；MiniMax 原生 cue 可直接使用，其他供应商至少使用实测总时长和句级边界。

剩余问题：

- 没有 MOS、母语自然度、情绪符合度、品牌词发音和说话人身份一致性模型。
- Qwen 没有原生词级 cue 时，句内时间仍可能是比例估算。
- 内置 `v1/v2/v3` 在不同供应商下对应不同物理音色；缓存和产物现在可追踪，但还没有跨供应商统一 speaker identity。
- 没有用真实 MiniMax/Qwen 多语言音频建立自动回归集；当前声音单测使用合成 PCM 检查技术门槛。

### 4.7 成片质量门禁

本轮结果：中上 Beta。

已具备：

- 检查 MP4 是否真实存在、大小、时长、视频解码和音轨解码。
- 检查整片亮度、纹理、边缘、清晰帧比例、运动和可区分画面数量。
- 检查逐镜空白、模糊、截断和重复。
- 检查素材语义证据、字幕安全区、字幕时间轴、目标语言和路径差异。
- 质量失败可针对单镜头重新分配素材，不必重做脚本和配音。
- 最终状态仍是 `requires_user_approval`，自动检查不会冒充人工审美确认。

剩余问题：

- 没有完整的画面美学、构图、人物表情、品牌一致性和营销说服力模型。
- 没有对每个转场的黑闪、运动方向连续性和视觉注意力连续性进行专门评分。
- 爆款复刻虽然有独立媒体评估，但缺少检测证据时会保守阻止放行，不能自动证明“爆款效果”。

## 5. PRD 和旧代码兼容性

| 约束 | 当前状态 | 结论 |
|---|---|---|
| 编导不直接承担具体素材执行选择 | 具体素材选择记录为 Content Agent 产出，最终由 Director review 锁定 | 已基本对齐 v4 和《编导Agent实现共识》 |
| 最终交接需要锁定镜头 | 最终 assetId、clipId、时间区间、动效、BGM、字幕和输出规格均进入哈希 | 对齐社媒工作流 PRD 的最终锁定要求 |
| ContentExecutionPlan 必须经编导逐镜审核 | 保存 execution plan/review 引用，镜头数量和 review 结果不一致会停止 | 已对齐 |
| 旧任务不得被自动新增动效 | 缺少显式 EffectPlan 的旧计划持续无动效，修订也不自动启用 | 已修复 |
| 零公式文案不能默认增加 CTA | 无事实兜底已移除私信、联系和发送需求类 CTA | 已修复 |
| 字幕应跟随真实音频 | 使用供应商或实测 TTS cue；无词级 cue 时保留句级比例估算 | 部分成熟 |
| 事实置信度不能代替剪口置信度 | v2 索引严格分离，两者不再回退混用 | 已修复 |

仍需文档治理：旧 PRD 之间对“编导是否锁定具体素材”的描述并不完全一致。当前实现采用的统一解释是：编导先定义意图；内容 Agent 选择具体素材；编导复核后，最终交接物可以锁定具体镜头。建议后续把这一解释写回唯一权威 PRD，并将历史 PRD 标记为 superseded。

## 6. 成熟度评分

评分说明：1=原型，2=可演示，3=受控 Beta，4=成熟生产，5=数据闭环自优化。

| 环节 | 评分 | 判断 |
|---|---:|---|
| Agent 契约和版本追踪 | 3.8/5 | 主链路完整可追溯；双运行时仍需合并 |
| 素材入库分析 | 3.4/5 | 已可复用并保守处理旧数据；非逐帧 |
| 素材匹配 | 3.1/5 | 多字段和中英概念匹配已生效；缺向量 reranker 与金标指标 |
| 素材裁切 | 3.1/5 | 有安全边界和动作完整性偏好；缺帧级算法 |
| 动效匹配 | 2.9/5 | 安全、可复现、可追踪；审美和节拍能力不足 |
| 口播文案 | 3.2/5 | 事实与自然度约束较完整；没有效果数据闭环 |
| 声音生成和质检 | 3.4/5 | 技术门禁较严；缺真实听感、发音和身份一致性评测 |
| 字幕和声画时间轴 | 3.6/5 | 场景已跟随 TTS cue；部分供应商只有句级估算 |
| 成片技术质检 | 3.6/5 | 能阻止多数技术坏片；不能替代人工审美判断 |
| 整体自动生产 | 3.3/5 | 适合受控试运行，不适合取消人工批准后全自动交付 |

- 真实付费 Qwen/MiniMax/外部视频供应商调用。
- 真实客户素材的大规模离线金标评测。
- 真人母语听审、营销转化 A/B 和不同平台实际投放效果评估。
- 生产部署或发布。

## 8. 上线建议和下一阶段

当前建议：可以进入内部和少量客户的受控试运行，但必须保留最终人工批准；不要宣传为“全自动成熟成片”。

提升到成熟生产级至少还需要完成：

1. 合并 Starter198 与 DigitalEmployee 两套社媒视频执行运行时，只保留一个版本化执行图。
2. 把最终具体 asset/clip 选择升级为独立 `ContentExecutionPlan` 修订，并让 Director review 直接审核这一版，而不是只在最终 lock 中绑定。
3. 建立真实素材匹配金标集，加入跨模态 embedding/reranker、负面约束和行业实体归一，给出 Recall@K、NDCG 和错配率。
4. 引入镜头切换、光流和动作边界算法，并增加转场黑闪、动作截断和运动方向连续性检查。
5. 建立真实多语言口播听审集，测量 MOS、自然度、营销感、发音、情绪、音色一致性和字幕偏移。
6. 增加音乐节拍检测和空间 mask 后，再开放 beat sync、商品周边动效和更强色彩风格。
7. 建立人工成片评分与实际发布结果回流；只有样本经过质量和经营结果筛选后，才能进入租户口播风格库。

最终判断：本轮修改已经解决上一轮审计中最明确的代码冲突和协作断点，使系统达到“可追踪、可阻断、可回归、可受控交付”的水平；尚未达到“审美、营销效果和声音听感均可无人监督保证”的成熟水平。

## 9. 后续无训练质量闭环改造

在上述审计之后，系统继续完成了以下改造：

- Starter198 与 DigitalEmployee 统一投影到 `video-production-graph.v1`，使用相同的九阶段状态、阻断和证据结构；业务执行器仍采用渐进迁移，尚未物理删除旧执行器。
- 每个分镜保存前五候选、排序分数、分差、视觉置信度和剪口置信度。候选接近、语义弱、仅产品关联或边界不安全时，成片预览会显示重点复核提示。
- 用户的成片批准/退回会沉淀为明确标注为 `weak_label` 的反馈，不能冒充人工金标，也不会自动训练模型。
- 素材入库增加 FFmpeg 镜头变化和局部运动复核；本地证据不足时会降低而不是抬高剪口置信度。
- BGM 增加本地节拍网格分析；只有高置信节拍才允许最多 120ms 的内部镜头边界微调。
- EffectPlan 增加空间证据合同；真实商品画面只有在 SAM3/人工 mask 稳定度达到 0.85 后才能开放安全区域叠加。
- 增加母语听审和营销实验准入合同；技术音频通过不能直接进入租户风格库。
- 新增只读离线评测命令 `pnpm quality:social-video-eval <evaluation.json>`，用于素材 Recall/NDCG/错配率、声音听审和营销实验评估，不更新任何模型权重。

具体人工投入和测试步骤见《社媒视频质量验证与数据闭环操作手册-2026-09-27》。
