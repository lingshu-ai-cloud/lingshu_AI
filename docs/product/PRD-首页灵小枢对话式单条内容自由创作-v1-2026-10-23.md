# PRD：首页灵小枢对话式单条内容自由创作 v1

> 日期：2026-10-23
>
> 文档落点：本会话工作区
>
> 代码参照：`codex/jimeng-creator-ui-20261023`
>
> 状态：产品与工程优化方案，尚未修改代码
>
> 本期范围：自由创作模式下的单条图片／视频内容，不包含数字员工周任务改造、自动发布或投流

## 1. 本期产品结论

首页是单条内容制作的唯一主操作面。用户在爆款卡片点击“爆款裂变”后，不再跳到灵感中心或内容工作台，而是在首页完成以下闭环：

1. 所选爆款以一条用户消息进入灵小枢对话；
2. 服务端原子地创建或续接一条 `instant + viral_replication` 内容任务；
3. 灵小枢先告诉用户“已识别的信息、采用的默认值、仍需补充的信息”；
4. 非付费的参考分析可以立即开始，缺少硬性信息时只暂停受影响的后续节点；
5. 硬门禁满足后，任务按“参考拆解 → 图片生产 → 视频生产（仅视频成品）→ 验收 → 交付”继续；
6. 对话中始终只有一个权威任务状态卡持续更新，候选图片、候选视频和需要用户处理的决定都回到同一对话；
7. 运行状态来自服务端快照与事件，不由前端根据计时器、请求是否返回或聊天文案猜测。

本期的“调用后端数字员工生产环节”指后台使用固定的专家、Worker、队列和生产图执行任务，不代表把自由创作任务改成周任务。自由创作的任务模式必须是 `instant`。

## 2. 产品目标与边界

### 2.1 产品目标

- 用户从看到爆款到取得可验收成品，不离开首页，不需要理解灵感中心、Studio、执行器或供应商。
- 灵小枢用业务语言解释当前在做什么、为什么等待、还缺什么以及用户下一步能做什么。
- 图片和视频共用同一任务身份、事实版本、参考证据、成本预留、审批与交付记录。
- 爆款拆解只保留最重要的 4–5 个可验证爆点，避免把全部可观察特征都冒充为爆点。
- 刷新、断网、切换设备或重复点击后可以恢复同一任务，不重复生成、不重复扣分。

### 2.2 本期不做

- 不改数字员工模式的周计划入口、周排期和批量生产规则。
- 不自动发布到社媒、不自动投流，也不把成品批准视为发布授权。
- 不在对话里展示模型思维链、Agent 内部推理、供应商名、Prompt、Token、数据库 ID 或执行日志。
- 不为单条内容复制第二套任务、积分、素材或审批系统。
- 本文档不代表相关代码、接口或供应商链路已经完成。

## 3. 入口和任务定义

### 3.1 首页入口

爆款卡片底部主操作固定为“爆款裂变”。点击后前端构造结构化参考对象，最少包含：

```text
referenceId
contentType: image | video
sourceUrl / mediaUrl
thumbnailUrl
title
platform
durationSeconds（视频可选）
analysisVersion / contentHash（已有分析时必传）
```

点击动作的用户可见结果是右侧用户气泡：

> 用这条做爆款裂变
>
> [封面] 标题 · 来源平台 · 图片/视频

气泡提交中显示“正在建立任务”；服务端确认后显示“任务已建立”。如果原子创建失败，气泡显示“未发送成功”，提供“重试”，不得先留下一条成功消息再静默失败。

### 3.2 一个会话、一条任务、一条运行链

- 一次点击只创建或续接一个 `ContentTask`。
- 任务固定为 `mode=instant`、`creationMode=viral_replication`、`requestedOutputCount=1`。
- 同一参考、同一用户意图的重试使用相同幂等键；重复点击先提示“已在制作，继续查看”，不得创建重复任务。
- 对话线程保存消息和任务绑定；`ContentTask`、运行快照、事件和产物才是生产事实源。
- 图片成品与视频成品均挂在同一任务的版本谱系中；视频使用的关键图必须能反查到图片节点产物。

### 3.3 图片和视频的分支

| 用户目标 | 默认判断 | 生产路径 |
| --- | --- | --- |
| 参考是图片，用户未另行说明 | 单张图片成品 | 公共节点 → 图片生产 → 图片验收 → 交付 |
| 参考是视频，用户未另行说明 | 单条视频成品 | 公共节点 → 图片关键画面生产 → 视频生产 → 视频验收 → 交付 |
| 用户明确要求图片 | 图片成品 | 即使参考是视频，也只使用参考拆解和关键帧证据，视频链路跳过 |
| 用户明确要求视频 | 视频成品 | 即使参考是图片，也先补齐运动方案，再进入视频链路 |

输出类型在首次付费生成前可修改。付费生成开始后修改输出类型应建立新版本和新成本确认，不覆盖原运行。

## 4. 对话如何补齐生产信息

### 4.1 先建任务，再报告缺口

点击“爆款裂变”后先创建带部分输入的任务，再由服务端缺口检查返回三组结果：

- **已确定**：参考内容、参考平台、内容类型、比例、已有分析、已绑定产品和企业资料；
- **采用默认**：目标平台、语言、时长、输出数量、制作模式、账号风格；
- **待补充**：会阻断事实、权利、生成或结算的信息。

灵小枢第一条任务回复示例：

> 已为《参考标题》建立单条爆款裂变任务。
>
> 已确定：9:16 视频、TikTok、1 条。
>
> 待补 1 项：请选择本次要推广的产品。选定后我会先拆出 4–5 个最关键爆点，再进入图片和视频制作。

### 4.2 只追问硬门禁

需要追问的硬门禁：

- 无法唯一确定要推广的企业产品；
- 产品事实、Logo、包装、人物身份或授权材料缺失；
- 输出是图片还是视频无法由参考类型与用户表达判断；
- 目标平台／账号会改变比例、时长或合规要求且没有默认账号；
- 本次预计积分超过租户已授权阈值；
- 参考素材无权访问，或来源记录已经失效。

不应阻断即时任务的信息：

- 截止时间；即时任务可以没有截止时间；
- 可从目标平台或参考媒体可靠推导的比例、时长和语言；
- 不影响事实与权限的风格偏好；没有回答时使用明确展示的默认值；
- 系统重试、供应商等待和普通排队，这些属于运行状态，不应反问用户。

每轮最多问一个决定；可在一组控件内提供互斥选项。所有硬门禁满足后，灵小枢显示一次生产摘要、预计积分和不可复用边界。租户已有额度预授权时可自动继续；超出授权或涉及新增权利声明时必须由用户确认。

## 5. 爆款分析规则

### 5.1 谁判断爆点

爆点由**编导 Agent**作最终判断，工具不直接宣布“这是爆点”。

- 工具负责下载与校验媒体、镜头切分、OCR、主体／物体／动作检测、音频与字幕提取、构图／显著性／节奏统计、来源与表现数据读取。
- 编导 Agent 根据工具证据、账号表现和业务目标，对候选因素排序，选出默认 4 个、最多 5 个爆点。
- 确定性校验器负责验证最终方案是否满足每个爆点的可测目标。
- 创意质检 Agent 独立检查成品是否表达了这些爆点，不能由生成该方案的编导自我批准。

### 5.2 爆点与强制边界分开

`HookFactorDecision[]` 必须为 4–5 项，每项至少包含：

```text
factorId
name
category
evidenceRefs[]
observedSignal
businessReason
decision: preserve | equivalent | replace | innovate
target
validator
tolerance
confidence
```

版权、Logo、水印、人物身份、产品事实、禁止照搬原台词和原音频不计入 4–5 个爆点，单独进入 `MandatoryBoundary[]`。没有来源证据的因素只能标为“创意假设”，不能写成“已证明的爆款原因”。

### 5.3 保留点与创新点

| 决策 | 含义 | 示例 |
| --- | --- | --- |
| 保留 `preserve` | 保留参考的作用和可验证结构 | 前 1.5 秒先展示结果、三段递进节奏 |
| 等价 `equivalent` | 不复用原资产，但保留感知效果 | 同类近景冲击、等价明暗反差 |
| 替换 `replace` | 必须换成企业自己的真实对象 | 产品、人物、Logo、场景、核心事实 |
| 创新 `innovate` | 有意制造差异并服务业务目标 | 新证据镜头、新 CTA、新场景转折 |

至少一项必须是 `innovate`，且所有 `replace` 必须绑定企业事实或已授权资产。参考画面、身份、台词或音乐不得因“保留爆点”被直接复制。

## 6. 固定生产节点与输入输出

### 6.1 节点通用合同

每个节点都读取冻结的 `ProductionNodeInput`，写出不可变的 `ProductionNodeResult`：

```text
schemaVersion
tenantId / contentTaskId / runId
graphVersion / nodeId / attempt
inputVersion / inputHash
state
userFacingSummary
evidenceRefs[] / artifactRefs[]
blockers[] / decisionRequest?
costReservationRef?
startedAt / updatedAt / completedAt?
```

节点不得直接读取上一节点的聊天文本。所有交接必须使用版本化字段、证据引用和产物引用；输入哈希变化时旧输出只能被标记为过期，不得混入新运行。

### 6.2 公共节点

| 节点 | 工具／确定性服务做什么 | AI 做什么 | 输入 | 稳定输出 |
| --- | --- | --- | --- | --- |
| C0 接收参考 | 校验租户、参考可访问性、媒体类型、内容哈希和幂等键 | 不参与 | 结构化参考、线程、请求键 | 原子创建回执、用户消息、任务绑定 |
| C1 建立／续接任务 | 创建 `instant` 任务；检查同意图未完成任务 | 将技术回执改写为一句业务说明 | C0 回执、用户身份 | `TaskSnapshot`、`missingInputs`、事件游标 |
| C2 事实与缺口检查 | 读取企业知识库、产品、账号、授权、积分；确定字段校验 | 仅把缺口按影响排序，不补造事实 | 任务快照、企业事实版本 | `VerifiedContext`、`DefaultedFields`、`BlockingItems` |
| C3 参考媒体拆解 | 下载／探测、镜头切分、OCR、ASR、检测、节奏与表现数据读取 | 编导解释叙事作用，提出候选因子 | 精确参考、分析版本 | `ReferenceAnalysis`、证据清单、覆盖率与不确定项 |
| C4 爆点裁决 | 为候选因子提供证据强度、可测指标和去重 | 编导排序并选 4–5 个爆点 | C3、业务目标、账号数据 | `HookFactorDecision[4..5]`、`MandatoryBoundary[]` |
| C5 保留／替换／创新 | 检查企业资产是否真实可用、权利是否满足 | 编导为每个因子作取舍并生成差异化策略 | C4、企业资产清单 | `AdaptationMap`，至少一项创新 |
| C6 导演方案 | 校验时长、平台安全区、事实引用完整性 | 编导生成图片构图、首帧、逐镜意图、字幕与连续性 | C2、C5 | 版本化 `DirectorBrief`、逐项验收标准 |
| C7 执行计划与付费预检 | 匹配能力／供应商、估价、预留积分、生成幂等调用计划 | 制作规划 Agent 选主路线、备选路线和最小回退 | C6、能力注册表、预算授权 | 冻结 `ExecutionPlan`、成本回执、图版本 |

| 节点 | 工具／Worker | AI／Agent | 输入 | 稳定输出 |

| I3 图片生成 | 调用图片能力，保存供应商回执与原始产物，处理结果未知 | 不直接操作供应商 | I2、成本预留 | `ImageCandidate[]`、调用回执、版本谱系 |

## 7. 对话任务卡要显示什么

### 7.1 固定结构

每条任务在对话里只有一张持续更新的任务卡；里程碑完成、需要用户处理和最终交付时才新增一条简短消息。任务卡从上到下为：

1. **标题**：`参考标题 · 爆款裂变`，显示图片／视频图标；
2. **总状态**：准备中、需要补充、生产中、需要验收、已暂停、失败、已完成；
3. **当前节点**：业务名称，不展示内部枚举；
4. **当前动作**：一句服务端确认的活动说明；
5. **进度**：只有服务端给出真实分母或供应商真实百分比时显示；否则使用旋转状态与节点名；
6. **预览**：当前最新且有权限的缩略图／视频；未生成时使用媒体状态框，不造模糊图；
7. **可展开详情**：“已完成”“采用依据”“版本变化”，只显示业务摘要和证据来源，不显示日志与内部推理；
8. **操作区**：最多一个主操作和一个次操作，操作必须来自服务端 `decisionRequest`。

已冻结执行计划后，可以显示“节点 6/14”；计划冻结前分母未知，只显示当前节点。参考图中的 `25%` 只有在供应商返回并经服务端确认真实百分比时才能使用，不能按等待时间插值。

### 7.2 每个正常节点的前端显示

| 节点 | 卡片标题／当前动作 | 展开内容 | 可用操作 |
| --- | --- | --- | --- |
| C0–C1 | “正在建立爆款裂变任务” | 参考标题、来源、输出类型 | 失败前无操作 |
| C2 | “正在核对产品与生产条件” | 已确定、默认值、待补项 | `补充信息` |
| C3 | “正在拆解参考内容” | 已完成镜头／画面、字幕、节奏等证据范围 | `查看参考` |
| C4 | “已选出 4–5 个关键爆点” | 每项“证据—作用—保留方式”，另列强制边界 | `查看爆点` |
| C5–C6 | “正在形成差异化制作方案” | 保留、替换、创新摘要；不展示长 Prompt | `查看方案` |

| I1–I2 | “正在准备产品素材与关键画面” | 已绑定素材数、缺失项、规格 | 缺素材时 `上传/选择素材` |
| I3 | “正在生成关键画面”／“正在生成图片” | 候选数量和真实调用状态 | `暂停`（仅后端支持时） |
| I4–I6 | “正在检查并修复图片” | 已通过项、失败区域、修复轮次 | 达到重试上限时 `选择方案` |
| I7 图片成品 | “图片已生成，请验收” | 大图、关键差异、质检通过摘要 | `采用图片`、`局部修改` |
| I7 视频关键画面 | “关键画面已准备，继续制作视频” | 关键画面组和自动门禁结果 | 高风险时 `确认继续`，否则无打断 |
| V1–V2 | “正在规划动作并准备镜头素材” | 镜头数量、素材覆盖、缺口 | 缺权利素材时 `补充素材` |
| V3 | “正在生成并对齐配音” | 语言、音色授权、字幕状态 | 授权不明时 `选择声音` |
| V4–V5 | “正在剪辑并添加字幕效果” | 已完成镜头数／总镜头数（真实分母） | 无 |
| V6 | “正在渲染视频” | 真实渲染阶段、供应商真实进度（若有） | `暂停`（仅支持时） |
| V7–V9 | “正在质检并修复失败镜头” | 失败镜头、失败标准、最小返工范围 | 达到上限时 `选择方案` |
| V10 | “视频已生成，请验收” | 可播放视频、版本变化、质检摘要 | `采用视频`、`修改镜头` |
| D1 | “已完成，可下载” | 文件类型、尺寸／时长、版本、实际积分 | `下载`；发布另行授权 |

### 7.3 每种例外情况的前端显示

| 情况 | 前端必须显示 | 前端不得显示 | 操作 |
| --- | --- | --- | --- |
| 缺产品／事实 | 缺哪一项、为什么阻断、已完成内容仍保留 | “系统异常” | 选择产品／补充事实 |
| 缺权利／身份授权 | 涉及的素材和允许的替代路线 | 默认替用户确认拥有权利 | 更换素材／确认授权 |
| 积分不足或超授权 | 预计需要、可用额度、未开始付费调用 | 供应商成本或 Token | 充值／调整数量／暂停 |
| 正常排队 | 当前节点、进入队列时间；无可靠 ETA 时写“等待可用产能” | 假百分比、倒计时 | 可取消时显示取消 |
| 外部处理中 | “服务已接收，正在处理”；有真实回执才展示进度 | 把 HTTP 请求未返回当成完成 | 无或暂停 |
| 结果未知 | “结果正在核对，请勿重复提交”，保留调用回执 | 直接报失败并再次扣分 | `继续核对`，系统自动执行 |
| 自动重试 | 第几次、重试原因的业务摘要、下一次时间 | 堆栈、内部错误码 | 通常无；达到上限后再让用户决定 |
| 技术质检失败 | 失败文件／镜头、检查项、自动修复范围 | “质量不好”这类空泛文案 | 自动修复中或选择替代 |
| 创意质检失败 | 未满足的爆点／导演标准及镜头位置 | 生成 Agent 的自我评价 | 定点返工／调整方案 |
| 用户要求修改 | 修改范围、将保留的已通过部分、预计新增积分 | 默认整条重做 | 确认局部修改 |
| 已暂停 | 暂停节点、已保存内容、恢复后的下一步 | “已取消” | 继续／取消 |
| 已取消 | 是否已产生可保留产物、实际结算与退款结果 | “可继续”除非后端允许恢复 | 复制为新任务 |
| 硬失败 | 第一处不可继续的业务原因、已自动尝试过什么、保留的产物 | 原始异常、全量日志 | 重试失败节点／更换路线／结束 |
| 版本冲突 | “任务已在其他窗口更新，已刷新为最新版本” | 用旧版本覆盖新版本 | 查看最新状态后重新决定 |
| 断网／流断开 | “实时状态暂时断开，正在恢复”；最后更新时间 | 将任务标为失败 | 手动刷新（自动恢复失败后） |
| 权限失效 | 无权限查看或操作的对象范围 | 泄露缩略图、下载地址、内部 ID | 重新登录／联系管理员 |
| 服务端未知状态 | 中性文案“状态暂时无法确认”并主动重读快照 | 前端自行归类为生产中或完成 | 刷新状态 |

## 9. 前后端状态合同

### 9.1 快照与事件

建议新增统一的单条生产 BFF，而不是让首页串联多个浏览器事件：

```text
POST /api/overseas/content-production/conversations/from-reference
GET  /api/overseas/content-production/tasks/:taskId/snapshot
GET  /api/overseas/content-production/tasks/:taskId/events?after=:sequence
POST /api/overseas/content-production/tasks/:taskId/decisions
```

首个接口应在同一事务／幂等业务操作内完成：校验参考 → 写入用户消息 → 创建或续接任务 → 绑定线程 → 返回任务快照、缺口和事件游标。不能先在前端添加成功消息，再分别调用任务接口。

事件最少包含：

```text
eventId, sequence, occurredAt
tenantId, threadId, contentTaskId, runId
graphVersion, nodeId, nodeLabel, attempt
state: queued | running | waiting_external | needs_input | needs_approval |
       retrying | paused | failed | completed | cancelled | outcome_unknown
progress: { mode: none | units | percent, completed?, total?, percent? }
userFacingSummary
artifactRefs[]
decisionRequest?
error: { category, retryable, userActionRequired, publicMessage }?
inputVersion, inputHash
```

服务端事件为追加写，`sequence` 单调递增；前端按 `eventId` 去重，断线后用最后序号续传。首次连接和重连必须先读权威快照，再消费缺失事件。SSE 不可用时允许退化为带版本号的快照轮询，不能退化为本地计时模拟。

### 9.2 对话展示与生产事实分离

- 聊天消息可以持久化用户和灵小枢的自然语言，但不能成为任务状态源。
- 任务卡由 `TaskSnapshot + latest events + decisionRequest` 渲染。
- 用户操作必须携带任务版本、产物版本、决定类型和幂等键。
- 刷新后任务卡从服务端恢复；本地存储只可保存折叠、滚动和草稿偏好。
- 线程删除、消息重试或对话切换不得删除生产任务与产物。

### 10.1 推荐实施顺序

1. 先建立统一命令、任务绑定、快照和事件合同；没有权威状态前不做“思考中”动效。
2. 将首页“爆款裂变”接到新命令，并实现用户参考气泡与同一任务卡恢复。
3. 修正即时任务类型、截止时间规则和 V2 执行器冻结。
4. 把图片生产迁入服务端持久子图，完成图片产物、质检、审批和图片到视频谱系。
5. 接入视频 V2 节点、局部返工和最终验收。
6. 最后补齐异常、断线、跨标签页、积分结算和可访问性回归。

不要先做一套前端动画再等待后端接线；那会把无法确认的状态包装成“正在生产”。

## 11. 验收标准

- 点击任意可用爆款的“爆款裂变”后，首页出现一条包含精确参考的用户气泡，不发生页面跳转。
- 服务端只创建一个 `instant + viral_replication` 任务；刷新、重复点击和网络重试不增加任务或扣费。
- 灵小枢首先展示已确定、默认和待补信息；没有截止时间也能创建即时任务。
- 参考拆解最终只向用户展示 4–5 个爆点；版权、身份和事实边界另列。
- 图片成品走完 I1–I7；视频成品先有可追溯图片关键画面，再走 V1–V10。
- 每个前端状态都能反查服务端快照或事件；未知总量时没有百分比，内部推理和日志不出现在对话。
- 所有用户决定带对象版本和幂等键；版本冲突不会覆盖更新后的任务。
- 技术失败、创意失败和用户修改均只重跑必要节点／镜头，并保留已通过产物。
- 最终图片或视频在同一对话内预览、验收和下载；“采用”不等于自动发布。
- 键盘、触屏、减少动效、日夜主题、媒体加载／空／错／无权状态符合全系统 UI 规范。
