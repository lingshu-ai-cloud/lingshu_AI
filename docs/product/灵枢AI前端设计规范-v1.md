# 灵枢 AI 前端设计规范 v1.0

> 更新日期：2026-09-23
> 适用范围：灵枢 AI 经营工作台的桌面端、平板端与移动端
> 业务依据：`PRD-灵枢AI前端交互-v1.md`、`PRD-灵枢AI当前系统-v3.md`
> 原型入口：`/design-prototype`
> 详细实施规格：[`灵枢AI前端信息架构与交互设计规格-v2.md`](./灵枢AI前端信息架构与交互设计规格-v2.md)；v1 作为视觉基础摘要，产品、设计和前端实施以 v2 为主。
> 目标用户：不熟悉 AI、视频制作与复杂 SaaS 的企业老板和一线员工

## 1. 设计定位

灵枢 AI 不是数据大屏，也不是模型控制台，而是让用户知道“经营现在怎么样、AI 正在做什么、我下一步要做什么”的经营工作台。

设计判断固定回答三个问题：

1. **谁在使用**：时间有限、不理解技术名词、希望系统托管执行的业务用户。
2. **要解决什么问题**：在复杂的多 Agent 流程中快速得到结论、处理例外、确认关键事实。
3. **完成后的感受**：清楚、可信、可控；系统主动工作，但任何对外动作都有边界和回执。

### 1.1 视觉关键词

- **可信的自然感**：深森林绿、薄荷青、暖米白，避免高饱和蓝紫色“AI 科技感”。
- **克制但不冷淡**：大面积留白、低对比背景、少量珊瑚橙用于提醒与洞察。
- **任务优先**：状态和下一步比图表、日志、模型参数更醒目。
- **圆润但专业**：容器采用 12–20px 圆角，控件采用 8–12px 圆角；不使用到处悬浮的大胶囊。

附件中的版式语言被转译为产品规则：大标题建立第一视觉，浅色内容区承载第二层信息，薄荷色表达稳定与完成，珊瑚色只强调关键洞察；不照搬海报比例和装饰图形。

## 2. 信息层级与注意力顺序

### 2.1 页面阅读顺序

每个任务型页面都按下面顺序组织：

| 视线顺序 | 页面内容 | 设计要求 |
| --- | --- | --- |
| 第一眼 | 当前结论 / 页面主任务 | 位于内容区左上；标题不超过两行；同时只出现一个状态结论 |
| 第二眼 | 当前对象或主视觉 | 商品、视频、经营目标或任务结果；占首屏最大视觉面积 |
| 第三眼 | 唯一下一步 | 主按钮与结论相邻或位于首屏下缘；全页只保留一个最高强调按钮 |
| 第四眼 | 需要处理的例外 | 待审批、缺资料、权利或预算问题优先于普通运行日志 |
| 第五眼 | 证据与历史 | 进入抽屉、弹窗、折叠区或页面下半区 |

### 2.2 信息克制规则

- 首屏最多包含 1 个主标题、1 个状态结论、1 个主操作和 3 个辅助信息组。
- 卡片标题建议 8–16 个汉字；描述最多两行；状态文案最多一行。
- 同一信息只出现一次。产品、市场、沟通对象用“任务上下文条”统一展示，不在每张卡片重复。
- 一个区域只保留一个主操作。次级操作使用文字按钮或溢出菜单。
- 默认隐藏模型名、提示词、供应商、内部评分、原始日志和长篇原理。
- 没有用户动作时不制造按钮；纯状态卡可以整卡进入详情。

### 2.3 标题、主视觉、按钮和商品卡位置

- **标题**：页面内容区左上，面包屑下方。桌面端距内容区顶部 32px；移动端 20px。
- **主视觉**：标题下方或标题右侧。当用户要评估产品/视频时使用 4:3 或 16:9 图像；当用户要处理任务时使用状态面板而非装饰图。
- **主按钮**：紧跟唯一下一步，不固定在页面右上。长表单的保存按钮可固定在底部操作条。
- **商品卡**：只在商品影响当前决策时出现。桌面端置于目标摘要右侧；移动端位于目标摘要下方。卡片包含图片、商品名、市场、可用事实数，不展开完整商品资料。
- **异常入口**：放在下一步之后、普通结果之前，保证用户先解决阻塞问题。

## 3. 品牌基础

### 3.1 字体

中文采用系统字体优先，避免额外字体加载造成闪烁：

```css
--font-sans: "SF Pro Text", "PingFang SC", "Noto Sans SC", system-ui, sans-serif;
--font-display: "SF Pro Display", "PingFang SC", "Noto Sans SC", system-ui, sans-serif;
--font-mono: "SFMono-Regular", "DM Mono", ui-monospace, monospace;
```

| 样式 | 桌面端 | 移动端 | 行高 | 字重 | 用法 |
| --- | --- | --- | --- | --- | --- |
| Display | 40px | 30px | 1.15 | 700 | 登录、空状态或关键结果，不用于普通后台页 |
| H1 | 30px | 26px | 1.25 | 700 | 页面主标题 |
| H2 | 22px | 20px | 1.35 | 650/700 | 一级区块 |
| H3 | 17px | 16px | 1.45 | 650 | 卡片组、弹窗标题 |
| Body L | 16px | 16px | 1.65 | 400/500 | 结论、关键说明 |
| Body | 14px | 14px | 1.6 | 400/500 | 默认正文与表单 |
| Caption | 12px | 12px | 1.5 | 500/600 | 元数据、标签、时间 |
| Micro | 11px | 11px | 1.4 | 600 | 序号、单位、短标记；禁止承载关键内容 |

排版约束：

- 中文正文不使用全大写；英文短标签可以使用大写并增加 `0.08em` 字距。
- H1 最宽 760px，正文最宽 680px，避免过长行宽。
- 数据使用等宽数字 `font-variant-numeric: tabular-nums`。
- 颜色和字重共同表达层级，不靠字号无限放大。

### 3.3 间距、栅格与尺寸

采用 4px 基准：

```text
4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64
```

| 场景 | 规范 |
| --- | --- |
| 应用侧栏 | 展开 232px；收起 72px |
| 顶部栏 | 64px；移动端 56px |
| 桌面内容宽度 | 最大 1440px；左右内边距 32px |
| 阅读型内容宽度 | 760–960px |
| 桌面栅格 | 12 列，24px gutter |
| 平板栅格 | 8 列，20px gutter |
| 移动栅格 | 4 列，16px gutter |
| 区块间距 | 32px；相关卡片间距 16px |
| 卡片内边距 | 紧凑 16px；标准 20px；重点 24px |
| 控件高度 | S 32px / M 40px / L 48px |

### 3.4 圆角、边框与阴影

- 输入框、按钮：10px。
- 标准卡片：14px。
- 重点面板、弹窗：18px。
- 胶囊标签：999px，只用于短状态、筛选和标签。
- 默认卡片使用 1px 边框，不依赖阴影分层。
- 只有弹窗、抽屉、浮层使用阴影：`0 20px 60px rgba(23,61,49,.16)`。
- Hover 通过边框加深和背景轻微变化表达，不使用夸张上浮。

### 3.5 图标与图像

- 界面图标统一使用 Lucide，线宽 1.75–2px。
- 常规图标 18px，卡片图标 20px，空状态图标 28–32px。
- 产品图保持真实比例，`object-fit: cover`；不得用生成图承担未经确认的事实证明。
- 视频封面优先使用 16:9；商品主图优先使用 4:3 或 1:1。
- 外部灵感、客户素材、AI 生成内容必须在图片附近明确标识来源类型。

## 4. 应用框架

### 4.1 左侧导航

导航按业务对象分组：智能经营、社媒运营、平台投放、客户管理、智能体管理、系统设置。当前页面使用薄荷浅底、深绿文字和 3px 左侧标记；不使用大面积品牌色填充。

原则：

- 默认展开当前分组，其余分组保持可识别但不抢占注意力。
- 徽标只显示需要用户处理的数量，不显示普通运行数量。
- 管理员入口仅对有权限角色展示。
- 移动端导航进入全屏抽屉，关闭后焦点回到菜单按钮。

### 4.2 页面头部

页面头部最多包含：面包屑、H1、一句状态或说明、必要的范围/更新时间。帮助、分享、导出等低频操作进入溢出菜单。

### 4.3 任务上下文条

用于统一展示本次任务的产品、市场、对象、平台和目标。默认单行，允许横向滚动；点击“查看上下文”进入抽屉。上下文条不承担编辑，避免在流程中误改全局事实。

## 5. 核心组件库

### 5.1 Button

| 类型 | 使用场景 | 视觉 |
| --- | --- | --- |
| Primary | 页面唯一下一步、确认保存 | 薄荷绿底、白字 |
| Secondary | 同层次非主要动作 | 白底、绿灰边框、深绿字 |
| Tertiary | 查看详情、取消、返回 | 无底色文字按钮 |
| Danger | 删除、撤销不可逆动作 | 红色；执行前确认影响 |
| Icon | 工具栏低频动作 | 40×40px，必须有可访问名称 |

按钮文字使用“动词 + 对象”，例如“确认事实边界”“开始制作”，避免“确定”“提交”。加载时保留原宽度并显示动作对象。

### 5.2 StatusPill

结构为“图标/圆点 + 状态文字”，高度 24–28px。运行态可使用呼吸点；等待和异常不可动画。状态命名必须包含对象或放在对象旁边。

### 5.3 AgentLiveStatusRail

桌面端 4 列、平板 2 列、移动端单列或横向滚动。单卡包含：

1. Agent 名称与专属色图标。
2. 状态文字。
3. 当前动作（单行）。
4. 真实数量 `已完成 2/5` 或真实阶段。
5. 最后更新时间。

运行中卡片顶部允许 2px 同色流动线；`prefers-reduced-motion` 下停用。点击整卡打开该 Agent 的详情，不能混入其他 Agent 日志。

### 5.4 NextActionPanel

页面只允许一个。包含：为什么现在需要处理、影响范围、主按钮、可选的“稍后处理/查看依据”。待处理使用暖米色或琥珀背景，不能使用红色制造无必要紧张。

### 5.5 ApprovalCard

包含审批对象、风险或影响、截止时间、发起 Agent、主决定。详情证据折叠；批准与退回不并列为两个高强调按钮，主要建议使用主按钮，另一项使用次按钮。

### 5.6 ProductContextCard

适合经营首页和内容创建页。结构：4:3 图片、产品名、目标市场、事实就绪度、资料来源。默认不显示完整参数；点击进入产品抽屉。

### 5.7 InspirationCard

首屏信息固定为：

- 16:9 封面和平台/来源状态。
- 命中场景或内容作用。
- 表现结论（“高表现候选”或有证据的“正在起量”）。
- 相关性、可迁移性和分析等级分别表达。
- 一句话推荐理由。
- 收藏、不相关、用于创作。

查询变体、采集工具、完整证据和权利说明进入“为什么出现”抽屉。

### 5.8 EntryChoiceCard

用于“素材加工 / 爆款裂变”。两张卡层级平等，整卡可选；选中后只在页面底部出现一个主按钮。卡内说明“用户需要提供什么、系统会做什么、最终得到什么”，不展示模型路线。

### 5.9 ShotCompareCard

用于逐镜对照。桌面端为“参考镜头 / 客户版本 / 作用与状态”三列；移动端纵向排列。必须显示：镜头作用、真实证据、功能等价说明、四级可行性、来源和修改入口。

### 5.10 SettingsSection

设置按“目标/输入 → 执行 → 对外动作 → 审批红线”单列排列。仅天然成对字段使用双列。标题区包含一句职责；说明超过两行进入“查看说明”。强制项锁定并明确标“强制”。底部固定保存操作条。

### 5.11 StateNotice

统一处理加载、空、等待、异常、完成和断线：

- 加载：显示正在读取的真实对象；不先渲染错误的 0。
- 空：解释为什么为空，并给出一个恢复入口。
- 异常：说明对象、原因和下一步；保留已经确认的数据。
- 断线：显示最后更新时间和“重新连接”，不清空卡片。
- 完成：提供真实回执或可追溯结果入口。

### 5.12 Overlay

- 对短任务使用 Dialog；对需要对照当前页的信息使用右侧 Drawer；移动端统一全屏。
- 支持 Esc、焦点锁定、关闭后焦点恢复。
- 标题和关闭按钮固定，内容区滚动，操作区固定。
- 弹窗中仍只保留一个主操作。

## 6. 关键页面规范

### 6.1 智能经营首页

正常运行时首屏从上到下：

1. 当前经营结论、本轮目标、更新时间。
2. 商品/市场上下文（桌面端可位于目标右侧）。
3. 四个 Agent 实时状态卡。
4. 唯一下一步。
5. 待审批与待补资料。
6. 生产和交付结果。
7. 历史与复盘。

普通日志不在首屏。需要用户处理的异常必须早于普通“运行中”。

当存在会阻断制作、发布或经营目标的待确认事项时，信息顺序动态调整为：经营结论 → 唯一下一步与受影响对象 → 四 Agent 状态 → 结果与历史。NextActionPanel 必须说明“为什么被提升”，处理完成后页面恢复正常顺序，避免同一页面无理由跳动。

### 6.2 灵感中心

首屏顺序：标题 → 发现范围 → 分类页签 → 结果与分页 → 卡片列表。筛选结果、总数、页码来自同一查询快照。

“最近发现 / 正在起量 / 高度相关 / 创新参考”只改变同一列表的排序与解释，不切换数据对象。每页 30 条，分页失败保留当前内容。

### 6.3 内容制作首页

只展示“素材加工”和“爆款裂变”两种选择。选择前先确认产品上下文；选择后在同页底部展示系统会自动检查的内容以及一个“继续”按钮。立即/每周是执行频率，不作为第三种制作类型。

#### 6.3.1 素材加工任务

素材加工采用同一条五阶段任务链：资料输入 → 脚本确认 → 制作 → 预览 → 交付。顶部显示产品、市场、语言、平台和目标上下文；主体先给出系统盘点结果，再说明由系统补齐的素材及事实/权利边界，最后只保留一个阶段主操作。

- 零素材、弱素材和已有素材均进入同一任务页，不新增第三种入口。
- 用户不选择模型、供应商或提示词；这些内容默认隐藏。
- 单镜头或单区域失败只重做受影响部分，不重跑整条任务。
- “确认计划”不等于授权发布；预览、交付与发布回执保持分离。

### 6.4 爆款裂变任务

顶部先显示真实阶段和 `已完成 x/y`；其次是前三秒钩子；然后是逐镜对照。结构还原度与原创差异度必须分开显示，并注明证据或检查项。高级模型、提示词和供应商默认隐藏。

四级可行性文案：

- 完整实现。
- 功能等价。
- 目标降级，需确认。
- 缺事实或权利，已阻断。

### 6.5 Agent 设置

固定页签：通用设置、经营 Agent、编导 Agent、内容 Agent、客服 Agent。通用字段只出现一次。每个 Agent 顶部先说明职责，然后仅展示自己的个性规则和审批红线。

### 6.6 发布、监控、客户与订单

- 发布卡必须显示账号、平台、版本、计划时间、审批和平台回执。
- 监控明确区分平台原始数据、系统计算和不可用数据。
- 客户列表优先意向、最近动作和下一步。
- AI 草稿与真实发送分离；订单仅展示正式记录。

## 7. 表单与文案

### 7.1 表单

- 标签位于字段上方，不使用 placeholder 代替标签。
- 必填用“必填”文字或整体规则说明，不堆叠红色星号。
- 错误紧贴字段，说明如何修复；提交失败自动定位第一个错误。
- 默认值必须说明来源，如“系统根据企业档案推荐”。
- 开关只用于立即生效的二元状态；需要解释影响时使用单选或选择卡。

### 7.2 文案结构

状态反馈固定为：

1. 现在是什么状态。
2. 系统正在做什么。
3. 用户是否需要操作。
4. 查看原因和证据。

推荐：“内容 Agent 正在制作第 3 个镜头；已完成 2/5，无需操作。”
禁止：“处理中”“未知错误”“任务失败”。

## 8. 动效与反馈

- 默认过渡 160–220ms，使用 `ease-out`。
- 动效只解释状态变化、层级或连续性，不作为装饰。
- 运行中的 Agent 允许呼吸点和顶部流动线；其他卡片不循环动画。
- 列表更新不整页闪烁；保留旧数据并在局部显示同步状态。
- Toast 只用于轻量、可撤销或不需要后续处理的结果；重要结果留在页面内。
- `prefers-reduced-motion: reduce` 下关闭循环动画、平滑滚动和大位移。

## 9. 响应式

| 断点 | 布局 |
| --- | --- |
| `≥ 1280px` | 展开侧栏，12 列；Agent 四列；重点内容可 8+4 |
| `768–1279px` | 收起或可切换侧栏，8 列；Agent 两列；抽屉宽度不超过 480px |
| `< 768px` | 顶部导航 + 全屏菜单，4 列；单列内容；固定底部主操作 |

移动端要求：

- 触控目标不小于 44×44px。
- 表格转换为分组列表，不强制横向浏览关键任务。
- Agent 状态可单列或横向滚动，但首卡必须完整可见。
- 逐镜对照先显示客户版本，再通过折叠查看参考证据。
- 设置弹窗变为全屏页，保存条避开系统安全区。

## 10. 无障碍

- 正文对比度不低于 4.5:1；大字不低于 3:1。
- 状态不能只靠颜色；图标按钮提供 `aria-label`。
- 键盘焦点使用 2px 薄荷绿轮廓和 2px 偏移。
- Tab 顺序与视觉顺序一致；卡片整卡可点击时使用真实 `button` 或链接。
- 页面标题、区块标题和列表结构使用正确语义标签。
- 弹窗使用 `role="dialog"`、`aria-modal`、明确标题关联。
- 实时状态使用节制的 `aria-live="polite"`，避免高频事件打断读屏。
- 图片提供描述其业务作用的 alt；纯装饰图使用空 alt。

## 12. 设计验收清单

设计评审逐页检查：

- 用户能否在 5 秒内说出页面当前结论？
- 第一主操作是否唯一，并且与当前结论相邻？
- 是否有重复字段、重复解释或重复按钮？
- 任务进度是否来自真实数量、阶段或回执？
- 等待和异常是否说明对象、原因和下一步？
- 外部参考、客户素材和生成内容是否明确区分？
- 商品/视频主视觉是否帮助决策，而不是装饰？
- 移动端是否仍能完成同一核心流程？
- 键盘、读屏和减少动态效果是否可用？
- 页面是否把技术实现暴露给了不需要理解它的用户？

## 13. 本版原型覆盖范围

`/design-prototype` 提供以下可交互高保真页面：

1. 智能经营首页：目标、产品上下文、四 Agent、唯一下一步、审批和结果。
2. 灵感中心：发现范围、分类、灵感卡和“用于创作”交互。
3. 内容制作：首页仅保留两种入口，并包含“资料输入 → 脚本确认 → 制作 → 预览 → 交付”的素材加工子流程。
4. 爆款裂变任务：真实阶段、前三秒钩子和逐镜对照。
5. Agent 设置：固定五页签、通用与个性字段分离、单列阅读流。
6. UI 规范：字体、色彩、间距、按钮、状态与卡片示例。

这套原型用于确定视觉和交互基线，不改变现有后端业务逻辑。全局“演示数据”标识必须持续可见，样例中的“已确认”“已完成”和数量只代表交互状态，不代表已经接入真实生产数据。

原型验收与生产集成验收分开：

- **交互原型验收**：验证信息顺序、组件语言、关键状态、主要交互和响应式行为。
- **生产集成验收**：验证 Agent 状态、数量、任务、审批、发布和发送结果均来自真实接口与可追溯回执；不得用静态样例替代。
