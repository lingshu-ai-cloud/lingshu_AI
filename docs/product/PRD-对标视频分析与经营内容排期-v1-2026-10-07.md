# 对标视频分析与经营内容排期 PRD

云端文档：https://chatgpt.com/space/page_4fed2c59d36081919e7354544f6b7acb

版本：v1.0。日期：2026-10-07。状态：第一阶段和第二阶段已实现并通过本地验证；第三阶段和第四阶段待同事接手。

## 产品目标与职责

让每条内容任务都能回答为什么做、参考哪条视频、使用什么钩子、采用什么分镜结构、需要什么素材。经营 Agent 先确定数量、账号、产品和日期，获取编导逐条分析后生成详细选题排期，用户确认后由经营 Agent 派给内容 Agent。编导 Agent 负责证据分析与改编方法；内容 Agent 读取任务绑定的分析版本并执行。制作数量由经营配额确定，一条对标可以支持多个不同选题，但不能用重复任务填满配额。

## 第一阶段 统一对标分析字段

为每条视频建立可供页面和后续经营排期共用的 benchmarkAnalysis 合同。保存合同版本、来源视频 ID、分析运行 ID、源分析内容修订指纹、人工修订版本、更新时间、分析状态与缺口。

钩子就是现有分镜分析的第一个分镜，不建立独立 hookAnalysis 对象，不重复摘取分析。benchmarkAnalysis.hookShotId 指向 shots 中第一张卡片；该卡片 narrativeRole=hook。经营 Agent 后续引用来源视频、source.evidenceRevision 与 hookShotId，读取该镜头原有画面、口播、声音、镜头作用和有效性分析，再交给内容 Agent。

全片拆解包含镜头列表、时间范围、首帧与切片引用、口播、画面描述、素材类型、镜头作用、依据与复核信息。素材固定为五类：真人口播、工厂实拍、产品实拍、D2C、其他通用素材；D2C 指消费者使用产品或效果演示，其他通用素材指不属于前四类但有明确可见证据的环境、道具、图形或转场等镜头。unknown 仅为证据不足时的内部缺失状态，不是第六种业务类别。钩子是第一分镜的作用标记，不是素材类别。

结构顺序只按素材类别合并相邻镜头，显示类别与镜头数量，首段标记首镜钩子；不混入镜头作用或“作用待确认”。各类素材数量来自逐镜归类，口播段与镜头数分开；粗 ASR 保留估计时间。

分类优先读取已有结构化素材类型、salesPresenterConfirmed 与 observedPresenterRole，复用既有真人识别逻辑；旧记录再结合画面、观察事实及场景中的生产动作、产品展示、消费者使用证据归类。识别到主播时不因产品或工厂背景改类，女工操作设备及工人分拣零件属于工厂素材。显示分类不改变生成准入和原有质检状态，不付费重跑、不改写源记录。

验收：一段口播覆盖多个镜头时总数正确；混合工厂与前景口播不以环境替代主体类型；消费者演示归类独立；未知分类、断档、分析失败、策略分析和待复核均明确标注；租户与现有媒体权限保持有效。

## 第二阶段 灵感大屏右侧分析栏

分析详情顶部展示全片结构与素材拆解、数量与结构顺序，下方展示分镜；第一分镜标为钩子并默认展开详情。删除全片结构标题下的“分析待复核”和“待补齐或复核·N项”区域，原有顶部工作状态和后端质量门保持独立。无独立钩子区。

全片展示镜头数、分类数量、结构顺序和逐镜卡片。卡片包含序号、时间、真实首帧或缺图占位、素材类型、镜头作用、口播、画面和分类来源；详细区保留景别、运镜、视角、构图、音轨、观察事实、意图推断、起止状态与衔接分析。第一张卡片的详细分析就是钩子分析。口播段可展开覆盖多个镜头，明确句级或估计来源。

旧记录缺新字段时展示可用原片证据和待补齐提示；分析中、失败、空分析、待复核及图文模式保持可用。原有播放、收藏、重试及既有制作入口继续使用原有授权和质量门。折叠展开无需付费调用。移动端卡片不横向溢出。

验收：全片结构位于分析栏顶部；第一张分镜标为钩子且详细区默认展开，无独立钩子区或重复分析；消费者演示标签正确；镜头数与口播段数区分；旧描述能明确归类时不全部显示待判断；保留分类来源与复核状态；缺首帧不以封面代替；相关回归、类型检查和构建通过。

## 第三阶段 经营排期读取分析 同事接手

经营骨架给出制作配额、账号、产品与日期。经营 Agent 从同租户且合格的对标候选中选择视频，读取第一阶段合同，生成逐条选题排期。不能继续以视频标题加固定模板代替分析。

每条排期保存 taskId、日期、账号/平台、企业产品、选题、对标视频 ID、分析修订指纹、hookShotId、钩子改编方向、逐镜结构、素材需求及缺口、制作方式与状态。钩子引用第一分镜的完整分析，不建立平行的钩子对象。制作与发布统计分开；分析不足保持待补齐，不跳过准入；企业事实与对标事实分开。

计划确认前校验引用是否过期；确认后冻结分析快照、排期版本与任务身份。变更走新周包修订并重新确认，保留现有双版本与冻结守卫。经营 Agent 保持合并与派单唯一权限，编导分析不直接派单。

接手入口：shared/contracts/socialProgram.ts、server/socialPrograms/planningAuthority.ts、周排期客户端与工作台。消费本 PRD 第一阶段 benchmarkAnalysis，不再创建另一份仅供排期使用的钩子/镜头合同。验收包括跨租户拒绝、未完整分析阻塞、更新冲突、确认后快照不变、同一对标多个差异化选题和制作/发布去重。

## 第四阶段 内容执行与目标看板 同事接手

内容 Agent 按经营派单的冻结任务读取分析快照，完成企业素材匹配、脚本/分镜改编、制作、质检、用户验收和发布授权。不得根据实时更新的对标分析默默改写已确认任务。缺输入、凭据、预算或质检失败保留真实阻塞；供应商未知回执先对账，不重复付费提交。

经营页面顶部为计划制作、已排期、制作中、待验收、已发布五项。计划制作按唯一制作任务计数；已发布按真实发布回执及发布任务计数，显示单位避免混淆；已排期是计划中已完成详细排期的制作任务数，与其他执行状态可以重叠，不能作为互斥分布求和。制作中和待验收从真实任务状态投影。排期表展示日期、账号、选题/产品、对标、钩子、结构、素材准备和状态，点击展开完整任务。

接手入口：周 executionTasks 与 dispatchConsumer、starter 内容生产交接、经营读模型和工作台。沿用现有消费者显式启用、队列租约、幂等、取消补偿与独立用户验收/发布授权。

验收：任意任务能追溯冻结分析；暂停/恢复/取消保持任务身份；一条成片跨三平台只算一次制作；已发布必须有真实回执；缺数据不显示成功；外部生成和发布单独验收。

## 已实现接口与接手约定

视频列表和详情 aiAnalysis JSON 新增 benchmarkAnalysis，server/lib/videoAnalysisCodec.ts 读取时调用 benchmarkAnalysisForRecord。逐镜 materialType/narrativeRole/classificationEvidence 保存在 gemini 下；hookShotId 仅引用第一镜，不新增独立钩子数据。旧字段在读取时保守兼容，不改写源分析，不启动付费重分析。

共享合同位于 shared/benchmarkAnalysis.ts，服务端入口为 server/lib/benchmarkAnalysis.ts，右侧栏组件为 src/components/inspiration/BenchmarkAnalysisSections.tsx。source.evidenceRevision 为 SHA256 修订指纹，schemaVersion 为合同版本，不要把修订指纹当递增 planningVersion；source.analysisRunId 和 analyzedAt 对旧记录允许为空。

status=ready 仅表示本合同字段和原片分析状态满足完整性检查，不代表业务候选 accepted、可直接生产、已确认排期或发布授权。第三阶段仍需检验租户、发现供给准入、企业事实与版本；确认后冻结完整分析快照及修订指纹。镜头 ID 在同一修订内有效，不应跨重分析复用。

totalShots 在策略分析或仅有 observation_window 时为 null；shots 保留已有片段以供阅读，页面显示实际镜头数待确认。materialCounts 与 structure 对不完整分析仅描述已有片段。speechGroups.timingPrecision 区分 phrase 与 coarse，粗时间码只显示估计关联。逐镜媒体引用仅保留当前视频既有鉴权路由，缺图不使用封面替代。

浏览器隔离样例为 benchmark-analysis-preview.html，不在正式业务导航中；本地执行 scripts/test-benchmark-analysis-ui.mjs 可复验。样例数据明确标为隔离验收，不能作为真实模型或供应商成功证据。

## 交付顺序与边界

第一阶段合同及服务端归一化 → 第二阶段详情栏 → 第三阶段详细排期 → 第四阶段执行与看板。本轮只实现前两阶段；后两阶段为接手需求，不标记完成。当前代码基线 local-preview-1002，分支喜子改动效+企业知识库引用生首帧。本轮不部署。
