# PRD：灵枢 AI 前端交互 v1.0

> 更新日期：2026-09-23
> 适用范围：灵枢 AI 经营工作台全部用户端页面
> 业务依据：`PRD-灵枢AI当前系统-v3.md`
> 目标用户：不懂 AI、不懂拍摄和剪辑、也不熟悉复杂 SaaS 的企业老板与一线员工

## 1. 这份 PRD 解决什么问题

这份文档只定义前端怎么组织、怎么展示、怎么反馈，不重新定义后端业务逻辑。

当前主要问题：

- Agent 设置把相同选项重复放在每个 Agent 页面里，用户看不出哪些是全局规则、哪些只影响一个 Agent。
- 设置项文字太多，字段缺少先后顺序，大量表单机械地两列并排。
- 用户发出命令后，只看到一个笼统状态，不知道四个 Agent 分别在做什么。
- 复杂信息默认全部展开，真正重要的操作反而不突出。
- 某些页面用模糊百分比表达进度，无法对应真实任务和真实回执。

改造目标：

1. 一个页面只解决一个主要问题。
2. 通用规则只设置一次，Agent 页面只显示自己的个性规则。
3. 用户发出命令后，四个 Agent 的状态持续可见。
4. 首页保持简洁；详细日志、输入输出和异常原因点击后再看。
5. 所有进度来自真实任务、阶段、完成数量或平台回执，不编造百分比。

## 2. 全局交互原则

### 2.1 默认简单，细节按需展开

- 首屏只显示当前结论、下一步和最重要的状态。
- 原理解释、风险说明、日志、历史版本放进折叠区或弹窗。
- 默认每个区域只保留一个主操作。
- 一个字段只在最相关的位置出现一次。

### 2.2 先结论，后原因

推荐文案顺序：

1. 现在是什么状态。
2. 系统正在做什么。
3. 用户是否需要操作。
4. 需要时再展示原因和证据。

禁止只显示“处理中”“失败”“未知”。必须说明对象和下一步，例如“内容 Agent 正在合成《防晒乳通勤演示》；无需操作”。

### 2.3 真实状态

- 不用人为映射的 20%、50%、80% 冒充进度。
- 有可计算子任务时显示“已完成 3/7”。
- 没有可计算进度时显示真实阶段，如“逐镜分析”“等待审批”“平台处理中”。
- 发布成功必须有平台回执；发送成功必须有渠道回执。
- 断线时保留最后一次已确认状态，并明确显示“实时连接中断”。

### 2.4 状态颜色

系统状态颜色保持统一：

| 状态 | 颜色 | 用法 |
| --- | --- | --- |
| 正常、完成 | 绿色 | 已完成、已通过、已就绪 |
| 运行中 | 对应 Agent 专属色 | 动画只用于正在运行的对象 |
| 等待用户 | 琥珀色 | 待审批、待补资料、待确认 |
| 异常 | 红色 | 失败、权限失效、回执异常 |
| 未开始 | 灰色 | 未排队、未启用、无任务 |

Agent 专属色：

- 经营 Agent：紫色。
- 编导 Agent：蓝色。
- 内容 Agent：青绿色。
- 客服 Agent：橙色。

颜色只是辅助信息，所有状态仍必须有文字和图标。

## 3. 全局信息架构

左侧导航继续按业务对象组织：

1. 智能经营：首页、周目标、Agent 设置、实时执行与复盘。
2. 社媒运营：灵感中心、内容制作、发布与渠道、内容监控。
3. 平台投放：投放总览、投放计划、AI 托管。
4. 客户管理：智能客服、会话、报价和订单。
5. 智能体管理：企业知识库、记忆、定时任务。
6. 系统设置：渠道、集成、组织与权限。
7. 管理员能力只对有权限的账号展示。

导航要求：

- 不恢复上一个账号的页面到新账号。
- 页面刷新后恢复当前租户自己的最近页面。
- 从任务进入业务页面时保留返回路径和任务上下文。
- 已删除业务不得残留导航入口、空白页或旧链接。

## 4. 登录与首次进入

### 4.1 登录

- 登录和注册分成两个明确页签。
- 错误信息紧贴表单显示，说明是账号密码、网络还是账号状态问题。
- 网络抖动不主动清除登录凭据。
- 切换账号后回到“智能经营”，不继承前一账号页面。

### 4.2 新用户三步配置

1. 建立企业档案：企业、行业、市场、客户。
2. 确认重点产品：只选择本期重点，不重复填写产品详情。
3. 确认 Agent 设置：先看推荐摘要，需要时再修改。

默认展示系统推荐，不强迫小白逐项填写。用户点击“查看并修改设置”后才进入完整设置弹窗。

## 5. Agent 设置

### 5.1 设置结构

Agent 设置固定为五个页签，并严格按下面顺序展示：

1. 通用设置。
2. 经营 Agent。
3. 编导 Agent。
4. 内容 Agent。
5. 客服 Agent。

### 5.2 通用设置

通用设置只出现一次，包含：

- 本期经营目标、重点产品、目标市场和目标客户摘要。
- 运营阶段。
- 默认参与方式。
- 自主等级。
- 审批负责人。
- 全局行动边界。
- 总体计划审批与扩大经营范围的规则。
- 业务资产就绪度。

这些字段不得再出现在四个 Agent 页签中。

### 5.3 Agent 个性设置

| Agent | 只展示的个性设置 |
| --- | --- |
| 经营 Agent | 发布账号、每周草稿量、真实发布开关、复盘时区、跨周期处理规则、经营 Agent 审批红线 |
| 编导 Agent | AI 推荐范围、采集平台、来源、关键词、采集时间、回看天数、采集上限、编导 Agent 审批红线 |
| 内容 Agent | 主语言、出镜方式、自动交付语言、AI 画面开关、事实宣称红线 |
| 客服 Agent | 接待知识、草稿时间、审批截止、发送时段、触达频控、真实发送开关、客服 Agent 审批红线 |

### 5.4 排版规则

- 每个页签顶部先用一句话说明职责，不展示大段原理。
- 表单按“目标/输入 → 执行 → 对外动作 → 审批红线”排序。
- 默认采用单列阅读流；只有天然成对的字段才并排，如“主语言/出镜方式”“开始时间/截止时间”。
- 说明文字最多两行；更长内容放入“查看说明”。
- 强制规则直接锁定并标注“强制”，不要提供无效开关。
- 页面底部固定一个保存操作；校验失败时自动定位第一个问题。

## 6. Agent 实时工作台

### 6.1 默认展示

用户确认命令并开始运行后，在智能经营页顶部持续展示四张紧凑 Agent 状态卡：

- Agent 名称和专属色。
- 当前状态：未开始、排队、运行中、待确认、已完成、异常。
- 当前动作，只显示一行。
- 真实完成数量，例如 2/5。
- 最后更新时间。

没有任务的 Agent 显示“本轮未分配任务”，不能伪装成运行中。

### 6.2 运行效果

- 运行中的卡片显示呼吸点和轻量旋转图标。
- 卡片顶部使用连续移动的同色跑马灯线，表示任务仍在推进。
- 动画不能改变布局，不能遮挡文字。
- 系统开启“减少动态效果”时停用跑马灯和旋转，仅保留静态状态。

### 6.3 Agent 详情弹窗

点击任意 Agent 卡片后打开弹窗，展示：

1. 当前任务名称和状态。
2. 该 Agent 本轮任务列表。
3. 已完成数量和总数量。
4. 最近真实事件时间线。
5. 等待原因或错误原因。
6. “打开任务现场”按钮；只有存在真实任务时才展示。

弹窗不混入其他 Agent 的日志。关闭弹窗后用户仍停留在原页面。

### 6.4 实时数据

- 首次进入读取当前运行、任务和事件快照。
- 运行期间通过现有实时事件流更新。
- 重连后按事件序号补齐，不能让旧响应覆盖新事件。
- 卡片只读真实 `run / tasks / events / approvals` 数据。

## 7. 智能经营页面

首屏顺序：

1. 当前经营状态和本轮目标。
2. 四 Agent 实时状态卡。
3. 唯一下一步。
4. 待审批和待补资料。
5. 生产与交付结果。
6. 历史与复盘。

页面不默认展开所有任务日志。需要处理的项目优先于普通运行信息。

## 8. 灵感中心

- 首次进入先显示加载骨架和“正在读取真实存量”，不能先闪现 0。
- 每页显示最新 30 条，使用分页，不使用无限“加载更多”。
- 灵感发现、我的素材、拍摄任务用页签分开。
- 视频卡优先显示封面、平台、发布时间、可迁移性和分析状态。
- 已完成且版本有效的分析直接复用；外部新链接进入分析队列。
- 只有达到对应就绪等级的内容才可进入正式编导。
- 筛选变化时保留清晰的空状态和恢复入口。

页面顶部先展示产品、市场、沟通对象和数据来源组成的“发现范围”，不直接铺开大量关键词。“调整发现范围”使用右侧抽屉，里面只保留产品、市场/语言、沟通对象、少量行业入口词、对标账号/参考视频、已跟踪场景和排除项。保存前展示少量真实样本、可获得字段和预计成本。

主列表使用同一数据源切换“最近发现的场景、正在起量、与你的产品高度相关、创新参考”。卡片首屏只显示来源状态、命中场景、表现结论、置信度、推荐理由和收藏/不相关/用于创作操作；查询变体和采集工具信息放进“为什么出现”。总数、当前页、总页数和筛选条件必须来自同一个查询快照。翻页失败时保留当前页和库存数，并提供重试。

点击“用于创作”时，用户只选择已有任务或新任务，并可填写一句备注。分析等级不足时后台自动升级；只有升级失败、关键证据需要复核或权利不清时才阻塞。

## 9. 内容制作

首页只保留两个入口：

- 素材加工。
- 爆款裂变。

创建流程统一为：

1. 选择制作方式。
2. 确认产品、平台、语言和目标。
3. 系统盘点素材或参考视频。
4. 展示能否自动完成、缺什么以及替代方案。
5. 用户确认后开始制作。

逐镜页面固定突出前三秒钩子，并提供参考镜头、客户版本、素材来源和差异化说明。高级模型、提示词和供应商选择默认隐藏。

## 10. 发布、监控和客户页面

### 10.1 发布与渠道

- 每条待发布内容显示账号、平台、时间、版本和审批状态。
- 账号未连接时不能出现“已发布”。
- 发布失败显示平台返回原因和可执行的重试方式。

### 10.2 内容监控

- 区分平台原始数据、系统计算和暂不可用数据。
- 时间范围、账号范围和数据更新时间保持可见。
- 没有数据时说明是未接入、未同步还是该周期为零。

### 10.3 客户与订单

- 客户列表优先展示意向、最近动作和下一步。
- AI 草稿与真实发送严格区分。
- 价格、折扣、交期、付款和售后承诺必须显示审批状态。
- 订单只显示真实订单和真实状态，不根据聊天内容伪造订单。

## 11. 企业知识库、记忆和定时任务

- 企业资料只维护一份，Agent 页面引用而不复制。
- 未确认事实明确标记“待确认”。
- 记忆必须说明来源、使用范围和可删除入口。
- 定时任务卡显示任务名称、下次执行、关键词范围、目标数量和最近结果。
- 任务失败必须显示失败原因；Worker 离线与业务失败分开表达。

## 12. 通用组件

前端统一复用以下组件：

- `AgentLiveStatusRail`：四 Agent 简洁状态卡。
- `AgentDetailDialog`：单 Agent 任务与事件详情。
- `SettingsSection`：带标题和可折叠说明的设置区。
- `StateNotice`：加载、空、等待、异常、完成。
- `NextActionPanel`：页面唯一主操作。
- `TaskDetailDrawer`：任务详情和版本记录。
- `ApprovalCard`：审批对象、影响范围和决定。

## 13. 响应式和无障碍

- 桌面端四张 Agent 卡同排；平板两列；移动端单列或横向滚动。
- 设置弹窗桌面端最大宽度控制在可读范围，移动端使用全屏抽屉。
- 所有弹窗支持 Esc 关闭、焦点锁定和关闭后焦点恢复。
- 状态不能只靠颜色；按钮和输入框有明确可访问名称。
- 动画遵守 `prefers-reduced-motion`。
- 正文不小于 12px，主要表单不小于 14px。

## 14. 验收标准

### 14.1 Agent 设置

- 通用设置只出现一次。
- 四个 Agent 页签不再重复自主等级、参与方式、审批负责人和资产就绪度。
- 每个 Agent 页签只展示自己的工作流和审批规则。
- 默认页面的可见说明文字较改造前明显减少。
- 字段有明确先后顺序，不再机械地全部两列并排。

### 14.2 实时状态

- 运行后四个 Agent 同时可见。
- 状态、完成数量、当前动作都来自真实任务数据。
- 运行中的 Agent 有专属颜色、运行图标和连续跑马灯效果。
- 点击卡片只弹出该 Agent 的任务与事件。
- 无任务、等待、失败、完成均有独立状态。
- 断线时不清空最后状态，也不伪装继续运行。

### 14.3 全局体验

- 页面只有一个明显主操作。
- 加载时不先显示错误的 0。
- 所有失败均给出原因和下一步。
- 真实发布、真实发送和完成状态都有可追溯回执。
- 桌面、平板和移动端均可完成核心流程。
