# 灵枢 AI 全系统 UI 设计规范 v2.5

> 状态：实施基线
> 更新日期：2026-10-10
> 适用范围：灵枢 AI 桌面端、平板端与移动端的用户工作台、管理后台及创作工作台
> 目标读者：产品、设计、前端、测试与交付团队
> 组件基线：Ant Design 6.x；日历基线：FullCalendar；图表基线：Chart.js
> 权威性：本文件是后续前端实现与验收的唯一产品设计规范。其他历史设计文档仅供背景查阅，不再作为实施依据。
> 历史取代范围（旧稿已从现行文档集移除）：`灵枢AI前端设计规范-v1.md`、`design-system/lingshu-visual-system.md`、`design-system/visual-language-v1.md` 的视觉、排版、组件与交互规则

## 1. 本版结论

2026-10-09 本次确认：全产品采用纯白底和黑灰正文；侧边导航图标、按钮与选中态保持黑灰；主要操作按钮与发出的对话气泡使用蓝紫渐变。关键数字、内容区功能图标和图表通过协调的蓝、青、粉、紫、黄突出重点，避免页面只有白灰而缺少信息层级。本条及下文更新的 Token 取代此前森林绿视觉基线。

每次前端修改都必须先遵循本规范；规范未涉及的组件与交互，先查 [Ant Design 官方组件](https://ant.design/components/overview-cn/) 与设计说明，复用官方模式并适配本规范 Token。可复用的新决定补回本规范，共享组件优先于页面内另造实现。

2026-10-10 新增：吸收 Material 3 的物理运动、缓动与持续时间、过渡模式、语义排版。采用适合高密度经营工具的 **Standard motion**，不引入另一套 Material 组件或皮肤。外部文档是研究来源，不与本规范并列成为产品规则；差异先在本规范确认，再改代码。沿用白底、黑灰正文、中性侧栏和蓝紫主操作，不恢复解释性副标题。

2026-10-10 新增：灵小枢定位为全局决策与轻操作入口，首次打开必须优先显示最需要用户审批或确认的事项；Agent 运行日志、复杂数据和批量工作继续留在对应操作台。具体优先级、交互边界与后端版本校验见 10.13。

2026-10-10 新增：浏览器窗口变化、系统文字放大与 80%–200% 浏览器缩放必须保持结构稳定。页面不得使用 `transform: scale()`、CSS `zoom` 或脚本反向补偿缩放；布局应在统一断点重排，复杂工作台在自己的容器内滚动，不得挤压文字、媒体或操作区。具体规则见 3.9。

灵枢 AI 的视觉方向定义为 **经营编辑台**：像一套由经营者、编导、内容制作人员共同使用的专业运营系统，而不是通用 AI 生成器。产品识别度来自真实业务对象、排期、证据、成本和结果回执。渐变、边框动画与插画仅作为被严格限制的品牌强调和邀请，不得替代业务信息。

本版确定四项基础技术与设计决策：

1. **Ant Design 是基础组件层，不是默认皮肤。** 统一按钮、表单、表格、反馈和无障碍行为，再通过灵枢主题 Token、页面模板与业务复合组件建立产品风格。
2. **所有日历统一使用 FullCalendar 的事件模型和交互。** 月视图、周视图、日视图和列表视图不得继续分别手写。
3. **所有经营数据图表统一使用 Chart.js 的视觉配置和数据口径。** 现有 Recharts 只在迁移期共存，不得新增第三套图表方案。
4. **弹层采用 Ant Modal、Drawer、Popover 和 Popconfirm 的实现能力，外观与信息克制参考 GitHub Docs / Primer。** GitHub Docs 是完整页面参考，不是弹窗组件；复杂流程不得塞入大弹窗。

## 2. 产品视觉身份

### 2.1 视觉关键词

- 可信：数据、来源、状态和时间可追溯。
- 克制：用版式、分隔线和留白建立层级，不依赖阴影与装饰。
- 高效：高频动作靠近业务对象，异常早于日志，详情按需展开。
- 清晰鲜活：纯白画布、黑灰正文、蓝紫主操作与少量彩色重点，颜色服务于操作优先级和数据区别。
- 可执行：每个页面先回答“现在怎样、下一步做什么、谁负责、何时完成”。

### 2.2 灵枢特有的可见语言

以下元素比“AI”标签更能建立灵枢的产品识别度：

1. **经营刻度**：目标、成本、发布时间、完成数量使用统一数据带和刻度，不拆成悬浮卡片墙。
2. **内容证据**：产品事实、产品素材、云素材、爆款参考、生成结果必须有固定来源标识。
3. **工作轨道**：经营 Agent、编导 Agent、内容 Agent、质检与发布按真实工作顺序展示责任、预计时长和结果。
4. **账号与平台**：平台用官方 Logo，账号用真实名称；平台色不承担任务状态。
5. **真实媒体**：视频首帧、产品图、素材结构与成片预览是页面主视觉，不用通用 AI 插画代替。

### 2.3 禁止的“AI 模板风”

核心工作界面禁止：

- 大面积蓝紫霓虹渐变、玻璃模糊、持续发光边框和无意义光点；受控的品牌渐变与边框邀请遵循 4.4 与 10.1。
- 每个区块都使用 20px 以上圆角、重阴影和悬浮上移。
- 大量英文大写眉题，如 `SMART OPERATIONS`、`WEEKLY COMMAND CENTER`；中文业务标题应成为第一信息。
- 魔法棒、四角星、机器人头像被重复用作所有功能图标。
- `font-black` 被用于正文、说明和所有数字；字重必须服务信息层级。
- 一个页面堆叠多块渐变 KPI 卡、胶囊标签和装饰性假图表。
- 用“处理中”“AI 正在思考”等拟人化文案代替真实节点、责任 Agent、已完成数量和预计时间。

### 2.4 五张参考图的强制映射

参考图只定义对应场景，不允许把某一种视觉机械套到全站：

| 参考图 | 全应用使用范围 | 强制实现 | 禁止事项 |
| --- | --- | --- | --- |
| 图 1：媒体墙 | 所有视频库、图片库、素材库；日历中的内容/发布事件 | 媒体优先、稳定比例、统一间距；带固定详情与操作区的视频卡使用 `LsMasonryGallery layout="grid"` 对齐成行，纯图片浏览才使用 Masonry；日历事件使用同语法的 `LsCalendarEventCard` | 不允许因瀑布流列高差产生整卡空位；任务、账号、审批列表不得使用瀑布流；日历不得嵌入 Masonry 布局引擎 |
| 图 2：图片/视频状态 | 所有图片、视频、首帧、生成结果和预览 | 使用 `LsMediaStateFrame + LsProgressiveMedia` 表达加载、生成进度、成功和失败；占位尺寸与完成态一致 | 黑框、空白、仅写“处理中”、加载后布局跳动 |
| 图 3：渐变进度 | 所有加载进度、Agent 工作进度、视频生成、素材处理、资料完整度和配额 | 已知总量使用 `LsGradientProgress`；未知总量使用 Spin + 当前节点；完成/失败切换语义状态 | 页面内手写单色进度条、虚构百分比、用进度条冒充趋势图 |
| 图 4：Steps 流程弹窗 | 用户首次进入的新手引导，以及 2–4 步的短流程 | 首次引导使用 `LsFlowDialog`，在顶部显示 Steps，正文只解释当前一步，底部只有跳过/返回与唯一主操作 | 把完整工作台塞进弹窗、每次进入都重复打扰、关闭后丢失进度 |
| 图 5：数据分析页 | 智能经营、运营复盘、账号与内容表现、管理统计 | 使用统一筛选区、连续指标带、主趋势、分布/排行和可执行建议；图表由 `LsDataChart` 渲染 | 渐变 KPI 卡墙、假趋势、无单位/口径/时间范围的数据装饰 |

上述映射同时适用于桌面、平板与移动端；响应式只能改变列数、信息密度和弹层形态，不能改变业务语义或状态来源。

## 3. 基础设计 Token

### 3.1 色彩

| 角色 | Token | 色值 | 用途 |
| --- | --- | --- | --- |
| 操作主色 | `colorPrimary` | `#2563EB` | 链接、输入聚焦、主操作渐变起点 |
| 正文主色 | `colorText` | `#171717` | 标题、正文、侧边导航 |
| 页面画布 | `colorBgLayout` | `#FFFFFF` | 全局工作区 |
| 内容表面 | `colorBgContainer` | `#FFFFFF` | 面板、表格、弹层 |
| 次级表面 | `colorFillSecondary` | `#F5F5F5` | 选中、表头、次级分区 |
| 主边框 | `colorBorder` | `#D4D4D8` | 输入、控件、强调分隔 |
| 次边框 | `colorBorderSecondary` | `#E4E4E7` | 表格行、区域分隔 |
| 次级文字 | `colorTextSecondary` | `#52525B` | 说明、元数据 |
| 三级文字 | `colorTextTertiary` | `#71717A` | 时间、单位、弱提示 |
| 信息 | `colorInfo` | `#2563EB` | 进行中、系统信息 |
| 成功 | `colorSuccess` | `#168568` | 完成、通过、已连接 |
| 等待 | `colorWarning` | `#A16207` | 待确认、缺资料、临近截止 |
| 异常 | `colorError` | `#DC3545` | 失败、阻断、风险 |
| 人工介入 | `supportApricot` | `#FF6384` | 洞察或人工介入，不等于错误 |

规则：

- 状态必须同时显示文字或图标，不能只靠颜色。
- 平台 Logo 保留官方颜色，但平台颜色不得染整张任务卡。
- 正文与背景对比度不低于 4.5:1；图标与图形标记不低于 3:1。
- 侧边导航使用黑灰图标与文字，选中态为 `#F4F4F5` 浅灰底，不使用彩色按钮或彩色导航图标。内容区图标可以按功能选用色板。
- 主操作与发出消息渐变为 `#2563EB → #6546E8`，白色文字；hover 为 `#1D4ED8 → #5635D6`。真实进度使用 `#36A2EB → #9966FF`。渐变不能覆盖页面大底或代替状态语义。
- 重点对话框头部可以使用淡蓝、淡紫、淡粉的浅渐变并配黑字；指标用彩色数字、小图标或细色条突出，不把所有卡片做成重彩渐变。
- 渐变不可改变语义：成功、等待、失败仍分别使用固定语义色，并必须带文字或图标。

### 3.2 图表色板

图表序列固定按以下顺序分配，并同时用线型、点型或图案区分：

| 顺序 | 色值 | 用途建议 |
| --- | --- | --- |
| 1 | `#36A2EB` | 蓝色序列 |
| 2 | `#FF6384` | 粉色序列 |
| 3 | `#4BC0C0` | 青色序列 |
| 4 | `#FFCD56` | 黄色序列 |
| 5 | `#9966FF` | 紫色序列 |
| 6 | `#FF9F40` | 橙色辅助项 |
| 中性 | `#A1A1AA` | 基准、未分类、历史参考 |

图表采用白色底与中性浅灰网格。相同指标跨页面保持同色，面积填充使用同序列的低透明度颜色；禁止 3D 图表、随机配色和仅靠颜色表达数值。数据序列颜色不自动表示成功或失败。

### 3.3 字体与数字

```css
--font-sans: "SF Pro Text", "PingFang SC", "Noto Sans SC", ui-sans-serif, system-ui, sans-serif;
--font-mono: "SFMono-Regular", ui-monospace, monospace;
```

以下为灵枢基于 M3 语义角色适配的中文工作台刻度，**不是照搬 M3 默认字号**。字号和行高单位为 px；共享 Token 与语义类是唯一实现入口。

| 语义角色 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| display | 36 / 44 | 600 | 独立品牌或少量关键大数；不用于工作台标题 |
| headline | 28 / 36 | 600 | 登录/独立流程标题；业务页 H1 按 5.1 隐藏 |
| title-large | 20 / 28 | 600 | 一级区块、主要弹层标题 |
| title-medium | 16 / 24 | 600 | 卡片、小节、次级弹层 |
| title-small | 14 / 22 | 600 | 紧凑分组、表单分区 |
| body-large | 16 / 24 | 400 | 阅读型正文、会话消息 |
| body-medium | 14 / 22 | 400 | 默认正文、列表、输入、表格 |
| body-small | 12 / 18 | 400 | 次要元数据、单位、时间 |
| label-large | 14 / 20 | 600 | 主操作、Tab、关键标签 |
| label-medium | 12 / 18 | 500 | 状态标签、紧凑控件 |
| label-small | 11 / 18 | 500 | 仅非关键媒体角标；不得用于正文、错误、核心操作 |
| metric | 24 / 32 | 600 | KPI，等宽数字 |

- 英文只用于平台名、专业缩写或用户真实内容，不用英文装饰眉题。
- 数字使用 `font-variant-numeric: tabular-nums`；金额、百分比、时间单位必须全系统统一。
- 产品工作区只使用上述系统无衬线字体；装饰字体只允许出现在品牌插画或营销素材中，不能进入导航、表格、卡片和表单。
- 同一层级只能有一套字号、字重和行高；`font-black`不得出现在产品正文，最高可视字重收敛为 700。
- 中文标题按语义换行，不使用字符级强制断行；正文与列表信息使用 `overflow-wrap: break-word`，URL、ID 和不可分隔的长串才使用 `overflow-wrap: anywhere`。
- 单行截断只用于有详情入口的次要元数据；客户名、任务标题和最后一条消息默认允许两行，不能因为窄列而丢失关键语义。
- 默认字距为 normal，不为中文正文全局添加负字距。数据使用等宽数字，不给普通段落强加等宽字体。
- 不把 9–10px 微小文本用于业务信息；媒体角标最低 11px，其余辅助信息最低 12px。浏览器文字放大到 200% 时允许局部换行/滚动，不用固定行高容器裁掉文字。
- 语义角色不改变 HTML 语义：视觉小标题仍应具有正确 heading 层级；不为了样式把所有文字改为 h1，也不添加已删除的页眉和说明。

### 3.4 间距、圆角、阴影与密度

- 基准间距：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。
- 控件高度：紧凑 32px、默认 36px、主要操作 40px。
- 控件圆角：6px；默认容器 8px；弹层 10px；媒体卡 8px。
- 只有状态 Tag 可以使用胶囊圆角；大容器禁止胶囊化。
- 普通卡片无阴影，以边框和留白分层；阴影仅用于 Modal、Drawer、Dropdown、Popover。
- 参考 Messenger 的框架密度：纯白页面和 1px 中性栏分隔线建立层级；列表选中态局部浅灰，发出消息用蓝紫渐变，不为每个子项反复加框。
- Hover 只改变背景、边框或文字，不整体上浮、缩放或发光。
- 高密度表格允许局部紧凑模式；全站不得启用全局紧凑模式。
- 连续列表项之间至少保留 6px 间距，或者共用单一 Divider；禁止两个带独立边框的列表项零间距相贴，造成双线、重叠或视觉粘连。
- 所有 Flex/Grid 子项默认 `min-width: 0`；媒体、图表、表格和弹层不得超出所在容器，需滚动时由明确的内部滚动容器承担。

### 3.5 图标与媒体

- 现阶段继续使用 Lucide 作为产品图标，避免迁移期同时出现两套图标语言；Ant 内部图标由共享适配层处理。
- 不在同一功能上混用 Lucide 与 Ant 图标。
- YouTube、TikTok、Instagram、Facebook、Messenger 等使用官方 Logo。
- 视频卡必须保留封面、时长、平台、来源与可用状态；图片和视频加载失败提供占位与重试。
- 工作区和登录表单底色统一纯白；登录页左侧独立品牌视觉区保留 `lingshu-water.jpg` 水纹图片，不把该图片延伸到表单或登录后的业务工作区。既有品牌 Logo 与真实媒体继续保留。

### 3.6 物理运动系统

M3 当前的物理方案与既有 easing/duration 并非两个叠加的动画：空间关系使用弹簧，CSS、Ant 与颜色/透明度使用受限时长曲线。灵枢采用 Standard 的克制感；禁止给同一属性同时叠加 CSS transition 和 Motion 动画。

| 空间 Token | stiffness | damping ratio | mass | 使用范围 |
| --- | --- | --- | --- | --- |
| fast | 1400 | 0.9 | 1 | 小范围控件位置变化 |
| standard | 700 | 0.9 | 1 | 侧栏/关联详情面板展开收起 |
| slow | 300 | 0.9 | 1 | 经评审的全屏空间转场；非默认 |

数值取自 AndroidX Material 3 StandardMotionTokens。Motion 的 `damping` 是阻尼系数而非上述阻尼比，须按 `2 × ratio × sqrt(stiffness × mass)` 转换；不得直接传入 0.9。弹簧不再指定 duration，不人为制造 velocity；快速反向操作从当前位置继续，不排队等待旧动画结束。颜色/透明度不得过冲，空间过冲不得裁切正文或遮挡操作。

- 默认不添加拖拽惯性、卡片浮起、摇摆、呼吸、纸屑或持续边框追光。成功使用静态成功态或一次短淡入。
- Ant Modal/Drawer 使用主题内置动效，不再外包一层 spring，保留焦点管理、键盘与关闭行为。
- 宽度动画仅用于受控应用壳，不对表格行、媒体墙、整页高度做逐帧布局动画。大列表禁止逐项延迟，数据刷新不得重新播放整页入场。

### 3.7 缓动与持续时间

下表是从 M3 时间刻度选择的产品子集，不把完整 50–1000ms 范围暴露给业务页。

| Token | 时长 | 场景 |
| --- | --- | --- |
| instant | 0ms | reduced-motion、直接数据刷新、紧急反馈 |
| fast | 150ms | hover、focus、颜色、按钮反馈 |
| exit | 200ms | 非空间元素退出 |
| enter | 250ms | 媒体就绪、首次内容淡入 |
| standard | 300ms | 局部流程或关联状态过渡 |
| slow | 400ms | 仅较大空间的非弹簧过渡 |

曲线：standard `cubic-bezier(0.2, 0, 0, 1)`；enter/decelerate `cubic-bezier(0, 0, 0, 1)`；exit/accelerate `cubic-bezier(0.3, 0, 1, 1)`。Ant fast/mid/slow 分别映射 150/250/300ms。hover 不改变几何尺寸，业务流转不等待动画完成。进度时长不是任务耗时，不允许定时器伪造 5%→90% 的进度。

实现约定：`src/lib/designTokens.ts` 提供 `lsMotion`、排版与 CSS 变量；`LingshuProvider` 同时提供 Ant 主题与 MotionConfig。页面复用 `lsMotion`，不再自定 spring、秒数、easing 或 stagger。CSS 使用 `--ls-motion-*` 与 `--ls-ease-*`。Chart.js 使用同源时长，但其专用曲线不冒充 CSS cubic-bezier。

### 3.8 过渡模式与减少动态效果

| 对象关系 | 模式 | 灵枢实现与边界 |
| --- | --- | --- |
| 卡片 → 对象详情 | container transform 的关联原则 | 保留封面/名称/选中来源，由共享 Ant Drawer 打开；不为了形变复制播放器或破坏焦点 |
| 同一流程前后步骤 | shared axis | Steps 保持原位，内容最多 8px 位移并淡入；输入值与错误不丢失 |
| 无关联 Tab / 一级页面 | fade through 的层级原则 | 只做短透明度过渡，不左右飞入、不缩放整页；不得重挂载已缓存的工作台 |
| 菜单、反馈、媒体就绪 | fade | 进入250ms/退出200ms；颜色150ms，不弹跳 |
| 侧栏与关联辅助面板 | standard spatial | 可中断的标准弹簧，不改变当前编辑内容 |
| 图表刷新、日历换日期 | stable update | 图表原实例更新，首次可短入场；日历保持原生导航与滚动，不包装第二层全屏动画 |

- 应用首次渲染即读取 `prefers-reduced-motion`，运行中切换也立即生效。Ant 关闭 motion；Motion 禁用空间动画；共享 CSS、Chart、Skeleton、装饰层与 JS smooth scroll 同步退化为即时状态。
- Reduced-motion 下不运行纸屑、呼吸、弹跳、列表 stagger；真实任务仍保留文字/静态进度，不能把关闭动画误当成任务结束。操作反馈、加载状态及无障碍语义必须保留。
- 页面切换不延迟可点击时间、不重置滚动/编辑状态；不得把动画结束回调用作提交、扣费、分析或发布的触发条件。
- 验收至少覆盖：快速连续开关、切 Tab 后返回、动态切换减少动态效果、键盘打开关闭弹层、媒体成功/失败、图表数据更新、窄屏与 200% 字号。正常动画不闪白、不改变文案位置、不引入页面级横向滚动。

### 3.9 布局稳定性、窗口变化与浏览器缩放

- 浏览器缩放视为可用布局宽度变化，不反向侦测或抵消用户缩放；禁止对 `html`、`body`、`#root`、应用壳或页面工作区使用 `transform: scale()`、CSS `zoom`。
- 应用壳固定为“可折叠侧栏 + 可收缩主区 + 可选固定宽度辅助栏”。侧栏展开/收起宽度必须同时约束 `width / min-width / max-width`；主区和页面栈必须使用 `min-width: 0`，不得把兄弟区域挤出视口。
- 移动断点统一为 `767px`，桌面与移动的 JS `matchMedia`、Tailwind/CSS 媒体查询必须使用同一边界，禁止 760/768 等相邻断点同时控制同一壳层。
- 所有 Flex/Grid 直接子项默认 `min-width: 0`。需要保持列宽的表格、日历、时间轴、媒体编辑器必须把 `min-width` 放在内部内容层，并由最近的显式 `overflow-x: auto` 容器承接；禁止让整页横向滚动。
- 图片、视频、Canvas 与 iframe 默认不得超过所在容器；封面和预览使用固定 `aspect-ratio` 或稳定占位，加载前后不得改变卡片尺寸。
- 标题、正文、表头和数据值允许语义换行；URL、ID 与连续英文长串使用 `overflow-wrap: anywhere`。固定高度只能用于单行控件，不得用于可能放大或换行的业务文字。
- 断点只改变列数、信息密度和弹层形态，不改变操作顺序或业务语义。进入窄布局后，主操作仍在对象附近，次要操作允许换行但不得覆盖正文。
- 验收尺寸至少覆盖 `1440×900`、`1280×720`、`1024×768`、`768×1024`、`390×844`，并检查桌面浏览器 80%、100%、125%、150%、200% 缩放。验收标准是无重叠、无裁字、无组件拉伸变形、无非预期页面级横向滚动。

### 4.4 禁用与慎用

- Ant `Calendar`：禁用；产品日历统一使用 FullCalendar。
- Ant Charts：禁用；业务图表统一使用 Chart.js。
- `BorderBeam`：默认禁用；仅允许在首次邀请、AI 建议候选或新能力发现中短时出现，不能表达状态、选中、焦点、校验或进度；`prefers-reduced-motion` 下完全关闭。
- `Masonry`：仅可用于灵感素材墙，任务与状态列表禁用。
- `Carousel`：不得承载告警、审批和唯一操作。
- `FloatButton`：只允许全局帮助、反馈或返回顶部，不能作为核心新建入口。
- `Switch`：仅表示点击后立即生效的二元状态；随表单提交的选择使用 Checkbox 或 Radio。
- `Tooltip`：只用于无文字图标的短说明，不能承载关键内容、长文本或操作。
- `Card`：只承载独立对象；卡片嵌套不超过一层。
- Ant Design Pro：不得直接成为整站皮肤；先完成基础组件与灵枢 Token，再单独评估 ProTable / ProForm。

## 5. 页面骨架与业务模板

### 5.1 全局应用壳

- 桌面侧栏展开 176px，收起 60px；移动端收起仅保留 56px 图标轨道，展开导航使用 Drawer，不永久挤压主内容。展开态导航正文使用 14px，品牌名称使用 15px，禁止用宽栏和小字制造无效留白。
- 一级页面不再重复显示与左侧导航同名的可见 H1 和说明副标题；文档结构保留屏幕阅读器可读的唯一 H1。页面级操作直接进入首个工具栏，范围与更新时间放入对应数据区或可视化时间控件。对象详情、流程步骤、弹层标题不受此规则影响。
- 页面与业务区块标题下不显示“本页做什么、点击后看什么”一类解释性副标题。日期、时区、数量、来源、同步状态等可操作元数据应并入标题行的 Tag、时间控件或状态区；错误恢复、空状态、表单约束、风险与不可逆操作仍必须保留必要说明。
- 搜索、内容类型、收藏状态与“更多筛选”在桌面端固定为同一行；空间不足时允许工具栏自身横向滚动，不得拆成两行。结果总数进入 Tab 或分页，不再单独占用一条统计提示栏。
- 全局消息不得占用独立右侧栏或形成页面右侧缝隙；需要用户立即处理的事件使用页内 Alert，需要稍后查看的结果进入对应业务页的通知入口。
- 面包屑仅在层级超过两级时出现。
- 页面最大内容宽度 1440px；全屏日历、创作工作台和会话页可突破该限制。
- 顶部与侧栏不使用渐变、毛玻璃或重阴影。

### 5.2 五类标准页面

## 6. FullCalendar 统一规范

### 6.1 统一视图

| --- | --- | --- |
| 月度发布总览 | `dayGridMonth` | 发布与渠道、经营月计划 |
| 精确到小时的周排期 | `timeGridWeek` | 内容制作、发布时间、待拍任务 |
| 单日执行 | `timeGridDay` | 当日 Agent To Do、拍摄日程 |

### 6.2 日历外观

- 工具栏顺序固定：新增/主要动作、今天、前后切换、当前日期、视图切换、筛选。
- 星期与日期使用中文；周一作为工作周起点时必须与目标市场规则一致。
- 周末只用极浅中性背景区分；今天使用 1px 蓝色边框或浅蓝底，不使用大色块。
- 事件颜色表达生命周期状态，平台由官方 Logo 表达。
- 月视图事件显示“平台 Logo + 账号简称 + 标题”；周/日视图再显示时间和缩略图。
- 同日溢出使用 `+N` 入口；Popover 只做快速浏览，点击事件进入 Drawer。
- 日历内容区为平面网格，不在每个日期单元套 Card。
- 日历中的“瀑布流”统一指 FullCalendar 原生日期列/时间列内的连续级联事件卡片流，不指 Ant `Masonry` 或 CSS 多列布局。同一日期/时段的 `LsCalendarEventCard` 按开始时间与稳定次序自上而下排列，使用统一间距，不得重叠、跨列重排或在媒体加载后换列；月/全年视图使用紧凑卡和原生 `+N` 溢出，周/日/列表视图使用媒体优先卡。日期、时区、拖拽、键盘与事件 Drawer 仍由 FullCalendar 原生模型负责。
- `timeGridWeek` / `timeGridDay` 必须显示明确但克制的小时刻度；有精确时间的事件进入对应时段，无精确时间但需要执行编排的任务使用有证据的“执行窗口”，不得补造 09:00 等假时刻。经营周排期逻辑范围默认覆盖 08:00–22:00，左轴默认每 2 小时标注一次；仅在确有全天事件时显示全天区。只有日期的发布计划继续使用 `allDay`，在左侧明确显示“全天 / 时刻待定”，不展示虚假的小时轴。
- 所有日历使用视口受限的共享工作区：桌面默认内容高度为 `clamp(320px, calc(100dvh - 280px), 720px)`，页面可在共享属性上收紧可用高度，但不得恢复内容自增高。工具栏留在页面中，超出排期只由 FullCalendar 内容区内部纵向滚动承载；页面本身不得跟随事件数量无限增长，也不得再叠加第二层滚动容器。
- 账号×日期的矩阵排期是 FullCalendar 外的保留例外，必须使用共享 `LsScheduleViewport`：日期头吸顶、内部滚动、视口受限，且复用与日历相同的一次性渐入和减少动效规则；不得为矩阵补造小时轴。
- 事件卡首次进入日历可视区时使用一次 `opacity + translateY(≤8px)` 渐入，统一使用 `--ls-motion-enter` 与 `--ls-ease-enter`，同一事件 ID 刷新、换视图或重新挂载不得重播，不使用 stagger 或 delay。键盘聚焦必须立即显示；`prefers-reduced-motion` 开启或运行中切换后立即显示全部卡片并断开观察。

### 6.3 交互

- 事件 hover 可显示轻量摘要，但所有内容必须能通过键盘 focus 或点击获取，不能只依赖 hover。
- 点击事件打开右侧 Drawer；Drawer 显示缩略图、标题、平台账号、责任 Agent、制作时长、交付时间、成本和状态。
- 仅有排期编辑权限时允许拖拽与缩放；拖拽后必须二次确认跨账号、跨日或已进入制作的变更。
- 必须提供键盘可操作的“移动到日期/时间”替代入口。
- 所有时间显式标注时区，如“北京时间”或“目标市场当地时间”；后台保存 IANA 时区。
- 日历更新保留旧数据并局部显示同步状态，不整页清空或闪烁。

### 6.4 Premium 决策门

`timeline`、`resourceDayGrid`、`resourceTimeGrid` 和 `resourceTimeline` 均属于 FullCalendar Premium。真正的“账号或 Agent 为行、时间横向”的工作排期只有两种合规方案：

1. 采购商业许可，使用 `resourceTimelineWeek/Month`；大资源量启用虚拟化。
2. 暂不采购，使用 Standard 的 `timeGridWeek + listWeek`，事件标题带账号和平台；现有自研泳道只维护、不扩张。

不得把 Premium 试用、非商业许可或 AGPL 路径直接用于闭源商业生产。

## 7. 弹层与详情统一规范

### 7.1 GitHub 参考的正确用法

GitHub Docs 文章页适合作为“克制、可深链、层级清楚”的完整页面参考；弹层行为以 GitHub Primer 的 Dialog / Overlay 规范为参考。灵枢的实际实现仍统一使用 Ant 组件，避免引入第二套组件库。

### 7.2 浮层选择

| 需求 | 组件 | 示例 |
| --- | --- | --- |
| 1–2 句短说明 | Tooltip | 无文字图标含义、字段单位 |
| 轻量摘要或少量就地操作 | Popover / Dropdown | 日历事件快览、表格行操作、筛选 |
| 简单确认或单一短表单 | Modal | 发布确认、覆盖确认、取消任务 |
| 不中断主页面的详情或编辑 | Drawer | 视频详情、逐镜分析、客户详情、任务详情 |
| 局部危险操作 | Popconfirm | 删除单条草稿、移除一个标签 |
| 多步骤、侧导航、可分享或可深链 | 完整页面 | 周计划确认、内容制作工作台、Agent 设置、复杂产品编辑 |

### 7.3 尺寸与结构

| 类型 | 桌面宽度 | 适用内容 |
| --- | --- | --- |
| 小 Modal | 400–480px | 确认、单字段输入 |
| 标准 Modal | 560–640px | 短表单、选择器 |
| 大 Modal | 720–840px | 批量复核、媒体选择；不得发展为完整页面 |
| 标准 Drawer | 480–560px | 对象详情、轻编辑 |
| 媒体 Drawer | 720–880px | 视频、逐镜、素材结构 |

统一结构：标题、可见关闭按钮、可滚动正文、固定页脚。标题必填；说明仅保留必要的风险、校验或业务信息，不增加解释性副标题。页脚右侧最多一个主按钮，危险操作与普通主按钮不并列强调。

### 7.4 行为与无障碍

- 打开后焦点进入弹层，Tab 不离开 Modal / Drawer；关闭后焦点返回触发器。
- 支持 Esc 和可见关闭按钮；未保存表单不可点击遮罩直接关闭。
- 使用 `role="dialog"` 或 `alertdialog`、明确的 name / description 和 `aria-modal`。
- 背景不可交互；正文滚动时头部与页脚固定。
- 窄屏 Modal 转底部面板或全屏，Drawer 转全屏。
- 原则上禁止嵌套弹层；必须嵌套时最多两层，并仅关闭最上层。
- Tooltip 与 hover 摘要不得承载卡点、成本、状态或唯一操作。

### 7.5 产品内建议改造点

- 爆款视频与对标账号：卡片点击进入媒体 Drawer；完整逐镜分析使用可深链详情页。
- 周计划确认：改为完整日历页面，不再使用超宽、超高 Modal。
- 素材选择和批量复核：使用大 Modal，固定操作区。
- 发布确认和危险重试：使用小 Modal / Popconfirm。
- 客户、订单、内容任务、账号：列表内快速查看统一右侧 Drawer。
- Agent 设置、渠道接入、复杂企业资料：使用完整页面或流程工作台。

## 8. Chart.js 数据可视化规范

### 8.1 图表选择

| 要回答的问题 | 图表 | 灵枢示例 |
| --- | --- | --- |
| 随时间如何变化 | Line / Area | 内容产量、播放量、询盘、成本、制作时长 |
| 多账号或平台谁高谁低 | 横向 Bar | 账号周更、渠道效果、Top 内容 |
| 每周状态如何构成 | 100% Stacked Bar | 排队、制作、验收、发布、失败 |
| 计划与实际如何对比 | Mixed Bar + Line | 计划产量与完成率、花费与转化 |
| 两指标是否相关 | Scatter / Bubble | 匹配分与表现、成本与播放、发布时间与询盘 |
| 少量类别占比 | Doughnut | 最多 5 类的内容来源；非首选 |
| 单目标完成情况 | Progress / Statistic | 不使用 Gauge 或环图 |

Radar、Pie、Polar Area 不用于关键经营判断；漏斗优先使用横向分段 Bar 和明确数字，不为形状牺牲可读性。

### 8.2 智能经营数据映射（2026-10-10 首页收口）

| 页面 | 必须展示的图表 | 明细载体 |
| --- | --- | --- |
| 经营总览 | 账号、询盘、内容、投流健康度比较；按账号的阶段目标与提升空间 | 总经营分、已评估覆盖度、按需展开的评分口径；底部下一轮建议 |
| 账号矩阵 | 保留账号职责、配置和工作排期，不重复纯统计区 | 可编辑账号 Table / Drawer |
| 数据复盘 | 账号、询盘、投流三个一级数据区；有真实序列才展示趋势 | 总量 → 平台/账号/渠道/报告 → 内容/归因/日明细，按需展开 |

- 删除独立“内容队列” Tab；旧内容队列入口兼容跳转数据复盘，单条生产详情仍可访问。
- 总经营分仅由可核验、已评估的领域形成，并同屏显示覆盖度；缺失项不得补零、虚构目标或用参考数替代真实结果。询盘归因质量不冒充成交能力，广告消耗不直接换算投流分。
- “评分口径与数据覆盖”必须优先可视化：用横向堆叠 Bar 对比四领域的“已评分 / 待数据 / 不适用”，同屏提供领域覆盖进度和指标覆盖图谱；覆盖率只按“已评分 ÷（已评分 + 待数据）”计算，不适用项排除分母，缺失分保持“— / 待数据”而不画成 0。完整文字口径保留在按需展开中。
- 数据复盘不得将不同币种直接相加；周期统计与累计平台回传明确分开；没有转化或收入回执时不计算 ROAS。
- 首页发布日历移除独立标题/计数行，贴齐周计划容器两侧。紧凑工具栏合并日期、时区和数量，不重复元数据行；仍保留键盘入口与必要状态。
- 日历视频卡使用稳定竖版舞台（9:16），缩略封面使用 `cover + center` 从卡片顶边开始铺满，不留上下信箱空白；完整封面在详情中使用 `contain` 查看，不强制转为横版。首页紧凑模式只压缩工具栏和卡片信息区；周/日媒体事件继续使用“上方竖版媒体、下方标题”的爆款视频卡语法。默认“已计划”不在封面重复显示，状态保留在详情与无障碍名称中；需处理、失败等异常状态仍必须显示。媒体舞台随日期列宽度保持 9:16，并以 180px 封顶避免日视图过度拉长。首页日历工作区上限为 640px，同时不得超过当前视口的可用高度；全部排期由 FullCalendar 内部纵向滚动承载，不裁掉事件或改为 `+N`；完整文案在事件详情查看。

### 8.3 图表视觉限制

- 每张图有中文标题；单位与时间范围合并为紧凑元数据或轴标签，不再新增解释性副标题。口径详情按需查看，核心数值不可只藏在 Tooltip。
- 超过 1 个数据集必须有图例；图例名称与表格列名一致。
- Line 最多 5 条；堆叠 Area 最好不超过 3 条、硬上限 5 条。
- 普通 Bar 最多 10 条；Grouped Bar 每组最多 4 类且最多 6 组。
- Stacked Bar 每条最多 5 段且最多 10 条；Pie / Doughnut 最多 5 片。
- 线宽 2px；多序列同时使用实线/虚线、点型或图案，不能只靠颜色。
- Tooltip 只补充精确值，不承载结论或唯一信息。
- 简单图提供“查看数据表”；需运营导出的图提供 CSV 下载。

### 8.4 空、错与演示数据

- 没有真实数据时不画零趋势、不造波动线；显示 Empty、缺少的数据源和恢复动作。
- Mock 或演示数据必须在图题、图例和数据表中持续标记“演示数据”，不得与真实值同视觉层级。
- 数据同步失败保留最后一次确认的数据，显示更新时间和错误，不清空为 0。
- 指标口径、统计范围和时区必须能从图旁查看。

### 8.5 无障碍与性能

- Chart.js Canvas 必须提供 `role="img"` 和准确 `aria-label`，并在旁边提供文字结论与可展开数据表。
- 大数据预整形后使用 `parsing: false`、`normalized: true`；折线图使用降采样。
- 高负载图关闭动画、固定合理轴范围并限制 tick 数量。
- 每个响应式 Canvas 使用独立、相对定位的父容器。
- 图表按需注册并 tree-shake；不得把完整 Chart.js 全量打入每个页面。

## 9. 状态、反馈与长任务

### 9.1 状态字典

| 状态 | 色彩 | 必须显示 |
| --- | --- | --- |
| 未开始 | 灰 | 等待条件或计划时间 |
| 排队中 | 中性蓝 | 队列位置或预计开始时间 |
| 执行中 | 信息蓝 / 蓝紫进度 | 当前节点、责任 Agent、已完成数量、预计剩余时间 |
| 等待用户 | 琥珀 | 缺少什么、影响什么、唯一下一步 |
| 失败 | 红 | 失败节点、已保留结果、重试或人工处理 |
| 完成 | 绿 | 结果数量、完成时间、查看结果入口 |
| 暂停 | 灰棕 | 谁暂停、如何恢复 |

平台色、Agent 身份色、状态色三者不得混用。

### 9.2 反馈层级

| 反馈 | 组件 | 存续时间 |
| --- | --- | --- |
| 保存、复制等轻量成功 | Message | 2–4 秒 |
| 后台完成、需要后续动作 | Notification | 可关闭，带结果入口 |
| 页面持续风险或阻断 | Alert | 直到条件恢复 |
| 重要流程终态 | Result | 用户确认离开前保留 |
| 首次加载 | Skeleton | 与最终结构一致 |
| 局部短等待 | Spin | 不覆盖全页 |
| 可计算长任务 | Progress | 显示真实阶段与数量 |

所有改变数据或启动任务的动作必须具备：即时 loading、成功结果、失败原因、可执行下一步。不得只显示一个旋转图标或“处理中”。

### 10.1 品牌渐变按钮

- 渐变按钮只用于页面或流程的唯一主操作，例如“开始本周任务”“生成成片”“发送消息”。Ant Design 的 `Button type="primary"`、`LsBrandAction` 与兼容旧页面的 `.btn-primary` 统一使用此样式；普通保存、筛选和返回使用 `Button type="default"`，删除使用危险操作语义，不套品牌渐变。
- 同一区域最多一个渐变按钮，不与另一枚 Primary Button 并列争抢。
- 默认、hover、active、disabled、loading、focus-visible 必须完整；禁用态移除渐变，loading 不改变按钮宽度。
- 不允许用渐变装饰普通 Card、Tag、输入框或导航。
- 灵小枢的“待你决定”概要气泡是受控例外：它是从对话进入单项决策详情的短时提示入口，只能复用 `--ls-action-gradient`，同时只显示一张，不得将该例外扩展到普通内容卡、数据卡或审批详情卡。

### 10.2 渐变进度

- 本规则是全站唯一进度样式：视频生成、素材处理、Agent 工作节点、资料完整度和配额使用均必须使用 `LsGradientProgress`，不得在业务页重新拼装单色 `div` 进度条。
- `line` 表示长任务、资料完整度与生产进度；`circle` 表示单一目标；`dashboard` 表示容量或接近上限的指标。
- 百分比必须来自真实数据。未知进度用 Spin + 当前节点，不能显示虚构百分比。
- 渐变仅编码“从开始到完成”的连续变化；失败、超限和阻断切换到语义色。
- 中心可显示百分比、完成图标或数值，不同时堆叠三者；进度文字可被读屏获取。

### 10.3 足不出户与流程弹层

- 用户首次进入的新手引导使用 `LsFlowDialog`：顶部 Steps、中部当前步骤说明、底部“跳过”与唯一主操作。关闭弹窗后可继续在页内高亮目标，完成当前操作后再打开下一步。
- 2–4 步、可在 10 分钟内完成且不要求深链的流程可使用 `Modal + Steps + Form`。
- 复杂周计划、内容制作、产品导入和账号设置必须使用完整页面；弹窗不能套侧栏模拟一个新应用。
- 当前步骤、已完成步骤、阻断原因和退出后的保存策略必须明确；关闭后焦点回到触发点。

### 10.4 加载与即时反馈

- 首次页面或卡片加载使用 Skeleton；局部等待使用 Spin；已知总量使用 Progress；按钮提交使用 Button loading。
- 预计超过 2 秒必须显示当前节点或解释；可取消任务提供取消；后台长任务离页后继续并可恢复。
- 输入校验贴近字段且持续存在；短成功用 Message，跨页面或带操作的消息用 Notification，阻断用 Alert/Result。
- 自动刷新不得清空旧数据；新内容到达先提示“有更新”，由用户决定是否刷新高密度列表。

### 10.5 紧凑字段组合

- 电话区号 + 电话、筛选条件 + 搜索、金额 + 币种、时间范围等强关联字段使用 `Space.Compact`。
- 组合后的 Tab 顺序、错误归属和读屏名称仍需独立明确；不得为了视觉紧凑而把无关动作粘在一起。

### 10.6 头像组

- `Avatar.Group` 用于显示责任人、客户参与者、协作 Agent；超过可见数量用 `+N`，Popover 展示完整清单。
- 头像无图片时使用稳定的姓名首字或平台身份，不随机换色；状态点与未读点不能混用。

### 10.7 渐进媒体与瀑布流

- 所有图片和视频先展示比例稳定的占位，再显示加载、生成百分比、成图/成片或失败重试；加载过程不能引起布局跳动。媒体状态必须经由 `LsMediaStateFrame + LsProgressiveMedia`，不使用空白黑框或纯文字占位。
- 视频卡在进入视口后主动解析可用封面或首帧，不能依赖鼠标悬停才加载；分析暂停、取消等任务状态不得遮住已存在的媒体画面，并必须在详情中提供“继续分析”入口。
- 多图预览使用 Ant Image PreviewGroup；敏感或未发布内容可加 Watermark。
- 视频库中带标题、指标和固定操作区的完整卡片统一使用等宽网格并对齐行高，避免 Masonry 因卡片高度不同在下一行制造整列空位；仅纯图片/纯媒体浏览可使用 Masonry。卡片保持首帧、时长、平台、来源、产品关联、收藏与可用状态。任务队列、账号和审批禁用瀑布流。
- 日历不使用 Masonry 布局引擎，但内容/发布事件必须使用同一套“媒体优先”卡片语法：周/日/列表视图显示首帧、平台账号、标题、时间与状态；月视图空间不足时保留平台、标题和状态，详情 Drawer 展示完整首帧。

### 10.8 数据看板

- 全部数据页固定为：筛选范围 → 连续指标带 → 主趋势 → 分布/排行 → 可执行建议；使用 `LsDataChart` 和连续网格构成的多维分析页，禁止把每个数字都做成渐变卡片。
- 图表必须显示标题、单位、时间范围、口径、图例、真实数据/演示数据标记以及空错态。
- Progress 适合完成率，不代替趋势；Chart.js 适合趋势与比较，不用装饰图形填满空白。

### 10.9 Messenger 式客服工作台

会话页采用 Messenger 的高效三栏信息架构，但使用灵枢品牌 Token 与真实业务能力，不复制 Meta 商标与专有素材：

1. **左栏**：标题“聊天”、实时搜索、视图/筛选、按最近动态排序的会话；头像、来源、未读、最后一条消息和时间一眼可辨。
2. **中栏**：客户头像与名称、参与者 Avatar.Group、会话操作；消息气泡、附件/表情/GIF；底部固定输入与唯一发送主操作。
3. **右栏**：大头像、名称、来源与本地时间；分享、资料、通知、搜索；“影音内容、文件和链接”“客户与销售工作台”“隐私设置与支持”使用 Collapse 渐进展开。
4. 桌面三栏可同时显示；平板收窄左/右栏；移动端以列表 → 会话 → 资料的可返回层级呈现，不横向挤压。
5. AI 草稿、人工修改、知识引用、报价与客户意图继续保留真实来源标记，不伪装成客户消息。
6. 左栏桌面目标宽度为 232px，平板最小 196px；会话项使用独立 8px 圆角选中面，项与项之间 6px，默认无框，不使用连续的 Button 默认边框。
7. 会话名称使用 13/20、600；最后消息使用 12/18、最多两行；时间和来源使用 11/18。所有列表文字必须在边框内完成排版。

### 10.10 卡片、菜单、分页与步骤

- Card 只表示可独立操作或独立复用的对象；普通区块使用标题、Divider 与留白，卡片不嵌套超过一层。
- Menu 是应用导航的唯一结构源；收起态有 Tooltip，选中态同时使用背景、文字和侧边标记。
- 超过一屏且全量渲染昂贵的对象列表使用 Pagination；桌面显示总量、每页数和必要时快速跳转，移动端使用 simple。
- Steps 只用于有真实先后依赖的任务；显示当前、完成、等待、失败和预计时间，窄屏改为竖向或精简步骤。

### 10.11 图标、插画、邀请与边框动效

- 图标遵循“准确、简单、节奏、愉悦”：同一功能只保留一种图标语义，线宽、视觉尺寸和对齐一致。
- 插画只用于登录、空状态、完成页、引导与品牌说明；工作区优先真实产品、人物与媒体，插画不能冒充业务证据。
- 邀请分为静态、hover、推论和“更多内容”四类；所有邀请可关闭、可键盘触发，不反复打扰。
- BorderBeam 只能服务短时邀请，持续不超过 3 秒或一次 hover；减少动态效果模式下隐藏。

### 10.12 间距与亲密性

- 页面按 1440px 设计板、24 栅格、8px 基础网格实现；常用关系间距为 8 / 16 / 24px。
- 同一信息组内 8px，字段与同组说明 8–12px，平级对象 16px，章节 24–32px；必要时用 Divider 替代无限加大空白。
- 强相关对象靠近，弱相关对象分开；不得用随机 margin 修补布局。

### 10.13 灵小枢决策入口

灵小枢是全局的**决策与轻操作入口**，不是 Agent 运行监控台。其默认目标是用单列对话承接当前页面的信息和必要决定；复杂信息仍回到对应业务工作台。

- 首次点击固定打开单列对话首页，不设“待你决定 / 问灵小枢”并排页签，也不展示 Agent 选择轮盘或执行记录。消息与提示气泡在上方独立滚动，输入框固定在面板底部。
- 对话记忆由后台既有机制默认维护；灵小枢前端不展示“对话记忆”、查看已确认决策、保存为经营决策或撤销决策等入口，不用记忆管理工具条占据对话首屏。
- 待办只先在对话中显示一张可点击的概要气泡，不在首页直接展开事实、备注与操作组。本周计划概要统一写作“请确认本周的内容计划”；点击后在同一弹出框的第二页展示完整 `LsAssistantDecisionCard`，返回后保留对话滚动位置、草稿与附件。
- 同一时刻只突出一项最高优先级待办，并在概要气泡显示剩余数量；完成或退回后自动切换到下一项，不形成审批卡片墙或 Carousel。
- 全局排序固定为：开始计划 / 调整计划 → 发布、发送、报价与商业承诺 → 内容与质量审批 → 必填资料 → 当前页面唯一下一步 → 上下文快捷问答。阻断后续任务的事项优先于普通提醒，同级按截止时间和创建时间排序。
- 计划开始、调整、批准、退回、补充必要字段等轻量动作应能在灵小枢内完成。完整计划、逐镜内容、大表格、大图表和批量编辑只提供“查看完整计划/详情”深链，在完整页面或 Drawer 中完成。
- 灵小枢禁止展示 Agent 执行日志、事件流、历史轨迹、内部推理、长任务逐步输出和大量经营数据；这些内容进入数字员工工作排期、任务运行状态或对应业务操作台。
- 决策卡必须来自真实后端状态，至少包含稳定 ID、类型、优先级、对象版本、标题、必要摘要、影响、唯一主操作、可选退回/查看详情以及来源页面。不得从聊天文本猜测可执行动作，不得用模拟数据补空。
- 审批与计划动作提交时必须带当前对象版本或等价校验。后端遇到版本过期、审批已处理、依赖变化时返回冲突，由前端刷新队列并明确提示，不能覆盖新状态。
- 当前页面上下文决定无审批时的下一步：智能经营优先计划与经营决策，内容制作优先缺失素材/内容审批，发布与渠道优先发布批准，客户与会话优先发送/报价批准。路由上下文不可作为授权，最终动作仍由服务端核验租户、权限、状态与版本。
- 无待办时不保留概要卡占位；对话仍可直接输入。不得用几个固定推荐对话占据默认首屏；只在用户主动问答后显示与当前页面相关的建议。
- 桌面默认采用 420px 的右下锚定弹出面板，概要页与详情页保持同宽、切换时不得横向跳变；知识采集等明确需要更宽表单的工具页可扩展至 560px。视口不足时收紧到左右各 16px，移动端全屏；正文独立滚动、输入区固定、Esc 可关闭、焦点进入与归还完整。概要气泡与主操作复用受控蓝紫渐变，同一详情操作区仅一个主按钮；等待、失败、成功仍使用固定语义色。
- 新待办到达只更新数量与当前卡片，不播放持续动效；卡片切换使用共享 `lsMotion` 的容器变换，`prefers-reduced-motion` 下即时切换。

## 11. 响应式与无障碍

| 断点 | 规则 |
| --- | --- |
| `>= 1280px` | 完整侧栏、12 列、并排主辅区、完整日历 |
| `768–1279px` | 可收起侧栏、8 列、辅助区下移、Drawer 不超过视口 60% |
| `< 768px` | 4 列、单列、全屏菜单、Modal/Drawer 全屏或底部面板、日历默认列表视图 |

- 触控目标不小于 44×44px。
- Tab 顺序与视觉顺序一致；所有图标按钮有可访问名称。
- `prefers-reduced-motion` 下关闭循环动画、平滑滚动和大位移。
- 表格在移动端优先变成分组列表或保留关键列，不能靠不可发现的横向滚动完成核心任务。
- 所有功能在没有 hover 的触屏设备上仍可完整使用。

## 12. 迁移方案

当前仓库已引入 Ant Design 6.x、FullCalendar 与 Chart.js，并保留 Tailwind、Lucide、motion、dnd-kit 和迁移期 Recharts。迁移通过全局主题、共享 `Ls*` 组件与逐页替换完成；不得仅在一张示例页实现，也不得一次无验证地全局替换造成主链路回归。

### 12.1 P0 基础层

1. 锁定 Ant Design 6.x 小版本，建立 `ConfigProvider + App` 和 Token。
2. 建立 Button、Form、Table、Modal、Drawer、Feedback、Status 的共享适配层。
3. 建立统一 `LsCalendarEvent` 和 FullCalendar 外壳；先迁移“发布与渠道”。
4. 建立 Chart.js `LsDataChart`，先迁移“智能经营数据复盘”。
5. 建立视觉回归和键盘/焦点测试；新页面不得继续手写基础控件。

### 12.2 P1 核心主链路

1. 智能经营四页：数据带、账号矩阵、内容队列、数据复盘。
2. 周计划与 Agent To Do 排期：根据许可证决定 `resourceTimeline` 或 Standard 方案。
3. 灵感中心：筛选、卡片、媒体 Drawer、逐镜详情。
4. 内容制作：流程、素材选择、分镜、批量复核和成片预览。
5. 会话、客户、订单与企业知识库。

### 12.3 P2 收口

1. 定时任务、集成、权限、管理后台。
2. 恢复平台投放时按本规范重建图表与表单。
3. 删除旧日历、旧弹层、旧 Recharts 包装和重复 CSS。
4. 清理无语义渐变、超大圆角、重阴影、英文装饰眉题和散落硬编码颜色；保留本规范定义的受控品牌渐变。

### 12.4 共存规则

- 新功能只能使用新组件层。
- 同一页面不得同时出现旧/新按钮、弹层或状态样式。
- Recharts 与 Chart.js 只允许跨页面临时共存，不允许同一页面混用。
- Lucide 保留为唯一产品图标集；平台官方 Logo 独立管理。
- FullCalendar Premium 在采购前不得进入商业生产构建。

## 13. 验收标准

逐页评审必须满足：

- 5 秒内能说出当前对象、状态和唯一下一步。
- 页面不出现 Ant 默认蓝色、默认圆角或未映射的默认状态色。
- 一个操作区只有一个 Primary Button；禁用操作说明原因。
- Card 嵌套不超过一层；普通信息分组使用标题、留白和 Divider。
- 日历均来自统一事件模型，支持月/周/列表视图，时区明确。
- 所有日历事件在所属日期/时间列内形成不重叠、顺序稳定的级联卡片流；不引入 Masonry/CSS 多列布局，媒体加载前后不得换列或跳位。
- 弹层类型选择正确，焦点进入/归还、Esc、关闭按钮和移动端退化可用。
- 图表标题、单位、范围、图例、数据表和空错态完整；不使用假趋势填空。
- 长任务显示当前节点、责任 Agent、预计时间和真实进度。
- 产品事实、产品素材、云素材、参考视频和生成内容来源明确。
- 键盘、读屏、触屏与减少动态效果模式可完成核心流程。
- 不出现大面积蓝紫霓虹、玻璃模糊、持续发光描边、大量胶囊、装饰性英文眉题和无意义 AI 图标；受控渐变与邀请符合 10.1、10.2、10.11。
- 页面注册表中的所有一级页面必须通过统一应用壳、Token、反馈与焦点验收；不能只验收客服或智能经营单页。
- 1440px 和 390px 两种基准视口均不得出现页面级横向滚动、文字越界、边框重叠、相邻列表项相交或固定层挡住主操作。
- 窄列中的文字换行必须保持至少 18px 行高；任何文字的实际高度不得超出父容器可用高度，截断时必须有 title、Tooltip 或详情入口。
- 会话页三栏、进度、加载、头像组、渐进媒体、Masonry、紧凑字段、Steps 与数据看板均有真实业务页面承载，不建立只供截图的静态组件展厅。
- 动效、排版按 3.3 与 3.6–3.8 验收：共享 Token、无装饰性无限循环、无列表 stagger、无假进度；系统偏好动态切换后动画与显式滚动都能立即降级。

## 14. 待产品确认的四个决策

| 决策 | 建议 | 影响 |
| --- | --- | --- |
| Ant 主版本 | 锁定 6.x | 决定 Listy、Masonry 等 v6 组件是否可用 |
