## 1. 本版结论

2026-10-09 本次确认：全产品采用纯白底和黑灰正文；侧边导航图标、按钮与选中态保持黑灰；主要操作按钮与发出的对话气泡使用蓝紫渐变。关键数字、内容区功能图标和图表通过协调的蓝、青、粉、紫、黄突出重点，避免页面只有白灰而缺少信息层级。本条及下文更新的 Token 取代此前森林绿视觉基线。

每次前端修改都必须先遵循本规范；规范未涉及的组件与交互，先查 [Ant Design 官方组件](https://ant.design/components/overview-cn/) 与设计说明，复用官方模式并适配本规范 Token。可复用的新决定补回本规范，共享组件优先于页面内另造实现。

2026-10-10 新增：吸收 Material 3 的物理运动、缓动与持续时间、过渡模式、语义排版。采用适合高密度经营工具的 **Standard motion**，不引入另一套 Material 组件或皮肤。外部文档是研究来源，不与本规范并列成为产品规则；差异先在本规范确认，再改代码。沿用白底、黑灰正文、中性侧栏和蓝紫主操作，不恢复解释性副标题。

2026-10-10 新增：灵小枢定位为全局决策与轻操作入口，首次打开必须优先显示最需要用户审批或确认的事项；Agent 运行日志、复杂数据和批量工作继续留在对应操作台。具体优先级、交互边界与后端版本校验见 10.13。

2026-10-10 新增：浏览器窗口变化、系统文字放大与 80%–200% 浏览器缩放必须保持结构稳定。页面不得使用 `transform: scale()`、CSS `zoom` 或脚本反向补偿缩放；布局应在统一断点重排，复杂工作台在自己的容器内滚动，不得挤压文字、媒体或操作区。具体规则见 3.9。

灵枢 AI 的视觉方向定义为 **经营编辑台**：像一套由经营者、编导、内容制作人员共同使用的专业运营系统，而不是通用 AI 生成器。产品识别度来自真实业务对象、排期、证据、成本和结果回执。渐变、边框动画与插画仅作为被严格限制的品牌强调和邀请，不得替代业务信息。

本版确定四项基础技术与设计决策：

1. **Ant Design 是基础组件层，不是默认皮肤。** 统一按钮、表单、表格、反馈和无障碍行为，再通过灵枢主题 Token、页面模板与业务复合组件建立产品风格。
2. **所有日历统一使用 FullCalendar 的事件模型和交互。** 月视图、周视图、日视图和列表视图不得继续分别手写。
3. **所有经营数据图表统一使用 Chart.js 的视觉配置和数据口径。** 现有 Recharts 只在迁移期共存，不得新增第三套图表方案。
4. **弹层采用 Ant Modal、Drawer、Popover 和 Popconfirm 的实现能力，外观与信息克制参考 GitHub Docs / Primer。** GitHub Docs 是完整页面参考，不是弹窗组件；复杂流程不得塞入大弹窗。

## 2. 产品视觉身份

### 2.1 视觉关键词

- 可信：数据、来源、状态和时间可追溯。
- 克制：用版式、分隔线和留白建立层级，不依赖阴影与装饰。
- 高效：高频动作靠近业务对象，异常早于日志，详情按需展开。
- 清晰鲜活：纯白画布、黑灰正文、蓝紫主操作与少量彩色重点，颜色服务于操作优先级和数据区别。
- 可执行：每个页面先回答“现在怎样、下一步做什么、谁负责、何时完成”。

### 2.2 灵枢特有的可见语言

以下元素比“AI”标签更能建立灵枢的产品识别度：

1. **经营刻度**：目标、成本、发布时间、完成数量使用统一数据带和刻度，不拆成悬浮卡片墙。
2. **内容证据**：产品事实、产品素材、云素材、爆款参考、生成结果必须有固定来源标识。
3. **工作轨道**：经营 Agent、编导 Agent、内容 Agent、质检与发布按真实工作顺序展示责任、预计时长和结果。
4. **账号与平台**：平台用官方 Logo，账号用真实名称；平台色不承担任务状态。
5. **真实媒体**：视频首帧、产品图、素材结构与成片预览是页面主视觉，不用通用 AI 插画代替。

### 2.3 禁止的“AI 模板风”

核心工作界面禁止：

- 大面积蓝紫霓虹渐变、玻璃模糊、持续发光边框和无意义光点；受控的品牌渐变与边框邀请遵循 4.4 与 10.1。
- 每个区块都使用 20px 以上圆角、重阴影和悬浮上移。
- 大量英文大写眉题，如 `SMART OPERATIONS`、`WEEKLY COMMAND CENTER`；中文业务标题应成为第一信息。
- 魔法棒、四角星、机器人头像被重复用作所有功能图标。
- `font-black` 被用于正文、说明和所有数字；字重必须服务信息层级。
- 一个页面堆叠多块渐变 KPI 卡、胶囊标签和装饰性假图表。
- 用“处理中”“AI 正在思考”等拟人化文案代替真实节点、责任 Agent、已完成数量和预计时间。

### 2.4 五张参考图的强制映射

参考图只定义对应场景，不允许把某一种视觉机械套到全站：

| 参考图 | 全应用使用范围 | 强制实现 | 禁止事项 |
| --- | --- | --- | --- |
| 图 1：媒体墙 | 所有视频库、图片库、素材库；日历中的内容/发布事件 | 媒体优先、保留原始宽高比、统一列宽与间距；素材卡和爆款视频卡使用 `LsMasonryGallery layout="masonry"`，支持 9:16、16:9、1:1 及其他真实比例；日历事件使用同语法的 `LsCalendarEventCard` | 不得将非 9:16 媒体硬裁为 9:16；任务、账号、审批列表不得使用瀑布流；日历不得嵌入 Masonry 布局引擎 |
| 图 2：图片/视频状态 | 所有图片、视频、首帧、生成结果和预览 | 使用 `LsMediaStateFrame + LsProgressiveMedia` 表达加载、生成进度、成功和失败；占位尺寸与完成态一致 | 黑框、空白、仅写“处理中”、加载后布局跳动 |
| 图 3：渐变进度 | 所有加载进度、Agent 工作进度、视频生成、素材处理、资料完整度和配额 | 已知总量使用 `LsGradientProgress`；未知总量使用 Spin + 当前节点；完成/失败切换语义状态 | 页面内手写单色进度条、虚构百分比、用进度条冒充趋势图 |
| 图 4：Steps 流程弹窗 | 用户首次进入的新手引导，以及 2–4 步的短流程 | 首次引导使用 `LsFlowDialog`，在顶部显示 Steps，正文只解释当前一步，底部只有跳过/返回与唯一主操作 | 把完整工作台塞进弹窗、每次进入都重复打扰、关闭后丢失进度 |
| 图 5：数据分析页 | 智能经营、运营复盘、账号与内容表现、管理统计 | 使用统一筛选区、连续指标带、主趋势、分布/排行和可执行建议；图表由 `LsDataChart` 渲染 | 渐变 KPI 卡墙、假趋势、无单位/口径/时间范围的数据装饰 |

上述映射同时适用于桌面、平板与移动端；响应式只能改变列数、信息密度和弹层形态，不能改变业务语义或状态来源。

## 3. 基础设计 Token

### 3.1 色彩

| 角色 | Token | 色值 | 用途 |
| --- | --- | --- | --- |
| 操作主色 | `colorPrimary` | `#2563EB` | 链接、输入聚焦、主操作渐变起点 |
| 正文主色 | `colorText` | `#171717` | 标题、正文、侧边导航 |
| 页面画布 | `colorBgLayout` | `#FFFFFF` | 全局工作区 |
| 内容表面 | `colorBgContainer` | `#FFFFFF` | 面板、表格、弹层 |
| 次级表面 | `colorFillSecondary` | `#F5F5F5` | 选中、表头、次级分区 |
| 主边框 | `colorBorder` | `#D4D4D8` | 输入、控件、强调分隔 |
| 次边框 | `colorBorderSecondary` | `#E4E4E7` | 表格行、区域分隔 |
| 次级文字 | `colorTextSecondary` | `#52525B` | 说明、元数据 |
| 三级文字 | `colorTextTertiary` | `#71717A` | 时间、单位、弱提示 |
| 信息 | `colorInfo` | `#2563EB` | 进行中、系统信息 |
| 成功 | `colorSuccess` | `#168568` | 完成、通过、已连接 |
| 等待 | `colorWarning` | `#A16207` | 待确认、缺资料、临近截止 |
| 异常 | `colorError` | `#DC3545` | 失败、阻断、风险 |
| 人工介入 | `supportApricot` | `#FF6384` | 洞察或人工介入，不等于错误 |

规则：

- 状态必须同时显示文字或图标，不能只靠颜色。
- 平台 Logo 保留官方颜色，但平台颜色不得染整张任务卡。
- 正文与背景对比度不低于 4.5:1；图标与图形标记不低于 3:1。
- 侧边导航使用黑灰图标与文字，选中态为 `#F4F4F5` 浅灰底，不使用彩色按钮或彩色导航图标。内容区图标可以按功能选用色板。
- 主操作与发出消息渐变为 `#2563EB → #6546E8`，白色文字；hover 为 `#1D4ED8 → #5635D6`。真实进度使用 `#36A2EB → #9966FF`。渐变不能覆盖页面大底或代替状态语义。
- 重点对话框头部可以使用淡蓝、淡紫、淡粉的浅渐变并配黑字；指标用彩色数字、小图标或细色条突出，不把所有卡片做成重彩渐变。
- 渐变不可改变语义：成功、等待、失败仍分别使用固定语义色，并必须带文字或图标。

### 3.2 图表色板

图表序列固定按以下顺序分配，并同时用线型、点型或图案区分：

| 顺序 | 色值 | 用途建议 |
| --- | --- | --- |
| 1 | `#36A2EB` | 蓝色序列 |
| 2 | `#FF6384` | 粉色序列 |
| 3 | `#4BC0C0` | 青色序列 |
| 4 | `#FFCD56` | 黄色序列 |
| 5 | `#9966FF` | 紫色序列 |
| 6 | `#FF9F40` | 橙色辅助项 |
| 中性 | `#A1A1AA` | 基准、未分类、历史参考 |

图表采用白色底与中性浅灰网格。相同指标跨页面保持同色，面积填充使用同序列的低透明度颜色；禁止 3D 图表、随机配色和仅靠颜色表达数值。数据序列颜色不自动表示成功或失败。

### 3.3 字体与数字

```css
--font-sans: "SF Pro Text", "PingFang SC", "Noto Sans SC", ui-sans-serif, system-ui, sans-serif;
--font-mono: "SFMono-Regular", ui-monospace, monospace;
```

以下为灵枢基于 M3 语义角色适配的中文工作台刻度，**不是照搬 M3 默认字号**。字号和行高单位为 px；共享 Token 与语义类是唯一实现入口。

| 语义角色 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| display | 36 / 44 | 600 | 独立品牌或少量关键大数；不用于工作台标题 |
| headline | 28 / 36 | 600 | 登录/独立流程标题；业务页 H1 按 5.1 隐藏 |
| title-large | 20 / 28 | 600 | 一级区块、主要弹层标题 |
| title-medium | 16 / 24 | 600 | 卡片、小节、次级弹层 |
| title-small | 14 / 22 | 600 | 紧凑分组、表单分区 |
| body-large | 16 / 24 | 400 | 阅读型正文、会话消息 |
| body-medium | 14 / 22 | 400 | 默认正文、列表、输入、表格 |
| body-small | 12 / 18 | 400 | 次要元数据、单位、时间 |
| label-large | 14 / 20 | 600 | 主操作、Tab、关键标签 |
| label-medium | 12 / 18 | 500 | 状态标签、紧凑控件 |
| label-small | 11 / 18 | 500 | 仅非关键媒体角标；不得用于正文、错误、核心操作 |
| metric | 24 / 32 | 600 | KPI，等宽数字 |

- 英文只用于平台名、专业缩写或用户真实内容，不用英文装饰眉题。
- 数字使用 `font-variant-numeric: tabular-nums`；金额、百分比、时间单位必须全系统统一。
- 产品工作区只使用上述系统无衬线字体；装饰字体只允许出现在品牌插画或营销素材中，不能进入导航、表格、卡片和表单。
- 同一层级只能有一套字号、字重和行高；`font-black`不得出现在产品正文，最高可视字重收敛为 700。
- 中文标题按语义换行，不使用字符级强制断行；正文与列表信息使用 `overflow-wrap: break-word`，URL、ID 和不可分隔的长串才使用 `overflow-wrap: anywhere`。
- 单行截断只用于有详情入口的次要元数据；客户名、任务标题和最后一条消息默认允许两行，不能因为窄列而丢失关键语义。
- 默认字距为 normal，不为中文正文全局添加负字距。数据使用等宽数字，不给普通段落强加等宽字体。
- 不把 9–10px 微小文本用于业务信息；媒体角标最低 11px，其余辅助信息最低 12px。浏览器文字放大到 200% 时允许局部换行/滚动，不用固定行高容器裁掉文字。
- 语义角色不改变 HTML 语义：视觉小标题仍应具有正确 heading 层级；不为了样式把所有文字改为 h1，也不添加已删除的页眉和说明。

### 3.4 间距、圆角、阴影与密度

- 基准间距：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。
- 控件高度：紧凑 32px、默认 36px、主要操作 40px。
- 控件圆角：6px；默认容器 8px；弹层 10px；媒体卡 8px。
- 只有状态 Tag 可以使用胶囊圆角；大容器禁止胶囊化。
- 普通卡片无阴影，以边框和留白分层；阴影仅用于 Modal、Drawer、Dropdown、Popover。
- 参考 Messenger 的框架密度：纯白页面和 1px 中性栏分隔线建立层级；列表选中态局部浅灰，发出消息用蓝紫渐变，不为每个子项反复加框。
- Hover 只改变背景、边框或文字，不整体上浮、缩放或发光。
- 高密度表格允许局部紧凑模式；全站不得启用全局紧凑模式。
- 连续列表项之间至少保留 6px 间距，或者共用单一 Divider；禁止两个带独立边框的列表项零间距相贴，造成双线、重叠或视觉粘连。
- 所有 Flex/Grid 子项默认 `min-width: 0`；媒体、图表、表格和弹层不得超出所在容器，需滚动时由明确的内部滚动容器承担。

### 3.5 图标与媒体

- 现阶段继续使用 Lucide 作为产品图标，避免迁移期同时出现两套图标语言；Ant 内部图标由共享适配层处理。
- 不在同一功能上混用 Lucide 与 Ant 图标。
- YouTube、TikTok、Instagram、Facebook、Messenger 等使用官方 Logo。
- 视频卡必须保留封面、时长、平台、来源与可用状态；图片和视频加载失败提供占位与重试。
- 工作区和登录表单底色统一纯白；登录页左侧独立品牌视觉区保留 `lingshu-water.jpg` 水纹图片，不把该图片延伸到表单或登录后的业务工作区。既有品牌 Logo 与真实媒体继续保留。

### 3.6 物理运动系统

M3 当前的物理方案与既有 easing/duration 并非两个叠加的动画：空间关系使用弹簧，CSS、Ant 与颜色/透明度使用受限时长曲线。灵枢采用 Standard 的克制感；禁止给同一属性同时叠加 CSS transition 和 Motion 动画。

| 空间 Token | stiffness | damping ratio | mass | 使用范围 |
| --- | --- | --- | --- | --- |
| fast | 1400 | 0.9 | 1 | 小范围控件位置变化 |
| standard | 700 | 0.9 | 1 | 侧栏/关联详情面板展开收起 |
| slow | 300 | 0.9 | 1 | 经评审的全屏空间转场；非默认 |

数值取自 AndroidX Material 3 StandardMotionTokens。Motion 的 `damping` 是阻尼系数而非上述阻尼比，须按 `2 × ratio × sqrt(stiffness × mass)` 转换；不得直接传入 0.9。弹簧不再指定 duration，不人为制造 velocity；快速反向操作从当前位置继续，不排队等待旧动画结束。颜色/透明度不得过冲，空间过冲不得裁切正文或遮挡操作。

- 默认不添加拖拽惯性、卡片浮起、摇摆、呼吸、纸屑或持续边框追光。成功使用静态成功态或一次短淡入。
- 例外：首页“查看当前周计划”仅在有真实运行中的生产任务回执时可使用沿按钮边缘持续旋转的细线作为进行中状态；没有开始、仅排队或已结束时不得播放。出现需用户处理的阻塞、失败或待审批时立即停止，改为静态红色边框和感叹号。减少动态效果下保留静态边框与文字状态，不播放旋转。
- Ant Modal/Drawer 使用主题内置动效，不再外包一层 spring，保留焦点管理、键盘与关闭行为。
- 宽度动画仅用于受控应用壳，不对表格行、媒体墙、整页高度做逐帧布局动画。大列表禁止逐项延迟，数据刷新不得重新播放整页入场。

### 3.7 缓动与持续时间

下表是从 M3 时间刻度选择的产品子集，不把完整 50–1000ms 范围暴露给业务页。

| Token | 时长 | 场景 |
| --- | --- | --- |
| instant | 0ms | reduced-motion、直接数据刷新、紧急反馈 |
| fast | 150ms | hover、focus、颜色、按钮反馈 |
| exit | 200ms | 非空间元素退出 |
| enter | 250ms | 媒体就绪、首次内容淡入 |
| standard | 300ms | 局部流程或关联状态过渡 |
| slow | 400ms | 仅较大空间的非弹簧过渡 |

曲线：standard `cubic-bezier(0.2, 0, 0, 1)`；enter/decelerate `cubic-bezier(0, 0, 0, 1)`；exit/accelerate `cubic-bezier(0.3, 0, 1, 1)`。Ant fast/mid/slow 分别映射 150/250/300ms。hover 不改变几何尺寸，业务流转不等待动画完成。进度时长不是任务耗时，不允许定时器伪造 5%→90% 的进度。

实现约定：`src/lib/designTokens.ts` 提供 `lsMotion`、排版与 CSS 变量；`LingshuProvider` 同时提供 Ant 主题与 MotionConfig。页面复用 `lsMotion`，不再自定 spring、秒数、easing 或 stagger。CSS 使用 `--ls-motion-*` 与 `--ls-ease-*`。Chart.js 使用同源时长，但其专用曲线不冒充 CSS cubic-bezier。

### 3.8 过渡模式与减少动态效果

| 对象关系 | 模式 | 灵枢实现与边界 |
| --- | --- | --- |
| 卡片 → 对象详情 | container transform 的关联原则 | 保留封面/名称/选中来源，由共享 Ant Drawer 打开；不为了形变复制播放器或破坏焦点 |
| 同一流程前后步骤 | shared axis | Steps 保持原位，内容最多 8px 位移并淡入；输入值与错误不丢失 |
| 无关联 Tab / 一级页面 | fade through 的层级原则 | 只做短透明度过渡，不左右飞入、不缩放整页；不得重挂载已缓存的工作台 |
| 菜单、反馈、媒体就绪 | fade | 进入250ms/退出200ms；颜色150ms，不弹跳 |
| 侧栏与关联辅助面板 | standard spatial | 可中断的标准弹簧，不改变当前编辑内容 |
| 图表刷新、日历换日期 | stable update | 图表原实例更新，首次可短入场；日历保持原生导航与滚动，不包装第二层全屏动画 |

- 应用首次渲染即读取 `prefers-reduced-motion`，运行中切换也立即生效。Ant 关闭 motion；Motion 禁用空间动画；共享 CSS、Chart、Skeleton、装饰层与 JS smooth scroll 同步退化为即时状态。
- Reduced-motion 下不运行纸屑、呼吸、弹跳、列表 stagger；真实任务仍保留文字/静态进度，不能把关闭动画误当成任务结束。操作反馈、加载状态及无障碍语义必须保留。
- 页面切换不延迟可点击时间、不重置滚动/编辑状态；不得把动画结束回调用作提交、扣费、分析或发布的触发条件。
- 验收至少覆盖：快速连续开关、切 Tab 后返回、动态切换减少动态效果、键盘打开关闭弹层、媒体成功/失败、图表数据更新、窄屏与 200% 字号。正常动画不闪白、不改变文案位置、不引入页面级横向滚动。

### 3.9 布局稳定性、窗口变化与浏览器缩放

- 浏览器缩放视为可用布局宽度变化，不反向侦测或抵消用户缩放；禁止对 `html`、`body`、`#root`、应用壳或页面工作区使用 `transform: scale()`、CSS `zoom`。
- 应用壳固定为“可折叠侧栏 + 可收缩主区 + 可选固定宽度辅助栏”。侧栏展开/收起宽度必须同时约束 `width / min-width / max-width`；主区和页面栈必须使用 `min-width: 0`，不得把兄弟区域挤出视口。
- 移动断点统一为 `767px`，桌面与移动的 JS `matchMedia`、Tailwind/CSS 媒体查询必须使用同一边界，禁止 760/768 等相邻断点同时控制同一壳层。
- 所有 Flex/Grid 直接子项默认 `min-width: 0`。需要保持列宽的表格、日历、时间轴、媒体编辑器必须把 `min-width` 放在内部内容层，并由最近的显式 `overflow-x: auto` 容器承接；禁止让整页横向滚动。
- 图片、视频、Canvas 与 iframe 默认不得超过所在容器；封面和预览使用固定 `aspect-ratio` 或稳定占位，加载前后不得改变卡片尺寸。
- 标题、正文、表头和数据值允许语义换行；URL、ID 与连续英文长串使用 `overflow-wrap: anywhere`。固定高度只能用于单行控件，不得用于可能放大或换行的业务文字。
- 断点只改变列数、信息密度和弹层形态，不改变操作顺序或业务语义。进入窄布局后，主操作仍在对象附近，次要操作允许换行但不得覆盖正文。
- 验收尺寸至少覆盖 `1440×900`、`1280×720`、`1024×768`、`768×1024`、`390×844`，并检查桌面浏览器 80%、100%、125%、150%、200% 缩放。验收标准是无重叠、无裁字、无组件拉伸变形、无非预期页面级横向滚动。

### 4.4 禁用与慎用

- Ant `Calendar`：禁用；产品日历统一使用 FullCalendar。
- Ant Charts：禁用；业务图表统一使用 Chart.js。
- `BorderBeam`：默认禁用；仅允许在首次邀请、AI 建议候选或新能力发现中短时出现，不能表达状态、选中、焦点、校验或进度；`prefers-reduced-motion` 下完全关闭。
- `Masonry`：用于灵感、爆款视频与“我的素材”媒体墙，卡片媒体区保留源宽高比；任务与状态列表禁用。
- `Carousel`：不得承载告警、审批和唯一操作。
- `FloatButton`：只允许全局帮助、反馈或返回顶部，不能作为核心新建入口。
- `Switch`：仅表示点击后立即生效的二元状态；随表单提交的选择使用 Checkbox 或 Radio。
- `Tooltip`：只用于无文字图标的短说明，不能承载关键内容、长文本或操作。
- `Card`：只承载独立对象；卡片嵌套不超过一层。
- Ant Design Pro：不得直接成为整站皮肤；先完成基础组件与灵枢 Token，再单独评估 ProTable / ProForm。

## 5. 页面骨架与业务模板

### 5.1 全局应用壳

- 桌面侧栏展开 176px，收起 60px；移动端收起仅保留 56px 图标轨道，展开导航使用 Drawer，不永久挤压主内容。展开态导航正文使用 14px，品牌名称使用 15px，禁止用宽栏和小字制造无效留白。
- 一级页面不再重复显示与左侧导航同名的可见 H1 和说明副标题；文档结构保留屏幕阅读器可读的唯一 H1。页面级操作直接进入首个工具栏，范围与更新时间放入对应数据区或可视化时间控件。对象详情、流程步骤、弹层标题不受此规则影响。
- 页面与业务区块标题下不显示“本页做什么、点击后看什么”一类解释性副标题。日期、时区、数量、来源、同步状态等可操作元数据应并入标题行的 Tag、时间控件或状态区；错误恢复、空状态、表单约束、风险与不可逆操作仍必须保留必要说明。
- 搜索、内容类型、收藏状态与“更多筛选”在桌面端固定为同一行；空间不足时允许工具栏自身横向滚动，不得拆成两行。结果总数进入 Tab 或分页，不再单独占用一条统计提示栏。
- 全局消息不得占用独立右侧栏或形成页面右侧缝隙；需要用户立即处理的事件使用页内 Alert，需要稍后查看的结果进入对应业务页的通知入口。
- 面包屑仅在层级超过两级时出现。
- 页面最大内容宽度 1440px；全屏日历、创作工作台和会话页可突破该限制。
- 顶部与侧栏不使用渐变、毛玻璃或重阴影。

### 5.2 五类标准页面

| 页面类型 | 固定结构 | 适用模块 |
| --- | --- | --- |
| 数据总览 | 页面头 → 连续 KPI 数据带 → 1 个主图 → 1–2 个明细区 → 下一步 | 智能经营、内容监控、投放、订单 |
| 对象列表 | 页面头 → 搜索/筛选 → 结果数量 → Table 或规则卡片 → 分页 | 灵感、账号、客户、订单、素材 |
| 对象详情 | 页面头/返回 → 状态与主操作 → 媒体或摘要 → Tabs → 历史与证据 | 视频、内容任务、账号、客户、订单 |
| 流程工作台 | 上下文/对象身份 → 当前阶段主区 → 证据/预览 → 固定操作条；需要显式导航时再使用 Steps | 内容制作、账号连接、产品导入 |
| 日历工作台 | 日历工具栏 → FullCalendar → 事件详情 Drawer | 发布、智能经营排期、定时任务 |

### 6.2 日历外观

- 工具栏顺序固定：新增/主要动作、今天、前后切换、当前日期、视图切换、筛选。
- 星期与日期使用中文；周一作为工作周起点时必须与目标市场规则一致。
- 周末只用极浅中性背景区分；今天使用 1px 蓝色边框或浅蓝底，不使用大色块。
- 事件颜色表达生命周期状态，平台由官方 Logo 表达。
- 月视图事件显示“平台 Logo + 账号简称 + 标题”；周/日视图再显示时间和缩略图。
- 同日溢出默认使用 `+N` 入口；Popover 只做快速浏览，点击事件进入 Drawer。数字员工中的发布周/日视图是全量例外：所有发布项使用紧凑卡连续展示，不得折叠为 `+N`。
- 日历内容区为平面网格，不在每个日期单元套 Card。
- 日历中的“瀑布流”统一指 FullCalendar 原生日期列/时间列内的连续级联事件卡片流，不指 Ant `Masonry` 或 CSS 多列布局。同一日期/时段的 `LsCalendarEventCard` 按开始时间与稳定次序自上而下排列，使用统一间距，不得重叠、跨列重排或在媒体加载后换列；月/全年视图使用紧凑卡和原生 `+N` 溢出。员工排期与发布日历的周/日视图共用紧凑事件卡、标准工具栏和工作台间距，缩略图只作身份提示，完整媒体进入 Drawer 查看。日期、时区、拖拽、键盘与事件 Drawer 仍由 FullCalendar 原生模型负责。
- `timeGridWeek` / `timeGridDay` 必须显示明确但克制的小时刻度；有精确时间的事件进入对应时段，无精确时间但需要执行编排的任务使用有证据的“执行窗口”，不得补造 09:00 等假时刻。经营周排期逻辑范围默认覆盖 08:00–22:00，左轴默认每 2 小时标注一次；仅在确有全天事件时显示全天区。只有日期的发布计划继续使用 `allDay`，在左侧明确显示“全天 / 时刻待定”，不展示虚假的小时轴。
- 所有日历默认使用视口受限的共享工作区：桌面默认内容高度为 `clamp(320px, calc(100dvh - 280px), 720px)`，页面可在共享属性上收紧可用高度。数字员工发布周视图因使用紧凑卡且要求一次显示全部本周内容，可按事件完整高度展开，不设固定 `contentHeight`、不折叠为 `+N`，也不得再套内部纵向滚动；窄屏仍降级为全量列表。其他日历的超出排期只由 FullCalendar 内容区内部纵向滚动承载，不得叠加第二层滚动容器。
- 账号×日期的矩阵排期是 FullCalendar 外的保留例外，必须使用共享 `LsScheduleViewport`：日期头吸顶、内部滚动、视口受限，且复用与日历相同的一次性渐入和减少动效规则；不得为矩阵补造小时轴。
- 事件卡首次进入日历可视区时使用一次 `opacity + translateY(≤8px)` 渐入，统一使用 `--ls-motion-enter` 与 `--ls-ease-enter`，同一事件 ID 刷新、换视图或重新挂载不得重播，不使用 stagger 或 delay。键盘聚焦必须立即显示；`prefers-reduced-motion` 开启或运行中切换后立即显示全部卡片并断开观察。

### 6.3 交互

- 周任务详情将“需用户补充”与“系统技术待恢复”分开。已确认的排期模板自动采用并留痕，不再次要求逐项批准默认值；采用记录不代表排期已生效、渠道已授权或成片已验收。已有企业与产品资料优先绑定可信版本，版本不一致时提供知识库核对入口，不清空原资料。WhatsApp 本地 Mock 必须持续标注模拟、无真实授权、无业务交付，模拟传输测试不能让正式任务变绿或解除真实消息权限门禁。

- 企业身份、目标市场、本地素材和权利提示仅出现在确实消费这些资料的步骤，并显示已有资料来源及对应公司/产品/渠道操作入口；资料诊断不新增执行阻塞、不要求重复确认已核验事实，也不阻止无关采集或客服 Mock。真实渠道缺项按平台分别命名，同一操作合并重复提示。采集服务余额不足归服务额度恢复，不误报为企业资料缺失；未知费用和当日请求数量保留，不以模拟结果补齐。

- 数字员工的经营总览保留“生产指挥舱”的真实运营指标与内容工程，不再要求发布投流和客服承接都挤在单屏；一级导航及页内发布日历遵循 16.2。经营总览不单设“数字员工实时状态”卡组，不展示“Agent 协作在线”数量，也不设置独立的“异常与待处理”固定模块。真实执行状态、责任 Agent 和阻塞必须回到对应内容工程、生产节点或业务对象内呈现。发布日历在经营总览内作为页内 Tab，不跳转新的一级视图；投流和客服承接是独立一级入口。内容工程以内容为第一层级，每条视频默认使用一行、节点拥挤时最多两行，集中展示视频预览、内容身份、单条预计或已结算积分，以及经营、编导、内容、客服四位 Agent 在该内容中的交付与接力关系；排期横轴统一按自然周展示，同一内容内的 Agent 节点按真实前后顺序同行排列，不再拆成逐日纵向卡片。固定里程碑经营定题、编导成稿、素材就绪、成片生产、质检验收、发布承接和数据复盘继续作为内部依赖与详情依据，但总览不得再以七张等权节点卡为主要结构，也不在日历内铺陈职责、输入输出或交付说明。状态投影必须遵守依赖门：上游未验收时，下游即使存在孤立完成回执也显示“等待上游”，不得计入整条视频完成度。缺少步骤时只显示“尚未派生”，不得伪造占位任务、完成度或开始时间；周级共同前置、保障与复盘任务折叠在总线下方，不与视频任务混排。点击真实生产节点统一进入右侧 Drawer，明确调用条件、承接输入、下游交付和稳定性门槛，并继续使用原任务的真实执行入口。

- 内容工程总览不展示数字人、素材复用、AIGC 补镜、统一音色等分项费率；每条内容只显示一个基于已冻结制作方案的预计积分或已结算积分，方案未冻结时明确显示“待制作方案冻结”，不得用供应商费用推算。数字人、素材库产品/工厂/场景视频、仅在缺镜头时调用的 AIGC 补充镜头，以及统一音色/字幕等结构与分项积分仅在内容详情中展示。已有素材匹配与外部技术生成必须明确区分，不能把素材库匹配显示成 AI 生成或收费调用。

- 积分统一使用 Lucide `Star` 小星星图标，不再使用金币、Token 或平台币样式。用户账单以产品功能板块为唯一核计维度，一级分为智能经营、灵感与策划、内容制作、投流增长、客服承接、知识与助手；各板块再按周计划、经营诊断、爆款分析、脚本分镜、素材复用、数字人、AI 补镜、投流建议、询盘理解、回复草稿、知识结构化、知识问答和灵小枢建议等用户可感知的业务结果定价。不得向用户展示 Token 数、底层服务商、模型、API 版本或按供应商调用成本直接换算的积分；同一产品功能在底层技术路线切换后保持相同的用户价格，供应商金额仅用于内部成本与容量管理。基础套餐包含的每周周任务仍记录功能消耗但不从加油包扣除，套餐外追加生成、重做和加量才从加油包扣除。生成或分析前按产品功能与预计交付量预留，成功后按实际交付的秒数、条数、轮次、文档或业务动作结算并自动退回差额；未成功交付不扣积分。同一用户业务动作中的多 Agent、多模型、校验、修复与系统重试合并为一次结算，不得重复扣分；浏览、筛选、打开已有结果和不生成答案的纯检索不扣积分。素材库已有视频的检索、裁切与编排为 0 积分。尚未产生产品功能结算事件时显示“暂无已结算的产品功能消耗”，不得用供应商账单或估算总额补齐。

- 套餐与积分页借鉴 Codex 使用情况页的信息层级，但保持灵枢自己的业务口径。页面使用单页结构，不设置“积分规则”页签：顶部展示当前套餐、状态、有效期、套餐积分与加油包积分，并提供“购买加油包”和“查看全部套餐/升级套餐”入口；主体严格按智能经营、灵感与策划、内容制作、投流增长、客服承接、知识与助手六大板块展示，每张板块卡同时呈现该板块包含的功能、已用积分、总积分和刷新周期，不再另设重复的可用功能区或本期结算流水。所有用户用量统一以积分计量并配合星星图标，已知总量统一使用 `LsGradientProgress`；套餐内积分与加油包积分必须分开，Token 与模型用量不得成为用户账单项目。开发环境允许用带“界面示意”标记的 Mock 数据验收完整布局及购买/升级面板，正式构建无权威额度或积分账本时必须回到明确空状态，不得把演示数字、供应商成本或推算余额当成真实数据。

- 套餐与积分弹窗的套餐摘要、指标区与业务板块卡统一使用共享 `Surface` 层级和边框 token，夜间模式不得保留硬编码白底或形成大面积高亮面板。未配置权威积分账户时仅将积分数值显示为明确空值，不展示常驻警告条，也不得推算或补造余额；接口读取失败仍保留可重试的错误反馈。

- 事件 hover 可显示轻量摘要，但所有内容必须能通过键盘 focus 或点击获取，不能只依赖 hover。
- 点击事件打开右侧 Drawer；Drawer 显示缩略图、标题、平台账号、责任 Agent、制作时长、交付时间、成本和状态。
- 仅有排期编辑权限时允许拖拽与缩放；拖拽后必须二次确认跨账号、跨日或已进入制作的变更。
- 必须提供键盘可操作的“移动到日期/时间”替代入口。
- 所有时间显式标注时区，如“北京时间”或“目标市场当地时间”；后台保存 IANA 时区。
- 日历更新保留旧数据并局部显示同步状态，不整页清空或闪烁。

### 6.4 Premium 决策门

`timeline`、`resourceDayGrid`、`resourceTimeGrid` 和 `resourceTimeline` 均属于 FullCalendar Premium。真正的“账号或 Agent 为行、时间横向”的工作排期只有两种合规方案：

1. 采购商业许可，使用 `resourceTimelineWeek/Month`；大资源量启用虚拟化。
2. 暂不采购，使用 Standard 的 `timeGridWeek + listWeek`，事件标题带账号和平台；现有自研泳道只维护、不扩张。

不得把 Premium 试用、非商业许可或 AGPL 路径直接用于闭源商业生产。

## 7. 弹层与详情统一规范

### 7.1 GitHub 参考的正确用法

GitHub Docs 文章页适合作为“克制、可深链、层级清楚”的完整页面参考；弹层行为以 GitHub Primer 的 Dialog / Overlay 规范为参考。灵枢的实际实现仍统一使用 Ant 组件，避免引入第二套组件库。

### 7.2 浮层选择

| 需求 | 组件 | 示例 |
| --- | --- | --- |
| 1–2 句短说明 | Tooltip | 无文字图标含义、字段单位 |
| 轻量摘要或少量就地操作 | Popover / Dropdown | 日历事件快览、表格行操作、筛选 |
| 简单确认或单一短表单 | Modal | 发布确认、覆盖确认、取消任务 |
| 不中断主页面的详情或编辑 | Drawer | 视频详情、逐镜分析、客户详情、任务详情 |
| 局部危险操作 | Popconfirm | 删除单条草稿、移除一个标签 |
| 多步骤、侧导航、可分享或可深链 | 完整页面 | 新周目标编辑、内容制作工作台、Agent 设置、复杂产品编辑 |

### 7.3 尺寸与结构

| 类型 | 桌面宽度 | 适用内容 |
| --- | --- | --- |
| 小 Modal | 400–480px | 确认、单字段输入 |
| 标准 Modal | 560–640px | 短表单、选择器 |
| 大 Modal | 720–840px | 批量复核、媒体选择；不得发展为完整页面 |
| 标准 Drawer | 480–560px | 对象详情、轻编辑 |
| 媒体 Drawer | 720–880px | 视频、逐镜、素材结构 |

统一结构：标题、可见关闭按钮、可滚动正文、固定页脚。标题必填；说明仅保留必要的风险、校验或业务信息，不增加解释性副标题。页脚右侧最多一个主按钮，危险操作与普通主按钮不并列强调。

### 7.4 行为与无障碍

- 打开后焦点进入弹层，Tab 不离开 Modal / Drawer；关闭后焦点返回触发器。
- 支持 Esc 和可见关闭按钮；未保存表单不可点击遮罩直接关闭。
- 使用 `role="dialog"` 或 `alertdialog`、明确的 name / description 和 `aria-modal`。
- 背景不可交互；正文滚动时头部与页脚固定。
- 窄屏 Modal 转底部面板或全屏，Drawer 转全屏。
- 原则上禁止嵌套弹层；必须嵌套时最多两层，并仅关闭最上层。
- Tooltip 与 hover 摘要不得承载卡点、成本、状态或唯一操作。

### 7.5 产品内建议改造点

- 爆款视频与对标账号：卡片点击进入媒体 Drawer；完整逐镜分析使用可深链详情页。
- 周计划启动：智能经营页不再展示独立“查看当前周计划”按钮或旧详情抽屉；查看计划统一打开灵小枢的单页周计划确认弹窗。已有计划的运行控制仍保留；新建下一周目标可进入独立编辑流程。
- 素材选择和批量复核：使用大 Modal，固定操作区。
- 发布确认和危险重试：使用小 Modal / Popconfirm。
- 客户、订单、内容任务、账号：列表内快速查看统一右侧 Drawer。
- Agent 设置、渠道接入、复杂企业资料：使用完整页面或流程工作台。

## 8. Chart.js 数据可视化规范

### 8.1 图表选择

| 要回答的问题 | 图表 | 灵枢示例 |
| --- | --- | --- |
| 随时间如何变化 | Line / Area | 内容产量、播放量、询盘、成本、制作时长 |
| 多账号或平台谁高谁低 | 横向 Bar | 账号周更、渠道效果、Top 内容 |
| 每周状态如何构成 | 100% Stacked Bar | 排队、制作、验收、发布、失败 |
| 计划与实际如何对比 | Mixed Bar + Line | 计划产量与完成率、花费与转化 |
| 两指标是否相关 | Scatter / Bubble | 匹配分与表现、成本与播放、发布时间与询盘 |
| 少量类别占比 | Doughnut | 最多 5 类的内容来源；非首选 |
| 单目标完成情况 | Progress / Statistic | 不使用 Gauge 或环图 |

Radar、Pie、Polar Area 不用于关键经营判断；漏斗优先使用横向分段 Bar 和明确数字，不为形状牺牲可读性。

### 8.2 智能经营数据映射（2026-10-10 首页收口）

| 页面 | 必须展示的图表 | 明细载体 |
| --- | --- | --- |
| 经营总览 | 账号、询盘、内容、投流健康度比较；按账号的阶段目标与提升空间 | 总经营分、已评估覆盖度、按需展开的评分口径；底部下一轮建议 |
| 账号矩阵 | 保留账号职责、配置和工作排期，不重复纯统计区 | 可编辑账号 Table / Drawer |
| 数据复盘 | 账号、询盘、投流三个一级数据区；有真实序列才展示趋势 | 总量 → 平台/账号/渠道/报告 → 内容/归因/日明细，按需展开 |

- 删除独立“内容队列” Tab；旧内容队列入口兼容跳转数据复盘，单条生产详情仍可访问。
- 总经营分仅由可核验、已评估的领域形成，并同屏显示覆盖度；缺失项不得补零、虚构目标或用参考数替代真实结果。询盘归因质量不冒充成交能力，广告消耗不直接换算投流分。
- “评分口径与数据覆盖”必须优先可视化：用横向堆叠 Bar 对比四领域的“已评分 / 待数据 / 不适用”，同屏提供领域覆盖进度和四领域拼图看板。拼图每块等面积代表一个真实口径，不以面积编码分数；已评分、待数据、不适用必须同时使用语义色、图标和文字，不得只靠颜色。覆盖率只按“已评分 ÷（已评分 + 待数据）”计算，不适用项排除分母；真实 0 分仍是已评分，缺失或非有限值保持“待数据”而不画成 0，完整文字口径保留在按需展开中。
- 数据复盘不得将不同币种直接相加；周期统计与累计平台回传明确分开；没有转化或收入回执时不计算 ROAS。
- 周经营计划的六项连续 KPI 数据带只展示指标名称和主值，不在每格下重复解释、来源或口径小字。异常状态、预算风险与恢复动作进入数据带外的反馈区；预计成本与已结算成本仍以明确指标名区分，不得因精简说明而混淆口径。
- 经营总览首屏以原周经营计划板块为同一外框与操作基础，不另叠放独立的今日数据、账号分、热门话题卡组。计划状态与六项周 KPI 之后，按今日播放、互动、真实客户进线、已发送主动触达四项展示当天信号；相邻区域使用近 7 日真实日级折线与已回传平台横向比较。账号分同屏展示已评估口径覆盖进度；热门话题仅列有原始来源的行业信号，不编造热度排名。无可核验数据时保留图标底图、缺失来源与下一步提示，不绘制假零趋势或用演示数据填充。
- 账号分采用“搭账号、提转化、扩流量、接询盘”四个等权过程维度，每个维度 25 分。评分优先检查账号资料与连接、转化路径与验收、稳定更新与发布、承接渠道与及时回复等持续经营动作；单次播放量、订单量、询盘量等结果不直接换算为账号分。首屏展示四维得分和证据覆盖，右侧“展开”使用 Ant Modal 查看逐项权重、当前证据、扣分原因与下一步；缺失证据保持待数据，不记为 0 分。
- 经营总览的本地显式预览以“界面预览”持续标识，不写入业务数据；预览卡片、指标、图表明细与工作项只打开只读详情，不触发真实任务。今日经营解读接在今日数据图表下方；右侧以企业名为标题、账号分为指标名，并按平台展示最新可追溯话题。询盘左栏合并四项指标与可展开的人群标签，右栏使用自上而下收窄的五阶段客户漏斗；每阶段保留精确人数、键盘可用详情与同源语义表，形状不冒充连续转化率。
- 内容生成任务不再分散在首页、内容创作、经营总览或灵小枢侧栏的独立队列中。所有内容任务入口统一打开应用壳唯一的“内容生成队列” Modal；同一弹窗内用 Segmented 切换任务列表与发布日历，合并、去重后默认显示全部任务，不展示来源或状态筛选，已完成任务置顶。入口带有任务或内容 ID 时在弹窗内显示该项详情，返回后仍停留在队列；关闭弹窗回到原页面，不改写主页面路由。周任务与临时单条任务可同屏查看；周计划查看、确认和启动复用灵小枢的同一弹窗，临时单条的创建仍沿用内容创作对话流程。
- 发布计划只有日期时继续使用 `allDay` 日期列并明确“全天 / 时刻待定”，不得补造小时。员工排期与发布日历的经营周起点按已持久化计划的真实开始日对齐，不得固定为周一而把周日计划拆到上一视图。发布周/日视图完整展开本周期全部紧凑卡，不设固定高度、不裁切、不分页、不折叠为 `+N`；月/全年视图仍可使用原生溢出入口。默认“已计划”无需在卡片重复显示，需处理、失败等异常状态必须保留；完整文案和制作进度进入事件详情。
- Agent 设置从周经营计划控制区移出，在统一“内容生成队列”弹窗右上角提供明确入口。入口先关闭队列，再进入经营总览内既有的 Agent 设置完整页面，不在弹窗内嵌套设置，也不新增“数字员工 → 员工排期”可见导航。周计划顶部只保留历史、删除与运行控制；设置修改默认从下一周期或尚未启动的任务生效，已启动任务继续保留其生成时使用的设置快照。
- 已存在可执行周计划时，“确认周计划”是启动生产的唯一主操作：用户点击即同时确认计划并授权本次内容生成，不再显示独立授权复选框或二次确认弹窗；系统记录模型、Token 和实际费用，但该动作不包含发布授权。它在当前页启动真实运行，不跳转到计划详情页。无计划或开始下一周时，仍可进入新目标编辑流程，但不得复用已删除的旧详情页。
- 直接启动期间，主按钮必须进入 loading 并防止重复提交；成功时明确告知“本周任务已启动”，并将用户带到实时生产/账号排期视图；失败时在当前页持续显示“周任务未启动”与真实原因、可执行的下一步，不得静默早退、只改本地状态或在后台失败时显示成功。
- 制作准备完成不等于开始生产。仅当后端已创建属于本周目标的运行 ID 和任务时，才能显示“已启动”；页面持续展示排队、执行、等待外部服务、等待确认、暂停、失败或完成的真实状态，并提供查看进度入口。其他周目标占用时须显示该目标名称、周期与状态；独立视频制作任务不作为周经营目标互斥依据。
- 账号矩阵的产品是未单独选品内容的默认值，不是该账号的独占产品。已明确绑定产品 ID 的视频保留自己的产品、素材及爆款引用；同一母版的跨平台版本保持产品身份一致。仅默认产品显示名不同不得提示“账号策略已修改”，也不得通过重新推荐整包来消除该提示。平台、语言、受众、目标和行动引导的真实变化仍须核验。
- 周任务启动核验归属、版本、计划结构、内容生成授权、幂等，以及成片制作单价。所有成片以完整成片预计制作费除以完整成片时长，统一按 ¥0.70/秒判断；预算取包含已规划重做次数的保守上限。超过时先停止启动，逐条展示预计费用、成片时长、平均每秒费用与标准上限，用户再次明确确认后才可继续；缺少可靠时长或费用估算不得默认为通过。该确认须绑定本次计划版本并留痕，不替代真实供应商费用回执，也不增加发布授权。脚本分析、素材匹配、口播、数字人、合成与质检是启动后的生产步骤，不以全部准备完成作为整周入口门槛；纯产品内容不得因缺少数字人物被阻止，只有实际包含人物口播的内容才检查人物与声音。某条内容缺资料只暂停对应内容。账号连接、渠道能力、用户成片确认和发布许可在正式发布前核验，不能以降低生产门槛为由绕过真实发布授权。
- 全局共享素材库中明确标记为共享，并具备商用、模型输入与二创授权证据的视频，可供所有租户的内容生产预检与素材匹配使用；租户私有素材仍严格隔离。成片生成后的技术与编导质检为建议性信息，不得因未取得 G4/G5 通过回执而丢弃成片或阻断其进入用户确认；文件不存在、字节损坏、来源归属不符和重复付费风险仍按技术故障处理。
- 同一运行的内容生产节点失败且可恢复时，主操作改为“继续生产”，明确复用原运行与已有产物；不重新创建周目标、不代替成片验收，也不隐式批准发布。生成服务未配置须如实显示等待原因，不能以任务创建成功冒充成片生成成功。
- 统一内容生成队列的发布日历点击内容后，在同一 Modal 内切换到“内容制作进度”详情，不再打开第二个 Drawer，也不直接跳往爆款库。详情使用紧凑封面与内容身份摘要、竖向真实制作阶段、当前卡点和唯一下一步；爆款参考作为次级入口保留。跨平台内容明确显示共用制作结果，但不共享或虚构发布回执。预生产脚本/素材准备与真实口播、数字人、合成产物区分；未知、不适用、待处理不能画成完成或假百分比。打开详情与定时刷新均只读取，不启动、重试或扣费。
- 数字人首次接入收敛为两步：先建立人物，再完成平台认证。第一步先让用户选择“录入我的人物（推荐）”或“选择 HeyGen 已有人物”；自建人物优先使用网页摄像头一次录制，系统从同一段视频生成训练视频、认证照片与口播声音，上传文件只作为设备不可用时的降级入口。第二步集中展示 HeyGen 本人授权与方舟认证，并复用第一步已经保存的照片和视频，不得要求重复上传。新人物尚未授权时，必须明确显示新人物的进行中状态和唯一继续入口；旧默认人物可以为保证存量任务继续运行而保留，但不得冒充本次录入结果。
- 数字人物录制取景必须使用可识别的人头、颈部和双肩轮廓，不得用胶囊形或普通圆角矩形代替人体。录制层同一时刻只强调一个动作，首个动作固定明确为“看镜头，保持自然微笑”；头肩入镜、点头和少量手势等后续要求按步骤提示，提示不得遮挡面部。
- 企业知识库的“企业真实资料”一级区只保留生产链路当前直接消费的公司名称、行业类目和企业类型；成立年份、公司简介不再作为可见表单字段或完成度条件。“社媒策略”不再占用独立一级页签，历史持久值兼容保留给既有生产链读取，旧深链统一回落到企业真实资料。
- 运营小程序一级工作区固定为“素材整理”和“待拍任务”。素材整理支持图片、视频上传，以及按类型、名称、产品和分析标签筛选；待拍卡片在不进入详情时可直接静音预览对应参考画面的前三秒，三秒后自动暂停并回到起点。预览缺少真实素材时必须回落为分镜信息，不得使用占位视频。

### 8.3 图表视觉限制

- 每张图有中文标题；单位与时间范围合并为紧凑元数据或轴标签，不再新增解释性副标题。口径详情按需查看，核心数值不可只藏在 Tooltip。
- 超过 1 个数据集必须有图例；图例名称与表格列名一致。
- Line 最多 5 条；堆叠 Area 最好不超过 3 条、硬上限 5 条。
- 普通 Bar 最多 10 条；Grouped Bar 每组最多 4 类且最多 6 组。
- Stacked Bar 每条最多 5 段且最多 10 条；Pie / Doughnut 最多 5 片。
- 线宽 2px；多序列同时使用实线/虚线、点型或图案，不能只靠颜色。
- Tooltip 只补充精确值，不承载结论或唯一信息。
- 简单图默认提供“查看数据表”；需运营导出的图提供 CSV 下载。产品明确要求隐藏冗余明细时，可移除可见展开与导出入口，但必须保留与图表同源、仅供辅助技术读取的完整语义表。经营健康概览中的“经营健康度与完善目标”和“四领域评分口径覆盖结构”采用此紧凑例外。

### 8.4 空、错与演示数据

- 没有真实数据时不画零趋势、不造波动线；显示 Empty、缺少的数据源和恢复动作。
- Mock 或演示数据必须在图题、图例和数据表中持续标记“演示数据”，不得与真实值同视觉层级。
- 数据同步失败保留最后一次确认的数据，显示更新时间和错误，不清空为 0。
- 指标口径、统计范围和时区必须能从图旁查看。

### 8.5 无障碍与性能

- Chart.js Canvas 必须提供 `role="img"` 和准确 `aria-label`，并在旁边提供文字结论与同源数据表；数据表默认可展开，产品明确隐藏时改为 `sr-only` 语义表并由 `aria-describedby` 关联，不得只留下 Canvas。
- 大数据预整形后使用 `parsing: false`、`normalized: true`；折线图使用降采样。
- 高负载图关闭动画、固定合理轴范围并限制 tick 数量。
- 每个响应式 Canvas 使用独立、相对定位的父容器。
- 图表按需注册并 tree-shake；不得把完整 Chart.js 全量打入每个页面。

## 9. 状态、反馈与长任务

### 9.1 状态字典

| 状态 | 色彩 | 必须显示 |
| --- | --- | --- |
| 未开始 | 灰 | 等待条件或计划时间 |
| 排队中 | 中性蓝 | 队列位置或预计开始时间 |
| 执行中 | 信息蓝 / 蓝紫进度 | 当前节点、责任 Agent、已完成数量、预计剩余时间 |
| 等待用户 | 琥珀 | 缺少什么、影响什么、唯一下一步 |
| 失败 | 红 | 失败节点、已保留结果、重试或人工处理 |
| 完成 | 绿 | 结果数量、完成时间、查看结果入口 |
| 暂停 | 灰棕 | 谁暂停、如何恢复 |

平台色、Agent 身份色、状态色三者不得混用。

### 9.2 反馈层级

| 反馈 | 组件 | 存续时间 |
| --- | --- | --- |
| 保存、复制等轻量成功 | Message | 2–4 秒 |
| 后台完成、需要后续动作 | Notification | 可关闭，带结果入口 |
| 页面持续风险或阻断 | Alert | 直到条件恢复 |
| 重要流程终态 | Result | 用户确认离开前保留 |
| 首次加载 | Skeleton | 与最终结构一致 |
| 局部短等待 | Spin | 不覆盖全页 |
| 可计算长任务 | Progress | 显示真实阶段与数量 |

所有改变数据或启动任务的动作必须具备：即时 loading、成功结果、失败原因、可执行下一步。不得只显示一个旋转图标或“处理中”。

### 10.1 品牌渐变按钮

- 渐变按钮只用于页面或流程的唯一主操作，例如“开始本周任务”“生成成片”“发送消息”。Ant Design 的 `Button type="primary"`、`LsBrandAction` 与兼容旧页面的 `.btn-primary` 统一使用此样式；普通保存、筛选和返回使用 `Button type="default"`，删除使用危险操作语义，不套品牌渐变。
- 同一区域最多一个渐变按钮，不与另一枚 Primary Button 并列争抢。
- 默认、hover、active、disabled、loading、focus-visible 必须完整；禁用态移除渐变，loading 不改变按钮宽度。
- 不允许用渐变装饰普通 Card、Tag、输入框或导航。
- 灵小枢的“待你决定”概要气泡是受控例外：它是从对话进入单项决策详情的短时提示入口，只能复用 `--ls-action-gradient`，同时只显示一张，不得将该例外扩展到普通内容卡、数据卡或审批详情卡。

### 10.2 渐变进度

- 本规则是全站唯一进度样式：视频生成、素材处理、Agent 工作节点、资料完整度和配额使用均必须使用 `LsGradientProgress`，不得在业务页重新拼装单色 `div` 进度条。
- `line` 表示长任务、资料完整度与生产进度；`circle` 表示单一目标；`dashboard` 表示容量或接近上限的指标。
- 百分比必须来自真实数据。未知进度用 Spin + 当前节点，不能显示虚构百分比。
- 渐变仅编码“从开始到完成”的连续变化；失败、超限和阻断切换到语义色。
- 中心可显示百分比、完成图标或数值，不同时堆叠三者；进度文字可被读屏获取。

### 10.3 足不出户与流程弹层

- 用户首次进入的新手引导使用 `LsFlowDialog`：顶部 Steps、中部当前步骤说明、底部“跳过”与唯一主操作。关闭弹窗后可继续在页内高亮目标，完成当前操作后再打开下一步。
- 首页「灵枢如何助力海外增长」实景导览例外：逐步高亮真实页面目标，说明使用贴近高亮区域空闲角落的小对话气泡，不固定在视口右下角；用户只需按 Enter 执行当前安全动作并进入下一步，Esc 暂停并保留进度。导览不得代替用户发送消息、覆盖已有草稿或创建任务。
- 2–4 步、可在 10 分钟内完成且不要求深链的流程可使用 `Modal + Steps + Form`。
- 新周目标编辑、内容制作、产品导入和账号设置必须使用完整页面；已有周计划从首页直接启动，不再打开详情确认页。弹窗不能套侧栏模拟一个新应用。
- 2026-10-28 周计划确认收束为单页：在“采集 → 生产 → 分发”三列任务流程上方展示已结算内容制作成本、实际投流成本与已核验合计三块成本；各列纵向列出所属任务，生产列展示已匹配爆款视频的缩略图与标题以及图文参考。没有真实结算或投流回执时明确显示“暂无结算”或“暂无可核验支出”，不得将预算预留、供应商估算或缺失回执的金额冒充实际成本；已核验合计注明不含未回执支出。不展示目标说明段落、逐条视频成本展开区或重复的启动提示。普通情况只有“确认周计划并开始运营”一个主操作，不再先确认方案、再确认预算。平台发布分配只是前置计划，不限制内容生成，实际发布平台由用户在发布时确认。仅当某条成片最高费用预留超过 ¥0.70/秒时，点击启动后暂停并弹出简短的超预算确认，不在确认页常驻展示逐条费用警告；取消则不启动，报价版本变化需重新核对。真实广告投放仍受平台授权、独立执行与回执约束。
- 周任务流程参考三阶段任务流图：采集、生产、分发使用连续箭头标题；每栏任务卡竖向排列，以向下箭头串接，并以跨栏箭头明确阶段流向。生产参考数量较多时每页最多展示三条，提供上一组/下一组及总数，不使用无限高度的内滚动。经营总览顶部与下方分析板块共用外层宽度，顶部卡片不单独设置高度上限或内层纵向滚动。灵小枢侧栏的“新建一条内容 / 修改已有内容 / 发布指定成片”直接进入输入框上方同一行快捷入口，不再保留“执行任务”折叠行；点击后沿用原核验表单与审批门禁。
- 周任务流程的采集栏将编导计划明确拆为“采集并筛选爆款参考 → 逐条分析爆款结构 → 编写适配脚本 → 完成镜头分镜”，不得再用一张“分析爆款并完成脚本分镜”卡片概括。分发栏不得把周复盘充当发布任务；按已冻结的发布位逐条呈现真实平台标识、来源爆款参考标题、是否复用适配及推荐北京时间，最多每页三条，并明确平台和时间仍由用户在实际发布时确认。内容制作成本只合计本周已结算回执；没有可归属本周的投流回执时不将投流预算或汇总快照当成实际支出，已核验合计不冒充完整实付。
- 当前步骤、已完成步骤、阻断原因和退出后的保存策略必须明确；关闭后焦点回到触发点。

### 10.4 加载与即时反馈

- 首次页面或卡片加载使用 Skeleton；局部等待使用 Spin；已知总量使用 Progress；按钮提交使用 Button loading。
- 主操作不得以跳转替代执行。“开始周任务”等真实运行操作必须在同一交互中给出 loading、成功或失败结果，以及明确的下一步；失败详情必须保留服务端返回的真实原因。
- 预计超过 2 秒必须显示当前节点或解释；可取消任务提供取消；后台长任务离页后继续并可恢复。
- 输入校验贴近字段且持续存在；短成功用 Message，跨页面或带操作的消息用 Notification，阻断用 Alert/Result。
- 自动刷新不得清空旧数据；新内容到达先提示“有更新”，由用户决定是否刷新高密度列表。

### 10.5 紧凑字段组合

- 电话区号 + 电话、筛选条件 + 搜索、金额 + 币种、时间范围等强关联字段使用 `Space.Compact`。
- 组合后的 Tab 顺序、错误归属和读屏名称仍需独立明确；不得为了视觉紧凑而把无关动作粘在一起。

### 10.6 头像组

- `Avatar.Group` 用于显示责任人、客户参与者、协作 Agent；超过可见数量用 `+N`，Popover 展示完整清单。
- 头像无图片时使用稳定的姓名首字或平台身份，不随机换色；状态点与未读点不能混用。

### 10.7 渐进媒体与瀑布流

- 所有图片和视频先展示比例稳定的占位，再显示加载、生成百分比、成图/成片或失败重试；加载过程不能引起布局跳动。媒体状态必须经由 `LsMediaStateFrame + LsProgressiveMedia`，不使用空白黑框或纯文字占位。
- 视频卡在进入视口后主动解析可用封面或首帧，不能依赖鼠标悬停才加载；分析暂停、取消等任务状态不得遮住已存在的媒体画面，并必须在详情中提供“继续分析”入口。
- 多图预览使用 Ant Image PreviewGroup；敏感或未发布内容可加 Watermark。
- 素材库与爆款视频库使用 Masonry：列宽统一，卡片高度由真实媒体宽高比和内容自然决定，不强制等高或 9:16。卡片保持首帧、时长、平台、来源、产品关联、收藏与可用状态；媒体存在宽高元数据时在首次绘制就预留正确比例，未知时使用中性占位并在真实媒体可用后更新。任务队列、账号和审批禁用瀑布流。
- 日历不使用 Masonry 布局引擎，但内容/发布事件必须使用同一套“媒体优先”卡片语法：周/日/列表视图显示首帧、平台账号、标题、时间与状态；月视图空间不足时保留平台、标题和状态，详情 Drawer 展示完整首帧。

#### 10.7.1 产品素材聚合卡与预制场景

- “我的素材”以稳定产品身份为单位展示：每个企业产品有且仅有一张产品素材占位卡，产品主图、其他图片/视频和预制场景不再作为多张同级卡散落在主墙中。
- 产品卡使用主图的真实原始宽高比，与其他素材共同进入 Masonry；没有可用主图时使用中性占位，不伪造封面。
- 点击“查看详情”从右侧打开 Drawer，在同一层级展示该产品的全部真实素材和预制场景缩略图；主页不单独放置“产品预制场景”板块。
- 预制场景只用“预制场景 1 / 2 / 3”等中性顺序名称与真实状态，不在前端编写具体画面描述或刻意场景分类。空场景位是准备目标，不是可用素材；人工上传不设时长上下限，仅产品归属一致、原始字节可完整解码、实际时长大于 0 且通过生产可用性校验的真实视频显示“已入库”并供内容 Agent 调用。系统生成目标时长可作为准备建议，不得用于拒绝人工上传。
- 未完成场景只显示“素材准备中”或“等待产品图片”，不得补造封面、来源、百分比、计时器或完成态；上传/更新必须在服务端绑定当前产品与槽位，内部补录和服务切换不进入用户文案。

#### 10.7.2 素材使用履历与表现回流

- 素材只有在真实成品产出并形成可核验 artifact 后才记为一次使用；编辑器选中、分镜草稿引用、预览和失败任务都不计数。每次使用记录必须绑定内容项目、成品版本、时间、实际镜头和素材角色。
- 与成片时间轴 0–3 秒相交的素材单独标记为“前三秒钩子”；普通素材卡和产品素材详情卡只显示简洁的总使用次数与前三秒次数，不把完整数据堆进瀑布流。
- 素材详情 Drawer 使用连续指标带展示总使用次数、前三秒钩子次数、已发布内容数和累计播放，并按内容成品列出使用时间、角色与历史表现。历史条目按最近使用排序，不以页面卡片墙替代记录列表。
- 数据表现只接受可归属到该内容成品的真实发布回执和平台指标；未发布显示“尚未发布”，已发布但尚无指标显示“等待平台数据回传”，禁止用零值、估算值或演示数据伪装真实表现。
- 素材复用可按播放、互动、线索及钩子角色提供排序依据，但界面不得把相关性写成因果结论；不同内容共用同一素材时，每个成品版本独立留痕并避免重复累计同一发布回执。

### 10.8 数据看板

- 全部数据页固定为：筛选范围 → 连续指标带 → 主趋势 → 分布/排行 → 可执行建议；使用 `LsDataChart` 和连续网格构成的多维分析页，禁止把每个数字都做成渐变卡片。
- 图表必须显示标题、单位、时间范围、口径、图例、真实数据/演示数据标记以及空错态。
- Progress 适合完成率，不代替趋势；Chart.js 适合趋势与比较，不用装饰图形填满空白。

### 10.9 Messenger 式客服工作台

会话页采用 Messenger 的高效三栏信息架构，但使用灵枢品牌 Token 与真实业务能力，不复制 Meta 商标与专有素材：

1. **左栏**：标题“聊天”、实时搜索、视图/筛选、按最近动态排序的会话；头像、来源、未读、最后一条消息和时间一眼可辨。
2. **中栏**：客户头像与名称、参与者 Avatar.Group、会话操作；消息气泡、附件/表情/GIF；底部固定输入与唯一发送主操作。
3. **右栏**：大头像、名称、来源与本地时间；分享、资料、通知、搜索；“影音内容、文件和链接”“客户与销售工作台”“隐私设置与支持”使用 Collapse 渐进展开。
4. 桌面三栏可同时显示；平板收窄左/右栏；移动端以列表 → 会话 → 资料的可返回层级呈现，不横向挤压。
5. AI 草稿、人工修改、知识引用、报价与客户意图继续保留真实来源标记，不伪装成客户消息。
6. 左栏桌面目标宽度为 232px，平板最小 196px；会话项使用独立 8px 圆角选中面，项与项之间 6px，默认无框，不使用连续的 Button 默认边框。
7. 会话名称使用 13/20、600；最后消息使用 12/18、最多两行；时间和来源使用 11/18。所有列表文字必须在边框内完成排版。

### 10.10 卡片、菜单、分页与步骤

- Card 只表示可独立操作或独立复用的对象；普通区块使用标题、Divider 与留白，卡片不嵌套超过一层。
- Menu 是应用导航的唯一结构源；收起态有 Tooltip，选中态同时使用背景、文字和侧边标记。
- 超过一屏且全量渲染昂贵的对象列表使用 Pagination；桌面显示总量、每页数和必要时快速跳转，移动端使用 simple。
- Steps 只用于有真实先后依赖的任务；显示当前、完成、等待、失败和预计时间，窄屏改为竖向或精简步骤。

### 10.11 图标、插画、邀请与边框动效

- 图标遵循“准确、简单、节奏、愉悦”：同一功能只保留一种图标语义，线宽、视觉尺寸和对齐一致。
- 插画只用于登录、空状态、完成页、引导与品牌说明；工作区优先真实产品、人物与媒体，插画不能冒充业务证据。
- 邀请分为静态、hover、推论和“更多内容”四类；所有邀请可关闭、可键盘触发，不反复打扰。
- BorderBeam 只能服务短时邀请，持续不超过 3 秒或一次 hover；减少动态效果模式下隐藏。

### 10.12 间距与亲密性

- 页面按 1440px 设计板、24 栅格、8px 基础网格实现；常用关系间距为 8 / 16 / 24px。
- 同一信息组内 8px，字段与同组说明 8–12px，平级对象 16px，章节 24–32px；必要时用 Divider 替代无限加大空白。
- 强相关对象靠近，弱相关对象分开；不得用随机 margin 修补布局。

### 10.13 灵小枢决策入口

- 会话生成回复时输入框仍可输入并提交文字；新提示词按发送顺序在输入框上方以紧凑条目显示，可逐条移除，当前回复结束后依次发送。附件随草稿保留，等待当前回复结束后发送。排队提示词只属于当前账号与会话，刷新或切换会话后恢复时须先暂停，由用户确认继续；清空会话后不再发送。
- 生成期间只保留一个会话内“思考过程”，不展示等待秒数或重复转圈。每两秒追加简短的任务状态提示，措辞按真实后台活动区分读取资料、分析资料、联网调查及引用核验；尚无活动回执时显示“思考中”。最新一条末尾显示省略号，之前的条目不重复显示省略号。定时提示不得虚构新阶段、发现或完成结果，不展示模型内部推理。最近八条提示内部滚动，完成、失败或停止后立即停止追加。
- 桌面灵小枢会话右上角使用共享 Dropdown 提供新建、历史、清空与删除。历史列表每条会话提供删除菜单；危险操作使用小 Modal，明确不可撤销及保留范围。清空保留会话身份与名称，移除消息、未提交草稿、引用卡片和聊天上下文；删除移除历史入口并打开空白新会话。任务、素材、企业资料和明确保存的长期记忆独立保留，清空/删除不得取消任务。切页和短暂关闭保留会话；版本冲突、迟到流与旧标签页不能恢复已清空消息。正在提交业务动作或恢复未知任务回执时，须先完成回执同步，再切换/删除会话。

灵小枢是全局的**决策与轻操作入口**，不是 Agent 运行监控台。其默认目标是用单列对话承接当前页面的信息和必要决定；复杂信息仍回到对应业务工作台。

- 回复像了解业务的同事自然交流，不设三句话或固定建议条数，也不机械套用“结论—原因—按钮”。状态查询直接回答，建议、比较和原因分析保留足够判断的解释与取舍，默认一屏内读完；删掉重复背景、内部术语与空泛总结，不删掉判断依据。普通交流不强行追加表格、图表、卡片或快捷按钮；真实任务、审批和文件才使用对应业务组件。
- 详细依据与更多方案支持在同一气泡中用共享Ant Collapse按需展开，不强迫跳页。新回复可用details块；明确要求详细说明时默认展开。历史超长的多段解释仅在完整段落边界折叠，不截断句子，不折叠交付文案、表格或文件卡。费用、失败、风险和审批条件始终保留在正文；原始内容与证据不被覆盖。普通项目列表不转换成按钮；可选next块最多承载两个可编辑草稿入口，不得用“是否需要”“是否立即”等二次确认问题。点击只把草稿或补录模板填入输入框并聚焦，用户修改后主动发送；模型文本不生成执行按钮或自动发送。
- 快捷查询与分析回复共用“关键判断先可见、补充证据后展开”的阅读规则，但不得共用一套固定回答模板。周经营按状态、阻塞和优先动作组织；资讯按事件、日期、来源和业务影响组织；经营数据突出真实数字、变化和异常；内容、发布、投放、客户及企业资料分别沿用其业务对象与状态语言。标题、列表、短表格、图表和自然段按场景选用，不要求相同栏目或相同条数。
- 快捷查询不得按字数把正文机械切成“摘要 / 详细分析”。失败、风险、关键数字、阻塞、建议动作和影响判断的依据始终裸露在正文；仅将逐项明细、统计口径、完整证据、次要来源和备选方案折叠，并使用“逐项任务与判断依据”“统计口径与逐项数据”等场景化名称。联网资讯和参考数据的已核验来源在正文附近先显示最多三个可点击入口，其余来源再折叠。
- 查询回复可在可见正文后提供一至两个由产品预设的相关工作区深链，例如经营总览、内容任务、发布与渠道、计划管理或智能客服；深链只导航，不代表执行授权。不得从模型文字猜测页面、对象 ID 或执行动作；有精确业务对象时继续复用真实任务/来源门户。
- 空会话保留页面相关快捷入口方便开始；进入正常交流后，通用页面快捷项收进“页面快捷入口”，由用户主动展开，不在每轮回答下重复铺满。真实待办与交付卡继续按业务状态显示，不受此收起规则影响。
- 禁止在正文暴露内部字段、状态枚举、数据库路径、记录ID、内部产品序号、集合扫描数量、供应商原始报错、HTTP状态、像素总数或调试JSON。历史回复显示层同样过滤技术信息并把已知状态、故障翻译为用户影响与可采取动作，不改写后台证据与执行命令。真实产品名、平台名及用户要求的外语交付文案保留。
- 用户明确要求PDF或JPG文件时，正文整理与实际文件渲染分开：对话只显示生成状态和经服务端确认的文件卡，不能用可复制正文替代文件。文件卡显示名称、类型、大小与下载动作，下载须验证当前租户及用户；失败不宣称已生成。业务路线图JPG必须标注示意图；地理地图需明确地区、标注内容和可信来源，不能以业务示意图或文字图片替代地理地图。生成文件不等于对外发送或客户承诺。

- 首次点击固定打开单列对话首页，不设“待你决定 / 问灵小枢”并排页签，也不展示 Agent 选择轮盘或执行记录。消息与提示气泡在上方独立滚动，输入框固定在面板底部。
- 空线程欢迎语只在该线程首次进入时作为一条普通助手气泡出现，随后与消息一起进入滚动流；不得置顶、固定悬浮、占用独立欢迎区，也不得在每次收起再打开面板时重复插入。线程已有消息时不再显示欢迎语占位。
- 同一轮新出现的欢迎语、消息与概要气泡按视觉顺序做一次短时依次进入：仅使用 `opacity + translateY(≤8px)`，相邻间隔不超过 60ms、整组不超过 `--ls-motion-enter`，不得循环或在普通重渲染时重播。此为对话叙事顺序的受控 stagger 例外；键盘聚焦的内容立即可见，`prefers-reduced-motion` 开启或运行中切换后全部即时显示。
- 原生小程序使用独立的“Hi 灵小枢”会话页，底部导航固定从左到右为“Hi 灵小枢 / 我的素材 / 我的客户”。我的素材标题下横排“去拍摄 / 去上传”，前者进入可返回的素材拍摄子页面，不设独立拍摄 Tab，后者复用现有素材选择和上传流程；我的客户复用客户会话、搜索、渠道筛选及全部/未读/待回复/待跟进列表。空状态仅保留居中问候与简短说明，不显示品牌图标及“今天想推进什么？”标题，左上角菜单打开白色左侧栏，依次提供标题、账号设置、会话搜索、新对话和历史会话；暂不增加其他功能入口；四张快捷卡片固定在输入框上方横向排列，输入框与底部安全区、键盘联动。白底、中性文字、蓝紫主操作沿用共享主题。离开会话页面或退出后默认清屏；再次打开显示空白新对话，首次发送时才创建会话，不自动恢复最近消息或上次未发送的问题。退出前的迟到回复不得写回新页面；后台已保存记录及已受理业务动作的回执保持原有恢复机制。用户发送后即保存到历史会话，离开页面不取消已发起请求；侧栏显示真实处理中状态，持久化有效回复或成功执行回执后显示红色“1”，打开阅读后清除。未确认、失败或取消不能标记完成；未读按当前账号及设备保存。选中历史会话在主会话页继续交流，处理中只查询已有结果、不重复提交任务。消息区和侧栏保留滚动但隐藏滚动条。
- 小程序客户会话的 AI 推荐必须来自实际成功结果，不以固定话术填补失败或不足的推荐；失败保留重试入口。中文外发在防抖等待、翻译处理中、翻译失败或译文不对应当前草稿时禁发，显示原因与重试翻译；不得静默发送中文原文。私有图片先通过带鉴权的下载接口取得本地临时文件再展示；相机上传后关联失败保留素材 ID，重试只关联、不重复上传。
- 对话记忆由后台既有机制默认维护；灵小枢前端不展示“对话记忆”、查看已确认决策、保存为经营决策或撤销决策等入口，不用记忆管理工具条占据对话首屏。
- 待办只先在对话中显示一张可点击的概要气泡，不在首页直接展开事实、备注与操作组。周计划由经营总览的周经营计划区和首页快捷入口承接，不在灵小枢中重复显示“请确认本周的内容计划”概要；首页已有周计划时显示“查看周计划”，没有周计划时显示“创建周计划”，并默认发出创建周计划提示词。
- 点击权威待办概要或普通任务概要时，统一在灵小枢对话面板之外打开标准 Ant `Modal`，完整 `LsAssistantDecisionCard` 和任务详情都由该外部弹窗承载。两类详情必须复用同一个 Modal 容器，不得在 420px 对话面板里增加第二页、分栏或嵌套 Drawer。
- 关闭外部决策 Modal 只关闭详情，不关闭或重置灵小枢对话，不暂停正在执行的任务；对话滚动位置、草稿、附件、已聚焦任务与助手开启状态必须保留。关闭后焦点返回原概要气泡；减少动效模式下禁用位移过渡。
- 同一时刻只突出一项最高优先级待办，并在概要气泡显示剩余数量；完成或退回后自动切换到下一项，不形成审批卡片墙或 Carousel。
- 全局排序固定为：开始计划 / 调整计划 → 发布、发送、报价与商业承诺 → 内容与质量审批 → 必填资料 → 当前页面唯一下一步 → 上下文快捷问答。阻断后续任务的事项优先于普通提醒，同级按截止时间和创建时间排序。
- 计划开始、调整、批准、退回、补充必要字段等轻量动作应能在灵小枢内完成。完整计划、逐镜内容、大表格、大图表和批量编辑只提供“查看完整计划/详情”深链，在完整页面或 Drawer 中完成。
- 灵小枢禁止展示 Agent 执行日志、事件流、历史轨迹、内部推理、长任务逐步输出和大量经营数据；这些内容进入数字员工工作排期、任务运行状态或对应业务操作台。
- 决策卡必须来自真实后端状态，至少包含稳定 ID、类型、优先级、对象版本、标题、必要摘要、影响、唯一主操作、可选退回/查看详情以及来源页面。不得从聊天文本猜测可执行动作，不得用模拟数据补空。
- 审批与计划动作提交时必须带当前对象版本或等价校验。后端遇到版本过期、审批已处理、依赖变化时返回冲突，由前端刷新队列并明确提示，不能覆盖新状态。
- 当前页面上下文决定无审批时的下一步：智能经营优先计划与经营决策，内容制作优先缺失素材/内容审批，发布与渠道优先发布批准，客户与会话优先发送/报价批准。路由上下文不可作为授权，最终动作仍由服务端核验租户、权限、状态与版本。
- 无待办时不保留概要卡占位；对话仍可直接输入。空会话可保留当前页面快捷入口以方便开始；进入正常交流后收起到用户主动打开的菜单，不在每轮回复下重复铺满固定推荐。
- 灵小枢启动动作必须以真实运行回执确认结果；启动后同步刷新对话概要、外部详情与智能经营页，移除已处理的待确认卡，并出现一次简洁结果气泡。运行已创建但随后等待、失败或取消时，气泡使用对应状态，不能统称“正在生产”。真正受阻时保留待办、显示原因；不得将所有 HTTP 409 都误报为“待办已更新”。执行日志仍只在业务操作台展示。
- 全局入口允许用户通过独立的 44×44px 控件手动收起到右侧；收起后只保留贴边的 44×44px 恢复入口与待办 Badge，不显示横向提示气泡。收起偏好保存在本地，系统不得自动缩边，也不得恢复拖动定位；收起与恢复都必须支持键盘操作并把焦点交给替代入口。打开对话时仍显示可关闭入口，关闭后按用户偏好返回完整或贴边形态。
- 桌面默认采用 420px 的右下锚定弹出面板，概要页与详情页保持同宽、切换时不得横向跳变；知识采集等明确需要更宽表单的工具页可扩展至 560px。视口不足时收紧到左右各 16px，移动端全屏；正文独立滚动、输入区固定、Esc 可关闭、焦点进入与归还完整。概要气泡与主操作复用受控蓝紫渐变，同一详情操作区仅一个主按钮；等待、失败、成功仍使用固定语义色。
- 输入区与面板底部使用同一白色表面，以留白和轻微层次区分，不使用包裹整块输入区的生硬描边或灰底方框。文本框本身不显示浏览器默认矩形 `outline`；键盘或指针聚焦均由最外层圆角输入容器提供符合 3:1 对比度的柔和 `focus-within` 边框或光环，不能通过移除焦点提示解决视觉问题。附件与发送操作保持在同一输入容器内并满足 44×44px 触控目标。
- 小程序灵小枢默认呈现文字输入，输入框左侧独立的 44×44px 加号展开向上浮出的单列能力快捷项；选中后直接把该能力的默认问题作为普通对话发送，不进入能力说明页，也不自动执行审批或生产动作。无文字草稿时输入框右侧显示语音入口，切换后按住录音、上滑取消；语音识别只回填可编辑文字草稿，必须由用户再确认发送。菜单与语音控件均复用现有对话状态和语义色，不占据消息滚动区。
- 小程序统一工作首页保留六项真实经营指标，以“内容生产 / 客户经营”两组连续数据带呈现；每格默认只显示指标名与主值，零值保持中性色，不展示难以扫读的“待办/已完成”斜杠组合，次级口径保留读屏语义。下方“今日待办”先按拍摄、任务与审批、客户、成片验收汇总为工作类型；多条待拍镜头只显示“今天需要拍摄 N 条”并跳转素材拍摄，其他类型默认收束、点开后仍可进入原业务对象。汇总仅使用当前工作台已有的真实队列与日期口径，不伪造截止时间或额外任务。
- 新待办到达只更新数量与当前卡片，不播放持续动效；卡片切换使用共享 `lsMotion` 的容器变换，`prefers-reduced-motion` 下即时切换。

### 10.14 内容制作工作台

- 灵小枢新建内容任务采用对话内逐项问答：产品、内容目标、平台、交付截止时间，每轮仅展示当前问题的控件，收齐后显示概要并由用户明确确认再提交。不使用一次性多字段创建弹窗。产品复用 Ant Select 的可搜索多选模式，真实读取企业知识库；新产品显式保存到知识库后方可选用。现有单产品任务契约下，多选产品分别创建独立周任务，确认时必须说明数量；部分成功重试不得重复创建已成功任务。关闭同页对话保留正在收集的答案，切页或身份变化取消未提交的收集。

- 每条内容从口播确认、分镜匹配到成片导出，顶部都必须使用同一个可编辑草稿名称作为对象身份；名称在步骤切换、项目续做、刷新和再次打开时不得回退为参考视频名或通用阶段标题。
- 可编辑草稿名称统一使用 `title-large`（20/28）字号，不得沿用表单输入框的正文默认字号。
- 内容制作工作台不重复展示“口播替换—分镜匹配—成片导出” Steps 或“画面预览”等通用区块标题；当前任务由主区真实内容、节点状态和固定底部操作表达。账号连接、产品导入等仍有真实顺序依赖的流程可继续使用 Steps。
- 固定底部操作区只承载保存状态与前进、后退、预览操作，不展示待办、警告、错误原因或其他提示框；阻断说明必须放回发生问题的字段或步骤设置区，临时反馈使用全局 Message / Notification。原成片失败镜头与局部返工属于原生产任务，不嵌入内容制作工作台顶部。
- 用户仅进入内容制作、切换内容或恢复草稿时不得自动弹出“任务已带入”“本地演示模式”“未关联员工任务”等说明性 Message / Notification；只在用户主动操作完成或发生必须处理的错误时给出一次反馈。
- 任何深链或续做请求在进入分镜匹配前，必须先完成项目、参考视频、口播、产品映射与本地草稿的原子化恢复。依赖未就绪时保留在可解释的准备态，不允许先跳入空壳分镜页、显示全白页或要求用户返回重试。同一续做请求只能应用一次，但必须在水合完成后才标记为已应用。

## 11. 响应式与无障碍

| 断点 | 规则 |
| --- | --- |
| `>= 1280px` | 完整侧栏、12 列、并排主辅区、完整日历 |
| `768–1279px` | 可收起侧栏、8 列、辅助区下移、Drawer 不超过视口 60% |
| `< 768px` | 4 列、单列、全屏菜单、Modal/Drawer 全屏或底部面板、日历默认列表视图 |

- 触控目标不小于 44×44px。
- Tab 顺序与视觉顺序一致；所有图标按钮有可访问名称。
- `prefers-reduced-motion` 下关闭循环动画、平滑滚动和大位移。
- 表格在移动端优先变成分组列表或保留关键列，不能靠不可发现的横向滚动完成核心任务。
- 所有功能在没有 hover 的触屏设备上仍可完整使用。

## 12. 迁移方案

当前仓库已引入 Ant Design 6.x、FullCalendar 与 Chart.js，并保留 Tailwind、Lucide、motion、dnd-kit 和迁移期 Recharts。迁移通过全局主题、共享 `Ls*` 组件与逐页替换完成；不得仅在一张示例页实现，也不得一次无验证地全局替换造成主链路回归。

### 12.1 P0 基础层

1. 锁定 Ant Design 6.x 小版本，建立 `ConfigProvider + App` 和 Token。
2. 建立 Button、Form、Table、Modal、Drawer、Feedback、Status 的共享适配层。
3. 建立统一 `LsCalendarEvent` 和 FullCalendar 外壳；先迁移“发布与渠道”。
4. 建立 Chart.js `LsDataChart`，先迁移“智能经营数据复盘”。
5. 建立视觉回归和键盘/焦点测试；新页面不得继续手写基础控件。

### 12.2 P1 核心主链路

1. 智能经营四页：数据带、账号矩阵、内容队列、数据复盘。
2. 周计划与 Agent To Do 排期：根据许可证决定 `resourceTimeline` 或 Standard 方案。
3. 灵感中心：筛选、卡片、媒体 Drawer、逐镜详情。
4. 内容制作：流程、素材选择、分镜、批量复核和成片预览。
5. 会话、客户、订单与企业知识库。

### 12.3 P2 收口

1. 定时任务、集成、权限、管理后台。
2. 恢复平台投放时按本规范重建图表与表单。
3. 删除旧日历、旧弹层、旧 Recharts 包装和重复 CSS。
4. 清理无语义渐变、超大圆角、重阴影、英文装饰眉题和散落硬编码颜色；保留本规范定义的受控品牌渐变。

### 12.4 共存规则

- 新功能只能使用新组件层。
- 同一页面不得同时出现旧/新按钮、弹层或状态样式。
- Recharts 与 Chart.js 只允许跨页面临时共存，不允许同一页面混用。
- Lucide 保留为唯一产品图标集；平台官方 Logo 独立管理。
- FullCalendar Premium 在采购前不得进入商业生产构建。

### 12.5 网页与原生小程序共享实现（2026-10-11）

- 两端共用 `shared/design/tokens.json` 作为本规范 Token 的代码实现源，生成网页 TypeScript Token 与小程序 WXSS；修改产品规则时先更新本规范和源，再生成两端产物。不得分别维护主色、字体刻度、圆角与动效。
- 小程序 `styles/components.wxss` 为共享基础控件的原生适配层，页面复用按钮、表单、导航和状态样式；React/Ant Design 组件保持网页实现。移动触控目标有物理 44px 下限，尺寸 Token 采用 rpx 响应式映射。
- 任务通用状态、Agent 角色和上海经营周规则由共享领域模块提供；海外发布排期继续使用既有冻结时区，业务专用状态文案允许显式覆盖。
- 网络与微信设备权限由平台适配器处理；两端共用错误分类。平台无关请求策略还提供网页版本命令校验、网页账号请求锁和小程序执行回执终态基础；既有动作流程继续要求明确确认，不从自由对话推断可执行动作。
- `pnpm run sync:mobile-shared` 生成产物；`pnpm run check:mobile-shared` 验证同源一致；`pnpm run test:mobile-shared` 验证业务行为和小程序包依赖完整性。网页开发/构建前执行一致性检查；小程序导入开发者工具前也需检查。生成文件禁止手工编辑。

### 12.6 共享表单、任务状态与拍摄基础（2026-10-11）

- 通用审批字段采用共享表单校验源：必填、字数、明确数值、HTTPS 链接和选择 ID。内容生成采用“明确任务授权 + 不限额计量”：启动前确认，执行中记录模型、Token、估算与实际费用，不以金额上限拦截创作；广告投放、采购等非内容生成资金动作仍按各自上限与审批规则执行。
- 周运行状态与单项任务状态采用共享投影规则；移动接口未提供完整周运行时不得从跨运行任务反推周运行、进度或完成数量。详情刷新同步真实状态、原因和下一步，不能继续显示已消除的旧卡点。
- 素材来源/主题分类和拍摄工作流复用平台无关源。原生拍摄详情展示与网页一致的声音要求和绑定说明；上传任务关联与草稿回填明确区分，缺少当前草稿时不推断可自动回填。
- 运营拍摄小程序的主工作域收敛为“素材上传与整理”和“待拍任务拍摄”两项；两项使用同一底部导航和企业素材库事实源，不在移动端复制网页的复杂配置。素材页允许上传图片或视频，并按类型、产品和 AI 标签查询整理；自动分析未完成时必须显示真实状态。
- 待拍任务列表的卡片可直接播放其已绑定参考片段的前三秒，播放到 3 秒后自动暂停并回到片段起点；预览只帮助理解构图和动作，不能代替任务详情中的完整拍摄要求。没有可核验参考视频时显示普通分镜占位，不拼造预览。
- 共享源继续进入统一生成、一致性和测试门禁；小程序生成物保持包内依赖闭包，网页组件和微信相机、相册、上传交互由各端适配。
- 自动周包缺少发布选品时，在原任务卡显示用户待干预并定位同一任务上下文的结构化选品。明确区分“单一商品用于全部发布任务”和“按母版组逐组选择”：前者展示实际发布任务与母版组数量，后者每次覆盖所选母版组全部发布任务；已签发回执不得被批量覆盖。选择列表只显示企业当前结构化产品记录，SKU 缺失应显示“SKU 未登记”，不得从产品名称或采集关键词推断。提交须基于当前周包/事实版本并在成功后重新读取；读取故障是技术恢复，不提示用户重复签发。选品只解除产品身份缺口，不代表免费样品政策、成片验收或发布授权。
- 免费样品政策 PDF 只在同周任务卡的独立证据区提交，必须先明确选择一个已认证选品的发布任务，并展示其商品、母版组、冻结 CTA 与文件适用范围；不循环替用户提交全周任务。运费、关税、数量、市场、客户类型和有效期采用结构化必填项，样品本体费用固定为 0 元。上传与候选留档仅显示“待独立核验”，不得用成功色或状态暗示政策通过、整周覆盖或放行成片；提交后重新读取当前任务候选，失败或未知回执提示先核验原记录，避免重复上传。

### 12.7 Agent 生产甘特图与社媒文案同源规则（2026-10-20）

- Agent 工作排期以“每条内容一行”为主体；左侧只保留序号与可识别的内容名，右侧按时间从前到后展示经营定题、编导成稿、素材就绪、成片生产、质检验收、发布承接与数据复盘。禁止在甘特图中另建“本周任务”摘要卡或重复的内容列表。
- 日期默认为单周七天；每条内容默认 1 行，同日节点密集时最多 2 行。节点顺序、责任 Agent、真实状态和计划日期必须可读；详细输入输出进入抽屉，不在甘特图主体堆文字。
- 发布链路以一份已确认的“统一发布文案 + 统一 Tag 集”为权威源；各平台仅处理媒体尺寸、封面、账号与技术发布参数，不得再让模型改写文案或增删 Tag。
- 跨企业迁移时只允许替换已结构化绑定的商品名、品牌名与企业名；不可替换或伪造认证、价格、交期、功效与交付能力。采集到的第三方原文只有在自有、已授权或用户明确确认可复用时才能进入统一发布文案。

## 13. 验收标准

逐页评审必须满足：

- 5 秒内能说出当前对象、状态和唯一下一步。
- 页面不出现 Ant 默认蓝色、默认圆角或未映射的默认状态色。
- 一个操作区只有一个 Primary Button；禁用操作说明原因。
- Card 嵌套不超过一层；普通信息分组使用标题、留白和 Divider。
- 日历均来自统一事件模型，支持月/周/列表视图，时区明确。
- 所有日历事件在所属日期/时间列内形成不重叠、顺序稳定的级联卡片流；不引入 Masonry/CSS 多列布局，媒体加载前后不得换列或跳位。
- 弹层类型选择正确，焦点进入/归还、Esc、关闭按钮和移动端退化可用。
- 图表标题、单位、范围、图例、数据表和空错态完整；不使用假趋势填空。
- 长任务显示当前节点、责任 Agent、预计时间和真实进度。
- 产品事实、产品素材、云素材、参考视频和生成内容来源明确。
- 键盘、读屏、触屏与减少动态效果模式可完成核心流程。
- 不出现大面积蓝紫霓虹、玻璃模糊、持续发光描边、大量胶囊、装饰性英文眉题和无意义 AI 图标；受控渐变与邀请符合 10.1、10.2、10.11。
- 页面注册表中的所有一级页面必须通过统一应用壳、Token、反馈与焦点验收；不能只验收客服或智能经营单页。
- 1440px 和 390px 两种基准视口均不得出现页面级横向滚动、文字越界、边框重叠、相邻列表项相交或固定层挡住主操作。
- 窄列中的文字换行必须保持至少 18px 行高；任何文字的实际高度不得超出父容器可用高度，截断时必须有 title、Tooltip 或详情入口。
- 会话页三栏、进度、加载、头像组、渐进媒体、Masonry、紧凑字段、Steps 与数据看板均有真实业务页面承载，不建立只供截图的静态组件展厅。
- 动效、排版按 3.3 与 3.6–3.8 验收：共享 Token、无装饰性无限循环；除 10.13 对话新气泡的一次性短时顺序进入外，无列表 stagger、无假进度；系统偏好动态切换后动画与显式滚动都能立即降级。

### 16.2 页面结构

| 层级 | 自由创作 | 数字员工 | 共用规则 |
| --- | --- | --- | --- |
| 模式 | 顶部选择“自由创作” | 顶部选择“数字员工” | 模式是同一租户工作区中的视图/任务上下文，不是两套独立账号、数据或执行 API；切换保留草稿，不隐式发起付费/对外动作 |
| 一级导航 | 经营总览 → 灵感爆款 → 内容创作 → 平台投流 → 客户会话 | 经营总览 → 灵感爆款 → 内容创作 → 平台投流 → 客户会话 | 顺序固定；有页面权限时持续保留“灵感爆款”Tab，不因爆款复刻、制作步骤、模式切换或刷新隐藏；点击进入完整灵感爆款页，不只滚动首页素材区域。隐藏不等于删除数据、深链或授权；无权入口仍受角色权限控制 |
| 内容创作 | 中央单一灵小枢对话框，下方仅展示现有爆款视频的第一行 | 同一对话能力按数字员工上下文启动/续接周任务；生产执行仍进入现有任务工作台 | 对话线程、待办卡、版本校验、附件和错误回执复用现有契约；首页不再叠加一个独立的全局助手浮窗 |
| 经营总览 | 读取同一经营事实的概览 | 保留原智能经营工作台的真实指标与内容工程 | 下设“发布日历、投流速览、询盘诊断”三个页内 Tab；详细任务仍可进入原对象详情 |
| 投流、客服 | 复用权限允许的原模块 | 复用权限允许的原模块 | 投流当前有产品展示开关，恢复前需核对真实账号、额度与数据口径；智能客服继续用现有会话/客户工作台 |

版式按截图的**信息层级**重排：中性左侧栏；内容创作首页主区右上放置“自由创作 / 数字员工”双态切换，移除该处积分与账户按钮；居中问候下不再重复切换器，输入框、建议和素材墙随文档流上移。积分与账户保留已有侧栏入口，通知入口仅在有真实通知数据源时出现；自由创作模式先是单一大输入框、再是爆款首行；数字员工模式先是“新建周任务/继续真实运行”等有数据的任务入口卡、再是同源输入框，不补造即梦式画布或空模板；下方仍可呈现与当前模式相关的真实内容。沿用本规范的纯白页面、黑灰文字、蓝紫主操作。页面标题与导航不重复，原经营状态和风险不能为了视觉简化而消失。

### 16.3 首页到爆款库与视频详情
