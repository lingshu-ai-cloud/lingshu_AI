# 灵枢 AI 全系统 UI 设计规范 v2.1

> 状态：实施基线
> 更新日期：2026-10-09
> 适用范围：灵枢 AI 桌面端、平板端与移动端的用户工作台、管理后台及创作工作台
> 目标读者：产品、设计、前端、测试与交付团队
> 组件基线：Ant Design 6.x；日历基线：FullCalendar；图表基线：Chart.js
> 取代范围：`灵枢AI前端设计规范-v1.md`、`design-system/lingshu-visual-system.md`、`design-system/visual-language-v1.md` 中与本规范冲突的视觉与组件规则

## 1. 本版结论

灵枢 AI 的视觉方向定义为 **经营编辑台**：像一套由经营者、编导、内容制作人员共同使用的专业运营系统，而不是通用 AI 生成器。产品识别度来自真实业务对象、排期、证据、成本和结果回执。渐变、边框动画与插画仅作为被严格限制的品牌强调和邀请，不得替代业务信息。

本版确定四项基础技术与设计决策：

1. **Ant Design 是基础组件层，不是默认皮肤。** 统一按钮、表单、表格、反馈和无障碍行为，再通过灵枢主题 Token、页面模板与业务复合组件建立产品风格。
2. **所有日历统一使用 FullCalendar 的事件模型和交互。** 月视图、周视图、日视图和列表视图不得继续分别手写。
3. **所有经营数据图表统一使用 Chart.js 的视觉配置和数据口径。** 现有 Recharts 只在迁移期共存，不得新增第三套图表方案。
4. **弹层采用 Ant Modal、Drawer、Popover 和 Popconfirm 的实现能力，外观与信息克制参考 GitHub Docs / Primer。** GitHub Docs 是完整页面参考，不是弹窗组件；复杂流程不得塞入大弹窗。

## 2. 产品视觉身份

### 2.1 视觉关键词

- 可信：数据、来源、状态和时间可追溯。
- 克制：用版式、分隔线和留白建立层级，不依赖阴影与装饰。
- 高效：高频动作靠近业务对象，异常早于日志，详情按需展开。
- 有温度：暖白画布、森林绿品牌色和少量杏珊瑚提示，不使用冷硬科技蓝紫作为主视觉。
- 可执行：每个页面先回答“现在怎样、下一步做什么、谁负责、何时完成”。

### 2.2 灵枢特有的可见语言

以下元素比“AI”标签更能建立灵枢的产品识别度：

1. **经营刻度**：目标、成本、发布时间、完成数量使用统一数据带和刻度，不拆成悬浮卡片墙。
2. **内容证据**：产品事实、产品素材、云素材、爆款参考、生成结果必须有固定来源标识。
3. **工作轨道**：经营 Agent、编导 Agent、内容 Agent、质检与发布按真实工作顺序展示责任、预计时长和结果。
4. **账号与平台**：平台用官方 Logo，账号用真实名称；平台色不承担任务状态。
5. **真实媒体**：视频首帧、产品图、素材结构与成片预览是页面主视觉，不用通用 AI 插画代替。

### 2.3 禁止的“AI 模板风”

核心工作界面禁止：

- 大面积蓝紫霓虹渐变、玻璃模糊、持续发光边框和无意义光点；受控的品牌渐变与边框邀请遵循 4.4 与 10.1。
- 每个区块都使用 20px 以上圆角、重阴影和悬浮上移。
- 大量英文大写眉题，如 `SMART OPERATIONS`、`WEEKLY COMMAND CENTER`；中文业务标题应成为第一信息。
- 魔法棒、四角星、机器人头像被重复用作所有功能图标。
- `font-black` 被用于正文、说明和所有数字；字重必须服务信息层级。
- 一个页面堆叠多块渐变 KPI 卡、胶囊标签和装饰性假图表。
- 用“处理中”“AI 正在思考”等拟人化文案代替真实节点、责任 Agent、已完成数量和预计时间。

### 2.4 五张参考图的强制映射

参考图只定义对应场景，不允许把某一种视觉机械套到全站：

| 参考图 | 全应用使用范围 | 强制实现 | 禁止事项 |
| --- | --- | --- | --- |
| 图 1：Masonry 媒体墙 | 所有视频库、图片库、素材库；日历中的内容/发布事件 | 媒体优先、稳定比例、统一间距；媒体库使用 `LsMasonryGallery`，日历事件使用同语法的 `LsCalendarEventCard` | 任务、账号、审批列表不得使用瀑布流；日历不得嵌入 Masonry 布局引擎 |
| 图 2：图片/视频状态 | 所有图片、视频、首帧、生成结果和预览 | 使用 `LsMediaStateFrame + LsProgressiveMedia` 表达加载、生成进度、成功和失败；占位尺寸与完成态一致 | 黑框、空白、仅写“处理中”、加载后布局跳动 |
| 图 3：渐变进度 | 所有加载进度、Agent 工作进度、视频生成、素材处理、资料完整度和配额 | 已知总量使用 `LsGradientProgress`；未知总量使用 Spin + 当前节点；完成/失败切换语义状态 | 页面内手写单色进度条、虚构百分比、用进度条冒充趋势图 |
| 图 4：Steps 流程弹窗 | 用户首次进入的新手引导，以及 2–4 步的短流程 | 首次引导使用 `LsFlowDialog`，在顶部显示 Steps，正文只解释当前一步，底部只有跳过/返回与唯一主操作 | 把完整工作台塞进弹窗、每次进入都重复打扰、关闭后丢失进度 |
| 图 5：数据分析页 | 智能经营、运营复盘、账号与内容表现、管理统计 | 使用统一筛选区、连续指标带、主趋势、分布/排行和可执行建议；图表由 `LsDataChart` 渲染 | 渐变 KPI 卡墙、假趋势、无单位/口径/时间范围的数据装饰 |

上述映射同时适用于桌面、平板与移动端；响应式只能改变列数、信息密度和弹层形态，不能改变业务语义或状态来源。

## 3. 基础设计 Token

### 3.1 色彩

| 角色 | Token | 色值 | 用途 |
| --- | --- | --- | --- |
| 品牌主色 | `colorPrimary` | `#117F51` | 主操作、当前导航、关键可执行状态 |
| 品牌深色 | `colorText` | `#173D31` | 标题、正文、深色品牌区域 |
| 页面画布 | `colorBgLayout` | `#F6F8F5` | 全局工作区 |
| 内容表面 | `colorBgContainer` | `#FFFFFF` | 面板、表格、弹层 |
| 次级表面 | `colorFillSecondary` | `#F1F6F2` | 选中、表头、次级分区 |
| 主边框 | `colorBorder` | `#C8D9CE` | 输入、控件、强调分隔 |
| 次边框 | `colorBorderSecondary` | `#DFE8E1` | 表格行、区域分隔 |
| 次级文字 | `colorTextSecondary` | `#53695F` | 说明、元数据 |
| 三级文字 | `colorTextTertiary` | `#617169` | 时间、单位、弱提示 |
| 信息 | `colorInfo` | `#356CAE` | 进行中、系统信息 |
| 成功 | `colorSuccess` | `#147A51` | 完成、通过、已连接 |
| 等待 | `colorWarning` | `#A45A3B` | 待确认、缺资料、临近截止 |
| 异常 | `colorError` | `#B74D43` | 失败、阻断、风险 |
| 人工介入 | `supportApricot` | `#E98268` | 洞察或人工介入，不等于错误 |

规则：

- 状态必须同时显示文字或图标，不能只靠颜色。
- 平台 Logo 保留官方颜色，但平台颜色不得染整张任务卡。
- 正文与背景对比度不低于 4.5:1；图标与图形标记不低于 3:1。
- 深紫色只允许作为多序列图表中的第五辅助色，不作为“AI 能力色”。
- 品牌渐变固定为 `#117F51 → #2F9DA5 → #86C968`；只允许用于唯一主操作、真实进度与短时邀请，不能成为页面背景、正文底色或状态色。
- 渐变不可改变语义：成功、等待、失败仍分别使用固定语义色，并必须带文字或图标。

### 3.2 图表色板

图表序列固定按以下顺序分配，并同时用线型、点型或图案区分：

| 顺序 | 色值 | 用途建议 |
| --- | --- | --- |
| 1 | `#117F51` | 主要业务结果 |
| 2 | `#356CAE` | 对比项或进行中 |
| 3 | `#C1842D` | 成本、等待或次要对比 |
| 4 | `#D66555` | 异常、下滑或警示 |
| 5 | `#7567A8` | 第五序列，仅在必要时使用 |
| 中性 | `#91A29A` | 基准、未分类、历史参考 |

禁止渐变面积填充、3D 图表、彩虹色和随机颜色。

### 3.3 字体与数字

```css
--font-sans: "SF Pro Text", "PingFang SC", "Noto Sans SC", ui-sans-serif, system-ui, sans-serif;
--font-mono: "SFMono-Regular", ui-monospace, monospace;
```

| 层级 | 桌面字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| H1 | 28 / 36 | 650–700 | 页面唯一主标题 |
| H2 | 20 / 28 | 650 | 一级区块 |
| H3 | 16 / 24 | 600 | 卡片、弹层、小节 |
| 正文 | 14 / 22 | 400–500 | 默认信息 |
| 辅助 | 12 / 18 | 400–500 | 元数据、单位、时间 |
| 数据 | 24 / 32 | 600–700 | KPI；使用等宽数字 |

- 英文只用于平台名、专业缩写或用户真实内容，不用英文装饰眉题。
- 数字使用 `font-variant-numeric: tabular-nums`；金额、百分比、时间单位必须全系统统一。
- 产品工作区只使用上述系统无衬线字体；装饰字体只允许出现在品牌插画或营销素材中，不能进入导航、表格、卡片和表单。
- 同一层级只能有一套字号、字重和行高；`font-black`不得出现在产品正文，最高可视字重收敛为 700。
- 中文标题按语义换行，不使用字符级强制断行；正文与列表信息使用 `overflow-wrap: break-word`，URL、ID 和不可分隔的长串才使用 `overflow-wrap: anywhere`。
- 单行截断只用于有详情入口的次要元数据；客户名、任务标题和最后一条消息默认允许两行，不能因为窄列而丢失关键语义。

### 3.4 间距、圆角、阴影与密度

- 基准间距：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。
- 控件高度：紧凑 32px、默认 36px、主要操作 40px。
- 控件圆角：6px；默认容器 8px；弹层 10px；媒体卡 8px。
- 只有状态 Tag 可以使用胶囊圆角；大容器禁止胶囊化。
- 普通卡片无阴影，以边框和留白分层；阴影仅用于 Modal、Drawer、Dropdown、Popover。
- 参考 Messenger 的框架密度：用浅灰页面底、白色大面和 1px 栏分隔线建立层级；列表项默认无框，选中时使用浅色面，不为每个子项反复加框。颜色仍使用灵枢 Token，不复制 Messenger 的蓝紫色。
- Hover 只改变背景、边框或文字，不整体上浮、缩放或发光。
- 高密度表格允许局部紧凑模式；全站不得启用全局紧凑模式。
- 连续列表项之间至少保留 6px 间距，或者共用单一 Divider；禁止两个带独立边框的列表项零间距相贴，造成双线、重叠或视觉粘连。
- 所有 Flex/Grid 子项默认 `min-width: 0`；媒体、图表、表格和弹层不得超出所在容器，需滚动时由明确的内部滚动容器承担。

### 3.5 图标与媒体

- 现阶段继续使用 Lucide 作为产品图标，避免迁移期同时出现两套图标语言；Ant 内部图标由共享适配层处理。
- 不在同一功能上混用 Lucide 与 Ant 图标。
- YouTube、TikTok、Instagram、Facebook、Messenger 等使用官方 Logo。
- 视频卡必须保留封面、时长、平台、来源与可用状态；图片和视频加载失败提供占位与重试。
- 水纹品牌图仅用于登录、品牌介绍和少量空状态，不进入高密度工作区。

## 4. Ant Design 主题与实现边界

### 4.1 主题入口

全应用必须由一个 `ConfigProvider` 与一个 `App` 根节点提供中文 locale、Token 和反馈 API。禁止业务页面直接覆盖 `.ant-*` 内部类名，禁止继续新增页面级硬编码色值。

主题至少统一以下 Token：

```ts
const lingshuTheme = {
  cssVar: true,
  token: {
    colorPrimary: '#117F51',
    colorLink: '#117F51',
    colorInfo: '#356CAE',
    colorSuccess: '#147A51',
    colorWarning: '#A45A3B',
    colorError: '#B74D43',
    colorText: '#173D31',
    colorTextSecondary: '#53695F',
    colorTextTertiary: '#617169',
    colorBgLayout: '#F6F8F5',
    colorBgContainer: '#FFFFFF',
    colorBorder: '#C8D9CE',
    colorBorderSecondary: '#DFE8E1',
    borderRadius: 8,
    controlHeight: 36,
    fontSize: 14,
    fontWeightStrong: 600,
    boxShadow: '0 16px 48px rgba(23,61,49,.14)',
    boxShadowSecondary: '0 10px 30px rgba(23,61,49,.10)',
  },
};
```

Button、Menu、Table、Tabs、Input、Select、Card、Modal、Drawer、Tag 和 Tooltip 必须再设置组件级 Token。主按钮无默认阴影；Menu 选中态使用浅绿底；Table 表头使用次级表面；输入聚焦环使用半透明品牌绿。

静态 `message.xxx`、`notification.xxx`、`Modal.xxx` 不得直接出现在业务代码中；统一使用 `App.useApp()` 或共享 hooks，确保主题和上下文一致。

### 4.2 组件白名单 P0

| 类别 | Ant 组件 | 灵枢主要场景 |
| --- | --- | --- |
| 应用基础 | `ConfigProvider`、`App`、`Typography` | 全局主题、中文 locale、排版、反馈上下文 |
| 布局 | `Layout`、`Grid`、`Flex`、`Space`、`Divider` | 应用壳、页面结构、响应式布局；不得用 Card 代替所有分区 |
| 导航 | `Menu`、`Breadcrumb`、`Tabs`、`Dropdown`、`Pagination`、`Steps` | 主导航、层级、同级视图、命令菜单、流程与分页 |
| 操作 | `Button`、`Segmented` | 唯一主操作、少量同级视图切换 |
| 表单 | `Form`、`Input`、`Input.TextArea`、`InputNumber`、`Select`、`AutoComplete`、`Radio`、`Checkbox`、`Switch` | 企业资料、产品、脚本、账号、预算与权限 |
| 时间与上传 | `DatePicker`、`RangePicker`、`TimePicker`、`Upload`、`Dragger` | 发布排期、统计周期、图片视频与文档上传 |
| 数据 | `Table`、`Descriptions`、`Statistic`、`Card`、`Image`、`Avatar` | 任务、订单、账号、KPI、视频与人物 |
| 状态 | `Tag`、`Badge`、`Progress`、`Timeline`、`Collapse`、`Empty` | 生命周期、待办数量、生产进度、历史、诊断和空状态 |
| 浮层 | `Modal`、`Drawer`、`Popover`、`Tooltip`、`Popconfirm` | 确认、详情、快速操作、短解释与轻量危险确认 |
| 反馈 | `Alert`、`Message`、`Notification`、`Result`、`Skeleton`、`Spin` | 页内异常、短反馈、复杂通知、终态、首次加载与局部等待 |

说明：Ant v6 已将旧 `List` 标记为废弃，新代码不使用；普通列表使用语义化布局、Table 或经评审后的 `Listy`。

### 4.3 组件白名单 P1

| 组件 | 使用场景 | 启用条件 |
| --- | --- | --- |
| `Tree`、`TreeSelect`、`Cascader` | 知识库、组织、分类、权限范围 | 数据存在真实层级 |
| `Transfer` | 批量分配账号、成员、角色、事实授权 | 左右集合对照显著提高效率 |
| `Splitter` | 脚本与预览、素材与属性并列 | 窄屏可降级为 Tabs 或 Drawer |
| `Anchor` | 企业知识、长说明、复杂详情页 | 页面章节稳定且需要深链 |
| `Mentions` | 评论、协作审核、会话提及 | 有对象权限过滤 |
| `Tour` | 首次连接账号、首次内容生产 | 只出现一次，不替代清晰界面 |
| `Watermark` | 客户敏感预览、未发布成片 | 确有防误用需求 |
| `Carousel` | 少量连续首帧或创意预览 | 不隐藏关键状态，不自动播放 |
| `QRCode` | 账号扫码连接、移动端预览 | 存在真实扫码路径 |
| `Affix` | 长页面唯一关键动作 | 不与其他固定区域冲突 |
| `Slider`、`Rate` | 近似强度、人工主观评分 | 不用于精确预算、模型置信度或经营 KPI |

### 4.4 禁用与慎用

- Ant `Calendar`：禁用；产品日历统一使用 FullCalendar。
- Ant Charts：禁用；业务图表统一使用 Chart.js。
- `BorderBeam`：默认禁用；仅允许在首次邀请、AI 建议候选或新能力发现中短时出现，不能表达状态、选中、焦点、校验或进度；`prefers-reduced-motion` 下完全关闭。
- `Masonry`：仅可用于灵感素材墙，任务与状态列表禁用。
- `Carousel`：不得承载告警、审批和唯一操作。
- `FloatButton`：只允许全局帮助、反馈或返回顶部，不能作为核心新建入口。
- `Switch`：仅表示点击后立即生效的二元状态；随表单提交的选择使用 Checkbox 或 Radio。
- `Tooltip`：只用于无文字图标的短说明，不能承载关键内容、长文本或操作。
- `Card`：只承载独立对象；卡片嵌套不超过一层。
- Ant Design Pro：不得直接成为整站皮肤；先完成基础组件与灵枢 Token，再单独评估 ProTable / ProForm。

## 5. 页面骨架与业务模板

### 5.1 全局应用壳

- 桌面侧栏展开 208px，收起 64px；移动端收起仅保留 60px 图标轨道，展开导航使用 Drawer，不永久挤压主内容。
- 页头只保留 H1、一句状态、范围/更新时间和页面级操作。
- 面包屑仅在层级超过两级时出现。
- 页面最大内容宽度 1440px；全屏日历、创作工作台和会话页可突破该限制。
- 顶部与侧栏不使用渐变、毛玻璃或重阴影。

### 5.2 五类标准页面

| 页面类型 | 固定结构 | 适用模块 |
| --- | --- | --- |
| 数据总览 | 页面头 → 连续 KPI 数据带 → 1 个主图 → 1–2 个明细区 → 下一步 | 智能经营、内容监控、投放、订单 |
| 对象列表 | 页面头 → 搜索/筛选 → 结果数量 → Table 或规则卡片 → 分页 | 灵感、账号、客户、订单、素材 |

## 6. FullCalendar 统一规范

### 6.1 统一视图

| 业务需求 | FullCalendar 视图 | 默认场景 |
| --- | --- | --- |
| 月度发布总览 | `dayGridMonth` | 发布与渠道、经营月计划 |
| 精确到小时的周排期 | `timeGridWeek` | 内容制作、发布时间、待拍任务 |
| 单日执行 | `timeGridDay` | 当日 Agent To Do、拍摄日程 |
| 移动端与可访问降级 | `listWeek` / `listDay` | 窄屏、读屏、打印 |
| 跨月经营计划 | `multiMonth` | 季度节奏、长期复盘 |
| 账号/Agent 泳道甘特 | `resourceTimelineWeek` | 数字员工工作排期，需 Premium 商业许可 |

Ant `Calendar`、手写月历和手写周历停止新增功能。迁移前先建立统一 `LsCalendarEvent` 数据模型，至少包含：

```ts
type LsCalendarEvent = {
  id: string;
  title: string;
  start: string;
  end?: string;
  timeZone: string;
  status: 'planned' | 'queued' | 'working' | 'needs_action' | 'failed' | 'done';
  eventType: 'content' | 'agent_task' | 'publish' | 'shooting' | 'follow_up';
  platform?: string;
  accountId?: string;
  accountName?: string;
  thumbnailUrl?: string;
  ownerAgent?: string;
  sourceId?: string;
  costEstimate?: number;
};
```

### 6.2 日历外观

- 工具栏顺序固定：新增/主要动作、今天、前后切换、当前日期、视图切换、筛选。
- 星期与日期使用中文；周一作为工作周起点时必须与目标市场规则一致。
- 周末只用极浅背景区分；今天使用 1px 品牌绿边框或浅底，不使用大色块。
- 事件颜色表达生命周期状态，平台由官方 Logo 表达。
- 月视图事件显示“平台 Logo + 账号简称 + 标题”；周/日视图再显示时间和缩略图。
- 同日溢出使用 `+N` 入口；Popover 只做快速浏览，点击事件进入 Drawer。
- 日历内容区为平面网格，不在每个日期单元套 Card。

### 6.3 交互

- 事件 hover 可显示轻量摘要，但所有内容必须能通过键盘 focus 或点击获取，不能只依赖 hover。
- 点击事件打开右侧 Drawer；Drawer 显示缩略图、标题、平台账号、责任 Agent、制作时长、交付时间、成本和状态。
- 仅有排期编辑权限时允许拖拽与缩放；拖拽后必须二次确认跨账号、跨日或已进入制作的变更。
- 必须提供键盘可操作的“移动到日期/时间”替代入口。
- 所有时间显式标注时区，如“北京时间”或“目标市场当地时间”；后台保存 IANA 时区。
- 日历更新保留旧数据并局部显示同步状态，不整页清空或闪烁。

### 6.4 Premium 决策门

`timeline`、`resourceDayGrid`、`resourceTimeGrid` 和 `resourceTimeline` 均属于 FullCalendar Premium。真正的“账号或 Agent 为行、时间横向”的工作排期只有两种合规方案：

1. 采购商业许可，使用 `resourceTimelineWeek/Month`；大资源量启用虚拟化。
2. 暂不采购，使用 Standard 的 `timeGridWeek + listWeek`，事件标题带账号和平台；现有自研泳道只维护、不扩张。

不得把 Premium 试用、非商业许可或 AGPL 路径直接用于闭源商业生产。

## 7. 弹层与详情统一规范

### 7.1 GitHub 参考的正确用法

GitHub Docs 文章页适合作为“克制、可深链、层级清楚”的完整页面参考；弹层行为以 GitHub Primer 的 Dialog / Overlay 规范为参考。灵枢的实际实现仍统一使用 Ant 组件，避免引入第二套组件库。

### 7.2 浮层选择

| 需求 | 组件 | 示例 |
| --- | --- | --- |
| 1–2 句短说明 | Tooltip | 无文字图标含义、字段单位 |
| 轻量摘要或少量就地操作 | Popover / Dropdown | 日历事件快览、表格行操作、筛选 |
| 简单确认或单一短表单 | Modal | 发布确认、覆盖确认、取消任务 |
| 不中断主页面的详情或编辑 | Drawer | 视频详情、逐镜分析、客户详情、任务详情 |
| 局部危险操作 | Popconfirm | 删除单条草稿、移除一个标签 |
| 多步骤、侧导航、可分享或可深链 | 完整页面 | 周计划确认、内容制作工作台、Agent 设置、复杂产品编辑 |

### 7.3 尺寸与结构

| 类型 | 桌面宽度 | 适用内容 |
| --- | --- | --- |
| 小 Modal | 400–480px | 确认、单字段输入 |
| 标准 Modal | 560–640px | 短表单、选择器 |
| 大 Modal | 720–840px | 批量复核、媒体选择；不得发展为完整页面 |
| 标准 Drawer | 480–560px | 对象详情、轻编辑 |
| 媒体 Drawer | 720–880px | 视频、逐镜、素材结构 |

统一结构：标题与说明、可见关闭按钮、可滚动正文、固定页脚。标题必填；页脚右侧最多一个主按钮，危险操作与普通主按钮不并列强调。

### 7.4 行为与无障碍

- 打开后焦点进入弹层，Tab 不离开 Modal / Drawer；关闭后焦点返回触发器。
- 支持 Esc 和可见关闭按钮；未保存表单不可点击遮罩直接关闭。
- 使用 `role="dialog"` 或 `alertdialog`、明确的 name / description 和 `aria-modal`。
- 背景不可交互；正文滚动时头部与页脚固定。
- 窄屏 Modal 转底部面板或全屏，Drawer 转全屏。
- 原则上禁止嵌套弹层；必须嵌套时最多两层，并仅关闭最上层。
- Tooltip 与 hover 摘要不得承载卡点、成本、状态或唯一操作。

### 7.5 产品内建议改造点

- 爆款视频与对标账号：卡片点击进入媒体 Drawer；完整逐镜分析使用可深链详情页。
- 周计划确认：改为完整日历页面，不再使用超宽、超高 Modal。
- 素材选择和批量复核：使用大 Modal，固定操作区。
- 发布确认和危险重试：使用小 Modal / Popconfirm。
- 客户、订单、内容任务、账号：列表内快速查看统一右侧 Drawer。
- Agent 设置、渠道接入、复杂企业资料：使用完整页面或流程工作台。

## 8. Chart.js 数据可视化规范

### 8.1 图表选择

| 要回答的问题 | 图表 | 灵枢示例 |
| --- | --- | --- |
| 随时间如何变化 | Line / Area | 内容产量、播放量、询盘、成本、制作时长 |
| 多账号或平台谁高谁低 | 横向 Bar | 账号周更、渠道效果、Top 内容 |
| 每周状态如何构成 | 100% Stacked Bar | 排队、制作、验收、发布、失败 |
| 计划与实际如何对比 | Mixed Bar + Line | 计划产量与完成率、花费与转化 |
| 两指标是否相关 | Scatter / Bubble | 匹配分与表现、成本与播放、发布时间与询盘 |
| 少量类别占比 | Doughnut | 最多 5 类的内容来源；非首选 |
| 单目标完成情况 | Progress / Statistic | 不使用 Gauge 或环图 |

Radar、Pie、Polar Area 不用于关键经营判断；漏斗优先使用横向分段 Bar 和明确数字，不为形状牺牲可读性。

### 8.2 智能经营四页数据映射

| 页面 | 必须展示的图表 | 明细载体 |
| --- | --- | --- |
| 经营总览 | 本周计划/完成 Line 或 Mixed；生产状态 Stacked Bar；平台产量 Bar | KPI 数据带、异常列表 |
| 账号矩阵 | 各账号周更与稳定度横向 Bar；账号表现趋势 Line | 账号 Table / Drawer |
| 内容队列 | 各阶段任务量 Stacked Bar；平均工期与失败原因 Bar | 内容 Table、单条进度 |
| 数据复盘 | 播放/互动/询盘趋势 Line；Top 内容 Bar；成本与结果 Scatter | 可排序数据表、下一轮建议 |

### 8.3 图表视觉限制

- 每张图必须有中文标题和一句说明；没有轴标题时，副标题必须说明单位与时间范围。
- 超过 1 个数据集必须有图例；图例名称与表格列名一致。
- Line 最多 5 条；堆叠 Area 最好不超过 3 条、硬上限 5 条。
- 普通 Bar 最多 10 条；Grouped Bar 每组最多 4 类且最多 6 组。
- Stacked Bar 每条最多 5 段且最多 10 条；Pie / Doughnut 最多 5 片。
- 线宽 2px；多序列同时使用实线/虚线、点型或图案，不能只靠颜色。
- Tooltip 只补充精确值，不承载结论或唯一信息。
- 简单图提供“查看数据表”；需运营导出的图提供 CSV 下载。

### 8.4 空、错与演示数据

- 没有真实数据时不画零趋势、不造波动线；显示 Empty、缺少的数据源和恢复动作。
- Mock 或演示数据必须在图题、图例和数据表中持续标记“演示数据”，不得与真实值同视觉层级。
- 数据同步失败保留最后一次确认的数据，显示更新时间和错误，不清空为 0。
- 指标口径、统计范围和时区必须能从图旁查看。

### 8.5 无障碍与性能

- Chart.js Canvas 必须提供 `role="img"` 和准确 `aria-label`，并在旁边提供文字结论与可展开数据表。
- 大数据预整形后使用 `parsing: false`、`normalized: true`；折线图使用降采样。
- 高负载图关闭动画、固定合理轴范围并限制 tick 数量。
- 每个响应式 Canvas 使用独立、相对定位的父容器。
- 图表按需注册并 tree-shake；不得把完整 Chart.js 全量打入每个页面。

## 9. 状态、反馈与长任务

### 9.1 状态字典

| 状态 | 色彩 | 必须显示 |
| --- | --- | --- |
| 未开始 | 灰 | 等待条件或计划时间 |
| 排队中 | 中性蓝 | 队列位置或预计开始时间 |
| 执行中 | 信息蓝 / 品牌绿 | 当前节点、责任 Agent、已完成数量、预计剩余时间 |
| 等待用户 | 琥珀 | 缺少什么、影响什么、唯一下一步 |
| 失败 | 红 | 失败节点、已保留结果、重试或人工处理 |
| 完成 | 绿 | 结果数量、完成时间、查看结果入口 |
| 暂停 | 灰棕 | 谁暂停、如何恢复 |

平台色、Agent 身份色、状态色三者不得混用。

### 9.2 反馈层级

| 反馈 | 组件 | 存续时间 |
| --- | --- | --- |
| 保存、复制等轻量成功 | Message | 2–4 秒 |
| 后台完成、需要后续动作 | Notification | 可关闭，带结果入口 |
| 页面持续风险或阻断 | Alert | 直到条件恢复 |
| 重要流程终态 | Result | 用户确认离开前保留 |
| 首次加载 | Skeleton | 与最终结构一致 |
| 局部短等待 | Spin | 不覆盖全页 |
| 可计算长任务 | Progress | 显示真实阶段与数量 |

所有改变数据或启动任务的动作必须具备：即时 loading、成功结果、失败原因、可执行下一步。不得只显示一个旋转图标或“处理中”。

### 10.1 品牌渐变按钮

- 渐变按钮只用于页面或流程的唯一主操作，例如“开始本周任务”“生成成片”“发送消息”；普通保存、筛选、返回和删除使用标准 Button。
- 同一区域最多一个渐变按钮，不与另一枚 Primary Button 并列争抢。
- 默认、hover、active、disabled、loading、focus-visible 必须完整；禁用态移除渐变，loading 不改变按钮宽度。
- 不允许用渐变装饰普通 Card、Tag、输入框或导航。

### 10.2 渐变进度

- 本规则是全站唯一进度样式：视频生成、素材处理、Agent 工作节点、资料完整度和配额使用均必须使用 `LsGradientProgress`，不得在业务页重新拼装单色 `div` 进度条。
- `line` 表示长任务、资料完整度与生产进度；`circle` 表示单一目标；`dashboard` 表示容量或接近上限的指标。
- 百分比必须来自真实数据。未知进度用 Spin + 当前节点，不能显示虚构百分比。
- 渐变仅编码“从开始到完成”的连续变化；失败、超限和阻断切换到语义色。
- 中心可显示百分比、完成图标或数值，不同时堆叠三者；进度文字可被读屏获取。

### 10.3 足不出户与流程弹层

- 用户首次进入的新手引导使用 `LsFlowDialog`：顶部 Steps、中部当前步骤说明、底部“跳过”与唯一主操作。关闭弹窗后可继续在页内高亮目标，完成当前操作后再打开下一步。
- 2–4 步、可在 10 分钟内完成且不要求深链的流程可使用 `Modal + Steps + Form`。
- 复杂周计划、内容制作、产品导入和账号设置必须使用完整页面；弹窗不能套侧栏模拟一个新应用。
- 当前步骤、已完成步骤、阻断原因和退出后的保存策略必须明确；关闭后焦点回到触发点。

### 10.4 加载与即时反馈

- 首次页面或卡片加载使用 Skeleton；局部等待使用 Spin；已知总量使用 Progress；按钮提交使用 Button loading。
- 预计超过 2 秒必须显示当前节点或解释；可取消任务提供取消；后台长任务离页后继续并可恢复。
- 输入校验贴近字段且持续存在；短成功用 Message，跨页面或带操作的消息用 Notification，阻断用 Alert/Result。
- 自动刷新不得清空旧数据；新内容到达先提示“有更新”，由用户决定是否刷新高密度列表。

### 10.5 紧凑字段组合

- 电话区号 + 电话、筛选条件 + 搜索、金额 + 币种、时间范围等强关联字段使用 `Space.Compact`。
- 组合后的 Tab 顺序、错误归属和读屏名称仍需独立明确；不得为了视觉紧凑而把无关动作粘在一起。

### 10.6 头像组

- `Avatar.Group` 用于显示责任人、客户参与者、协作 Agent；超过可见数量用 `+N`，Popover 展示完整清单。
- 头像无图片时使用稳定的姓名首字或平台身份，不随机换色；状态点与未读点不能混用。

### 10.7 渐进媒体与瀑布流

- 所有图片和视频先展示比例稳定的占位，再显示加载、生成百分比、成图/成片或失败重试；加载过程不能引起布局跳动。媒体状态必须经由 `LsMediaStateFrame + LsProgressiveMedia`，不使用空白黑框或纯文字占位。
- 多图预览使用 Ant Image PreviewGroup；敏感或未发布内容可加 Watermark。
- 凡是“视频库/媒体库”的卡片集合，统一使用 Masonry 媒体墙；卡片保持首帧、时长、平台、来源、产品关联、收藏与可用状态。任务队列、账号和审批禁用瀑布流。
- 日历不使用 Masonry 布局引擎，但内容/发布事件必须使用同一套“媒体优先”卡片语法：周/日/列表视图显示首帧、平台账号、标题、时间与状态；月视图空间不足时保留平台、标题和状态，详情 Drawer 展示完整首帧。

### 10.8 数据看板

- 全部数据页固定为：筛选范围 → 连续指标带 → 主趋势 → 分布/排行 → 可执行建议；使用 `LsDataChart` 和连续网格构成的多维分析页，禁止把每个数字都做成渐变卡片。
- 图表必须显示标题、单位、时间范围、口径、图例、真实数据/演示数据标记以及空错态。
- Progress 适合完成率，不代替趋势；Chart.js 适合趋势与比较，不用装饰图形填满空白。

### 10.9 Messenger 式客服工作台

会话页采用 Messenger 的高效三栏信息架构，但使用灵枢品牌 Token 与真实业务能力，不复制 Meta 商标与专有素材：

1. **左栏**：标题“聊天”、实时搜索、视图/筛选、按最近动态排序的会话；头像、来源、未读、最后一条消息和时间一眼可辨。
2. **中栏**：客户头像与名称、参与者 Avatar.Group、会话操作；消息气泡、附件/表情/GIF；底部固定输入与唯一发送主操作。
3. **右栏**：大头像、名称、来源与本地时间；分享、资料、通知、搜索；“影音内容、文件和链接”“客户与销售工作台”“隐私设置与支持”使用 Collapse 渐进展开。
4. 桌面三栏可同时显示；平板收窄左/右栏；移动端以列表 → 会话 → 资料的可返回层级呈现，不横向挤压。
5. AI 草稿、人工修改、知识引用、报价与客户意图继续保留真实来源标记，不伪装成客户消息。
6. 左栏桌面目标宽度为 232px，平板最小 196px；会话项使用独立 8px 圆角选中面，项与项之间 6px，默认无框，不使用连续的 Button 默认边框。
7. 会话名称使用 13/20、600；最后消息使用 12/18、最多两行；时间和来源使用 11/18。所有列表文字必须在边框内完成排版。

### 10.10 卡片、菜单、分页与步骤

- Card 只表示可独立操作或独立复用的对象；普通区块使用标题、Divider 与留白，卡片不嵌套超过一层。
- Menu 是应用导航的唯一结构源；收起态有 Tooltip，选中态同时使用背景、文字和侧边标记。
- 超过一屏且全量渲染昂贵的对象列表使用 Pagination；桌面显示总量、每页数和必要时快速跳转，移动端使用 simple。
- Steps 只用于有真实先后依赖的任务；显示当前、完成、等待、失败和预计时间，窄屏改为竖向或精简步骤。

### 10.11 图标、插画、邀请与边框动效

- 图标遵循“准确、简单、节奏、愉悦”：同一功能只保留一种图标语义，线宽、视觉尺寸和对齐一致。
- 插画只用于登录、空状态、完成页、引导与品牌说明；工作区优先真实产品、人物与媒体，插画不能冒充业务证据。
- 邀请分为静态、hover、推论和“更多内容”四类；所有邀请可关闭、可键盘触发，不反复打扰。
- BorderBeam 只能服务短时邀请，持续不超过 3 秒或一次 hover；减少动态效果模式下隐藏。

### 10.12 间距与亲密性

- 页面按 1440px 设计板、24 栅格、8px 基础网格实现；常用关系间距为 8 / 16 / 24px。
- 同一信息组内 8px，字段与同组说明 8–12px，平级对象 16px，章节 24–32px；必要时用 Divider 替代无限加大空白。
- 强相关对象靠近，弱相关对象分开；不得用随机 margin 修补布局。

## 11. 响应式与无障碍

| 断点 | 规则 |
| --- | --- |
| `>= 1280px` | 完整侧栏、12 列、并排主辅区、完整日历 |
| `768–1279px` | 可收起侧栏、8 列、辅助区下移、Drawer 不超过视口 60% |
| `< 768px` | 4 列、单列、全屏菜单、Modal/Drawer 全屏或底部面板、日历默认列表视图 |

- 触控目标不小于 44×44px。
- Tab 顺序与视觉顺序一致；所有图标按钮有可访问名称。
- `prefers-reduced-motion` 下关闭循环动画、平滑滚动和大位移。
- 表格在移动端优先变成分组列表或保留关键列，不能靠不可发现的横向滚动完成核心任务。
- 所有功能在没有 hover 的触屏设备上仍可完整使用。

## 12. 迁移方案

当前仓库已引入 Ant Design 6.x、FullCalendar 与 Chart.js，并保留 Tailwind、Lucide、motion、dnd-kit 和迁移期 Recharts。迁移通过全局主题、共享 `Ls*` 组件与逐页替换完成；不得仅在一张示例页实现，也不得一次无验证地全局替换造成主链路回归。

### 12.1 P0 基础层

1. 锁定 Ant Design 6.x 小版本，建立 `ConfigProvider + App` 和 Token。
2. 建立 Button、Form、Table、Modal、Drawer、Feedback、Status 的共享适配层。
3. 建立统一 `LsCalendarEvent` 和 FullCalendar 外壳；先迁移“发布与渠道”。
4. 建立 Chart.js `LsDataChart`，先迁移“智能经营数据复盘”。
5. 建立视觉回归和键盘/焦点测试；新页面不得继续手写基础控件。

### 12.2 P1 核心主链路

1. 智能经营四页：数据带、账号矩阵、内容队列、数据复盘。
2. 周计划与 Agent To Do 排期：根据许可证决定 `resourceTimeline` 或 Standard 方案。
3. 灵感中心：筛选、卡片、媒体 Drawer、逐镜详情。
4. 内容制作：流程、素材选择、分镜、批量复核和成片预览。
5. 会话、客户、订单与企业知识库。

### 12.3 P2 收口

1. 定时任务、集成、权限、管理后台。
2. 恢复平台投放时按本规范重建图表与表单。
3. 删除旧日历、旧弹层、旧 Recharts 包装和重复 CSS。
4. 清理无语义渐变、超大圆角、重阴影、英文装饰眉题和散落硬编码颜色；保留本规范定义的受控品牌渐变。

### 12.4 共存规则

- 新功能只能使用新组件层。
- 同一页面不得同时出现旧/新按钮、弹层或状态样式。
- Recharts 与 Chart.js 只允许跨页面临时共存，不允许同一页面混用。
- Lucide 保留为唯一产品图标集；平台官方 Logo 独立管理。
- FullCalendar Premium 在采购前不得进入商业生产构建。

## 13. 验收标准

逐页评审必须满足：

- 5 秒内能说出当前对象、状态和唯一下一步。
- 页面不出现 Ant 默认蓝色、默认圆角或未映射的默认状态色。
- 一个操作区只有一个 Primary Button；禁用操作说明原因。
- Card 嵌套不超过一层；普通信息分组使用标题、留白和 Divider。
- 日历均来自统一事件模型，支持月/周/列表视图，时区明确。
- 弹层类型选择正确，焦点进入/归还、Esc、关闭按钮和移动端退化可用。
- 图表标题、单位、范围、图例、数据表和空错态完整；不使用假趋势填空。
- 长任务显示当前节点、责任 Agent、预计时间和真实进度。
- 产品事实、产品素材、云素材、参考视频和生成内容来源明确。
- 键盘、读屏、触屏与减少动态效果模式可完成核心流程。
- 不出现大面积蓝紫霓虹、玻璃模糊、持续发光描边、大量胶囊、装饰性英文眉题和无意义 AI 图标；受控渐变与邀请符合 10.1、10.2、10.11。
- 页面注册表中的所有一级页面必须通过统一应用壳、Token、反馈与焦点验收；不能只验收客服或智能经营单页。
- 1440px 和 390px 两种基准视口均不得出现页面级横向滚动、文字越界、边框重叠、相邻列表项相交或固定层挡住主操作。
- 窄列中的文字换行必须保持至少 18px 行高；任何文字的实际高度不得超出父容器可用高度，截断时必须有 title、Tooltip 或详情入口。
- 会话页三栏、进度、加载、头像组、渐进媒体、Masonry、紧凑字段、Steps 与数据看板均有真实业务页面承载，不建立只供截图的静态组件展厅。

## 14. 待产品确认的四个决策

| 决策 | 建议 | 影响 |
| --- | --- | --- |
| Ant 主版本 | 锁定 6.x | 决定 Listy、Masonry 等 v6 组件是否可用 |
| FullCalendar Premium | 采购前先用 Standard；确认后启用资源泳道 | 决定数字员工账号/Agent 甘特是否直接使用 `resourceTimeline` |
| 图表迁移 | 新图用 Chart.js，旧 Recharts 按页面迁移 | 避免一次性回归，也避免长期双栈 |
| 图标体系 | 保留 Lucide，不新增 Ant 图标业务用法 | 降低迁移量并保持线性图标一致 |
