# 移动工作台上线审查（2026-10-10）

## 当前结论

目前可继续本地开发和测试，**尚不能认定为可以正式上线**。本次只进行了源码审查和本地 mock 验收；没有发布、生产请求、真实账号联调或生产迁移。

产品应提供统一工作台体验，账号登录后由后端确定租户、用户和能力，底栏、指标、队列和动作遵循同一份契约。现有后端数据结构差异属于适配问题，不应表现为用户套餐选择。

- `mobileWorkbenchQueue.ts` 在父路由安装认证后，队列只读取认证租户；稍后状态按租户和用户持久化。客户端不能指定租户。

- 支持人员只读会话不能修改稍后状态。此前队列测试已覆盖跨租户写入、跨用户读取、失败写入和撤销。

## 实际验收顺序

1. 修复全仓类型及迁移校验，记录可复现的全部通过结果。
2. 在测试环境安装对应迁移与后端版本，配置测试小程序合法域名、隐私和麦克风权限。
3. 两租户账号对照桌面工作台检查本周统计、当前队列、所有 Agent 和任务详情；重点准备跨周、多目标、多 run、超过分页上限样本。
4. 对真实测试任务执行稍后、撤销、批准、拒绝和重试；检查后端记录与桌面状态，不以页面动画作为成功证据。
5. 真机录音与网络恢复验收，完成微信审核前所需材料。
6. 经用户明确授权后，再按仓库 AGENTS.md 的既定发布流程部署；发布后核对版本、服务状态和 ready 结果。
