# Meta 投放目标：业务确认与自动处理

适用：本分支已接入的五个 Meta 目标。其他尚未接入的品牌认知、应用推广、销售目标不能因本设计视为可用；TikTok Spark、Google Demand Gen 属于独立适配，本轮不扩展其平台能力。

## 共同流程

1. 业务方案：用户确认目标、投放国家、市场语言、账户与预算币种、视频及文案、总预算和日预算、渠道及时间安排。名称可自动生成；文案与承诺须来自真实业务，不静默编造。国家不从自然语言猜测，不默认美国；日预算不默认 10。
2. 保存与复用：已选视频、国家、文案、推广页面和预算保存到原计划 configuration；执行页面带入已保存信息，可修改当前执行值。缺项允许存草稿，实际创建前须补齐。版本变更清空旧素材引用，回执或请求结果不确定禁止重建。
3. 技术准备：产品读取账户、币种、时区、可推广主页与用户授权的交集；唯一业务对象自动关联，多个对象按名称确认，不要求经营者查找编号。已确认的同账户、同素材版本 ready 视频和封面自动复用。首次新素材继续使用现有绑定、上传与核对流程，不能宣称已全自动准备。
4. 预检与创建：系统核对参数、版本、资产归属、发布状态和原回执。用户点击创建是对页面所示业务信息的一次确认，不增加重复确认框。创建保持暂停；启用、增加预算、扩大权限、签署条款分别按现有权限与授权执行。
5. 成效：真实创建须有四层资源回执及读回；客户行为须有对应事件或线索回执。离线夹具、浏览器冒烟和平台只读检查分别记录，不混称真实 E2E。

## 分目标流程

| 目标 | 用户必须参与的业务确认 | 系统直接处理 | 客户路径与验收 |
| --- | --- | --- | --- |
| 网站访问 | 推广页面、广告承诺与语言；共同预算/国家/素材确认 | 主页/视频/封面引用、链接点击优化、网站 CTA、HTTPS 格式与资源归属检查；不收 Pixel 或表单 | 广告→网站；统计链接点击，不当作询盘 |
| 视频观看 | 视频版本、字幕、广告文案与语言；共同确认 | 视频/封面引用、ON_VIDEO/ThruPlay；不询问网站、表单或数据源 | Meta 内观看；核对 ThruPlay，不当作站点访问 |
| 消息会话 | 接收消息的应用及可见商业身份；共同确认 | 读取主页关联号码/专业账户，写入账户引用和消息 CTA | 广告→所选应用→客户发起对话；会话与有效询盘分开 |
| 即时表单 | 获客承诺、语言、问题与联系字段、隐私说明、完成页；多个表单时确认业务版本 | 查询 ACTIVE 表单、关联编号、核对主页归属/条款；不让用户手填编号 | 广告→表单→填写→提交→完成页→lead 回收；每段须有证据 |
| 独立站询盘 | 询盘页面、承诺、语言；多个数据源时确认对应站点 | 读取账户 Pixel/数据源、关联引用、配置 Lead 优化；不把点击当转化 | 广告→站点询盘→成功提交→Lead 回传；关联成功不代表事件回传通过 |

## 不必让用户完成的流程

- 查表单 ID、主页 ID、Pixel ID、Instagram ID，复制平台视频 ID 或封面 URL。
- 对已保存业务信息再填写一遍；给自动生成的计划强制起名。
- 选择 Marketing API 枚举、优化事件、CTA 代码、计费枚举或手工拼请求。
- 为了创建计划填写跟进负责人、客资接收入口、回访渠道或测试联系确认。
- 把策略备注当成已经写入平台的精确受众/版位。本实现实际定向为确认的国家、18 岁以上及所选 Meta 平台自动版位；备注单独明确其非执行性质。

## 不能静默代确认的条件

- 不同网站、不同获客内容的多个表单/数据源不能仅按最新时间随意选一个。
- 企业隐私政策、广告产品承诺和合同条款不编造；不代签条款。
- 缺主页、有效表单、数据源、权限或支付条件时明确显示缺项，不以手填 ID、改目标、假成功或重试绕过。
- 未发布表单的自动创建、首次新视频全自动准备、网站真实 Lead 回传及客户表单提交仍需独立完成；本轮不把缺少这些证据写成全链路通过。
