# 灵小枢首页场景卡片与周内容任务 PRD

版本：v0.4 讨论稿\
日期：2026-10-25，Asia/Shanghai\
适用分支：`feature/assistant-home-dialogue-20261026`\
源码起点：`8c7cc7d304ffd268fcd5f20deeabf68fb5f8b10d`\
适用对象：产品、设计、前后端开发与测试。

首页通过四张场景卡片，让用户从表达需求开始，逐步确认产品、创作方向、周任务归属和发布安排，并在同一条内容任务上完成制作、审核、发布和复盘。首页对话、内容创作页、周任务包和发布日历共同呈现任务的真实状态，用户可以跨页面继续处理。

本稿定义待开发的业务和交互，不代表能力已经上线。视觉、组件、布局、动效与无障碍继续遵循《灵枢 AI 全系统 UI 设计规范 v2.5》。本稿不改变现有一级导航，不另建发布日历页面；与现行规范存在差异的事项须在实施前同步确认并更新规范。

## 一 目标与范围

### 目标

1. 用场景和业务目标帮助用户发起需求，减少重新填写企业资料与重复确认。
2. 将内容需求接入现有周任务、生产和发布流程，形成可恢复的业务记录。
3. 分开表达制作交付、成片验收、计划发布、实际发布，避免误报完成。
4. 从首页到工作台再返回时，保留对话、选择、任务定位及排期上下文。

### 本期四张卡片

| 卡片 | 所属快捷按钮 | 业务起点 | 确认后的结果 |
| --- | --- | --- | --- |
| 借鉴一条爆款 | 内容创作 | 一条参考视频及其分析 | 关联参考与产品的内容任务，绑定周任务包和排期 |
| 选定一个开场 | 内容创作 | 一个开场镜头或钩子 | 保留开场约束的内容任务，绑定周任务包和排期 |
| 为活动准备内容 | 内容创作 | 活动目标及活动时间 | 活动方案下的一条或多条内容任务，分别绑定周任务包和排期 |
| 查看本周发布日历 | 周计划 | 已有周计划和发布安排 | 日历查询、任务查看；用户明确提出并确认后才修改安排 |

其他首页场景不在本期扩展范围。完整视频编辑、批量排期、人物管理及账号授权使用已有工作台。

### 业务关系

“共用同一条任务、同一份排期”指同一业务对象在各入口中的身份一致，不是所有场景操作都写到固定的一条任务上。

- 新需求经确认后创建新任务；查看、补充、审核或调整已有内容时使用原任务。
- 同一任务可在多次对话中被引用。会话不是任务的唯一容器，删除或关闭会话不自动取消任务。
- 内容任务与周任务中的内容条目建立明确关联。制作执行、产物和发布事件引用该任务，不重复创建内容记录。
- 活动保留一个共同方案归属，每条内容各有任务身份；一条内容的失败不把其他内容标成失败。
- 一条内容可有多个平台或账号的发布事件，每个事件独立记录时间、审核及发布回执。新增发布事件不自动复制生产任务；确需新语言或新成片版本时关联派生版本。
- 本期新任务绑定周任务包后再进入制作。尚未确定周归属的需求保存为草稿，不宣称已加入周任务。

## 二 首页入口与通用交互

### 快捷按钮和场景卡片

点击快捷按钮，在输入区附近展开所属场景卡片。桌面按现有首页布局展示，移动端支持横向浏览；键盘可聚焦和选择，不能仅依赖滑动。卡片显示名称、一句话用途和适当的业务示意，不虚构产品或参考内容。

点击场景卡片只填入可编辑提示词，显示可移除的场景标签，不发送消息、不建立任务、不开始制作。用户发送后，爆款复刻可在明确确认建立准备任务时生成任务身份，具体遵循第四节。输入框已有文字时提供“替换当前输入”“保留当前输入”选择；取消后原文字不变。切换快捷按钮不清空输入。

| 场景 | 默认提示词 |
| --- | --- |
| 借鉴一条爆款 | 我想借鉴一条爆款视频，为自己的产品策划内容，并安排进周任务包。 |
| 选定一个开场 | 我想先选一个吸引人的开场，再围绕它为产品策划一条视频，安排进周任务包。 |
| 为活动准备内容 | 我想为一次活动准备内容，请帮我确认主题、产品和发布节奏，并安排进周任务包。 |
| 查看本周发布日历 | 帮我查看本周发布日历，看看哪些内容已发布、哪些待发布，以及哪些事项需要我处理。 |

用户发送后收起场景卡片；保留重新展开入口。普通自由输入与场景入口进入相同需求识别流程。场景标签是提示，用户正文中的明确更改优先。

### 对话中的选择与确认

每轮围绕一个业务决定，通常展示一个选择组；相关的少量字段可合并。已知产品、平台、语言、市场、受众及 CTA 优先带入，展示来源和修改入口。推断或建议标明待确认。产品多义、参考多义及“下周”等日期歧义必须消解。

用户既能点击选项，也能用自然语言修改。每次修改先更新草稿摘要，反馈影响；不要求用户重填无关字段。首次对话完成后不再次逐项询问已核验的企业事实。

对话卡片包含：当前问题、候选或字段、推荐理由或缺口、一个主操作以及必要的次操作。默认设置集中折叠，用户可展开修改。复杂选择和编辑进入 Drawer 或既有页面，避免把完整工作台塞入聊天气泡。

### 草稿与恢复

发送需求后保存对话草稿；刷新、关闭后重进可恢复选择及待处理节点。未发送输入只在本地按现有编辑器规则保留，不视为服务端任务。切换账号或企业立即清理当前页面的旧身份状态，禁止跨企业恢复。

同一会话可讨论多个任务，但每次执行操作明确显示当前任务标题；“改到周五”“继续制作”等指代存在多个候选时先选择对象。

## 三 内容任务的共同确认流程

前三张卡片完成各自的创作方向选择后，进入本节共同流程。本节是用户确认与展示顺序，不要求后端直到最终确认才建立记录。爆款复刻按第四节先建立准备任务以承接参考、审核与版本，最终确认绑定或采用正式周任务并启动；不得因此创建第二条生产任务。

| 阶段 | 对话展示 | 用户动作 | 保存结果 |
| --- | --- | --- | --- |
| 明确需求 | 企业产品、受众、内容目的和 CTA | 确认或修改本条目标 | 产品及事实来源、需求草稿 |
| 确定方向 | 场景对应的参考、开场或活动方案 | 采用方向或修改 | 创作约束和方案版本 |
| 确定归属 | 可用周任务包、已有内容及推荐位置 | 追加、选择替换项或改周 | 周归属及变更草稿 |
| 确定时间 | 制作交付目标、计划发布时间和时区 | 采用建议、调整或发布待定 | 交付与发布的独立字段 |
| 检查条件 | 产品、事实、素材、人物、预算和执行条件 | 补充缺项或接受可行方案 | 当前条件检查结果 |
| 最终确认 | 任务摘要、周排期变化、预计积分和待办 | 加入周任务；符合条件时同时开始制作 | 可追踪任务、周条目及操作回执 |

### 最终确认卡

摘要必须包含：标题、产品、目标、创作来源及方式、输出数量及版本、平台和账号、语言、周任务包及追加或替换方式、预计交付时间、计划发布时间、时区、待补资料、预计积分和本次执行范围。未选发布账号时标明“账号待定”，允许加入任务和制作，不允许排入真实发布队列。

主操作按实际状态显示：

- **加入周任务并开始制作**：必要输入、预算确认和执行条件已满足。
- **仅加入周任务**：允许保存计划，暂不启动；卡片列明后续待办。
- **保存草稿并补充资料**：尚不满足绑定周任务或创建正式任务所需条件。

创建和执行是两个可辨识结果。任务建立成功而制作启动失败时，返回原任务及具体原因，提供“继续启动”；重复点击不得再创建一条任务。检查结果对应资料版本，期间资料或排期变更时展示差异后重新确认。

### 周归属与时间规则

1. 优先读取已有有效周任务包；显示实际起止日期，不只显示“本周／下周”。新建草稿采用企业经营周设置；已有周包按持久化周期，不强制改成周一开始。
2. 无可用周包时提出创建草稿周包，最终确认明确包含这项变化；不悄悄新建或激活整周计划。
3. 存在多个业务线或周包时要求选择。不得通过“最新一条”猜测用户目标。
4. 周包已满时展示追加、替换、改周的影响。默认不挤占原任务。替换操作保留原任务和历史；已启动或已发布内容不能自动取消、覆盖或移出。
5. 制作交付目标独立于发布事件。单条内容存在多个发布事件时，以最早有效发布需求检查制作及审核余量。
6. 发布时间精确到时刻时保存明确时区；账号时区与北京时间不同则同时展示。仅确认日期时标为“时刻待定”，不补造默认时刻。
7. 无发布时间可以加入周任务，但放在周视图的“发布时间待定”区域；没有日期的任务不伪造日历事件。
8. 发布早于交付或审核余量不足时提示冲突，允许调整；不得承诺无法满足的到点交付。活动截止时间和素材供应会共同影响可行性。
9. 调整周归属不等于自动修改所有发布事件。跨周或跨账号修改展示完整差异及对制作、审核的影响后确认。

## 四 爆款复刻工作流

首页卡片继续使用“借鉴一条爆款”，业务对应现有 `creationMode=viral_replication`。用户选择参考、产品和目标后，系统沿用参考分析、逐镜脚本、素材路线、执行审核和媒体评估链路。首页负责收集和展示业务决定，原领域服务负责真实状态变化。

### 现有业务边界

1. `contentCreationTurn` 是只读规划接口，不能将它返回的推荐、分镜或问答状态当作已创建任务、已审核或已排队。
2. 现有参考附加、分析刷新和审核接口需要内容任务 ID。发送需求后先保留对话草稿；用户确认“建立复刻准备任务”后才调用任务创建。准备任务和最终生产任务是同一个对象。若从已有周内容进入，直接读取该任务，不另建准备任务。
3. 当前代码的普通模式要求显式逐镜审核，`one_click_managed` 有独立自动确认和参考等待处理。产品要求：本场景 R4、R5 由系统自动策划和校验，不要求用户逐镜确认或审批。实施时须在服务端接入自动校验及状态推进，并与已有托管路径评估复用；不能只隐藏前端按钮、伪造用户审核证据或直接放行。自动化仅限本节节点，不扩大后续付费或发布授权。
4. 当前既有 `social-content-weekly-plan.v1` 内容周计划，也有经营域的 `WeeklyOperatingPackage`。二者不能因名称相似视为同一份排期。内容周计划里的 `weeklyPlanId`、`mode=weekly` 或能力包选择不构成经营周包的生产授权。
5. 本稿目标是接入经营周包及其发布任务。周调度已有生产适配器和权威引用链，首页新增入口必须接入此链，不能在客户端拼接 `_weeklyAuthority` 或伪造周任务身份。

### 总体顺序

需求草稿 → 确认建立或选用准备任务 → 绑定企业产品和显式参考 → 读取或准备精确分析 → 系统生成逐镜适配方案 → 系统自动校验及执行条件检查 → 确认周任务归属与发布安排 → 通过经营周调度承接该任务 → 原生产链执行 → 独立复刻评估及产物审核 → 交付及发布承接。

周归属、目标账号和发布时间可以在前几轮提前收集；正式周包确认可能反过来改变账号策略或创作约束。发生这种变化时刷新受影响方案并由系统重新校验，不把上述展示顺序当成不可回退的后端状态机。

### 逐步业务和前端交互

| 步骤 | 已有后端业务及约束 | 首页前端交互 | 结果与下一步 |
| --- | --- | --- | --- |
| R1 明确需求 | 企业产品、主题和目标是参考适配与事实绑定的输入；创建服务读取有效能力包并执行任务容量和幂等检查 | 选择企业产品、确认内容目标；展示带入的平台、语言及 CTA。首次写入前点击“建立复刻准备任务”，说明尚未制作 | 通过 `createSocialContentTask` 建立原任务，保存返回的任务身份和版本；已有任务直接复用 |
| R2 附加参考 | `addSocialTaskSource` 保存实际 `reference_link`，触发任务对账和参考输出刷新；来源只能在允许状态编辑，重复附加会拒绝 | 预览并选择当前企业参考；确认后展示“已绑定参考”，附来源与分析状态 | 将来源身份和版本关联到原任务；不只保存一段标题或 URL 文本 |
| R3 分析准备 | `refreshSocialTaskReferenceOutputs` 解析参考并派生参考分析、复刻脚本、逐镜素材映射与脚本基线。缓存复用校验同企业、唯一活动来源、媒体哈希和原分析运行身份 | 显示“参考准备中／需要完善分析／已就绪”，展示覆盖缺口；提供查看原分析、处理缺口和刷新结果 | 返回真实 `referenceVideoAnalysis`、`replicationScript`、`shotMaterialMap` 等；仅分析就绪后进入审核 |
| R4 系统策划逐镜方案 | 复刻脚本关联参考分析；系统生成适配口播、画面、素材计划及事实引用 | 显示“正在策划复刻方案”及可选查看的摘要，不弹逐镜确认、不等待用户批准；用户可主动提出修改 | 自动产出原任务的方案版本并进入 R5；聊天文本不能替代真实后端方案 |
| R5 系统自动校验 | 服务端校验版本、分析与脚本身份、全部镜头覆盖、产品事实、画面和素材可执行性；自动审核接入与状态推进为待实现 | 显示“正在检查制作条件”；通过后自动进入下一步，不展示审核确认按钮。失败先走允许的自动修订，仅无法自动解决的真实输入缺口才询问用户 | 真实检查通过后由服务端记录系统校验结果并推进；保留来源和版本，不冒充用户确认，不以直接写 confirmed 代替校验 |
| R6 确认周排期 | 周生产需要真实项目、周包版本、发布任务、工作流任务和有效 lineage；现有周适配器建立并核验这些关系 | 显示周包起止、目标账号、交付和发布时间、追加或替换差异；确认后等待后端接受并返回定位 | 新增首页到周域的承接命令，优先让周适配器采用原准备任务；当前适配器能否采用需实现核验，不承诺已有即插即用接口 |
| R7 开始执行 | `startSocialContentTask` 再次核验状态和版本，刷新参考与输入，检查执行方案，预留内容订单并进入原队列；周任务再经过周生产门禁 | 服务端明确确认进入执行队列后，在对话中生成该任务的生产门户卡片，主操作“查看内容任务详情” | 卡片绑定原任务及真实执行回执，直达对应生产页面的单条内容任务详情；已有运行只观察或恢复，不重复启动；入队不等于成片完成 |
| R8 生产交接 | 编导锁定计划通过哈希及镜头素材引用校验后交给内容执行；路线依真实素材、人物、事实、授权和预算决定 | 后续节点进展在门户所指向的单条任务详情集中展示；首页门户同步当前节点和待办摘要 | 修改锁定脚本或镜头时返回编导修订并产生有效新版本，内容执行不能私自重写锁定口播 |
| R9 评估与审核 | 存在复刻 job 时，独立媒体评估检查爆点保真、身份替换、原创差异、复用风险和账号适配；随后以真实产物及审核结果推进 | 单条任务详情显示真实预览、评估结果和待处理项；用户在原产物上通过或提出修改，门户同步状态摘要 | 渲染完成、评估完成、产物通过分别表达，不因文件出现就标整条完成 |
| R10 交付发布 | 交付包和发布记录有各自状态与版本；发布登记要求允许状态及有效交付包，不是平台发送接口 | 显示交付、待发布、已发布及效果状态；发布操作进入原账号与发布流程 | 平台发送、发布回执登记和效果回填分开，不用登记发布记录代替真实平台执行 |

### 参考准备与分析复用

首期优先选择已有企业灵感记录，复用后端已保存的精确分析。`cachedReferenceRecordId` 路径要求已确认主题、复刻模式和唯一活动参考等条件，并由服务端生成复用绑定。不存在可用分析、原媒体变化或原分析被重跑时，显示实际缺口，不能继续假定原确认有效。

`refresh-reference` 的作用是刷新任务中的参考输出，不能解释为它一定执行新采集、下载或付费分析。新上传或新链接进入现有灵感导入和分析流程；其成本和权限按原流程确认，完成后回到原准备任务绑定和刷新。首页不能自行调用另一路模型临时分析后冒充精确分析。

`referencePreparation` 的 pending、review_required、blocked 等准备信息与任务分析是否 ready 分别解释。分析尚未就绪时不能提前确认复刻脚本。反复点击刷新仅获取或更新已有任务上下文，必须遵守后端版本与幂等约束。

用户已经明确选择参考时，任务创建到附加来源期间可能存在短暂空档。首页接入须确保该空档不会采用系统推荐参考，复用或补齐明确参考的准备约束；此项属于待开发接入，不默认所有普通创建调用都已具备该行为。

### 系统自动策划校验与修订

R4、R5 均为系统内部节点，用户不需要逐镜选择、审脚本或点击审核通过。前端展示实际进度；方案摘要和逐镜详情作为可选查看入口，查看与否不影响自动推进。用户主动提出修改时，更新原任务的方案版本并自动重跑受影响校验。

自动校验必须保留现有业务要求：任务及分析版本一致、镜头覆盖完整、产品身份与事实有依据、方案具备可执行素材路线。通过后服务端保存真实系统校验结果及版本，再推进后续节点；失败时先在已确认目标、事实、预算和授权范围内自动修订。不能自动解决时，仅请求缺失产品资料、素材或会影响目标与费用的业务选择，不把技术校验转成用户“确认无误”的问题。

现有 `/replication-script/review-context` 和 `/replication-script/confirm` 体现普通模式的人工审核合同，不能描述为已经支持本稿要求的自动审核。开发需明确系统执行身份、校验依据、版本和幂等记录，复用已有校验逻辑并提供合法状态推进。前端不得代填人工证据，也不能在任务仍为 review_required 时假报校验完成。

现有 `one_click_managed` 可作为自动推进与参考等待的复用候选，但现有自动置为 confirmed 的行为不等同于本稿要求的全部逐镜质量检查。需评估并补齐，不因免除用户确认而取消产品事实、素材、执行和周授权检查；不自动扩大到付费重做、成片验收或真实发布。

`adapt-product-only` 仍是受限修订：必须满足当前产品绑定、有效图片来源及版本。采用后由系统重新校验；重复静态视觉、时长不适合或内部制作文案等问题不能靠自动确认放行。修改目标、增加费用或需要用户提供新事实时，返回对应业务节点处理。

### 周任务承接与执行身份

经营周包的接入是本期后端核心工作，不是前端显示一个周标签即可完成。

- 首页收集并确认周包、发布条目、账号、时间和追加或替换范围，向服务端提交意图，不提交伪造冻结证明。
- 服务端读取真实经营周包及其版本，通过现有周调度和 `createSocialWeeklyProductionAdapter` 等领域服务建立或采用生产身份。已有周内容直接继续原任务；准备任务如何合法被采用需要新增承接能力，避免适配器又创建另一条原始生产任务。
- 调度冻结的 program、周包、publication、workflow、参考和目标账号策略必须相互一致。`readWeeklyReplicationContext` 还会核对分析及来源链；不能拿最新账号策略代替冻结版本。
- `withWeeklyProductionStartGuard` 会核验有效 lineage、生产覆盖和周包冻结状态。缺少或失效时返回具体阻塞，不改走普通任务启动绕过。
- 普通能力包选择接口 `/package-selection` 选择的是业务能力包，不是选择经营周任务包；`/weekly-plans` 的内容周计划不能作为经营周调度接入的替代。
- 周归属确认失败时保留准备任务。周归属已成功但启动失败时显示原任务的待办或恢复入口，不能重建任务、重占原始订单或假报已经制作。
- 已有运行、已完成产物和真实消耗不能通过补写字段追认成另一份周授权。改周、替换和重做遵循现有修订与承接规则；不直接改冻结对象。

### 入队后的生产门户与单条任务详情

本场景在 R7 进入“对话交接到生产详情”的阶段。门户卡片出现在原对话消息流中，是原任务的可恢复入口，不新增一级页面或另一条生产任务。

**出现条件**：后端返回真实队列或执行记录，并明确确认任务已进入执行队列。仅保存任务、通过预检、预留订单、返回请求已受理或等待初次确认时，不生成“已进入执行队列”的门户。请求超时或结果未知时先查询原操作；确认入队后补回同一张卡片。重复请求、刷新或重新打开会话不重复生成同一任务的门户。

**卡片内容**：内容标题、主推产品、周任务归属、平台及语言、交付和发布安排摘要、当前真实节点、待办或阻塞，以及最后更新时间。主操作为“查看内容任务详情”，次操作可提供“查看周安排”。后台使用任务与执行身份绑定，界面不要求用户识别内部 ID。刚入队时显示“已进入执行队列，等待执行”，不能显示为已经生成成片。

**跳转行为**：点击门户，在当前应用中直接打开对应生产页面的单条内容任务详情，按原 `socialContentTaskId` 定位，不先落到任务列表，不匹配标题、不猜最新任务。已存在运行或产物时展示该任务的当前有效状态；保留原对话返回入口。若现有生产路由尚不能直接呈现单条详情，补齐该路由及定位能力，不通过创建新任务替代。

**详情内容**：顶部显示任务身份、周归属、产品和排期；主体按实际业务依赖展示后续节点，包括生产准备与编导交接、素材匹配或补齐、适用的首帧或数字人生成、配音与字幕、成片合成与渲染、质检及独立复刻评估、成片验收与交付。节点依实际执行路线呈现；未使用的步骤标为不适用或不展示，不能伪造执行记录。

每个节点显示实际状态、可用时间、已有产物、阻塞原因和可执行动作。状态至少区分等待上游、排队、进行中、待补充、失败、已完成和不适用；只有存在真实统计时才展示进度比例。成片节点提供真实视频预览和当前版本。缺素材、失败或需验收时在对应节点处理，调用原工作台动作及恢复服务，不在详情页另建平行执行链。

**同步与返回**：任务详情刷新和重新进入后继续读取原执行进展，离开页面不取消队列任务。返回首页恢复原对话位置，门户更新为原任务最新节点、成片及待办摘要。对话不逐步复制生产工作台；后续成片生成等详细进展以单条内容任务详情为集中查看位置。

### 复刻场景的开发和验收增量

已有能力：任务创建、来源附加、分析刷新、复用校验、逐镜审核、执行方案校验、周生产适配及门禁、内容订单与原队列、锁定编导交接、独立媒体评估、产物和交付记录。

需要接入或补齐：首页受控准备任务、显式参考空档保护、对话草稿与原任务绑定、系统自动策划与逐镜校验的状态推进和结果回流、准备任务被经营周包合法采用、跨页定位与恢复、入队后生产门户及单条详情的节点进展、依真实动作生成按钮。首期不能将另一分支中的单条创建表单当成以上经营周接入已完成的证据。

验收必须覆盖：R4、R5 无用户确认按钮且不等待人工审批；系统校验通过后自动推进，失败不伪造通过或用户证据；自动修订只在已确认业务范围内进行；旧普通模式未审核启动仍被拒，新增自动路径合法承接状态；逐镜覆盖不足及旧哈希不能自动放行；缓存原分析变化不能继续复用；显式参考未绑定前不换成推荐参考；周绑定失败保留原草稿；周适配不重复创建生产身份；周权威失效不能普通启动绕过；执行缺口不被“确认”按钮掩盖；渲染成功不等于评估和发布成功；跨页后持续使用原任务及当前版本。

## 五 选定一个开场

“开场”指开头片段或表达钩子，是本期产品定义；可用素材与结构参考分别表达，选择它不意味着获得第三方画面的使用许可。

### 场景步骤

1. 展示“从已有候选中选”“选择或上传自己的片段”。候选卡含预览、开场特点、适用方向及来源类型。
2. 对自有长视频支持选择开场起止片段，保存具体素材及片段范围；复杂裁切进入原素材处理页。参考开场保存参考和片段范围，标明需重现。
3. 开场存在多个镜头或含产品误导风险时，先说明需要确认的范围和重现方式。
4. 选择主推产品，给出开场接到产品的衔接建议；关联弱时提供“更换开场”“调整衔接”“保留并修改方案”。
5. 围绕开场给出二至三个方向，每个只展示钩子、核心内容和 CTA。用户采用或自由修改后进入共同周任务确认流程。

### 执行与页面

短预览和方向选择在对话中完成。完整素材选择进入内容创作的素材库，参考分析进入灵感中心，均能采用并返回。

已选开场作为任务约束，在完整脚本和分镜中可见。检查开场能否实际使用或制作、与产品是否一致、后续衔接是否自然。无法实现时提出替代并说明差异；未经确认不静默替换。后续更换开场保留原任务，产生新的方案版本。

本期优先复用已有素材、参考和分析结果；不以本场景为由另建完整开场资产管理系统。

## 六 为活动准备内容

### 场景步骤

1. 确认活动类型、名称、时间或时间范围、时区和业务目标。支持上传活动资料并提取字段，事实需可查看来源。
2. 选择主推产品与顺序。优惠、价格、展位、地址和链接仅在相关内容使用时要求补齐；缺失项不由模型虚构。
3. 提出可删减的内容组合，展示每条内容的主题、目的、阶段、素材依赖、预计积分及日期。用户可保留一条或多条。
4. 统一设置公共默认项，再逐条确认差异。分别指定周归属、交付和发布安排；跨周内容进入各自周包并保留共同活动归属。
5. 展示活动总确认卡：条数、每条去向、总预计积分、关键时间、资料缺口和执行范围。确认后创建活动关联及各条任务。

### 执行与页面

简短方案留在对话；多条排期和批量编辑进入活动方案 Drawer，复杂排期进入已有周任务及发布日历。每条任务均能单独打开内容创作详情。

创建过程中发生部分失败时，逐条标记已建立、未建立和待重试；按原请求恢复未完成项，不重复创建成功项，也不宣称全部成功。

活动日期、优惠和链接变更时，展示受影响内容：未制作可更新草稿；已审核、已制作或已排期内容重新确认受影响部分；已发布内容提示人工处理实际平台结果，不能仅改计划冒充撤回。临近截止仍受阻时提供缩减内容、改期或取消未执行部分的选择，说明已完成产物和已发生消耗。

## 七 查看本周发布日历

### 查询和展示

发送后查询当前企业的周任务与发布事件，不创建任务、不修改排期、不生成内容。“本周”以企业当前时间和经营周期解释，并显示起止日期；存在多个周期时提供明确切换。

对话先返回紧凑的按日安排和简短概览，展示内容标题、平台、账号、计划时间和必要状态。已发布事件同时保留实际发布时间。发布时间待定的任务单列；有日期无时刻的事件明确“时刻待定”。

操作包括“上一周”“下一周”“查看完整日历”和每条内容的“查看详情”。无排期提供“安排本周内容”，只进入需求草稿。接口失败展示重试；不得显示为“本周没有任务”。

### 查看与修改

点击某条打开任务或发布事件 Drawer，显示对应版本、制作状态、产物、发布准备、阻塞和下一步。多次发布必须先定位具体事件，“移动视频”不能默认改动该内容所有账号的安排。

用户通过对话或日历提出修改后，先展示变更前后、时区、受影响事件和风险；确认后保存。已进入制作的交付调整、跨日、跨周、跨账号变化均需要明确确认。与原排期冲突时保留用户修改草稿，展示最新版本重新选择。

已发布事件保留真实发布时间，不能拖动成待发布事件。发布失败不等于制作失败；可进入对应发布恢复操作。具备查看权限但无编辑权限时保留查看功能，禁用修改并解释原因。

## 八 制作审核发布与任务状态

### 需要用户介入的节点

| 节点 | 展示与操作 | 继续条件 |
| --- | --- | --- |
| 脚本与分镜 | 口播、核心卖点、CTA、画面安排及事实依据；爆款复刻仅供查看或主动修改，不要求用户确认 | 爆款复刻由系统自动校验并推进；其他场景采用各自有效审核规则 |
| 素材缺口 | 缺哪段、影响什么；上传、加入待拍或选择可行替代 | 必要素材或被明确接受的替代满足条件 |
| 数字人与声音 | 已选企业人物、声音及缺口；进入人物管理 | 原资产与授权有效，沿用已确认配置 |
| 费用变化 | 新增制作或重做的预计积分与原因 | 获得本次范围所需确认，不重复收取系统重试费用 |
| 成片验收 | 真实视频预览、质检结果、版本和修改入口 | 成片被验收；失败或未完成不显示成功 |
| 发布 | 成片、账号、文案、时间及授权状态 | 成片有效、发布条件具备并满足授权规则 |
| 效果复盘 | 实际发布回执、数据范围和采集时间 | 有数据才分析，无数据说明等待或缺口 |

确认加入周任务不等于授权所有后续付费、重做或真实发布。已确认的执行规则可在有效范围内沿用，不为相同默认设置重复打断用户。

### 前端状态表达

| 业务状态 | 用户看到的重点 | 下一步 |
| --- | --- | --- |
| 需求草稿 | 已选内容与未确认项 | 继续补充或确认 |
| 已加入周任务 | 周归属、交付及发布安排 | 开始制作或补齐条件 |
| 待补充 | 具体缺项、受影响节点 | 补资料、上传或安排拍摄 |
| 制作中 | 当前真实节点、已有产物 | 查看进度或暂停 |
| 待审核 | 明确需要审核的对象及版本 | 审核或提出修改 |
| 成片已验收 | 成片与交付结果 | 准备或确认发布 |
| 待发布 | 发布事件、账号、时间及准备情况 | 完成发布条件 |
| 已发布 | 平台回执与实际时间 | 查看效果 |
| 发布异常 | 原因、回执及可恢复动作 | 在原事件恢复 |
| 暂停或取消 | 原因、保留产物与后续影响 | 满足条件后恢复或查看历史 |

状态由原任务、产物及发布回执投影，不由模型回复文字决定。制作状态和发布状态独立；同一内容可出现“一处已发布、另一处待发布”。未知数量不展示虚构百分比。

### 路由与上下文约定

当前代码存在首页 `page=strategy`、内容生产入口 `page=smartAssets&view=create&socialContentTaskId=…`，并有经营页面 `page=digitalEmployees` 及生产导航上下文。实施时复用导航解析，不能以历史页面 ID 推断当前展示名称或复制一套路由。

本期需补齐可刷新恢复的“对话来源＋业务对象＋返回上下文”契约，至少包含：企业身份、会话身份、需求草稿或任务身份、周包和内容条目、发布事件、目标步骤、日期范围、筛选以及来源位置。仅传当前操作所需字段；不在 URL 放令牌或敏感资料。

发布日历的子视图、日期、任务聚焦和返回会话参数属于待实现的导航能力，本稿不把示意参数视为现有可用链接。开发时先确认现有导航兼容方式，再形成统一契约。

跳转前保存未提交选择；返回后读取最新服务端状态。可变筛选和滚动恢复可作为页面上下文保存，但业务身份与权限以服务端为准。刷新或直接打开链接时能定位已保存对象；来源会话不存在时仍可查看任务并提供回首页入口。

未找到对象、无权限或身份不符时给出明确结果，不回退为“最新任务”。浏览器后退返回原页面状态，不重新触发创建、执行或发布。

## 十 一致性和异常处理

1. 首页任务卡、内容创作、周任务和日历均读取原业务对象。操作成功后同步刷新相关投影；重新聚焦页面时读取最新状态，避免显示过期的已确认结果。
2. 新建请求防重复，后端按请求身份返回相同结果。重试、刷新、返回和多次点击不会重复建立任务、活动子项或发布事件。
3. 创建任务与绑定周包若无法一次完成，必须有可恢复的中间结果。部分完成时展示真实结果和恢复入口，未绑定前不允许冒充成功或启动后续执行。
4. 排期或审核版本冲突时展示新旧差异；已被修改的旧确认按钮不能继续执行。对历史消息保留摘要，操作入口基于当前版本重新核验。
5. 网络中断保留草稿和已知回执。执行结果未知时先查询原操作，不当作失败重新提交付费或发布请求。
6. 素材缺失、授权失效、额度不足分别反馈到对应节点；恢复后继续原任务，不从头新建。
7. 生产执行器不可用时可以建立任务和周归属，显示待启动。本地预览不得以模拟生成或发布结果标记真实完成。
8. 生成中切换页面不取消服务端任务；取消须是明确业务操作，并说明保留产物及已发生消耗。
