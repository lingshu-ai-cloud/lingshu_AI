# 灵枢视频生成固定工作流现状说明

- 日期：2026-10-23
- 性质：当前代码现状说明，不是未来方案
- 范围：从任务目标形成到成片交付；不把发布算作视频生成完成
- 当前主执行版本：`content-production.v2`

## 1. 一句话结论

当前视频生成不是让 Agent 临时决定下一步，而是先冻结经营目标、导演方案和逐镜执行计划，再进入一条有版本、有输入哈希、有检查点的固定生产图：

> 经营目标 → 参考与素材证据 → 导演方案 → 执行计划 → 编导审核 → 素材供给 → 配音 → 时间线裁切 → 特效/字幕/混音 → 渲染 → 技术质检 → 创意质检 → 用户验收 → 交付包

其中供应商、素材和镜头路线可以因任务而不同，但一旦执行计划通过审核并开始生产，本次任务使用的版本、输入、路线和成本边界就被冻结，运行中不能静默改计划。

## 2. 固定工作流分为两层

### 2.1 决策与冻结层

这一层解决“为什么做、做什么、每一镜怎么做”，还不直接渲染视频。

| 节点 | 主责 | 稳定输入 | 稳定输出 | 固定门禁 |
| --- | --- | --- | --- | --- |
| 1. 经营目标 | 经营 Agent | 已核验企业事实、产品事实、平台账号、预算与授权 | 目标、受众、平台、CTA、指标、事实与权利边界 | 缺事实、权利或预算时阻断，不让模型补造 |
| 2. 参考与素材证据 | 工具/Worker 提证据，编导 Agent 解释 | 参考视频、企业素材、素材能力、授权和账号策略 | 参考分析、素材能力清单；爆款复刻任务另有因素与身份替换要求 | 外部参考默认只用于学习结构，不能自动进入成片 |
| 3. 导演方案 | 编导 Agent | 经营目标、参考分析、素材能力和事实边界 | `DirectorBrief`：逐镜目的、主体、动作、景别、时长、口播、连续性、证据和验收标准 | 每镜必须可执行、可验收；编导不直接调用供应商 |
| 4. 执行计划 | 内容 Agent/制作规划 | `DirectorBrief`、素材清单、能力注册表、预算 | `ExecutionPlan`：逐镜主路线、备选、素材绑定、供应商绑定、成本、时间和回退 | 付费调用前暴露缺素材、缺权限、缺预算和能力不匹配 |
| 5. 计划审核 | 编导 Agent | `DirectorBrief + ExecutionPlan` | `ExecutionPlanReview`：逐镜通过、失败标准、修改要求和原因 | 未通过不得进入生产；内容 Agent 不能自审自批 |

冻结对象至少包括：`directorBrief`、`executionPlan`、`executionPlanReview`、素材供给计划、计划版本、任务输入哈希和预算边界。

### 2.2 媒体生产执行层

通过计划审核后，`content-production.v2` 按固定顺序执行。除“用户验收”外，每个节点都有独立检查点；失败后从对应检查点恢复，不从头重跑。

| 顺序 | 固定节点 | 责任者 | 必须读取的输入 | 必须留下的输出 |
| --- | --- | --- | --- | --- |
| 1 | `assets` 素材供给 | 素材供给 Worker | 已批准上下文、逐镜素材计划、企业素材、权利/身份/预算证据 | 每镜选中或生成的素材、来源身份、内容哈希、供应商回执、`social.asset_supply` 检查点 |
| 2 | `voice` 配音 | 配音 Worker | 冻结口播、语言、音色/人物绑定、逐镜时间窗 | 可恢复的音频、音频 SHA-256、总时长、逐句时间点、对齐来源、`social.graph_voice` 检查点 |
| 3 | `trim` 时间线裁切 | 剪辑 Worker | 导演方案、镜头素材、配音哈希、逐镜起止时间 | 唯一剪辑时间线、镜头数、总时长、时间线哈希、`social.graph_trim` 检查点 |
| 4 | `effects` 特效/字幕/混音规格 | 特效 Worker | 时间线、特效计划、字幕时间点、配乐与音量规则 | 冻结合成清单、特效/字幕/清单哈希、`social.graph_effects` 检查点 |
| 5 | `render` 渲染 | 渲染 Worker | 冻结合成清单和已绑定的真实媒体字节 | MP4 成片、输出 SHA-256、字幕与帧渲染证明、`social.graph_render` 检查点 |
| 6 | `technical_quality` 技术质检 | 技术质检 Worker | 成片字节、合成清单、预期时长和镜头区间 | 解码、时长、帧、镜头、音轨、BGM、字幕等技术报告及通过状态，`social.graph_technical_quality` 检查点 |
| 7 | `creative_quality` 创意质检 | 独立创意质检专家；复刻任务另有媒体评估 Worker | 技术质检已通过的成片、`DirectorBrief`、参考证据和逐镜验收标准 | 创意质检结果、逐镜失败、最小返工范围；复刻任务另输出保真、身份替换、原创和权利风险结果 |
| 8 | `review` 用户验收 | 用户/有效业务审批人 | 当前成片版本、内容哈希、质检结果和风险说明 | 与当前文件哈希、对象版本绑定的批准回执；客户端布尔值不能代替批准 |
| 9 | `delivery` 交付 | 交付 Worker | 不可变成片、有效批准回执、当前任务版本 | 交付包、成片与包 ID、完成检查点；`externalPublishPerformed=false` |

实际固定拓扑为：

```text
assets
  → voice
  → trim
  → effects
  → render
  → technical_quality
  → creative_quality
  → review（人工暂停点）
  → delivery
```

## 3. AI、工具和用户的边界

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| 经营 Agent | 经营目标、受众、平台、CTA、指标和事实边界 | 选供应商、渲染、批准发布 |
| 编导 Agent | 参考解释、导演方案、执行计划审核、创意验收 | 直接执行生成工具、批准自己的最终成片 |
| 内容 Agent/制作规划 | 素材与能力匹配、逐镜执行路线、生产组织、局部返工 | 改写经营目标、事实和核心表达；自行最终放行 |
| 媒体 Worker | 素材处理、配音、裁切、合成、渲染和可重复检测 | 解释经营因果、修改创意目标 |
| 独立质检 | 检查技术质量、参考保真、身份替换、原创差异与权利风险 | 修改成片或替用户验收 |
| 用户 | 批准当前成片版本，决定是否进入交付/后续发布 | 不需要选择模型、提示词或内部检查点 |

固定放行顺序遵循：内容侧技术质检 → 独立媒体/创意检测 → 编导验收 → 用户验收。任何生成者都不能用自己的评分跳过下一个门禁。

## 4. 工作流靠什么“固定”

### 4.1 用版本和哈希固定

每次生产绑定以下身份：

- `tenantId`
- `taskId`
- `runId`
- `jobId`
- `graphVersion`
- `planVersion`
- `inputHash`

任何节点开始前都会重新检查任务范围和输入身份。导演方案、素材计划或任务版本在生产中发生变化时，当前图不会继续使用旧批准，需要形成新版本或获得受控修订授权。

### 4.2 用节点检查点固定

每个节点分别保存开始、完成或失败状态，以及：

- 节点版本和图版本；
- 输入哈希与输出 SHA-256；
- 尝试次数、起止时间和失败码；
- 供应商请求回执；
- 预算预留与真实费用；
- 产物引用。

因此服务重启或节点失败时可以从已验证检查点恢复。对可能产生费用的外部请求，先对账原请求再恢复，避免重复提交和重复扣费。

### 4.3 用人工验收回执固定

创意质检完成后，图会在 `review` 节点暂停。继续执行必须重新读取服务端保存的有效批准回执，并同时匹配：

- 当前成片内容哈希；
- 当前对象版本；
- 当前批准回执 ID；
- 当前任务和运行身份。

成片、版本或批准发生变化，交付节点会拒绝继续。交付只生成交付包，不等于已发布。

## 5. 不同任务如何进入这条固定链

| 任务情况 | 当前行为 |
| --- | --- |
| 周计划任务，且不是 `shooting_plan` | 固定进入持久化队列和 `content-production.v2` |
| 即时/手工任务 | 只有环境显式启用 LangGraph 时进入 V2，否则仍可能使用旧执行器 |
| `shooting_plan` | 只输出逐镜代拍清单，不调用配音、数字人、视频生成或渲染，不进入媒体生产图 |
| `material_processing` | 不要求爆款复刻证据，但仍需导演方案、执行计划和质量门 |
| `viral_replication` | 在相同生产图前增加参考、爆点因素、逐镜保真、身份替换和权利门禁；产后增加独立复刻评估 |
| 已冻结历史任务 | 可继续按 `content-production.v1` 兼容恢复：`assets → render → quality → review → delivery`，不自动改写为 V2 |

## 6. 当前结论

目前真正固定的是：

1. 决策职责：经营目标、编导创意、内容执行和独立质检不能混为一个 Agent；
2. 开工条件：导演方案和逐镜执行计划先审核、后生产；
3. 生产拓扑：V2 节点顺序固定，不能运行中跳步；
4. 任务身份：版本、哈希、批准上下文和成本边界固定；
5. 恢复方式：按节点检查点恢复，付费调用先对账；
6. 放行顺序：技术质检、创意质检、用户验收、交付依次通过；
7. 交付边界：生成交付包不代表已经发布。

目前尚未做到“所有视频任务都只走 V2”：周计划的非代拍任务已固定走 V2；即时/手工任务仍保留旧执行器兼容分支。这是理解当前系统时最重要的边界。

- `shared/contracts/videoProductionSupervisor.ts`：V2 固定节点、责任者、依赖和检查点。
- `server/contentExecution/langgraphIdentity.ts`：图版本、任务身份和哈希规则。
- `server/contentExecution/langgraphEngine.ts`：实际节点顺序、人工暂停、恢复与交付前批准复核。
- `server/starter198/socialContentProductionGraph.ts`：周计划/即时任务的执行器选择、批准上下文冻结和交付包生成。
- `server/starter198/socialContentProductionExecution.ts`：素材、配音、时间线、特效、渲染、技术质检和创意质检的实际执行。
- `shared/contracts/socialContentAgentContract.ts`：经营、编导、内容、媒体评估和最终门禁职责。
