# 灵枢 198 标准版｜社媒内容制作工作流 PRD

> 版本：v1.2 周经营批次版
> 日期：2026-09-14
> 当前状态：周任务、批次验收与预算边界已进入产品实现；三类作业包继续只保留技术框架，实际策略内容待内部团队配置

## 0. 一分钟看懂产品

这条流程只解决一件事：**客户每周只确定经营重点、目标客户、生产规模和预算，灵枢自动安排本周内容，先用代表样片确认方向，再批量生产并交付；客户自行发布后，把链接或数据回传用于下一周改进。**

~~~text
设置本周重点、数量与预算
  → 继承企业资料并补充本周素材
  → 灵小枢形成周计划
  → 新内容先出代表样片
  → 方向确认后批量生产
  → 用户按批次验收并下载交付包
  → 用户上传到自己的社媒账号
  → 回传发布结果与表现数据
  → 系统形成周复盘和下周建议
~~~

客户不需要选择 Agent，也不需要理解系统如何调度：

- **灵小枢**是本次任务的统一入口，负责检查资料、安排工作、汇总进度并完成交付。
- **灵小图**负责灵感、选题、脚本、分镜、画面、文案及内容质量。
- **灵小量**负责各平台内容适配、交付包整理、发布登记和数据回收。
- **灵小售**只在任务包含获客目标时检查客户行动路径和承接内容；出现真实咨询后再进入后续销售流程，不强行占用内容生产主流程。

“行业起航包、内容火箭包、任务飞车包”是系统内部为同一个周任务调用的三部分专业能力，不是购买套餐，也不是客户每周需要选择的三个选项：

- **行业起航包**决定依据什么方向做。
- **内容火箭包**决定具体生产什么内容。
- **任务飞车包**决定怎样推进、检查、交付和复盘。

灵小枢根据本周目标自动调用可用版本。198 用户只看本周计划、进度、待处理事项和交付结果；作业包版本与规则由内部团队管理。

### 0.1 本轮融合后的核心判断

1. **把“做多少条内容”升级为“经营一个内容周”。** 数量只是交付目标，系统还要管理方向、样片、批量生产、异常、补拍、交付与复盘。
2. **采集量、生产量和可发布量分开。** 收集到 100 条参考不等于要生产 100 条内容；计划 60 条也不代表 60 条都已经通过检查。
3. **客户不逐条选题、选素材和选制作方式。** 灵小枢先排周计划，用户只看摘要、代表样片和异常内容。
4. **创意方式与制作方式分开。** “产品展示、知识问答、结构变体、场景创意”等决定内容怎么表达；“已有素材制作、产品画面生成、数字人、补拍”等决定画面怎么完成。
5. **先验证样片，再展开批量。** 新产品、新系列和新表达先确认代表样片；成熟系列可以继承上周规则，不重复确认。
6. **素材缺口一次合并。** 不连续弹出十几条“缺一个镜头”，而是形成一张集中补拍清单，写清拍什么、拍多久、能支持哪些内容。
7. **反馈按批次生效。** 用户的一条意见应用到受影响的一组内容，同时说明影响范围；单项例外仍可进入专业页修改。
8. **预算只给可靠边界。** 显示本周上限、单条上限和重试预留；成本尚未校准时先做小批样片，不给虚假的精确报价。投流预算始终与内容制作预算分开。

## 1. 产品目标

### 1.1 核心目标

让 198 标准版用户在首页完成一周社媒内容经营的主要操作：

1. 确定本周重点产品、目标客户和内容目标。
2. 选择或上传本周新增素材；企业知识、品牌口径和禁用表达默认继承。
3. 填写平台、市场、语言、计划数量、生产预算、可集中拍摄时间和特殊要求。
4. 查看灵小枢给出的周计划摘要和素材缺口。
5. 新方向只确认一次代表样片，之后由系统批量生产。
6. 按批次预览、确认、退回并下载交付包。
7. 登记实际发布结果。
8. 回传平台数据并查看下一轮建议。

用户不进入其他页面也可以完成一整轮任务；需要精细调整时，可以进入对应的专业工作台手动完成，保存后与首页保持一致。

### 1.2 成功标准

- 新用户无需培训、无需持续对话，也能建立并启动第一个内容周。
- 首页在任何时刻只突出当前进度、已有成果和一个最重要的下一步动作。
- 交付包中的内容足以让用户在自己的社媒账号完成发布。
- 自动制作与人工修改使用同一个周任务、素材和作品版本。
- 用户不需要逐条重复相同的确认或修改意见。
- 页面不把参考数量、计划数量、完成数量和可发布数量混为一谈。
- 用户离开页面后任务可以继续，回来后能从原位置继续处理。
- 未收到真实发布结果或数据时，不显示为已发布、已回收或已完成。
- 客户界面不出现开发术语、系统原理说明、内部配置项或空白开发占位。

## 3. 前端设计原则

本节是内部产品要求，不能作为解释文案直接展示给客户。

### 3.1 专业 SaaS 交互原则

1. **先完成任务，再解释功能。** 页面首先告诉用户现在能做什么，不用大段文字讲系统原理。
2. **一个状态只有一个主要动作。** 例如“继续补充资料”“确认方案”“查看成品”“下载交付包”“登记发布结果”。
3. **高频信息直接展示，低频设置逐步展开。** 首次创建任务不让用户面对几十个字段。
4. **默认给出专业推荐。** 用户可以调整，但不要求从空白开始搭建流程。
5. **同一对象只有一份。** 首页、素材库、脚本库、创作台和交付中心看到的是同一任务及同一作品版本。
6. **修改有记录，交付可追溯。** 人工修改生成新版本，不覆盖已经交付或已经发布的版本。
7. **错误就地解决。** 明确说明缺什么、影响什么、下一步怎么处理，不把用户带进长对话。
8. **页面密度专业但不拥挤。** 使用清晰的表单、表格、抽屉、筛选、状态和操作区，不用大量装饰性卡片堆叠。
9. **操作可恢复。** 支持自动保存、离开提醒、失败重试、返回上一步和继续未完成任务。
10. **电脑与移动端都能完成关键操作。** 复杂编辑以电脑端为主，移动端至少可以查看、确认、下载和回传发布结果。

### 3.2 客户界面文案红线

客户界面禁止出现以下类型的文字：

- “AI 工作流对应页面”“固定节点”“服务端工作图”等原理说明。
- “写入托管”“接口未接通”“不会绕过权限”等开发或安全实现说明。
- 运行编号、任务编号、模型名称、提示词、密钥、数据表和内部错误堆栈。
- “本页用于展示”“开发预留”“待开发”“模拟数据”等内部状态。
- 为证明系统可靠而写的大段辩解性文字。

客户界面统一使用业务语言：

- “资料还差 2 项”
- “方案待确认”
- “正在制作 3 项内容”
- “1 项需要确认”
- “交付包已准备好”
- “等待登记发布结果”
- “数据已回收”
- “开始下一轮优化”

帮助说明放在问号提示、侧边帮助或帮助中心中，不能占据主要工作区。

## 4. 产品信息结构

### 4.1 客户使用的页面

| 页面 | 主要用途 | 是否可以独立手动操作 |
| --- | --- | --- |
| 灵小枢首页 | 安排内容周、提交资料、查看周计划与进度、批次验收、集中补拍、下载交付包、登记发布和回收数据 | 是，完成绝大多数日常操作 |
| 企业知识 | 维护企业、产品、目标客户、品牌表达、事实依据和禁用表达 | 是 |
| 灵感中心 | 查找、筛选、收藏或手动新建灵感，并加入当前任务 | 是 |
| 素材库 | 上传、预览、分类、关联产品、替换、停用和补充素材 | 是 |
| 内容策划 | 调整栏目、选题、内容形式和发布安排 | 是 |
| 脚本库 | 新建、生成、编辑、比较、选用和管理脚本 | 是 |
| 内容创作 | 调整脚本、分镜、素材、配音、字幕、封面和成片 | 是 |
| 我的创作／交付中心 | 查看作品版本、确认成品、单项下载和整包下载 | 是 |
| 发布记录 | 登记平台、账号、链接、发布时间和实际发布版本 | 是 |
| 数据复盘 | 导入或填写发布数据，查看本轮结果和下一轮建议 | 是 |

账号授权、一键直发及批量账号管理不是 198 用户的主流程，可继续保留给灵枢内部交付团队或后续高级能力。

### 4.2 首页与专业页面的关系

- 首页是同一个内容周的总工作台，不是信息展示大屏，也不是聊天首页。
- 首页不展示 Agent 拓扑、内部协作步骤或“AI 如何工作”的说明，只展示任务进度、结果和用户下一步。
- 点击首页中的“素材”“脚本”“成片”“交付包”“发布结果”可进入相应专业页面。
- 专业页面允许完整手动操作，不得做成只读摘要或统一模板壳。
- 专业页面保存后，首页立即显示最新状态和成果。
- 首页与专业页面不能各自创建一套互不关联的任务或作品。

## 5. 首页内容任务工作台

### 5.1 首页总体布局

首页由任务主区和固定操作区组成。

任务主区首先回答客户四个问题：

1. **本周准备做什么**：重点产品、目标客户、计划数量、平台和交付时间。
2. **已经完成多少**：周计划、样片、批量成品、已确认内容和交付包分别完成多少。
3. **现在需要我做什么**：只显示一个最重要动作，例如补资料、确认代表样片、处理集中补拍或验收本批内容。
4. **本周预算是否够**：显示预算上限与已发生的真实成本；尚无可靠成本时显示“待样片校准”，不编造数字。

四个问题下方展示本周生产安排、批次内容和交付回收。三个作业包不占据客户首页，也不要求客户配置；系统根据任务自动安排，内部团队在专用页面管理。

固定操作区是灵小枢的统一操作台：桌面端常驻在任务主区右侧，移动端固定在页面底部。它始终显示当前阶段、完成比例、内容／待确认／交付数量，并且只突出一个主要动作；同时保留“编辑任务”“新建任务”和专业工作区快捷入口。用户滚动查看成果时不需要返回页面顶部寻找操作按钮。

Token 与人民币成本作为任务的次级信息保留：首页显示本轮总消耗；展开详情后可查看灵小枢、灵小图、灵小量和灵小售各自的消耗与产出，不占用首页主操作位置。

### 5.2 首页随任务状态变化

| 当前状态 | 首页主要内容 | 唯一主要动作 |
| --- | --- | --- |
| 尚未开始 | 最近内容周、可复用资料和简洁的新建入口 | 安排本周内容 |
| 草稿未完成 | 已保存内容、缺少资料和上次编辑位置 | 继续填写 |
| 可以开始 | 资料完整度、周计划摘要、预算边界和素材缺口 | 开始本周任务 |
| 样片确认 | 代表样片、会影响的批次范围和样片成本 | 确认方向或统一调整 |
| 制作中 | 批次进度、已经完成的成果、集中补拍和预计交付 | 查看最新成果 |
| 需要确认 | 本批代表作品、异常作品和修改影响范围 | 验收本批或批量退回 |
| 已交付 | 交付包内容、检查结果和版本 | 下载交付包 |
| 等待发布 | 发布说明和回传入口 | 登记发布结果 |
| 等待数据 | 已登记内容、需要回收的数据和回收方式 | 回传数据 |
| 已复盘 | 本轮结果、有效做法、问题和下一轮建议 | 创建下一轮任务 |

制作过程正常进行时不要求用户停留在页面，也不通过连续对话汇报每个小步骤。

### 5.3 新建任务窗口

新建内容周采用四步短窗口，允许保存草稿，并默认继承长期企业资料和上周已确认规则。

#### 第一步：明确本周重点

- 本周任务名称。
- 选择重点产品或业务主题。
- 本周唯一主要目标。
- 目标客户、市场和语言。
- 希望看到的交付时间。

#### 第二步：准备资料

- 从素材库选择已有图片、视频、音频和文件。
- 上传新的图片、视频、文件或文字。
- 粘贴可公开访问的参考链接。
- 选择已有企业、产品和品牌资料。
- 补充本次任务必须使用的事实、不能使用的表达和希望客户采取的下一步动作。

系统只要求影响本次交付的必要资料；可选内容收进“更多设置”。

#### 第三步：确定规模与边界

- 计划发布的平台。
- 内容形式。
- 本周计划数量。
- 目标语言和市场。
- 画面比例或其他平台要求。
- 计划发布时间或内容节奏。
- 本周生产预算、单条预算上限和重试预留。
- 数量固定，或允许系统根据素材和预算自动调整。
- 本周可以集中拍摄的时间。
- 新品、促销、禁用功能等本周特殊要求。

选择平台不代表必须连接社媒账号。

#### 第四步：核对并开始

- 用一页摘要展示本周重点、资料、生产规模、预算边界和预计交付。
- 明确列出仍缺少的必要内容。
- 告知用户系统将先形成周计划，新方向先出代表样片，素材缺口会合并为一次补拍。
- 用户点击“开始制作”后，系统自动调用三类作业能力，不再增加一页作业包选择。

## 6. 三类作业包框架

### 6.1 三类作业包的关系

一条完整内容任务由三个部分共同组成：

~~~text
行业起航包：确定方向和依据
        ↓
内容火箭包：形成可以交付的内容
        ↓
任务飞车包：安排制作、检查、交付和数据回收
~~~

它们不是让用户学习的三个工具，也不是三个价格套餐。客户看到的是本次任务采用的专业方案；内部团队维护的是方案的内容、版本和适用范围。

### 6.2 每个作业包共同具备的框架

本轮只建立以下空框架，不填入实际行业规则或模板：

1. 适合什么客户和任务。
2. 开始前需要哪些资料。
3. 根据什么信息作出选择。
4. 会完成哪些工作。
5. 最终交付哪些内容。
6. 哪些情况必须请用户确认。
7. 怎样检查质量。
8. 发布后需要回收什么数据。
9. 资料不足或结果不理想时怎样调整。
10. 当前版本、更新时间和适用期限。

### 6.3 行业起航包

**作用：** 帮助系统理解本次内容应面向谁、在哪个平台表达、重点讲什么、哪些内容不能说。

**需要的资料框架：**

- 企业所属行业和业务模式。
- 产品、服务和真实事实。
- 本次唯一主要目标。
- 目标客户及其使用场景。
- 市场、语言和计划平台。
- 客户当前的社媒基础。
- 可持续提供的素材与内容能力。
- 收到咨询后的承接能力。

**内部方案框架：**

- 行业基本知识。
- 客户如何了解、比较和选择产品。
- 常见使用场景和重点问题。
- 平台特点和近期规则。
- 可参考的优秀与失败内容。
- 账号组合和内容方向建议。
- 不能使用的表达和风险提示。
- 信息来源、最近更新时间和失效提醒。

**交付类型框架：**

- 本次行业与客户方向摘要。
- 推荐平台和内容重点。
- 推荐账号角色。
- 可优先尝试的内容机会。
- 需要避开的内容。

本版不填写任何具体行业结论、平台排名、账号数量或成功门槛。

### 6.4 内容火箭包

**作用：** 把用户素材和企业事实变成完整、可检查、可发布的社媒内容。

**需要的资料框架：**

- 已确认的企业与产品事实。
- 用户提供的图片、视频、音频、文字和参考内容。
- 目标客户、内容目的和希望客户采取的下一步动作。
- 平台、语言、内容形式和画面要求。
- 品牌表达和不能使用的说法。

**内部方案框架：**

- 选题选择方式。
- 标题和开头方式。
- 内容组织方式。
- 脚本与分镜结构。
- 素材选择和镜头安排。
- 不同平台的内容调整。
- 不同语言的表达要求。
- 资料不足时的安全处理方式。
- 事实、品牌、平台适配和完整性检查。
- 多版本比较方式。

**交付类型框架：**

- 选题和标题。
- 文案或口播稿。
- 脚本、分镜和镜头清单。
- 可发布的图片或视频内容。
- 封面、字幕和配套文字。
- 平台发布文案和行动引导。
- 需要时提供的语言版本。

具体公式、模板正文、生成规则、提示内容和交付数量全部留空，后续由内部团队逐步配置。

### 6.5 任务飞车包

**作用：** 把一次内容任务从准备、制作推进到交付，并在用户发布后完成数据回收和下一轮调整。

**需要的资料框架：**

- 本次主要目标。
- 计划平台、内容数量和交付时间。
- 当前可用的素材和人员。
- 需要用户确认的负责人。
- 发布后的数据回传方式。
- 行业起航包与内容火箭包给出的本次方案。

**内部方案框架：**

- 资料准备安排。
- 内容制作安排。
- 检查与确认安排。
- 交付包整理方式。
- 发布登记与数据回收安排。
- 制作失败或资料不足时的处理。
- 数据不完整时的补充方式。
- 下一轮复盘和调整方式。

任务飞车包中的三条工作线可以同时进行，不是必须依次等待：

- **准备与冷启动**：补资料、找参考、形成第一轮内容。
- **持续经营**：收集数据、比较内容、调整下一轮方向。
- **客户转化**：内容产生真实咨询时立即开始承接，不必等待一个经营周期结束。

本版不填写具体周期、任务数量、升级数值或结果承诺。

### 6.6 客户看到的生产摘要

客户侧不展示作业包内部结构，只展示本周生产摘要：

- 本周计划交付多少内容。
- 重点覆盖哪些产品、客户问题、语言和平台。
- 哪些内容使用现有素材，哪些需要生成产品展示，哪些用于结构变体测试。
- 是否需要一次集中补拍。
- 哪些内容要先做代表样片。
- 当前预算边界及是否需要先用样片校准成本。

只有已经通过内部检查并正式启用的作业包才能被系统调用。内部仍在编写或测试的版本直接隐藏，客户侧不能出现“待开发”卡片、内部版本号或“更换作业包”操作。

## 7. 灵小枢与子 Agent 如何完成任务

### 7.1 正常协作

| 阶段 | 灵小枢负责 | 子 Agent 负责 | 用户需要做什么 |
| --- | --- | --- | --- |
| 本周设定 | 汇总本周重点、规模、资源和预算边界 | 灵小图检查素材与内容机会；灵小量检查平台要求；需要获客时灵小售检查承接信息 | 补齐真正缺少的资料 |
| 周计划 | 形成选题圈、样片范围、生产批次和集中补拍清单 | 灵小图安排表达方式与素材；灵小量安排平台版本；灵小售按需检查行动引导 | 查看摘要，必要时调整优先级 |
| 代表样片 | 控制先小批验证再展开生产 | 灵小图完成代表样片；灵小量检查平台适配；灵小售检查获客内容的承接表达 | 新方向只确认一次整体偏好 |
| 批量生产 | 安排批次、汇总进度并隔离失败内容 | 灵小图完成主要内容生产；灵小量完成平台适配；灵小售按需检查行动引导 | 正常情况下无需操作 |
| 批次验收 | 汇总代表作品和异常作品，说明修改影响范围 | 各 Agent 完成自动检查和可自行修正的问题 | 批量确认或提交一条统一修改意见 |
| 生成交付包 | 确认所有交付项完整 | 灵小量按平台整理文件与发布资料，灵小图确认成品版本 | 预览并下载 |
| 用户发布 | 保留本次交付版本和发布入口 | 灵小量提供发布说明和回传清单 | 上传到自己的账号，并登记链接、账号和时间 |
| 数据回收 | 汇总已收到与仍缺少的数据 | 灵小量整理平台表现；灵小图比较内容差异；出现咨询时灵小售接手 | 按提示上传或填写真实数据 |
| 下一轮 | 汇总有效做法、问题和建议 | 三个子 Agent 分别给出可执行调整 | 确认是否创建下一轮任务 |

### 7.2 什么时候才打断用户

系统只在以下情况要求用户处理：

1. 缺少会直接影响内容真实性的资料。
2. 企业事实之间存在冲突，系统无法自行判断。
3. 内容可能违反品牌要求或产生商业风险。
4. 新方向的代表样片或本批最终成品需要用户确认。
5. 自动制作失败且无法自行恢复。
6. 用户发布后尚未登记实际结果。

待处理卡必须直接说明：

- 还缺什么或发现了什么问题。
- 这会影响哪项交付。
- 系统推荐怎样处理。
- 用户现在可以选择什么。

同类问题应合并处理，不能连续弹出多次确认。系统要说明一条反馈会影响哪些内容，以及是否增加成本；不能要求用户把同一句话重复填写几十次。

### 7.3 用户如何手动介入

- 首页的每个成果都提供“打开专业工作台”入口。
- 用户可以从对应步骤继续编辑，而不是重新创建整条任务。
- 用户修改素材、脚本、文案或成片后，系统以新版本继续后续工作。
- 已交付或已发布的版本保持不变，避免发布内容与系统记录不一致。
- 用户可以只退回一项成果重做，不需要整单重启。
- 用户也可以把一条意见应用到本批所有待验收内容；有例外时先排除，再批量确认。
- 手动完成的结果与自动完成的结果使用相同的确认和交付方式。

### 7.4 内容怎样被安排和生产

灵小枢先根据产品事实、客户常见问题、已有素材、参考内容、历史表现和本周资源形成“选题圈”，再为每项内容选择合适的表达方式。选题可以围绕为什么需要、怎样使用、与其他方案有何差异、客户担心什么、有哪些事实证据展开。

表达方式包括产品展示、知识问答、客户案例、场景创意和结构变体等；制作方式包括使用现有素材、生成产品画面、数字人表达、集中补拍等。两者分开安排，避免因为一种素材不足让整个内容周停住。

每个镜头在生产前都要有一份内部素材清单，至少写明：

- 需要什么画面和大致时长。
- 素材来自哪里，是否允许用于本次任务。
- 使用现有素材、生成画面还是补拍。
- 怎样判断镜头合格。
- 当前方式失败时改用什么办法。

系统自动完成素材整理、去重、选题安排、素材匹配、内容生产和基础检查。只有缺少真实产品事实或真实拍摄素材、超出预算、存在版权或合规不确定性、以及外部发布需要授权时，才要求人工处理。

### 7.5 集中补拍

素材不足时，灵小枢把同类镜头合并为一次拍摄任务，而不是逐条提醒。补拍清单向用户说明：拍什么、每段建议拍多久、怎样拍、上传后能支持哪些内容。上传后的素材自动匹配回周任务；无法确定用途的素材先回到素材库等待确认。

## 8. 交付包

### 8.1 交付包是什么

交付包不是一个只有文件名的下载按钮，而是本次任务的完整交付中心。用户在下载前可以清楚看到每个平台将获得什么、是否完整、是否已经确认。

### 8.2 交付包最低内容

每个平台的交付内容至少包括：

- 可直接发布的图片、视频或其他成品。
- 封面或首图。
- 标题、正文和行动引导。
- 话题、标签或其他平台配套文字。
- 字幕、脚本或必要的文字版本。
- 发布注意事项。
- 本次任务、适用平台和作品版本。
- 发布后需要回传的数据说明。

具体文件格式、内容数量和语言数量由后续配置的作业方案决定，本 PRD 不预设固定数值。

### 8.3 交付中心操作

- 按平台查看交付内容。
- 在线预览图片、视频和文字。
- 查看每项内容是否完整、是否已经确认。
- 单项下载。
- 按平台下载。
- 整包下载。
- 查看版本变化。
- 退回某一项修改。
- 确认本次交付。
- 进入“登记发布结果”。

如果某项内容不完整，不能把整个交付包显示为“已准备好”。

## 9. 用户发布与数据回收

### 9.1 默认发布方式

198 用户默认下载交付包后，自行上传到自己的社媒账号。系统不要求先绑定账号，也不把一键发布放在主要操作位置。

高级账号连接或辅助发布能力可由内部交付团队使用，但不影响 198 用户完成主流程。

### 9.2 发布登记

用户发布后，可在首页或发布记录页填写：

- 使用的平台。
- 实际发布账号。
- 发布链接或平台作品编号。
- 实际发布时间。
- 使用的交付版本。
- 必要的备注。

系统根据任务和作品版本自动带入已知内容，用户不需要重复填写。

一份内容发布到多个平台时，每个平台分别保留发布记录，但共同关联到原任务和作品。

### 9.3 数据回收方式

在不依赖账号连接的情况下，系统需要支持以下一种或多种方式：

- 粘贴已发布内容链接。
- 填写平台作品编号。
- 上传平台导出的表格。
- 上传数据截图。
- 手工填写关键数据。
- 后续在用户明确授权后，从已连接账号读取。

首页根据本次作业方案提示何时需要回收数据，不在本版预设固定时间点。

### 9.4 数据确认

- 回收的数据必须关联到具体任务、平台、账号、作品和版本。
- 能清楚识别的数据直接进入复盘。
- 无法确定归属或识别不完整的数据进入“待确认”。
- 不使用 0 代替尚未收到的数据。
- 不根据截图、链接或文字猜测无法证明的结果。
- 用户可以补充或修正数据，并保留修改记录。

### 9.5 数据回收后的结果

系统向用户展示：

- 哪些内容已经取得真实数据。
- 哪些内容仍在等待数据。
- 哪些表达、形式或平台表现更好。
- 哪些问题可能来自素材、内容、发布或客户承接。
- 下一轮建议保留什么、调整什么、停止什么。

播放、点赞和粉丝等数据用于判断内容表现，不自动等同于产生了真实生意。出现咨询、商机或订单时，必须由相应的真实记录支持。

## 10. 专业功能页的手动操作要求

### 10.1 企业知识

必须支持：

- 新增和编辑企业、产品、目标客户及品牌资料。
- 上传图片、视频、文件和事实依据。
- 标记必须使用和禁止使用的表达。
- 选择本次任务引用的资料。
- 查看资料被哪些任务使用。
- 资料更新后提示哪些进行中任务可能受影响。

### 10.2 灵感中心

必须支持：

- 搜索、筛选、查看和收藏灵感。
- 上传或手动新建参考内容。
- 查看内容拆解。
- 将灵感加入当前任务。
- 更换系统自动选择的灵感。
- 记录灵感来源和使用情况。

### 10.3 素材库

必须支持：

- 上传、预览、搜索、分类和筛选。
- 关联企业、产品、市场和任务。
- 编辑名称、标签和使用说明。
- 替换不可用素材。
- 停用不应继续使用的素材。
- 查看任务还缺少哪些画面或文件。
- 上传补拍内容后继续原任务。

### 10.4 内容策划

必须支持：

- 查看和调整本次内容方向。
- 新增、删除、排序和替换选题。
- 调整内容形式、平台和发布时间。
- 保存为草稿。
- 提交给灵小枢继续制作。

### 10.5 脚本库

必须支持：

- 新建、生成、编辑和复制脚本。
- 查看不同版本和修改差异。
- 选择脚本加入当前任务。
- 退回修改或确认使用。
- 按产品、平台、语言和任务查找。
- 保留已经交付或发布的脚本版本。

### 10.6 内容创作

必须支持：

- 编辑脚本、分镜和文案。
- 选择、排序和替换素材。
- 调整配音、字幕、音乐和封面。
- 预览制作结果。
- 重新制作单个环节。
- 保存草稿、比较版本和确认成品。
- 将确认结果同步到交付中心。

### 10.7 我的创作与交付中心

必须支持：

- 按任务、平台、状态和版本筛选作品。
- 预览、修改、确认和下载。
- 单项、按平台或整包导出。
- 查看内容是否已经交付、发布和回收数据。
- 从作品进入对应的发布记录和复盘。

### 10.8 发布记录与数据复盘

必须支持：

- 新增和编辑实际发布记录。
- 关联正确的任务、作品和版本。
- 上传或填写平台数据。
- 标记数据完整或待补充。
- 查看不同内容和平台的表现。
- 将复盘建议带入下一轮任务。

## 11. 内部作业方案管理窗口

该窗口只供灵枢内部产品、运营和开发团队使用，198 客户不能进入。

### 11.1 页面结构

内部“作业方案中心”包含三个区域：

1. **方案列表**：查看行业起航包、内容火箭包和任务飞车包。
2. **方案编辑**：填写方案框架和后续实际内容。
3. **客户预览**：确认客户最终会看到的方案卡、输入要求和交付内容。

### 11.2 通用编辑内容

每个作业包预留：

- 名称和一句话说明。
- 适用行业、目标、市场、平台和内容形式。
- 需要用户准备的资料。
- 要完成的工作。
- 交付内容清单。
- 质量检查要求。
- 需要用户确认的事项。
- 数据回收要求。
- 资料不足或制作失败时的处理。
- 版本、更新时间和有效期。
- 对哪些客户开放。
- 内部更新说明。

### 11.3 各作业包专属窗口

**行业起航包编辑窗口：**

- 行业与客户知识。
- 平台与账号方向。
- 内容机会和风险。
- 信息来源和更新时间。
- 策略内容预留区。

**内容火箭包编辑窗口：**

- 适用内容类型和平台。
- 输入要求。
- 选题、结构、脚本、分镜和平台改编预留区。
- 资料不足时的处理。
- 质量检查。
- 交付结构。

**任务飞车包编辑窗口：**

- 适用目标。
- 准备、经营和转化三条工作线。
- 工作节奏和确认事项。
- 失败处理。
- 数据回收和复盘。
- 交付完成标准。

本轮只创建这些窗口和字段框架的产品定义。实际方案内容、公式、模板、行业数据和判断数值全部留给后续深化。

### 11.4 方案状态

内部方案有四种状态：

- **草稿**：仍在编写。
- **内部试用**：只对内部团队开放。
- **正式可用**：可被指定客户的周任务自动调用。
- **已停用**：不能用于新任务，历史任务继续保留原版本。

只有“正式可用”的方案会被客户任务调用，但作业包内部名称、版本和规则不在客户界面展示。

| 我的创作 | 已有作品、版本、预览和下载能力 | 升级为批次交付中心，补齐批量确认、平台交付清单和整包下载 |
| 内容发布 | 已有账号连接、排期和直接发布方向 | 198 主流程改为交付包下载、发布登记和数据回传；账号直发不作为前置条件 |
| 社媒数据 | 已有连接账号后的作品与表现概览 | 增加链接、作品编号、表格、截图和手工填写等回收方式 |
| 作业方案 | 已有三类作业包的版本框架 | 客户侧自动调用，选择与管理只留在内部作业方案中心 |

### 12.1 当前最需要修正的问题

1. 现有社媒页面虽然已经恢复入口，但尚未围绕同一条内容任务真正连通。
2. 198 标准工作区中的部分页面可能只能打开界面，不能完整加载或保存真实业务内容。
3. 当前首页仍以单个内容任务为单位，不能一眼看清本周产量、批次、待办和预算。
4. 页面上仍存在解释系统原理、内部状态和开发边界的文字，不符合成熟 SaaS 产品表达。
5. 当前发布方向仍偏向账号连接和直接发布，不符合 198 用户优先领取交付包、自行发布的路径。
6. 当前数据查看主要依赖已连接账号，无法覆盖不愿绑定账号的 198 用户。
7. 当前确认更偏向逐条处理，重复内容多时会把用户变成审核员。

### 12.2 修改后的完整效果

- 用户从首页安排一个内容周，只填写本周重点、资料变化、数量、预算和特殊要求。
- 灵小枢自动形成周计划，先验证代表样片，再批量生产；首页只呈现业务进度、批次成果和必要操作。
- 用户随时可以进入专业页面手动调整，调整结果回到同一条任务。
- 素材不足时只生成一次集中补拍任务，上传后自动恢复相关内容生产。
- 用户可以批量验收或提交一条统一意见，也可以在专业页处理单项例外。
- 系统完成检查后生成完整交付包。
- 用户自行发布，不需要先连接社媒账号。
- 用户回传链接或数据，系统完成本轮复盘并准备下一轮任务。
- 内部团队可以持续完善三个作业包，客户只看到系统形成的周计划和结果。

## 13. 状态、版本与提醒

### 13.1 客户可见状态

一个内容周只使用以下业务状态：

- 草稿
- 待补充
- 周计划已形成
- 代表样片待确认
- 批量生产中
- 本批待验收
- 正在整理交付包
- 已交付
- 等待发布
- 等待数据
- 已完成复盘
- 已暂停
- 需要处理

客户不看到内部小步骤、运行编号或系统处理名称。

### 13.2 版本规则

- 素材、企业资料、脚本、成片和交付包都要保留版本。
- 用户确认后的内容才进入交付包。
- 用户修改已确认内容时，生成新版本并重新检查受影响的交付项。
- 已经发布的版本不能被后续编辑覆盖。
- 数据始终关联实际发布的作品版本。

### 13.3 提醒方式

只在以下时刻提醒用户：

- 必要资料仍缺失。
- 周计划存在必须由客户决定的优先级冲突。
- 代表样片或本批成品需要确认。
- 一次集中补拍清单已经准备好。
- 交付包已经准备好。
- 发布结果尚未登记。
- 到达本次方案设定的数据回收时间。
- 出现无法自动解决的问题。

多个提醒合并成一份待办。正常制作过程不持续发送“正在处理”类消息。

## 14. 关键页面交互要求

### 14.1 表单与上传

- 支持拖拽上传、批量上传、上传进度和失败重试。
- 清楚显示支持的文件类型与限制。
- 已上传内容可以预览、替换和移除。
- 表单自动保存，并显示最近保存时间。
- 退出未保存编辑前给出提醒。
- 必填项只在影响继续操作时提示，不在页面一开始整屏报错。

### 14.2 列表与筛选

- 内容多时使用表格或紧凑列表，不用无限堆叠大卡片。
- 支持按任务、产品、平台、语言、状态和时间筛选。
- 支持搜索和批量选择。
- 常用操作直接显示，低频操作进入更多菜单。
- 删除、停用和覆盖已有版本前必须二次确认。

### 14.3 预览与确认

- 图片、视频和文字可以在同一任务中连续预览。
- 确认前展示本次变化，不要求用户重新检查全部历史内容。
- 退回时可以直接标注需要修改的项目。
- 批量确认必须允许先排除有问题的内容。
- 下载前展示交付完整度和仍缺少的项目。

### 14.4 空状态与错误

- 没有数据时说明用户现在可以做什么，并提供一个主要按钮。
- 暂时失败时保留已经填写的内容。
- 可以重试的问题直接提供重试操作。
- 需要内部处理的问题只告诉用户当前影响和预计下一步，不展示内部错误。
- 未配置完成的作业方案不进入客户页面，因此客户不会看到空白方案卡。

## 15. 验收标准

### 15.1 首页主流程

- [ ] 用户无需进入聊天，也能从首页新建并启动社媒内容任务。
- [ ] 首页可以设置本周重点、上传或选择素材、引用企业知识、填写生产规模和预算边界。
- [ ] 首页一眼可见本周准备做什么、完成多少、需要处理什么和预算边界。
- [ ] 首页在每个状态只突出一个主要动作。
- [ ] 制作中离开页面不会丢失任务，重新登录后可继续。
- [ ] 首页可以完成代表样片确认、批次验收、交付包下载、发布登记和数据回传。
- [ ] 同一条修改意见可以作用于本批内容，不要求逐条重复填写。
- [ ] 首页保留本轮 Token 和人民币成本汇总，并可查看各 Agent 的消耗与产出。

### 15.2 三类作业包

- [ ] 三类作业包作为同一个周任务的内部组合能力，不做成三个购买套餐或客户选择入口。
- [ ] 灵小枢根据本周目标自动调用正式可用版本。
- [ ] 客户侧只显示周计划、生产安排、待处理事项和交付结果。
- [ ] 内部具有完整的方案列表、编辑、预览、版本和启停窗口。
- [ ] 本轮不写入任何实际行业知识、内容公式、模板正文、判断数值或虚构示例。
- [ ] 草稿和内部试用方案不会出现在客户侧。

### 15.3 专业功能页

- [ ] 企业知识、灵感、素材、策划、脚本、内容创作、作品交付、发布记录和数据复盘均可独立手动操作。
- [ ] 专业页面不是只读说明页，也不是四个统一摘要模板。
- [ ] 从首页打开专业页面时自动进入正确任务和内容。
- [ ] 专业页面保存后，首页立即显示相同结果。
- [ ] 自动制作与人工修改不会产生两条重复任务或两份不一致的作品。
- [ ] 用户可以重做单项成果，不必重新开始整条任务。

### 15.4 交付与发布

- [ ] 交付中心按平台展示成品、配套文字、发布说明和版本。
- [ ] 用户可以预览、单项下载、按平台下载或整包下载。
- [ ] 缺少必要文件时不能标记为交付完成。
- [ ] 198 用户不连接账号也能完成下载、发布登记和后续数据回传。
- [ ] 账号授权和一键发布不出现在 198 主流程中。
- [ ] 已发布记录与实际交付版本一致。

### 15.5 数据回收

- [ ] 支持链接、作品编号、表格、截图、手工填写中的至少一种基础回收方式，并为其他方式保留入口。
- [ ] 每条数据关联到任务、平台、账号、作品和版本。
- [ ] 无法确认的数据进入待确认，不自动猜测。
- [ ] 未收到的数据不显示为 0 或成功。
- [ ] 复盘结论可以直接创建下一轮任务并带入已经确认的资料。

### 15.6 前端专业性

- [ ] 客户页面不出现节点、服务端、接口、模型、密钥、提示词、写入方式和开发状态。
- [ ] 客户页面不展示“本页用于什么”“系统为什么这样设计”等大段解释。
- [ ] 页面使用统一的状态、按钮、表单、表格、抽屉和确认方式。
- [ ] 上传失败、保存失败、制作失败和数据识别失败都有明确恢复路径。
- [ ] 关键流程可使用键盘完成，状态和错误不只依赖颜色表达。
- [ ] 电脑端完成全部操作，移动端可完成查看、确认、下载和回传。

## 16. 实施顺序

产品实现和系统联调按以下顺序推进：

### 第一阶段：首页与统一内容任务

- 建立首页内容任务工作台。
- 完成本周设置、资料提交、生产规模、预算边界和任务恢复。
- 增加代表样片、批次验收和集中补拍入口。
- 移除客户侧的开发解释性文案。

### 第二阶段：专业页面打通

- 将企业知识、灵感、素材、脚本、创作和作品接入同一任务。
- 确保每个页面可以手动操作并同步回首页。

### 第三阶段：作业方案中心

- 建立三类作业包的内部管理窗口。
- 建立自动调用规则和内部预览，不把作业包选择暴露给客户。
- 只上线框架，不填实际方案内容。

### 第四阶段：交付包与数据回收

- 建立完整交付中心。
- 完成发布登记。
- 完成无需账号连接的数据回收入口。
- 将真实数据带回下一轮任务。

### 第五阶段：完整联调与体验验收

- 贯通从新建任务到下一轮建议的全流程。
- 分别验证自动制作和全手动操作。
- 验证不同角色、不同平台和不同中断情况下的数据一致性。
- 完成桌面端与移动端关键流程验收。

## 17. 本版已确定的产品决策

1. 198 用户默认领取交付包并自行发布，不以账号连接或一键发布为前提。
2. 首页承担整条内容任务的主要操作，专业页面承担精细手动操作。
3. 三个作业包互相配合，由灵小枢自动调用，不做成购买套餐或客户选择页。
4. 灵小枢是唯一统一入口，用户不需要选择或指挥子 Agent。
5. 灵小图负责主要内容生产；灵小量负责平台适配、交付和数据回收；灵小售只在获客内容或真实咨询出现时参与。
6. 本轮只定义三个包的框架和内部管理窗口，不填写实际内容。
7. 客户页面不显示任何开发解释、内部流程原理或未完成的方案占位。
8. 未取得真实发布结果和数据时，系统不显示虚假成功。
9. 内容运营以“周任务—代表样片—批量生产—批次验收—周复盘”为主线，不让客户逐条做重复管理。
10. 采集量、计划量、已生产量和可发布量必须分别显示。
11. 内容制作预算与投流预算分开；没有可靠成本依据时先样片校准。
