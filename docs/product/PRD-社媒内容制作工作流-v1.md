# 灵枢｜社媒内容运营与企业微信智能客服 PRD

> 版本：v2.2 编导 Agent 与实现对齐版
> 日期：2026-09-21
> 当前状态：本轮 PRD 已确认并直接进入本地实现；本轮在灵小枢（统筹 Agent）、内容 Agent、经营 Agent、客服 Agent 之间增加独立编导 Agent，按“爆款参考采集／全片分析 → 编导 Agent 生成完整导演方案 → 内容 Agent 执行成片 → 质量门 → 用户验收”完成可用成片
> 爆款公式边界：保留爆款公式库、管理员配置入口、数据模型和版本规则；本轮不录入、不导入、不预置任何爆款公式，公式库保持空。
> 本次边界：主题驱动的内容生产、按平台生成发布包、受控的浏览器辅助发布、账号内容与视频数据监控、企业微信智能客服；不包含付费投流、报价订单、批量外呼和未经授权的自动互动

## 0. 一分钟看懂产品

这版产品解决一条完整经营链路：**客户从“想讲什么主题”出发完成内容生产，再把内容安全地交付到社媒平台，持续看见真实效果，并把由内容带来的咨询接入企业微信客服。**

| 环节 | 用户得到什么 | 本版默认方式 |
| --- | --- | --- |
| 内容生产 | 完整导演方案、素材建议、成片与版本 | 编导 Agent 先产出结构、脚本、口播、字幕、镜头、音乐与节奏、素材使用／补拍和质量验收点；内容 Agent 只执行方案和必要的素材适配 |
| 发布协同 | 每个平台可直接使用的发布包 | 默认不要求客户在灵枢内登录社媒账号 |
| 内容监控 | 已发布内容、状态和可获得的视频数据 | 有正式授权时走官方接口；无授权时只监控已登记的公开内容 |
| 咨询承接 | 内容来源可追踪的企业微信客服会话 | V1 接“微信客服”，默认 AI 草稿、人工确认或接管 |

产品有两个入口，但共用同一套主题、素材、可空公式引用、导演方案、作品和版本：

- **首页数字员工｜本周内容计划**：解决一周多条内容的计划与批量生产。系统结合视频矩阵告诉用户本周做什么、还可以补充什么素材；未来只在当前租户存在正式启用的内容公式时结合公式，本轮不使用公式。
- **内容创作｜即时生成**：解决用户现在就要生成一条内容的需求。用户选择主题后，不等待周计划，也不调用周维度视频矩阵；只有存在正式启用且适用的内容公式时，系统才在后台匹配。

在内容生产子流程中，无论从哪个入口开始，用户只做三件事：**明确主题、拍摄／上传素材、验收成果。** 发布确认、账号授权和客服接管属于后续经营动作，不与这三项内容动作混在同一个页面。

~~~text
选择或确认内容主题；用户的一句话只作为创作意图，不直接进入口播或字幕
  → 系统从“正式爆款公式 → 灵感中心全片精确分析 → 企业知识安全骨架”中选择最高优先级的可用结构来源；本轮公式库为空，因此实际从全片精确分析开始匹配；连企业事实也不足时，产品精确关联素材只能解锁 `knowledge_fallback` 下的无事实宣称短片，不作为第四种结构来源
  → 编导 Agent 把结构来源、已确认企业事实和任务约束组合为可追溯的导演方案草案；只借参考结构，不复制原视频台词、品牌、人物或事实
  → 导演方案草案产出拍摄指导，对照素材库列出已有素材和可选补拍方向
  → 用户选择已有素材，或拍摄／上传可用于制作的真实素材并确认使用
  → 系统自动分析、拆段、去重、打标、归类，并只在当前任务中筛选可用镜头
  → 通常至少需要 2 个相互独立、相关且可信的有效镜头；无企业事实且视觉分析不可用时，则至少需要 2 份由当前租户明确关联到当前产品的独立真实素材；不达标则暂停制作并合并提示补拍，不删除素材库原文件
  → 用户点击一次“开始制作”
  → 编导 Agent 根据入选真实素材锁定一份完整导演方案：结构、脚本、口播、字幕、镜头计划、音乐与节奏、素材使用与补拍建议、质量验收点
  → 内容 Agent 按锁定导演方案自动完成素材编排、配音、字幕、音乐、封面、渲染和技术质检；只能做裁剪、构图、节奏对齐等必要素材适配，不自行重写脚本、口播或字幕
  → 旧制作能力被拆成后台模块，不再向用户开放旧制作流程或要求逐步操作
  → 用户只在成片完成后预览、统一反馈或确认成果
  → 生成按平台冻结版本的发布包
  → 用户自行发布、浏览器辅助发布，或在已获授权时使用官方接口
  → 回收发布凭证与视频数据
  → 内容咨询进入企业微信客服，结果反哺后续选题
~~~

客户不选择 Agent、旧技术生成路线或内容公式；客户只通过首页周计划或内容创作即时生成进入对应场景：

- **主题决定“讲什么”**，是客户唯一可见的创作入口。
- **内容公式决定“怎么讲”**，只有存在正式启用且适用的公式时才由系统自动匹配，仅管理员可以配置和启停。
- **素材决定“现在能真实展示什么”**，系统按产品、主题和画面用途自动匹配；当前阶段只给非强制拍摄建议。
- 原有“从素材生成、爆款裂变、从产品生成”不再作为三个并列入口或第二段流程，只保留为系统内部可组合的执行能力和旧数据兼容字段。

### 0.1 本轮融合后的核心判断

1. **主题与内容公式分层。** “产品、场景、工厂、定制、案例”回答讲什么；“痛点切入、对比、实证、趋势、FAQ”等回答怎么讲，不能混在同一级入口。
2. **周计划与即时生成分开。** 周计划调用视频矩阵安排多条内容；即时生成只处理当前主题，不等待周计划。
3. **两个入口共用同一底层对象。** 同一份企业事实、素材、可空公式引用、导演方案、作品和版本不能因为入口不同而复制两套。
4. **先给拍摄指导，再允许补充素材。** 系统必须说清可以拍什么、怎么拍、拍多久、支持哪条内容；当前建议不构成内容结构或启动门槛。
5. **素材上传后自动整理。** 系统完成拆段、去重、标签、产品关系建议、镜头功能和主题适配；用户主动上传时可继承已确认任务上下文，系统自动识别的关系只作候选，用户只处理无法判断或高风险事实。
6. **内容公式只在管理员侧配置。** 客户不看到公式名称、参数、版本或管理入口，也不需要手工选择公式。
7. **先验证样片，再展开批量。** 周计划中的新方向先确认代表样片；即时生成直接验收当前单条成果。
8. **不承诺必然爆款。** “爆款公式”是内部用于试验和复用的内容结构假设，不是播放量、询盘或成交保证。
9. **发布能力分层，不强迫账号登录。** 默认生成发布包；浏览器辅助发布复用客户本机已登录会话；只有客户主动授权并且平台审核通过时才启用官方发布接口。
10. **监控结果必须标明来源。** 官方接口数据、公开页面观测、浏览器辅助读取和人工补录分别标记，缺失值不能写成 0，也不能把“已下载发布包”当作“已发布”。
11. **国内抖音与 TikTok 国际版完全分开。** 抖音使用 `douyin_cn`，拥有独立凭据、权限、发布规则和指标，不复用现有 TikTok 接口。
12. **智能客服先可控、再自动。** V1 默认由 AI 生成可引用依据的回复草稿，人工确认后发送；只有低风险白名单问题可由租户 Owner 明确开启自动回复。
13. **主题不等于内容结构。** 当前阶段五类主题都不生成固定镜头顺序。常规生产至少需要 2 个经分析确认且已选择（`selected`）的独立、相关、可信镜头；同一原视频中不同的真实分镜可分别计数，同一分镜的切窗、裁剪、循环或末帧停留只算一个。仅在无公式、无灵感结构、无可核验企业事实且视觉分析不可用时，才允许使用“两份独立上传文件＋与当前产品精确关联”的无事实宣称安全短片路径。
14. **任务是唯一制作上下文。** 主题、产品、企业事实、导演方案、素材和更多设置确认后，用户只点击一次“开始制作”；后台生产编排继续处理同一个 `ContentTask`，不再创建第二个任务、重新选路线或重复上传。
15. **企业知识维护事实，不维护创作素材。** 企业、产品、目标买家、品牌表达及事实凭证以企业知识为准，其中 `Product` 是产品事实主数据；产品图片、视频和音频不在企业知识中另建上传入口。
16. **“我的素材”是唯一创作素材主数据。** 可以从素材页、内容任务或拍摄任务发起上传，但所有入口调用同一上传服务并创建或复用同一个素材对象，再关联知识库产品、主题与任务；任何页面不得保存私有副本。
17. **导演方案有明确来源顺序。** 编导 Agent 优先使用管理员已经正式发布且适用的爆款公式；没有适用公式时，使用灵感中心中已经完成“全片精确分析”的参考视频结构；两者都没有时，才按企业知识生成保守的安全骨架。如果可核验企业事实也不存在，安全骨架只能使用两份与当前产品精确关联的独立素材生成无事实宣称短片；这是 `knowledge_fallback` 的受限变体，不是新的 `director_source_type`。无论来源为何，都必须由编导 Agent 转化为完整导演方案，不允许绕过编导 Agent 直接进入内容制作。
18. **任务原文不是口播稿。** 用户填写的主题、任务名和一句具体诉求只用于识别创作目标、产品和受众，任何字段都不得直接整段送入配音或字幕。口播与字幕文本必须来自已锁定的 `DirectorPlanVersion`。
19. **创意适配归编导 Agent，素材执行归内容 Agent。** 编导 Agent 根据真实素材缩短文案、换序、删去无依据表达并生成新导演方案版本；内容 Agent 只可裁剪、缩放、重构图、转码、响度规范化和时间对齐，不得改写结构、脚本、口播、字幕文字、核心主张或 CTA。无法执行时必须退回编导 Agent 修订方案，不能在内容 Agent 内推倒重写。
20. **素材筛选不等于删除素材。** 去重、质量、相关性和内容覆盖度判断只决定当前任务使用哪些片段；未入选素材仍保留在“我的素材”，只有用户主动删除、授权撤回或保留策略到期才进入删除流程。
21. **宁可缩短，也不注水。** 素材有限时由编导 Agent 按有效镜头总量缩短导演方案中的脚本、口播和成片时长；内容 Agent 不循环片段、不长时间停留末帧、不用大段文字页冒充内容。不满足常规两镜头门槛，且也不满足“两份独立、精确产品关联素材”安全路径时，任务进入“待补素材”，不输出低质量伪成片。
22. **开始制作后默认全自动，但职责不混合。** 编导 Agent 负责生成、按素材修订并锁定导演方案；内容 Agent 负责按方案完成素材编排、配音、字幕合成、音乐、封面、渲染和技术质检。用户只处理真实性／授权／最低镜头数量硬阻塞和最终成片审批，不点击“继续制作”进入旧制作台。
23. **网上采集严格区分参考与可商用素材。** 公开网页视频默认只进入灵感参考库；只有授权证据明确允许下载、商业使用和改编的文件，才可以进入后端可商用素材库。素材文件保存到 PocketBase 后端文件字段或其对象存储，应用服务器不持久保存视频；处理只使用操作系统临时目录并在任务后清理，同时保留来源与授权证据。
24. **本轮爆款公式库必须为空。** 保留模型和管理入口，但不得通过 seed、migration、fixture、导入脚本或默认配置写入占位公式。全部真实任务使用 `formula_id = null`，按“全片精确分析结构 → 企业知识安全骨架 → 精确产品关联素材的无事实宣称安全短片”逐级降级，仍由编导 Agent 产出完整导演方案。

### 0.2 本次需要产品负责人确认的十一项决策

| 待确认决策 | 本版建议 |
| --- | --- |
| 一级主题 | 稳定主题 ID 仍是“产品与卖点、场景与解决方案、供应保障、定制与合作流程、客户案例与合作成果”五类；客户前端简化为“产品亮点、使用场景、工厂与交付／供应与交付、定制合作、客户案例”，另提供自定义入口 |
| 两个入口的边界 | 首页数字员工只做周计划与批量；内容创作只做单条即时生成 |
| 爆款公式权限 | 只在管理员后台保留录入、试跑、发布和停用能力；普通用户默认完全不显示 |
| 本轮公式数据 | 公式库、配置入口和版本机制保留，但本轮零录入、零预置，任务默认 `formula_id = null` |
| 编导与内容 Agent 边界 | 编导 Agent 独立产出并版本化完整导演方案；内容 Agent 只按方案生成视频和做必要素材适配，不自行重写脚本 |
| 客户与质量标准 | 一套专业核心能力同时服务验证期客户和高客单长期客户；套餐只控制用量、渠道和服务，不维护低质量分支 |
| 发布策略 | 发布包为所有客户默认能力；浏览器辅助发布是可选能力；官方直发仅在客户主动授权、平台许可和真实验收通过后启用 |
| 数据监控边界 | 没有账号授权时只跟踪用户登记的公开内容；需要完整账号内容和稳定指标时必须使用平台正式授权 |
| 企业微信接入 | V1 接“微信客服”API；AI 默认只生成草稿，价格、合同、投诉、功效等高风险问题强制人工接管 |
| 旧制作能力融合方式 | 用户只在原任务点击一次“开始制作”；旧三路线、脚本页、配音页、字幕页和渲染页全部拆成 Agent 后台模块，不再作为用户后续流程 |
| 产品素材归属 | 企业知识维护企业／产品／买家／品牌事实，“我的素材”统一管理所有创作素材；二者通过产品 ID 建立关联，不重复上传或复制文件 |

以上十一项已经作为本轮实现基线；前端具体改法与验收口径见第 17 节，整体实施顺序和 30／90 天计划见第 18 节。

### 0.3 Agent 角色与交接边界

| Agent | 负责范围 | 主要输入 | 必须输出 | 明确不做 |
| --- | --- | --- | --- | --- |
| 灵小枢（统筹 Agent） | 识别用户意图，创建／恢复同一 `ContentTask`，编排编导、内容、经营和客服阶段，聚合状态与异常 | 用户 Brief、任务状态、各 Agent 结果 | 阶段指令、唯一任务上下文、对用户可见的下一步 | 不撰写导演方案，不直接渲染视频，不代替经营或客服做外部动作 |
| 编导 Agent | 位于爆款参考采集／全片精确分析与内容制作之间；选用合法结构来源，将企业事实、真实素材和平台约束编排为完整导演方案 | 主题 Brief、公式（可空）、灵感全片分析（可空）、企业知识、入选素材、平台规格 | 版本化 `DirectorPlanVersion`，完整包含结构、脚本、口播、字幕、镜头计划、音乐与节奏、素材使用与补拍建议、质量验收点 | 不下载或复制无授权原视频，不生成无依据事实，不执行视频渲染 |
| 内容 Agent | 把已锁定导演方案转成可播放成片，进行必要的素材适配和技术质检 | 锁定的 `DirectorPlanVersion`、素材修订版本、输出规格 | 配音、字幕轨、剪辑时间线、音乐、封面、渲染成片、技术质检与执行报告 | 不重新选结构，不重写脚本／口播／字幕文字，不改变核心主张；方案不可执行时退回编导 Agent |
| 经营 Agent | 将已验收内容转为发布包，编排发布协同、回收凭证和指标，把效果信号反哺选题 | 已确认作品版本、渠道能力、发布凭证和指标快照 | 按平台冻结的发布包、发布状态、监控摘要和后续选题建议 | 不改写已确认作品，不在无授权时直发或抓取全账号 |
| 客服 Agent | 承接企业微信咨询，基于知识生成可引用的回复草稿，执行风险分级和人工接管 | 客户消息、来源内容、企业知识、会话上下文 | 回复草稿、引用依据、风险等级、发送／接管状态 | 不自动承诺价格、合同、功效或投诉结果，不改动内容作品 |

管理员负责爆款公式的人工录入、审核、发布和停用；编导 Agent 只消费已正式发布且对当前任务可用的公式，不自动写入、改写或发布公式。本轮公式库为空，因此编导 Agent 实际使用“全片精确分析结构 → 企业知识安全骨架 → 用户精确关联素材的无事实宣称安全短片”降级链。最后一级只在两份独立素材都有当前租户写入的精确产品关联时可用，文件名、通用标签或用户的任务文字不能解锁该路径。

## 1. 产品目标

### 1.1 核心目标

让处于商业验证期和长期运营期的企业客户，通过两种场景完成内容生产，并把同一条作品继续用于发布协同、数据监控和客户咨询承接：

1. **周计划场景**：用户确认本周主题，系统按视频矩阵形成计划；编导 Agent 按可用结构来源为每条任务生成导演方案，并将可选拍摄建议合并展示后交给内容 Agent 批量制作。
2. **即时生成场景**：用户在内容创作中直接选择一个主题，系统检查企业事实与素材，编导 Agent 生成一份完整导演方案后由内容 Agent 生成一条内容；公式库为空也能完成制作。
3. **共同动作**：在内容生产子流程中，用户只需明确主题、拍摄／上传素材、验收成果；其余选择由企业默认配置和系统推荐完成。
4. **发布与监控**：已确认作品生成按平台冻结的发布包；发布结果有凭证，视频数据有来源和同步时间。
5. **咨询承接**：发布内容可以携带可追踪的微信客服入口；新咨询进入统一客服工作台，由 AI 辅助、人工负责最终承诺。

平台、语言、比例和预算优先继承企业或任务默认值；需要调整时放入“更多设置”，不能与三项内容核心动作并列。即时生成的数量固定为 1；周计划数量由 `WeeklyPlan` 的视频矩阵和租户服务配置决定，不能以“试用版／高客单版”复制两套工作流。

### 1.2 成功标准

- 新用户无需理解“素材生成、爆款裂变、产品生成”的区别，也能开始第一条内容。
- 周计划和即时生成都只要求用户完成“主题、素材、验收”三项核心动作。
- 选择主题后，系统能够分开说明已有素材、可选拍摄建议，以及确实会阻塞制作的事实／授权要求。
- 上传素材后，系统自动完成整理，并能说明素材适合哪些主题和镜头功能。
- 任务原文不会直接成为口播或字幕；每条成片都能追溯到结构来源、完整导演方案版本和实际使用镜头。
- 内容 Agent 每次生产都必须收到一个可解析的已锁定方案交接（`directorPlanId + version + lineageHash + handoffHash`）；没有导演方案不得进入配音、字幕、剪辑或渲染。成品另外保存完整 `directorPlanReference` 用于追溯。
- 在脚本、口播、字幕文字和镜头意图上，内容 Agent 的实际执行结果与导演方案一致；只允许可审计的技术性素材适配。
- 当前任务只选取质量、相关性和覆盖度合格的素材；未入选素材仍留在“我的素材”，不被系统批量删除。
- 素材有限时系统自动缩短内容；不足 2 个独立、相关且可信的有效镜头，且不满足第 6.5.2 节“2 份独立、精确产品关联素材”安全特例时，明确进入“待补素材”，不靠循环片段、末帧停留或大段文字页凑成片。
- 即时生成不依赖周计划；有活跃周计划时，可由用户明确选择是否关联，不得静默改变原计划数量和预算。
- 每条作品记录使用的主题、素材版本、企业事实版本和导演方案版本；本轮公式库为空，公式 ID／版本保持空。
- 用户离开页面后任务可以继续，回来后能从原位置继续处理。
- 客户界面不出现公式配置、模型、提示词、内部评分或空白开发占位。
- 发布包与作品版本一一对应；没有平台回执、公开链接或经审核的人工凭证时，不能显示“已发布”。
- 抖音与 TikTok 国际版在连接、发布、状态和数据中始终是两个平台。
- 内容监控展示数据来源、覆盖范围、最近成功同步时间和授权状态，未知指标保持“暂无数据”。
- 企业微信真实入站消息能够完成验签、解密、去重、建会话、生成草稿、人工发送或接管的完整链路。
- 所有客户共用租户隔离、角色权限、审计、幂等、重试、告警和可观测性标准。

## 3. 前端设计原则

本节是内部产品要求，不能作为解释文案直接展示给客户。

### 3.1 专业 SaaS 交互原则

1. **先完成任务，再解释功能。** 页面首先告诉用户现在能做什么，不用大段文字讲系统原理。
2. **一个状态只有一个主要动作。** 例如“确认主题”“查看拍摄清单”“上传素材”“确认成品”“下载交付包”。
3. **高频信息直接展示，低频设置逐步展开。** 首次创建任务不让用户面对几十个字段。
4. **默认给出专业推荐。** 用户可以调整，但不要求从空白开始搭建流程。
5. **同一对象只有一份。** 首页、素材库、脚本库、创作台和交付中心看到的是同一任务及同一作品版本。
6. **修改有记录，交付可追溯。** 人工修改生成新版本，不覆盖已经确认或交付的版本。
7. **错误就地解决。** 明确说明缺什么、影响什么、下一步怎么处理，不把用户带进长对话。
8. **页面密度专业但不拥挤。** 使用清晰的表单、表格、抽屉、筛选、状态和操作区，不用大量装饰性卡片堆叠。
9. **操作可恢复。** 支持自动保存、离开提醒、失败重试、返回上一步和继续未完成任务。
10. **电脑与移动端都能完成关键操作。** 复杂编辑以电脑端为主，移动端至少可以查看主题、拍摄清单、确认和下载。

### 3.2 客户界面文案红线

客户界面禁止出现以下类型的文字：

- “AI 工作流对应页面”“固定节点”“服务端工作图”等原理说明。
- “写入托管”“接口未接通”“不会绕过权限”等开发或安全实现说明。
- 运行编号、任务编号、模型名称、提示词、密钥、数据表和内部错误堆栈。
- “本页用于展示”“开发预留”“待开发”“模拟数据”等内部状态。
- 为证明系统可靠而写的大段辩解性文字。

客户界面统一使用业务语言：

- “主题待确认”
- “还缺 3 个镜头”
- “素材已整理，可以开始制作”
- “正在制作 3 项内容”
- “1 项需要确认”
- “交付包已准备好”

帮助说明放在问号提示、侧边帮助或帮助中心中，不能占据主要工作区。

客户不需要先连接社媒账号才能完成内容生产。默认路径是生成发布包；浏览器辅助发布、平台正式授权和账号级监控按租户需要启用，并统一进入“发布与渠道中心”，不再散落为多套独立入口。

### 4.2 首页与专业页面的关系

- 首页只承担周计划，不再同时承担即时生成。
- 内容创作是即时生成的主入口，不要求用户先创建内容周。
- 两个入口必须写入同一个内容任务模型，并共用企业事实、素材、主题、可选公式、导演方案、作品和版本。
- 有活跃周计划时，即时生成完成后可提示“关联到本周计划”；只有用户确认后才关联，不能自动改变周计划数量、预算或批次。
- 从首页或内容创作打开素材、导演方案版本和成片时，必须携带正确的产品、主题和任务上下文；专业后台页面只是同一任务的内部视图，不得要求客户重新建单或继续制作。
- 授权的专业编辑动作必须继续写回同一任务和新版本，不得创建一份与首页脱节的作品副本。
- 客户界面可以在一句引导语和任务抽屉中显示“编导 Agent 定方案 → 内容 Agent 生视频”的两段业务接力，用于解释当前进度；不展示技术拓扑图、内部状态码、运行编号、内容公式名称／评分、哈希或“AI 如何工作”的长说明。
- 作品确认后，系统从该固定版本派生 `PublicationPackage`；之后的发布、监控和咨询归因都引用同一 `content_id + content_version`。
- 发布和客服页面只展示客户需要处理的结果与异常，连接密钥、游标、队列、内部错误和模型判断留在管理与审计层。

## 5. 双场景入口与用户操作

### 5.1 首页数字员工：本周内容计划

首页解决“这一周应该做哪些内容”，不承担单条即时创作的全部编辑操作。

首页首先回答三个问题：

1. **本周做什么**：按产品、目标买家和内容目标形成主题组合与内容数量。
2. **还可以准备什么素材**：把多条内容的非强制拍摄建议，以及事实／授权或正式公式明确要求的项目，分别合并展示。
3. **现在要我做什么**：确认主题、关联真实素材、处理确实会阻塞的问题或验收成果，任何时刻只突出一个主要动作。

周计划使用视频矩阵安排多条内容。只有存在对当前租户正式启用且适用的内容公式时，系统才在后台匹配；没有正式公式时仍可按主题、企业事实和真实素材生成。用户不逐条选择公式，也不逐条重新填写平台、语言、比例和品牌资料。

~~~text
确认本周产品与目标
  → 系统形成主题组合和内容计划
  → 按“正式公式 → 全片精确分析的灵感结构 → 企业知识安全骨架”选择结构来源；本轮公式库为空，从灵感结构开始；事实不足时再在安全骨架中使用精确产品关联素材的受限降级
  → 编导 Agent 生成导演方案草案与非强制拍摄建议，并汇总为集中准备清单
  → 用户选择已有素材，或拍摄／上传真实素材并确认使用
  → 系统自动整理并回填各内容任务
  → 每条内容通过常规两镜头门槛，或通过“两份独立且精确关联当前产品的真实素材”安全特例后，编导 Agent 锁定完整导演方案并交给内容 Agent 制作
  → 新方向先出代表样片
  → 用户确认后批量生产
  → 用户按批次验收
~~~

### 5.2 内容创作：即时生成

内容创作解决“我现在就要做一条内容”，不要求先进入首页建立周计划。

即时生成首页不再展示“素材、爆款裂变、产品”三个并列入口，改为五张使用通俗文案的主题卡和一个自定义入口；稳定 `theme_id` 不变：

1. 产品亮点（原“产品与卖点”）。
2. 使用场景（原“场景与解决方案”）。
3. 工厂与交付；企业资料明确没有自有工厂时显示为“供应与交付”（原“工厂／企业与供应保障”）。
4. 定制合作（原“定制与合作流程”）。
5. 客户案例（原“客户案例与合作成果”）。
6. 自定义主题：用户用一句话描述想讲的内容，系统必须归入最接近的一级主题；无法归类时标记为待确认，不能悄悄创建新的一级分类。

用户选择主题后，只补充三个必要信息：**本次产品、目标买家、具体想讲的内容**。第三项只是创作意图，不是口播稿，也不能直接作为字幕。目标市场、语言、平台、比例、CTA 和预算默认继承企业设置，放入“更多设置”。

~~~text
选择主题
  → 选择产品并填写一句具体诉求
  → 系统按“正式公式 → 全片精确分析的灵感结构 → 企业知识安全骨架”选择结构来源；本轮实际从灵感结构开始，事实不足时在安全骨架中使用精确产品关联素材的受限降级，任何路径都不直接朗读用户原文
  → 编导 Agent 按结构来源与企业事实生成导演方案草案和非强制拍摄指导
  → 关联企业资料与真实素材，按任务去重并筛选有效镜头
  → 不足常规 2 镜头门槛，且不满足第 6.5.2 节的两文件精确产品关联安全特例时，合并提示补拍；原素材仍保留在素材库
  → 用户点击一次“开始制作”
  → 编导 Agent 根据已选素材完成创意适配，生成并锁定包含结构、脚本、口播、字幕、镜头、音乐节奏、素材使用／补拍和质量验收点的导演方案
  → 内容 Agent 只按导演方案自动完成配音、字幕合成、素材编排、渲染与技术质检，不自行重写脚本
  → 页面只显示后台制作状态，不打开旧制作台，也不要求用户逐步确认脚本、配音或字幕
  → 用户预览、退回或确认
~~~

即时生成不调用周维度视频矩阵。有活跃周计划时，作品完成后可以由用户明确选择“加入本周计划”，但不能自动改变原周计划数量、批次或预算。

### 5.3 两个入口共用的三项用户动作

| 用户动作 | 用户看到什么 | 系统自动完成什么 |
| --- | --- | --- |
| 明确主题 | 五个通俗主题、推荐的具体选题、产品和目标买家 | 继承企业资料；按结构来源优先级交给编导 Agent，具体诉求只作任务 Brief，不直接作口播 |
| 拍摄／上传素材 | 已有素材、可选拍摄方向、怎么拍、建议时长和示例 | 素材统一进入“我的素材”，自动拆段、去重、打标并关联任务；产品关系和主题适配按已确认上下文或候选规则处理 |
| 验收成果 | 代表样片或单条成品、改动范围、版本和下载入口 | 完成基础质检、保留版本、将反馈应用到受影响内容并整理交付包 |

### 5.4 状态与唯一主要动作

| 当前状态 | 页面主要内容 | 唯一主要动作 |
| --- | --- | --- |
| 尚未开始 | 周计划或五个主题入口 | 安排本周内容／立即创作 |
| 主题待确认 | 推荐主题、具体选题与目标买家 | 确认主题 |
| 待关联素材 | 当前候选素材、入选原因和非强制拍摄建议 | 从“我的素材”选择／上传素材；达到常规两镜头门槛，或满足严格受限的两份独立、精确产品关联素材路径后确认使用 |
| 待补素材 | 已有关联素材、未通过原因和一份合并补拍清单 | 补充缺少的对象／动作，或从“我的素材”改选其他素材 |
| 可以制作 | 导演方案摘要、使用素材和预计结果 | 开始制作 |
| 制作中 | 一枚紧凑机器人状态入口；点击后在右侧抽屉查看多任务明细 | 查看任务详情 |
| 需要处理 | 只显示真实性、授权、文件损坏或外部服务不可恢复的问题；保留全部已完成结果 | 查看问题／补充必要资料 |
| 待验收 | 代表样片或单条成品及修改影响 | 确认或退回修改 |
| 正在整理交付包 | 已确认作品和交付整理进度 | 查看交付进度 |
| 已暂停 | 暂停原因、已保留内容和恢复影响 | 恢复任务 |
| 已交付 | 成品、配套文字、版本和完整度 | 下载交付包 |

制作正常进行时不要求用户停留在页面，也不通过连续对话汇报内部小步骤。导演方案生成／修订、配音、字幕合成、剪辑和质检失败应在对应 Agent 边界内自动重试或降级；内容 Agent 遇到创意不可执行时退回编导 Agent，可恢复的内部失败不得显示成“请继续完成脚本”，更不得把用户送入旧制作流程。

## 6. 主题、爆款公式与素材的底层模型

本文所称“爆款公式”是管理员内部名称和产品入口名称；数据模型统一使用 `content_formula`。它表示可试验、可版本化的内容结构，不代表结果保证。客户侧统一称“内容结构”或“创作方案”。

### 6.1 四类核心对象的职责

| 对象 | 回答的问题 | 谁可以操作 | 是否对客户显示 |
| --- | --- | --- | --- |
| 主题 | 这条内容讲什么 | 客户选择，系统推荐 | 显示 |
| 爆款公式／内容公式 | 这条内容如何被完整导演 | 管理员配置，编导 Agent 匹配和实例化；本轮为空 | 默认不显示 |
| 素材 | 这条内容能够真实展示什么 | 用户上传，系统整理和匹配 | 显示可用结果与缺口 |
| 导演方案 | 当前这条视频究竟怎么说、怎么拍、怎么剪和如何验收 | 编导 Agent 生成并版本化，内容 Agent 只读执行 | 客户可查看业务摘要与成果，内部字段不显示 |

一条作品必须记录 `theme_id`、`product_id + product_version_id`、所用 `material_id + revision_id`、实际片段、`director_source_type`、完整 `directorPlanReference` 和作品版本；当前实现不使用独立的 `director_plan_version_id`，而是用 `directorPlanId + version` 定位版本，再校验血缘、事实快照、素材快照和记录哈希。兼容期可将现有 `script_source_type` 映射为 `director_source_type`。使用正式公式时记录 `formula_id + formula_version`，使用灵感结构时记录对应的参考分析 ID／版本；使用产品关联降级时，`director_source_type` 仍为 `knowledge_fallback`，关联依据单独写入事实／来源快照。主题不能代替事实，公式或参考结构都不能突破素材和事实边界。

### 6.2 V1 一级主题

一级主题按“内容对象”划分，而不是按钩子或叙事技巧划分。制造业与美妆 B2B 工厂使用同一套一级主题，行业差异下沉到子主题、素材模板、事实约束和内容公式中。

| 前端主题名 | 内部主题含义 | 用户容易理解的问题 | 可包含的子主题 | 制造业／美妆示例 | 优先需要的素材 |
| --- | --- | --- | --- | --- | --- |
| 产品亮点 | 产品与卖点 | 这个产品好在哪里、适合谁 | 产品线、成分／材质、规格、性能、产品细节、适配对象 | 高粘液体泵的结构特点／精华质地与包材适配 | 产品多角度、细节、演示、规格依据、包装 |
| 使用场景 | 场景与解决方案 | 什么时候、在哪里、怎样使用 | 目标人群、使用环境、工况、使用环节、渠道陈列、季节场景 | 高温产线稳定运行／油皮夏季使用场景 | 完整使用动作、环境、人物／设备、过程和可见结果 |
| 工厂与交付；无自有工厂时为“供应与交付” | 工厂／企业与供应保障 | 能不能稳定生产、质检和交付 | 厂区、研发、生产、设备、质检、仓储、交付、团队 | 精密加工质检链／灌装、微生物检查与发货 | 工厂、产线、工序、质检、仓储物流及经确认的能力依据 |
| 定制合作 | 定制与合作流程 | 从需求到样品、量产怎样合作 | OEM／ODM、配方／材质、规格、包装、打样、报价准备、合作步骤 | 来图到首样／品牌 Brief 到配方、包材和首样 | 可选项、样品、色卡／包材、流程、人员及经确认的 MOQ／交期 |
| 客户案例 | 客户案例与合作成果 | 谁合作过、过程和结果怎样 | 真实客户问题、采用方案、执行过程、交付结果、评价、复购 | 客户产线改善案例／品牌从打样到量产复购 | 已授权背景、过程、结果、评价、订单／出货及合作证明 |

“买家痛点、产品实证、选型对比、趋势热点、FAQ、幕后揭秘、清单、前后对比”等不再作为一级主题，统一作为内容公式中的叙事角度，可以与任一一级主题组合。

认证、检测、参数、功效、产能、交期和客户授权等属于跨主题的事实证据，不属于主题，也不属于叙事角度；系统只能在企业知识存在已确认依据时使用。

主题边界按“买家看完后首先要回答什么问题”裁决：产品好在哪里、什么时候怎样用、能否稳定交付、如何定制合作、谁合作过且结果如何。每条内容只能有一个主主题，可以附加多个二级标签，不能用多主主题回避选择。

V1 优先服务制造业企业和美妆 OEM／ODM／Private Label B2B 工厂。第三类使用稳定的 `theme_id=supplier_capability`：有自有工厂时显示“工厂与交付”，没有自有工厂时显示“供应与交付”。后者只使用可验证的研发、供应商管理、质检和履约证据，不暗示其拥有工厂。

五个主题可以提供以下拍摄方向作为非强制建议，用于帮助用户准备素材；它们不是固定结构。能阻止制作的只有真实性、授权、必要事实或本章统一素材质量门，不能由主题名称自行推导更多必拍项。常规门槛为至少 2 个独立、相关且可信的有效镜头；严格受限的无事实宣称路径以 2 份独立、精确关联当前产品的真实素材代替视觉相关性判断：

| 主题 | 可选拍摄方向 |
| --- | --- |
| 产品亮点 | 产品全景 → 关键细节 → 使用／性能演示 → 已确认依据 |
| 使用场景 | 环境／对象 → 具体问题 → 使用动作 → 可见结果／适用边界 |
| 工厂与交付／供应与交付 | 场地／团队 → 关键工序 → 质检节点 → 仓储／交付动作 |
| 定制合作 | 客户需求 → 可选项 → 打样 → 确认 → 量产／交付 |
| 客户案例 | 授权背景 → 客户问题 → 解决过程 → 已确认结果 → 授权证据 |

V1 不增加第六个固定主题。无法归类的真实选题先进入“自定义主题／待确认”，连续四周出现稳定需求后再决定是否扩充一级分类。

### 6.3 主题选择后的必要输入

客户选择主题后，页面首先只要求三个输入：

- 本次产品或产品组。
- 目标买家，例如品牌方、采购、渠道、研发或工厂负责人。
- 一句话具体诉求。它只用于说明“想让谁看到什么”，不得直接作为最终脚本、口播或字幕。

核心主张及事实依据、目标市场、可选 CTA 意图、合规限制和禁用表达默认从企业知识继承。只有缺失、相互冲突或属于高风险主张时，系统才合并成一次待办要求用户确认；不能把这些字段重新变成每次创作都要填写的第二套长表单。本轮零公式路径只保留 CTA 意图，不将其直接写入口播或字幕，也不自动编造。

### 6.4 爆款公式的定义

内容公式是编导 Agent 可实例化的完整导演配置，不是只包含钩子的简短提示词，也不是“必然爆款”的承诺。每个可发布公式版本必须独立完整地定义生成一条视频所需的全部内容：

- 公式名称、内部说明、适用主题、行业、平台、内容形式、时长、语言和目标买家。
- **结构与时间轴**：Hook、信息推进、证据位置、转折、CTA、每段目标时长和节奏点。
- **完整脚本**：每段要传达的信息、可替换事实槽位、证据引用和禁用表达，不得只保存“让模型写一段”类空提示。
- **口播**：逐段可直接用于配音的文本、角色／音色要求、语速、语气、重音、停顿和发音备注。
- **字幕**：与口播句段对应的字幕文本、分行、关键词强调、安全区、屏幕文字与时间对齐规则。
- **镜头计划**：镜头序号、起止时间、画面意图、景别／运镜／构图、镜头功能、素材条件、转场和对应口播／字幕。
- **音乐与节奏**：可商用授权类型、风格／情绪、节拍和剪辑点、起止与淡入淡出、口播期间压低规则；无合法音乐时明确允许无配乐。
- **素材使用与补拍**：每个镜头优先使用的 `material_id + revision_id + clip_id`、可替换条件、裁剪／构图约束、缺口、补拍对象、动作、方向和建议时长。
- **质量验收点**：事实与画面一致性、授权、真实镜头数、口播可听、字幕同步、音乐响度、时长、比例、编码、封面和平台安全区。
- 素材／事实不足时的降级、补拍、停止条件，自动匹配条件、优先级和适用客户。
- 版本、状态、创建人、审核人、更新时间和用于校验不可变内容的哈希。

本轮只实现上述字段、管理入口、校验和版本机制，**不创建任何公式记录**。不得为了跑通流程而填入“默认公式”“安全公式”或示例公式。

### 6.5 内容公式匹配规则

系统按以下顺序匹配，不要求客户选择：

1. 过滤非“正式可用”、非当前租户白名单“灰度可用”、无权限或不适用于当前平台／形式的公式。
2. 按主题、行业、产品、目标买家、语言和时长筛选。
3. 只有缺少不可补救的事实、授权或合规依据时，才硬性排除对应公式。
4. 缺少但可以补拍的画面不能导致公式被排除；系统保留该公式，并把缺口生成拍摄任务。
5. 在可执行公式中，综合事实完整度、补拍成本、交付时间和历史验收稳定性排序。
6. 记录匹配原因、未选原因和匹配结果；没有适用公式时记录 `no_formula`，最终公式及版本允许为空。

缺少硬证据时不得选择“实证型”结构；只有具备授权案例和可核实结果时才能使用案例型结构。公式匹配不得改变用户已经确认的主主题。如现有正式公式不适用，编导 Agent 直接在当前主题下完成无公式导演方案并提供非强制拍摄建议，不能套用占位公式；如建议更换主主题，必须由用户确认，并生成新的主题 Brief 和导演方案版本。

公式、爆款参考或安全骨架一旦选定，编导 Agent 必须把它与企业事实、任务约束和已选素材融合为 `DirectorPlanVersion`，保存来源、公式／参考版本（可空）、主题、事实快照、素材快照、创建时间、`lineage_hash` 和整条版本记录的 `record_hash`。因素材时长、可见画面或平台限制发生的删减、换序和措辞调整必须由编导 Agent 创建新方案版本和差异；内容 Agent 不得创建脚本适配版本或覆盖已锁定方案。

本轮不是“允许无公式”，而是明确按**零公式生产**验收：任务不绑定内置占位公式，先尝试使用完成全片精确分析的灵感结构；仍无可用结构时按可核验企业知识生成安全骨架；连企业知识也无法提供产品事实时，只能在至少两份独立真实素材都被当前租户精确关联到任务产品的情况下，生成不扩展任何产品事实的安全短片。所有路径都经编导 Agent 生成完整导演方案。

#### 6.5.1 导演方案结构来源优先级

导演方案不是把用户输入的任务文字包装成视频。编导 Agent 必须按下列顺序寻找“怎么讲、怎么拍、怎么剪”的依据，找到第一个满足权限、适用性和事实安全要求的来源后再形成完整导演方案：

| 优先级 | 结构来源 | 可以使用什么 | 不能使用什么 |
| --- | --- | --- | --- |
| 1 | 管理员正式发布且适用的爆款公式 | 公式的结构节点、节奏、镜头功能、口播模板和降级规则 | 草稿、内部试用、越权灰度或不适用公式 |
| 2 | 灵感中心完成“全片精确分析”的参考视频 | 经授权保存的结构分析：开头作用、信息推进、镜头功能、节奏和结尾动作 | 原视频台词、品牌名、人物身份、案例、数据、产品事实、原音频或未经许可的画面 |
| 3 | 企业知识安全骨架 | 已确认的产品事实、适用场景、企业能力、禁用表达，以及当前任务真实素材能证明的内容 | 不能被知识或画面证明的卖点、功效、认证、产能、客户与商业结果 |

产品精确关联素材不是第四种结构来源。它是 `knowledge_fallback` 下的受限证据降级：视觉分析不可用时，精确产品关联只能证明“当前租户确认这份素材用于当前产品”，不能证明画面中实际出现什么。有可核验企业事实时，安全骨架仍只能使用被快照的事实；没有可核验事实时，则只能生成无事实宣称短片。

用户的一句话具体诉求只用于确定主题、受众和内容目标，不能进入上述优先级，也不能直接成为脚本、口播或字幕。每次生成必须保存 `director_source_type`、来源 ID／版本、企业事实快照和采用原因；使用灵感结构时同时保存“只借结构”的检查结果；使用精确产品关联降级时保存 `user_product_association` 来源、关联依据和置信度，且所有未经视觉识别的片段保持画面置信度 `0` 与 `needsReview=true`。

#### 6.5.2 没有公式和可用灵感时

如果没有适用的正式公式，也没有完成全片精确分析且可合法使用的灵感结构，编导 Agent 先按可核验企业知识生成保守导演方案：

1. 开头直接展示当前产品或真实场景，不编造夸张钩子。
2. 主体只保留 1—2 个已确认事实，并且每个事实都能被当前入选镜头或企业知识凭证支持。
3. 没有可见结果时，只说明产品、动作、流程或适用边界，不写“效果显著”“客户都在用”等推断。
4. 本轮零公式路径不把用户填写的 CTA 直接放入口播或字幕，也不默认补“联系我们”。只有未来已正式发布的受管公式显式定义 CTA 槽位和适用规则时，才能将经确认的 CTA 写入方案；否则省略。
5. 按有效镜头总时长缩短脚本和成片，不为满足预设时长重复镜头、停留末帧或堆叠文字页。

视觉分析不可用时，当前租户写入的精确产品关联可作为“这两份文件允许用于当前产品任务”的保守依据。如果企业知识有可核验产品事实，口播与字幕仍只能使用那些已进入 `fact_snapshot` 的事实；产品关联不能代替事实凭证。

若企业知识也没有可核验产品事实，系统不伪造事实，而是检查素材来源中的产品关联。只有至少 2 份彼此独立的上传文件都与任务的 `product_ref` 精确一致时，才能产出只展示真实关联素材、不扩展产品事实的安全短片。每份文件只计一个证据镜头；即使视频分析服务不可用，也必须保留画面置信度 `0` 和“待复核”标记，不得将产品关联冒充为视觉识别结果。

以下任一情况进入“待补素材”，不能继续渲染：常规路径少于 2 个相互独立、相关且可信的有效镜头，且不满足上述“2 份独立文件＋精确产品关联”特例；镜头无法支持主题的核心对象；画面损坏、模糊到无法辨认；素材授权不清；唯一可讲内容涉及功效、认证、客户案例、工厂所有权等高风险事实但缺少凭证。其余缺口由编导 Agent 创建缩短版导演方案解决，不把写脚本交给用户，也不交给内容 Agent 临场改写。

#### 6.5.3 导演方案数据模型

`DirectorPlan` 是 `ContentTask` 下的稳定逻辑对象，`DirectorPlanVersion` 是编导 Agent 每次锁定或阻塞时追加的不可变版本。当前任务的 `director_plan` 只是供页面和兼容逻辑读取的“最新版投影”，可被新版替换；它不是历史真值，不能代替 `starter_social_director_plan_versions` 中的不可变记录。一次内容 Agent 执行只能消费一个已锁定版本；实现中以 `tenant_id + director_plan_id + plan_version` 定位，并校验方案血缘、事实快照、素材快照和整条记录的哈希。持久化字段与方案内容最低要求如下：

| 字段组 | 必须内容 |
| --- | --- |
| 版本集合顶层字段 | `tenant_id`、`schema_version`、`task_id`、`director_plan_id`、`plan_version`、`previous_version`、`lineage_hash`、`status`、`lock_status`、`plan`、`fact_snapshot`、`fact_snapshot_hash`、`material_snapshot`、`material_snapshot_hash`、`record_hash`、`created_by`、`created_at` |
| `plan` 内的归属与版本 | `directorPlanId`、`version`、`revision.previousVersion`、`status`、`lockStatus`、`lockedAt`、`createdBy`、`createdAt`、`lineageHash`；`lockedAt` 不是版本集合顶层字段 |
| 来源追溯 | `script_source.kind`（对应业务层 `director_source_type`）、`formula_id/formula_version` 可空、灵感分析记录与置信度可空、基线版本和事实来源 |
| 任务约束 | 主题、目标买家、核心主张、CTA、平台、语言、比例、目标时长、品牌语气、合规／禁用表达 |
| 结构与脚本 | 结构节点、逐段时间、完整脚本、事实引用、Hook、证据表达、转折与 CTA |
| 口播与字幕 | 最终口播文本及音色／语速／语气／停顿，字幕文本、句段对应、分行、强调、安全区和对齐规则 |
| 镜头计划 | 镜头序号、起止时间、画面意图、景别／运镜／构图、对应口播和字幕、优先素材片段、替换条件、转场 |
| 音乐与节奏 | 授权要求、情绪／风格、节拍／剪辑点、起止、淡入淡出、压低与目标响度 |
| 素材与补拍 | 输入素材快照、逐镜头素材使用、允许的裁剪／重构图范围、缺口、可选／必需补拍建议和阻塞原因 |
| 验收点 | 画面与事实、授权、口播、字幕、音乐、音画时长、真实镜头数、平台规格、封面和不得出现项 |
| 不可变证据 | `fact_snapshot + fact_snapshot_hash`、`material_snapshot + material_snapshot_hash`、`record_hash`；成片保存由 `directorPlanId`、`version`、`lineageHash`、`factSnapshotHash`、`materialSnapshotHash`、`recordHash` 组成的 `directorPlanReference` |

**状态分层不得混用：**

- 不可变 `DirectorPlanVersion` 记录使用两个字段：`status = ready | blocked`，`lock_status = locked | blocked`。两对有效组合为 `ready + locked` 和 `blocked + blocked`；只有 `status=ready && lock_status=locked`，且所有质量门都不是 `blocked` 时，才能交给内容 Agent。阻塞版本可留作审计，但绝不能渲染。
- `draft`、`director_revision_required` 是 `ContentTask`／生产编排阶段，不是不可变版本的 `status`；`superseded` 用于被新成片替代的作品，不回写旧导演方案版本。
- 方案首次锁定或因口播超时、用户退回等原因修订时，编导 Agent 以递增 `version` 和 `previous_version` 追加新记录。同一版本的完全相同重试幂等返回旧记录；同一版本但内容或哈希不同时拒绝覆盖。
- 内容 Agent 若发现方案与已锁定素材无法对齐，只能提交带镜头号、原因和证据的 `director_revision_required`；编导 Agent 追加新版本并锁定后才能继续。

### 6.6 客户可见与管理员可见边界

客户可以看到：

- 主题和具体选题。
- 系统建议的内容方向。
- 已有素材、可选拍摄建议，以及确实需要处理的事实／授权问题。
- 导演方案的业务摘要，包括脚本、口播、字幕、分镜、素材建议、成片和质量问题。

客户默认看不到：

- “爆款公式”管理入口、公式 ID、版本、评分和匹配权重。
- Prompt、模型、内部测试数据和管理员备注。
- 未发布、内部试用或已停用的公式。

客户侧如需解释，只使用“内容结构”或“创作方案”，不使用暗示效果保证的措辞。

### 6.7 产品事实、创作素材与任务引用

产品信息和产品素材有关联，但不是同一个对象。为避免同一产品在企业知识、任务页和制作台重复上传，必须按以下唯一主数据规则实现：

| 对象 | 唯一来源 | 保存什么 | 明确不保存什么 |
| --- | --- | --- | --- |
| 底层文件 `FileBlob` | PocketBase 文件字段或其配置的对象存储 | 租户边界内的不可变文件、SHA-256、类型、大小和存储键，用于业务对象安全复用 | 产品归属、主题或任务状态；不得保存到应用服务器 `data/media` 等运行目录 |
| 产品 `Product`／`ProductVersion` | 企业知识 | 名称、SKU／型号、类目、规格、卖点、成分／材质、适用场景、资质、禁用表达及事实版本 | 产品图片、视频、音频的第二份文件 |
| 创作素材 `MaterialAsset`／`MaterialRevision` | “我的素材” | 同一语义素材、图片／视频／音频修订、授权状态、来源、文件版本和可用状态 | 产品事实的另一套副本 |
| 产品素材关系 `MaterialProductLink` | “我的素材” | 素材与唯一主产品、多个相关产品或“企业通用”范围的关系，含来源、置信度和人工确认状态 | 复制出的产品素材文件 |
| 素材分析 `MaterialClip`／`MaterialThemeFit` | “我的素材”分析结果 | 指向 `revision_id + analysis_version` 的片段、主题、场景、画面用途和置信度 | 产品归属；主题标签不能代替产品关系 |
| 任务引用 `TaskMaterialRef` | 原 `ContentTask` | 任务引用的 `material_id + revision_id`、片段、用途、来源，以及 `candidate / selected / used / removed` 状态 | 任务私有文件或制作台副本 |
| 事实凭证 `KnowledgeEvidence` | 企业知识 | 检测报告、资质、规格书、合同等支撑产品事实的文件及审核状态 | 默认可直接用于剪辑的创作素材 |

具体规则如下：

1. 企业知识的产品详情页取消图片、视频、音频“产品素材上传”。页面只显示已关联素材的缩略图和数量，并提供“去我的素材管理”；产品封面也从“我的素材”选择，不复制文件。
2. “我的素材”是所有创作素材的唯一主数据与管理工作区，但允许从内容任务和拍摄任务发起带上下文的快捷上传。所有入口调用同一上传服务并先创建或复用 `MaterialAsset`；只有从内容任务或拍摄任务发起时才额外创建 `TaskMaterialRef`，素材库独立上传只建立素材及可选产品关系。退出任务后素材仍可在“我的素材”找到，不得创建临时任务文件或空任务引用。
3. 从产品详情进入“我的素材”时自动带入产品筛选和预选关系；从任务上传时自动带入当前 `product_id`、`theme_id` 和 `task_id`。用户在已经明确选择产品的任务中主动上传并确认使用时，产品关系与任务引用可直接记为已确认／`selected`；系统自动识别或复用推荐只能先建 `candidate`。启动制作时，常规路径按拆分后的独立有效分镜计数，第 6.5.2 节安全特例按独立上传文件计数。任务主题只是本次使用上下文，不能自动写成全局已确认的主题适配。
4. 每个有效素材最多一个主产品，相关产品可以有多个，同一 `material_id + product_id` 只能有一条有效关系，关系类型变更使用更新／审计记录而不是新增重复行。`scope=enterprise` 时主产品为空，可以保留相关产品建议但不表示素材归属于该产品；既没有产品关系也未明确为企业通用时进入“待确认”。产品关系与主题适配是两条独立关系，例如一段多产品合拍视频可关联多个产品，同时适合多个主题。
5. 同一租户内 `SHA-256` 精确命中，且素材语义、原始出处／权利来源与授权范围一致时才自动复用现有 `MaterialAsset`；这里的“来源”不是上传页面或任务入口。元数据冲突时要求用户确认复用关系或新建逻辑素材，但底层 `FileBlob` 不重复。上传请求使用租户级幂等键防止并发重复。感知指纹只标记“疑似重复”并交用户确认，因为裁剪、字幕和授权可能不同。跨租户不得建立逻辑复用关系，也不得向任一租户泄露“其他租户已存在此文件”的信号。
6. 事实凭证与创作素材分开管理。确需把知识凭证用于画面时，用户在“我的素材”选择“引用知识凭证”，系统创建 `MaterialAsset(source_evidence_id=...)` 并复用同一 `FileBlob`，同时补齐授权与用途确认；停用素材不影响知识凭证访问。
7. `TaskMaterialRef` 的 `candidate` 不计入启动条件；`selected` 可在制作前移除；成片实际消费后改为 `used`，只能标记“不用于后续版本”，历史引用不能删除。取消产品关联只影响 `MaterialProductLink`，产品归档不删除素材。
8. 未被产品、任务或作品引用的 `MaterialAsset` 可进入回收站，即使它通过 `source_evidence_id` 来自知识凭证；删除逻辑素材只移除该 `MaterialAsset` 对 `FileBlob` 的引用，不影响原 `KnowledgeEvidence`。已被任务或作品引用的素材普通删除等于停用。因授权或隐私必须撤回时走受控清除：删除可识别文件、保留最小审计墓碑，并把受影响任务和作品标记为“来源素材已撤回”。只有当 `MaterialAsset` 与 `KnowledgeEvidence` 对 `FileBlob` 的引用计数都为 0 且满足保留策略时，才能物理删除底层文件。
9. 替换文件只允许用于同一主体、同一产品语义的重编码或质量升级，并创建新的 `MaterialRevision`；主体或产品已经改变时必须新建 `MaterialAsset`。`MaterialClip`、主题适配和 AI 识别结果必须指向 `revision_id + analysis_version`，新修订重新分析，不能沿用旧画面结论。
10. 开始制作后输入快照不可变。产品事实或素材更新时，用户选择“使用新版本”必须创建新的 production run 和输入快照，由编导 Agent 生成相应的新 `DirectorPlanVersion`，再生成新作品版本；原运行、原导演方案、原素材引用和原产物继续保留，不能在运行中原地替换版本。

### 6.8 网上采集视频的双库与存储边界

网上可观看的视频不等于可商用素材。采集美妆 B2B 行业内容时，必须分成两类对象：

| 库 | 保存内容 | 能否进入成片 | 最低要求 |
| --- | --- | --- | --- |
| 灵感参考库 `InspirationReference` | 来源链接、标题、作者／账号、平台、发布时间、封面，以及全片精确分析得到的结构、节奏和镜头功能 | 否；只能借鉴分析后的结构 | 来源页面可合法访问；遵守平台条款与抓取限制；不下载、转存或改编无许可视频 |
| 可商用素材库 `MaterialAsset` | 可以直接剪辑的原始视频／图片／音频及其修订 | 是，经过任务筛选后才可用 | 有明确证据同时允许下载、商业使用和改编；授权范围覆盖当前租户、地区、渠道和使用期限 |

每个外部记录必须保存 `source_url`、平台、作者／权利人、采集时间和来源快照摘要。进入可商用素材库时还必须保存 `license_type`、授权链接或文件、允许用途、地区、期限、授权证据哈希和审核人；证据缺失、含糊或过期时自动降级为“仅供参考”，不得下载到后端或参与剪辑。

美妆 B2B 可商用素材库第一批目标为 **30 条有明确下载、商业使用和改编许可的种子视频**；每一条都必须先完成授权审核才能进入“我的素材”。灵感参考库的首期展示容量目标为 **约 50 条参考记录**，其中没有商用改编许可的内容只保存来源链接、封面、元数据和结构分析，不保存原视频文件。两个数字分别是“可剪辑种子素材目标”和“灵感参考容量”，不能混为一项，也不能为了凑数降低授权标准。

用户所谓“放在后端数据库里”在技术上拆为两部分：PocketBase 集合保存素材元数据、产品／主题关系、来源和授权证据；视频二进制保存到 PocketBase 后端文件字段或其配置的对象存储，并通过数据库记录引用。**应用服务器不持久保存任何视频文件**，`data/media`、`data/social-content-sources`、项目目录或容器可写层都不能作为正式素材源或缓存。下载、探测、转码和渲染只允许使用操作系统临时目录；单次任务结束时立即清理，异常退出遗留文件由定时清理任务按短保留期删除，任何作品都不能依赖临时路径继续播放或下载。

## 7. 从主题到成片的统一工作流

### 7.1 统一内容任务

周计划使用父子结构，不能把一周多条内容塞进一条只有一个主题和公式的记录：

- `WeeklyPlan`：一周计划的父对象，保存本周产品、目标、矩阵、批次、集中素材准备和总体进度。
- `ContentTask(mode=weekly)`：周计划下的单条内容；每条只允许一个主主题，正式匹配爆款公式后再绑定一个公式版本。
- `ContentTask(mode=instant)`：独立单条即时内容，不依赖 `WeeklyPlan`。

两种 `ContentTask` 共用产品及其事实版本、目标买家、主题、`DirectorPlan / DirectorPlanVersion`、`TaskMaterialRef`、`ProductionRun`、质检、作品版本和交付包；已匹配爆款公式时也共用对应公式版本。即时内容后续关联周计划时，只增加明确关系，不复制素材、导演方案或作品，也不改变原任务的主主题。主题任务页、内部生产记录、脚本库、“我的素材”和交付中心都指向同一任务，不得重新建单。

### 7.2 生成顺序

| 阶段 | 系统完成 | 用户完成 | 阶段产物 |
| --- | --- | --- | --- |
| 1. 明确主题 | 根据企业资料推荐一级主题和具体选题；用户原文只作为任务 Brief | 选择／确认主题，补一句具体诉求 | 主题 Brief，不是口播稿 |
| 2. 采集与分析结构来源 | 依次查找正式爆款公式、完成全片精确分析的灵感结构、企业知识安全骨架；本轮从第二项开始 | 无需选择公式或抄写参考视频 | 结构来源与匹配记录 |
| 3. 编导 Agent 准备方案草案 | 将所选结构与已确认企业事实融合，准备结构、脚本、口播、字幕、镜头、音乐节奏、素材／补拍和验收点；只借参考结构 | 无需写脚本；只在主题或事实本身有误时返回修改 | 任务上的脚本基线／方案草案投影与拍摄建议；此时尚未创建不可变 `DirectorPlanVersion` |
| 4. 关联并筛选素材 | 在“我的素材”中按导演方案的镜头意图匹配，完成拆段、精确去重、质量／相关性／覆盖度判断 | 选择已有素材，或从任务快捷上传 | `TaskMaterialRef`、入选镜头与素材建议；未入选素材仍在素材库 |
| 5. 开始制作 | 校验已确认事实与素材门槛：常规路径至少 2 个独立、相关、可信且 `selected` 的有效镜头；无事实宣称安全路径至少 2 份独立且精确关联当前产品的真实素材。通过后冻结本次输入 | 只点击一次“开始制作”；不足时按一份合并清单补拍 | 制作运行与输入快照 |
| 6. 编导 Agent 锁定导演方案 | 根据冻结的素材与平台约束完成创意适配，检查全部必需字段并追加不可变版本 | 无需逐项确认 | `DirectorPlanVersion(status=ready, lock_status=locked)`、前版本引用与完整性哈希 |
| 7. 内容 Agent 执行成片 | 按锁定方案完成配音、字幕合成、素材编排、封面、音乐、渲染与技术质检；只做必要素材适配 | 无需进入制作台；可离开页面 | 真实 MP4、执行报告与质检记录 |
| 8. 验收成果 | 说明导演方案版本、成片版本、问题和反馈影响范围 | 确认、退回或给出一次修改意见 | 已确认作品或新修改版本 |

#### 7.2.1 后台制作编排与旧能力拆解

旧制作工作台不再是用户必须进入的后续页面。任务达到最低制作条件后，用户只点击一次“开始制作”；后台生产编排器自动读取 `task_id`、主题、产品及事实版本、目标买家、素材及版本、结构来源、平台、语言和更多设置，先调用编导 Agent 锁定 `DirectorPlanVersion`，再将该版本交给内容 Agent 推进到成片。旧制作台可继续作为开发调试／高级人工修复工具，但不能成为普通任务的默认下一步，也不能通过“继续制作”暴露给客户。

旧页面能力按以下方式融合：

| 原有能力 | 新的位置 | 用户是否选择 |
| --- | --- | --- |
| 从素材生成 | 作为真实素材编排、剪辑与镜头组合引擎 | 否，由系统按任务素材调用 |
| 爆款裂变／参考爆款 | 作为已授权参考分析能力，输出交给编导 Agent 做结构迁移；本轮公式库为空 | 否，参考内容仅作为可选结构来源 |
| 从产品生成 | 作为编导 Agent 的企业知识安全骨架来源；不得用生成画面冒充真实工厂、功效或案例 | 否，由事实、授权和租户能力决定 |
| 配音、字幕、音乐、封面、渲染 | 作为内容 Agent 按锁定导演方案执行的后台制作模块 | 否；用户只验收成片或对成片提出修改 |

`material / clone / product` 仅用于后台编排、审计和旧草稿迁移，不是互斥三选一，也不是客户请求参数。同一条成片可以组合多个能力，但所有导演方案、素材引用、运行记录和成果必须写回原 `ContentTask`，不得创建第二个内容任务或制作台私有副本。

当前实现把“执行交接”和“成品追溯”分成两层，不得混为一个虚构字段：

- 编导 Agent 交给内容 Agent 的 `SocialDirectorContentHandoff` 包含 `directorPlanId`、`planVersion`、`lockStatus=locked`、`lineageHash`、锁定的镜头／口播／字幕／配乐／封面／输出规格、允许／禁止动作以及 `handoffHash`。缺任一项、方案未锁定或交接哈希不匹配时拒绝制作，内容 Agent 不得自行补写脚本。
- 完成的成品保存 `directorPlanReference`，包含 `directorPlanId`、`version`、`lineageHash`、`factSnapshotHash`、`materialSnapshotHash`、`recordHash`。入库成品前必须能在同一租户、同一任务下反解到唯一不可变版本；任一哈希不一致则停止入库。

页面主按钮随任务状态变化：

| 状态 | 主按钮 | 行为 |
| --- | --- | --- |
| 可以制作 | 开始制作 | 幂等创建一次后台制作运行，留在原任务页即可 |
| 制作中 | 查看任务详情 | 打开右侧任务抽屉，不打开旧制作台、不重复启动 |
| 需要处理 | 查看问题 | 只定位真实性、授权、文件损坏或不可自动恢复的问题；处理后后台自动续跑 |
| 待验收 | 验收成果 | 直接进入成片预览、反馈与确认 |

正常任务必须全自动在后台继续，用户无需停留。结构、脚本、口播文本、字幕文字、镜头计划和音乐节奏由编导 Agent 负责；素材执行、配音、字幕合成、音乐混音、镜头编排和渲染由内容 Agent 负责，都不能生成用户待办。只有真实性、授权、文件不可读或持续外部服务故障可以打断用户；高级人工修复由运营／交付人员在后台工具处理，客户界面不出现“Studio”“制作路线”“重新生成脚本”或内部路由等技术文案。

#### 7.2.2 素材筛选、有限素材与补拍门槛

系统不能把用户上传的全部文件直接顺序拼接，也不能为了让视频看起来更长而重复镜头。每次制作先在任务范围内完成筛选：

1. **去重**：SHA-256 相同文件直接复用；感知相似、同一原视频重叠时间段和视觉几乎相同的片段只保留质量最好的一份，它们不能重复计入有效镜头数量。
2. **质量**：检查可读性、清晰度、抖动、曝光、遮挡、画面方向、有效时长和是否存在大面积水印；质量太差的片段本次不使用，但不从素材库删除。
3. **相关性**：常规路径根据可追溯的画面分析判断画面是否包含当前产品、动作、场景或企业对象；仅文件名、标签或用户任务文字相似不能算相关。视觉分析不可用时，只有上传来源数据中与当前任务 `product_ref` 完全一致的用户产品关联，才能解锁无事实宣称安全路径；该关联不等于画面识别。
4. **覆盖度**：把导演方案中每个可见表达映射到真实镜头。没有镜头或企业凭证支持的句子由编导 Agent 在方案锁定前删除或改写，内容 Agent 不能临场改台词，也不能让配音描述画面里不存在的产品、工厂、效果或客户案例。
5. **任务级选择**：筛选结果只更新 `TaskMaterialRef` 的 `candidate / selected / used / removed` 状态。未入选素材继续保存在“我的素材”，也可以供其他任务使用；系统不得批量删除用户素材。

通过上述筛选后，常规路径至少需要 **2 个相互独立、相关且可信的有效镜头**。两个镜头可以来自同一原视频中不同时间段和不同真实分镜；同一分镜的裁切、放大、变速、切窗、循环或末帧停留仍只算一个。在无企业事实且视觉分析不可用的安全特例中，必须是 **2 份独立上传文件**，同一文件被拆成多个片段也只算一份证据。单张图片或只有一个有效片段／一份关联文件不能直接交付成片，任务进入“待补素材”，一次性告诉用户还缺什么对象或动作。

素材刚好达到最低门槛时，由编导 Agent 创建短版导演方案：按实际有效时长缩短脚本、口播和成片，只保留一个主题和最有依据的 1—2 个信息点。内容 Agent 严格禁止循环片段、长时间停留末帧、连续使用同一画面的不同裁切冒充多个镜头，或用大段文字页填满时间。只有导演方案明确要求解释流程时才使用简短信息页，且信息页不能作为真实事实镜头计数。

只有租户明确允许、并且产品外观有可验证锚点时，才可生成补充产品画面；AI 生成画面必须明确标识且不能作为工厂、功效、认证、客户案例或商业结果的证据，也不能替代最低 2 个真实镜头。

#### 7.2.3 导演方案执行、配音、字幕、配乐与质量门

开始制作后，创意内容先由编导 Agent 写入并锁定导演方案，内容 Agent 只按该方案自动执行，用户只审核最终结果：

- **口播文案**：由编导 Agent 产出并保存在已锁定 `DirectorPlanVersion` 中；内容 Agent 只读取并送入配音，不直接朗读任务名称、主题名称或用户的一句话具体诉求，也不自行改词。
- **配音**：内容 Agent 按方案指定的语言、音色要求、语速、语气和停顿使用已授权音色；失败时只能按方案的备用音色规则重试，不能用静音成片冒充完成。
- **字幕**：字幕文字和分行由编导 Agent 写入方案；内容 Agent 只按实际音频对齐时间，检查错字、遮挡、安全区和画面边缘，不得生成新句子或改写原句。
- **配乐**：内容 Agent 按方案指定的授权、风格、节奏、剪辑点和响度执行；只用允许商业使用的音乐，无合规音乐时宁可按方案的无配乐降级执行，也不能使用来源不明音频。
- **编排与渲染**：内容 Agent 按导演方案的镜头序号、素材映射、转场和时间轴执行；允许在约束内裁剪、缩放、重构图、转码和对齐，不允许重排叙事结构或改变镜头意图。封面、比例和编码按目标平台输出。

成片必须同时通过导演方案指定的内容验收点和通用技术质量门才可进入“待验收”：视频可解码且非黑屏，真实镜头数达标，素材授权有效，画面与方案相关，所有事实有依据，口播完整可听，字幕与口播同步且不溢出，配乐不盖过人声，音画总时长一致，无循环／末帧凑时长，目标平台编码和比例合格。内容 Agent 先在不改变导演方案的前提下自动修复并重渲染；若需改变脚本、口播、字幕文字或镜头意图，标记 `director_revision_required` 并退回编导 Agent。重试后仍失败时进入内部处理，不能把不可播放或明显不合常理的视频交给客户验收。

### 7.3 灵感大屏“我的素材”自动整理

所有用户上传、内容任务快捷上传、拍摄任务上传和**有明确商用改编授权**的导入文件，都先创建或复用“我的素材”中的 `MaterialAsset`，再通过关系表关联产品、主题和任务。无下载／商用／改编许可的网上视频只进入灵感参考库，不得进入“我的素材”。企业知识与后台生产模块不得再创建另一份产品素材。系统在后台自动完成：

1. 基础检查：文件可读、时长、分辨率、比例、重复素材和授权范围。
2. 视频拆段：识别连续镜头和可独立复用的片段，不只给整个文件一个标签。
3. 内容识别：识别可见产品、包装、人物、动作、环境、工厂环节和画面质量。
4. 业务归类：建立可修正的产品关系、一级主题适配、镜头功能、适用场景和任务来源；产品关系与主题标签分开保存。
5. 使用判断：按当前任务计算去重、质量、相关性、覆盖度和授权状态，标记可直接使用、需要裁剪、可补充、待确认或不可使用；本次不使用不等于删除素材。
6. 可选公式适配：只有存在对当前租户正式启用的公式时，才计算素材可满足的公式位置；无公式时该字段为空。

客户默认看到四种业务视图，而不是复杂文件夹：

- **可直接使用**：可以立即进入当前主题制作。
- **适合的主题**：按五个一级主题查看可复用素材。
- **可补充**：可以让当前周计划或即时任务效果更好的拍摄建议；只有真实性、授权或正式公式明确要求时才另标“必须处理”。
- **待确认**：产品归属、授权、事实或用途无法可靠判断的素材。

系统标签和产品关系允许用户修正，但不得要求用户逐条手工分类。一个素材可以关联一个主产品、多个相关产品、多个主题、公式和任务，或明确标记为“企业通用”；不因第一次使用而被锁死。

产品详情页只显示关系带来的素材缩略图、数量和“去我的素材管理”。用户从这里跳转时，“我的素材”自动按该产品筛选；新增上传仍由“我的素材”完成。任务页上传成功后必须同时在“我的素材”可见，刷新或进入任何任务视图仍引用同一个 `material_id + revision_id`。

AI 对画面的识别不能自动证明工厂所有权、认证、产能、功效、客户关系或商业结果。涉及这些高风险事实时，必须继续引用企业知识中的已确认依据。

### 7.4 素材建议与正式公式要求

本轮爆款公式库明确为空，编导 Agent 只创建非强制的 `material_suggestion`，保存来源任务、导演方案版本、目标主题、对象、动作、环境、方向、建议时长、匹配片段、置信度和判断原因。它用于帮助用户拍得更好，不能变成内容结构或“全部拍齐才能制作”的门槛。

只有未来经单独产品决策由管理员正式录入、试跑并发布某个公式后，公式明确声明的素材要求才创建 `material_requirement`，并额外保存来源公式节点、公式版本、必需性和降级规则。该未来能力不是本轮公式录入授权。

素材上传并完成拆段后，系统逐项更新建议或要求：

1. 系统匹配到的片段先建立 `candidate` 引用；用户主动选择／上传并确认使用后才转为 `selected`。高置信只影响推荐排序，不能代替用户对产品归属和使用授权的确认。
2. 低置信，或涉及授权、功效、认证、客户案例等高风险内容时，合并为一次用户确认，不能逐条弹窗，也不能计入启动条件。
3. 开始基础制作前必须通过第 6.5.2 和 7.2.2 节定义的统一素材门：常规路径至少 2 个相互独立、相关、可信且 `selected` 的真实镜头；无事实宣称安全特例至少 2 份独立且与当前产品精确关联的真实上传文件。未满足普通 `material_suggestion` 不阻塞，但未通过上述任一最低质量门时进入“待补素材”。
4. 素材不适用时标明原因并更新建议状态，不把“画面不理想”误写成“缺少必填内容”。
5. 没有正式公式时，`formula_id`、`formula_version` 和 `material_requirement` 均可为空，界面不显示“必拍”“必须满足”或“降级结构”。

### 7.5 拍摄任务

拍摄任务有两种来源：

- **前置积累**：周计划根据主题矩阵，以及存在时的正式内容公式，生成一周可集中准备的非强制素材清单；上传后进入“我的素材”，可被本周和后续任务复用。
- **任务内补拍**：编导 Agent 在导演方案中发现画面可以改善时，为当前任务生成可选拍摄建议；只有事实、授权或已发布公式明确要求时才标记为必须处理。

每个拍摄任务都必须保留产品、主题、来源计划／任务和目标画面用途；公式版本和公式节点允许为空。前置积累也不能变成无来源的通用拍摄清单。

每项任务必须说明：

- 拍什么对象和动作。
- 建议景别、方向和时长。
- 哪些内容会使用这段素材。
- 最低合格标准和常见错误。
- 可以用已有素材替代还是仅建议补拍；“必须补拍”只能来自真实性、授权或正式公式的明确要求。

周计划把相同画面方向合并为“集中素材建议”和“必要要求”两个区域；即时生成只显示当前内容的建议与真实阻塞项。上传后系统按上述规则自动关联或集中请求确认；如需改变脚本、口播、字幕或镜头意图，必须由编导 Agent 生成新导演方案版本。

### 7.6 什么时候打断用户

系统只在以下情况要求用户处理：

1. 缺少会直接影响内容真实性的资料或画面。
2. 企业事实之间存在冲突，系统无法自行判断。
3. 素材授权、功效、认证、客户案例或商业主张存在风险。
4. 当前任务既不满足常规两镜头门槛，也不满足两份独立、精确产品关联素材的安全特例，需要补拍或补充已有素材。
5. 新方向的代表样片、即时成片或最终成果需要确认。
6. 自动制作多次重试后仍失败，并且确实需要用户更换损坏文件或调整外部授权才能恢复。

以下情况不得打断客户：编导 Agent 内部修订方案、口播与字幕方案生成、内容 Agent 素材裁切、达到适用最低素材门后的普通素材缺口、音乐执行、封面、渲染重试或基础质检。系统先在对应 Agent 边界内自动缩短、降级、退回编导修订或重试；确实无法恢复时进入内部运营待办，并在客户侧仅显示“生成遇到问题，我们正在处理”，不出现“请完成脚本”“继续剪辑”或跳转旧制作台。两类最低素材门都未通过时不属于“普通素材偏少”，必须合并提示补拍后再继续。

待处理卡必须直接说明缺什么、影响什么、建议怎么处理以及用户现在可以选择什么。同类问题合并处理，不能连续弹出多次确认。

### 7.7 用户如何修改

- 用户从当前步骤继续编辑，不重新创建任务。
- 制作开始前修改素材、脚本或文案由编导 Agent 更新导演方案草稿；制作开始后凡是改变产品事实、脚本、口播、字幕、镜头意图或素材输入，都生成新 `DirectorPlanVersion` 和新的 production run／输入快照，不覆盖原运行与已确认版本。
- 只调整已锁定导演方案明确允许的非创意执行参数，例如输出码率、封装、容器或同一文字内容的字幕时轴对齐时，可在不改变冻结输入的前提下重做对应产物并生成新的输出版本；旧产物继续保留。任何口播文字、字幕文字、配音风格、音乐节奏、封面意图或镜头叙事变更，都必须由编导 Agent 生成新 `DirectorPlanVersion`。
- 用户可以只退回一项成果，也可以把一条意见应用到当前批次。
- 主题改变时形成新的导演方案版本；如未来有正式适用公式则重新匹配，本轮仍按无公式路径生成，旧主题版本继保留。
- 手动编辑和系统自动生成使用同一套版本、质检、确认和交付规则。

## 8. 交付包

### 8.1 交付包是什么

交付包不是一个只有文件名的下载按钮，而是本次任务的完整交付中心。用户在下载前可以清楚看到每个平台将获得什么、是否完整、是否已经确认。

交付包与发布包是两个对象：

| 对象 | 用途 | 生成条件 | 是否可继续变化 |
| --- | --- | --- | --- |
| `DeliveryPackage` | 汇总本次任务全部成品、导演方案摘要、脚本、字幕和说明 | 内容任务完成验收 | 用户修改作品后可生成新版本 |
| `PublicationPackage` | 把一条已确认作品适配为某个平台／账号可直接发布的冻结版本 | 选定平台，完成平台规则检查 | 已发起发布后不可原地覆盖，只能创建新版本 |

### 8.2 交付包最低内容

每个平台的交付内容至少包括：

- 可直接发布的图片、视频或其他成品。
- 封面或首图。
- 标题、正文和行动引导。
- 话题、标签或其他平台配套文字。
- 首评、替代文本、推荐发布时间和内容来源追踪参数；平台不支持的字段不生成。
- 字幕、脚本或必要的文字版本。
- 平台规格检查结果、发布注意事项和逐步操作说明。
- 本次任务、适用平台、目标账号（如已选择）、作品版本、导演方案版本、文件哈希和发布包版本。
- 可选的企业微信客服链接或二维码；只在可验证追踪参数存在时记录来源。

即时生成每个 `ContentTask` 固定交付 1 条内容；周计划数量由 `WeeklyPlan` 的视频矩阵和客户权益决定。实际匹配的正式内容公式只影响单条内容结构、素材要求和交付组件，不决定周内容数量。

系统内部必须记录主题、产品事实版本、素材修订、`director_source_type` 以及可解析到不可变导演方案的 `directorPlanReference`（方案 ID／版本、血缘哈希、事实快照哈希、素材快照哈希和记录哈希）；只有实际匹配正式公式时才记录 `formula_id + formula_version` 供审计。公式元数据不写入客户交付包，也不通过客户接口返回。

### 8.3 交付中心操作

- 按平台查看交付内容。
- 在线预览图片、视频和文字。
- 查看每项内容是否完整、是否已经确认。
- 单项下载。
- 按平台下载。
- 整包下载。
- 查看版本变化。
- 退回某一项修改。
- 确认本次交付。
- 从已确认作品为抖音或其他平台生成独立发布包。
- 下载发布包、发起浏览器辅助发布，或在已有正式授权时选择官方接口发布。
- 发布后提交公开链接或平台内容 ID，进入凭证核验与数据监控。

如果某项内容不完整，不能把整个交付包显示为“已准备好”。

下载、打开或发起发布包都不等于发布成功。只有取得平台回执、公开链接／内容 ID，或通过人工复核的发布凭证后，状态才可以进入“已发布”；结果不明时进入“待对账”，不得自动重复发布。

## 9. 社媒渠道、发布与内容监控

这一部分的目标不是把所有平台都做成“账号登录后一键直发”，而是用一套渠道模型支持三种独立能力：**发布包、浏览器辅助发布、官方接口连接**。客户可以只用其中一种；内容生产不以账号连接为前置条件。

### 9.1 三种发布方式

| 方式 | 适用场景 | 用户动作 | 系统责任 | 主要限制 |
| --- | --- | --- | --- | --- |
| 发布包（默认） | 所有客户、所有已适配平台 | 下载后在平台发布，再回填链接或内容 ID | 冻结媒体、封面、文案、标签、CTA、检查项、上传步骤和版本哈希 | 不能自动证明已经发布 |
| 浏览器辅助发布（可选） | 客户电脑已有登录会话，希望少做复制上传 | 用户发起任务、处理登录／验证并在发布前最终确认 | 在本机打开目标页面、填表、上传、做规格检查并回传步骤凭证 | 平台页面变化和风控会影响稳定性，不允许绕过验证 |
| 官方接口（按需） | 客户愿意授权，且应用已经取得平台权限 | 管理员连接账号并确认发布范围 | 通过官方 API 发布、查状态、同步账号内容和指标 | 受应用审核、Scope、配额、账号类型和平台政策限制 |

三种方式不是必须依次经过的状态。客户可以长期只用发布包；浏览器辅助发布也不自动获得账号监控权限；需要稳定、完整的账号内容和视频数据时，应单独完成官方授权。

本版不建设“在灵枢输入社媒用户名和密码”的登录页。确需官方授权时，由管理员在集成设置中发起平台 OAuth／官方授权，客户只在平台自己的页面登录和确认，灵枢接收授权结果而不接触其登录凭据。

### 9.2 统一渠道适配器

前后端只识别统一 `ChannelAdapter`，不能继续为每个平台在页面和路由中各写一套判断。

| `channel_id` | 平台 | 说明 |
| --- | --- | --- |
| `douyin_cn` | 国内抖音 | 新增适配器；独立凭据、授权、接口、发布规则和数据字典 |
| `tiktok_global` | TikTok 国际版 | 承接现有 `tiktok` 能力；旧 ID 仅作兼容别名，不与抖音共用 Token |
| `instagram` | Instagram | 现有能力经统一适配器收束 |
| `facebook` | Facebook | 现有能力经统一适配器收束 |
| `youtube` | YouTube | 现有能力经统一适配器收束 |

每个适配器返回能力清单，至少包括：

- `publication_package`：是否可生成发布包。
- `assisted_browser_publish`：是否有经过验收的浏览器辅助流程。
- `official_publish`：当前租户、应用、账号和 Scope 是否允许官方直发。
- `content_list`：是否可以读取账号作品列表。
- `content_metrics`：是否可以读取单条内容指标。
- `account_metrics`：是否可以读取账号级指标。
- `webhook_or_status_poll`：发布状态来自回调还是轮询。

适配器统一提供 `validateArtifact`、`buildPublicationPackage`、`startAssistedPublish`、`publishOfficially`、`getPublishStatus`、`listContent`、`getContentMetrics` 和 `normalizeProviderResult`。某个平台不支持某项能力时返回明确的 `unsupported`，前端隐藏或禁用该动作，不能展示一个无法完成的按钮。

### 9.3 国内抖音接口

国内抖音作为独立平台接入，不调用 TikTok 国际版域名、应用或 Token。目标能力如下：

| 能力 | 抖音正式接口 | 产品使用方式 |
| --- | --- | --- |
| 上传并创建视频 | 当前服务端代发能力对应 `video.create.bind`，须单独申请 | 仅在灵枢应用通过能力审核、客户主动授权且页面明确提示代用户发布时启用；创建成功后仍要等待平台审核 |
| 读取账号视频 | 由应用类型、经营关系、账号资质、Token 类型和获批 Scope 共同决定 | 只同步当前授权实际允许读取的作品；不能把“已授权”直接等同于完整视频列表 |
| 读取视频数据 | 对应获批的视频数据 Scope | 只读取平台允许返回的字段与时间范围；私密、部分可见或已删除内容不宣称可监控 |
| 用户数据 | 对应用户数据权限 | 只在产品确有账号级指标需要且已取得独立权限时启用 |

抖音 V1 交付顺序为：

1. 先上线 `douyin_cn` 发布包、平台规格校验、发布结果登记和公开链接监控。
2. 再上线经过真实账号验收的浏览器辅助发布，V1 在最终发布按钮前交还用户确认。
3. 同步准备官方应用、OAuth `state` 校验、实际授权 Scope 落库、单账号刷新锁、撤权／重授权、Token 轮换、内容／数据接口和发布状态对账；能力矩阵按“应用类型 × Scope × Token 类型 × 账号资质”计算，权限获批后按租户开启。
4. 官方直发每次都必须由用户明确发起或由已批准的计划触发，保存操作者、作品版本、目标账号、请求幂等键、平台回执和最终状态。

### 9.4 发布包与发布凭证

`PublicationPackage` 至少保存：`tenant_id`、`content_id`、`content_version`、`channel_id`、可选 `target_account_id`、媒体与文案清单、规格检查结果、内容哈希、来源追踪参数、生成时间和状态。

客户可见状态统一为：**准备中 → 可发布 → 等待发布确认 → 核验中 → 已发布／待对账／失败／已失效**。

- “可发布”只表示包内文件完整，不表示平台已经接收。
- “已发布”必须绑定 `external_content_id`、公开 URL、平台回执或经人工复核的证据。
- 平台结果未知时进入“待对账”，同一幂等键不得自动重发，避免重复发布。
- 作品、文案或目标平台规则变化后创建新包；已经发起发布的包不能原地覆盖。
- 每次发布尝试记录开始人、方式、账号、内容哈希、步骤、结果、错误类别和可重试性。

### 9.5 浏览器辅助发布技术方案

“浏览器辅助发布”指在**客户自己的浏览器和已登录会话**中减少重复操作，不是从服务端接管账号，也不是规避官方发布限制。

~~~text
用户在灵枢点击“浏览器辅助发布”
  → 服务端生成短时、一次性的签名任务
  → 已签名浏览器扩展／本地助手通过 127.0.0.1 回环端口领取任务
  → 打开目标平台并使用当前浏览器登录会话
  → 按版本化平台脚本上传媒体、填写文案和完成页面检查
  → 遇登录、验证码、二次验证或风控立即暂停，请用户处理
  → 发布前展示账号、作品、文案和可见范围，由用户最终确认
  → 回传平台内容 ID、公开链接或经脱敏的步骤凭证
  → 服务端核验并进入监控；无法确认时标记“待对账”
~~~

技术与安全要求：

- 本地端口只绑定 `127.0.0.1`，使用一次性 nonce、短时 Token、来源白名单和任务签名，不能暴露到局域网或公网。
- 平台密码、Cookie、Session Storage 和浏览器凭据不上传、不写入服务端日志；灵枢只保存连接状态和发布凭证。
- 页面选择器和步骤脚本按平台版本管理；页面结构不匹配时停止，不做猜测式点击。
- V1 不自动点击最终发布、不自动处理验证码／二次验证、不模拟养号行为，也不绕过反自动化或频率限制。
- 任务有明确超时、取消、失败回退和重复提交保护；截图或 DOM 凭证必须脱敏，并遵守租户数据保留策略。
- 该能力必须单独完成真实账号 E2E 和平台条款评审，不能复用现有仅能操作灵枢内部页面的浏览器执行器后就宣称可用。

### 9.6 账号内容与视频数据监控

监控既要覆盖灵枢发布的内容，也要覆盖客户在平台自行发布的其他内容。系统按可信度从高到低使用数据源：

| 数据源 | 可覆盖范围 | 产品显示 | 边界 |
| --- | --- | --- | --- |
| 平台官方授权接口 | 账号内容列表、发布状态和获批指标 | “官方接口”，显示 Scope 与最近同步时间 | 最稳定，但依赖账号授权、平台审核和配额 |
| 浏览器辅助读取 | 当前已登录账号页面可见的数据 | “浏览器辅助”，显示采集时间 | 只在客户本机在线且明确授权时运行，不保存登录态 |
| 公开内容 URL | 已登记且公开可见的单条作品 | “公开页面”，显示覆盖字段 | 仅在平台规则允许时使用，不能代表完整账号，也可能受页面变化影响 |
| 人工导入／补录 | 客户上传 CSV、截图或手工填写的数据 | “人工提供”，保留附件与操作者 | 不与官方数据混写，不自动当作平台已核验 |

监控的统一对象：

| 对象 | 作用 |
| --- | --- |
| `PlatformConnection` | 保存租户、平台、账号、授权范围、连接健康度和密钥引用 |
| `ExternalContent` | 统一保存平台内容 ID、公开 URL、发布时间、发布状态和关联作品版本 |
| `SocialMetricSnapshot` | 以不可变快照保存指标、采集时间、数据源、值类型和原始字段摘要 |
| `SyncCursor` | 保存每个平台／账号的增量游标、最近成功时间和下一次重试时间 |
| `MonitorJob` | 记录同步范围、调度、重试、限流和失败原因 |

最低监控字段包括：内容状态、发布时间、播放、点赞、评论、分享、收藏、完播率、粉丝变化和由该内容进入客服的咨询数。平台未提供的字段保存为 `null / unavailable`，不能补 0；不同平台口径不同的指标分别展示，不强行相加。

同步策略由渠道适配器根据配额决定。新发布内容优先在 1 小时、24 小时、3 天、7 天和 30 天形成观察点；平台只提供日级数据时按平台节奏执行，不伪装成实时。Token 失效、Scope 不足、内容下架／转私密、同步延迟和连续异常必须告警，并保留历史快照。

### 9.7 专业化技术底座

- 新渠道能力共用租户隔离、RBAC、审计日志、幂等键、持久任务队列、指数退避、限流、熔断和死信处理。
- 所有平台 App Secret、Access Token 和 Refresh Token 使用统一密钥管理与信封加密；接口永不回传明文。现有以普通文本保存的账号 Token 必须在启用新连接前迁移，这是 P0 安全前置项。
- 断开连接时同时停止任务、标记数据新鲜度，并在平台支持时调用撤销接口；只删除本地记录不算完整断开。
- 指标同步从当前“用户打开页面才更新”改为持久化后台任务；页面展示最后成功同步时间、下一步处理和数据是否过期。
- 正式发布、监控和客服连接都必须有 readiness 检查与真实 E2E，不能用“配置字段已填写”代替可用性。

## 10. 企业微信智能客服与咨询承接

### 10.1 接入选择

V1 明确接入企业微信的**微信客服**能力，用于从视频、主页、二维码或客服链接进入的外部咨询。它与以下能力分开：

| 能力 | 本版定位 |
| --- | --- |
| 微信客服 | V1 主链路：客服账号、接待链接、会话分配、消息同步、回复和统计 |
| 企业微信群机器人 | 仅用于内部告警和通知，不能代替客户会话 |
| 企业微信自建应用回调 | 可复用配置与验签基础，不能单独证明微信客服已接通 |
| 客户联系＋会话内容存档 | 后续独立合规能力；仅在客户确有员工外部联系人历史分析需求、已购买能力并取得必要授权时接入 |

### 10.2 用户链路

~~~text
发布包为每条内容生成带来源参数的微信客服链接／二维码
  → 客户从视频、主页或落地页进入微信客服
  → 企业微信回调通知灵枢有新消息
  → 同步 Worker 拉取并去重真实消息
  → 系统识别问题并检索已确认的企业知识
  → AI 生成回复草稿和引用依据
  → 低风险白名单按租户规则自动回复；其余由客服确认或接管
  → 发送结果、失败原因、解决状态和内容来源写入会话
  → 常见问题和咨询结果只经过审核后反哺企业知识与选题
~~~

没有可验证 `scene / scene_param`、短链或二维码参数时，来源显示“未知”，不能把会话强行归因给某条视频。

### 10.3 核心对象

| 对象 | 关键内容 |
| --- | --- |
| `WeComConnection` | 租户 CorpID、应用、客服账号、密钥引用、可见范围、回调和健康状态 |
| `WeComConversation` | `open_kfid`、外部用户标识、接待状态、负责人、来源和最近消息时间 |
| `WeComMessage` | 平台 `msgid`、方向、类型、时间、内容／媒体引用、同步游标和送达状态 |
| `ReplyDraft` | 用户问题、知识引用、草稿版本、风险级别、生成方式和审批状态 |
| `HumanHandoff` | 转人工原因、指派对象、响应时间、处理结果和关闭原因 |
| `ConversationOutcome` | 问题类型、是否解决、有效咨询、后续动作和可选业务结果；不代替 CRM 订单 |

### 10.4 消息接收与发送技术栈

现有 TypeScript／Node 服务继续作为接入层，复用租户应用配置和 AES 验签基础，但必须补齐真正的微信客服链路：

1. 回调入口校验签名、时间窗与 nonce，完成 AES 解密和 CorpID 校验；重复或非法请求不进入业务队列。
2. 微信客服回调只作为“有新事件”的信号。Worker 按 `open_kfid` 保存游标并调用 `kf/sync_msg` 拉取实际消息，严格处理 `has_more`，即使当前批次为空也不能擅自结束游标推进。
3. 同步窗口只有最近 3 天，任务失败必须在窗口内告警和补偿；以平台 `msgid` 做幂等，媒体在有效期内下载到租户隔离存储。
4. API 发出的消息不会在同步接口中原样返回，因此发送前先写本地出站记录，再保存企业微信回执、失败码和最终状态，保证会话时间线完整。
5. 会话分配、接待人员、转接、拒绝、撤回、超过回复窗口、发送条数限制和安全限制都转成明确状态；结果未知时不盲目重发。
6. 密钥使用统一密钥管理加密，日志与模型输入脱敏；按角色限制查看、导出、删除和知识沉淀。

微信客服发送前必须实时校验会话状态：客户主动发消息后的 48 小时窗口内最多可下发 5 条，客户再次发消息后才重置。API 返回成功只表示服务端已接收请求，最终送达以“消息发送失败”等后续事件为准。

单企业自建应用可以使用 CorpID 与应用 Secret；面向多租户的正式 SaaS 交付应使用企业微信第三方应用授权、永久授权码和企业 Access Token，不把“让每家客户长期填写 Secret”作为最终架构。

### 10.5 AI 回复与人工接管规则

| 风险级别 | 典型问题 | 默认动作 |
| --- | --- | --- |
| 低风险 | 已确认 FAQ、营业时间、资料领取、通用流程、物流查询入口 | 先生成草稿；租户 Owner 可对单个意图显式开启自动回复 |
| 中风险 | 产品选型、定制要求、交期范围、样品流程、需要补充事实的问题 | AI 草稿＋引用依据，客服确认后发送 |
| 高风险 | 价格承诺、合同、付款／退款、投诉、认证、功效、法律、隐私删除、定制承诺 | 强制人工接管，AI 只整理上下文，不得自动发送 |

所有回复只能引用当前租户已确认且在有效期内的企业知识。证据不足、资料冲突、客户身份不明或模型置信度不足时，统一回答“需要工作人员确认”并进入人工队列，不能编造答案。

### 10.6 客服工作台与统计

客服工作台按“待首次响应、AI 草稿待确认、处理中、待客户回复、需人工接管、已解决、发送失败”组织会话。每个会话展示来源内容、客户问题、引用知识、草稿、历史消息、负责人和下一步，不显示模型内部思考。

最低统计包括：新会话数、首次响应时间、人工接管率、解决率、发送失败、未解决积压、来源内容带来的有效咨询。统计必须区分企业微信官方数据和灵枢内部计算口径，并支持回到原会话核验。

### 10.7 完成定义

只有真实测试账号完成以下链路，页面才显示“微信客服已连接”：**客服账号可用 → 接待链接可打开 → 入站消息被验签解密 → `sync_msg` 拉取并去重 → 生成草稿 → 人工发送／接管 → 回执入库 → 统计可追溯**。只保存 CorpID、Secret、Token、EncodingAESKey 或点过“自检通过”，状态仍为“配置中”。

## 11. 专业功能页的手动操作要求

### 11.1 企业知识

必须支持：

- 新增和编辑企业、产品、目标客户及品牌资料。
- 维护产品名称、SKU／型号、规格、卖点、成分／材质、适用场景、资质、禁用表达及事实版本。
- 上传检测报告、资质、规格书、合同等事实凭证；这些文件默认属于 `KnowledgeEvidence`，不是可直接制作的产品素材。
- 查看该产品已经关联的素材缩略图和数量，并通过“去我的素材管理”进入按产品筛选后的素材页。
- 产品封面从“我的素材”选择引用；企业知识不提供图片、视频或音频的独立“产品素材上传”。
- 标记必须使用和禁止使用的表达。
- 选择本次任务引用的资料。
- 查看资料被哪些任务使用。
- 资料更新后提示哪些进行中任务可能受影响。

### 11.2 灵感大屏｜爆款灵感

必须支持：

- 搜索、筛选、查看和收藏灵感。
- 上传或手动新建参考内容。
- 查看内容拆解。
- 对可合法分析的参考视频保存“全片精确分析”，至少拆出开头作用、信息推进、镜头功能、节奏和结尾动作。
- 全片精确分析完成后，只将结构分析 ID／版本、可用范围和“只借结构”约束交给编导 Agent；不能绕过编导 Agent 直接启动内容 Agent。
- 将灵感作为结构参考加入当前任务，但不复制原台词、品牌、人物、案例、数据、产品事实、原音频或无许可画面。
- 将拆解出的钩子、节奏和镜头功能提供给管理员创建或优化内容公式。
- 记录来源页面、作者／账号、平台、采集时间、可访问性和使用情况；没有下载／商用／改编许可时只保存链接与分析，不转存原视频。

### 11.3 灵感大屏｜我的素材与拍摄任务

必须支持：

- 上传、预览、搜索和筛选企业素材。
- 作为图片、视频、音频等创作素材的唯一主数据与管理工作区；任务页和拍摄任务可以发起快捷上传，但必须共用同一上传服务并落到这里。
- 系统自动拆段、去重并生成产品关系建议、主题、镜头功能、适用场景和可用状态标签。
- 在每个任务中按去重、质量、相关性、覆盖度和授权状态筛选镜头；本次未入选只影响该任务，不删除素材库对象。
- 按“可直接使用、适合的主题、可补充、待确认”查看素材。
- 查看一段素材适合哪些主题、哪些内容公式位置和哪些任务。
- 关联一个主产品、多个相关产品或“企业通用”，并独立关联主题、可选公式位置和来源任务。
- 按知识库产品筛选，显示素材关联的产品、使用任务数和锁定版本。
- 允许用户修正名称、产品归属、授权和系统标签。
- 替换不可用素材时建立新版本，不覆盖历史任务引用。
- 停用不应继续使用的素材；删除前显示被哪些任务和作品引用。
- 查看周计划或即时任务还缺少哪些镜头、怎样拍和建议时长。
- 从任务上传后先创建或复用 `MaterialAsset`，再建立 `TaskMaterialRef` 并回到原任务；用户在已选产品任务内主动上传并确认使用时记为 `selected`，系统自动匹配只建 `candidate`，低置信或高风险结果合并确认。
- 同一文件从不同入口再次上传时不新增素材，只建立缺少的产品／任务关系，并明确提示“素材已存在，已关联”。
- 网上导入的素材必须展示来源与授权状态；只有明确允许下载、商业使用和改编的文件可以进入“我的素材”，其他内容只能进入灵感参考库。
- 视频二进制通过 PocketBase 后端文件字段或对象存储保存，集合中保存元数据与文件引用；应用服务器不得持久保存视频，下载、转码和渲染只使用操作系统临时目录并在任务后清理。

### 11.4 内容策划

必须支持：

- 查看和调整本次一级主题与具体选题。
- 新增、删除、排序和替换选题。
- 周计划中调整主题组合、内容顺序和代表样片范围。
- 即时生成中只调整当前主题，不展示周维度视频矩阵。
- 保存为草稿。
- 提交后进入统一制作流程；本轮公式库为空，先尝试灵感全片分析结构，无可用结构则使用企业知识安全骨架，企业事实也不可用时只能按两份独立、精确产品关联素材生成无事实宣称安全短片。任一路径都必须由编导 Agent 生成完整导演方案后才能进入内容制作。

### 11.5 脚本库／创作方案

必须支持：

- 查看由编导 Agent 根据主题、企业事实、真实素材和结构来源生成的导演方案业务视图。
- 查看和比较脚本、口播、字幕、分镜、素材使用／补拍和质量验收点；客户正常制作流程不需要在这里新建方案。
- 查看不同版本和修改差异。
- 选定的公式（本轮为空）、灵感结构或安全骨架自动绑定原任务；素材上传后由编导 Agent 生成适配后的新 `DirectorPlanVersion` 和差异说明，内容 Agent 无写入权。
- 客户可针对业务事实退回修改，但不需要逐镜编写、确认后才能继续。
- 按产品、主题、平台、语言和任务查找。
- 保留已经锁定、确认和交付的导演方案版本。
- 客户不能在脚本库查看、编辑或切换管理员内容公式。

### 11.6 后台自动制作与高级修复工具

必须支持：

- 客户点击“开始制作”后不打开制作工具；后台自动带入任务、产品及事实版本、主题、结构来源、素材及版本和更多设置，先调用编导 Agent。
- 后台依次执行“编导 Agent 生成／锁定导演方案 → 内容 Agent 按方案完成分镜素材执行、配音、字幕合成、音乐、封面、渲染和质检”，刷新或重新登录后继续同一 `ContentTask`。
- 口播文本和字幕文字只来自已锁定 `DirectorPlanVersion`；用户任务原文、主题名和一句具体诉求不得直接送入配音或字幕。
- 内容 Agent 只能在方案声明的范围内做素材裁剪、缩放、重构图、转码、响度规范化和时间对齐；不得重新生成或改写脚本、口播、字幕文字、叙事结构、核心主张和 CTA。
- 素材选择必须通过任务级去重、质量、相关性、覆盖度与授权检查；既不满足常规两镜头门槛，也不满足第 6.5.2 节两文件精确关联安全特例时进入“待补素材”，不能渲染伪成片。
- 素材有限但达到最低门槛时，由编导 Agent 生成缩短版导演方案，内容 Agent 执行该版本；禁止内容 Agent 循环片段、末帧停留和大段文字页凑时长。
- 自动质量门至少检查可播放、非黑屏、真实镜头数量、素材授权、画面与脚本对应、事实依据、口播可听、字幕同步、配乐音量、音画时长与平台编码；未通过不能进入客户验收。
- 高级修复工具仅供运营／交付人员处理自动重试后仍失败的个别环节，不属于客户工作流，也不能成为“继续制作”跳转目标。
- 制作开始后，产品事实、导演方案或素材等输入发生变化时明确提示并创建新 `DirectorPlanVersion` 与新的 production run；不得原地修改当前运行的冻结快照。
- 配音、字幕、音乐、封面和渲染等不改变冻结输入的调整，可以重做对应产物并生成新输出版本，旧输出仍保留。
- 客户只预览制作结果、比较成片版本、给出修改意见和确认成品。
- 后台可在不改变冻结事实和主题的前提下重做单个环节，并保存完整版本记录。
- 将确认结果同步到交付中心。

原有三种生成能力仅作为后台可组合执行能力：

- 已有真实素材时，可调用素材编排与剪辑能力。
- 有完整且可合法使用的参考分析时，编导 Agent 可调用结构参考能力；本轮公式库为空，不形成公式结构硬门槛。
- 企业事实充分时，编导 Agent 可调用企业知识安全骨架能力，并给出非强制拍摄建议。
- 配音、字幕、音乐、封面和渲染可以与上述能力在同一任务内组合，不要求三选一。

系统选择和组合执行能力，不要求客户理解或手动选择。内部路由值不得出现在客户页面或客户提交参数中，制作结果始终写回原任务。

### 11.7 我的创作与交付中心

必须支持：

- 按任务、平台、状态和版本筛选作品。
- 预览、修改、确认和下载。
- 单项、按平台或整包导出。
- 查看内容使用的主题、素材、导演方案版本和交付状态。
- 从作品返回原周计划或即时生成任务。

### 11.8 发布与渠道中心

必须支持：

- 按平台、账号、发布方式、状态和时间查看发布包与发布尝试。
- 清楚区分“包已准备”“等待用户确认”“平台处理中”“已发布”“待对账”和“失败”。
- 为国内抖音单独展示规格检查、发布步骤、授权状态和数据能力，不与 TikTok 国际版合并。
- 发起浏览器辅助发布前展示将要操作的账号、作品版本、文案和权限；发布前再次由用户确认。
- 对官方接口连接展示 Scope、Token 健康度和最后真实 E2E 时间；没有能力时不出现直发按钮。
- 处理失败重试、待对账、人工补凭证和撤销／断开连接；未知结果不得盲目重发。

### 11.9 账号内容监控

必须支持：

- 查看账号内由灵枢发布和客户自行发布的内容，并标记关联状态。
- 查看单条视频的播放、点赞、评论、分享、收藏、完播等平台实际可提供指标。
- 每个指标展示数据源、采集时间和是否过期；未知值显示“暂无数据”。
- 按平台、账号、内容主题、发布时间和表现区间筛选，并回到对应作品、发布包或客服咨询。
- 显示 Token 失效、Scope 不足、同步延迟、内容删除／转私密和平台限流等异常及处理方式。
- 默认只读，不自动删除、编辑、评论、点赞、关注或修改平台内容。

### 11.10 智能客服｜企业微信

必须支持：

- 按待响应、草稿待确认、处理中、需人工、发送失败和已解决筛选会话。
- 展示客户消息、来源内容、AI 草稿、知识引用、风险级别、负责人和完整时间线。
- 编辑并发送草稿、拒绝草稿、请求补充资料、指派客服、转人工和关闭会话。
- 对高风险问题锁定自动发送，并清楚说明需要人工确认的原因。
- 查看连接健康、同步延迟和回复限制，但不向普通客服展示 Secret、Token、游标和内部错误堆栈。

### 11.11 本次仍不修改的专业页面

付费投流、广告执行、报价、合同、订单、支付、批量外呼和完整销售 CRM 不纳入本 PRD 的设计、开发与验收。发布与客服只产生可追溯的内容、会话和结果，不擅自推进成交阶段或生成商业承诺。

## 12. 管理员爆款公式库

入口固定为“管理员后台 → 内容策略 → 爆款公式库”。该入口只供平台侧内部内容运营管理员或平台超级管理员使用；客户租户成员以及租户 Owner／admin 默认都不显示菜单、页面和接口能力。租户管理权限不能自动获得公式管理权限。

**本轮交付时公式库必须是真实空库。** 本节定义的是管理端结构与未来配置合同，不是本轮录入公式的指令。列表空状态使用“尚未录入爆款公式”，不自动创建示例、占位或安全公式；客户生产不因空库受阻。

### 12.1 页面结构

管理员“内容公式库”包含四个区域：

1. **公式列表**：按主题、行业、平台、状态和版本筛选。
2. **公式编辑**：维护适用条件及完整导演配置，包括结构、脚本、口播、字幕、镜头、音乐节奏、素材／补拍和质量验收点。
3. **试跑与预览**：未来录入公式后，选择一组内部测试产品与素材，查看完整导演方案和样片结果；本轮空库时不生成伪试跑记录。
4. **版本与使用记录**：查看哪些任务使用了哪个版本、验收结果和停用影响。

### 12.2 编辑字段

每个内容公式至少包含：

- 内部名称、说明和唯一 ID。
- 适用的一级主题和可选子主题。
- 适用行业、产品类型、目标买家、市场、语言、平台、形式和时长。
- 钩子、主体、证据、转折、结尾动作、节奏点和逐段时长等完整内容结构。
- 完整脚本、可替换事实槽位、逐段口播文本、音色／语速／语气／停顿要求。
- 字幕文本、句段对应、分行、关键词强调、安全区和时间对齐规则。
- 每个结构节点需要的镜头功能、素材类型、景别／运镜／构图、转场和建议时长。
- 音乐授权要求、风格／情绪、节拍／剪辑点、起止、淡入淡出、压低和目标响度。
- 素材使用条件、替换条件、裁剪／重构图边界、缺口与补拍建议。
- 必须使用的事实类型、禁止使用的主张和合规限制。
- 素材不足、事实不足和生成失败时的降级规则。
- 自动匹配优先级、适用客户和权限范围。
- 事实与画面一致、授权、口播、字幕、音乐、时长、平台规格等质量验收点和内部验收说明。

### 12.3 管理动作

管理员可以：

- 新建、复制和编辑草稿公式。
- 未来录入公式后，用真实测试资料生成完整导演方案、拍摄清单和样片进行试跑。
- 提交内部审核并发布新版本。
- 停用公式，或将公式设为“灰度可用”并配置租户白名单。
- 查看匹配记录、使用任务和验收结果。

上述是入口建成后的能力清单；本轮不执行实际公式录入、试跑、发布或灰度，交付数据中不应出现任何公式记录或使用记录。

任何已经被内部试跑、白名单灰度或正式客户任务引用的公式版本都不得原地覆盖。修改必须生成新版本；历史任务和作品继续保留原版本引用。

### 12.4 公式状态

- **草稿**：仍在编辑，不能进入任何客户任务。
- **内部试用**：只供管理员和内部测试账号使用。
- **灰度可用**：只允许租户白名单中的客户任务自动匹配。
- **正式可用**：可以被符合条件的周计划和即时生成任务自动匹配。
- **已停用**：不能用于新任务，历史任务和作品继续保留原版本。

只有“正式可用”的公式，或对白名单租户“灰度可用”的公式可进入客户生产。客户不能通过伪造参数指定草稿、内部试用、越权灰度或已停用版本。

### 12.5 权限与审计

- 前端隐藏不是权限控制；服务端必须校验平台侧公式管理角色，租户管理员无权访问。
- 创建、修改、试跑、发布和停用都记录操作者、时间和变更内容。
- 公式正文、Prompt、内部评分和测试数据不得通过客户接口返回。
- 每次自动匹配保存候选、过滤原因和匹配结果；未匹配时记录 `no_formula` 原因，最终公式及版本允许为空。

### 13.1 当前最需要修正的问题

1. 客户需要先理解三条技术路线，再选择主题；入口顺序与用户真实思考方式相反。
2. 当前八个主题把内容对象与“痛点、对比、趋势”等叙事角度混在同一层，容易选择困难。
3. 周任务和即时任务当前仍会建立人工执行记录并转入旧制作台，不是真正的自动成片执行器。
4. 周任务上传的临时文件、企业知识中的产品图片／视频与素材库引用不是同一种对象，进入制作台后不能全部自动还原，也会造成重复上传。
5. 素材已有智能分类，但缺少与知识库产品的统一关系，以及主题、可选公式位置、任务、版本、停用和替换等完整关系。
6. 当前补拍主要服务单个脚本缺口，尚未做到周计划层面的合并和自动回填。
7. 内容公式没有管理员可维护、可试跑、可版本化和可审计的产品入口。
8. 当前没有独立编导 Agent 和完整导演方案契约，内容 Agent 会同时承担创意改写与制作执行，无法保证脚本、口播、字幕和成片一致可追溯。
9. 渠道平台、账号、直发和指标能力分散在不同路由，前端容易把“代码存在”误判为“当前租户可用”。
10. 国内抖音尚未接入，现有 `tiktok` 只能代表国际版，不能换名字后直接使用。
11. 浏览器执行器不具备外部平台发布能力；账号监控也没有持久调度，不能宣传为自动发布和持续监控。
12. 部分账号 Token 的落库存储不满足高客单客户的安全要求，必须先迁移再扩展连接。
13. 企业微信只完成配置基础，真实客户消息接收、回复和人工接管链路仍不存在。

### 13.2 修改后的完整效果

- 用户在首页处理周计划，在内容创作处理即时生成，不会在两个入口看到重复的创建表单。
- 两种场景都从五个主题开始，用户只需明确主题、拍摄／上传素材、验收成果。
- 系统把主题转换为具体选题；本轮公式库为空，编导 Agent 按“全片精确分析结构 → 企业知识安全骨架 → 精确产品关联素材安全短片”生成完整导演方案和非强制拍摄建议。
- 用户在原任务只点击一次“开始制作”，后台生产编排自动带入产品、事实、主题、结构来源和素材；编导 Agent 锁定方案后交给内容 Agent 执行，旧三路线、脚本、口播和字幕页面都不再成为客户步骤。
- 企业知识维护企业／产品／买家／品牌等事实与凭证，不维护创作素材；“我的素材”统一管理全部创作素材，并清楚显示产品关系、可用素材、适合主题、可补充和待确认。
- 周计划合并非强制素材建议与必要要求并先验证代表样片；即时生成只处理当前单条，不等待周计划。
- 用户反馈和专业页修改写回同一任务和新版本，不产生重复作品。
- 管理员侧保留完整导演级公式配置、试跑和版本能力；本轮不录入、不预置任何公式，客户只看到内容方向、素材建议和成果。
- 系统从已确认作品生成按平台冻结的发布包，并按客户选择进入手工发布、浏览器辅助发布或已授权官方接口。
- 国内抖音与 TikTok 国际版由统一渠道能力矩阵管理，但凭据、规则和数据完全隔离。
- 发布凭证把作品与平台内容关联，监控任务持续保存有来源、有时间的指标快照，结果可回到原内容核验。
- 内容带来的咨询通过带来源参数的微信客服入口进入统一工作台，AI 辅助回复，人工控制高风险承诺。
- 试用验证和高客单客户使用同一套专业底座，差异只体现在用量、启用渠道、服务和自动化权限。

## 14. 状态、版本与提醒

### 14.1 目标客户可见状态（改造后）

父级周计划与单条内容任务分别保存状态，不能把“本周进度”和“某条内容进度”混成一个枚举：

| 对象 | 客户可见状态 |
| --- | --- |
| `WeeklyPlan` | 草稿、主题计划待确认、待集中准备素材、代表样片待确认、批量生产中、本批待验收、正在整理交付包、已交付、已暂停、需要处理 |
| `ContentTask` | 草稿、主题待确认、待关联素材、待补素材、可以制作、制作中、待验收、正在整理交付包、已交付、已暂停、需要处理 |
| `PublicationPackage` | 准备中、可发布、等待发布确认、核验中、已发布、待对账、失败、已失效 |
| `PlatformConnection` | 未配置、配置中、可用、需重新授权、权限不足、同步异常、已停用 |
| `WeComConversation` | 待首次响应、草稿待确认、处理中、待客户回复、需人工接管、发送失败、已解决 |

即时生成只显示其 `ContentTask` 状态；周计划首页显示 `WeeklyPlan` 总状态，并允许展开查看各条 `ContentTask`。父级状态由真实子任务汇总，不能仅由前端估算。

客户不看到内部小步骤、运行编号或系统处理名称。

#### 14.1.1 `ContentTask` 内部状态机与 Agent 交接

| 内部状态 | 处理者 | 进入条件 | 允许的下一状态 | 客户映射 |
| --- | --- | --- | --- | --- |
| `source_resolving` | 灵小枢／来源分析 | 主题与企业事实已确认 | `director_drafting` | 待关联素材 |
| `director_drafting` | 编导 Agent | 结构来源已确定；本轮为灵感分析或安全骨架 | `awaiting_material` / `ready_to_start` / `needs_user_input` | 待关联素材／待补素材／需要处理 |
| `ready_to_start` | 灵小枢 | 事实／无事实宣称边界、授权和适用的统一素材门通过 | `director_finalizing` | 可以制作 |
| `director_finalizing` | 编导 Agent | 用户幂等点击“开始制作”并冻结输入 | `director_plan_locked` / `awaiting_material` / `needs_internal_action` | 制作中／待补素材／需要处理 |
| `director_plan_locked` | 灵小枢 | `DirectorPlanVersion` 完整、`status=ready`、`lock_status=locked`，且方案／事实／素材／记录哈希已固定 | `content_rendering` | 制作中 |

| `director_revision_required` | 编导 Agent | 内容 Agent 提交镜头级不可执行证据 | `director_plan_locked` / `awaiting_material` / `needs_internal_action` | 制作中／待补素材／需要处理 |
| `technical_qc` | 内容 Agent／质检 | 渲染产物完成 | `awaiting_acceptance` / `content_rendering` / `director_revision_required` / `needs_internal_action` | 制作中／待验收／需要处理 |
| `awaiting_acceptance` | 灵小枢 | 方案验收点和通用技术质量门全部通过 | `accepted` / `director_revision_required` | 待验收／制作中 |

内容 Agent 不得从 `content_rendering` 直接跳回 `source_resolving`、修改 `DirectorPlanVersion` 或自行创建脚本版本。`director_revision_required` 为内部自动回路，只在需要新素材、新事实或授权确认时映射为用户待办；其余情况由编导 Agent 产生新版本后自动继续。

### 14.2 版本规则

- 主题 Brief、可选内容公式、产品事实、素材修订、导演方案、成片和交付包都要保留版本或明确引用版本。
- 任务在开始制作时固定引用 `product_version_id` 与各素材的 `revision_id`；编导 Agent 在此快照上追加并锁定 `DirectorPlanVersion`。当前执行记录保存导演方案版本和 `lineageHash` 用于运行观测；最终成片必须保存可反解的 `directorPlanReference`，其中含 `directorPlanId + version + lineageHash + factSnapshotHash + materialSnapshotHash + recordHash`。任一输入更新后，用户选择升级必须创建新导演方案版本、production run、输入快照和相应作品版本，原运行不得原地替换；已交付内容不被静默改变。
- `DirectorPlanVersion` 只追加不更新。新版本必须指向紧邻 `previous_version`；完全相同的重试为幂等命中，同一版本内容冲突必须拒绝。旧方案版本永不改成 `superseded`；“已被替代”是作品或当前投影的关系。
- 从任务移除未使用的 `selected` 素材只把引用改为 `removed`；已经产物消费的 `used` 引用只可标记“不用于后续版本”，历史引用不能删除。取消产品关系只影响关联；产品归档不删除素材，素材停用不破坏历史任务追溯。
- 用户确认后的内容才进入交付包。
- 发布包引用不可变的作品版本和内容哈希；已发起发布后只能新建版本，不能改写原包。
- 外部平台内容与指标快照只追加或校正来源，不覆盖历史观察点。
- 客服草稿、人工修改、实际发送内容和引用知识分别留痕，不能用新草稿覆盖已经发送的消息。
- 用户修改已确认内容时，生成新版本并重新检查受影响的交付项。
- 已被内部试跑、白名单灰度或正式客户任务引用的内容公式不能原地覆盖；本轮无任何公式记录或引用，该规则作为未来约束保留。
- 主题改变时由编导 Agent 重新生成导演方案；本轮按灵感结构／企业知识安全骨架重新解析。旧主题与旧导演方案版本不删除。

### 14.3 提醒方式

只在以下时刻提醒用户：

- 必要资料仍缺失。
- 周计划存在必须由客户决定的优先级冲突。
- 即时生成尚未关联任何可用真实素材，或缺少会影响真实性、授权和合规的必要资料；普通拍摄建议不足不提醒。
- 代表样片或本批成品需要确认。
- 存在真实性、授权或正式公式明确要求的集中素材清单，需要用户处理；普通非强制建议不单独提醒。
- 交付包已经准备好。
- 发布前需要用户最终确认，或发布结果进入待对账／失败。
- 平台授权过期、同步持续失败或监控数据明显过期。
- 企业微信出现新会话、草稿待确认、高风险人工接管或消息发送失败。
- 出现无法自动解决的问题。

多个提醒合并成一份待办。正常制作过程不持续发送“正在处理”类消息。

## 15. 关键页面交互要求

### 15.1 表单与上传

- 支持拖拽上传、批量上传、上传进度和失败重试。
- 清楚显示支持的文件类型与限制。
- 企业知识产品页不展示创作素材上传；所有创作素材上传器都调用“我的素材”的统一服务。
- 在任务内上传时自动带入当前产品、主题和任务；成功后明确区分“本次新增”和“已有素材已关联”。
- 已上传内容可以预览、建立新版本和从当前任务移除；已使用引用只标记为后续不使用，“从任务移除”不能删除素材库对象或历史作品来源。
- 表单自动保存，并显示最近保存时间。
- 退出未保存编辑前给出提醒。
- 必填项只在影响继续操作时提示，不在页面一开始整屏报错。

### 15.2 列表与筛选

- 内容多时使用表格或紧凑列表，不用无限堆叠大卡片。
- 支持按任务、产品、平台、语言、状态和时间筛选。
- 支持搜索和批量选择。
- 常用操作直接显示，低频操作进入更多菜单。
- 删除、停用和替换已有素材前必须二次确认；替换建立新修订，不允许覆盖历史修订。

### 15.3 预览与确认

- 图片、视频和文字可以在同一任务中连续预览。
- 确认前展示本次变化，不要求用户重新检查全部历史内容。
- 退回时可以直接标注需要修改的项目。
- 批量确认必须允许先排除有问题的内容。
- 下载前展示交付完整度和仍缺少的项目。

### 15.4 空状态与错误

- 没有数据时说明用户现在可以做什么，并提供一个主要按钮。
- 暂时失败时保留已经填写的内容。
- 可以重试的问题直接提供重试操作。
- 需要内部处理的问题只告诉用户当前影响和预计下一步，不展示内部错误。
- 对当前租户不可用的内容公式不进入客户任务，因此客户不会看到空白公式卡或内部占位。
- 平台管理员进入本轮空的爆款公式库时，显示“尚未录入爆款公式”及管理入口，不渲染示例卡、默认卡或伪使用记录。

## 16. 验收标准

### 16.1 双入口与三项动作

- [ ] 首页数字员工只承担周计划，内容创作承担即时生成；两个入口职责清楚且不出现重复创建表单。
- [ ] 即时生成无需先创建周计划，也不调用周维度视频矩阵。
- [ ] 有活跃周计划时，即时作品只有在用户确认后才关联，原计划数量和预算不被静默修改。
- [ ] 两个入口都只把“明确主题、拍摄／上传素材、验收成果”作为用户核心动作。
- [ ] 平台、语言、比例、预算等默认继承，并收进“更多设置”。
- [ ] 即时生成每个 `ContentTask` 固定为 1 条；周计划数量只由 `WeeklyPlan` 视频矩阵和客户权益决定，内容公式不得修改数量。
- [ ] 任务级筛选必须通过两类门槛之一：常规路径至少 2 个独立、相关、可信且 `selected` 的有效真实镜头；无事实宣称安全特例至少 2 份独立且与当前产品精确关联的真实上传文件。常规路径的两个镜头可来自同一原视频的不同真实分镜，同一分镜的裁切、切窗、放大或变速不能重复计数。
- [ ] 用户从任务点击一次“开始制作”后留在同一任务并进入后台自动制作；全程不再选择旧三路线，不进入脚本／配音／字幕／剪辑步骤，也不重复填写产品、主题、素材或更多设置。
- [ ] 开始制作失败时保留原任务和全部素材引用；使用同一幂等键重试不会重复建任务、重复计费或重复启动运行。
- [ ] 制作中离开页面不会丢失任务，重新登录后可继续。
- [ ] 导演方案结构来源严格按“正式爆款公式 → 灵感中心全片精确分析结构 → 企业知识安全骨架”选择并保存；本轮因公式库为空从第二级开始，参考只借结构，不复制台词、品牌、人物或事实。精确产品关联安全短片是 `knowledge_fallback` 的受限证据降级，不增加第四种 `director_source_type`，也不声称经视觉识别的画面事实。
- [ ] 用户任务名、主题名和一句具体诉求不会直接成为口播或字幕；上传素材导致的文案／结构适配只由编导 Agent 生成可追溯的新 `DirectorPlanVersion`，不要求用户重新写脚本，也不由内容 Agent 改写。
- [ ] 有限素材刚好达到适用的最低素材门时，编导 Agent 能生成缩短版导演方案，内容 Agent 按方案生成带口播、字幕、配音和合规配乐的可验收 MP4；两类门槛都未满足时进入“待补素材”，不循环镜头、停留末帧或使用大段文字页凑时长。

### 16.2 主题入口

- [ ] 内容创作首页展示五个一级主题和一个自定义入口，不再展示三条技术生成路线。
- [ ] 五个客户可见主题分别为“产品亮点、使用场景、工厂与交付／供应与交付、定制合作、客户案例”；稳定主题 ID 不变，`supplier_capability` 按企业资料正确显示“工厂与交付”或“供应与交付”。
- [ ] “痛点、实证、对比、趋势、FAQ”等只作为内容公式／叙事角度，不与一级主题并列。
- [ ] 用固定历史选题集验收主题分类：制造业和美妆 B2B 工厂各不少于 20 条，由产品与交付人员独立归类；至少 90% 可选择唯一主主题，双方一致率不低于 85%，自定义入口占比不高于 10%。
- [ ] 选择主题后，编导 Agent 能生成具体选题、完整导演方案草案和非强制拍摄建议；公式库为空时使用全片精确分析的灵感结构、企业知识安全骨架，或严格受限的精确产品关联安全路径，但不得产生公式专属的镜头硬门槛。

### 16.3 周计划与即时生成

- [ ] 周计划能按主题形成内容组合；有正式启用且适用的内容公式时才匹配，没有公式时仍可制作。
- [ ] 周计划能把重复拍摄建议合并为一次集中准备清单，并明确建议是否会影响制作。
- [ ] 新方向能先生成代表样片，确认后再进入批量生产。
- [ ] 即时生成能够从一个主题独立完成结构来源解析、导演方案、素材检查、内容 Agent 执行和单条验收。
- [ ] 后台生产编排器准确读取同一 `task_id`、`theme_id`、`product_id + product_version_id`、素材及修订版本、企业事实、结构来源和更多设置；编导 Agent 锁定后，内容 Agent 只能以同一 `director_plan_id + version + lineage_hash + fact_snapshot_hash + material_snapshot_hash + record_hash` 执行，不创建第二个任务或素材副本；客户不进入制作工作台。
- [ ] 同一成片可组合多个旧制作能力，客户页面和客户请求参数均看不到内部 `material / clone / product` 路由值。
- [ ] 同一条反馈可以作用于当前批次，单项例外可以排除后单独处理。

### 16.4 我的素材与拍摄任务

- [ ] 企业知识产品页没有图片、视频或音频“产品素材上传”；只显示关联素材及“去我的素材管理”，产品封面也引用“我的素材”。
- [ ] “我的素材”是创作素材唯一主数据与管理工作区；从内容任务或拍摄任务快捷上传后，素材立即在“我的素材”可见并关联原任务。用户在已选产品任务中主动上传可确认该产品关系，系统自动匹配只能先进入候选状态。
- [ ] 上传图片或视频后，系统自动完成基础检查、去重、视频拆段和业务标签。
- [ ] 制作前按任务完成去重、质量、相关性、覆盖度和授权筛选；未入选素材仍保留在“我的素材”，不会因为当前任务不用而被删除。
- [ ] 素材能够关联一个主产品、多个相关产品或“企业通用”，并独立关联一级主题、镜头功能、可选内容公式位置和来源任务。
- [ ] 同一租户内，SHA-256、素材语义、原始出处／权利来源与授权范围均一致的文件从“我的素材”和任务页重复上传时素材总数不增加，只新增缺少的产品／任务关系并明确提示复用；上传页面不同不算来源不同，感知指纹相似只提示用户确认，跨租户不泄露存在性。
- [ ] 产品名称或展示信息更新后，关联素材卡片通过同一 `product_id` 同步显示新信息，不要求重新上传或重新关联；历史任务仍保留原产品事实版本。
- [ ] 用户可以按“可直接使用、适合的主题、可补充、待确认”查看素材；只有真实阻塞项进入“必须处理”。
- [ ] 每项拍摄建议或正式素材要求都明确说明拍什么、怎么拍、建议时长、参考标准、服务哪些内容以及是否影响开始制作。
- [ ] 当前主题素材建议保存状态、匹配片段、置信度和判断原因，普通建议为非强制；常规路径的成片质量门为至少 2 个独立、相关且可信的真实镜头；无事实宣称安全特例必须是 2 份独立且与当前产品精确关联的真实上传文件。本轮不存在公式节点硬门槛；未来只有在真实公式经独立产品决策、试跑和发布后，才可增加该公式明确定义的必需性。
- [ ] 上传补拍素材后回到原任务，不要求重新选择产品和主题；本轮只重算 `material_suggestion` 和导演方案的素材映射。未来真实公式经独立决策发布后，才按其版本重算 `material_requirement`。
- [ ] 事实／无事实宣称边界、授权和适用的统一素材门满足后任务进入“可以制作”；普通建议不阻塞，两类最低素材门都未满足时进入“待补素材”。
- [ ] 高置信、低风险素材只自动进入推荐位并创建 `candidate`，仍不计入启动条件；用户确认后才转为 `selected`。只有用户在已明确产品的任务中主动上传并确认使用时可直接记为 `selected`；低置信或高风险结果合并为一次确认。
- [ ] AI 标签不被当作认证、功效、工厂所有权、客户关系或商业结果证明。
- [ ] 系统自动匹配的 `candidate` 不计入启动条件；用户确认的 `selected` 才计入，成片消费后转为 `used` 并保留不可删除的历史引用。
- [ ] 从任务移除未使用素材不会删除素材库对象；已使用素材只能标记为后续版本不再使用；取消一个产品关系不影响其他产品和历史任务；产品归档不删除素材。
- [ ] 替换素材只允许同一语义内容的质量升级并建立新修订；主体或产品改变时新建素材。新修订重新分析，已交付作品继续引用旧修订。
- [ ] 开始制作后更换产品事实版本或素材修订时，页面提示“创建新一轮制作”；确认后生成新的运行与输入快照，旧运行和旧成片仍可追溯。
- [ ] 没有产品、任务或作品引用的逻辑素材可进入回收站；已被任务或作品引用的素材普通删除只会停用。授权／隐私撤回经过受控清除并标记受影响作品，删除前显示引用范围；底层文件仍被知识凭证引用时不得物理删除。
- [ ] 知识凭证转为创作素材后不增加 `FileBlob`，新增一个带 `source_evidence_id` 的 `MaterialAsset`；停用或删除素材不影响原知识凭证访问。
- [ ] 网上公开视频无明确下载、商用和改编许可时只进入灵感参考库，不能进入“我的素材”或成片；获许可素材保留来源、授权范围、期限、证据文件／链接与证据哈希。
- [ ] PocketBase 集合保存素材元数据与文件引用，视频二进制保存到 PocketBase 后端文件字段或对象存储；应用服务器没有持久视频文件，`data/media`、`data/social-content-sources`、项目目录和容器可写层均不承担正式存储。
- [ ] 下载、探测、转码和渲染只使用操作系统临时目录；正常完成后立即清理，异常遗留文件有短保留期清理任务，成片播放和下载只读取 PocketBase 文件／对象存储。
- [ ] 美妆 B2B 可商用素材库首批目标为 30 条有明确下载、商用和改编许可的种子视频；灵感参考库支持约 50 条参考记录。页面和接口明确区分“只看链接与结构”和“可用于剪辑”。
- [ ] 五个一级主题各完成一次完整 E2E：关联知识库产品 → 选择／上传真实素材 → 自动整理并建立同一素材引用 → 一次开始制作 → 统一工作台 → 验收；拍摄建议可以全部未完成。

### 16.5 编导 Agent、内容 Agent 与管理员公式库

- [ ] 灵感中心完成全片精确分析后，调用链路必须先进入编导 Agent；无有效的 `directorPlanId + planVersion`、`lockStatus=locked`、`lineageHash` 和 `handoffHash` 时内容 Agent 拒绝启动。
- [ ] 每个可执行 `DirectorPlanVersion` 都满足 `status=ready && lock_status=locked`，并完整包含结构与时间轴、完整脚本、逐段口播、字幕文本与对齐规则、镜头计划、音乐与节奏、素材使用与补拍建议、质量验收点；缺任一类不得锁定或交接。
- [ ] `ProductionRun` 和成片保存 `director_plan_id + version + lineage_hash + fact_snapshot_hash + material_snapshot_hash + record_hash`；必须能在同一租户、同一任务中解析到唯一不可变版本，任一值不一致时不得渲染。
- [ ] 导演方案版本为追加式存储：完全相同重试幂等，同版本异内容覆盖被拒绝，新版本的 `previous_version` 必须连续，历史版本不因新成片生成而改写。
- [ ] 内容 Agent 只可按方案做素材裁剪、缩放、重构图、转码、响度规范化和时间对齐；对脚本、口播、字幕文字、叙事顺序、核心主张和 CTA 无写权限。
- [ ] 内容 Agent 发现方案不可执行时进入 `director_revision_required`，并携带镜头号、原因和证据；编导 Agent 生成新方案版本并锁定后自动继续，旧版本不覆盖。
- [ ] 分别用三组任务验收零公式路径：①有可用全片精确分析时使用灵感结构；②无灵感分析但有可核验企业事实时使用企业知识安全骨架；③公式、灵感、企业事实和视觉分析都不可用时，仅凭 2 份与当前产品精确关联的独立真实素材生成无事实宣称安全短片。三组都由编导 Agent 产出完整方案并由内容 Agent 执行成片。
- [ ] 第③组中文件名、通用标签和任务原文不能解锁生产；同一文件拆出多段仍只算一份证据；每个镜头保持视觉置信度 `0`、`needs_review=true`，口播与字幕不包含画面推断。
- [ ] 零公式路径不默认生成“联系我们”，也不把用户自由输入 CTA 直接送入口播或字幕；只有未来正式发布的受管公式显式定义时才允许使用 CTA 槽位。

- [ ] 只有平台侧内部内容运营管理员或平台超级管理员可以访问公式列表、编辑、试跑、发布、停用和版本记录。
- [ ] 客户租户成员和租户 Owner／admin 前端没有公式入口，直接调用管理员接口也会被服务端拒绝。
- [ ] 公式表单契约覆盖适用范围、结构与时间轴、完整脚本、口播、字幕、镜头计划、音乐与节奏、素材使用与补拍、事实／风险约束、降级规则和质量验收点；本轮只验证表单和 API 合同，不保存公式数据。
- [ ] 草稿、内部试用和已停用公式不能进入普通客户任务；灰度公式只进入租户白名单任务。
- [ ] 被内部试跑、白名单灰度或正式客户任务引用过的版本不能原地覆盖，历史作品可以追溯到原公式版本。
- [ ] 系统保存候选公式、过滤原因和匹配结果；未匹配时记录 `no_formula` 原因，最终公式及版本允许为空。
- [ ] 本轮验收时公式表、API 列表和管理页列表均为空，不存在 seed、migration、fixture、导入脚本、示例或占位公式；全部生产任务 `formula_id / formula_version = null`。
- [ ] `formula_id / formula_version = null` 时通过灵感结构、企业知识安全骨架，或上述严格受限的精确产品关联安全路径完成主题到验收 E2E；不得调用内置占位、草稿、内部试用或未授权灰度公式，也不得产生公式专属结构硬门槛。

### 16.6 作品与交付

- [ ] 自动制作与人工修改不会产生重复任务或两份不一致的作品。
- [ ] 成片通过可解码、非黑屏、真实镜头数、授权、相关性、事实依据、口播可听、字幕同步、配乐音量、音画时长和平台编码质量门后才进入待验收；不合格成片不会展示给客户确认。
- [ ] 用户可以重做单项成果，不必重新开始整条任务；非创意技术重渲染沿用锁定方案，脚本、口播、字幕文字、音乐节奏或镜头意图变更必须由编导 Agent 创建新方案版本。
- [ ] 每条作品可追溯到主题、素材修订与实际片段、产品事实、`director_source_type` 和完整 `directorPlanReference`；本轮使用灵感结构时追溯参考分析记录，使用企业知识时追溯事实快照，使用精确产品关联安全路径时仍保存事实快照对象，其 `source=user_product_association`、`facts=[]`、`verifiedFactKeys=[]`，同时追溯关联来源；公式版本为空。
- [ ] 交付中心展示成品、配套文字、发布说明和作品版本。
- [ ] 用户可以预览、单项下载、按平台下载或整包下载。
- [ ] 缺少必要文件时不能标记为交付完成。

### 16.7 渠道、抖音与发布

- [ ] 页面由 `ChannelAdapter` 能力清单驱动；不支持或尚未通过真实验收的动作不显示为可用。
- [ ] `douyin_cn` 与 `tiktok_global` 的平台 ID、应用、Token、发布规则、回执和指标完全隔离。
- [ ] 客户不连接任何社媒账号也能完成内容生产，并为抖音生成包含视频、封面、文案、标签、CTA、检查项和版本哈希的发布包。
- [ ] 发布包下载、打开和发起辅助流程都不会被误记为发布成功；只有可核验凭证才能进入“已发布”。
- [ ] 发布结果未知时进入“待对账”，同一幂等键不会自动重发。
- [ ] 官方抖音发布和数据能力必须经过应用审核、用户授权、Scope 校验和真实账号 E2E 后才对该租户开启。
- [ ] 浏览器辅助发布使用客户本机已有会话，平台密码和 Cookie 不上传；本地端口只绑定回环地址并校验一次性签名任务。
- [ ] 浏览器流程遇到登录、验证码、二次验证、风控、页面不匹配或频率限制时立即暂停，不存在绕过逻辑。
- [ ] 浏览器辅助发布 V1 在最终发布前展示目标账号、作品和文案，由用户完成最后确认。
- [ ] 每种已启用发布方式至少用一个真实测试账号完成“发起 → 平台接收 → 状态对账 → 凭证入库”的 E2E；仅单元测试或字段自检不算通过。

### 16.8 账号内容与视频数据监控

- [ ] 监控能区分灵枢发布内容和客户自行发布内容，并通过平台内容 ID 或公开链接与作品对账。
- [ ] 每条指标展示数据源、采集时间、覆盖范围和值类型；平台未返回时显示“暂无数据”，不能写成 0。
- [ ] 官方接口、浏览器辅助、公开页面和人工导入的数据不会无标记地混写。
- [ ] Token 过期、Scope 不足、同步延迟、限流、内容删除／转私密和连续失败都有明确状态、告警和恢复路径。
- [ ] 社媒指标由持久后台任务主动同步，不依赖用户打开页面；任务支持幂等、限流、退避、重试和死信处理。
- [ ] 历史快照不因重新授权、平台字段缺失或当天新同步而被覆盖；不同平台口径不强行相加。
- [ ] 无账号授权时只监控用户登记且平台规则允许读取的公开内容，页面明确说明不是完整账号监控。
- [ ] 默认监控为只读，不产生删除、编辑、评论、点赞、关注或其他平台副作用。

### 16.9 企业微信智能客服

- [ ] 页面明确区分微信客服、群机器人、自建应用回调和客户联系／会话内容存档；任何一个配置项不能冒充完整客服接入。
- [ ] 真实消息完成“验签与 AES 解密 → 防重放 → `sync_msg` 拉取 → `msgid` 去重 → 建立会话 → 生成草稿 → 人工发送／接管 → 回执入库”。
- [ ] `open_kfid` 游标和 `has_more` 正确持久化；服务异常可在 3 天同步窗口内补偿，不丢失或重复展示消息。
- [ ] API 发出的消息拥有独立本地出站记录和最终状态，不依赖同步接口回显。
- [ ] 默认 AI 只生成带知识引用的草稿；只有租户 Owner 明确开启的低风险白名单意图允许自动发送。
- [ ] 价格、合同、付款／退款、投诉、认证、功效、法律、隐私删除和定制承诺强制人工接管。
- [ ] 企业知识不足、冲突、过期或置信度不足时不编造答案，自动进入人工队列。
- [ ] 客服密钥加密保存且接口不回传明文；消息、媒体、知识和审计记录严格租户隔离并执行保留策略。
- [ ] 带追踪参数的客服链接能回到来源作品；参数缺失时显示“来源未知”，不做猜测归因。
- [ ] 完整真实链路通过前，连接状态只能是“配置中”或“待验收”，不能显示“微信客服已连接”。

### 16.10 前端专业性

- [ ] 客户页面不出现节点、服务端、接口、模型、密钥、提示词、写入方式和开发状态。
- [ ] 客户页面不展示“本页用于什么”“系统为什么这样设计”等大段解释。
- [ ] 页面使用统一的状态、按钮、表单、表格、抽屉和确认方式。
- [ ] 上传失败、保存失败、制作失败和数据识别失败都有明确恢复路径。
- [ ] 关键流程可使用键盘完成，状态和错误不只依赖颜色表达。
- [ ] 电脑端完成全部操作，移动端可完成查看、确认和下载。

## 17. 前端界面改造（独立实施与验收板块）

本节只说明前端怎么改。无论客户处于验证期还是高客单长期服务期，都使用同一套专业界面；套餐差异只影响额度和可用能力，不决定是否看得到主题创作工作流。

### 17.1 本轮五项前端精简

本轮先解决首屏信息太多、状态卡悬空和空白板块过大的问题。前端按以下五项直接修改：

| 用户指出的问题 | 直接改法 | 最终效果 |
| --- | --- | --- |
| 顶部“这次想让客户看到什么”说明板块太大 | 删除大标题、两段按钮和右侧三张说明卡，只保留一句引导语：**“选好视频主题并上传素材，编导 Agent 会先定导演方案，再由内容 Agent 生成视频，你只需审核成品。”** | 首屏马上看到主题，用一句话说清两个 Agent 的接力关系 |
| 主题卡下方整块“当前任务／成品待确认”信息重复 | 删除该大卡片；当前任务不在首屏单独占一整行，统一从页面右下角的紧凑机器人状态入口进入右侧抽屉查看 | 主题选择区结束后直接进入必要操作，不重复展示任务摘要 |
| 主题词不够通俗 | 客户前端改为“产品亮点、使用场景、工厂与交付／供应与交付、定制合作、客户案例”；内部 `theme_id` 不变 | 用户一眼知道每类内容讲什么 |
| “成品待确认／正在生成”状态卡放在页面中间，造成大片空白 | 把机器人状态做成页面右下角的紧凑悬浮入口；制作中显示旋转圈，完成后显示“内容已经生成，等待你审核”。点击后统一打开右侧多任务抽屉 | 状态始终可见但不打断页面布局，不再占独立一行 |
| “交付与回收／等待交付”空面板过大 | 删除空面板；成片未生成时不展示交付区，成片生成后只在成果列表上方显示一行紧凑的交付状态和主要动作 | 没有结果时没有空白大框，有结果时直接处理预览、确认或下载 |

上述五项是本轮前端硬要求，不因后台仍保留旧字段而回退。删除的是重复展示，不删除任务、成片、交付状态或历史数据。

### 17.3 「内容制作」页面状态规则

| 进入方式 | 打开的界面 | 原因 |
| --- | --- | --- |
| 用户从左侧导航点击「内容制作」 | 主题任务页 | 这是所有新内容的统一入口 |
| 用户打开“主题待确认”的任务 | 原任务的主题确认步骤 | 先完成主题，不绕过最低条件 |
| 用户打开“待关联素材”的任务 | 原任务的关联素材步骤 | 选择或上传真实素材；通过常规两镜头门槛，或第 6.5.2 节两文件精确产品关联安全特例后确认使用，不进入制作台 |
| 用户打开“待补素材”的任务 | 原任务的素材步骤＋一份合并补拍清单 | 只补当前欠缺的对象／动作，已上传但未入选素材仍保留在素材库 |
| 用户在“可以制作”的任务上点击「开始制作」 | 原任务页＋右下角紧凑机器人状态入口 | 一次启动后台自动制作，不打开任何旧制作步骤 |
| 用户在“制作中”的任务上点击机器人入口 | 右侧多任务详情抽屉 | 查看同一次后台运行，不重复启动、不要求操作脚本／配音／字幕／剪辑 |
| 用户打开“需要处理”的任务 | 任务抽屉中的问题说明 | 只处理真实性、授权、文件损坏等必要问题；普通制作失败由系统自动重试或内部处理 |
| 用户打开“待验收”的任务 | 原任务的成果验收页 | 直接预览、反馈或确认成果 |
| 用户打开“正在整理交付包”的任务 | 原任务的交付进度页 | 查看处理进度，不重复创建交付包 |
| 用户打开“已暂停”的任务 | 原任务详情页 | 查看暂停原因并明确选择是否恢复 |
| 用户打开“已交付”的任务 | 原任务的交付页 | 查看版本并下载交付包 |
| 数字员工携带明确生产任务跳转 | 按任务当前状态打开原任务、问题说明、验收页或交付页 | 兼容已经排好的周计划和历史任务，不绕过最低条件，也不创建第二任务或打开旧制作台 |
| 用户再次从侧栏点击「内容制作」 | 回到主题任务页 | 防止用户被上一次任务锁在制作台 |
| 浏览器后退 | 恢复上一个主题页或任务页 | 页面状态和 URL／历史记录保持一致 |

前端只能通过当前任务 ID 打开任务详情、进度抽屉、验收页或交付页，不能仅凭浏览器里保存的“最近任务”自动进入其他任务或旧制作台。这样可以避免不同客户、不同标签页或上一次任务互相串线。`material / clone / product` 等内部路由值不得出现在 URL、客户表单、按钮或客户端可修改参数中。

### 17.4 前端完成定义

- [ ] 普通／高客单账号与验证期账号都能看到主题创作入口，且接口权限与页面一致。
- [ ] 内容制作首屏顶部只出现一句“选好视频主题并上传素材，编导 Agent 会先定导演方案，再由内容 Agent 生成视频，你只需审核成品。”，不再出现大标题、双按钮和右侧三张说明卡。
- [ ] 主题卡使用“产品亮点、使用场景、工厂与交付／供应与交付、定制合作、客户案例”五个通俗名称；内部主题 ID 与历史任务不变。
- [ ] 主题卡下方不再渲染重复的当前任务大卡；制作状态是右下角紧凑悬浮入口，不在页面中间单独占一行。
- [ ] 无成品时不展示“交付与回收／等待交付”空面板；有成品或交付包时只显示紧凑状态行和一个主要动作。
- [ ] 「内容制作」首屏和数字员工内容设置不再把旧三路线作为用户选择；客户流程不会进入旧制作工作台。
- [ ] 客户正常流程不再进入旧制作工作台；需要改主题时返回原任务，由编导 Agent 生成新导演方案版本和生产运行。
- [ ] 五类主题、自定义主题、即时生成和周计划在电脑端与移动端均可完成关键操作。
- [ ] 从主题任务点击一次“开始制作”时准确携带任务、产品事实版本、主题、结构来源、导演方案草案、素材修订和自定义具体诉求；返回后成果仍在原任务。
- [ ] 任务页不会显示含义重复的“进入内容创作／继续制作”按钮；唯一主按钮按业务状态切换为确认主题、关联素材、开始制作、验收成果、查看交付进度、恢复任务或下载交付包。
- [ ] 任务开始后右下角出现紧凑机器人状态入口；制作中显示编导／内容 Agent 当前接力阶段和旋转动效，不显示虚构百分比、复杂大进度板或页面中间的独立占位卡。
- [ ] 点击机器人入口打开右侧任务抽屉；多个任务按更新时间排列，逐项显示真实状态、当前自动步骤、完成产物和待用户动作；选中项显示“编导 Agent／内容 Agent”接力、导演方案摘要和可用主操作，但不显示内部状态码、运行编号、哈希或公式元数据。
- [ ] 数字员工角色／规则界面将“编导 Agent”作为独立角色展示，负责爆款参考分析、公式匹配（本轮为空）和导演方案锁定；“内容 Agent”只读执行已锁定方案。
- [ ] 开始制作后不出现脚本制作、口播制作、字幕制作或旧路线选择；真实素材导致的创意适配由编导 Agent 生成新导演方案版本，可查看版本差异；内容 Agent 不改写文案。
- [ ] 使用至少 2 个独立、相关且可信的真实镜头完成端到端浏览器验收：上传 → 任务级筛选 → 开始制作 → 编导 Agent 锁定导演方案 → 内容 Agent 按方案执行配音／字幕／配乐／渲染／质检 → 出现可播放 MP4 → 用户验收；后端无未处理异常。
- [ ] 只上传单张图片或一个有效片段时，页面显示一份简短的“待补素材”说明，不允许开始渲染，也不删除已上传素材。
- [ ] 企业知识产品页没有产品素材上传控件；从产品页跳转“我的素材”后自动按该产品筛选并可维护关系。
- [ ] 从任务上传素材后，“我的素材”立即可见同一对象；同一文件跨入口上传不会增加素材总数或生成制作台私有副本。
- [ ] 通用导航、任务跳转、刷新、前进／后退和重新登录都不会串任务或误进旧制作台。
- [ ] 页面只显示业务语言；公式 ID、模型、接口、内部路由和套餐内部名称不出现在客户界面。
- [ ] 确认页按唯一资料去重，准确显示“已关联／待新增”；启动失败后不得把同一资料重复计算。
- [ ] 主题镜头清单统一显示为“可选建议”，不出现“必拍”“全部满足后才能制作”等硬门槛文案。
- [ ] `formula_id = null` 的任务仍显示“开始制作”，客户界面不显示“缺少公式”、空公式卡、公式选择器或降级提示，并能完成制作与验收。
- [ ] 平台管理员的爆款公式库显示真实空状态；数据库、API 与页面均无示例、占位或默认公式。
- [ ] 上述每一行都完成真实浏览器验收，不能只以接口测试或组件渲染测试代替。

## 18. 实施顺序

产品实现和系统联调按以下顺序推进。内容生产主线优先满足当前客户的即时需求；渠道与企业微信在完成第一阶段公共底座后可以并行，不等待全部平台审核才交付内容生产。

### 第一阶段：统一数据模型与兼容边界

- 建立 `WeeklyPlan → ContentTask` 父子模型，并为单条任务增加 `weekly / instant` 模式、主主题、产品事实版本、素材引用和来源关系。
- 建立 `DirectorPlan / DirectorPlanVersion`、`director_source_type` 和完整 `directorPlanReference`。不可变版本使用 `status=ready|blocked` 与 `lock_status=locked|blocked`；`draft / director_revision_required` 属于任务编排阶段，`superseded` 属于作品替代关系。将现有 `script_source_type` 作为兼容映射。
- 建立“灵小枢统筹 → 编导 Agent 生成／锁定方案 → 内容 Agent 执行 → 经营 Agent 发布与监控 → 客服 Agent 承接咨询”的交接契约、幂等和审计事件。
- 建立 `FileBlob`、`Product / ProductVersion`、`MaterialAsset / MaterialRevision`、`MaterialProductLink`、`MaterialClip / MaterialThemeFit`、`TaskMaterialRef` 和 `KnowledgeEvidence` 的唯一主数据边界、租户隔离和版本规则。
- `FileBlob` 的正式文件统一使用 PocketBase 后端文件字段或其对象存储；应用服务器不持久保存视频。处理过程只使用操作系统临时目录，任务结束立即清理，异常遗留文件由短保留期清理任务回收；迁移前先核对引用与授权证据。
- 将现有企业知识中的产品图片／视频和任务临时文件迁移或引用到 `MaterialAsset`，按哈希去重并回填产品、任务关系；迁移验证完成前保留只读兼容，不复制底层文件。
- 实现可空的 `formula_id / formula_version`、覆盖完整导演配置的 `content_formula` 注册表和管理员配置接口；本轮公式表保持空，不通过 seed、migration、fixture、示例或导入写入任何公式。
- 建立导演方案结构来源优先级：正式公式优先，其次是灵感中心全片精确分析结构，然后是企业知识安全骨架，最后是严格受限的精确产品关联素材安全短片；本轮实际从第二级开始，并阻止任务原文与自由 CTA 直接进入口播／字幕。
- 本轮建立非强制 `material_suggestion`，不产生公式节点强约束；`material_requirement` 只在未来真实公式经独立产品决策、完成试跑并正式发布后启用。
- 保留内部 `material / clone / product` 字段仅用于旧草稿迁移和后台编排；新客户界面与客户 API 不接收路线选择，同一任务允许组合多个执行能力。
- 统一周任务、即时任务和拍摄任务上传服务，全部先创建或复用“我的素材”对象再建立任务引用，避免进入制作工作台后丢失或重复素材。
- 新领域对象和 API 去除特定低价套餐命名；旧套餐命名只保留兼容层，权益改由独立配额／entitlement 策略判断。
- 建立 `ChannelAdapter`、发布包、外部内容、指标快照和客服会话的通用 ID 与租户边界。
- 先迁移账号 Token 加密并补齐审计、幂等和持久任务队列，再开放新的账号连接或自动化能力。

### 第二阶段：即时生成主题入口

- 将内容创作首页改为五个主题入口。
- 完成主题 Brief、产品事实引用、导演方案草案、非强制拍摄建议、素材关联和一次开始制作；在零公式前提下依次尝试灵感结构、企业知识安全骨架或严格受限的精确产品关联安全路径，编导 Agent 锁定完整方案后由内容 Agent 完成配音、字幕合成、配乐、渲染、质检到验收 E2E。
- 加入任务级素材去重、质量、相关性和覆盖度筛选；既不足 2 个独立相关可信镜头，也不满足两文件精确产品关联安全特例时进入“待补素材”；达到适用门槛但素材有限时生成短版，不循环或末帧凑时长。
- 打通返回原任务、退回修改、重新提交和下载交付包。

### 第三阶段：我的素材自动整理

- 移除企业知识产品图片／视频上传入口，产品页改为展示关联素材并跳转到按产品筛选后的“我的素材”。
- 扩展素材的产品关系、主题、镜头功能、可选公式位置、任务、版本、停用和替换关系。
- 完成跨入口去重、上传后的自动分析、四种业务视图和拍摄任务回填。
- 建立网上内容双库：无明确许可的公开视频只保存为灵感参考及结构分析；有明确下载、商用和改编授权的文件才进入可商用素材库，并完整保存来源与授权证据。
- 首批整理 30 条具有明确下载、商用和改编许可的美妆 B2B 种子视频进入可商用素材库；灵感参考库按约 50 条容量建设，只对有许可内容保存原文件，不得以数量目标降低授权要求。
- 修复跨存储来源的编辑、删除、权限和租户隔离一致性。

### 第四阶段：周计划批量工作流

- 建立真实的视频矩阵规划和每条内容执行记录。
- 完成集中素材准备、代表样片、批量生产和批次反馈。
- 周计划与即时生成复用同一素材、可选公式、导演方案、作品和版本模型。

### 第五阶段：编导／内容 Agent 交接、空公式库与内容生产验收

- 在第一阶段可空公式数据和权限基础上，补齐完整导演级编辑、试跑、审核、发布、灰度、停用和审计 UI；**本阶段仍不置入任何爆款公式**，公式列表、匹配记录和使用记录保持空。
- 验证编导 Agent 必须产出完整 `DirectorPlanVersion`、内容 Agent 必须只读执行方案、`director_revision_required` 只回到编导 Agent，不允许内容 Agent 改写脚本。
- 用制造业和美妆 B2B 工厂的真实产品与素材完成双入口浏览器验收。
- 验证权限、任务恢复、导演方案版本／哈希、空公式库、租户隔离、失败重试和交付包完整性。

### 第六阶段：统一渠道与抖音发布包

- 将现有 TikTok、Instagram、Facebook、YouTube 能力收束到 `ChannelAdapter`，把 `tiktok` 迁移为 `tiktok_global` 兼容别名。
- 新增 `douyin_cn` 平台、规格校验、发布包模板、发布登记、内容 ID／公开链接凭证和待对账状态。
- 上线“发布与渠道中心”，默认无需账号授权即可完成发布包全流程。
- 用一个真实抖音账号完成人工发布包“生成 → 发布 → 回填 → 核验”的业务验收。

### 第七阶段：浏览器辅助发布与抖音官方接口

- 独立实现签名浏览器扩展／本地助手、回环端口、短时任务、用户在场、平台脚本版本和脱敏凭证。
- 先做抖音单平台小范围试点，最终发布前由用户确认；稳定后再评估其他平台，不同时铺开。
- 完成抖音官方应用、授权回调、Scope 门禁、Token 轮换、发布／状态接口和真实账号 E2E；平台权限未获批时保持关闭。
- 对现有海外直发进行统一 readiness 验收，修复真实 permalink、未知回执和断开授权问题。

### 第八阶段：持续内容监控

- 建立账号内容增量同步、发布内容对账和持久化调度，不再依赖用户打开页面触发更新。
- 接入抖音 `video.list`、`video.data` 及已授权海外平台数据；统一来源、新鲜度、`null` 语义和告警。
- 上线账号内容监控页，并用真实账号验证 Token 失效、限流、内容转私密、数据延迟和历史快照保护。

### 第九阶段：企业微信智能客服

- 接入微信客服账号、接待链接、会话分配、回调通知、`sync_msg` 游标同步、消息与媒体入库和发送回执。
- 复用现有企业知识，先上线 AI 草稿、知识引用和人工接管；自动回复只对白名单低风险意图灰度。
- 把发布包的来源参数带入会话，并完成内容 → 咨询的可核验归因。
- 用真实测试账号完成入站、草稿、人工发送、失败恢复、转接和统计 E2E 后，才将状态改为“已连接”。

## 19. 本版建议锁定的产品决策（确认后生效）

1. 首页数字员工解决周计划和批量生产；内容创作解决单条即时生成。
2. 在内容生产子流程中，用户只做三件事：明确主题、拍摄／上传素材、验收成果；发布和客服动作在各自工作台完成。
3. 主题回答“讲什么”，内容公式回答“如何完整导演”，素材限定“真实能展示什么”，导演方案回答“当前这条视频具体怎么说、怎么拍、怎么剪和怎么验收”。
4. V1 使用五个一级主题；痛点、实证、对比、趋势等降为公式／叙事角度。
5. 原有“素材、爆款裂变、产品”不再是客户入口、页面步骤或互斥路线，只保留为后台可组合执行能力和旧数据兼容字段；客户端不得提交或修改内部路由。
6. 周计划调用视频矩阵；即时生成不调用周矩阵，也不等待周计划。
7. 两个入口共用 `ContentTask`、产品事实版本、素材引用、可选公式、`DirectorPlan / DirectorPlanVersion`、作品、版本和交付模型；周计划额外使用 `WeeklyPlan` 父对象组织多条任务。
8. 爆款公式只允许平台侧内部内容运营管理员或平台超级管理员管理；普通用户和租户管理员默认不显示，服务端也不得放行。
9. 爆款公式是内容结构假设，不构成播放、询盘或成交承诺。
10. 素材上传后由系统自动整理；用户只处理无法判断、授权不明或高风险事实。
11. 一套专业核心能力服务验证期和高客单客户，套餐只控制额度、渠道、自动化权限和服务，不复制低质量产品分支。
12. 社媒账号登录不是默认入口；发布包是基础能力，浏览器辅助和官方接口按租户能力启用。
13. 浏览器辅助发布只使用客户本机已登录会话，V1 最终发布由用户确认，任何验证码、二次验证和平台风控都不绕过。
14. 国内抖音使用 `douyin_cn`，与 `tiktok_global` 完全分离；完整账号监控以正式授权为前提。
15. 监控必须显示数据来源、新鲜度和覆盖范围；没有可验证凭证不标记已发布，未知指标不写成 0。
16. 企业微信 V1 选择“微信客服”，默认 AI 草稿＋人工确认；低风险自动回复必须显式开启，高风险问题强制人工接管。
17. 本次仍不包含付费投流、报价订单、自动外呼、自动互动和完整销售 CRM。
18. 用户完成主题和产品后，素材必须通过两类门槛之一：常规路径至少 2 个独立、相关且可信的真实镜头；无事实宣称安全特例至少 2 份独立且与当前产品精确关联的真实上传文件。通过后只在原任务点击一次“开始制作”；后台先由编导 Agent 锁定完整导演方案，再由内容 Agent 按方案执行成片，不要求用户进入脚本、配音、字幕、剪辑或旧制作路线，也不创建第二任务。
19. 企业知识是企业／产品／买家／品牌事实及凭证的来源，其中 `Product` 是产品事实主数据；“我的素材”是图片、视频、音频等创作素材的唯一主数据。任务内快捷上传只创建或复用素材并建立关系，企业知识不再提供产品素材上传。
20. 用户任务原文只作为创作 Brief，绝不能直接作为口播或字幕；本轮自由 CTA 也只是意图，不直出。导演方案结构来源顺序固定为“管理员正式爆款公式 → 灵感中心全片精确分析结构 → 企业知识安全骨架 → 精确产品关联素材的无事实宣称安全短片”。
21. 素材是否入选只在任务级判断；系统不得因为当前任务不用而删除用户素材。素材不足时缩短内容，不循环镜头、不停留末帧凑时长；常规两镜头门和两文件精确产品关联安全特例都未满足时等待补拍。
22. 网上采集视频分为灵感参考库和可商用素材库。只有明确允许下载、商业使用和改编的素材才进入后端素材库；元数据存 PocketBase 集合，文件存 PocketBase 后端文件字段／对象存储。应用服务器不持久保存视频，处理仅使用操作系统临时目录并清理，同时保留来源和授权证据。
23. 编导 Agent 独立负责结构、脚本、口播、字幕、镜头计划、音乐与节奏、素材使用与补拍建议、质量验收点，并将 `status=ready && lock_status=locked` 的追加式不可变 `DirectorPlanVersion` 交给内容 Agent。
24. 内容 Agent 只按已锁定导演方案生成视频和做必要技术性素材适配，不得重新选结构，不得改写脚本、口播、字幕文字、核心主张或 CTA；方案不可执行时返回编导 Agent 生成新版本。
25. 爆款公式库、管理员入口和完整导演级数据模型保留，但本轮乃至本 PRD 90 天计划内不录入、不导入、不预置任何公式；任务按“全片精确分析结构 → 企业知识安全骨架 → 精确产品关联素材的无事实宣称安全短片”降级，仍必须由编导 Agent 产出完整导演方案。
