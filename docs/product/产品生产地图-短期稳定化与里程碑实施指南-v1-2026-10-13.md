# 产品生产地图：灵枢 AI 全链路生产能力与里程碑实施指南

日期：2026-10-13
版本：v1（范围纠正版）
状态：本轮已落地基线（M0/M1 底座）与 M2+ 路线规划的主实施依据
设计依据：`PRD-灵枢AI全系统UI设计规范-v2-2026-10-09.md`

## 1. 范围纠正与文档权威

本文中的“产品生产地图”指的是**灵枢 AI 这套软件产品从发现内容机会到交付和复盘的完整生产能力地图**，不是“用户所售商品的视频生成地图”。

用户商品、包装、SKU、标签替换、货架和流水线等能力仍然重要，但它们只是“视觉素材生产”阶段的一个子域。相关细节已迁移到：

- `用户商品镜头生产子地图-现有技术栈实施附录-v1-2026-10-13.md`

发生冲突时，以本文为准。任何后续 PRD、代码、前端文案、数字员工提示词和灵小枢动作，都不得再把“产品生产地图”缩窄为 SKU 视频生成。

## 2. 本轮目标

本轮不以增加最多的模型和按钮为目标，而以**在现有技术栈上快速提高全链路成功率**为目标：

1. 所有入口先落到同一条可恢复的生产任务，不再由页面本地状态各自推进。
2. 系统只承诺当前真实接通、具备输入、成本和质量门禁的能力。
3. 素材缺口先由系统复用、检索、改镜、数字人、动效、确定性合成或已接入 AIGC 解决；实拍是可选补充，不是默认答案。
4. 付费执行前展示可解释报价和成本上限，执行后记录真实费用，缓存命中不得重复收费。
5. 数字员工负责跨阶段推进，灵小枢负责解释、收集最小输入和承接异常，而不是只做一个悬浮聊天入口。
6. 删除或停用绕过统一任务、预算和质检的旧入口，减少试用卡点和不可恢复的半成品。
7. Blender、3D 建模、动态视频换标等当前缺少的技术栈暂不进入正式自动路线。

### 2.1 实施状态口径

本文使用以下口径，表格中的“已有”与“规划”不得混用：

- **本轮已落地**：仓库内已有合同、持久化／路由或前端消费代码，并有对应回归测试；只承诺已接入的社媒内容主链和 Studio 路径，不代表所有历史入口均已迁移。
- **当前已有**：系统原有可用能力；需继续受现有运行环境、适配器、预算和 QA 门禁约束。
- **本轮部分收口**：新读模型或门禁已落地，但仍有历史写路径、供应商回执或页面待迁移。
- **M2+ 路线规划**：尚未作为当前可执行能力交付，不得出现在正式能力选择器、报价或成功率承诺中。

文中“退出标准”是里程碑验收条件，不等于这些条件在本轮已全部达成。

## 3. 全链路定义

灵枢的生产链不是“生成一段视频”，而是：

```text
内容机会发现
  → 可生产性与获客价值评估
  → 任务与目标冻结
  → 脚本／口播／分镜
  → 素材与生产输入供给
  → 能力选路与成本预检
  → 逐镜执行
  → 质量门禁与失败恢复
  → 剪辑、字幕、配音与渲染
  → 人工验收与交付
  → 发布、指标回流与复盘
```

每一阶段必须回答六个问题：

- 当前事实来源是什么；
- 谁是运行时负责人；
- 需要什么最小输入；
- 使用哪个已经接通的执行器；
- 最大可能成本是多少；
- 成功、阻塞、失败和恢复分别如何判断。

## 4. 产品原则

### 4.1 单一生产真值

统一生产任务是所有页面、数字员工、Studio、后台执行器和任务中心的事实来源。`localStorage`、URL 参数和页面 state 只能承担导航提示，不能承担任务状态、成本、素材绑定或完成状态。

### 4.2 规划能力必须等于执行能力

能力只有同时满足以下条件，才可显示为“可执行”：

- 运行环境已接通；
- 输入合同完整；
- 执行适配器存在；
- 预算可计算且未超过上限；
- 质量检查器存在；
- 失败后有明确回退或可恢复输入请求。

只有配置名称、提示词、设计稿或供应商宣传，不构成灵枢能力。

### 4.3 用户只补系统无法推断的最小输入

系统不得把“缺少现成素材”直接翻译成“请去拍摄”。需要区分：

- 系统能从企业素材、共享库存或参考库复用；
- 系统能用数字人、动效、图文、确定性合成或现有 AIGC 生产；
- 原镜头可改成同功能、更易生产的镜头；
- 只有事实、权利、身份或精确主体无法推断时，才向用户请求输入；
- 用户实拍始终是明确选择后的补充路线。

### 4.4 生成不等于通过

媒体文件生成完成后仍必须经过解码、时长、画幅、字幕、主体、事实、身份和渲染完整性检查。前端不得用“已生成”替代“可采用”或“已交付”。

### 4.5 优先复用和确定性生产

默认优先级：

```text
缓存命中
→ 已有企业素材
→ 已授权共享素材／已入库参考素材
→ 裁切、拼接、字幕、动效和确定性合成
→ 已接入且通过准入的 AIGC
→ 改镜或降级表达
→ 用户主动选择的实拍
```

### 4.6 不虚构事实

通用工厂、展会、客户、效果或证书画面可以承担环境和解释功能，但不能被描述成客户自己的真实工厂、真实采访、真实效果或真实认证。缺少真实证据时，应改写为流程说明、示意画面或事实卡片。

## 6. 当前技术栈与近期边界

### 6.1 近期可依赖

- 社媒任务、来源、包选择、产物、交付和指标合同；
- Studio 项目、逐镜候选、素材绑定和渲染链；
- 企业素材库、产品表素材投影、共享素材库存；
- 数字人、TTS、字幕和多语言链路；
- FFmpeg、Sharp、Remotion；
- 已接入的 Gemini、Qwen、Seedream／Seedance 等服务；
- durable job、checkpoint、幂等、任务事件和已有成本记录；
- 现有设计令牌、Ant Design 和共享前端组件。

### 6.2 有代码但不得扩大承诺

- 能调用供应商不等于质量稳定；
- 能生成首帧不等于跨帧主体稳定；
- 语义评分不等于真实 OCR；
- 配置项存在不等于运行环境具备密钥和额度；
- 素材库里有参考视频不等于获得商业使用权；
- 旧页面显示“生成中”不等于后台存在 durable job；
- 旧估算费用不等于供应商已经结算的实际费用。

### 6.3 本轮明确不实现

- Blender、CAD、USDZ、3D 数字孪生建模与渲染；
- 未接入的视频对象分割、曲面跟踪、动态去物、跨帧换标；
- 未接入的 Product Swap、Aleph、VACE、ProPainter 等能力；
- 透明、高反光、柔性包装的自动精确替换；
- 强手物交互和复杂物理过程的自动精确复刻；
- 任何缺少运行适配器、报价或 QA 的新供应商能力。

暂缓能力可以保留为 `planned` 或 `unsupported` 的后台目录项，但不得出现在正式选择器、报价、成功率或“系统可完成”的用户文案中。

## 7. 统一领域模型

### 7.1 Canonical Task

每次从自由创作、爆款复刻、灵感中心、周计划或数字员工进入生产，都必须获得同一个 canonical task ID。任务至少保存：

- 业务目标、平台、受众和 CTA；
- 当前确认的脚本／分镜版本；
- 来源素材和版本；
- 产品、人物、品牌和事实绑定；
- 生产模式、管理模式和预算边界；
- 输入请求、候选、产物、成本与质量状态；
- 可恢复 checkpoint 和当前允许命令。

### 7.2 Production Read Model

前端和数字员工只能消费统一投影，不自行拼接状态。本轮已落地合同以 `shared/contracts/productionReadModel.ts` 为唯一代码事实；顶层结构如下（嵌套类型名同样定义在该合同中）：

```ts
type ProductionReadModelV1 = {
  schemaVersion: 'production-read-model.v1';
  authority: 'canonical_task';
  project: {
    kind: string;
    id: string;
    version: string;
    title: string;
    taskStatus: string;
    runId: string | null;
    studioProjectId: string | null;
    studioProjectVersion: string | null;
    studioProjectStatus: string | null;
    studioProjectConflict: boolean;
  };
  aggregate: {
    stage: ProductionPipelinePhase;
    status: ProductionReadStatus;
    executable: boolean;
    identityGuarantee: ProductionIdentityGuarantee;
    inputs: ProductionInputSummary;
    cost: ProductionCostSummaryV1;
    blockers: ProductionBlocker[];
    counts: {
      total: number;
      ready: number;
      running: number;
      needsInput: number;
      blocked: number;
      review: number;
      completed: number;
    };
    phases: Array<{
      phase: ProductionPipelinePhase;
      status: ProductionPipelinePhaseStatus;
    }>;
    allowedCommands: ProductionAllowedCommand[];
  };
  shots: ProductionShotReadModelV1[];
  updatedAt: string;
};
```

其中 `ProductionReadStatus` 的已落地取值为 `planning | needs_input | ready | running | rendering | quality_review | review_ready | completed | paused | failed | blocked`；`ProductionPipelinePhase` 为 `planning | input | production | render | qa | review`。项目 ID 位于 `project.id`，镜头计数位于 `aggregate.counts`，不得再创造顶层 `taskId`、`currentStage`或另一套 `aggregate.total`字段。

不得由页面根据“有没有 URL”“有没有素材”“按钮点过没有”自行推断任务完成。

### 7.3 Capability Registry

每项能力登记：

- `capabilityId`、版本、状态和运行时负责人；
- 支持的输入签名和输出合同；
- 使用的 adapter 和运行环境准入；
- 固定成本、变动成本、重试上限和并发限制；
- 必须执行的 QA；
- 回退链；
- 按条件签名统计的真实首轮通过率、最终通过率和失败原因。

成功率不能写成全局静态常数，也不能把实验能力包装成稳定能力。

### 7.4 Production Input Request

输入请求是跨系统的通用对象，不应只叫“商品素材请求”或“拍摄任务”。本轮已落地合同以 `shared/contracts/productionInputRequest.ts` 为准：

- `category`：`product_asset | fact_evidence | person_authorization | scene_plate | digital_human_input | account_authorization | production_choice | other`；
- `kind`：`product_front_image | product_side_image | product_back_image | product_detail_image | product_transparent_png | product_label_artwork | product_packaging_dieline_pdf | product_dimensions | fact_evidence | person_authorization | scene_plate | digital_human_portrait | digital_human_voice_sample | account_authorization | production_choice | content_clarification | other`；
- `status`：`open | partial | fulfilled | waived`；
- `fulfillment.type`：`material | document | structured_data | authorization`；
- 任务和镜头关联通过 `bindings: Array<{ taskId; shotId? }>` 表达，非商品主体通过 `subjectRef` 表达。

`product_asset` 只是通用请求的一个类别；`ProductAssetRequest` 和 `/studio/product-asset-requests` 是商品资料消费方的兼容视图。Read Model 使用另一组交互投影类型：`material | product_asset | presenter_asset | reference_media | fact_confirmation | rights_confirmation | account_authorization | production_choice | budget_confirmation | shooting_media | quality_review | other`；这些是投影层 `ProductionInputKind`，不是持久化层的 `category/kind`。

对外 HTTP 只提供租户隔离的输入请求查询和商品兼容视图。创建、履约和豁免必须由已校验的生产工作流在服务端调用领域函数；浏览器不能用伪造 `materialId`、授权字符串或直接 `waive` 清除阻塞。普通商品素材通过现有上传、租户归属和 Material Asset V2 分类校验后自动履约；账号和人物授权必须走对应授权系统。

`person_authorization` 只表示人物授权，不应冒充音乐、素材或其他内容权利的通用类别。本轮合同对其他权利尚无专用 `kind`；必要时只能以 `other + subjectRef + specification` 保守记录，M2+ 如要自动路由应先版本化扩展合同。

已落地合同通过 `title`、`instructions`、`required`、`blocking`、`minimumItems`、`acceptedMimeTypes`、`specification`、`bindings` 和 `fulfillments` 表达原因、最小输入、影响镜头与履约情况。截止时间、结构化替代路线和取消后果尚没有独立类型字段；如果 M2+ 需要用于自动编排，应版本化扩展合同，不得假设当前已持久化。

### 7.5 Material Asset V2

素材不再默认等于产品素材。统一素材至少区分：

- 所有者与租户；
- 权利和使用范围；
- 来源类型；
- 是否绑定具体商品；
- 主题、人物、环境、动作和镜头功能；
- 可用片段、质量、画幅和时长；
- 内容哈希和分析版本；
- 复用次数和历史效果。

工厂、展会、办公、仓储、人物动作、转场、音乐和图形都可作为企业通用素材上传，不得强制绑定具体产品。

## 8. 素材供给与高频复用

### 8.1 素材供给层级

1. 当前任务已经绑定且通过权利检查的素材；
2. 同企业、同主体或同主题历史素材；
3. 企业通用素材；
4. 权利明确的共享库存；
5. 已入库参考素材，仅在权利允许时进入成片；
6. 图文、动效、数字人和确定性合成；
7. 已接入 AIGC；
8. 改镜；
9. 用户主动选择实拍。

### 8.2 可复用对象

- 数字人身份、音色和口播样式；
- 平台安全区、字幕、片尾和 CTA 模板；
- 工厂、展会、仓储、办公、货架等环境底板；
- 常见人物动作和 B-roll 片段；
- 商品身份包和确定性商品镜头模板；
- 分镜结构、节奏、转场和音效模板；
- QA 规则、供应商输入和输出转换器；
- 已确认的企业事实、禁用表达和权利边界。

### 8.3 缓存键

缓存至少由以下内容形成：

```text
capabilityVersion
+ sourceContentHash/sourceVersion
+ frozenScriptOrShotVersion
+ identityAndFactVersion
+ renderParameters
+ providerAndModelVersion
+ validatorVersion
```

输入未变化时不得重复调用付费模型。只变更字幕时，不应让已经通过的视觉镜头失效；只变更一个镜头时，不应重跑整条视频。

## 9. 可生产性与获客价值评分

### 9.1 不要求人工逐条完整拉片

评分采用“机器初筛＋结构化分析＋规则计算＋边界人工复核”：

1. 采集层计算来源完整性、时长、画幅、清晰度和重复度；
2. 分析层提取钩子、叙事角色、镜头、口播、主体、动作、证据与 CTA；
3. 规则层结合当前能力注册表、素材库存、成本上限和目标客户价值评分；
4. 只有低置信度、事实敏感、权利不明或高成本项目进入人工复核；
5. 发布后的播放、有效互动、线索和成交回流校准权重。

### 9.2 评分维度

- 获客价值：目标买家相关度、问题强度、信任证据、CTA 承接；
- 浏览价值：前三秒、信息密度、节奏、视觉变化、完播假设；
- 生产可行性：素材覆盖、执行器准入、输入缺口、QA 可验证性；
- 成本效率：预计上限、缓存和复用机会、重试风险；
- 事实与权利：当前可适当降低合规权重，但不能伪造客户事实、授权或主体身份。

### 9.3 输出不是一个总分

至少输出：

- 是否入选；
- 推荐生产路线；
- 必须保留的爆款因子；
- 可替换的表达；
- 最小输入请求；
- 成本上限；
- 预计成功率的证据与样本量；
- 失败后的功能等价改镜。

## 10. 路由与执行规则

### 10.1 生产前准入

每个镜头按以下顺序判断：

1. 该镜头承担什么内容功能；
2. 是否包含真实事实、身份、权利或可读文字；
3. 当前素材是否已经覆盖；
4. 哪些现有执行器能够接受当前输入；
5. 各路线的成本上限、延迟、质量门禁和回退是什么；
6. 选择成本最低且满足事实和质量要求的路线；
7. 无路线时改镜；仍不可行时才创建最小输入请求。

### 10.2 禁止的旁路

- 缺素材时直接调用 Seedance 或其他付费模型；
- 没有稳定幂等键时重复提交；
- 未报价先执行；
- 未做身份或事实输入就声称精准；
- 将永久阻塞显示为“稍后自动恢复”；
- 用客户端按钮状态代替后台任务状态；
- 失败后自动创建拍摄任务；
- 让数字人承担未验证的人货物理接触；
- QA 失败后自动采用失败候选。

### 10.3 失败恢复

失败必须归一为：

- `retryable_runtime`：限流、临时网络、供应商短暂失败；
- `input_required`：缺少事实、权利、身份或必要选择；
- `quality_failed`：结果存在明确质量问题；
- `unsupported`：当前技术栈无法完成；
- `budget_blocked`：报价或实际费用超过边界；
- `cancelled`：用户或系统明确终止。

只有 `retryable_runtime` 可以自动重试；其余状态需要改镜、输入、审批或能力变化。

## 11. 成本系统

### 11.1 付费前报价

报价应包含：

- 固定准备成本；
- 每秒、每张、每字符或每次调用的变动成本；
- 预计调用次数；
- 最大自动重试次数；
- 重试储备；
- 缓存减免；
- 含税或汇率口径；
- 预计值和不可突破的上限。

### 11.2 预留与结算

```text
提交前：quote → 用户阈值检查 → reserve
执行中：记录每次 attempt 和 provider receipt
完成后：settle actual → 释放未使用 reserve
失败后：有可核验账单时结算真实费用 → 释放剩余 reserve
账单未知：保留 reserve 和 `actual = null` → 收到可核验回执后再结算
```

未知费用不能显示为 0；预计费用不能写入实际费用；失败重试不能覆盖前一次真实账单。

### 11.3 复用成本

模板、数字人、环境底板、商品身份包和 QA 规则的首建成本与单次执行成本必须分开。前端需要显示“本次增量成本”和“首次建设后预计复用成本”。

## 12. 数字员工与灵小枢

### 12.1 经营数字员工

- 冻结目标、预算、账号和产量；
- 判断是即时任务还是计划任务；
- 在跨任务冲突时决定优先级；
- 不直接替编导或执行器生成媒体。

### 12.2 编导数字员工

- 把参考结构和企业目标变成原创脚本与分镜；
- 明确每个镜头的功能、事实边界和可替代部分；
- 只选择能力注册表中已准入路线；
- 对不可生产镜头自动提出功能等价改镜。

### 12.3 内容数字员工

- 匹配素材、数字人、动效、合成和 AIGC；
- 提交逐镜报价和执行；
- 管理候选、QA、重试和渲染；
- 不绕过成本、权利和质量门禁。

### 12.4 灵小枢

灵小枢承担交互责任：

- 用用户语言解释当前阶段、责任人、费用和阻塞原因；
- 根据 read model 只展示当前允许动作；
- 收集最小输入并引导用户进入已校验的上传、授权或选择流程；由服务端工作流写入或履约正式 input request，灵小枢不直接调用治理写接口；
- 对生产缺口先解释已接通的系统路线；仅有未接执行器的候选时明确标为“需确认／待改镜”，不得显示为可执行，也不默认让用户拍摄；
- 帮用户定位素材库、任务、Studio、验收和发布页面；
- 对高成本、事实敏感和不可逆动作请求明确确认；
- 不直接在聊天中绕过任务合同调用付费生成。

## 13. 前端交互要求

### 13.1 页面共用状态语义

- `系统处理中`：存在真实后台 job；
- `需要你补充`：存在 active input request；
- `等待验收`：候选已完成且 QA 达到人工复核条件；
- `已完成`：正式产物已通过并持久化；
- `失败`：已经有可读失败类型和下一步；
- `暂不支持`：当前能力缺失，不提供虚假按钮或费用。

不得显示虚构百分比或无依据成功率。

### 13.2 生产卡片

每个任务和镜头卡片至少显示：

- 当前阶段与正在执行的真实动作；
- 使用的素材来源和能力；
- 是否需要真实主体／事实精度；
- 预计成本上限、实际费用或“尚未结算”；
- 质量状态；
- 阻塞原因；
- 由后端 `allowedCommands` 决定的操作。

### 13.3 素材上传

- 默认允许“企业通用素材（不绑定产品）”；
- 只有具体商品身份素材才要求关联商品；
- 上传后明确显示来源、权利和可复用范围；
- 通用素材和商品素材都进入同一素材库，但筛选维度不同。

### 13.4 生产缺口

旧“拍摄任务”主入口改为“生产缺口”。主操作是“让灵小枢选路”；“上传现有素材”和“可选实拍”作为次级操作。旧的一键 Seedance 旁路必须移除。

## 14. 兼容与迁移

### 14.1 不与原功能冲突

- 保留旧字段读取，新增字段采用版本化可选扩展；
- 写入统一新模型，读取时兼容历史任务；
- 已有 Studio 项目不强制迁移，重新打开时投影到 read model；
- 已有商品素材关联继续有效，空关联只表示企业通用素材；
- 现有数字人链保持原执行器，仅改为消费统一任务和成本状态；
- 旧 localStorage handoff 暂时保留为导航兼容，但不再是事实源；
- 所有新行为先对新任务启用，历史任务只做安全投影。

### 14.2 Feature Flag

以下是 M2+ 灰度规划的建议开关名，不是当前仓库已全部存在的运行配置：

- `production_read_model_v1`；
- `canonical_studio_task_handoff`；
- `production_input_requests_v1`；
- `production_cost_quote_v1`；
- `material_asset_v2`；
- `assistant_production_routing_v1`。

关闭开关必须回到原可用流程，而不是删除数据。

### 14.3 数据迁移

迁移顺序：

1. 只读投影历史任务；
2. 双写新任务的 task、input、cost 和 material 元数据；
3. 对账状态和成本；
4. 前端切读 read model；
5. 停止旧路径写入；
6. 观察期结束后删除死代码。

## 15. 应删除或停用的废功能

满足替代条件后删除：

- 规划页只写 `localStorage`、不创建 canonical task 的旧主链；
- 素材上传强制绑定具体商品；
- “没有匹配素材＝优先补拍”的客户端判断；
- 生产缺口直接调用通用 Seedance 的旁路；
- 无报价、幂等和 QA 的“AI 生成素材”按钮；
- 动态商品必须用户提供真实视频、工厂镜头必须用户实拍的全局硬编码；
- 把永久 `input_required` 显示为“暂停后会自动恢复”；
- 将估算费用写成实际费用；
- 页面自行组合多份状态并推导完成度；
- 静态写死的全局成功率；
- 已被 canonical task 覆盖的重复临时任务对象。

删除前必须满足：替代路径已启用、历史数据可读、回归测试通过、日志中无活跃调用。不要为了“清理”直接删除仍被历史任务读取的兼容字段。

## 16. 里程碑路线

### M0：全链路止血与事实统一

目标：先消除最容易造成试用失败、重复费用和假状态的问题。

状态：**本轮已落地社媒生产主链基线，全历史入口迁移仍需按退出标准回归。**

本轮已落地：

- 建立 `production-read-model.v1`，并挂载到 canonical social task 详情；
- 社媒创作规划进入 Studio 前创建或复用 canonical task，不再仅依赖本地 handoff；
- 收紧能力准入，缺 adapter／输入／预算／QA 的能力不进入自动规划；
- `input_required` 映射为明确的 `needs_input`，不再假等待；
- 实际费用、未结算预计和未知费用分开；
- 移除素材缺口直接付费生成旁路；
- 素材元数据支持 `enterpriseCommon` 和 Material Asset V2，前端允许企业通用素材不绑定商品；
- 工厂和动态商品镜头不再默认创建实拍阻塞；命中已接执行器的路线才可继续，未接通的“系统改写／系统动作”候选保持 `needs_input`，并要求确认改镜或绑定已授权素材；
- 保留商品镜头子地图已经完成的安全能力边界。

退出标准：

- 任一入口都能获得 task ID；
- 任一按钮都能对应后端允许命令；
- 不会出现“前端生成中、后台无任务”；
- 不会在缺报价时调用付费执行；
- 不会把未知成本显示为 0；
- 不会把系统可替代的素材缺口强制变成实拍。

### M1：输入、素材与成本底座

目标：让任务在缺输入、素材复用和费用控制上可解释、可恢复。

状态：**本轮已落地通用持久化、租户隔离只读 API 和读模型投影底座；可变更写入只向已校验服务端工作流开放。所有供应商执行器和历史页面的全量接入仍待完成。**

本轮已落地：

- 通用 `production_input_requests` 的创建／复用、查询、履约、豁免领域能力与商品资料兼容视图；HTTP 写入已收口为服务端验证工作流；
- Material Asset V2 与片段候选元数据；
- 企业通用素材、商品素材和共享素材的明确边界；
- `production_cost_quotes`、报价行、上限、预留、结算与失败对账；浏览器不能提交实际费用或供应商回执；
- 输入请求和报价的稳定去重键与租户隔离；
- canonical task 读模型消费持久化输入请求和成本报价。

待继续收口：各外部供应商的 receipt 全量对账、所有旧页面的输入请求卡、跨能力缓存收益统计。

退出标准：

- 每个阻塞都能指向具体 input request；
- 输入补齐后从 checkpoint 恢复，不重开任务；
- 同一素材和输入版本不重复分析或收费；
- 成本可从 quote 对账到 provider attempt 和 actual。

### M2：现有技术栈的稳定生产主链

目标：不增加缺失技术栈，先把已有能力组合成稳定路线。

状态：**M2+ 路线规划，不属于本轮已完成交付。**

交付：

- 数字人＋TTS＋字幕＋独立商品镜头组合；
- 企业素材／共享库存的片段匹配、裁切和拼接；
- 图文、信息卡、CTA、模板动效；
- 工厂、展会、仓储等环境素材复用和非证据性改写；
- 已接入 AIGC 的准入、报价、重试和 QA；
- 商品静态、基础动效和现有确定性合成子能力；
- 失败后的功能等价改镜；
- 单镜候选、验收、重试和渲染闭环。

退出标准：

- 每条正式路线都有 adapter、输入、成本和 QA；
- 自动任务没有 Blender 等未接入依赖；
- 单镜失败不导致整条视频重跑；
- 缓存和模板复用能稳定降低增量成本。

### M3：前端、数字员工与灵小枢协同

目标：让用户看到同一个真实生产过程，并在需要时得到明确帮助。

状态：**本轮已完成部分读模型、按钮权限和决策卡接入；完整的 M3 是 M2+ 路线规划。**

交付：

- 任务中心、Studio、数字员工页统一 read model；
- 生产状态卡、成本卡、输入请求卡和 QA 卡；
- `allowedCommands` 驱动按钮；
- “生产缺口”替代默认“拍摄任务”；
- 灵小枢能读取任务上下文、解释路线、收集输入和导航；
- 数字员工按职责推进，不重复创建任务或绕过 Studio；
- 完整遵循 UI v2 规范、Ant Design 模式、键盘与减少动效设置。

退出标准：

- 同一任务在所有页面显示一致状态；
- 用户能从任一阻塞直达正确输入位置；
- 灵小枢不提供后台当前不允许的动作；
- 刷新、返回、跨页和失败恢复不丢任务上下文。

### M4：受控扩展和真实样本验收

目标：只扩展有真实业务价值、能被验证的新能力。

状态：**M2+ 路线规划。**

候选顺序：

1. 更完整的授权素材采购／入库闭环；
2. 现有 AIGC 供应商的结构化 adapter 和更强 QA；
3. 商品镜头子地图中的同容器换标或流水线能力；
4. 其他通过样本矩阵证明的能力。

每项能力必须先完成离线样本、灰度、成本、失败分类和人工验收，再从 `experimental` 升为 `supported`。仍不实现 Blender 和未接入 3D 路线。

### M5：清理、指标校准和规模化

目标：删除已经被替代的路径，并以真实业务结果更新选路。

状态：**M2+ 路线规划。**

交付：

- 删除观察期内无调用的旧旁路和重复状态；
- 按能力、输入签名、平台和镜头类型统计首轮通过率、最终通过率、P50/P90 成本与延迟；
- 将发布、线索和成交回流到获客价值评分；
- 自动调整默认路线，但每次调整保留可审计版本；
- 建立模板复用收益和供应商质量看板。

退出标准：

- 生产成功率和成本来自真实样本；
- 路由变化可解释、可回滚；
- 废功能不再有运行时调用；
- 用户试用链路不依赖开发者手工修复状态。

## 17. 测试与回归

### 17.1 必测入口

- 自由创作无素材；
- 自由创作有企业通用素材；
- 爆款复刻已有任务；
- 灵感中心首次发起；
- 数字员工周计划交接；
- Studio 历史项目恢复；
- 单镜重试和整片渲染；
- 任务完成后发布和指标回流。

### 17.2 必测能力组合

- 纯数字人口播；
- 数字人＋商品独立镜头；
- 企业素材剪辑；
- 通用工厂／展会环境＋事实改写；
- 图文动效＋字幕＋配音；
- 条件 AIGC 成功、QA 失败和预算阻塞；
- 精确商品图但无动态视频；
- 完全无素材时的系统选路；
- 用户主动选择可选实拍。

### 17.3 故障注入

- 供应商 429、超时和返回空结果；
- 进程重启和任务重复投递；
- 预算在执行前后变化；
- 素材被删除或版本变化；
- 产品、人物或事实绑定失效；
- QA 通过后渲染失败；
- 前端刷新、跨页和多标签页并发；
- 发布账号失效。

### 17.4 回归要求

- 历史任务可读；
- 已有数字人流程不倒退；
- 用户已选择的素材和路线不被后台静默覆盖；
- 失败步骤重试不重复收费；
- 通用素材上传不要求产品；
- 真实商品素材仍能按产品精确筛选；
- 所有用户可见成本和状态可追溯到持久化记录；
- 无部署行为，除非当前任务另有明确授权。

## 18. 监控指标

### 链路指标

- 入口到 task 创建成功率；
- task 到首个可执行计划的成功率和耗时；
- `needs_input` 的原因、数量和解决时长；
- checkpoint 恢复成功率；
- 前端状态与后台状态不一致次数。

### 生产指标

- 按能力签名的首轮和最终通过率；
- 单镜重试次数；
- 改镜率；
- 人工复核率；
- 渲染和导出成功率。

### 成本指标

- 报价与实际偏差；
- 未知成本任务数；
- 缓存命中和节省金额；
- 每条成片、每个通过镜头和每条有效线索成本；
- 供应商失败但已计费次数。

### 业务指标

- 完播、互动、私信、询盘和有效线索；
- 不同生产路线的获客转化；
- 高频模板复用次数；
- 用户主动实拍比例，目标是只在确有必要时发生。

## 19. Definition of Done

一项优化只有同时满足以下条件才算完成：

- 进入统一 task；
- 有版本化输入和输出合同；
- 有真实 adapter；
- 有运行时准入；
- 有付费前报价和上限；
- 有稳定幂等键；
- 有 QA 和失败分类；
- 有 checkpoint 恢复；
- 前端消费统一 read model；
- 数字员工和灵小枢知道自己的责任；
- 历史任务兼容；
- 自动化、故障注入和端到端测试通过；
- 没有把未接入能力写成可用；
- 没有新增平行状态机或页面专用组件体系。

## 20. 当前实施顺序

当前代码基线已完成：`production-read-model.v1`、社媒规划页 canonical task 交接、通用 Production Input Request、Material Asset V2、Production Cost Quote／预留／结算底座、素材缺口保守选路（未接执行器的 fallback 保持 `needs_input`），以及部分 Studio／数字员工／灵小枢投影接入。上述“已完成”仅指当前提交覆盖的主链，不自动扩展为所有历史任务和供应商。

后续顺序固定为：

1. 对 M0/M1 已落地主链做完整回归，补齐旧入口和外部 provider receipt 的投影／对账；
2. 使所有仍在使用的创作入口、任务中心、Studio 和数员工共用 canonical task 与 `allowedCommands`；
3. 再用现有数字人、素材剪辑、动效、字幕、配音和已接入 AIGC 完成 M2 稳定组合路线；
4. 完成 M3 全页面一致交互、故障注入和真实小样本验收；
5. 观察稳定后删除旧路径；
6. 再评估 M4，不为当前缺失的 Blender／3D 等技术栈预留虚假入口。

这份路线的核心承诺是：

> 灵枢先把已经拥有的能力连成一条真实、低成本、可恢复的生产链，再扩展新的生成能力。用户看到的每一个状态、按钮、费用和“可生产”结论，都必须能被同一个后台事实证明。
