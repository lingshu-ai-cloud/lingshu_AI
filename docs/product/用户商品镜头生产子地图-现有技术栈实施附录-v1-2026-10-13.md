# 用户商品镜头生产子地图：现有技术栈实施附录

日期：2026-10-13
版本：v1
状态：灵枢全链路生产能力地图的下位附录（本轮已落地安全基线＋M2+ 商品镜头路线规划）。本文只描述“用户所售商品/SKU 镜头”的生产能力，不代表灵枢软件产品的完整生产地图，也不能单独决定全系统里程碑。全系统实施以同目录下《产品生产地图：灵枢 AI 全链路生产能力与里程碑实施指南》为准。

> 边界修正：本文中的“产品”仅指用户商品、包装和 SKU；“产品生产地图”中的“产品”指灵枢 AI 软件产品。此前将两者混用的表述已废止。

## 1. 文档目的

本轮优化不追求一次性补齐所有用户商品视频镜头能力，而是用最短路径解决以下问题：

1. 让系统只推荐当前真正能执行的生产路线，避免“规划时可用、执行时失败”。
2. 优先复用已有素材、产品图、模板和本地合成能力，降低外部生成次数与失败率。
3. 把产品身份与场景底板解耦：系统解决场景，用户主要提供产品身份资料，不默认要求拍摄现场视频。
4. 把高频镜头沉淀为可复用模板，成本按“首次建设＋单次复用”计算。
5. 对缺少技术栈的能力明确标记为“暂不实现”，不能进入自动路由、预算卡或成功率承诺。
6. 保持现有分镜、素材绑定、数字人、候选、预算、渲染和历史数据兼容；每个里程碑均可独立回滚。

本文优先级高于早期文档中以下未经实测的描述：

- “人物出现即可由数字人完成全部人物与产品交互”；
- “产品场景生成能够普遍锁定包装文字、Logo 和跨帧 SKU”；
- “工厂、展会、客户采访必须由用户实拍”；
- “手持、流水线、复杂使用场景已经具备同等生产成熟度”。

早期字段和接口可为历史兼容保留，但不得继续作为新任务的能力事实来源。

## 2. 核心产品决策

用户商品镜头子地图不再按“工厂、展会、采访、货架”等叙事场景分类，而按以下四层组合：

```text
场景底板获取
    ↓
产品身份注入
    ↓
交互与运动
    ↓
身份与成片质检
```

场景名称只用于检索和创意表达。真正决定生产难度的是：

- 是否需要精确到真实 SKU；
- 产品图是否足以支持目标视角；
- 产品是否与人物、机器或环境发生物理接触；
- 是否存在遮挡、旋转、反光、透明或柔性形变；
- 同一镜头中需要保持一致的产品实例数；
- 当前执行器和质检器是否真实可用。

近期默认策略是：

> 能复用不生成；能确定性合成不全量生成；生成模型负责场景、动作和融合，真实产品像素负责身份；不能验证时就改镜，不输出错误 SKU。

## 3. 本轮范围与明确非目标

本节同时列出当前基础和后续路线。标注“本轮已落地”的项目才可按当前代码能力理解；标注 M2/M4 或“计划”的项目均不是当前可执行承诺。

### 3.1 近期纳入范围

- 租户已有视频、爬取参考视频和可用素材的检索、裁切、拼接、调色与画幅适配；
- 产品图片、透明底图和现有产品知识库资产的整理与版本锁定；
- 产品图基础动效、静态英雄镜头和确定性图层合成；
- 数字人口播与产品镜头的顺序组合，但不虚构数字人持握关系；
- 使用现有 Sharp、FFmpeg、Remotion 完成的货架焦点 SKU 模板；
- 使用既定轨迹而非自动视频跟踪的简单 2D 流水线模板；
- 已接通时的 Seedream／Seedance 产品场景生成，但必须在提交前通过运行环境、输入和预算预检，并在采用前通过真实门禁；
- Tesseract 本地 OCR、现有语义质检和人工复核的组合；
- 模板缓存、输入指纹、幂等、失败镜头单独重试和真实运行指标。

### 3.2 暂不实现

下列能力缺少当前生产技术栈、稳定适配器或真实样本验收，本轮不得进入自动执行路线：

- Blender、USDZ、CAD 或其他 3D 数字孪生生产；
- SAM、CoTracker、OpenCV 视频面跟踪、Mocha PowerMesh 等动态标签面跟踪；
- ProPainter／VACE 等视频去物和时序修补；
- 人物手持不同几何产品的自动整体替换；
- 开盖、挤压、倾倒、喷洒、上脸等强物理交互；
- 透明、高反光、柔性包装的自动视频替换；
- 自动从任意流水线视频恢复相机、传送带和机器遮挡并批量植入产品；
- 依赖尚未接入供应商的新 Product Swap、Aleph 或同类接口；
- 任何不能由现有执行器和质检器证明的“精确 SKU”承诺。

这些能力可以保留在远期能力目录中，但必须是 `planned` 或 `unsupported`，不能出现在用户可点击的正式能力、自动预算、预计成功率或“可执行”状态中。

## 4. 名词与承诺等级

### 4.1 场景底板

不承担产品身份的背景视频或图片，包括工厂、展会、仓库、采访环境、桌面、货架和传送带。来源可以是租户素材、可用爬取素材、共享素材或生成画面。

### 4.2 产品身份包

与一个产品版本绑定、可跨镜头复用的输入资产：

- A1：正面高清图或透明底图；
- A2：正、侧、背多视角图，尺寸和包装类型；
- A3：标签原稿、刀模或可验证文字列表；
- A4：3D／CAD 资产。当前仅登记，不进入近期执行。

产品身份包必须保存产品 ID、资产 ID、内容哈希和版本。产品资产变化后，只失效引用该版本的下游镜头。

### 4.3 可复用生产模板

模板不是一条成片，而是可替换产品参数的生产资产：

```text
基础画面
+ 产品槽位或运动轨迹
+ 前景遮挡层
+ 光影与阴影参数
+ 目标画幅与安全区
+ 可替换产品入口
+ 质检规则
```

### 4.4 结果承诺等级

- `deterministic`：产品可见区域来自真实产品像素或可验证确定性图层。
- `qa_gated`：生成结果只有通过结构化质检和必要人工复核后，才能标记可用。
- `approximate`：只保证品类或场景语义，不保证真实 SKU。
- `unsupported`：当前不能稳定生产，不允许自动执行。

“已生成”只描述任务产生了媒体，不代表“已通过”“可采用”或“精准到真实产品”。

## 5. 当前技术栈真实能力审计

### 5.1 已有且可作为近期基础

| 基础能力 | 当前代码基础 | 近期用途 |
| --- | --- | --- |
| 素材与参考视频读取 | `trend_videos`、租户素材库、对象存储 | 建立场景底板池，复用真实运动与环境 |
| 本地图片处理 | Sharp | 产品抠图结果合成、缩放、裁切、遮挡层和静态模板 |
| 本地视频处理 | FFmpeg、`ffmpeg-static` | 裁切、抽帧、转码、拼接、画幅适配、轻量运动 |
| 可编程视频合成 | Remotion | 产品图基础动效、模板化货架、既定轨迹流水线 |
| 产品几何规划 | `storyboardGeometryPlanner.ts` | 已验证桌面和传送带静态槽位；不能当成动态跟踪 |
| 产品身份图层 | `productIdentityLayer.ts` | 静态产品和前景遮挡合成；不能当成视频手持替换 |
| 产品图兼容路线 | `customer_product_image_animation` | 当前最稳定的精确产品回退路线 |
| 产品场景生成 | Seedream／Seedance 适配器 | 仅在环境、输入、预算和参考素材齐全时条件启用 |
| 本地 OCR | Tesseract.js 中英文语言包 | 对静态产品图和可读关键帧做真实文字证据 |
| 语义画质检查 | Qwen 画面质检 | 检查构图、明显产品变化和画面完整性；不能替代真实 OCR |
| 数字人口播 | 已有数字人执行与质检链 | 处理可见口播；不承担未验证的人货物理接触 |
| 幂等与任务状态 | 现有任务、候选、预算和执行记录 | 避免重复收费，只重试失败步骤 |

### 5.2 已实现接口但尚未证明为正式能力

- `exactProductComposite` 目前是固定摄影台式首帧合成，不是通用货架、手持或动态流水线能力。
- `productIdentityLayer` 接受 `handheld` 类型，但缺少视频级手部遮挡追踪，不能据此宣称手持视频可交付。
- `aigc_product_scene_replication` 能调用首帧和视频生成，但真实样本矩阵仍未完成，不能用静态成功率代替实测。
- 产品场景输出中的 `labelOcrExactMatch` 当前由语义分数和问题文本推导，不是真实 OCR 精确比对。
- `storyboardGeometryPlanner` 只支持桌面和传送带静态几何，不支持多实例轨迹和人物持握。
- 分析阶段的 `currentStackAdmission` 假准入已在本轮收紧：复杂人货接触和工厂人物交互不再统一标成可执行；完整能力注册表仍属 M2+ 收口。
- `licensed_stock_asset` 当前只会选择已经进入共享素材库的内容，并不等于系统已经具备在线搜索、下载、授权和入库闭环；产品文案应称“授权共享库存复用”。
- 本轮已允许企业通用素材不绑定商品，并写入 `material-asset.v2` 元数据；旧记录仍需兼容读取。
- “没有匹配片段即优先补拍”和生产缺口直接调用通用 Seedance 的前端旁路已在本轮收口；实拍仅作为无可执行系统路线或用户明确选择时的 fallback。
- 数据合同保留 `system_fallback` 作为规划语义，但当前 readiness 不会把未接执行器的“身份图＋系统动作”或“工厂底板＋事实改写”投影为可执行；它们保持 `needs_input`，要求确认静态／事实卡改写或绑定已授权素材，不默认实拍。
- 本轮已增加 `production-cost-quote.v1` 的报价、上限、预留、结算与失败对账底座；它已进入 canonical task 读模型，但失败且账单未知时必须保留预留和 `actual = null`，等待可核验 receipt，多供应商全量对账仍是 M2+ 工作。

### 5.3 当前缺失

- 视频对象分割与掩码跨帧传播；
- 动态平面／网格标签跟踪；
- 视频去物与干净底板恢复；
- 多实例产品轨迹自动标定；
- 3D 产品建模与渲染；
- 跨几何手持产品替换；
- 面向上述能力的正式适配器、成本上限和真实验收集。

### 5.4 当前链路断点

本轮已修复两个关键断点：社媒规划页现在先创建或复用 canonical social task 再进入 Studio；`production_input_required` 会投影为明确的 `needs_input`，不再伪装成可自动恢复的等待。但仍需区分“主链已接入”和“全系统已迁移”：

- canonical social task 已挂载 `production-read-model.v1`，且可关联服务端 Studio 项目；历史 unlinked Studio 项目仍只做保守投影，不自动改写为已关联。
- 灵感任务原有的 `social_content_tasks`、调度、队列、checkpoint 和恢复继续保留，新读模型不另建状态机。
- 规划、执行和 baseline alignment 中仍有历史路由读取和 fallback；在完整能力注册表与冻结逐镜合同完成前，必须继续保守准入。
- 通用输入请求和成本报价底座已存在，但尚未能据此宣称每个历史页面、每个 provider attempt 都已迁移到统一账本。
- 规划能力注册与执行时动态注册的全量一致性仍是 M2+ 工作。

因此，近期最先建设的不是新模型入口，而是把所有生产入口统一到：

```text
canonical social task
→ versioned shot execution contract
→ Studio / automatic executor
→ shared candidate and artifact state
→ shared render readiness
```

本轮 canonical task 与读模型底座已建立；逐镜冻结执行合同仍属 M2+ 路线。在其完成前，不再新增另一套生产页、状态机或局部 fallback。

成本链路中，M0 已修正实际费用、未结算预计和未知费用的混用；M1 底座已支持 quote、上限、reserve、settle 和 fail 对账。对外 HTTP 目前只提供租户隔离的查询投影，创建、授权、预留、结算与失败入账只能由已校验的服务端工作流调用；失败且账单未知时不得释放预留或写成 0 元。这不等于真实供应商账单已在所有执行路径全量对账，后者仍属 M2+ 收口。

成本按 4–6 秒、720P／1080P 可用镜头估算，只作为商品镜头路线的规划区间。实际预算必须由运行时供应商报价、缓存命中和重试次数计算。下表中的“暂不实现”不得生成费用预览。

## 7. 可复用资产体系

### 7.1 四类资产

1. **场景底板模板**：工厂、货架、桌面、展会、仓库、传送带等无品牌环境。
2. **产品身份包**：与 SKU 和版本绑定的图片、文字、尺寸及可选标签稿。
3. **生产模板**：产品槽位、路径、遮挡、阴影、画幅和动效参数。
4. **质检模板**：该生产模板要求的解码、OCR、构图、边缘、时长和人工复核规则。

### 7.2 复用范围

- 全局模板：中性桌面、空货架、通用工厂、无品牌传送带。
- 品类模板：瓶、罐、盒、软管等固定正面构图。
- SKU 资产：同一产品跨货架、英雄镜头、CTA 和流水线复用。
- 镜头专用资产：参考视频区间、用户锁定素材和特殊遮挡。

### 7.3 缓存键

模板输出至少由以下内容形成稳定指纹：

```text
templateVersion
+ basePlateContentHash
+ productAssetVersion/hash
+ slotOrPathParameters
+ aspectRatio/resolution/duration
+ rendererVersion
+ validatorVersion
```

输入未变化时不得重复调用付费模型。产品资产变化只使引用该资产的镜头失效，不清空整条视频。

### 7.4 成本口径

```text
平均单镜成本
=（模板首建成本＋SKU 身份包建设成本）÷ 实际复用次数
+ 单次渲染成本
+ 单次质检成本
+ 实际重试成本
```

产品后台应分别记录固定成本和单次执行成本，不能继续只显示一个静态单镜价格。

### 7.5 素材库升级为生产供给库

本轮不另建大规模采集系统，复用现有租户素材、趋势视频、共享素材和对象存储；新增的是生产索引和质量门禁。素材必须以可使用片段为单位，而不只以整条文件为单位登记。

每个片段至少记录：

- 来源、租户、原始资产、裁切区间和内容哈希；
- 工厂、展会、仓库、货架、办公室、桌面、传送带等场景标签；
- 无产品、品类产品、品牌可识别、精确 SKU 四级产品身份；
- 是否存在人物、可见口型、人货接触和环境交互；
- 机位、镜头运动、时长、画幅、分辨率和解码状态；
- 明显 Logo、可读错误品牌、遮挡、运动模糊、反光和重复实例；
- `clean_plate`、`template_eligible`、可复用评分、最近验证时间和失效状态；
- 来源与授权元数据。当前可降低合规权重，但不能删除来源记录或把未知来源伪装为已授权。

入库流程为：

```text
已有素材/采集结果
→ 去重与解码检查
→ 缩略图和关键帧
→ 片段级标签
→ 品牌污染与产品身份检查
→ 可复用评分
→ 可用/待复核/失效
```

商品镜头侧至少区分四个视图：产品身份资产、场景底板、可复用模板、已生成并通过质检的候选。逐镜成功产物只有在来源、输入版本、QA 和租户范围完整时，才能晋升为可复用素材。

### 7.6 用户输入清单，而不是默认实拍清单

系统默认解决环境与场景素材。缺少精确产品资产时，优先生成“产品资料补充清单”：

- 正面高清图；
- 需要侧视或旋转时的侧面、背面图；
- 有条件时的透明底图；
- 标签原稿或需要核对的文字；
- 对构图有影响的实物尺寸和包装类型。

该清单的已落地持久化对象是 `production-input-request.v1`，不是新建一个只有商品的平行状态机。商品资料使用 `category: product_asset`，`kind` 只能取 `product_front_image | product_side_image | product_back_image | product_detail_image | product_transparent_png | product_label_artwork | product_packaging_dieline_pdf | product_dimensions`。其他生产缺口继续使用同一通用对象，分类为 `fact_evidence | person_authorization | scene_plate | digital_human_input | account_authorization | production_choice | other`。

只有同时满足以下条件时，才能建议用户拍摄视频：

1. 目标必须是客户真实现场或不可替代的真实动作证据；
2. 素材库、确定性模板、功能等价改镜和受控生成均不能满足；
3. 用户主动选择保留该镜头，而不是接受改镜。

真正的拍摄任务必须是最小清单，并包含 `shotId`、拍摄原因、角度／构图、时长、光线、必须出现的证据、上传入口以及上传后系统会继续执行的能力。资产上传并验证后自动完成相应清单项；一个镜头缺输入不得阻塞无关镜头。

### 7.7 运行时成本与预算硬门禁

每个镜头和整批任务都要显示：

- 一次性产品身份包或模板建设成本；
- 本地渲染、外部生成、质检和预计重试成本；
- 首次生产与缓存复用的差异；
- 预计值、上限值和已发生实际值；
- 免费／本地步骤、付费步骤、缓存命中和剩余预算。

预算流程固定为：

```text
preflight 计算运行时报价和最坏上限
→ 预算预留
→ 唯一幂等提交
→ provider receipt / 未知状态对账
→ 有可核验账单：实际成本入账，释放剩余预留
→ 无可核验账单：保留预留与 `actual = null`，收到回执后再对账
```

静态配置价只能作为缺少实时报价时的保守上限，不能冒充实际价格。供应商失败但费用未知时，报价可记录为失败，实际费用必须保持未知，账本预留继续保留；只有收到可核验回执后才能结算并释放剩余预留。供应商返回未知结果时不得自动重新提交；只允许重试失败步骤，并受逐能力最大尝试次数约束。只有超过已确认预算或要切换到新的付费路线时才再次询问用户。

`shooting_plan` 中的平台调用成本可以为 0，但外部拍摄成本必须显示“未估算”，不能显示为 0 元。读模型的最终费用状态只允许：`free`、`estimated`、`partially_settled`、`settled`、`unknown`；有未知账单时不得显示“已结算”。持久化报价对象的状态是 `quoted | reserved | settled | overrun | failed`，页面必须通过读模型映射，不可混用两组枚举。

## 8. 近期逐镜路由规则

### 8.1 输入签名

近期不要求一次性重构全部历史合同，但路由内部至少要推导以下字段：

```ts
type ProductProductionSignature = {
  identityPrecision: 'none' | 'category' | 'exact_visible_pixels' | 'exact_readable_label';
  interaction: 'none' | 'presenter_separate' | 'tabletop' | 'shelf' |
    'conveyor_authored' | 'handheld' | 'functional_use';
  productAssetGrade: 'none' | 'A1' | 'A2' | 'A3' | 'A4';
  personVisible: boolean;
  personProductContact: boolean;
  multiInstance: boolean;
  readableLabelRequired: boolean;
  sourceMaterialAvailable: boolean;
  referenceVideoAvailable: boolean;
};
```

新增字段应先作为可选、可回填的执行元数据，不强制迁移所有历史记录。

每个新任务还应持久化一份不可在执行中被关键词重算的逐镜合同。下列 `ShotExecutionContractV1` 是 **M2+ 路线规划，尚不是已落地共享合同**：

```ts
type ShotExecutionContractV1 = {
  schemaVersion: 'shot-execution-contract.v1';
  taskId: string;
  shotId: string;
  generationRevision: number;
  capabilityId: string;
  capabilityVersion: string;
  identityGuarantee: 'not_required' | 'exact_source' | 'locked_reference' |
    'qa_gated' | 'generic_only' | 'unverified';
  sourceRefs: Array<{ assetId: string; version: string; segment?: [number, number] }>;
  productIdentityPackRef?: { productId: string; version: string };
  requiredUserInputs: string[];
  blockers: string[];
  fallbackCapabilityIds: string[];
  cost: { expected: number; upperBound: number; currency: string; maxAttempts: number };
  qaPolicyId: string;
  inputFingerprint: string;
};
```

旧 `sourceStrategy` 由该合同投影生成用于兼容；执行器只消费已经冻结的合同，不再根据文案关键词另做一次路线分类。

### 8.2 决策顺序

```text
用户已锁定素材可用
  → 保留用户选择，不覆盖

无需精确产品
  → 已有素材/底板检索
  → 可执行的非证明性 AI 补镜
  → 动态图文

需要精确产品
  → 产品身份包是否完整
  → 确定性产品图动效或静态模板
  → 已验收的货架/既定流水线模板
  → 输入、运行环境、预算、参考视频均满足时才尝试产品场景生成
  → 失败后改为“场景镜头＋精确产品镜头”的功能等价剪辑

人物口播
  → 数字人口播

人物与产品发生接触
  → 不直接交给数字人
  → 近期改为人物动作/口播镜头＋独立精确产品镜头
  → 不支持的完整持握要求标记为需改镜，不伪装成已完成
```

### 8.3 生产前预检

每个镜头在创建付费任务前必须一次性检查：

- 推荐适配器已注册并且运行环境就绪；
- 输入资产存在、可读、属于当前租户且版本未变化；
- 当前能力支持镜头时长、画幅、产品数和参考输入数量；
- 必需参考视频能够读取；
- 预算上限、重试上限和幂等键已锁定；
- 所需质检器真实可用；
- 不支持的交互没有被错误地路由到数字人或产品场景生成。

预检失败不得先创建供应商任务。只有替代路线已经接通执行器时才可标记为可执行；否则必须返回 `needs_input`／`blocked`、明确 blocker，并提供改镜或绑定授权素材的下一步，而不是让用户停在加载或“待生成”状态。

## 9. 正常生产链路

### 9.1 阶段一：解析与冻结

输入：稳定分镜 ID、目标时长、口播区间、参考区间、产品映射、用户锁定素材和预算。
输出：版本化逐镜输入、商品镜头生产签名和候选路线。

规则：

- 只读取已经确认的分镜，不重新划分原片镜头；
- 原片商品不能被当成本企业产品；
- 产品映射有歧义时只询问该镜头，不阻塞无歧义镜头；
- 用户锁定素材拥有最高优先级；
- 同一份路由结果必须供前端计数、后端提交和渲染门禁共同使用。

### 9.2 阶段二：底板与模板选择

顺序为：

1. 当前租户已选素材；
2. 当前租户素材库其他兼容片段；
3. 已缓存的全局／品类模板；
4. 可用共享或爬取场景底板；
5. 已接通且可预检的生成底板；
6. 动态图文或改镜。

工厂、展会和货架没有客户实拍并不构成生产阻断。

### 9.3 阶段三：产品身份注入

近期优先级：

1. 产品原图直接作为主视觉；
2. 产品透明图进入确定性槽位；
3. 固定模板中的多实例复制；
4. 条件满足时才使用生成模型维持产品；
5. 当前不能保证的标签替换或完整换物不执行。

### 9.4 阶段四：渲染与验证

所有输出依次经过：

1. 文件存在、内容哈希、媒体解码；
2. 画幅、时长、帧率和黑帧检测；
3. 产品资产版本和输入指纹复核；
4. 确定性模板的槽位、遮挡和边界检查；
5. 需要可读标签时的真实 OCR；
6. AIGC 输出的语义产品一致性与场景检查；
7. 尚未达到自动验收样本量的路线进入人工复核；
8. 通过后才写入分镜可用资产。

### 9.5 阶段五：失败恢复

- 供应商临时失败：只重试当前步骤，复用已成功输入和首帧。
- 产品身份失败：不继续生成下游；回退产品图基础动效或改镜。
- 场景不符但产品正确：保留产品资产，重做底板或场景阶段。
- 标签不可读：不能标成精确标签镜头；回退至确定性产品图镜头。
- 用户改产品：只失效引用旧产品版本的镜头。
- 部分镜头失败：不要求整批重新开始。

## 10. 质检标准

### 10.1 所有镜头的硬门禁

- 输出真实存在且可完整解码；
- 时长、画幅、音视频轨道符合分镜；
- 没有空文件、黑帧、异常冻结或错误循环；
- 执行记录包含真实 provider、模型、任务 ID、成本和输入版本；
- 采用动作具有幂等性，同一候选不能重复扣费或重复写入。

### 10.2 精确产品的硬门禁

- 产品 ID、资产 ID、内容哈希与任务输入一致；
- 确定性路线不得拉伸产品比例或丢失关键可见区域；
- 要求可读标签时必须保存真实 OCR 文本和证据帧；
- 语义模型只能评价外观和构图，不能单独把 `labelOcrExactMatch` 判为真；
- AIGC 视频至少检查开始、中间和结束关键帧；
- 任何关键帧出现错误 Logo、错误标签、产品变形或额外 SKU，均不得自动采用。

### 10.3 人货交互的硬门禁

在未来能力正式开放前，人物与产品直接接触的完整镜头默认不满足自动交付条件。近期功能等价剪辑必须明确由两个或多个镜头完成：

1. 人物口播或通用动作；
2. 精确产品英雄镜头；
3. 可选品类级使用／环境镜头。

系统不得把三者拼接后的叙事效果描述为已经生成了精确手持或实际使用过程。

## 11. 状态机与前端行为

前端不再建立商品镜头专用状态机，而是直接消费 `production-read-model.v1` 的已落地状态：

```text
planning | needs_input | ready | running | rendering | quality_review |
review_ready | completed | paused | failed | blocked
```

关键规则：

- 不支持的能力不作为可执行 route 投影，也不显示生成按钮和虚假费用；
- `needs_input` 只列当前真正缺少的资料、事实、授权或必要选择，不要求用户选择供应商；
- `failed` 必须包含失败步骤和原因码；
- 备选路线可通过 `route.fallbacks` 展示；只有 `executable = true` 的路线才可开放 `use_fallback`，未接执行器的 `system_fallback` 必须保持 `needs_input`／`blocked`，不能开放生成；
- 只有 `review_ready` 且后端返回 `approve_output` 命令时才可采用；
- 全部分镜达到可渲染状态后才开放成片渲染。

近期不新增一套平行页面。继续使用现有“匹配素材／智能生成”、候选卡、集中确认和渲染入口；只修正路线、状态和错误反馈。

### 11.1 逐镜生产卡

现有分镜卡／生产工作台增加同一组信息，不创建另一套商品镜头生产页面：

- 推荐能力与“为何选择”；
- 产品身份保证：`not_required | exact_source | locked_reference | qa_gated | generic_only | unverified`，前端可转换为用户可读文案，不改变后端语义；
- 素材或模板来源及复用状态；
- 用户还需提供的最小输入；
- 预计成本、成本上限、缓存节省和已发生成本；
- 当前步骤、进度、失败原因和可执行 fallback；
- 产品、素材、预算和候选的锁定状态。

当前没有可执行路线时，读模型保留 `blocked`／`failed` 及 blocker，不出现可点击的生成按钮与虚假价格；`needs_input` 根据后端实际返回的 `allowedCommands` 提供选择已有资产、上传资料、确认事实／预算／授权或接受 fallback 等动作。批量界面只汇总真正需要用户决定的异常，正常镜头继续执行。

### 11.2 canonical task 与状态映射

自由创作、爆款复刻、灵感入口和 Studio 都必须先关联同一个 taskId。Studio project、逐镜 job、candidate、artifact 和最终成片均保存该 taskId；禁止默认创建不可回写的 unlinked project。

队列的永久 `production_input_required` 必须投影成 `needs_input` 并附具体动作；其他不可执行阻塞保留为 `blocked`／`failed`，不另造合同中不存在的 `action_required` 状态。只有真正可由系统再次入队的情况才显示 `paused/自动恢复`。状态计数、数字员工和灵小枢都读取同一份后端 read model，不能各自推算。

```ts
type ProductionReadModelV1 = {
  schemaVersion: 'production-read-model.v1';
  authority: 'canonical_task';
  project: {
    kind: string;
    id: string;
    version: string;
    title: string;
    taskStatus: string;
    runId: string | null;
    studioProjectId: string | null;
    studioProjectVersion: string | null;
    studioProjectStatus: string | null;
    studioProjectConflict: boolean;
  };
  aggregate: {
    stage: ProductionPipelinePhase;
    status: ProductionReadStatus;
    executable: boolean;
    identityGuarantee: ProductionIdentityGuarantee;
    inputs: ProductionInputSummary;
    cost: ProductionCostSummaryV1;
    blockers: ProductionBlocker[];
    counts: {
      total: number;
      ready: number;
      running: number;
      needsInput: number;
      blocked: number;
      review: number;
      completed: number;
    };
    phases: Array<{
      phase: ProductionPipelinePhase;
      status: ProductionPipelinePhaseStatus;
    }>;
    allowedCommands: ProductionAllowedCommand[];
  };
  shots: ProductionShotReadModelV1[];
  updatedAt: string;
};
```

该形状与 `shared/contracts/productionReadModel.ts` 一致：任务 ID 位于 `project.id`，费用位于 `aggregate.cost`，计数位于 `aggregate.counts`，镜头级输入、费用、阻塞和命令位于 `ProductionShotReadModelV1`。前端、数字员工和灵小枢只能执行 `allowedCommands` 中的命令。对有版本控制的 canonical task，409 冲突时先刷新 read model；幂等写入使用各已接入的可信服务端工作流自身的幂等键。输入与成本治理 HTTP 当前只提供租户隔离查询，不接受浏览器直接写入。

### 11.3 数字员工职责

- 策划／导演员工：只使用能力注册表与逐镜合同，不创造不存在的技术能力；复杂镜头优先拆镜或改镜。
- 素材员工：检索场景底板、登记片段来源、检查品牌污染并沉淀可复用候选。
- 生产员工：执行冻结合同，只重试允许的阶段，切换预先声明的 fallback，并记录成本与 provenance。
- 质检员工：执行媒体、产品身份、OCR 和采用门禁；不能以语义分数代替真实证据。
- 运营员工：监控卡住、未知 provider 状态、预算超限和缓存异常。

任何数字员工都不能在未获授权时更换产品身份、突破预算、覆盖用户锁定素材、改变付费路线或自动采用错误 SKU。

### 11.4 灵小枢的交互责任

灵小枢承担生产过程的统一交互入口，但不直接操作存储或治理写接口。它读取同一 read model；输入、授权和预算动作当前应导航到已校验业务流程，或交由服务端决策处理器执行，再回显执行结果。

本轮后端可执行权限以读模型的 `ProductionAllowedCommand` 为准：

```text
open_project | open_shot | select_material | upload_product_asset |
select_presenter | confirm_facts | confirm_rights | confirm_budget |
connect_account | confirm_production_choice | generate | retry |
use_fallback | request_shoot | review_output | approve_output
```

“解释路线”“报告失败”等可以是灵小枢的对话意图，但它们不是后端写命令，不得混入 `allowedCommands`。`request_shoot` 只在当前路线本身是用户采集，或没有可执行系统路线时出现，不是默认生产动作。

交互规则：

- 一次集中询问最少必要信息，不在多个页面重复追问；
- 能自动继续时只汇报进度，不打断用户；
- 只有产品歧义、缺失资产、超预算、付费路线变化和无安全 fallback 时请求决定；
- 用用户语言解释“会得到什么”和“是否精确到真实产品”，不暴露供应商内部术语；
- 接受上传／选择产品资产、采用 fallback、调整预算、重试或终止等明确命令；
- 不声称当前不存在的手持换物、动态换标、3D 或复杂流水线能力。

## 12. 兼容、迁移与防冲突原则

### 12.1 单一事实来源

- 分析层只描述镜头需求；
- 能力注册表描述当前执行器事实；
- 路由器根据需求、输入和注册表选择路线；
- 执行器不再次自作主张改路线；
- 质检器决定结果是否可采用；
- 前端只展示同一份路由和执行状态。

所有入口的目标是先创建或关联 canonical task；本轮已接入社媒规划主链，其他历史入口按 M2+ 迁移。Studio 只是该任务的人工操作界面之一，不再新建独立事实来源。在 M2+ 完成后，冻结的逐镜执行合同应成为规划与执行之间的唯一交接物，候选和 artifact 作为结果事实来源。

禁止分析、前端、执行器各维护一套不同的“可生成”判断。

### 12.2 历史合同兼容

- 现有 `sourceStrategy` 继续读取，用作历史数据和外层兼容路由；
- 新的组合生产信息先作为可选 `productionGraph`／trace 写入；
- 历史记录缺少新字段时按保守兼容路线读取，不自动升级为高级能力；
- 新写入必须带 schema/version；
- 只有所有读写端和测试均迁移后，才能删除旧字段。

### 12.3 不覆盖用户选择

- 用户锁定素材、产品、数字人或已采用候选不得被批量重规划覆盖；
- 重新路由只影响未开始或失败且未锁定的镜头；
- 输入变化按依赖图精准失效，禁止整项目清空；
- 旧候选保留审计信息，但标记为输入版本过期。

### 12.4 Feature Flag

以下为 M2+ 灰度路线建议开关名，不是当前仓库已全部定义的运行配置：

```text
PRODUCT_ROUTE_TRUTHFUL_ADMISSION
PRODUCT_STATIC_TEMPLATE_V1
PRODUCT_SHELF_TEMPLATE_V1
PRODUCT_CONVEYOR_2D_TEMPLATE_V1
PRODUCT_SCENE_STRICT_OCR
PRODUCT_PRODUCTION_GRAPH_V1
SOCIAL_CANONICAL_TASK_ENTRY_V1
SOCIAL_MATERIAL_SUPPLY_INDEX_V1
SOCIAL_PRODUCTION_ASSISTANT_COMMANDS_V1
```

默认顺序是测试环境开启、内部租户灰度、真实样本达标后再扩大；关闭开关必须回到稳定旧路线或产品图基础动效，不能落入空状态。

## 13. 废弃与删除计划

删除必须先完成调用搜索、历史数据兼容、测试覆盖和回滚验证。不能为了“代码干净”直接删掉仍被持久化数据或前端读取的字段。

| 项目 | 当前问题 | 处理方式 | 删除条件 |
| --- | --- | --- | --- |
| `currentStackAdmission` 全量 `admitted/executable` | 复杂人货接触被错误标成当前可执行 | M0 改成真实准入；不支持交互返回 `fallback_only` 或 `rejected` | 新准入测试和历史读取通过后替换旧实现 |
| “任何可见人物都走数字人”分支 | 数字人被错误要求完成持握、使用和工厂交互 | M0/M1 将口播和人货接触拆开；接触镜头走功能等价剪辑 | 路由矩阵覆盖全部人物类型后删除旧分支 |
| 通用 `aigc_product_scene_replication` 作为万能产品路线 | 无参考视频、无运行环境或复杂接触时仍可能被选择 | 增加预检并限制支持签名；稳定回退为产品图基础动效 | 真实样本达标后保留为条件能力，不再作为万能路线 |
| 语义推导的 `labelOcrExactMatch` | 字段名宣称精确 OCR，实际上没有执行 OCR | M1 改用本地 Tesseract 证据；暂时无法读取时进入人工复核 | 所有写入端均提供验证方法和证据后删除旧推导逻辑 |
| 静态 `estimatedSuccessRate` 决定路线 | 0.78 等数字没有真实签名样本支撑 | 降级为规划初始值；路线使用真实运行指标和最小样本数 | 指标服务有足够样本后移除静态决策权重 |
| `customerShootRequired: false` 硬编码字段 | 没有表达力，且容易被误解为能力已经解决 | 近期只作为兼容字段；新增明确 `systemFallbackAvailable`／`unsupportedReason` | 所有客户端迁移且历史数据兼容后删除 |
| 自动 `shooting_plan` 回退 | 与“系统优先解决场景素材”目标不符 | 只保留用户明确选择的拍摄方案；自动失败不创建待拍任务 | 路由和前端均不再依赖自动待拍后删除隐式分支 |
| 无执行适配器的能力卡片 | 用户看到能力但点击后才失败 | 注册表无 adapter 时不得产生可执行候选 | 所有候选均由运行注册表生成后删除硬编码展示 |

## 14. 分里程碑实施路线

里程碑按照依赖顺序推进。前一阶段没有通过退出标准，不进入下一阶段扩面。

### M0：能力事实与链路止血

目标：消除“假可用”“错误路由”和无效提交，不增加新的生成技术。

状态：**本轮已落地主要止血项；逐镜冻结执行合同和全历史入口迁移仍属 M2+ 收口。**

实施项：

1. **[已落地]** 修改复杂人货交互的准入结果，不再统一 `admitted/executable`。
2. **[已落地]** 将人物口播和人物持有／使用产品拆开；数字人只承担已验证口播能力。
3. **[已落地准入]** 产品场景生成检查运行环境、产品图、参考视频、预算和质检器；更完整的白名单样本门禁属 M4。
4. **[已落地保守准入]** 无参考视频或执行器不可用时，不提交付费任务；产品图基础动效或功能等价剪辑只能作为重规划选项，执行链尚未接通的候选继续投影为 `needs_input`／`blocked`。
5. **[已落地]** 不支持的 Blender、动态换标、跨几何手持能力不生成可执行候选和费用。
6. **[本轮部分收口]** 社媒主链已用同一读模型投影前端、计划和执行状态；历史页面继续迁移。
7. **[本轮部分收口]** 社媒规划主链在进入 Studio 前创建或关联 canonical social task；其他旧入口按 M2+ 迁移。
8. **[已落地]** 将 `production_input_required` 等永久输入阻塞映射为明确的 `needs_input`，不另造 `action_required` 状态，不再显示假自动恢复。
9. **[M2+ 路线规划]** 持久化冻结逐镜执行合同，使执行器停止按关键词重新分类和临时追加未声明 fallback。
10. **[已落地]** 保留历史合同读取，不做破坏性数据迁移。
11. **[已落地底座]** 修复实际费用漏记和假结算，收口无逐镜预算、幂等与 QA 的“一键 AI 生成素材”旁路；provider receipt 全量对账属 M2+。
12. **[已落地文案边界]** 把 `licensed_stock_asset` 准确表述为已入库授权共享素材，不宣称在线开源素材已经可自动获取。

退出标准：

- 复杂人货接触不会被标成可直接由数字人执行；
- provider 未配置时不会生成产品场景付费任务；
- 无参考视频不会进入当前必须依赖参考视频的执行器；
- 每个不可执行镜头都有一个明确替代路线，或以 `blocked`／`failed` 加明确 blocker 保守投影；
- 路由单测、共享合同测试和社会内容工作流测试通过；
- 没有新增前端死按钮或无法退出的等待状态。
- 从自由规划页进入 Studio 后可在任务中心看到同一任务，刷新后能够从原 checkpoint 继续。
- 同一镜头在规划页、Studio、队列和渲染门禁中的能力、状态和计数一致。

### M1：稳定的现有技术栈主链

目标：用已有素材和确定性产品图能力，提高正常任务的可完成率。

状态：**本轮已落地通用输入请求、Material Asset V2、服务端报价／预留／结算领域底座和部分读模型接入；治理 HTTP 当前仅提供租户隔离查询，本节其余生产能力组合是 M2+ 路线。**

实施项：

1. **[M2+ 路线规划]** 建立产品身份包 A1/A2/A3 的聚合与版本化读取，不新增平行上传入口。
2. **[当前已有]** 把 `customer_product_image_animation` 作为精确产品的稳定回退路线。
3. **[M2+ 路线规划]** 建立“数字人口播＋独立产品镜头”的自动拆镜／装配规则。
4. **[当前已有与部分收口]** 场景底板优先检索租户素材和已入库参考片段；片段索引完整化属 M2+。
5. **[M2+ 路线规划]** 对静态产品图和足够清晰的关键帧执行并持久化真实 Tesseract OCR 文本、方法和证据帧。
6. **[当前已有底座]** 失败仅重试当前镜头和当前阶段；已成功镜头不重复生成或收费。
7. **[本轮已落地保守选路]** 收敛用户提问；系统可识别潜在 fallback，但未接执行器时保持 `needs_input`，只请求身份资料、事实、授权或改镜选择。
8. **[本轮已落地元数据，M2+ 完成索引]** Material Asset V2 已能记录片段候选、身份等级和模板资格；全库解码／去重／品牌污染索引属 M2+。
9. **[本轮已落地]** 把默认实拍计划改为保守选路和按需资料补充；未接执行器的系统候选不会假装可执行，实拍只在无可执行系统路线且输入已明确，或用户主动选择时出现。
10. **[本轮已落地报价底座，M2+ 对账]** 已支持服务端领域函数计算预计值、上限、预留和核验后的实际结算；对外 HTTP 只读，失败且账单未知时保留预留和 `actual = null`；缓存节省和 provider receipt 全量对账属 M2+。
11. **[本轮已落地]** 允许通用场景素材不绑定具体产品入库，并支持片段候选元数据；完整收藏和运营策略属 M2+。
12. **[本轮已落地]** 建立持久化 `production_input_requests`；`/studio/product-asset-requests` 是租户隔离只读兼容视图，已校验的商品素材上传可自动履约，浏览器不能直接 `fulfill` 或 `waive`。

退出标准：

- 无外部产品视频生成能力时，整批任务仍可通过产品图动效、素材和数字人口播完成；
- 产品图、素材和用户锁定选择在刷新、重试和重新规划后不丢失；
- 静态精确产品路线具有真实输入哈希和 OCR／人工证据；
- 供应商失败不导致整批任务重来；
- 至少覆盖自由创作、爆款复刻、有人无接触、有人有接触、产品-only、工厂底板六类集成测试。
- 产品资料上传后只解除关联镜头的 blocker，不会重置已成功镜头；预算未知或超限会在付费提交前被拦截。

### M2：高频可复用模板

目标：不引入新重型技术栈，使用 Sharp、FFmpeg、Remotion 建立高复用确定性镜头。

状态：**M2+ 路线规划，尚未作为正式能力交付。**

实施项：

1. 静态英雄镜头模板：中性台面、留白、轻推近、轻横移。
2. 品牌货架模板：固定货位，1–3 个精确焦点 SKU，背景只承担氛围。
3. 简单 2D 流水线模板：系统自建底板和既定轨迹，不分析任意外部流水线视频。
4. 模板参数、输入指纹、缓存和复用次数落库。
5. 模板级 QA：槽位、比例、边界、遮挡、阴影和关键帧 OCR。
6. 成本拆分为模板首建、SKU 资产和单次渲染。

退出标准：

- 同一模板更换 SKU 不需要重新生成底板；
- 产品像素在全过程不被生成模型改写；
- 模板缓存命中时不触发付费生成；
- 货架和流水线模板各有真实可播放样本与回归测试；
- 失败能定位到模板、资产、渲染或质检中的具体阶段。

### M3：前端、数字员工与灵小枢协同

目标：让新生产能力在现有工作台中可理解、可控制、可恢复，不增加一套旁路 UI。

状态：**本轮已完成部分 `allowedCommands` 门禁、数字员工摘要和灵小枢决策卡接入；完整交互闭环为 M2+ 路线规划。**

实施项：

1. 逐镜生产卡展示推荐路线、身份保证、来源、所需输入、成本上下限、状态、失败原因和 fallback。
2. 增加批量异常中心，只聚合产品歧义、缺资产、预算审批、未知结果和无 fallback 五类行动项。
3. 数字员工统一读取能力注册表、逐镜合同和生产 read model；明确规划、素材、生产、质检和运营职责。
4. 灵小枢接入可审计命令层，承担集中问询、资料收集、预算审批、fallback 解释、异常恢复与进度汇报。
5. 所有计数、按钮 enablement 和渲染门禁来自同一后端状态，不在前端根据文案二次判断。
6. 严格复用全系统 UI 规范、共享 token 和 Ant Design 组件；不引入页面专属配色或新的组件体系。

前端落点固定为：

- `StudioWorkbenchFrame` 的现有分镜卡承载逐镜生产信息；
- `StudioBatchReviewDialog` 承载批量异常与预算确认；
- `ShotMaterialLibraryDialog` 承载产品资产、场景底板和模板选择；
- `SocialProductionProgressPanel`／现有任务详情读取统一进度；
- `AssistantDecisionCenter` 承载灵小枢的版本化行动卡；
- `GlobalAssistant` 只做解释、导航和命令确认，不直接修改生产存储。

前端不再使用浏览器本地的关键词路由来控制生成按钮；服务端 `allowedCommands`、版本号和幂等键是唯一操作权限来源。

退出标准：

- 用户从任一入口都能看到同一个任务进度，刷新和跨页后状态一致；
- 无需用户处理时，数字员工可推进到采用／渲染前门禁；
- 需要用户处理时，灵小枢一次给出原因、影响镜头、建议动作和预算影响；
- 未支持能力没有可点击死按钮，失败镜头可以选择 fallback 或精确重试；
- 锁定产品、素材、预算和候选不会被员工或重新规划静默覆盖；
- 关键交互通过键盘、焦点、加载、错误和恢复测试，并符合现行 UI 规范。

### M4：受控产品场景生成

目标：在稳定主链之外，以白名单方式开放现有 Seedream／Seedance 路线。

状态：**M2+ 路线规划。**

实施项：

1. 仅开放真实样本验证通过的镜头签名和产品类型。
2. 生成前锁定产品资产、参考视频区间、成本和重试次数。
3. 首帧、视频开始／中间／结束帧分别验证。
4. 标签检查使用真实 OCR 或人工复核，不再由语义分数伪装为精确 OCR。
5. 记录首轮通过率、最终采用率、身份错误、平均重试、P50/P90 耗时和实际成本。
6. 达不到阈值的签名自动降级到 M1/M2 路线，不继续盲目重试。

退出标准：

- 每项开放签名具有足够真实样本，而不是只通过模拟测试；
- 所有采用视频均有关键帧证据和人工／自动验收记录；
- 产品身份错误率、最终采用率和成本达到产品设定门槛；
- 关闭供应商或能力开关后可以无损回退到稳定路线。

### M5：清理、指标驱动和能力扩面

目标：删除已经完成迁移的废分支，并由真实数据决定是否增加新技术。

状态：**M2+ 路线规划。**

实施项：

1. 按调用统计删除旧路由、重复计数、伪 OCR 和不再读取的兼容字段。
2. 成功率按“能力＋产品资产等级＋交互＋遮挡＋景别”签名统计。
3. 模板按复用次数、采用率和获客表现排序。
4. 只有当现有路线无法覆盖的高价值镜头占比足够高时，才评估接入动态跟踪、Product Swap 或 3D。

退出标准：

- 废弃项在代码、合同、持久化数据和前端中均无调用；
- 删除后全量相关测试与真实回归样本通过；
- 产品能力注册表和运行指标成为唯一能力事实来源。

## 15. 暂缓能力的重新评估门槛

以下条件同时满足，才允许把一个新技术栈加入实施计划：

1. 现有稳定路线无法通过改镜或模板覆盖该需求；
2. 该镜头在真实任务中出现频率足够高；
3. 预计带来的采用率或获客价值高于维护成本；
4. 已有可部署 adapter、明确许可证、运行资源和故障隔离方案；
5. 有真实输入、验收集、预算和退出标准；
6. 失败时能回退到 M1/M2，而不是让用户卡住。

Blender、动态换标和跨几何手持替换当前均不满足上述全部条件，因此不进入近期开发。

## 16. 测试与回归要求

### 16.1 路由矩阵

至少覆盖：

- 无人物、无产品；
- 品类级产品；
- 精确产品 A1；
- 精确产品但缺图；
- 数字人口播无产品接触；
- 人物持有产品；
- 人物使用产品；
- 工厂环境无产品；
- 传送带固定正面产品；
- 多产品；
- provider 已配置／未配置；
- 有参考视频／无参考视频；
- 预算充足／不足；
- 用户锁定素材／未锁定素材。

### 16.2 故障注入

- 参考视频读取失败；
- 产品图不存在、过期或跨租户；
- 供应商超时、失败或返回不完整任务 ID；
- 首帧生成成功、视频生成失败；
- 视频生成成功、解码或 QA 失败；
- OCR 无文本、乱码或超时；
- 用户刷新页面、重复点击或修改产品；
- 一批镜头中只有一个失败。

### 16.3 必须保持的回归行为

- 用户锁定素材不被覆盖；
- 历史任务可打开并显示；
- 未修改输入的成功候选不会重新收费；
- 数字人口播原有无产品接触路线正常；
- 现有素材匹配和渲染链路正常；
- 未就绪镜头不会进入空渲染页；
- 计数由同一份逐镜状态推导，总和等于分镜总数。

## 17. 监控指标

每个能力签名至少记录：

- 规划次数、预检通过率；
- 执行启动率、供应商完成率；
- 首轮 QA 通过率、最终采用率；
- 产品身份错误率、OCR 失败率；
- 平均重试次数；
- P50/P90 耗时和实际成本；
- 模板缓存命中率和实际复用次数；
- fallback 使用率及最终采用率；
- 失败原因分布；
- 用户在此镜头退出、重做或改镜的次数。

没有最小真实样本量时，界面只显示“样本不足”，不得展示伪精确成功率。

## 18. Definition of Done

一条用户商品镜头生产路线只有同时满足以下条件，才算正式完成：

1. 有明确支持签名、输入要求和不支持边界；
2. 有注册且运行就绪的真实执行器；
3. 有提交前预检，不会先收费再发现不能执行；
4. 有结构化输出、来源、成本和版本记录；
5. 有真实质检方法和证据，不以提示词或模拟分数代替；
6. 有失败回退，不会把用户留在死状态；
7. 有单测、集成测试、故障测试和真实媒体验收；
8. 有 feature flag 和回滚路径；
9. 不覆盖历史数据和用户锁定选择；
10. 达到真实样本设定的最终采用率与成本门槛。

## 19. 本轮实施顺序

里程碑依赖顺序固定为：

```text
M0 能力事实与预检
→ M1 输入／素材／成本底座与现有稳定路线
→ M2 可复用确定性模板
→ M3 前端／数字员工／灵小枢协同
→ M4 白名单产品场景生成
→ M5 数据驱动清理与扩面
```

短期成功率来自减少错误路线、减少不必要生成、复用已成功资产和让失败可以局部恢复，而不是一次接入更多模型。

## 20. 本次已落地范围与后续边界

本次已经落地的 M0 止血项：

1. 公共场景能力签名补齐人物、产品接触、上脸与工厂环境交互推导；
2. 脚本准入不再把上述复杂动作标成数字人可完整执行，改为 `fallback_only + material_edit`；
