# PRD｜灵枢 AI 经营 Agent、编导 Agent 与视频矩阵闭环 v4

- 版本：v4.0
- 日期：2026-09-26
- 状态：当前代码基线 + 分阶段增强方案
- 适用范围：海外 B2B 社媒经营、爆款裂变、内容生产、四平台分发与询盘归因
- 参考输入：
  - 《经营Agent和编导Agent完整闭环示例-v1》
  - 《跨平台B2B双账号运营范例与执行方案》
  - 《灵枢四平台对标分析与启动方案总报告》

> 本文是三份方案的合并版本。参考文档中的数量和案例用于产品设计，不代表未经验证的经营结论；平台规则、账号授权与外部发布仍以运行时真实状态为准。

## 1. 产品结论

灵枢不再把“找爆款、做视频、发平台”拆成互不相认的工具页，而是形成一条可追溯经营链：

`企业事实 → 经营目标 → 账号矩阵 → 发现与对标 → 编导方案 → 内容生产 → 平台改编 → 审批与发布 → 回执 → 询盘与客户 → 周复盘 → 下周计划`

本版确定五个关键原则：

1. 经营 Agent 决定业务目标、账号、频次、预算、CTA、授权范围和复盘口径。
2. 编导 Agent 决定发现策略、参考证据、选题、脚本、分镜意图、爆款因子和创意验收，不越权修改经营承诺。
3. 内容 Agent 只执行已经冻结的方案，负责素材、生成、剪辑、字幕、混音、技术质检和成片，不自行改题或发布。
4. 原创内容、平台改编版本和发布任务必须分开计数；一次发布是“一个交付物发送到一个账号”，不能把分发次数伪装成原创产量。
5. 矩阵分两阶段启动：默认四平台单账号验证，具备真实数据和承接能力后才允许 TikTok / Facebook 双账号增长。

## 2. 目标与非目标

### 2.1 目标

- 建立企业事实、产品、市场、账号和转化入口的单一事实源。
- 将现有经营周包、社媒计划和编导链路编译为同一执行图，避免双链路重复运行。
- 支持 TikTok、Facebook、Instagram、YouTube 的差异化内容版本与发布策略。
- 支持品牌能力号、买家顾问号和综合账号三种定位。
- 将爆款裂变纳入“对标账号 → 自有账号 → 内容形式 → 单条视频”的完整上下文。
- 通过内容哈希、质量门、账号范围、授权范围和平台回执保证外部动作可审计。
- 将评论、私信、表单和 WhatsApp 回流到客户工作台，但只允许业务人员确认有效询盘、报价、样品和成交。

### 2.2 非目标

- 不保证浏览量、询盘量或成交结果。
- 不凭公开互动量推断竞品 ROI 或有效询盘。
- 不根据内容语言直接推断目标国家。
- 不把对标账号的同名或相似头像当作跨平台同一主体证据。
- 不自动绕过账号授权、人工审批、事实边界或平台政策。
- 不在本版自动扩建外部平台账号。

## 3. 统一业务对象

| 层级 | 核心对象 | 责任人 | 作用 |
| --- | --- | --- | --- |
| 企业事实 | EnterpriseProfile / ProductMarketingProfile | 企业资料 + 经营 Agent | 市场、语言、产品、证据、禁区的唯一来源 |
| 经营计划 | SocialProgram / MonthlyPlan / WeeklyOperatingPackage | 经营 Agent | 冻结目标、账号、频次、预算、CTA 与授权 |
| 发现 | KeywordSet / DiscoveryBrief / CrawlStrategy | 编导 Agent | 把经营需求编译为关键词、场景、账号和配额 |
| 灵感交接 | CandidateEvidence / InspirationHandoff | 编导 Agent | 记录为什么选、借什么、不能借什么 |
| 编导 | ReplicationJob / DirectorBrief | 编导 Agent | 冻结结构、镜头意图、爆款因子、差异化与验收 |
| 生产 | ContentExecutionPlan / AssetSupplyPlan | 内容 Agent | 选择素材和生产技术，产出平台版本 |
| 质量 | G4 / G5 / G6 | 内容 + 编导 + 经营 | 技术、创意、发布前经营校验 |
| 发布 | PublicationPackage / Receipt | 平台执行器 | 逐账号排期、发布、失败重试和回执 |
| 客户 | Engagement / Customer / Inquiry | 客服 Agent + 业务人员 | 归因、分层、跟进；人工确认商业阶段 |
| 学习 | WeeklyReview / CreativeLearning | 经营 Agent | 比较假设与真实结果，生成下周建议 |

### 3.1 单一写入原则

- SocialProgram 是社媒经营主档，不再创建第二套“新社媒项目”。
- WeeklyOperatingPackage 是周经营授权主档；SocialWeeklyContentPackage 是其中的内容子包。
- ReplicationJob 是旧 Studio 入口和 Agent 入口共同使用的爆款裂变事实源。
- 历史 `collection`、`inspiration` 周任务只读兼容，读取时合并为 `director`，新计划不再生成。
- 历史数据兼容层、安全边界和迁移守卫不得因“清理旧程序”被直接删除。

## 4. Agent 权限边界

### 4.1 灵小枢 / Orchestrator

- 读取企业、产品、账号、授权和运行状态。
- 组织任务依赖、阻塞、重试和页面跳转。
- 不替经营 Agent 决定目标、预算或账号矩阵。

### 4.2 经营 Agent

拥有：

- 业务目标、目标市场、买家角色和重点产品；
- 账号矩阵阶段、账号用途、周频次、预算与交期；
- CTA、承接入口、发布授权和成功标准；
- 发布前经营校验、询盘口径、周复盘和扩号建议。

禁止：

- 直接选择具体镜头参考；
- 绕过 G4/G5/G6；
- 把点赞、评论或私信自动认定为有效询盘。

### 4.3 编导 Agent

拥有：

- 关键词图谱和发现策略；
- 对标账号、候选内容、选用与淘汰理由；
- 单源复刻、账号系列和多源混合的参考模式；
- 脚本、分镜意图、叙事结构、镜头功能、爆款因子与创意验收；
- 成片相似度、原创度和内容质量的创意判断。

禁止：

- 修改账号数量、市场、预算、频次和业务承诺；
- 替内容 Agent 决定具体模型、供应商或素材文件；
- 把相关性描述为已证实因果。

### 4.4 内容 Agent

拥有：

- 素材匹配、缺失镜头补给、数字人、视觉生成、剪辑、字幕、配音、混音和渲染；
- 成片技术检查、身份保护、事实边界和可发布文件交付。

禁止：

- 修改选题、核心事实、CTA 或目标账号；
- 把 AI 画面冒充客户工厂、客户案例或已验证效果；
- 自行发布。

### 4.5 平台执行器

- 按平台改编规则生成文案、封面、比例、字幕、CTA 和排期。
- 一条内容对一个账号生成一个发布任务。
- 只有真实平台 ID 或 `publishResults=published` 才算发布成功。
- 不得把排期当发布，不得把一个账号回执复制给其他账号。

### 4.6 客服 Agent

- 回流评论、私信、表单、WhatsApp 及来源内容。
- 记录产品/规格、数量、国家、买家角色等资格字段。
- 生成逐客草稿并遵守时区、窗口、频次和商业承诺边界。
- 有效询盘、报价、样品、赢单和输单由业务人员确认。

## 5. 分阶段视频矩阵

### 5.1 数量定义

- 基础原创：第一次形成独立主题、证据链和叙事结构的源内容。
- 平台改编：基于同一源内容，改变首三秒、表达角度、证据顺序、字幕、比例、封面、CTA 或归因标记。
- 发布任务：一个交付物发布到一个账号；同一版本发到两个账号计两个任务。
- 非视频内容：采购说明文、轮播图等单独计数，不混入视频原创数。

必须满足：

`基础视频原创 + 基础非视频原创 + 平台改编版本 = 发布任务总数`

### 5.2 阶段 A：四平台单账号验证（默认）

| 平台 | 账号定位 | 周视频 | 周非视频 | 核心形式 |
| --- | --- | ---: | ---: | --- |
| TikTok | 品牌综合账号 | 5 | 0 | 原生短视频 |
| Facebook | 品牌综合账号 | 5 | 1 | Reels + 采购说明文 |
| Instagram | 品牌综合账号 | 5 | 1 | Reels + 轮播图 |
| YouTube | 品牌综合账号 | 3 | 0 | Shorts |

周目标：

- 5 条基础视频原创；
- 1 篇基础采购内容；
- 14 个平台改编版本；
- 20 个发布任务。

该方案用于验证内容、承接和生产能力，不代表每个平台都要制作五条完全独立的视频。

### 5.3 阶段 B：TikTok / Facebook 双账号增长

| 平台 | 账号定位 | 周视频 | 主要任务 |
| --- | --- | ---: | --- |
| TikTok | 品牌能力号 | 5 | 工厂、产品、交付、可核验证据 |
| TikTok | 买家顾问号 | 5 | 采购问题、选型、避坑、决策教育 |
| Facebook | 品牌能力号 | 5 | 企业身份、稳定供货和能力证据 |
| Facebook | 买家顾问号 | 5 | 采购教育、评论互动和询盘筛选 |
| Instagram | 品牌综合账号 | 3 | 高视觉密度精选版本 |
| YouTube | 品牌综合账号 | 3 | 搜索价值最高的 Shorts |

周目标：10 条基础视频原创、16 个平台/账号改编、26 个发布任务。

增长阶段必须同时满足：

- 至少连续四周有制作、发布回执和 24 小时 / 7 天数据；
- 至少存在由业务人员确认并可归因的有效询盘；
- 生产和询盘承接能力稳定；
- TikTok、Facebook 各有两个已接入账号；
- 周矩阵中分别标记品牌能力号与买家顾问号；
- 每个账号的受众承诺、首三秒、证据顺序、字幕、CTA 和归因标记独立。

当前代码已硬校验经营成熟度、账号数量和双账号角色；连续四周数据与有效询盘证据仍需在后续里程碑接入自动判定，目前由成熟度评估和人工证据负责。

## 6. 发现与对标

### 6.1 冷启动发现配比

- 趋势动量：50%；
- 对标账号：35%；
- 创新探索：15%。

该配比只是冷启动实验，不是永久硬编码。周复盘必须根据自有账号数据重新分配。

### 6.2 发现输入

- 企业、产品、市场、语言、买家角色；
- 网站、历史询盘和已确认竞品；
- 关键词种子、场景簇、证据问题、买家决策问题；
- 平台、回看天数、单次上限、预算和生产缺口。

### 6.3 候选内容判断

每个候选至少记录：

- 相关性：是否服务本周买家问题；
- 动量：相对账号基线是否异常，而非只看绝对播放；
- 新颖度：是否补充现有内容库；
- 可迁移性：哪些机制能迁移，哪些依赖原作者、IP 或场景；
- 权利边界：可分析、可改编、可使用原媒体分别判断；
- 证据：来源链接、时间点、置信度和需人工复核项。

## 7. 爆款裂变与质量保证

### 7.1 目标

爆款裂变不是只保留“结构像”，而是复制被判断为影响表现的功能性因素，同时强制替换产品身份、人物身份、受保护素材和不可证明事实。

可能需要冻结的因素包括：

- 首三秒问题与信息揭示时点；
- 镜头功能、动作起止状态、物体位置和连续性；
- 构图、主体面积、机位、运动、景别；
- 光线方向、软硬、色温、对比和阴影；
- 产品是否打开、是否有使用痕迹、道具关系和生活化程度；
- 字幕、旁白、环境声、音乐和音效层级；
- 证据出现位置、情绪变化、CTA 时点。

### 7.2 参考模式

- `single_source_fidelity`：单条参考，优先保持结构与关键因子。
- `account_format_series`：从同一账号的多条内容中提取重复格式。
- `multi_source_hybrid`：主结构、证据、节奏和 CTA 分别来自不同参考。

### 7.3 原创度边界

必须替换：

- 原创作者脸部、声音、账号身份和品牌身份；
- 原产品外观及商标；
- 未获授权的原媒体片段；
- 客户案例、效果结论和商业事实。

允许保持：

- 镜头功能和信息顺序；
- 可证明影响理解、留存、信任或转化的视觉/声音机制；
- 在容差范围内的构图、光线、动作和节奏。

### 7.4 三层验收

- G4 技术门：文件、时长、比例、清晰度、音轨、字幕、黑帧、渲染完整性。
- G5 创意门：因子命中、时间线、镜头功能、叙事完整性、原创差异和人工复核项。
- G6 经营门：事实、产品身份、目标账号、平台规则、CTA、承接入口、内容哈希和授权范围。

不通过时只修复失败镜头或失败版本，不重做整个项目；影响事实、预算或交期的替换回到编导/经营复核。

## 8. 四平台执行方案

### 8.1 TikTok

- 首三秒直接给买家问题、结果或明显冲突。
- 保留平台原生节奏、字幕和声音，不带其他平台水印。
- 同源素材必须改变首三秒、证据顺序和 CTA。
- 关注 3 秒留存、平均观看时长、完整播放率、主页访问和有效询盘。

### 8.2 Facebook

- 先给结论与可信证据，再补采购背景。
- Reels 和采购说明文独立组织，不把长文压进视频字幕。
- 评论问题进入客户工作台，承接使用已验证主页、表单或 WhatsApp。
- 关注 3 秒播放、适用时的一分钟观看、互动、链接点击和有效询盘。

### 8.3 Instagram

- 强化封面、构图和可收藏信息。
- Reels 与轮播图分别设计信息层级。
- 统一品牌风格，但不能把统一风格误当作画面复制。
- 关注播放、分享、收藏、主页访问和有效询盘。

### 8.4 YouTube

- 每条 Shorts 围绕一个可搜索的买家问题。
- 只保留最完整的一条证据链，避免把多条论点塞入短视频。
- 采购链接放在频道个人资料入口。
- 不把 Shorts 评论或描述中的普通 URL 当作可点击承接。
- 关注选择观看率、平均观看时长、观看百分比、频道访问和有效询盘。

## 9. 审批、发布与回流

### 9.1 周授权

周包授权必须冻结：

- 周期；
- 账号 ID；
- 最大发布任务数；
- 内容版本或哈希；
- 客户范围和最大消息数；
- 预算和审批人。

范围外动作重新审批。授权不等于发布成功，发布仍要等待真实回执。

### 9.2 询盘资格

至少采集：

- 产品或规格；
- 数量；
- 国家/市场；
- 买家角色；
- 来源平台、账号、内容和 CTA；
- 业务人员确认的阶段。

普通点赞、泛评论、无采购信息私信不得自动计为有效询盘。

### 9.3 数据窗口

- 内容发布后采集 24 小时与 7 天快照。
- 同时展示中位数和平均数，避免单条爆款扭曲判断。
- 无时间序列时不得输出增长趋势。
- 无真实回执时展示“暂无数据”，不得填 0 或模拟值。

## 10. 用户界面要求

- Agent 设置增加“社媒矩阵阶段”，默认四平台单账号验证。
- 周矩阵账号支持“品牌综合 / 品牌能力 / 买家顾问”定位和内容形式。
- 周包展示原创、改编、发布三组数量，不合并为“内容数”。
- 编导工作区只保留一个编导任务，内部展示采集、候选、脚本和创意验收节点。
- 平台规则写入内容订单，内容 Agent 可见但不可修改经营边界。
- 增长阶段不满足成熟度、账号或角色要求时给出可行动阻塞原因。
- 发布成功、排期、等待回执和失败重试必须使用不同状态。

## 11. 代码与数据策略

### 11.1 本版已落地

- 新增两套可校验社媒运营 Profile，数量守恒由测试保证。
- Agent 设置可选择矩阵阶段，默认单账号验证。
- 经营目标拆解归属经营 Agent，不再归属 Orchestrator。
- 平台差异化与 CTA 规则写入内容生产订单。
- 周矩阵增加账号定位和内容形式，并传入视频计划。
- 双账号增长校验经营成熟度、账号数量、逐账号矩阵与账号角色。
- 冷启动发现 50/35/15 配比进入运行输出，明确只作初始实验。
- 删除新计划中的独立采集/灵感任务模板；旧任务读取时自动合并为编导任务。
- 现有 ReplicationJob、镜头级因子、相似度/原创度评估和发布前质量门继续作为爆款裂变事实源。

### 11.2 保留但不再新增的兼容层

- 历史周包字段和旧任务 ID；
- Starter/legacy 租户隔离与效果守卫；
- 历史渲染结果、质量记录和迁移读取适配器。

这些代码承担数据安全与回滚职责，不属于可直接删除的“无用程序”。达到迁移完成、历史数据清零和回滚窗口结束三个条件后，再单独立项删除。

### 11.3 后续里程碑

#### M1：平台改编实体化

- 从 5 条基础视频自动编译 18 个视频发布版本；
- 补齐 Facebook 采购说明文与 Instagram 轮播图生成器；
- 每个版本拥有独立文案、封面、字幕、CTA、账号和内容哈希。

#### M2：增长阶段自动证据门

- 自动读取最近四周回执完整率、24 小时/7 天数据和人工确认有效询盘；
- 满足条件才允许从阶段 A 升级阶段 B；
- 证据不足只给建议，不自动扩号。

#### M3：矩阵学习闭环

- 按账号定位、主题、首三秒、证据顺序和 CTA 形成实验单元；
- 以中位数为基线比较，不把单条高播放当成稳定规律；
- 学习结论带样本数、适用范围、失败条件和置信度。

## 12. 验收标准

### 12.1 Agent 链路

- 经营 Agent 能输出冻结的目标、账号、频次、CTA、预算和授权。
- 编导 Agent 只能在冻结边界内决定发现、参考、脚本和镜头因子。
- 内容 Agent 收到可执行计划，不需要重新选择参考或改写业务事实。
- 平台执行器只能处理通过 G4/G5/G6 的版本。
- 客服 Agent 不得自行升级有效询盘或商业阶段。

### 12.2 矩阵

- 阶段 A 数量严格等于 6 份基础原创 + 14 个改编 = 20 个发布任务。
- 阶段 B 数量严格等于 10 条基础视频 + 16 个改编 = 26 个发布任务。
- 阶段 B 缺成熟度、账号、矩阵或角色任一项时不能启动发布。
- 同源素材跨账号时，首三秒、证据顺序、字幕、CTA 和归因标记至少有一项可验证差异。

### 12.3 发布与数据

- 无平台回执不得标记发布成功。
- 一个账号的回执不能提升其他账号状态。
- 24 小时与 7 天数据分开保存；缺失数据显式展示。
- 有效询盘可追溯到平台、账号、内容和承接入口。

### 12.4 兼容与质量

- 历史 collection/inspiration 周任务读取后仅出现一个 director 任务。
- 类型检查、社媒 Profile 测试、周包测试、矩阵测试、Agent 角色测试和生产构建通过。
- `git diff --check` 无空白错误。
- 不部署、不运行生产迁移、不触发外部发布。

## 13. 风险与产品判断

- 平台规则可能变化，生产环境应以平台官方文档和真实 API 返回为准。
- 账号扩张会放大生产、审核和询盘承接压力，不应以“账号越多越好”为目标。
- 相似度不是单一总分；关键爆款因子命中与版权/身份差异必须分别评估。
- 爆款因子首先是创意假设，只有通过多样本和自有账号实验后才能升级为较强证据。
- AI 生成画面只能承担解释和表达功能，不能代替客户事实和商业证明。
