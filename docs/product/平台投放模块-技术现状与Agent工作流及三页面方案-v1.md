# 平台投放模块：技术现状、投放 Agent 工作流与三页面方案 v1

- 整理日期：2026-09-27。
- 定位：竞品讨论前的产品与技术基线；用于明确现状、补齐工作流、讨论页面和排定开发顺序。
- 范围：Meta（Facebook / Instagram）、TikTok；保留现有 Google / YouTube 兼容能力，本轮不扩展其产品范围。
- 页面：按用户截图保留「投放总览」「投放计划」「AI 托管」三个一级入口。本文的“页面”指正式业务页面，不表示已完成生产环境验收。
- 证据：当前仓库代码及本任务本地检查。本文没有重新核验平台最新 API 政策，也没有进行真实账户调用；平台能力表描述的是本产品已写出的实现。
- 标记约定：**已实现**＝代码存在；**未验收**＝尚无本次真实账户验证；**建议新增**＝待讨论和开发，不能当作现有功能销售或演示。

## 1. 当前结论

现有工程已经包含账户连接、投放草稿、AI 方案、平台执行、审批、有限托管、执行回执和效果读取。主要工作是把这些能力组织为可用的业务闭环，并补齐素材、同步、归因和运行可观测性。

建议产品主流程：经营目标 → 选择素材 → 制定投放方案 → 校验账户和预算 → 审批或授权 → 平台执行与核验 → 效果观察 → 优化或素材改版 → 经营复盘。

第一阶段用 Meta 网站访问 / 视频观看和 TikTok Spark 视频观看验证基础闭环。若业务优先级是询盘获客，应将获客目标和归因另立为明确工作包，不能用点击或播放指标代替询盘验收。

## 4. 三个页面的产品分工

### 4.1 投放总览：回答“钱花到哪里，结果怎么样，哪里需要处理”

**已有：** 日期与币种筛选、花费 / 点击 / 曝光等展示、趋势图、逐日明细、报告来源、未接通的获客漏斗占位。

**建议正式页面结构：**

| 区域 | 内容 | 用户动作 |
| --- | --- | --- |
| 全局筛选 | 时间、平台、账户、币种、目标；明确报告时区 | 切换分析范围 |
| 数据状态 | 最近同步时间、覆盖计划数、缺失与历史快照提示 | 查看失败原因 / 请求重试 |
| 核心指标 | 花费、曝光、点击、CTR、CPC；视频目标单独显示观看口径 | 查看指标解释和来源 |
| 花费与结果趋势 | 同口径时间序列；缺失日期留空 | 下钻到计划 |
| 计划表现 | 目标、预算、花费、结果成本、平台状态 | 打开计划详情 |
| 待处理事项 | 授权失效、待审批、执行待核对、素材不可用 | 进入对应计划或 AI 托管 |
| 获客漏斗 | 会话、有效询盘、报价、成交 | 归因接通后开放，未接通明确标记 |

**口径要求：**

- 按币种分组，不直接相加 CNY 与 USD；预算和花费分别展示，计划预算不是账户余额。
- 对相同 provider + accountId + campaignId 去重后再汇总；当前总览尚未建立完整跨计划资源去重能力。
- CTR、CPC 等比率用同一覆盖范围内的原始分子分母计算，不能平均各计划比率；分母为零或缺失时不显示伪数值。
- Meta ThruPlay 和 TikTok 不同观看定义分别展示，不能统一当作完全等价的“有效观看”。
- 当前前端按 UTC 日期构造筛选；后续需明确平台账户时区与报告日期转换，不能只改显示文案。
- 没有完整可比数据时不显示增长结论；数据缺失与真实零消耗不同。
- ROAS 仅在归因成交额、币种、窗口和消耗覆盖一致时计算。

**验收：** 部分接口失败时总览仍可显示已知数据，但必须标明部分覆盖；点击指标或异常能够到达可处理的记录。

### 4.2 投放计划：回答“投什么，怎么投，当前执行到了哪里”

**已有：** 草稿列表、人工 / AI 创编、管理方式切换、账户连接、平台执行控件、审批与回执入口。

**建议页面结构：** 列表 + 计划详情；创建采用分步流程，账户连接可从流程内打开并返回。

| 创建步骤 | 需要的信息 | 校验 / 产物 |
| --- | --- | --- |
| 1. 目标与账户 | 经营目标、平台、账户、币种、投放目标 | 平台能力预检；不可执行目标不进入启动步骤 |
| 2. 选择素材 | 灵枢成片版本、封面、文案、落地页或帖子 | 素材归属、可访问性、平台身份 / 授权、规格校验 |
| 3. 预算与人群 | 日 / 总预算、时间与时区、地域、受众、版位 | 结构化平台参数；自然语言建议需转换和验证 |
| 4. 审阅方案 | 参数摘要、AI 依据、假设、缺失项、执行方式 | 保存可追溯版本；可单独保存草稿 |
| 5. 执行与核验 | 创建暂停广告；按人工确认或有效托管授权启动 | 平台资源 ID、回执、读回状态和失败原因 |

列表建议字段：计划名称、平台 / 账户、目标、素材版本、来源、管理方式、业务状态、平台状态、预算、实际消耗、结果、最近同步时间。

详情建议使用「配置」「素材」「效果」「执行记录」四个页签；托管设置链接至 AI 托管并保留当前计划上下文。

**素材归并：** 截图的三个一级入口与 Layout.tsx 一致；App.tsx 仍支持 adsCreatives，现有素材页主体为占位。建议将其能力放入计划详情的素材页签，并在总览提供素材表现入口。未来处理旧入口兼容，本轮不直接删除路由。

**状态要求：** 分开展示本地草稿状态、执行核验状态与平台实际投递状态。“API 已接受”“平台读回已启用”“审核通过”“正在产生曝光”是不同事实。

**验收：** 断网或超时重试不重复创建；返回详情后保留已保存方案；只读导入计划不会出现可直接接管的误导按钮。

### 4.3 AI 托管：回答“Agent 在做什么，依据是什么，需要我处理什么”

**已有：** 有效授权、待审批、已核验与需关注统计；审批 / 执行 / 观察时间线；授权边界；人工接管；复用计划设置控件。

**建议正式页面结构：**

| 区域 | 内容 |
| --- | --- |
| 运行状态 | 最近检查、下次检查、worker 是否在线、当前观察范围、阻塞原因 |
| 待办 | 待批准动作、失效授权、未知执行、账户异常；能直接定位处理 |
| 决策卡 | 观察窗口、数据时间、样本、规则 / 假设、建议动作、金额变化、预期验证方式 |
| 决策时间线 | 建议 → 审批 / 授权判定 → 平台执行 → 读回核验 → 后续观察 |
| 托管边界 | 账户、允许动作、日 / 总预算、单次调整幅度、授权到期时间 |
| 人工控制 | 接管、撤销授权；暂停广告为独立明确动作 |
| 复盘 | 已验证结果、仍在观察的动作、需交给编导的素材需求 |

当前“有效授权”计数不能当作“Agent 正在运行”。建议新增持久化 worker 心跳和 nextCheckAt 等运行证据；不能仅用前端计时器制造运行状态。

撤销托管只阻止后续自动操作，不会自动暂停平台上的广告。暂停操作必须经过平台执行和回执核验，并向用户清楚说明结果。

**验收：** 数据不足时显示观察原因；TikTok 未开放托管时明确提示人工模式；任何已执行动作可以追溯到授权、计划版本、依据与回执。

## 5. 投放 Agent 的职责和工作流

### 5.1 与其他 Agent 的边界

这里的“投放 Agent”是产品职责定义。当前代码由规划服务、确定性规则和平台执行服务组成，尚不是一个覆盖全流程的独立自主 Agent。

| 主体 | 职责 | 交接内容 |
| --- | --- | --- |
| 经营 Agent | 商业目标、市场、优先级、总资源分配 | 经营目标、投放依据、约束、衡量标准 |
| 投放 Agent | 媒体方案、平台适配、素材测试、预算内优化、效果复盘 | 投放方案、决策、执行请求、素材需求 |
| 编导 Agent | 将投放反馈转为表达和脚本改版 | 有证据的创意假设、DirectorBrief、表达验收 |
| 内容 Agent | 制作、技术质检、输出版本化成片 | 成片、版本、规格和质检结果 |
| 销售 / 客服能力 | 接待线索、标记有效询盘、报价与成交 | 在明确归因条件下回传结果 |
| 执行层 | 平台 API、调度、同步、重试和对账 | 平台资源、原始报告、回执与故障证据 |

与现有社媒经营方案衔接时，不默认增加新的一级导航或重复内容生产链路；“投放 Agent”是否作为独立用户可见角色，留待竞品讨论。

### 5.2 主流程与现状

| 阶段 | 输入与输出 | 当前实现 | 待完善 |
| --- | --- | --- | --- |
| 接收目标 | 目标 + 依据 → 投放任务 | handoff.ts 已能从经营目标生成草稿 | 素材需求与业务衡量标准的结构化交接 |
| 收集上下文 | 账户 / 素材 / 历史数据 → 可用能力 | 已有账户验证、计划和报告读取 | 统一能力预检及上下文快照 |
| 制定方案 | 上下文 → 人群、素材策略、风险与假设 | planning.ts 调用 LLM 并校验 JSON | 使用已验证历史数据，形成可执行参数版本 |
| 准备素材 | 成片 → 平台可用素材 | 当前引用平台已有资源 | 上传、处理状态、版本绑定和授权有效性 |
| 判定权限 | 动作 + 版本 + 授权 → 允许 / 待批 / 拒绝 | management、approvals、releasePolicy | 统一可解释的预检结果呈现 |
| 执行核验 | 请求 → 系列 / 广告组 / 广告与回执 | execute、launch、reconcile 已有 | 真账户验收、审核与投递状态持续同步 |
| 观察效果 | 平台报告 → 指标与决策依据 | metrics 与有限自动规则 | 持久化日数据、补采、素材维度、数据质量 |
| 优化迭代 | 指标 → 保持观察 / 暂停 / 调预算 / 改版 | Meta 有限规则 | TikTok 能力扩展、创意实验、改版交接 |
| 经营复盘 | 广告结果 + 归因线索 → 下一轮策略 | 尚未形成完整闭环 | 询盘 / 成交归因及复盘对象 |

### 5.3 四种管理方式

| 模式 | 用户体验 | 执行边界 |
| --- | --- | --- |
| 人工管理 manual | 用户设置并触发动作 | AI 不取得自动操作权限 |
| AI 建议 suggest | 展示建议与依据 | 不写入广告平台 |
| 审批执行 approval | 对具体动作、参数和影响审批 | 批准后仍要复核版本、账户和平台条件 |
| 授权托管 managed | 在预先授予的范围内持续执行 | 超出动作、账户、预算、幅度或有效期即阻止 |

AI 创建来源（ai_assisted / ai_managed）与管理权限是两回事；创建 AI 方案不会自然获得托管权限。已有有效授权可复用，只有新动作超出边界或授权失效时才要求重新处理。

### 5.4 状态与异常

当前任务状态：draft / paused / active / error / unknown。

当前执行主要状态：EXECUTING → PROVIDER_ACCEPTED → VERIFIED；确定失败为 FAILED，不确定结果为 UNKNOWN。未知结果先对账，不能盲目重新创建。

建议在任务状态之外增加工作流阶段视图：待补资料、待素材、待审批、待执行、待核验、观察中、需处理、已结束。它是工作流投影，不替换平台真实状态。

| 异常 | 应对 |
| --- | --- |
| 授权失效 / 账户不可用 | 阻止受影响账户的新动作，保留方案和待办 |
| 上传或规格失败 | 返回素材处理；新版本不能覆盖旧广告素材证据 |
| 平台拒绝 | 展示可操作的原因；修复参数后产生新版本 |
| 请求超时 / 回执丢失 | 进入待核对，读取资源确认后恢复 |
| 指标过期 / 样本不足 | 停止优化动作，保留观察原因 |
| 用户在平台改了预算 | 当前规则已有外部变化检查，停用规则并要求核对 |
| 达到预算边界 | 根据已有暂停授权执行并核验；无权限则形成待办 |
| 数据库或租约不可用 | 阻止平台写入，不退回本地锁冒险执行 |

平台账单和报告存在延迟，预算上限与周期检查不能被描述为即时扣费保证。

### 5.5 一个目标闭环示例（建议流程，非已完成能力）

经营 Agent 给出“在指定市场验证产品视频能否带来网站访问”，同时给出账户范围、素材和预算约束。投放 Agent 读取账户能力，选择已验收成片，生成测试方案；人工模式先创建暂停广告，用户确认后启用；托管模式在已有有效授权范围内执行。

平台读回成功后进入观察。样本不足则继续等待；满足规则时形成可解释的预算或暂停动作。若要测试新的开场表达，向编导交付具体指标、素材版本和待验证假设，再由内容 Agent 产出新版本。新旧素材独立记录，最终回传经营复盘。后半段的自动素材改版交接和归因复盘仍需开发。

### 6.3 API 复用与建议

现有 API 前缀：/api/overseas/platform-ads。

- 计划：GET /tasks、POST /tasks、POST /tasks/ai-plan、GET /tasks/:id、PATCH /tasks/:id。
- 账户：/connections、/connections/:id/verify、/connections/:id/campaigns；Meta OAuth 位于 /oauth/meta 下。
- 管理：POST /tasks/:id/management；审批、launch、automation 位于任务下。
- 执行：POST /tasks/:id/execute；GET /tasks/:id/executions；POST /tasks/:id/executions/:executionId/reconcile。
- 效果：GET /tasks/:id/metrics；导入：POST /connections/:connectionId/import。
- 经营交接：GET /business-goals/:goalId/ads、POST /business-goals/:goalId/ads。

建议新增统一能力预检、素材绑定 / 上传任务、历史指标查询、决策列表与 worker 健康查询。具体端点应在竞品和产品范围确定后定稿；现有权限与执行校验继续复用。

当前列表有 200 条读取上限，托管页按任务分别请求审批、执行和观察记录。规模扩大前需做服务端分页与汇总读模型，避免把前端小计当作完整账户统计。

## 7. 分阶段实施与验收

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| P0：基线修复 | 总览测试与数据提示、平台能力表、三页职责、旧文档校正 | 套件通过；未支持能力不冒充可执行；无真实平台写入 |
| P1：单平台闭环 | Meta 素材绑定 / 上传、预检、暂停创建、人工启动、效果读回；完善 TikTok 人工 Spark 流程 | 在用户指定账户及明确预算授权下完成真实验收；资源与素材可追溯 |
| P2：可解释托管 | worker 运行证据、决策卡、持久化指标、异常恢复、素材改版交接 | 授权内运行；未知结果不重建；每个动作可追溯；新素材能返回计划 |
| P3：获客与跨平台优化 | 选择获客入口、归因、有效询盘成本、跨平台实验与预算分配 | 指标与业务记录有证据关联；跨计划预算总额约束可验证 |

P1 的真实验收单独准备账户、动作、预算、时间窗口和停止条件。本文及普通开发请求不构成真实投流或生产部署授权。

建议验收场景：人工建草稿、AI 建议不执行、审批版本变化、授权到期、同一请求重试、平台已接受但本地写入失败、外部预算变化、租约丢失、报告部分缺失、重复资源汇总、跨币种展示、TikTok 不支持动作、撤销托管后广告仍运行、素材改版版本追溯。

## 8. 后续竞品讨论框架

本节是研究提纲，不是已验证的竞品结论。下一轮先确定产品名单、版本及可访问页面，再记录带日期的证据。

| 对照维度 | 需要回答的问题 | 对本项目的决策 |

每个竞品记录：产品 / 页面、体验日期、链接或截图、实际操作流程、已观察能力、未验证宣传、适合借鉴部分、与本产品前提差异。

讨论优先确定四件事：

1. 第一版核心结果是视频观看、网站访问，还是有效询盘？
2. 用户主要从灵枢新建广告，还是接入已经在跑的广告做监控与优化？
3. 第一阶段默认人工、审批还是授权托管？不同平台可以采用不同范围。
4. 获客优先连接网站、平台表单还是即时会话？该选择决定素材、目标和归因实现。
