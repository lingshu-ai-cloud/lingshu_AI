# 成片渲染与导出：字幕与重点信息动效设计基线

日期：2026-10-07
状态：后台第一版已实现，待真实样片视觉验收。后续开发、样片评审和事件—动效映射讨论以本文为准；新增结论应先更新本文。
当前范围：字幕样式、重点信息事件、事件驱动动效、预览与导出一致性。当前阶段不开发镜头运动。

## 1. 背景与目标

当前成片渲染与导出页面的动效表现偏通用化，缺少对素材类型、字幕语义和内容事件的区分。问题不是特效数量不足，而是动效与内容之间缺少明确关系：相似效果可能按固定时间或统一模板出现，却没有回答“为什么此刻出现”“它强调了什么”。

本阶段目标是建立一套轻量、可解释、可复用的字幕与重点信息动效系统：

1. 根据素材和内容表达选择合适的字幕 Profile。
2. 将内容分析结果转为结构化事件。
3. 让渲染层根据事件决定动效出现的时间、层级和强度。
4. 保持预览与最终导出的表现一致。
5. 降低模型生成自由文本、逐帧样式或一次性代码所需的 token。

## 2. 已确认的范围

### 2.1 本阶段包含

- 字幕的语义分层、版式、颜色、字号、描边、背景和入退场。
- 重点信息的识别、时间定位、优先级和动效触发。
- 素材类型 Profile 与事件渲染规则。
- 同一时间多个事件的冲突、合并和降级规则。
- 事件数据的人工校正、预览和导出。
- 使用 Remotion 组织字幕、标签和时间线，使用 FFmpeg 处理转码、音频混合与最终封装。

### 2.2 本阶段不包含

- 自动推近、平移、缩放、跟踪等镜头运动。
- 复杂 3D、粒子系统或 After Effects 模板解析。
- 为每条视频临时生成逐帧 CSS、Remotion 组件或任意动画代码。
- 仅为增加“热闹感”而随机触发的装饰性特效。
- 对配乐节拍、响度和人声压低量的完整策略设计；待取得可分析的本地音轨后单独补充。

镜头语言仍可作为素材理解和后续扩展依据，但不得混入本阶段验收范围。

### 3.1 四类素材的共识

1. **D2C**：字幕承担情绪、角色关系、产品卖点和转化信息，多层文字可以同时存在，但必须有清楚层级。
2. **真人口播**：可信度和可读性优先。逐句字幕是主层，关键词强调和 B-roll 说明是辅层，不适合持续使用装饰特效。
3. **工厂素材**：应表达厂区、设备、产线、操作、工艺、成品和交付之间的证据关系。当前阶段用工序名、能力词、参数和证明信息完成强调。
4. **产品实拍**：产品、材质、结构、价格和使用价值是重点。字幕与标签应帮助用户看懂产品，不遮挡产品主体。

同一视频可以是混合类型。Profile 表示主要表达方式，不要求镜头只能属于一个互斥类别。

### 3.2 字幕与强调的实际频率

重新按时间抽样后，需要区分两种频率：

- **普通字幕刷新**：跟随语句，通常每 1–3 秒更换一次。这只是阅读节奏，不算重点事件，也不应每次都触发明显动效。
- **样式变体或重点强调**：标题、角色标签、放大的卖点词、价格、品类卡、结果揭示等。它们明显更稀疏。

| 样本类型 | 普通字幕刷新 | 明显样式变体／强调 | 观察结论 |
| --- | --- | --- | --- |
| D2C 剧情／种草 | 约 1–2.5 秒一次 | 对话角色、利益点或效果揭示较多；短视频开头可能更密 | 可以承载较强强调，但不能据此为 D2C 片段单独计算时间间隔 |
| 真人口播 | 约 1.5–3 秒一次 | 品类词、关键承诺或地点偶尔变化 | 多数语句只使用基础字幕 |
| 坐播＋B-roll | 约 1.5–3 秒一次 | 大部分时间只有统一字幕，重点变化很少 | B-roll 切入本身不等于一次强调 |
| 工厂／产品实拍 | 约 1.5–3 秒一次 | 阶段标题、产品卖点或结果说明偶尔出现 | 短片段可以没有强调，也可以在承载核心证据时只出现一次 |

以上是小样本观察，不是逐帧精确统计。它足以确定一个产品原则：**字幕可以频繁更新，强调不能跟着每句话更新。** 强调密度按整条成片和语义段落控制，不按某类素材累计时长分别计算。

## 4. 技术选型共识

采用 **Remotion＋FFmpeg** 的组合：

- Remotion 负责字幕、标题、标签、重点信息组件、事件时间线和预览。
- FFmpeg 负责素材裁切、转码、音频混合、拼接和最终封装。
- 内容分析层只输出有限、稳定的结构化事件，不生成逐帧渲染代码。
- 渲染层使用已实现、可测试的组件和 Profile 将事件转为画面。

这一方案优先复用当前前端／Node 技术栈，减少额外运行时、供应商和模板格式，也能让预览与导出共享同一套视觉规则。

## 5. Profile 设计

首版建立四套 Profile，但只实现字幕和重点信息表现。

| Profile | 适用内容 | 默认字幕策略 | 重点信息策略 |
| --- | --- | --- | --- |
| `d2c_dialogue` | 剧情带货、多人对话、体验种草 | 支持说话人／角色标签、对白字幕、情境标题 | 价格、优惠、产品名、效果揭示和情绪转折可获得较强强调 |
| `talking_head` | 真人坐播、走播、专业讲解 | 单行或双行逐句字幕，稳定位置，关键词局部着色 | 核心观点、数字、品类、服务承诺使用克制强调 |
| `factory_process` | 厂区、仓库、设备、产线、工人加工 | 解说字幕保持清晰，工序名或能力说明独立成层 | 工序切换、设备能力、材料、参数、质检结果和产能证据优先 |
| `product_showcase` | 产品实拍、展厅、材质和功能展示 | 字幕避开产品主体；短句优先 | 产品首次出现、卖点、材质、尺寸、价格和前后效果优先 |

Profile 决定视觉表现，不负责判断业务事实。事件识别层负责说明“发生了什么”，Profile 负责说明“怎样表现”。同一份事件数据应能够切换 Profile 重新渲染。

## 6. 字幕语义分层

字幕不能继续只作为一种统一皮肤。首版至少支持以下层级：

| 层级 | 用途 | 生命周期 | 示例 |
| --- | --- | --- | --- |
| `hook` | 开头吸引注意的命题或利益点 | 通常 1–3 秒 | “69.9 四支正装” |
| `speech` | 与人声同步的逐句字幕 | 随语句切换 | “就算只买两张石膏板” |
| `speaker` | 说话人、角色或身份 | 说话人变化时更新 | “柜姐 A”“工厂负责人” |
| `context` | 场景、前提或情境说明 | 一个段落或场景内有效 | “当富姐穿着睡衣逛专柜” |
| `keyword` | 逐句字幕中的重点词 | 依附 `speech`，短时强调 | “生态板”“免费配送” |
| `fact` | 地址、规格、参数、价格、优惠等事实 | 按事实有效区间显示 | “萧山区红泰六路 888 号” |
| `process` | 工序、步骤或生产环节 | 对应工序画面 | “精密切割”“质检” |
| `callout` | 指向画面中产品、部件或局部的说明 | 对象可见时显示 | “岩板台面”“隐藏式插座” |
| `cta` | 行动提示 | 通常在结尾或转化节点 | “到店看样”“私信询价” |

同一文字只能有一个主语义角色，避免既作为逐句字幕又重复生成相同的大标题。

## 7. 两层时间线模型

事件体系改为两层，避免把每个内容概念都变成一次视觉强调。

### 7.1 基础字幕层

基础字幕层只保存语句时间、文本和可选说话人，约每 1–3 秒更新。它持续工作，但不进入重点动效配额。

```ts
type CaptionSegment = {
  id: string;
  startMs: number;
  endMs: number;
  text: string;
  speakerId?: string;
  keywords?: string[];
};
```

`keywords` 默认只改变局部字色或字重，不自动生成一次独立动效。

### 7.2 稀疏强调层

只有值得改变字幕形态或新增信息层的时刻才进入强调层。首版只保留五类：

| 事件 | 含义 | 示例 |
| --- | --- | --- |
| `hook` | 开头核心利益、冲突或问题 | “69.9 四支正装” |
| `key_fact` | 需要被记住的产品、价格、参数、品类或服务事实 | “生态板、多层板”“支持配送” |
| `reveal` | 产品、效果、成品或前后结果被清楚揭示 | 开灯后的唇妆、成品岛台 |
| `section_label` | 进入新的内容阶段、场景或工序 | “仓储实力”“精密加工” |
| `cta` | 咨询、到店、购买等行动提示 | “到店看样”“私信询价” |

角色名、地址和长期显示的信息属于字幕状态或固定信息层，只有首次出现时可以消耗一次强调配额。普通产品提及、问题句、回答句、镜头变化、机器运转和工人动作都不自动生成强调事件；它们只有承载本段最重要信息时，才归并为上述五类之一。

### 7.3 简化数据结构

```ts
type EmphasisEvent = {
  id: string;
  type: "hook" | "key_fact" | "reveal" | "section_label" | "cta";
  startMs: number;
  endMs: number;
  text?: string;
  importance: 1 | 2 | 3;
  confidence: number;
  source: "transcript" | "vision" | "metadata" | "editor";
  targetId?: string;
};
```

其中 `importance` 只使用三级，减少模型在相近等级之间反复判断。价格、优惠、规格、地址和服务承诺置信度不足时，不进入强调层。

## 8. 强调事件筛选

模型可以识别较多候选，但进入渲染时间线前必须做稀疏化：

1. 先按整条成片时长生成总强调预算，再在全片候选中择优，不为每种素材分别生成配额。
2. 同一句中的多个关键词合并成一次 `key_fact`。
3. 产品被提及且同时出现在画面时，只生成一次事件。
4. 相邻的主张、证据和结果合并为一次强调，优先落在证据或结果出现的时间。
5. 同一卖点重复出现时，只保留第一次或表达最完整的一次。
6. 相邻两个强调默认保持可读间隔；若开头钩子和紧随其后的揭示确有必要，可以缩短间隔。
7. 没有足够重要事件的时间段允许完全不出现强调。

选择顺序为：`hook` → 已验证的价格／优惠／参数 → `reveal` → 本段核心 `key_fact` → `section_label` → `cta`。Profile 只改变表现方式，不能提高事件排名或突破全片预算。

## 9. 全片预算与落点规则

Profile 只决定表现方式，不拥有自己的频率或配额。一个 3 秒工厂片段可能有一次 `section_label` 或 `key_fact`，也可能完全没有；判断依据是它是否承担全片的重要信息，而不是该素材类型持续了多久。

### 9.1 全片预算

首版采用软预算而非固定公式：

| 成片长度 | 建议强调总量 | 说明 |
| --- | --- | --- |
| 0–15 秒 | 2–4 个 | 通常覆盖 Hook、核心事实、Reveal，必要时加入一次辅助强调 |
| 15–30 秒 | 4–8 个 | 优先覆盖开头、核心卖点、证据和结果 |
| 30–60 秒 | 6–12 个 | 按信息段落分配，不要求平均分布 |
| 60 秒以上 | 每 20–30 秒约 2–4 个 | 先按章节选重点，再受全片去重约束 |

预算是上限附近的建议值，不要求填满。内容只有两个值得强调的信息时，即使视频一分钟，也只生成两个强调。

该预算包含强弱两级表现，不表示所有事件都使用大字卡或强入场。一个信息段内可以由一次主要强调和一次轻量关键词变化组成，但两者仍分别计入预算。

### 9.2 落点选择

强调先绑定语义，再选择承载它的最佳画面：

1. 从脚本和字幕中选出全片最重要的 Hook、事实、揭示、章节和 CTA 候选。
2. 在候选有效时间范围内寻找最匹配的画面，例如产品清楚出现、仓库全景出现或成品完成。
3. 若最佳画面恰好是 3 秒工厂镜头，就把一次强调放在这 3 秒内；不继续寻找所谓“工厂素材间隔”。
4. 若短镜头只作过渡、不承载独立信息，则不加重点动效。
5. 同一语义跨多个镜头时只强调一次，选择主体最清楚、空间最安全的镜头。

### 9.3 Profile 的作用

- `d2c_dialogue` 决定 Hook、价格和 Reveal 的视觉力度。
- `talking_head` 决定关键事实如何嵌入稳定字幕。
- `factory_process` 决定工序或能力信息的样式。
- `product_showcase` 决定产品卖点和结果说明的样式。

Profile 不增加事件，也不因镜头切换重新计算预算。

## 10. 冲突与显示规则

- 同一时间只显示一个强强调组件。
- 普通字幕始终优先，强调不能遮挡或打断阅读。
- 两个候选过近时合并；无法合并时保留重要性更高者。
- 固定信息可以持续显示，但首次出现后的静态展示不再计为新事件。
- 低置信度事实退回普通字幕，不生成独立信息卡。
- 无安全区域时，强调降级为字幕局部字色或字重变化。
- 不用装饰动效填补空白时间。

## 11. 事件与动效映射的边界

事件只描述强调意图，不包含具体动画名称。后续为五类事件分别确定组件、入场、保持、强调、退场和降级方式。

参考素材分析采用统一记录格式：

`时间点 → 是否只是普通字幕刷新 → 强调事件类型 → 视觉变化 → 持续时间 → 与前一次强调的间隔`

优先补充含价格揭示、产品／效果揭示、品类集合、工序阶段和 CTA 的参考素材，用来校准五类事件的视觉表现与真实频率。

## 13. 首版验收标准

- 同一份事件数据可以切换 Profile 并重新渲染。
- 所有独立重点信息都能追溯到事件和证据。
- 事实类文字不因模型改写而改变价格、单位、地址、规格或承诺范围。
- 人脸、产品和关键操作不被字幕或信息卡遮挡。
- 强调总量符合全片软预算；短素材片段不单独计算频率。
- 同一信息不会以字幕、大标题和信息卡重复三次。
- 修改一个事件只使相关时间区间和下游成片失效。
- 预览与导出的文字、时间、位置和动画结果一致。
- 导出失败时能够定位到事件、组件或媒体处理步骤。

## 13.1 混合渲染架构与性能预算

字幕和动效采用分级渲染，避免所有文字都进入高成本动画流程：

- 普通字幕、简单字色和字重变化继续使用 ASS，由 FFmpeg 直接合成。
- 与口播字幕重合的 Hook 或 Reveal 只改变原字幕，不新增第二条重复文字。
- `key_fact`、`reveal`、`cta` 等少量关键事件可进入 Remotion 透明动效层。
- Remotion 只输出包含文字、贴纸和图形的透明 WebM；原始视频、配音、配乐和最终编码仍由 FFmpeg 处理。
- 没有高级事件时跳过透明层，维持现有快速导出路径。
- 透明层缓存键由分辨率、帧率、时长、Profile 和标准化事件共同决定；只修改配音、配乐或底层素材时允许复用。
- 修改单个事件时，优先只使透明动效层失效，不重复执行无关的媒体准备步骤。

性能目标：20 秒、720×1280、30fps 短视频的完整导出控制在 15～25 秒；引入透明层后的额外耗时原则上不超过现有导出耗时的 50%。首次冷启动可以更慢，但同一动效计划的缓存命中必须明显缩短后续导出。

视觉层级固定为：基础字幕、原字幕强调、独立短贴纸。制作元数据、镜头说明和长段脚本文字不得进入独立动效层。

当前实现的性能验收结果（约 21 秒、720×1280、30fps 的已有创作草稿）：

- 透明动效层首次冷渲染约 32.1 秒，包含 Remotion 首次启动和浏览器组件准备。
- 同一动效计划命中缓存后，完整导出约 3.7 秒。
- 常规重复导出已满足 15～25 秒目标；冷启动仍需继续优化，但不阻塞缓存后的生产路径。

事件语义与布局必须同时通过验证：

- 自动贴纸必须由同期或邻近口播字幕直接支持，或来自明确的用户业务事实。
- 分镜中的镜头说明、后期建议和预设字幕只能提供落点，不能单独创造起订、配货、联系等商业事实。
- 可以从口播原句压缩出短事实或行动文案，但必须可回溯至原字幕，不扩写含义。
- 渲染优先采用已验证的安全锨点；安全证据为否时必须回退到左右侧保守位置。
- 缺少视觉检测信息时，`key_fact` 使用上区、`reveal` 使用中区、`cta` 使用下区，并为底部字幕与平台控件保留安全边界。

## 18. 下一轮开发规划：镜头内语义动效

本轮目标从“能够渲染贴纸”推进到“动效在正确的镜头、正确的时刻指向正确的对象”。继续保持后台静默完成，不增加或修改当前可见前端操作。

### 18.1 样片复盘结论

`宏昱越南灯具` 前 10 秒样片暴露出五个必须先解决的问题：

1. 事件时间窗跨越硬切，切镜后贴纸仍停留在原位置；
2. `30年灯具工厂` 在同期口播开始前出现，语义与画面错位；
3. 原视频已有烧录字幕时，独立文字卡重复表达同期内容；
4. 贴纸虽避开人脸和字幕，但没有明确指向机器、产品或人物动作；
5. 原始 GIF 含透明阶段，循环播放会产生闪灭，白底文字卡的视觉风格也与商业短视频不协调。

### 18.2 开发阶段 A：镜头边界与事件时间窗（P0）

输入端新增镜头切分结果 `shotWindows`，每个窗口包含 `startMs`、`endMs`、镜头类型和置信度。事件生成后必须与镜头窗口求交集：

- 一个动效实例不得跨越硬切；跨镜头事实拆成多个实例或只保留证据最强的镜头；
- 入场不得早于对应口播或字幕短语，退场不得晚于所属镜头结束；
- 事件前后各保留 80～150 ms 安全边界，避免贴纸与切镜同帧闪现；
- 事件有效时长不足 500 ms 时，降级为字幕字色／字重变化或取消；
- 为事件记录 `evidenceStartMs`、`evidenceEndMs` 和 `shotId`，渲染层不再自行猜测时间。

验收要求：固定样片中的所有高级事件均完全位于单个镜头内；`30年灯具工厂` 只能在相关工厂口播和机器画面开始后出现。

### 18.3 开发阶段 B：字幕占用与信息去重（P0）

在事件决策前判断画面是否已有字幕信息。优先读取项目已有字幕元数据；对外部成片素材补充轻量字幕占用检测，首版只判断底部／中下部是否存在持续文字区域，不在渲染关键路径执行全量 OCR。

- 同期字幕已完整表达事件时，禁止再生成同义文字卡；
- 能修改项目字幕时，只增强原字幕中的关键词；
- 外部素材的烧录字幕不可修改时，只允许使用无文字装饰、指向标记或取消事件；
- 只有价格、规格、年限、CTA 等字幕未完整表达的新增事实，才允许独立短标签；
- 新增 `presentationMode: caption_emphasis | graphic_only | label | none`，由编排层明确下发。

验收要求：宏昱样片中的 `Are you from Vietnam?` 不再出现中文同义标签；`30-year indoor lighting` 已在原字幕中出现时，只保留指向机器或产线的图形强调。

### 18.4 开发阶段 C：逐镜头主体绑定与构图（P0）

布局从“全片固定安全角”升级为“每个镜头独立求解”。分析结果至少提供人物框、产品／机器主体框、字幕占用框和候选空白区。

- 先选择事件所指主体，再选择资产；没有主体证据时不得使用环形或指向型贴纸；
- 贴纸锚点随镜头重新计算，不复用上一镜头坐标；
- 环形光芒围绕主体边缘放置，箭头／光片朝向主体，不能只落在背景空区；
- 标签与装饰合并成一个可缩放组件，禁止形成相互分离的“贴纸＋后台提示框”；
- 对人物脸部、手势、机器运动区域、字幕区和平台控件区执行完整矩形碰撞检测；
- 无可靠构图解时依次降级为 `graphic_only`、字幕强调、取消。

验收要求：人工抽查事件开始、中点、结束三帧，贴纸必须能明确回答“它在强调哪个对象”，并且镜头切换后没有位置继承。

### 18.5 开发阶段 D：资产播放与视觉组件（P1）

对参考 GIF 预计算有效可见帧区间，渲染时采用一次性 `enter → hold → exit`，不再无限循环完整源 GIF。

- 删除或跳过连续透明帧，动效保持阶段不得闪灭；
- 每个事件只播放一次主动画，默认总时长 0.8～1.6 秒；
- 为 `question`、`fact/years`、`product_focus`、`cta` 建立不同组件，不重复使用同一套放射光芒；
- 独立标签改为高对比、圆角、短文字的大字号组件，并随 Profile 统一颜色、描边和阴影；
- 工厂事实优先采用数字主视觉或印章式组件；产品焦点优先采用环形光芒；提问优先使用问号／轻提示，不重复字幕原文。

### 18.6 自动验收与性能（P0）

扩展当前验收脚本，增加以下失败关闭条件：

- 事件跨越 `shotWindows`；
- 事件早于语义证据或晚于所属镜头；
- `label` 与同期字幕发生高相似度重复；
- 资产有效像素在保持阶段连续缺失超过 120 ms；
- 主体框与强调组件没有预期的邻接、包围或指向关系；
- 同一时间出现超过一个主装饰资产；
- 贴纸、标签、主体、字幕或安全边界发生碰撞。

### 19.1 技术栈选择

### 19.4 核心数据契约

```ts
type ShotWindow = {
  id: string;
  startMs: number;
  endMs: number;
  confidence: number;
  source: 'ffmpeg_scene' | 'storyboard' | 'fallback';
};

type VisualEvidence = {
  shotId: string;
  subjectType: 'person' | 'product' | 'machine' | 'process' | 'unknown';
  subjectBox?: { x: number; y: number; width: number; height: number };
  subjectAnchor?: { x: number; y: number };
  safeZones: Array<{ x: number; y: number; width: number; height: number; clarity: number }>;
  captionBoxes: Array<{ x: number; y: number; width: number; height: number }>;
  confidence: number;
};

type EmphasisPresentation = {
  shotId: string;
  evidenceStartMs: number;
  evidenceEndMs: number;
  presentationMode: 'caption_emphasis' | 'graphic_only' | 'label' | 'none';
  targetRelation: 'surround' | 'point_to' | 'adjacent' | 'none';
};
```

所有坐标采用 0～1 归一化值，所有时间采用整数毫秒。服务端完成规范化后签入 Manifest；桌面渲染端只消费结果，不再次调用模型。

### 19.5 事件对齐算法

每个候选事件按以下顺序处理：

1. 找到与字幕或口播证据重叠最多的 `ShotWindow`；
2. `startMs = max(candidate.startMs, evidence.startMs, shot.startMs + 100)`；
3. `endMs = min(candidate.endMs, evidence.endMs + 250, shot.endMs - 100)`；
4. 若结果小于 500 ms，设置 `presentationMode=caption_emphasis`；原字幕不可修改则设为 `none`；
5. 将事件文本与同期项目字幕和 OCR 文本归一化比较；双向包含率达到 0.72，或数字＋单位完全一致时，禁止 `label`；
6. 有可信主体框时选择 `graphic_only` 和主体关系；无主体但存在新增事实时才允许 `label`；
7. 每个镜头最多一个主装饰事件，冲突时按事实可靠度、重要性、主体置信度排序。

### 19.6 模型调用和 Token 控制

Gemini 不直接读取整段视频，也不逐镜头分别请求。一次请求包含：

- 一张最多 18 格、单格 256 px 的 JPEG 联系表；
- 已由本地程序计算好的 `shotId` 和时间范围；
- 最多八条候选事件的短文本、类型和时间；
- 严格 JSON 字段说明。

输出限制在约 2,000 tokens。相同 `sourceSha256 + shotWindows + analyzerVersion` 直接读取 `~/.cache/lingshu-ai/emphasis-analysis/<hash>.json`。纯字幕视频、已有可信 `placementWindows` 的草稿和没有高级事件的视频跳过模型调用。

## 20. 外语词级高亮与多语言排版

当前业务以外语视频为主。字幕高亮的最小语义单元统一改为**按语言切分后的单词**，中文逐字高亮不再作为主要设计基线。句子如何分行、语义短语如何分组、当前哪个词高亮，是三个互不替代的决策：一条字幕可以按完整短语排成一至两行，但仍根据词级时间戳逐词高亮。

### 20.1 时间与分词数据契约

分析层优先消费 ASR 或强制对齐器提供的词级时间戳，再将识别 token 映射成适合展示的单词。禁止仅用空格切分，也禁止由渲染端按字符数临时猜测高亮位置。

```ts
type CaptionCue = {
  id: string;
  startMs: number;
  endMs: number;
  language: string; // BCP 47，例如 fr-FR、de-DE、es-ES
  text: string;
  words: CaptionWord[];
};

type CaptionWord = {
  id: string;
  text: string;                 // 最终展示拼写
  startMs: number;
  endMs: number;
  alignmentTokenIds: string[];  // 可由多个 ASR token 合成一个展示词
  separatorBefore: string;      // 空格、窄不换行空格或空字符串
  confidence: number;
};
```

规范化步骤固定为：

1. 使用音频识别或强制对齐得到原始 token 与时间；
2. 使用 Unicode 分词规则和对应语言 locale 将 token 合并为展示词；实现层优先使用 ICU／`Intl.Segmenter(locale, { granularity: "word" })`，再叠加语言规则；
3. 将标点附着到相邻词，标点本身不产生独立闪烁；
4. 保持原文大小写、变音符号、撇号和连字符；
5. 分行只改变布局，不改变 `CaptionWord` 的时间范围；
6. 缺少词级时间戳时，才按字素权重在 cue 内估算时间，并标记低置信度；低置信度字幕只做轻量当前词变色，不使用强缩放或弹跳。

### 20.2 语言规则

- **法语**：`l’entreprise`、`d’accord`、`qu’il` 等撇号结构保持自然拼写；底层允许多个 alignment token，画面上作为一个展示词高亮。`porte-clés`、`dites-le` 等连字符结构不拆坏。
- **德语**：复合词默认作为一个词高亮，例如 `Energieeffizienzklasse`。单词过长时允许排版层在合法断词点换行，但同一词的高亮状态保持连续；没有可靠形态学证据时不自动拆成词素动画。
- **西班牙语、意大利语、葡萄牙语及其他拉丁字母语言**：保留重音符号、倒置标点和缩合形式；问号、感叹号、逗号和句号跟随相邻词，不单独高亮。
- **英语及其他使用空格的语言**：空格只是候选边界，最终仍以词级对齐结果为准，避免缩写、数字单位和连字符词被错误拆分。
- **阿拉伯语等从右到左语言**：时间仍按语音逻辑顺序存储，由支持 BiDi 和字形塑形的渲染器处理视觉顺序，禁止手动反转字符串。
- **中文、日文、泰文等不能可靠依赖空格的语言**：继续通过 locale 分词器或模型分词得到词级单元；中文兼容能力保留，但不是当前视觉方案的优先优化对象。

### 20.3 字体与高亮表现

外描边与前景字形分层绘制同样适用于外语字幕，并且对拉丁字母的细笔画、法语重音、德语变音符号和字母内部留白更重要。字体栈必须覆盖目标语言全部字形；发生 fallback 时，字号、基线和描边视觉重量需保持一致。

默认高亮只改变当前词的前景色、字重或轻微尺度，整条 cue 的字号、基线、描边宽度和行高保持不变。禁止因词长、语言或高亮状态导致全篇字幕字号跳变。强强调只用于已经进入强调事件预算的关键词，不能随每个口播词重复触发贴纸或独立动效。

### 20.4 验收标准

1. 法语、德语、西班牙语和英语样例均能按照真实发音逐词高亮；
2. 撇号词、连字符词、德语复合词和变音字符显示完整，没有错误拆字或缺字；
3. 标点不会单独闪烁，换行不会改变词级时间；
4. 当前词切换时整句字号、位置、行高和描边不跳变；
5. ASR 缺少词级时间时能明确降级，不制造与语音明显错位的强卡拉 OK 效果；
6. 同一语义只保留一层字幕，高亮在现有字幕内部完成，不额外生成重复文字层。
