# 灵枢 AI 全系统前端体验改版方案 v3.0

> - 文档性质：全系统前端改版总方案 / 设计与开发实施基线
> - 日期：2026-09-27
> - 状态：待产品评审；本轮只输出方案，不修改现有前端代码
> - 第一原则：让用户先读懂，再决定，再操作
> - 覆盖范围：灵枢 AI 主应用、社媒项目与内容生产、广告、客户与订单、企业与系统设置、平台管理后台、公开页面、授权辅助页、独立 AI 账号管理台

---

## 0. 结论先行

这次改版不是单纯统一颜色、圆角和按钮，而是重新安排全系统的信息出现顺序。

目标体验只有一句话：

> 用户进入任一页面后，5 秒内知道“这里是做什么的、现在是什么状态、我下一步要做什么”。

全系统统一为以下阅读顺序：

```text
页面是什么
→ 当前结论是什么
→ 是否需要我处理
→ 唯一下一步是什么
→ 为什么这样判断
→ 历史、技术和诊断细节
```

本方案锁定以下十项改版决策：

1. “智能经营”“首页”“经营工作台”重新命名和分工，消除三个“像首页”的入口。
2. 一级导航按用户业务目标分组，不按组件、Agent 或接口能力分组。
3. 每个页面只保留一个 H1、一个当前结论、一个最高强调主操作。
4. 用户界面默认说“AI 员工、平台授权、内容任务”，不直接暴露 Agent、OAuth、Webhook、任务哈希等技术语言。
5. 空状态不再只解释“为什么没有”，必须给出最短可执行路径。
6. 加载、等待用户、失败、结果未知、完成严格分开；没有真实回执不能显示成功。
7. 内容制作、发布、客户、广告四条主链都用真实 URL 保存对象和步骤，刷新、前进、后退可恢复。
8. 普通页面正文不小于 14px；9–11px 只允许用于非关键元信息并逐步清理。
9. 桌面、平板、移动端使用同一信息优先级，不在移动端简单压缩桌面三栏。
10. 主应用、平台后台、独立账号管理台共用一套设计 Token、组件状态和文案语言。

当前 30 个注册页面 ID 中：

- `retention` 已兼容跳转到 `conversion`；
- `accountManagement` 已兼容跳转到 `traffic`；
- `plugins`、`channels`、`youtube` 共用集成页面；
- `adsCreatives` 是投放计划下的兼容页面；
- `socialSetup`、`socialAccounts`、`socialPlanning` 本质上是同一社媒项目的连续步骤。

这些兼容关系应保留，但不应继续让用户看到重复导航心智。

### 1.3 当前最影响阅读的七类问题

| 问题 | 当前表现 | 用户影响 |
| --- | --- | --- |
| 首页心智重复 | “智能经营”“首页”“经营工作台”并存 | 用户不知道从哪里开始，也不知道三者差别 |
| 页面首屏解释过多 | 机制、限制、状态、证据和按钮同时出现 | 必须阅读大量文字才能找到下一步 |
| 标题体系不统一 | 一部分页面有 H1，一部分以 H2、指标卡或标签开场 | 页面切换后缺少稳定定位感 |
| 技术信息进入业务层 | 页面可见 `webhook_or_status_poll`、API、OAuth、Agent、内部回执口径 | 普通用户难以理解，且降低产品完成度感 |
| 空状态只说明问题 | “尚未接入”“暂无真实数据”“还没有任务”较多 | 用户知道没有，但不知道先去哪一步 |
| 视觉密度失控 | 小字号、圆角卡片、阴影和标签数量过多 | 页面看似丰富，重点反而不突出 |
| 跨页上下文不稳定 | 部分任务上下文依赖 History State、本地缓存或上次状态 | 刷新、前进后退、多标签页时难以预测 |

### 1.4 可量化的界面债务

源码静态扫描显示：

- `text-[9px]`、`text-[10px]`、`text-[11px]` 合计出现约 2,291 次；
- `rounded-2xl`、`rounded-3xl` 合计出现 228 次；
- `shadow-` 类使用约 325 次；
- 抽样的 14 个主要页面组件中，8 个没有直接定义 `<h1>`；
- 根文档仍是 `lang="en"`，默认标题是“领小鼠管理中台”，会影响中文读屏与登录/法律页面标题。

这些数字不代表每一处都必须删除，但说明目前视觉和语义规则主要由页面自行决定，还没有真正收敛为系统级约束。

### 1.5 当前值得保留的基础

以下能力应保留并成为改版基础：

- 对真实数据、真实发布回执和状态未知的谨慎表达；
- 按角色隐藏无权限导航；
- 内容任务的任务上下文条和回退机制；
- 灵感中心已有的媒体卡、预览和“用于创作”能力；
- 内容制作的逐镜、版本、验收与退回逻辑；
- 发布日历和账号连接能力；
- 客户页的列表、会话、客户资料三栏结构；
- 全局 AI 助手、通知、任务监控和后台运行能力；
- 现有绿色、深绿、暖杏、浅灰绿组成的品牌基础。

## 2. 目标体验与信息优先级

### 2.1 用户进入页面时只需要回答四个问题

1. 这是哪个业务页面？
2. 现在发生了什么？
3. 有没有必须由我处理的事情？
4. 我点击后会发生什么？

页面如果不能在首屏回答前三个问题，就需要继续删减和重排。

### 2.2 四级信息层

| 层级 | 内容 | 默认位置 | 示例 |
| --- | --- | --- | --- |
| L0 | 当前结论与必须处理事项 | 页头下方 | “1 条视频等待你确认” |
| L1 | 当前对象和主任务 | 主内容区 | 视频、客户、广告计划、订单 |
| L2 | 影响、依据和更新时间 | 对象附近或详情抽屉 | 影响 1 个镜头、数据更新时间 |
| L3 | 技术字段、原始日志和诊断 | 高级详情或管理员页 | 模型、任务 ID、Webhook、原始回执 |

L3 不再和 L0/L1 平铺在同一首屏。

### 2.3 一页一事

- 一个页面只回答一个主要业务问题。
- 一个区块只回答一个次级问题。
- 一张卡只表达一个对象和一个结论。
- 一个可操作状态只保留一个主按钮。
- 页面允许多个次要查看入口，但不能同时出现多个绿色主按钮。

### 2.4 “阅读友好”的具体定义

阅读友好不是“文字更少”这么简单，而是：

- 标题先说明对象，不写宣传口号；
- 首句给结论，不先讲系统原理；
- 说明文字最多两行；
- 数字必须带口径、时间和范围；
- 用户不需要理解后端、模型和平台接口；
- 错误要说明已保留什么和如何恢复；
- 同一概念全系统只使用一个名称。

## 4. 全局页面骨架

### 4.1 桌面端

```text
┌──────── 232px 侧栏 ────────┬────────────────── 64px 顶栏 ──────────────────┐
│ 品牌 / 当前企业             │ 面包屑 / 页面名         搜索 / 通知 / 账户       │
├─────────────────────────────┼───────────────────────────────────────────────┤
│ 一级导航                    │ H1 页面标题                    页面辅助操作     │
│ 当前分组                    │ 一句页面说明 / 数据范围 / 更新时间             │
│                             ├───────────────────────────────────────────────┤
│                             │ 当前结论 + 唯一下一步                          │
│                             ├───────────────────────────────────────────────┤
│                             │ 当前业务对象 / 列表 / 工作台                   │
│                             ├───────────────────────────────────────────────┤
│ 账户 / 组织 / 帮助          │ 依据、历史、诊断（默认次级或折叠）             │
└─────────────────────────────┴───────────────────────────────────────────────┘
```

### 4.2 页面头部固定结构

每个生产页面统一包含：

1. 面包屑或明确返回路径；
2. 一个 H1；
3. 最多两行的页面说明；
4. 范围、来源和更新时间；
5. 最多一个页面级辅助操作。

页面级主操作通常跟随“当前结论”出现，不机械放在右上角。

### 4.3 任务上下文条

跨页面任务使用统一上下文条，字段按业务显示：

```text
产品 / 客户 / 广告计划 / 内容任务
目标市场 · 平台 · 当前阶段 · 最近保存时间
[返回任务] [查看上下文]
```

上下文条只显示当前对象，不重复完整项目说明。任务 ID、运行 ID 和技术引用放在“技术详情”。

### 4.4 页面宽度

- 数据总览：最大 1440px；
- 表单和配置：正文最大 960px；
- 长文本和法律页面：正文最大 760px；
- 三栏工作台：允许铺满剩余宽度，但每栏必须有最小和最大宽度；
- 页面横向滚动只允许出现在明确的数据表或时间轴容器中。

## 5. 视觉与排版系统

### 5.1 继续使用现有品牌基础

| Token | 值 | 用途 |
| --- | --- | --- |
| Brand / Primary | `#117F51` | 主操作、当前选择、成功 |
| Brand Deep | `#173D31` | 标题、正文主色 |
| Canvas | `#F6F8F5` | 页面背景 |
| Surface | `#FFFFFF` | 面板和输入控件 |
| Border | `#DFE8E1` | 边框和分隔 |
| Muted | `#617169` | 次级信息 |
| Attention | `#E98268` / `#FFF3E7` | 需要人工处理、洞察 |
| Danger | `#B74D43` | 已确认失败或危险动作 |

颜色必须和文字或图标同时出现，不能只靠颜色表达状态。

### 5.2 字体层级

| 层级 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| Display | 36 / 44 | 极少数经营结果或空状态主结论 |
| H1 | 28–32 / 38 | 页面标题 |
| H2 | 20–22 / 30 | 主要区块 |
| H3 | 16–18 / 26 | 卡片和子区块 |
| Body | 14 / 22 | 默认正文和业务信息 |
| Body S | 13 / 20 | 次级说明 |
| Meta | 12 / 18 | 时间、来源、标签 |

规则：

- 关键状态、按钮、表单标签和数据口径不得使用 9–11px；
- 12px 不能承载必须读懂才能完成任务的信息；
- 数字使用等宽数字特性；
- 中文标题不使用全大写英文前缀抢占注意力；
- 英文仅用于品牌、平台名和确有必要的专业名词。

### 5.3 容器和卡片

- 普通面板圆角 8px，重点面板 12px，弹层 12px；
- 常规面板不使用阴影，以边框、留白和分隔线建立层级；
- 阴影只用于 Drawer、Dialog、Popover 和悬浮操作；
- 列表行不做成一排独立大卡；
- 不允许超过两层卡片嵌套；
- 胶囊只用于短状态，不用于普通按钮和长文案。

### 5.4 主视觉和缩略图

- 需要用户评估内容、产品、广告素材或成果时，主视觉优先于描述文字；
- 缩略图必须标明来源：企业素材、平台公开内容、AI 生成或示例；
- 示例内容显式标“示例”，不能伪装成真实客户结果；
- 无图时使用稳定占位，不使用与业务无关的装饰图。

## 6. 全系统文案规范

### 6.1 标题公式

页面标题优先使用“业务对象”或“用户任务”，避免宣传式长句。

| 不推荐 | 推荐 |
| --- | --- |
| 不会拍、不会剪也能做视频。选择一种制作方式，剩下的交给编导 Agent 和内容 Agent。 | 内容制作 |
| 花费有依据，增长看全程 | 投放总览 |
| 让每一次托管操作都有依据 | AI 投放托管 |
| 数字员工正在等待调遣 | 本周还没有经营计划 |

宣传性表达可以放在说明或营销落地页，不作为生产页面 H1。

### 6.2 状态文案公式

```text
[对象] + [当前结果或动作] + [是否需要用户处理]
```

示例：

- “视频正在合成第 5 个镜头；无需操作。”
- “镜头 4 缺少产品事实；请改用安全表达或补充资料。”
- “TikTok 暂未返回发布结果；系统正在核对，请勿重复发布。”
- “6 个镜头已通过检查；等待你确认成片。”

### 6.3 错误文案四段式

1. 哪个对象出了什么问题；
2. 已保留什么；
3. 为什么发生；
4. 用户现在可以做什么。

示例：

> YouTube 暂未返回发布结果。成片和发布设置已保留，系统正在核对平台状态；请稍后刷新，不要重复发布。

### 6.4 术语统一

| 当前或技术用语 | 用户界面统一用语 | 使用范围 |
| --- | --- | --- |
| Agent | AI 员工 / AI 编导 / 内容 AI | 普通用户界面 |
| OAuth | 平台授权 | 普通用户界面 |
| Webhook / Poll | 自动同步方式 | 只在高级详情显示 |
| `webhook_or_status_poll` | 不展示 | 仅诊断日志 |
| ReplicationJob | 内容任务 | 全系统 |
| Artifact | 成果 / 成片 / 文件 | 按真实对象命名 |
| AI 托管模式 | 自动执行 | 设置和状态 |
| 人工接管 | 转人工处理 | 客服和异常流程 |
| 暂无真实数据 | 还没有数据 + 原因 + 下一步 | 空状态 |
| 连接广告账户 | 连接广告账号 | 按中文一致性统一 |
| 智能体记忆 | AI 记忆 | 导航与页面标题 |

### 6.5 按钮文案

按钮使用“动词 + 对象”，点击前说明结果：

- `开始制作`
- `确认成片`
- `退回修改`
- `连接 YouTube`
- `创建广告计划`
- `发送回复`
- `保存权限`

避免：`确定`、`提交`、`处理`、`下一步`等脱离上下文的泛化词。多步流程可以使用“下一步：选择素材”。

### 6.6 空状态

统一结构：

```text
还没有什么
为什么没有 / 建立后会获得什么
[唯一主操作]
可选帮助链接
```

示例：

```text
还没有内容数据
先发布并登记一条内容，系统才能同步播放和互动数据。
[去发布内容]
查看支持的平台
```

## 7. 全局交互规范

### 7.1 页面状态

每个生产页面至少设计以下状态：

| 状态 | 页面表现 | 必须提供 |
| --- | --- | --- |
| Loading | 保留骨架和页面定位 | 正在加载的对象名 |
| Empty | 明确当前没有什么 | 最短下一步 |
| Ready | 展示当前对象和主任务 | 唯一主操作 |
| Running | 展示真实阶段或完成数量 | 是否可以离开页面 |
| Needs action | 暖杏提醒并提升到首屏 | 对象、影响、决定 |
| Error | 红色只用于确认失败 | 已保留内容和恢复动作 |
| Unknown | 平台或网络结果未知 | 核对状态，禁止盲重试 |
| Offline | 保留最后数据和时间 | 重连入口；禁用高风险动作 |
| Complete | 先展示结果和回执 | 合理的下一步建议 |

### 7.2 异步动作

异步操作按固定时序反馈：

1. 点击后 100ms 内进入 Loading，阻止重复提交；
2. 服务端接受后显示持续任务状态，不让按钮一直转圈；
3. 使用真实阶段或 `完成 x/y`，不用人为映射百分比；
4. 用户离开页面后任务继续，可从通知或执行现场找回；
5. 成功展示结果和真实回执；失败保留输入和已有成果。

### 7.3 表单与保存

| 内容 | 保存方式 |
| --- | --- |
| 简单筛选和低风险偏好 | 自动保存 |
| 多步创建 | 每步自动保存草稿 |
| 复杂设置 | 明确“保存设置” |
| 权限、预算、对外动作边界 | 版本化保存 + 影响确认 |

表单规则：

- 必填项在提交前可见，不在提交后才集中报错；
- 错误就近显示，并聚焦第一个错误字段；
- 离开 Dirty 页面前提供保存、放弃、继续编辑；
- 已保存、保存中、保存失败必须可区分；
- 不能用 Toast 替代重要的页面级失败。

### 7.4 列表、筛选和详情

- 筛选收起后显示“已启用 n 项筛选”并提供清除；
- 筛选结果为 0 时清空旧详情，不能继续操作已被过滤对象；
- 列表负责管理，右侧抽屉负责轻详情，完整页面负责连续重操作；
- 翻页和刷新失败时保留原列表；
- 任务详情通过 URL 保存 `taskId` 和 `view`，不只依赖内存状态。

### 7.5 Dialog 与 Drawer

- Dialog 只用于确认、少量编辑和高风险决定；
- Drawer 用于不打断列表上下文的详情和轻编辑；
- 上传、制作、验收、复杂设置使用完整页面；
- 支持焦点锁、Esc、关闭后恢复焦点；
- 提交中的关闭不等于取消任务；
- 危险 Dialog 默认聚焦“取消”，不能让 Enter 误触确认。

### 7.6 高风险动作

发布、真实发送、报价承诺、广告花费、权限扩大、渠道解绑和删除必须显示：

- 操作对象；
- 最终内容或参数；
- 账号/接收人/预算/范围；
- 影响和不可逆性；
- 当前版本；
- 成功后的真实回执。

### 7.7 通知与全局 AI 助手

- 通知中心只保留需要处理、完成、失败和结果未知四类高价值事件；
- 页面已明确展示的错误不再重复弹相同 Toast；
- 全局 AI 助手是唯一自然语言对话入口；
- 页面内“问问灵小枢”“灵小枢操作台”改为普通业务动作或帮助链接；
- 助手读取当前 `page + objectId + stage` 上下文，但不替代页面主操作；
- 移动端助手必须避让底部主操作栏和安全区。

## 8. 各界面改版方案

### 8.1 登录、注册与公开页面

#### 登录 / 注册

当前问题：登录与注册整体结构已较清楚，但标题和默认浏览器元数据不统一，邀请注册错误信息仍偏系统化。

目标首屏：

```text
灵枢 AI
登录工作台
继续处理今天的内容、客户和经营任务。

邮箱
密码                         忘记密码 / 联系管理员
[登录]

没有账号？使用企业邀请码注册
```

规则：

- 登录和注册共用稳定框架，切换不造成布局跳动；
- 邀请码先验证再显示企业名称和将获得的角色；
- 分开表达“密码错误”“账号停用”“网络不可用”；
- 页面标题、语言和品牌元信息在进入页面时立即正确设置；
- 输入框正确设置自动填充属性，成员创建表单不能接收管理员登录凭据。

#### 授权辅助链接

使用三种单一状态：等待授权、授权完成、链接失效。按钮明确写“连接 Facebook”“返回灵枢 AI”，不写泛化“继续”。

#### 法律页面

- 增加页内目录和当前章节高亮；
- 更新日期、适用范围和联系方式固定在页头；
- 正文最大宽度 760px、字号至少 14px；
- 每个页面设置正确的浏览器标题；
- 文档根语言改为 `zh-CN`。

### 8.2 今日工作台与经营总览

#### 今日工作台（`digitalEmployees`）

当前：以“数字员工正在等待调遣”和四个过程入口为主，尚未制定目标时信息较空。

目标首屏顺序：

1. 今天需要你处理；
2. 本周经营计划和唯一下一步；
3. 正在执行的 AI 员工；
4. 最近完成结果；
5. 经营异常和系统提醒。

空状态改为：

```text
本周还没有经营计划
确定一个主目标后，AI 员工会自动拆解内容、客户和跟进任务。
[制定本周目标]
查看推荐目标
```

“Agent 设置”“历史记录”“执行现场”放在页头辅助操作或更多菜单，不和主任务并列。

#### 执行现场（`agentMonitor`）

默认展示：执行中 → 等待用户 → 失败 → 最近完成。每个任务行只显示业务任务名、AI 员工、真实阶段、开始时间和当前需要。浏览器画面和原始事件只在展开任务后显示。

空状态主文案：

> 当前没有正在执行的任务。任务开始后会自动出现在这里，无需停留等待。

#### 经营总览（`strategy`）

当前：获客指标、漏斗、建议、外部市场信号和社媒数据同时平铺。

目标结构：

1. 本周期结论；
2. 3–5 个关键指标；
3. 从曝光到订单的漏斗；
4. 本周优先动作；
5. 渠道表现；
6. 外部市场信号与来源。

外部信号不直接混入企业经营结论，必须标“外部参考”；没有内部数据时不生成确定性经营判断。

### 8.3 社媒项目

#### 社媒项目总览（`socialWorkspace`）

将“项目方向、账号矩阵、内容计划、执行复盘”保留为一个项目内四步，而不是四个类似一级页面。

目标布局：

```text
社媒项目 / Aurelia 美国市场
项目已完成 2/4 步；下一步需要确认账号分工。
[继续配置账号]

项目方向      已完成
账号矩阵      待确认
内容计划      未开始
执行与复盘    未开始
```

没有项目时只显示项目价值、最少字段和“创建社媒项目”。

#### 项目方向（`socialSetup`）

表单只保留品牌/业务线、市场、目标受众、经营路线和候选平台。字段下直接解释对后续页面的影响；保存后显示项目摘要，不再反复提醒“不会用虚构数据”。

#### 账号矩阵（`socialAccounts`）

以账号卡或表格展示平台、账号、职责、内容方向、状态和负责人。账号未授权时提供“先建立账号规划”和“去连接真实账号”两个不同动作，不把规划和授权混为一谈。

#### 内容计划（`socialPlanning`）

月目标、周主题、发布频率和验收标准分层；默认只让用户确认目标和节奏，高级平台配比放在更多设置。

### 8.4 灵感、素材与内容制作

#### 灵感与素材（`socialInspiration`）

当前：范围、场景簇、运行统计、平台、形式、筛选和 30 张卡同时出现，首屏密度高。

目标结构：

```text
灵感与素材
为“美国 · 护肤品买家”找到 31 条相关内容，最近更新 10:32。
[调整发现范围]

找灵感 | 我的素材 | 拍摄任务
搜索 + 关键筛选                         已启用 2 项筛选

媒体网格 / 列表
```

卡片只显示：封面、标题、平台、时长/形式、与当前业务的相关性、一个主动作“用于创作”。来源、趋势、迁移性和判断依据放详情抽屉。

#### 脚本与历史（`scriptLibrary`）

不再强调“脚本库”是独立系统。目标页签：可继续制作、历史版本、已归档。列表先显示产品/主题、平台、状态、更新时间和下一步，长脚本文本进入详情。

#### 内容制作首页（`smartAssets`）

当前：两种制作方式、长说明、任务状态、准备情况、制作链路、逐镜分析和批次验收可能同时出现。

目标按生命周期变化：

| 用户状态 | 首屏优先内容 | 主操作 |
| --- | --- | --- |
| 无任务 | 素材加工、爆款裂变两个入口 | 选择制作方式 |
| 有待处理 | 待确认/待补资料事项 | 处理当前事项 |
| 正在制作 | 当前阶段、完成数量、可离开提示 | 查看制作进度 |
| 待验收 | 成片或图文预览 | 验收成果 |
| 已交付 | 交付包与发布准备 | 去发布 |

入口页 H1 固定为“内容制作”，说明压缩为：

> 选择现有素材加工，或参考一条优秀内容重新制作。

两张入口卡：

- 素材加工：`使用已有产品图、视频或企业资料制作内容`；
- 爆款裂变：`参考结构和节奏，用你的产品重新表达`。

进入任务后，统一阶段：资料 → 策划 → 制作 → 检查 → 验收 → 交付。编导、内容 AI、模型和供应商细节进入阶段详情。

成果卡必须以真实媒体预览为主。退回修改使用结构化原因：画面、文案、事实、声音、字幕、平台规格、其他。

### 8.5 发布中心与内容复盘

#### 发布中心（`traffic`）

当前：发布、账号、日历、潮汐、节庆、发布节奏和待发布内容集中在一个长页面。

目标页内视图：

1. 待发布；
2. 内容日历；
3. 发布记录；
4. 账号状态。

默认进入“待发布”，先看到可以做什么，再进入日历安排时间。日历中的节庆和建议时段是辅助信息，不占据待发布首屏。

发布确认必须显示：内容预览、目标平台和账号、文案、时间、权限、当前内容版本。发布包下载、平台已接收、发布成功严格使用不同状态。

#### 内容复盘（`socialMonitoring`）

当前首屏先解释五个平台能力，并直接显示技术状态名。

目标首屏：

1. 时间、账号和更新时间；
2. 内容整体结果；
3. 异常和数据缺口；
4. 内容排名与趋势；
5. 可复用结论；
6. 平台连接能力折叠区。

空状态：

> 还没有可复盘的内容数据。先发布并登记一条内容，或连接平台账号自动同步。

主操作根据条件显示“去发布内容”或“连接平台账号”，不同时高亮两个动作。

### 8.6 广告投放

#### 投放总览（`adsOverview`）

当前将“未接通、无报告、日期口径、计划预算、漏斗限制”等大量说明放在首屏。

目标结构：

1. 当前周期结论；
2. 花费、触达、有效询盘、成交回报；
3. 投放漏斗；
4. 计划和素材表现；
5. 数据覆盖与核对。

数据未接通时，用一块状态说明替代每个指标重复“未接通”。技术口径进入“数据说明”。

#### 投放计划与广告素材（`adsPlans` / `adsCreatives`）

页面使用“计划 / 素材 / 审批”页签。无计划时只显示创建计划所需内容：目标、账号、素材、预算、周期和受众。

“手动创建投放”“AI 辅助创编”“AI 托管创编”不作为三个同级主按钮。先创建计划，再在计划内选择协作方式。

#### AI 投放托管（`adsManaged`）

第一眼回答：哪些计划已授权、正在执行什么、有什么需要批准、哪些状态需要核对。授权不等于运行，平台已接收不等于投放有效。

主操作改为“选择广告计划”，说明：

> 设置目标、预算和审批边界后，AI 才能开始执行。

### 8.7 客户、客服与订单

#### 企业微信客服（`wecomCustomerService`）

保持会话工作台，但首屏只展示：待首次回复、草稿待确认、需人工、发送失败。配置缺失时显示缺少的配置类别和“去配置企业微信”，不在业务页要求用户理解 CorpID、Secret、Token、AESKey 的细节；详细字段留在集成设置。

#### 客户与会话（`conversion` / `retention`）

保留三栏：客户列表、会话、客户资料。优化为：

- 左栏先显示意向、最近动作、下一步和负责人；
- 中栏明确区分客户消息、AI 草稿、已发送消息；
- 右栏优先展示客户结论和待办，完整画像按需展开；
- 筛选为 0 时清空详情和操作；
- 自动回复能力采用设置提示，不用模态框在无关时阻断主任务。

发送前显示接收人、渠道、最终文本和审批状态。只有渠道回执成功后标“已发送”。

#### 订单管理（`orders`）

补齐标准 H1 和页头说明。首屏顺序：有效 GMV、待处理订单、筛选、订单列表。新增订单使用独立 Drawer；导出显示文件名、条数和成功/失败；订单必须来自正式记录，不从聊天推断成交。

### 8.8 企业资料、AI 记忆和自动任务

#### 企业资料（`enterprise`）

当前将企业真实资料、社媒策略、客服规范和产品资料放在多个嵌套层级。

目标首页先展示资料完整度和对 AI 工作的影响：

```text
企业资料完成 72%
还缺公司介绍和 2 个产品事实，会影响内容开场和客户报价。
[继续补充资料]
```

页签：公司与市场、产品、内容策略、客服规范、资料来源。每项显示已确认/待确认、来源、更新时间和使用范围。

#### AI 记忆（`agentMemory`）

每条记忆回答：记住了什么、来自哪里、用于哪些工作、何时更新、谁可以修改。内容运营经验、沟通风格、客户上下文、响应策略保留为分类；“内容运营监控”不与记忆编辑混为同一首屏。

#### 自动任务（`scheduled`）

当前模板、实时动态、企业资料状态和任务列表同时出现。

目标默认先显示任务列表：任务名称、执行内容、下次时间、最近结果、负责人。模板作为“新建任务”入口。点击“立即执行”后必须立即出现运行状态和最终结果。

### 8.9 账号、集成与权限

#### 账号与集成（`plugins` / `channels` / `youtube`）

默认按平台显示：连接状态、能力范围、连接账号、上次同步、需要修复的问题和主操作。开发者应用凭证放入“高级配置”，不在普通用户首屏展示 Client ID、Secret、Redirect URI。

平台卡统一状态：未配置应用、可连接账号、已连接、需要重新授权、同步失败、权限不足。

#### 团队与权限（`organizationPermissions`）

页签：成员、角色、权限变更记录。成员列表先显示姓名、角色、状态和最近活动。添加成员表单明确邀请码或初始密码的生命周期，禁止浏览器用管理员凭据自动填充。

角色说明使用业务能力，不堆页面名：

- 社媒运营：管理灵感、内容、发布和复盘；
- 客服：处理客户、会话和订单；
- 管理员：管理企业设置、成员和集成；
- 超级管理员：管理管理员与全部组织能力。

### 8.10 平台管理员后台

#### 账号总控（`admin`）

按“需要处理的问题”优先：试用到期、登录异常、配额异常、支持访问、权限风险。账号分类和运营数据放在后续区块。

#### 客户运维（`adminDelivery`）

按客户列出交付状态、连接状态、失败任务、最近联系和负责人。内容运维、客户部署作为页签；高风险支持访问始终显示租户、有效期和只读/可写范围。

管理员页面继续遵守租户隔离，不因为信息密度高而缩小关键文字。

### 8.11 独立 AI 账号管理台

当前账号管理台整体职责清楚，但英文前缀、10px 文字、运维术语和多个同级按钮较多。

目标导航：

- 团队用量；
- AI 账号；
- 连接状态；
- 操作记录。

登录页删去 `Host operations` 等英文装饰，保留一句安全说明：

> 这里只登录管理台，不会收集 Codex 或 Claude 的密码。

账号页将“添加槽位 → 成员官方登录 → 运行连接器 → 状态同步”做成可展开指引；常态页面只显示账号、归属成员、连接状态、最近心跳和需要处理的问题。命令、Token 类型和配置文件权限放到连接指引，不占据列表主视图。

### 8.12 领小鼠管理中台

这是内部经营管理产品，不与灵枢客户工作台共用页面标题。保留经营总览、公司、协作、客户、产品、服务器与设置六个模块，但清理 8–10px 英文装饰标签；“LIVE DATA”“SYSTEM LINK”等改为中文业务状态。

## 9. 核心端到端流程

### 9.1 首次进入

```text
登录/邀请注册
→ 确认企业与角色
```

### 9.2 社媒内容闭环

```text
社媒项目 / 灵感与素材
→ 内容制作
→ 资料准备

→ 用户验收
→ 交付包
→ 发布中心

```

### 9.3 客户经营闭环

```text
企业微信客服 / 客户列表
→ 判断意向与下一步
→ AI 起草
→ 人工确认并发送
→ 报价
→ 正式订单
→ 跟进与复购
```

AI 草稿、真实发送、客户承诺和订单状态在视觉与状态上严格分开。

```text
连接广告账号

→ 投放总览

```

### 9.5 系统配置闭环

```text
企业资料
→ AI 工作边界
→ 账号与集成
→ 团队与权限
→ 自动任务
```

设置页面必须说明“改动会影响哪些任务”，不能只展示字段。

## 10. 响应式与无障碍

### 10.1 响应式断点

| 范围 | 规则 |
| --- | --- |
| `>= 1280px` | 完整侧栏，可使用双栏或三栏工作台 |
| `768–1279px` | 侧栏可收起，辅助列下移或进入 Drawer |
| `< 768px` | 内容单列，导航为全屏抽屉，详情为全屏层 |

移动端不能保留 64px 图标栏后再压缩内容宽度；默认应让主内容占满屏幕。

### 10.2 移动端优先级

移动端固定顺序：

1. 页面标题；
2. 当前结论；
3. 唯一主操作；
4. 当前对象；
5. 次级内容；
6. 证据和历史。

长流程使用底部主操作栏，但不能遮挡最后内容或全局助手。

### 10.3 无障碍基线

- 根文档使用 `lang="zh-CN"`；
- 每页一个可识别 H1；
- 正文对比度至少 4.5:1；
- 图标按钮有可访问名称；
- 状态使用文字 + 图标 + 颜色；
- 移动触控目标至少 44×44px，桌面至少 40×40px；
- Tabs 使用正确语义、方向键和焦点管理；
- Dialog/Drawer 支持焦点锁、Esc 和关闭后焦点恢复；
- 表单错误使用 `aria-invalid` 与 `aria-describedby`；
- 异步关键状态通过 `aria-live="polite"` 播报；
- 图表提供表格或可访问摘要；
- 390px 宽和 200% 缩放下不出现整页横向滚动；
- 尊重 `prefers-reduced-motion`。

## 12. 分阶段实施计划

### 阶段 0：冻结基线

- 评审本方案的导航、命名和页面职责；
- 确认哪些旧入口保留兼容、哪些只保留深链；
- 建立全量页面和状态清单；
- 锁定 Token、字号、主操作和文案规范；
- 不改业务接口，不改真实状态边界。

完成标准：产品、设计、前端、测试对同一页面树和术语表达成一致。

### 阶段 1：全局骨架与阅读基础（P0）

- 页面注册表单一信息源；
- 新导航和页面命名；
- 统一 PageHeader、NextActionPanel、状态和空状态；
- 根语言、浏览器标题、H1 和焦点基础；
- 关键正文清理到 14px；
- 移动端导航改为 Drawer。

完成标准：所有主要页面有稳定标题、当前结论和唯一下一步。

### 阶段 2：经营与社媒主链（P0）

- 今日工作台、执行现场、经营总览；
- 社媒项目四步；
- 灵感与素材；
- 内容制作生命周期首页和任务 URL；
- 待发布、日历、发布记录拆分；
- 内容复盘结果优先。

完成标准：用户能完成“找灵感 → 制作 → 验收 → 发布 → 复盘”，且每一步能说明当前状态和下一步。

### 阶段 3：客户与广告主链（P0/P1）

- 企业微信配置空状态；
- 客户列表、会话和资料三栏状态一致；
- 发送、报价和订单回执；
- 投放总览、计划、素材和托管分层；
- 结果未知与对账流程。

完成标准：AI 草稿不误标发送，平台请求不误标成功，广告授权不误标运行。

### 阶段 4：企业设置与后台（P1）

- 企业资料完整度；
- AI 记忆可解释性；
- 自动任务列表；
- 集成连接状态；
- 团队权限和审计；
- 平台管理员后台；
- 独立 AI 账号管理台。

完成标准：管理员能在不阅读技术文档的情况下完成常用配置；技术细节仍可在高级区找到。

### 阶段 5：视觉清理与质量门槛（P1/P2）

- 清理 9–11px 关键文本；
- 减少无意义圆角、阴影、胶囊和英文装饰；
- 统一图表、表格、媒体预览；
- 完成 1440、1024、390 三个视口验收；
- 完成键盘、读屏、200% 缩放和 Reduced Motion 验收。

## 13. 验收标准

### 13.1 全局

- [ ] 用户 5 秒内能说出页面名称、当前状态和下一步。
- [ ] 每个页面只有一个 H1 和一个最高强调主操作。
- [ ] 关键业务文字不小于 14px。
- [ ] 页面不直接展示未翻译的技术状态和内部字段。
- [ ] 空状态都有原因、价值和下一步。
- [ ] 所有数据展示范围、来源或更新时间。
- [ ] 示例、AI 生成和真实数据可区分。

### 13.2 交互

- [ ] 异步动作 100ms 内有反馈，且最终状态可找回。
- [ ] 列表筛选为 0 时不保留旧详情和可操作按钮。
- [ ] 刷新、前进、后退和新标签能恢复任务上下文。
- [ ] 重要失败保留用户输入和已完成成果。
- [ ] 禁用按钮就近说明解锁条件。
- [ ] Dialog、Drawer 和表单具备完整键盘与焦点行为。

### 13.3 真实性与安全

- [ ] 任务完成、交付包生成、平台接收和真实发布状态严格分开。
- [ ] AI 草稿和真实发送状态严格分开。
- [ ] 授权、运行、花费和结果状态严格分开。
- [ ] 结果未知时先核对，不允许盲目重复提交。
- [ ] 无权限导航隐藏，深链进入显示可解释的权限状态。
- [ ] 敏感凭证只在需要的高级配置中出现。

### 13.4 响应式与无障碍

- [ ] 1440、1024、390px 完成核心流程实测。
- [ ] 390px 与 200% 缩放无整页横向滚动。
- [ ] 触控目标符合最小尺寸。
- [ ] 颜色不是唯一状态表达。
- [ ] 键盘可完成创建、筛选、审批、保存和预览。
- [ ] 页面语言、标题、H1、表单标签和图标名称完整。

### 13.5 体验指标

改版前先记录基线，改版后持续观察：

- 首页找到唯一下一步的成功率；
- 首次创建内容任务的完成率和中位耗时；
- 内容任务中途退出率；
- 空状态主操作点击率；
- 因不理解状态导致的重复提交率；
- 发布结果未知时的重复发布率；
- 打开技术详情和 AI 助手求助的比例；
- 首次交付后 7 天内再次创建内容的比例；
- 移动端任务完成率；
- 可访问性自动检查和人工键盘检查通过率。
