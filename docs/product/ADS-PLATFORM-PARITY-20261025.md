## 后续实现与验收约束

1. 每个操作登记平台、API 版本、对象层级、目标/资产条件、权限、输入、原执行入口、回执及验证证据。平台 UI 有而 API 不开放的能力明确区分，保留原生平台入口；未开发与无权限不能混为同一禁用原因。
2. 每类数据登记请求字段、未请求字段、响应页数、完整性、原始业务载荷、归一化结果及派生算法；不请求所有字段的盲目通配，按平台合法组合采集并记录缺项。原值与平台补报修订保留，不将金额字符串、缺失值或多个 action_type 压成失真的单值。
3. 原始业务数据在企业权限内可查看/导出；凭证和签名脱敏，记录脱敏位置；分页链接不直接交给浏览器携带 access_token。客户字段须遵守来源权限，不凭单一线索聚合指标推测客户身份。
4. UI 两主页面保持；高级功能采用对象就近操作和按需展开。AI 自动填充可验证的技术信息，预算、目标和业务承诺仍由用户确认；不新增客户跟进负责人/联系渠道门禁。
5. 扩充动作复用既有幂等、租约、授权、审批、未知结果与资源读回链；不通过放宽 paused_only 获得假就绪。真实写平台、发布、扣费及 Webhook 订阅不随浏览自动触发。
6. 先完成离线请求/响应与权限测试，再在获得真实联调授权且符合仓库稳定基线要求时验收供应商；页面按钮出现、构建通过、模拟数据通过均不能证明平台操作完成。
