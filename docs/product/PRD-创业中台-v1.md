# 灵枢｜创业中台 PRD

> 版本：v1.0 评审稿
> 日期：2026-09-22
> 状态：待产品评审，尚未进入全面开发
> 产品定位：面向创业公司创始人和核心团队的统一经营、协作、产品研发与技术运维中台

## 0. 一分钟看懂产品

创业中台要解决的不是“再做一个项目管理工具”，而是让一家创业公司的关键对象进入同一套可关联、可追踪、可复用、可审计的系统：

- 公司层：主体、证照、合同、印章、股权、财务、税务、人员。
- 执行层：目标、项目、待办、日历、审批、业务 SOP。
- 产品层：产品、需求、版本、发布、统一 API、统一日志与 Bug。
- 技术层：服务器、域名、证书、云资源、服务状态、安全事件。
- 资产层：SOP、模板、组件、脚本、提示词、连接器等可复用能力。
- 治理层：用户、角色、数据权限、敏感字段、审批和审计日志。

平台首页只回答三件事：

1. 公司现在是否健康。
2. 今天最需要处理什么。
3. 每一项经营结果可以追溯到谁、什么任务、哪份数据和哪个版本。

## 1. 背景与问题

创业公司的信息通常分散在表格、聊天、网盘、财税软件、项目工具、代码仓库、云厂商和监控平台中，容易出现：

- 创始人无法快速得到现金、税务、人员、产品和服务器的完整状态。
- 待办与业务目标脱节，完成了很多任务但无法判断是否推进经营结果。
- API 文档、版本、负责人和调用凭证分散，接口变更不可追踪。
- 日志、告警、Bug、任务和发布版本相互割裂，故障定位与复盘成本高。
- SOP 停留在文档里，无法形成可执行、可统计、可持续改进的流程。
- 已验证的模板、脚本、组件和方法重复开发，团队能力无法沉淀。
- 成员离职、外包协作或角色变化后，权限无法及时回收或审计。

## 2. 产品目标

### 2.1 核心目标

1. 建立创业公司统一的经营数据入口和行动入口。
2. 让任务、项目、产品、API、Bug、发布、服务器与经营目标互相关联。
3. 将业务 SOP 从“静态文档”变成可执行、可留痕、可复盘的流程实例。
4. 将团队反复使用的方法和工具沉淀为有版本、有负责人、有使用数据的能力资产。
5. 建立最小权限、敏感数据隔离、临时授权和完整审计机制。

### 2.2 成功指标

| 指标 | 首期目标 |
| --- | --- |
| 创始人获得完整经营概览所需时间 | 小于 3 分钟 |
| 关键事项有负责人和截止时间的覆盖率 | 大于 95% |
| 生产 API 有负责人、文档和版本的覆盖率 | 大于 90% |
| 线上 Bug 可关联日志、版本和处理人的比例 | 大于 80% |
| 高频业务 SOP 化覆盖率 | 大于 70% |
| SOP 或能力资产月复用率 | 持续增长，可按团队统计 |
| 高风险权限有审批与审计记录的覆盖率 | 100% |

### 2.3 非目标

- 首期不自研完整财务会计、工资核算或电子报税系统。
- 不直接保存网银、税务局、云厂商的明文密码或长期密钥。
- 不替代代码仓库、专业 APM、日志存储和云监控平台，而是统一目录、关联和处理入口。
- 不在首期建设复杂低代码平台；SOP 先支持标准步骤、表单、审批和自动动作。
- 不允许 AI 在无人确认时执行付款、报税、删库、生产发布、权限提升等高风险操作。

## 3. 用户与角色

| 角色 | 主要诉求 | 默认权限建议 |
| --- | --- | --- |
| 创始人／Owner | 掌握全局状态、风险、现金和重大决策 | 全局可见；高风险操作仍需二次确认 |
| 公司管理员 | 管理成员、角色、主体、制度和审计 | 系统配置与组织管理，不默认查看薪资明细 |
| 财务／税务 | 资金、发票、报销、申报、合同付款 | 财税模块读写；敏感字段按职责隔离 |
| HR／行政 | 人员、合同、入离职、证照、资产 | 人事行政范围读写，不默认查看产品密钥 |
| 产品／项目负责人 | 产品、需求、版本、项目与 SOP | 所负责产品及项目读写 |
| 研发／运维 | API、Bug、日志、发布、服务器 | 按环境和服务授权；生产操作单独控制 |
| 普通成员 | 个人任务、参与项目和被授权知识 | 仅本人及参与范围 |
| 外部顾问／外包 | 临时协作 | 有时效的最小权限，不进入默认组织数据范围 |
| 审计只读 | 查阅记录和导出审计证据 | 只读、带水印、禁止批量导出敏感字段 |

## 5. 经营总览

### 5.1 首页指标

- 可用现金、月度净现金流、现金跑道、待收款、待付款。
- 本月待缴税、下一申报截止日、缺失发票、税务异常。
- 团队人数、试用期、合同到期、招聘、待审批事项。
- 本周任务完成率、逾期事项、阻塞项目、待决策事项。
- 产品版本、活跃需求、发布风险、客户反馈。
- 服务可用率、未恢复故障、资源成本、证书到期、安全提醒。

### 5.2 今日关注

系统按以下因素排序，不只按时间排序：

- 法定或合同截止时间。
- 现金、合规、客户或生产风险。
- 事项优先级、影响范围和依赖关系。
- 是否阻塞其他任务、发布、回款或人员入职。
- 当前用户是否有权限和能力完成该动作。

每条提醒必须展示负责人、截止时间、影响、数据来源和下一步动作。

### 5.3 全局搜索与关联

支持搜索公司、人员、合同、任务、产品、API、Bug、日志、服务器、SOP 和能力资产。搜索结果遵守用户权限，敏感字段不进入无权限索引。

## 6. 公司中心

### 6.1 公司主体与合规

- 公司主体、统一社会信用代码、注册地址、开户行等基础档案。
- 营业执照、许可证、知识产权、域名、保险等证照台账。
- 证照有效期和年报提醒。
- 印章类型、保管人、使用申请和使用记录。
- 合同台账、相对方、金额、履约节点、续约与终止提醒。
- 股权结构、期权池、融资轮次和董事会决议归档。

### 6.2 财务资金

- 账户与资金余额；首期允许手工录入或导入，后续接银行开放接口。
- 收入、支出、应收、应付、报销、预算和成本中心。
- 发票与合同、客户、付款、报销之间的关联。
- 月度现金流、预算执行、成本趋势和现金跑道预测。
- 大额付款、重复付款、逾期应收和预算超支提醒。
- 敏感金额按字段权限控制，所有修改保留审计记录。

### 6.3 税务

- 税种、申报周期、税务主管机关、办税人员和服务商档案。
- 税务日历、申报任务、应缴金额、申报状态和完税凭证。
- 进销项发票归集、缺票、异常票和抵扣状态。
- 财务数据与税务申报口径的核对清单。
- 首期不直接报税；正式直连必须使用获得授权的财税服务接口。

### 6.4 人员

- 员工、顾问、外包和候选人档案。
- 部门、岗位、汇报关系、入职、转正、调岗和离职。
- 劳动合同、保密协议、知识产权协议和到期提醒。
- 员工资产、账号和权限的发放与回收。
- 薪酬只对特定角色开放，和普通人事权限分离。
- 离职流程可自动触发账号禁用、密钥轮换和资产回收任务。

## 7. 协作中心

### 7.1 目标、项目与待办

- 公司目标、团队目标和项目目标。
- 项目、里程碑、任务、子任务、负责人、协作者、截止时间和依赖。
- 列表、看板、日历和我的工作视图。
- 任务可以关联产品、需求、客户、合同、发票、API、Bug、服务器、SOP 或能力资产。
- 评论、附件、变更记录、提醒和审批。
- 支持从提醒、Bug、日志告警、SOP 执行实例一键创建任务。

### 7.2 业务 SOP 沉淀

SOP 不是普通文档，而是可执行流程模板。

#### SOP 内容

- SOP 名称、业务场景、适用范围、触发条件、负责人和协作角色。
- 前置条件、输入材料、步骤、决策分支、表单、检查项和完成标准。
- 每一步的预计耗时、责任角色、证据要求、审批规则和失败处理方式。
- 关联政策、模板、能力资产、系统入口和风险提示。

#### SOP 生命周期

- 草稿、评审、已发布、已废弃。
- 版本对比、变更说明、生效时间和回滚。
- 发布后产生执行实例，实例固定引用当时版本，避免流程中途被静默修改。
- 执行过程记录实际耗时、跳过原因、异常、证据和审批结果。
- 根据执行数据统计完成率、平均耗时、瓶颈和返工率。

#### 首期建议 SOP

- 新员工入职／离职。
- 合同审批与盖章。
- 报销与付款。
- 月度结账与税务申报准备。
- 产品需求评审与版本发布。
- 线上故障响应与复盘。
- 客户交付与验收。

### 7.3 可复用能力沉淀

能力库用于沉淀“已经验证、以后可以直接复用”的资产。

#### 能力类型

- 表单、文档、合同、邮件和项目模板。
- 业务规则、清单、话术、Playbook 和决策树。
- 代码组件、脚本、自动化流程和命令工具。
- API 连接器、Webhook、数据转换和集成配方。
- AI 提示词、Agent 技能、知识包和评测集。
- 设计组件、品牌素材和交付物模板。

#### 能力管理

- 名称、类别、适用场景、输入、输出、依赖、负责人和风险等级。
- 草稿、试用、已验证、推荐、已废弃状态。
- 版本、变更说明、兼容性、使用说明和示例。
- 可见范围、可调用角色、敏感信息要求和许可证。
- 收藏、评分、复用次数、成功率和最近使用时间。
- 可被 SOP、项目、任务、产品、API 或 Agent 直接引用。
- 能力升级不自动改变历史执行；使用者可以评估后升级版本。

## 8. 产品与研发

### 8.1 产品管理

- 产品线、产品、模块、负责人、目标客户和业务指标。
- 需求池、用户反馈、优先级、评审结论和拒绝原因。
- 路线图、迭代、里程碑、版本和发布说明。
- 需求关联任务、API、Bug、测试、发布和客户反馈。
- 发布门禁：未完成高优先级 Bug、验收或审批时禁止标记为正式发布。

### 8.2 统一 API 接口管理

#### API 目录

- 按产品、服务、领域、负责人和环境组织 API。
- 支持 HTTP／REST、Webhook；GraphQL、gRPC 可在后续版本加入。
- 记录路径、方法、说明、请求、响应、错误码、认证方式、限流和数据等级。
- 支持 OpenAPI 文件导入、同步、版本对比和文档生成。
- 标记设计中、开发中、测试中、生产、废弃状态。

#### 环境与凭证

- 开发、测试、预发布和生产环境地址分离。
- 凭证只保存引用或加密密文，页面默认不回显完整密钥。
- 支持凭证负责人、有效期、轮换记录和最小权限。
- 高风险生产凭证申请需要审批并设置自动过期。

#### 协作与质量

- API 负责人、消费者、上下游依赖和影响范围。
- 在线示例、Mock、调试和基础契约测试。
- 破坏性变更识别、评审、通知和迁移截止时间。
- API 与需求、版本、发布、日志、Bug 和服务状态关联。
- 展示调用量、错误率、P95 延迟和最近异常；指标来自接入的网关或监控系统。

### 8.3 统一日志与 Bug 管理

#### 统一日志

- 接入应用日志、API 网关、服务器、任务队列、浏览器错误和第三方回调日志。
- 按时间、环境、服务、级别、关键字、用户、租户、请求 ID、Trace ID 搜索。
- 结构化展示上下文，敏感字段自动脱敏。
- 保存常用查询、仪表盘、告警规则和数据保留策略。
- 从 API、发布版本、服务器或用户反馈直接跳转到相关日志。
- 首期可查询外部日志平台，不要求把全部原始日志复制进业务数据库。

#### Bug 工作流

- 从日志、告警、用户反馈、测试或人工录入创建 Bug。
- 记录严重程度、优先级、影响环境、影响用户、复现步骤、期望／实际结果和附件。
- 自动携带相关日志片段、Trace ID、API、服务、服务器、版本和发生时间。
- 状态：待确认、已确认、处理中、待验证、已解决、已关闭、重新打开。
- 指定负责人、协作者、SLA、根因、解决方案和回归结果。
- 关联需求、任务、代码提交、发布和复盘报告。
- 重复 Bug 合并，保留所有来源和影响用户。
- 严重线上事故自动创建事故处理 SOP 实例，并在结束后要求完成复盘。

#### 关键指标

- Bug 数量、严重等级分布、重复率和逃逸率。
- 首次响应时间、平均修复时间、重新打开率。
- 按产品、版本、API、服务和负责人统计趋势。
- 发布前后错误率变化与新增异常。

## 9. 基础设施

- 云账号、区域、服务器、容器、数据库、缓存、对象存储和第三方服务台账。
- 服务与产品、API、负责人、代码仓库和运行环境关联。
- CPU、内存、磁盘、流量、可用性和资源成本摘要。
- 域名、DNS、SSL 证书和到期提醒。
- 备份策略、最近成功备份、恢复演练和恢复证据。
- 变更、扩容、重启、续费和下线记录。
- 告警转 Bug 或任务；高危操作要求二次确认和审计。
- 首期以只读监控和人工操作记录为主，生产控制能力分阶段开放。

## 10. 用户与权限管理

### 10.1 权限模型

采用“角色权限 RBAC + 数据范围 + 条件权限”的组合：

- 模块权限：是否可以进入财税、人员、API、日志、服务器等模块。
- 动作权限：查看、新建、编辑、删除、导出、审批、执行、授权。
- 数据范围：全公司、指定主体、部门、项目、产品、环境或仅本人。
- 字段权限：薪资、证件号、银行账号、合同金额、密钥等单独控制。
- 条件权限：仅在指定时间、IP、设备、审批单或工单范围内生效。

### 10.2 用户管理

- 邀请、停用、恢复、离职和永久删除。
- 部门、岗位、用户组、直属负责人和所属公司主体。
- 角色模板与自定义角色。
- 批量授权、临时授权和自动到期。
- 外部用户只能进入明确共享的项目、SOP 或文件。
- 支持会话管理、强制退出、密码策略；SSO、SCIM 和 MFA 进入后续阶段。

### 10.3 审批与审计

- 生产操作、批量导出、权限提升、敏感信息查看和凭证申请支持审批。
- 审计记录包含操作者、时间、对象、动作、来源、前后值和审批依据。
- 审计日志不可由普通管理员修改或删除。
- 提供成员权限总览和“为什么我能看到这条数据”的解释入口。
- 定期生成闲置账号、过期权限、超权角色和未回收凭证报告。

## 11. 关键跨模块流程

### 11.1 Bug 到修复发布

~~~text
日志告警／用户反馈
  → 创建或关联 Bug
  → 自动带入 Trace、API、服务、环境和版本
  → 分级并指定负责人
  → 生成研发任务
  → 关联代码提交和候选发布
  → 回归验证
  → 发布后观察错误率
  → 关闭 Bug；严重事故进入复盘 SOP
~~~

### 11.2 新员工入职

~~~text
HR 创建人员记录
  → 启动入职 SOP
  → 签署合同与保密协议
  → 分配部门、角色和资产
  → 按岗位模板开通最小权限
  → 完成培训和试用期目标
  → 所有步骤、证据和审批归档
~~~

### 11.3 API 变更

~~~text
提交 API 新版本
  → 系统识别破坏性变更
  → 展示上下游消费者和影响版本
  → 负责人评审
  → 生成迁移任务与截止时间
  → 测试环境契约验证
  → 发布审批
  → 生产指标观察
~~~

### 11.4 SOP 与能力复用

~~~text
业务问题形成稳定解法
  → 沉淀为能力资产
  → 试用与验证
  → 被 SOP 引用
  → SOP 产生执行实例
  → 收集耗时、异常与结果
  → 改进能力或发布新版本
~~~

## 13. 通知与自动化

- 站内通知为基础；邮件、企业微信、飞书、Slack 等通过集成启用。
- 提醒支持立即、每日摘要、每周摘要和仅高风险。
- 自动化采用“触发器—条件—动作”模型。
- 首期动作包括创建任务、启动 SOP、发送通知、请求审批、更新状态和调用已授权 Webhook。
- 所有自动化执行必须记录输入、输出、操作者身份、结果和重试信息。
- 高风险动作只能生成待确认操作，不允许静默执行。

## 14. 非功能要求

### 14.1 安全

- 租户隔离与服务端权限校验，不能只依赖前端隐藏。
- TLS 传输加密；敏感字段和凭证加密存储。
- 日志、搜索索引、导出文件和通知内容统一脱敏。
- 生产环境、财税、薪资和密钥权限默认关闭，按需申请。
- 高风险操作支持 MFA／二次确认、审批和自动过期。

### 14.2 可靠性

- 重要写操作幂等，失败可重试，审批与自动化不能重复执行。
- 数据导入提供预览、校验、错误报告和回滚方式。
- 外部集成不可用时保留最近同步时间，未知数据不能显示为 0。
- 关键对象支持软删除、恢复和版本历史。

### 14.3 可用性

- 桌面端完成全部管理操作；移动端至少支持查看、待办、审批和告警处理。
- 首页首屏优先展示风险和动作，不使用营销式大标题占据空间。
- 每个状态只突出一个主要动作，错误信息说明影响和解决方式。

### 15.2 P1：系统集成与自动化

- 银行流水、财税服务、电子发票和工资系统连接。
- GitHub／GitLab、CI/CD、API 网关、Sentry、Loki／ELK、云监控连接。
- API 指标、契约测试、破坏性变更检测和消费者通知。
- 日志检索、告警聚合、Bug 自动归类和重复问题识别。
- SOP 条件分支、定时触发、Webhook 与跨系统自动化。
- 飞书、企业微信、Slack、邮件和日历通知。
- MFA、SSO 和更完整的权限审批。

### 15.3 P2：智能经营与规模化治理

- 基于历史现金流的跑道预测与预算情景模拟。
- 经营异常检测、跨模块风险解释和决策建议。
- AI 辅助生成 SOP、Bug 摘要、根因线索和复盘初稿。
- 能力资产推荐、依赖图谱和复用收益统计。

## 16. 可以直接实现与需要外部条件的边界

### 16.1 可以在系统内直接实现

- 统一首页、任务项目、产品需求、SOP、能力库、API 目录、Bug 流程。
- 公司、合同、人员、服务器和财税管理台账。
- 用户角色、细粒度权限、审批和审计日志。
- 文件导入、手工录入、到期提醒、关联关系和统计报表。

### 16.2 需要外部系统授权或接口

- 银行余额与流水自动同步。
- 电子发票查验、纳税申报和完税结果同步。
- 工资、社保、公积金和电子签约。
- 云资源实时指标、账单和远程控制。
- Git 提交、CI/CD、发布状态和代码评审。
- 实时日志、Trace、APM 和浏览器错误。
- SSO、企业通讯录和第三方消息通知。

### 16.3 不建议由中台直接承担

- 直接代替持牌财税系统记账报税。
- 直接保存生产 SSH 私钥、云厂商主账号密码或网银凭证。
- 自建大规模原始日志存储；建议接入成熟日志平台，中台负责统一关联与处置。

## 17. MVP 验收标准

1. Owner 登录后可以在一个首页看到经营、财税、团队、任务、产品和服务器状态。
2. 用户只能看到角色和数据范围允许的模块、记录与敏感字段。
3. 新建任务可以关联项目、产品、API、Bug、服务器、合同或 SOP。
4. SOP 可以发布版本并启动执行；历史实例不受新版本静默影响。
5. 能力资产可以被 SOP 和任务引用，并记录使用次数和版本。
6. OpenAPI 文件可以导入为 API 目录，识别新增、修改和删除接口。
7. Bug 可以关联日志线索、API、服务、版本、负责人和回归结果。
8. 严重 Bug 可以启动事故处理 SOP，并在关闭前要求复盘。
9. 成员离职后可以一键停用账号并生成权限、资产和凭证回收清单。
10. 所有敏感查看、权限变更、导出和高风险操作均产生审计记录。
11. 外部数据同步失败时展示失败原因和最后成功时间，不把未知值写成 0。
12. 系统在没有外部接口时仍可通过手工录入和导入完成基本管理闭环。

## 18. 待确认产品决策

| 决策 | 本版建议 |
| --- | --- |
| 服务对象 | 先服务单公司、10–100 人团队，底层保留多公司字段 |
| 财务深度 | 先做经营台账与财税协作，不自研总账和报税 |
| 日志架构 | 接入现有日志平台，中台保存索引、关联、摘要和处置记录 |
| API 范围 | P0 先支持 REST／Webhook 与 OpenAPI；GraphQL、gRPC 放 P1 |
| 权限粒度 | P0 同时支持模块、动作、数据范围和敏感字段，不能后补 |
| SOP 自动化 | P0 做人工步骤、表单、审批；外部自动动作放 P1 |
| 能力资产 | P0 支持模板、脚本、连接器、提示词和知识包五大类 |
| 生产控制 | P0 只读和留痕；远程重启、发布、密钥操作分阶段开放 |
| AI 权限 | 默认只生成建议和草稿，高风险动作必须人工确认 |

## 19. 建议实施顺序

1. **统一底座**：组织、用户、权限、审计、附件、标签、全局关联。
2. **行动闭环**：项目、任务、提醒、审批、经营首页。
3. **公司管理**：主体、合同、财税台账、人员和服务器台账。
4. **能力沉淀**：SOP 模板／执行实例、能力库和版本机制。
5. **产品研发**：产品、需求、版本、API 目录和 Bug 工作流。
6. **外部集成**：日志、Git、CI/CD、云监控、财税、通讯工具。
7. **智能化**：跨模块风险识别、自动摘要、预测和能力推荐。

权限与审计必须在第一阶段完成，不能等所有业务功能开发后再补。统一 API、统一日志与 Bug、SOP 和能力库都依赖同一套对象关联、版本和权限底座。
