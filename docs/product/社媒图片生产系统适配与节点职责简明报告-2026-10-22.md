# 社媒图片生产系统适配与节点职责简明报告

> 日期：2026-10-22
>
> 用途：供产品负责人快速确认图片生成功能是否符合灵枢产品目标，以及工具与 AI 的职责是否清楚

## 一句话结论

图片生成应成为现有内容任务中的一个交付能力：经营 Agent 定目标，编导 Agent 定爆点与创意，内容 Agent 负责生产，工具负责证据与检查，用户批准后才能进入发布和复盘。

## 1. 图片生产怎样适配灵枢其他系统

### 1.1 用户只看到一个内容创作入口

```text
内容创作首页
→ 自由创作：直接描述／上传素材／点击爆款裂变
→ 或数字员工：创建／继续周任务
→ 灵小枢建立或恢复同一个 ContentTask
→ 明确产品、目标和待补信息
→ 系统完成策划与生成
→ 用户验收
→ 发布包
→ 发布和数据复盘
```

“周任务、即时任务、灵感参考”是后台任务来源和上下文，不是三个并列的前端入口。图片不是新的独立业务入口，也不再维护另一套产品、素材、任务和发布记录。自由创作单条任务的完整首页对话规则见《PRD：首页灵小枢对话式单条内容自由创作 v1》。

### 1.2 各系统怎样连接

| 系统 | 为图片生产提供什么 | 图片生产返回什么 |
| --- | --- | --- |
| 内容任务 | 目标、受众、账号、平台、CTA、截止时间 | 当前图片进度、最终作品和阻断原因 |
| 企业知识 | 经过确认的企业、品牌、产品和事实 | 本次使用了哪些事实及其版本 |
| 我的素材 | 产品图、Logo、场景图和证据图 | 素材实际使用履历 |
| 灵感中心 | 参考图、来源、权利状态和真实表现 | 本次参考了什么、保留和替换了什么 |
| 内容制作工作台 | 任务入口、预览和用户操作 | 修改要求、版本选择和最终验收 |
| 交付与发布 | 账号、平台规格和发布能力 | 已批准图片、文案和发布包 |
| 内容监控 | 真实发布指标 | 爆点表现观察和下一轮实验建议 |

### 1.3 必须坚持的产品原则

1. 同一任务：周计划、即时生成和灵感中心进入后，使用同一个 `ContentTask`。
2. 同一事实：企业知识是产品事实唯一来源。
3. 同一素材：图片只引用“我的素材”，不复制第二套素材库。
4. 同一作品：生成、返工、批准、发布和复盘都围绕同一个版本链。
5. 最少操作：用户不选模型、不写提示词，只确认产品、必要事实和最终成品。
6. 真实状态：下载不等于发布；没有检查不等于通过；没有数据不等于零。

## 2. 图片生产节点与职责

后台建议固定为 16 个节点。客户界面只显示“明确内容、系统策划、生产与检查、验收与交付”四个阶段。

| 节点 | 工具做什么 | AI 做什么 | 稳定输出 |
| --- | --- | --- | --- |
| 0. 创建或恢复任务 | 查重、鉴权、恢复状态、锁定并发 | 判断新建还是继续 | `ImageProductionRunRef` |
| 1. 标准化需求 | 读取平台默认值并验证格式 | 归一目标、受众和成功指标 | `ImageBusinessContext` |
| 2. 解析事实与素材 | 读取事实；检查文件、哈希、尺寸、OCR和可读性 | 建议素材角色，识别证据缺口 | `ImageAssetManifest` |
| 3. 冻结参考与表现 | 保存参考原图、来源、权利和真实指标 | 判断参考图在本任务中的用途 | `ImageReferenceSnapshot` |
| 4. 客观拆解参考图 | 检测文字、主体、区域、显著性、颜色和构图 | 补充主体关系、情绪和阅读顺序 | `ImageElementInventory` |
| 5. 判断爆点 | 提供机器观察、相对表现和实验数据 | 合并重复因素，默认保留最重要的 4 个、最多 5 个；不把装饰细节列为爆点 | `ImageHookFactorSpec` |
| 6. 决定保留与替换 | 检测 Logo、水印、人物身份和版权风险 | 决定锁定、等价、有限变化、身份替换和创新方向 | `ImageAdaptationSpec` |
| 7. 形成导演方案 | 验证事实引用、文字长度和平台规则 | 形成核心主张、构图、图文关系和验收条件 | `ImageDirectorBrief` |
| 8. 选择生产路线 | 返回模型、合成、模板的能力、成本和队列 | 选择复用、合成、参考生成或辅助生成 | `ImageExecutionPlan` |
| 9. 编译生成规格 | 计算真实像素、安全区、素材句柄和幂等键 | 将导演方案转成模型无关视觉指令 | `ImageRenderSpec` |
| 10. 后台生成候选 | 排队、提交、对账、保存文件和成本 | 图像模型按冻结规格执行 | `ImageCandidateSet` |
| 11. 自动质量检查 | 检查产品、OCR、Logo、尺寸、安全区和禁止复用 | 检查图文语义与错误暗示 | `ImageQualityReport` |
| 12. 独立创意审稿 | 展示证据、差异和失败区域 | 编导 Agent 决定接受、修复、重生成或阻断 | `ImageReviewDecision` |
| 13. 定向返工 | 局部重绘、图层修改、记录版本差异 | 生成最小修改方案 | `ImageRepairPlan` 和新候选版本 |
| 14. 用户验收 | 校验版本、记录批准人并冻结文件 | 解释保留、创新和限制 | `ApprovedImageArtifact` |
| 15. 交付与回流 | 生成发布包、记录发布凭证和真实指标 | 给出下一轮实验建议 | `ImageDeliveryPackage`、`ImagePerformanceObservation` |

### 2.1 爆点到底由谁判断

编导 Agent 判断，工具提供证据。

- 工具回答“图里实际有什么”：文字、主体、位置、占比、显著性、颜色、表现数据。
- 编导 Agent 回答“为什么可能有效”：影响注意、理解、证明、信任、情绪还是转化，并将近义因素合并后按重要性排序。
- 规则引擎检查每个判断有没有证据、区域、置信度和验证方式。
- 真实发布数据或 A/B 实验才能回答“是否真的有效”。

每次默认输出 4 个核心爆点，最多 5 个。第 5 个只有在承担独立作用且有充分证据时才保留；证据不足可以少于 4 个，不允许为凑数补写。

没有发布或实验数据时，只能称为“爆点假设”，不能称为“已验证爆点”。

### 2.2 节点为什么能持续稳定工作

所有节点交接都必须带：

- 合同版本；
- 租户和任务 ID；
- 对象版本；
- 上游输入 ID、版本和哈希；
- 创建者和时间；
- 证据引用；
- 警告与阻断原因；
- 幂等键和运行状态。

下游只读取已完成且版本匹配的上游结果。输入变化后，旧结果自动失效；返工永远创建新版本，不覆盖已批准版本。

### 2.3 三条不可放宽的门禁

1. 强制产品图、Logo 或证据图不可读取时必须停止，不能移除素材后继续生成。
2. 任一硬检查为 `fail` 或 `uncertain` 时不能批准；“没有检查”不能算通过。
3. 图片必须经过独立编导审稿和用户显式批准，才能成为正式交付物；此前只能是草稿。

## 最终判断

这套方案与灵枢现有经营、企业知识、素材、内容制作、发布和复盘系统保持一条主链，同时把图片生产拆成可恢复、可检查、可返工的稳定节点。产品重点不再是“能否生成一张图”，而是“能否持续生产企业可以放心发布、可以追溯、可以复盘的图片”。
