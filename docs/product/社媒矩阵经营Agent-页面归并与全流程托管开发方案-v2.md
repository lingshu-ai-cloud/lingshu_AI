# 社媒矩阵经营 Agent：页面归并与全流程托管开发方案 V2

- 日期：2026-09-27
- 状态：目标产品与技术设计；本轮实现范围和限制见[开发与验收记录](社媒矩阵经营Agent-开发与验收记录-2026-09-27.md)，不能将全部设计视为已实现
- 目标：数字员工在完成一次性业务配置与账号授权后，自动完成经营规划、灵感发现、选题、制作、发布、监测和复盘，正常执行链路不需要用户人工介入。

## 2. 产品目标与自动化边界

### 2.1 正常链路无人介入

完成初始配置后，数字员工持续执行：

经营目标 → 周期任务 → 灵感发现 → 选题 → 脚本与分镜 → 内容生产 → 自动质检 → 平台适配 → 排期与发布 → 数据采集 → 复盘 → 下一轮任务。

上述任一常规阶段都不得默认进入“待用户确认”。界面上的操作按钮用于主动发起、修改或接管，不能成为自动流程的必要触发器。

### 2.2 一次性前提

系统复用企业知识库、已有素材和已连接账号，尽量自动补齐配置。以下无法替用户凭空完成：账号所有者授权、必要企业事实、素材使用权、可使用的预算与自动发布范围。

用户在智能经营启用托管时，一次性明确：经营目标、可用账号、预算、频次、可公开事实、可用素材、允许自动发布的范围及有效期。已有有效授权直接复用，不重复索取。

未满足发布条件时可以进行允许的发现和草稿生产，但不能将“已产出草稿”宣称为“全流程托管已就绪”。

### 2.3 无人介入不等于故障无限重试

优先自动重试、使用已授权备用能力、改换有证据支持的选题、跳过单项并补位。仅当无法在既有范围内继续时形成异常待办，如全部账号授权失效、关键事实缺失或预算耗尽。

异常只阻塞受影响的任务或账号；其他可执行工作继续。系统不得为了维持表面成功而虚构事实、绕过授权、无限增加成本或将失败标为完成。

## 3. 三个 Agent 与执行层

| 主体 | 决策与执行职责 | 输出 | 边界 |
| --- | --- | --- | --- |
| 经营 Agent | 经营目标、账号分工、内容组合、预算、任务优先级、平台适配、发布排期、执行监控及经营复盘 | 经营配置、任务包、内容需求、分发任务、复盘决策 | 不直接设计镜头，不把推断写成企业事实 |
| 编导 Agent | 发现范围、参考分析、选题、脚本、分镜、制作方案审核与表达验收 | 选题、DirectorBrief、表达验收结果、创作经验 | 不擅自扩大账号、预算、经营市场或商务承诺，不代替内容 Agent 决定具体制作实现 |
| 内容 Agent | 制作方案、素材匹配、模型与工具选择、生成、配音、剪辑、渲染、技术质检和局部返工 | ContentExecutionPlan、成片版本、技术质检结果 | 不擅自修改经营目标、事实、核心表达和验收标准 |
| 执行层 | 采集、模型调用、素材处理、渲染、平台发布、指标拉取、任务调度 | 素材、执行结果、回执、真实指标 | 不自行改变经营策略；不增加用户可见 Agent |

### 3.1 编导与内容的自动交接

“内容生产”特指素材匹配、视频/图像生成、数字人、配音、字幕、剪辑、混音和渲染等内容制作，不指制造业生产，也不是区别于内容 Agent 的另一套能力。

```text
经营 Agent：ContentDemand / WeeklyContentPackage
  → 编导 Agent：DirectorBrief（表达目标、脚本、分镜、验收要求）
  → 内容 Agent：ContentExecutionPlan（素材、工具、步骤、成本）
  → 编导 Agent：自动审核制作方案
  → 内容 Agent：实际制作与技术质检
  → 编导 Agent：表达验收
  → 经营 Agent：发布预检、排期发布、效果复盘
```

制作方案不通过时回内容 Agent 修改方案；技术质检不通过时由内容 Agent 自动修复；表达不通过时由编导提供具体差距，再交内容 Agent 局部返工。只有目标或资源边界不可满足时回经营 Agent 重排或补位。整个交接在托管模式下自动进行。

跨 Agent 交接通过持久化任务与版本化对象完成，不依赖聊天上下文，也不使用进程内临时对话作为唯一状态。

## 4. 信息架构与功能归并

```text
智能经营

社媒运营
├─ 灵感中心
├─ 内容制作
├─ 发布与渠道
└─ 内容监控
```

| 删除页面 | 归并位置 | 具体处理 |
| --- | --- | --- |
| 经营工作台 | 智能经营 | 在现有页面增加社媒经营摘要、托管状态与下一步动作；不嵌入第二套完整工作台 |
| 项目搭建 | 智能经营中的业务配置抽屉/对话引导 | 复用知识库，系统维护经营上下文；取消强制建项目步骤 |
| 账号矩阵 | 发布与渠道中的账号管理 | 连接状态、账号定位、受众、语言、风格、职责和频次共同维护 |
| 月周计划 | 智能经营、灵感中心、发布与渠道 | 周期目标归智能经营；选题归灵感中心；具体发布时间归发布日历；共用后台任务数据 |

智能经营展示“现在为什么做、正在做什么、是否需要处理”；内容监控展示详细效果与归因。两者不复制整套数据看板。

## 5. 五个页面的改造要求

### 5.1 智能经营：目标、托管与例外入口

- 从已有知识库读取品牌、产品、市场、受众、素材和承接入口，展示缺失项而非重建表单。
- 用户可以用自然语言提出目标，系统转换成有版本的经营配置。
- 显示托管开关、执行范围、预算使用、账号就绪度、本周期重点和异常待办。
- 正常情况下展示简短进展，不要求用户逐项批准数字员工的动作。
- 经营 Agent 自动创建周期任务包，并将内容需求交给编导。
- “查看选题”打开对应灵感列表；“查看制作”打开原任务；“查看发布”打开对应分发记录。
- 不使用一个含糊的“暂停”按钮：区分暂停新增任务、暂停发布和全部暂停；后者同时停止新增调度并尽可能取消未提交的外部动作。
- 首次没有账号时允许先探索与生产，明确展示发布未就绪。

### 5.2 灵感中心：经营需求转成可制作的选题

同页保留候选发现与选题/素材管理能力，不增加独立子页面；根据最新确认，候选视频直接发起爆款复刻是优先动线：

**推荐选题**：经营选题池与采用情况；不作为候选视频复刻的必经视图。

- 来源包括周期经营需求、用户想法、参考素材及效果复盘。
- 卡片展示标题、内容角度、经营目的、建议账号/平台、参考依据、当前状态。
- 筛选支持账号、目标、来源和状态；无需先选择项目才能查看。
- 主操作为“开始创作”；进入制作后替换为“继续制作”，始终打开已有任务。
- 托管时系统自动评分、去重、检查账号覆盖与内容多样性，并采用合适选题；无需用户点击。
- 已采用卡片显示选择原因及关联任务，不要求用户维护“本周计划”。

**候选视频与参考素材**：优先展示现有采集与分析结果，继续承载行业起量、对标账号、创新参考等供给，用户可以直接发起爆款复刻。

- 保留现有采集与分析能力，不另建灵感采集页面。
- 参考详情用侧栏查看分析、来源、时间和可用依据。
- 候选视频主操作为“爆款复刻”，直接创建复刻任务并进入制作；“基于此生成选题”仅作可选探索操作，不是复刻的前置关卡。托管时由编导自动采用候选。
- 外部参考仅作分析依据，不自动认定具有下载、剪辑或再发布权利。
- 连续发现循环独立运行；单个任务先检索现有池，参考不足再补采，不能等待某一条采集导致所有任务停滞。

选题状态：候选、已采用、制作中、已发布、暂存、淘汰。制作与发布状态从关联任务派生，不能维护第二份独立状态真值。

### 5.3 内容制作：一个任务内完成全部生产

- 自动继承经营目标、账号策略、企业事实版本、选题与参考素材，不再次询问已有信息。
- 在同一任务详情中展示脚本、分镜、素材、生成进度、成片与版本，不逐步跳转到新页面。
- 托管模式自动通过脚本和分镜阶段，自动完成制作方案验收、生成、技术质检、表达验收及修复。
- 页面提供观察、暂停和人工接管能力；“确认脚本”“确认成片”不能成为托管默认关卡。
- 成片验收合格后自动创建或推进分发任务，交回经营 Agent。
- 用户修改时创建新版本；已经排期的旧版本不得无提示地替换为未验收新版本。

### 5.4 发布与渠道：账号管理与发布执行

同页用账号管理、发布队列/日历组织现有功能。

- 账号管理承接原账号矩阵：授权状态、平台能力、定位、受众、语言、内容职责、频次和时区。
- 账号策略由经营 Agent 在已授权范围内维护；账号连接或重新授权仍通过真实平台授权完成。
- 队列展示待发布、已排期、提交中、已发布、失败和结果待核实。
- 经营 Agent 自动完成平台文案、封面、格式适配、账号选择、时间安排及发布前检查。
- 平台适配改变内容事实或主体表达时，回交编导验收，不能只通过格式检查。
- 成片上传可直接创建轻量任务与分发记录，不要求反向补走灵感和制作。
- 自动发布能力不足的平台明确标为“不支持全自动发布”；导出发布包不是托管发布成功。

### 5.5 内容监控：效果回到下一轮执行

- 指标关联账号、发布实例、成片版本、选题和经营目标。
- 区分真实零值、尚未返回、采集失败、平台不提供四种情况。
- 展示内容表现、可获得的转化信号、观察窗口、结论依据及已执行优化。
- 经营 Agent 负责经营组合与节奏调整，编导负责选题与表达优化。
- 托管模式自动创建下一轮任务，不等待用户点击“优化”。
- 用户主动点击优化时复用同一去重机制，避免和后台复盘重复建任务。
- 没有可靠归因数据时只报告可观察指标，不推断询盘或成交。

## 6. 五条入口路径及其衔接

### 路径 A：经营目标驱动

入口：智能经营。触发：首次启用托管、周期到期或目标变更。

1. 经营 Agent 读取配置、历史效果、账号能力和可用预算。
2. 生成后台周期任务包，拆成每个账号需要覆盖的内容需求。
3. 编导检索灵感池、补充发现、产出并自动选择选题。
4. 创建内容任务，执行脚本、分镜、制作与验收。
5. 经营 Agent 创建平台分发任务并自动排期发布。
6. 收集效果，自动复盘并触发下一周期。

衔接：完整选题可直接进入制作，无需要求用户访问灵感中心；灵感中心仍可查看其来源与采用记录。

### 路径 B：直接选择候选视频发起爆款复刻

入口：灵感中心。主要触发：用户直接选择候选视频，点击“爆款复刻”。也支持用户粘贴参考视频，以及托管时编导自动采用符合经营需求的候选。

1. 候选视频卡片直接提供“爆款复刻”，用户无需先生成或选择一轮选题，也不必复制链接、重新上传或重填经营信息。
2. 系统携带候选视频 sourceRef、sourceVersion、原始链接、已有分析及经营上下文，创建唯一复刻任务；已有同一采用记录时打开原任务。
3. 经营 Agent 自动核对目标、账号、频次、预算和授权范围，关联已有内容需求或创建即时需求。
4. 编导 Agent 复用已有分析，缺失时后台补分析，形成适合自身品牌与产品的复刻方案、脚本和分镜；选题成为任务内部产物，不作为额外人工关卡。
5. 内容 Agent 提交制作方案，由编导自动审核后完成制作、技术质检与表达验收。
6. 成片进入路径 A 的统一发布和复盘链路，按已有托管授权自动推进。

衔接：点击后打开已创建任务的内容制作详情，用户可查看过程，但无需再次点击“确认开头”“开始制作”才能推进。候选卡片在已有任务时显示“继续制作”或“查看任务”，重复点击不得重复创建。若用户明确要求再做一版，创建关联原任务的新版本或派生任务，重新核算资源。

爆款复刻指迁移可用的内容结构与表达方法并用于自身业务，不代表自动取得参考素材的再使用权；事实与素材授权仍通过现有规则自动检查。

### 路径 C：已有成片驱动

入口：发布与渠道。触发：用户上传成片或已连接素材源按明确规则导入可发布成品。

1. 创建轻量内容记录，标记来源为外部成片，保存文件版本和来源。
2. 绑定经营上下文，自动识别格式和内容；信息缺口不靠模型猜测填充。
3. 内容 Agent 执行技术检查，编导 Agent 执行表达验收；需修改则创建原任务下的修复制作步骤。
4. 经营 Agent 检查账号授权、事实、素材权利和预算，生成平台适配及分发任务。
5. 发布、采集指标并进入统一复盘。

衔接：不强制补写选题、脚本或分镜；这些字段允许为空，但发布依据、成片版本与授权必须可追溯。相同文件重复上传提供复用识别，不阻止明确要求的合法再次使用。

### 路径 D：数据复盘驱动

入口：内容监控。触发：观察窗口到期、有效指标变化或用户主动发起优化。

1. 经营 Agent 判断数据是否足够支持决策，避免用短时波动改写长期策略。
2. 仅调整发布时间、频次或账号组合：直接更新后续分发安排，不重新制作。
3. 修改原成片的字幕、封面或表达：创建关联原任务的新修订版本，进入制作与验收。
4. 需要新选题：生成派生内容需求，交给灵感中心的同一选题流程。
5. 新发布记录继续采集，按观察窗口评估改动效果。

衔接：保留 parentTaskId、reviewId 和改进假设；已经发布的版本不覆盖。复盘不是无限重生成，每个观察窗口和改进假设只产生一次自动动作，并受预算与实验配额限制。

### 路径 E：制作中断恢复或直接素材创作

入口：内容制作。触发：已有草稿、用户直接上传原始素材、失败任务恢复。

1. 已有任务直接读取检查点恢复，不重新创建选题和任务包。
2. 新素材创作建立轻量即时经营上下文，再由编导补齐必要的表达方案。
3. 托管开启且任务处于授权范围内时，后续自动制作、发布与复盘。
4. 仅创作授权的任务产出合格成片后停止在可发布状态，不自行扩大为发布授权。

### 6.1 跨路径合流规则

所有入口最终进入同一条主链：

```text
经营需求 / 灵感 / 素材 / 成片 / 复盘
                    ↓
         唯一任务 + 经营上下文 + 授权范围
                    ↓
       按缺失阶段补齐，已完成阶段直接复用
                    ↓
          合格成片 → 分发 → 效果 → 复盘
                    └───────────────→ 下一轮需求
```

页面跳转不创建任务；显式发起命令或调度事件才创建任务。页面展示同一任务在当前阶段的视图，不互相复制数据。

## 7. 托管控制与自动判定

### 7.1 托管策略 ManagedPolicy

建议字段：tenantId、scopeId、mode、allowedAccountIds、allowedActions、budgetLimit、perTaskBudget、frequencyLimits、activeWindow、timezone、factPolicyVersion、assetPolicyVersion、qualityPolicyVersion、fallbackPolicy、retryLimits、validUntil、version。

- mode：managed（托管）或 assisted（人工辅助）；本方案默认目标是 managed。
- allowedActions 明确发现、生成、修改、排期、发布等动作；启用生成不能隐含获得发布权限。
- 用户可一次性授权完整链路，执行中不重复要求确认同类动作。
- 每次外部动作重新校验最新授权、有效期和预算，而非只检查任务创建时快照。
- 降级范围明确记录；例如允许从复杂场景变为合规口播，不允许删除必要产品证据后仍宣称目标完全达成。

### 7.2 自动验收门槛

| 阶段 | 自动检查 | 未通过处理 |
| --- | --- | --- |
| 选题 | 目标匹配、事实可支持、账号适配、去重与产能 | 调整选题或换候选 |
| 脚本/分镜 | 事实来源、表达完整性、镜头可执行性、素材可用性 | 编导自动修订 |
| 制作 | 文件完整、音画与字幕、平台规格、品牌与产品一致性 | 局部重做、备用生产能力 |
| 表达验收 | 是否实现导演方案、关键证据与 CTA 是否保留 | 定向修复或换可行方案 |
| 发布预检 | 授权、预算、版本、平台能力、重复发布、发布时间 | 重排、恢复授权后续跑或局部阻塞 |
| 效果复盘 | 数据新鲜度、观察窗口、样本与归因可信度 | 延后结论，继续采集 |

确定性检查与语义检查结合，所有检查保存规则版本、结果及依据，不能仅用 Agent 一句“通过”代表全部验收。阈值应配置化并经过产品验收，不在提示词里散落硬编码。

## 8. 数据对象与交接契约

以下为目标逻辑契约，实施前映射现有表与类型，优先扩展而非另建平行系统。

| 对象 | 作用 / 关键关联 | 主写入者 |
| --- | --- | --- |
| OperatingContext | 企业事实引用、目标、市场、受众、承接入口和版本；兼容现有 SocialProgram | 经营 Agent / 既有知识库服务 |
| AccountStrategy | accountId、账号定位、语言、受众、职责、频次、平台能力引用 | 经营 Agent |
| ManagedPolicy | 自动执行范围、预算、授权有效期及版本 | 用户授权服务；Agent 只在边界内使用 |
| OperatingCycle / WeeklyContentPackage | 周期目标、内容需求、资源配额；后台对象 | 经营 Agent |
| ContentDemand | 经营目的、目标账号、截止窗口、预算、成功标准 | 经营 Agent |
| TopicCandidate / InspirationHandoff | 选题、参考证据、采用原因与需求关联 | 编导 Agent |
| ContentTask | 跨页面唯一任务、来源、状态、上下文与版本引用 | 编排服务 |
| DirectorBrief | 脚本、分镜、表达目标、事实与验收要求 | 编导 Agent |
| ContentExecutionPlan | 素材、模型、工具、制作步骤、成本估算与降级建议 | 内容 Agent；编导审核 |
| ArtifactVersion | 成片与衍生素材、技术质检结果、来源和哈希 | 内容 Agent；编导另存表达验收结果 |
| DistributionJob | 单平台单账号发布实例、成片版本、时区与回执 | 经营 Agent / 发布执行器 |
| PerformanceSnapshot / ReviewDecision | 指标来源、观察窗口、结论和下轮动作 | 采集执行器 / 经营 Agent |

公共信封至少包含：tenantId、taskId、correlationId、causationId、inputVersion、outputVersion、policyVersion、idempotencyKey、attempt、budgetReservationId、createdAt、actor、result、reasonCode。

数量口径必须分开：一项内容需求可以有多个选题候选；一个选定任务可以产出多个成片版本；一个成片可以对应多个账号的分发任务。原创数、制作版本数、发布数不可混计。

每次交接必须同时保存输入版本、产物引用、验收结果、成本、下一步动作和失败原因；持久化成功后才能投递下一阶段事件。

## 9. 状态机、事件与可靠性

### 9.1 主任务状态

```text
created → context_ready → topic_ready → producing → validating
        → ready_to_distribute → distributing → observing → reviewed
```

外部成片允许从 context_ready 进入 validating；修订任务可从 context_ready 进入 producing。每个阶段可进入 retry_wait、blocked、paused、cancelled 或 failed，保存失败阶段和恢复检查点。

多账号发布使用子任务状态，不能因为一个账号失败就将整个内容任务标为失败或全部成功。父任务额外维护分发汇总 pending / partial / succeeded / failed；满足指定观察窗口后可对已有结果复盘，缺失分发仍保留真实状态。

### 9.2 分发状态

```text
pending → preflight → scheduled → submitting → published
                                      ↘ unknown → reconciling
```

- 请求超时不等于发布失败。先根据平台任务 ID、幂等键或查询能力核对，再决定是否重试。
- 无法确认是否已经发布时停留 unknown；不能盲目重发造成重复帖子。
- 不支持查询的平台保留局部异常，其他账号继续。

### 9.3 事件约定

目标事件包括：operating.cycle.due、demand.created、topic.selected、brief.ready、artifact.validated、distribution.requested、distribution.published、metrics.updated、review.completed、policy.changed。

必须通过数据库事务与 outbox 或现有等价机制持久化，消费者按事件 ID 和业务幂等键去重；采用至少一次投递，不假设消息恰好一次送达。

### 9.4 编排保障

- 调度在后台服务运行，关闭浏览器或切换页面不影响任务。
- Worker 使用租约、心跳与检查点，宕机后恢复未完成阶段。
- 发布锁按账号及时间窗口控制；同一分发任务只允许一个有效提交者。
- 预算先预占、完成结算、失败释放；并发任务共用原子预算账本。
- 重试采用退避、抖动、分类上限与总时间上限；供应商降级同样受预算约束。
- 修改目标后，新任务读取新版本；在途任务评估影响后继续或重做；未发布任务发布前重新校验事实与策略。
- 暂停或撤销授权后，未提交发布被拦截；已提交外部请求进入结果核对，不能承诺瞬间撤回。
- 跨租户查询、任务调度、素材引用、发布凭证均必须以 tenantId 隔离。

## 10. 异常处理与持续经营

| 异常 | 自动处理 | 最终影响范围 |
| --- | --- | --- |
| 参考不足 | 补采、复用已验证模式、选择其他有依据的选题 | 单个需求；不阻塞整个灵感池 |
| 素材或事实不足 | 选用已有合规素材或改换能被证据支持的选题 | 无可行替代时阻塞相关任务 |
| 生成失败 / 质量不达标 | 局部重做、已授权备用供应商、允许范围内改方案 | 达到上限后保留失败产物与原因 |
| 平台限流 | 退避、重排窗口、尊重账号频次 | 受影响账号 |
| 账号授权失效 | 标记账号不可发布，继续其他账号；不擅自换号 | 该账号，形成重新授权待办 |
| 发布结果未知 | 回执核对、轮询查询或平台回调 | 该分发任务，禁止盲重发 |
| 预算不足 | 停止新增付费动作，继续免费采集与已完成结果整理 | 相应预算范围 |
| 指标暂缺 | 重采、等待窗口，不将缺失视为零 | 相关复盘，其他周期工作继续 |
| 单条任务永久失败 | 经营 Agent 在剩余配额内补位，记录目标缺口 | 不无限生成补位任务 |

只有需要补充外部事实、授权或修改原有限制时通知用户。正常推进、成功重试和非行动性变化静默记录，按用户设置汇总经营结果。

不得设置“所有异常统一转人工”的默认捷径，也不得声称永远不需要外部干预。

## 11. 开发落地顺序与迁移

### 第一阶段：统一对象和导航归并

- 盘点现有路由、经营配置、任务包、灵感交接、制作和发布对象，建立字段映射。
- 移除四个页面入口；旧 URL 重定向到对应页面/抽屉，保留原上下文 ID。
- 智能经营复用知识库配置；账号职责迁入发布与渠道。
- 历史项目与计划保留数据和溯源，不因删页面删业务记录。
- 灵感、制作、发布与监控统一使用 ContentTask 关联。

### 第二阶段：自动生产与跨入口合流

- 实现目标、灵感、成片、复盘、直接制作五条入口。
- 接通经营需求、选题、DirectorBrief、ContentExecutionPlan、成片与分层验收的版本化交接。
- 去除托管模式下人工确认按钮对状态迁移的强依赖。
- 实现自动质检、局部返工与有限补位。

### 第三阶段：自动发布与恢复

- 引入/复用托管授权、预算预占、平台能力检查和排期。
- 实现发布幂等、结果未知核对、账号局部阻塞和服务重启恢复。
- 用测试适配器或平台沙箱验证；生产启用与实际对外发布另行授权。

### 第四阶段：持续复盘

- 指标回写到内容与经营目标，按窗口生成复盘。
- 复盘自动创建下一轮需求或修改未来排期。
- 验证长期循环的预算、频次、去重、暂停和异常隔离。

各阶段均可独立验收，但只有完整闭环验收后才能对用户标识为“全流程托管”。

## 12. 验收标准

### 12.1 用户动线

1. 导航不再出现四个被删除入口；旧链接可到达新位置且保留上下文。
2. 用户不创建项目或计划也能发起内容任务。
3. 五条入口都进入同一任务系统，无重复填写品牌与账号信息。
4. 候选视频点击“爆款复刻”直接发起任务，无需先生成选题或二次点击启动；“继续制作”打开同一任务，页面刷新和返回不重复建任务。
5. 成片可直接进入检查和发布，不强制补脚本分镜。
6. 页面可查看任意阶段，但不需要访问这些页面才能推进任务。

### 12.2 无人值守端到端

在企业事实、素材权利、账号授权、预算和平台能力齐备的测试环境启用 managed 后：

- 连续完成至少两个经营周期，从经营目标到复盘再到下一轮内容，人工点击及人工审批次数均为 0。
- 每个发布成功状态对应真实测试回执，不使用假成功或导出文件替代发布。
- 关闭前端仍能推进；中途重启 Worker 后继续执行且不重复生成、扣费或发布。
- 同一成片多账号分发，一账号失败不阻止其余账号。
- 注入生成失败、指标缺失、平台限流和消息重复，系统按既定策略恢复或局部阻塞。
- 模拟发布提交超时，先核对结果，不出现重复帖子。
- 同时提交多个任务不会超出预算和账号频次。
- 复盘与用户同时触发同一优化，不生成重复任务。
- 暂停发布或撤销权限后，不再提交新的外部发布请求。
- 修改事实或成片后，旧验收不会错误地沿用到新版本。

### 12.3 可观测指标

记录并展示：端到端自动完成率、需人工介入任务比例、阶段耗时、自动修复率、发布成功率、重复发布数、单内容及单发布成本、预算超限数、指标覆盖率、复盘动作执行率。

自动完成率分母为观察期内到期且满足托管前提的任务；阻塞、失败和未到期任务分别披露，不通过移出失败任务美化结果。按内容任务与分发实例分别统计，避免混用。

## 13. 完成定义

用户完成一次性托管设置后，数字员工能自动决定本周期做什么、找到适合的参考、完成选题和作品、按账号安排发布、追踪效果并开始下一轮。智能经营与四个社媒页面是同一执行系统的观察和接管入口，而不是五道需要用户点击的关卡。

经营 Agent 对经营目标、资源、账号、发布和复盘负责；编导 Agent 对发现、选题、导演方案与表达验收负责；内容 Agent 对制作方案、实际制作和技术质检负责。所有正常交接自动执行，所有异常有恢复策略和清晰影响范围，所有外部结果可追溯。
