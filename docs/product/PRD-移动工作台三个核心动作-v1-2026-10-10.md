# PRD｜移动工作台三个核心动作 v1.0

> 日期：2026-10-10  
> 产品范围：微信小程序移动工作台  
> 产品定位：所有工作台账号共用的移动入口。账号登录后由服务端确定企业、用户、角色和能力；套餐、存储结构或历史工作流差异不出现在产品导航中。  
> 状态：三个核心动作已由用户明确要求写入 PRD；本文的验收标准是本轮开发与上线依据。目标态和已上线能力必须分别记录。

## 1. 用户问题

用户离开公司或电脑后，需要在手机上完成三件事：快速判断业务与 Agent 是否按计划推进；处理必须由本人决定的关键事项；通过助手查询和推进工作，并在离开页面后仍能看到执行结果。

小程序不再只是素材拍摄和上传工具。拍摄上传保留为任务处理能力，进入统一待处理队列、任务详情和工作排期。

## 2. 三个核心动作

### 动作一：打开后看清真实进展

#### 用户目标

用户进入默认的“工作”Tab，在十秒内回答：本周完成了什么、还有什么没完成、所有可见 Agent 正在做什么、哪里受阻、今天或本周将交付什么，以及数据最后更新时间。

#### 产品行为

1. 顶部显示企业身份、统计区间、最近同步时间和数据状态。
2. 工作播报展示本周任务、已完成、已发布视频、曝光、有效询盘。每个指标同时返回数值、统计区间、数据来源和可用性；缺失显示“暂无可靠数据”，不能用零代替未知。
3. 点击指标进入与该数值使用同一过滤条件、时间范围和去重规则的列表。列表总数必须能与指标核对；分页或截断必须显式说明。
4. Agent 区展示账号权限内全部 Agent 的实际状态：当前任务、阶段、最近事件时间、阻塞原因和下一步。没有活跃任务显示空闲，不因角色存在而显示运行中。
5. 内容排期使用七日日期条和当天任务卡，覆盖制作、验收、排期、发布与复盘。点击任务进入同一任务身份的进度详情、成果、事件和下一步。
6. 离线时保留最后一次成功数据并显示“数据可能已过期”及时间；读取失败不能显示为真实空队列。

#### 状态与数据规则

- 周范围采用企业时区；当前默认北京时间周一 00:00 至周日 23:59:59。
- 本周任务必须由服务端权威查询完整分页，明确任务归属规则；跨周目标不能把全部历史任务算成本周任务。
- 已发布视频区分独立视频数与平台发布次数，主指标采用独立视频数，详情显示发布次数。
- 曝光只使用平台提供的同口径曝光；播放量不能改名为曝光。
- 有效询盘指标和下钻列表使用同一资格、时间范围和去重规则。
- 所有 Agent 状态必须包含 `observedAt`；过期阈值由服务端给出或标记陈旧。

#### 验收标准

- 两个测试企业分别登录时，首页、下钻和桌面工作台的同口径数据一致，互不可见。
- 准备跨周、多目标、多执行轮次、超过单页上限的数据，任务数和下钻总数仍一致。
- 无曝光或询盘数据时显示未知原因；真实零值显示 0。
- Agent 状态与真实任务和事件一致；断网后明确显示缓存状态。

### 动作二：对关键事项做决定并看到业务结果

#### 用户目标

用户进入“待处理”Tab，先处理最紧急且会阻塞工作的事项。用户清楚知道为什么需要自己、建议怎么做、决定后影响什么，并能看到最终业务结果。

#### 产品行为

1. 卡片按超期、是否阻塞后续、业务风险、优先级、截止时间和稳定 ID 排序。
2. 卡片至少显示对象、原因、影响、建议动作、截止时间、负责 Agent、权限状态和最近更新时间。
3. 左滑是“稍后处理”，选择提醒时间；设置按企业、用户和事项保存，换设备可见，并可撤销。
4. 右滑是“现在处理”，只打开处理详情，不直接批准、发送、发布或扣费。点击卡片只看详情。
5. 详情按事项类型提供真实处理界面：批准或退回、预览并验收、拍摄或补资料、重新授权、选择恢复方式、调整排期、查看询盘及草稿。
6. 危险、外发、发布、费用和业务承诺类动作必须显示影响范围并明确确认。
7. 请求提交后依次表达“已接收、执行中、已成功或失败”。只有权威业务状态成功才移出队列；HTTP 2xx 或进入后台队列不等于业务完成。
8. 重复点击、断网重试和页面恢复使用同一幂等键；版本变化返回冲突并刷新详情，不能覆盖其他端的最新决定。

#### 统一事项类型

| 类型 | 核心处理 | 权威完成依据 |
| --- | --- | --- |
| 计划待确认 | 查看目标、产量、预算和变更并确认 | 对应计划版本已确认 |
| 脚本/视频待验收 | 预览、批准或填写修改要求 | 验收记录保存且版本匹配 |
| 缺素材/资料 | 拍摄、上传或补充表单 | 素材入库并关联，依赖重新核验通过 |
| 发布授权/账号异常 | 查看内容、账号和风险，确认或修复连接 | 权限和发布动作的业务状态成功 |
| 询盘待跟进 | 查看会话和回复草稿，发送或转交 | 实际发送回执或转交记录成功 |
| 执行失败待恢复 | 查看失败节点、成果和成本，选择恢复方式 | 恢复命令被接收后继续跟踪到最终状态 |
| 排期冲突/临近超期 | 比较影响并确认新时间 | 新排期版本保存成功 |

#### 验收标准

- 左滑不会改变业务状态；右滑和点卡不会直接执行不可逆动作。
- 稍后设置可跨设备读取；到期重新进入队列；服务端失败时卡片保留。
- 同一动作重复提交只产生一次业务操作；旧版本决定不能覆盖新版本。
- 桌面端处理后，移动端下一次同步移除或更新该事项；移动端处理结果也能在桌面端看到。
- 所有失败保留原卡、错误原因、已保存成果和可恢复入口。

### 动作三：用助手推进工作，并持续追踪执行

#### 用户目标

用户通过文字或语音询问进度、定位卡点，或发出工作指令。助手基于当前企业的真实上下文回答；执行型请求先展示会发生什么，经必要确认后进入后台，用户离开页面也不会丢失。

#### 产品行为

1. 助手首页展示真实业务相关建议问题、文字输入、语音输入，以及对话/通知切换。
2. 进度查询只读取当前账号有权查看的数据，回答标注统计区间、更新时间和证据入口；不知道时明确说未知。
3. 语音先转成可编辑文字，不自动发送；拒绝麦克风权限或识别失败时保留文字入口。
4. 系统先区分查询和执行。查询不会创建任务、启动周期或改变状态。
5. 执行型请求返回结构化操作预览：目标、影响对象、计划步骤、所需资料、权限、风险和是否产生费用。信息不足时追问。
6. 需要确认的请求由用户明确确认后提交；提交包含幂等键、目标版本和账号作用域。
7. 助手展示后台工作状态与真实回执：已接收、排队、执行中、等待用户、成功或失败。成功结果包含任务、成果、发布或会话入口；失败包含原因和恢复方式。
8. 通知与待处理引用同一任务、事项或命令身份。阅读通知不等于解决事项；需要用户动作的事件同时进入待处理。

#### 验收标准

- 询问“这周完成多少”不会启动任务或工作周期，答案可下钻到同口径数据。
- 提交工作指令前显示影响并按权限确认；重复提交不产生重复任务。
- 切后台或换设备后仍能看到同一命令的状态、事件和最终结果。
- 账号退出或切换企业后，旧企业的对话上下文、详情和异步响应不能进入新会话。
- 助手不得宣称未执行的动作已完成，也不得用本地模拟状态代替后端回执。

## 3. 信息架构

底栏固定为 `待处理 / 工作 / 助手`，默认选择中间“工作”。三个 Tab 分别对应“做决定、看进展、推进工作”。拍摄上传作为工作页快捷入口、缺素材事项的处理界面和保留的拍摄任务页，不单独占用底栏。

Tab 之间不通过整页横滑切换，避免与事项卡手势冲突。详情使用页面或底部抽屉，并保留返回位置。

## 4. 通用技术契约

1. 身份：所有读取和动作由服务端从登录令牌解析 `tenantId`、`userId`、角色和能力；客户端不得指定租户作用域。
2. 任务：任务、事项、日历、Agent 状态、通知和助手结果共享稳定业务身份。
3. 查询：指标返回 `value`、`availability`、`range`、`source`、`generatedAt`，下钻复用同一服务端过滤器。
4. 动作：返回稳定 `commandId`、幂等键、目标版本和 `accepted/running/waiting_user/succeeded/failed`；业务结果可单独查询或订阅。
5. 同步：前台定期刷新，回到前台立即刷新；后台任务不依赖小程序存活。缓存含企业作用域、更新时间和陈旧标记。
6. 权限：支持只读、成员、管理员等既有权限；内部数据模型差异通过服务端适配，不能绕过已有能力边界。
7. 安全：发布、发送、费用、授权和业务承诺保留明确确认、审计记录与最小权限。

## 5. 非功能要求

- 首屏在正常网络下优先展示骨架和最近可信数据；任何空态都区分真实为空、未配置、无权限、离线和服务失败。
- 移动触控目标不小于 44px；状态不用颜色作为唯一表达。
- 大列表必须分页；录像和录音遵守小程序限制并提供弱网恢复。
- 不在客户端保存服务密钥；认证失效后清空企业数据和异步请求。
- 所有业务日志避免记录密码、Token、录音原文等敏感信息。

## 6. 上线门槛

只有以下证据全部具备，才可声明上线完成：

1. PRD 三个动作的自动化契约测试通过，且覆盖租户隔离、分页、幂等、版本冲突和失败恢复。
2. 全仓类型检查、迁移完整性检查、构建和相关回归测试通过。
3. 测试环境应用新增迁移，并以至少两个企业账号验证指标、队列、动作和跨租户隔离。
4. 微信后台完成 AppID、合法域名、隐私说明和麦克风权限配置；iOS 与 Android 真机验证登录、三 Tab、滑卡、录音、上传、弱网和后台恢复。
5. 部署后记录代码提交、服务状态及 `/api/overseas/ready` 的准确结果；小程序版本上传和发布状态可追溯。

## 2026-10-10 联调共识：真实数据、行动路线与移动排期

### 数据原则

小程序不得在接口失败、账号未配置或数据为空时自动显示 Mock 数据。工作页、待处理队列、内容排期与询盘下钻均从当前登录账号所属租户的真实工作台数据读取。开发验收数据也必须写入本地 PocketBase，再经过正式服务端接口返回；页面需要如实区分“暂无记录”“数据源不可用”和“同步失败”。

### 待处理卡片与行动路线

| 卡片类型 | 首要判断 | 明确处理路线 | 完成凭证 |
|---|---|---|---|
| 发布审批 | 内容、账号、发布时间与影响是否正确 | 预览冻结版本 → 批准，或选择原因退回 → Agent 进入发布队列或返工 | 审批回执、任务新状态 |
| 成片验收 | 成片和质检结果是否达标 | 预览成片 → 通过，或选择画面/字幕/口播问题 → 进入排期或退回内容 Agent | 验收决定、排期记录 |
| 缺素材 | 缺哪个镜头、规格和截止时间 | 查看拍摄要求 → 拍摄/相册上传/选择已有素材 → Agent 从素材检查节点续跑 | 素材 ID、任务恢复时间 |
| 账号授权异常 | 哪个账号影响哪些任务 | 打开账号连接 → 重新授权 → 返回原任务重试 | 授权状态、重试回执 |
| 执行失败 | 已完成到哪一步、失败点是否可安全重试 | 查看执行记录 → 恢复依赖 → 从失败节点重试或取消 | 动作回执、任务状态 |
| 人工发布 | 平台暂不支持自动发布 | 下载发布包/复制文案 → 去平台发布 → 回填链接并标记完成 | 平台链接、发布回执 |
| 回执待核对 | 平台已有结果但系统未闭环 | 查看平台证据 → 核对帖子 → 确认回写或重试对账 | 回执证据、归因状态 |
| 高意向询盘 | 客户意图、时限和责任人 | 查看上下文与资格判断 → 编辑回复草稿 → 发送、转人工或安排跟进 | 回复记录、下一跟进时间 |

“去处理”必须进入对应路线，不得只打开通用详情。动作提交使用服务端幂等回执；页面仅在服务端确认后改变业务状态。

### 稍后处理

左滑提供 5 分钟、1 小时和明早 9 点。卡片移入“稍后”后显示准确返回时间并允许撤销；到时先从服务端重新读取真实状态。仍需处理时按原紧急度重新入队，已经完成或失效时自动消失，截止时间在延后期间越过时提示将逾期。

### 手机端内容排期

参考电脑端发布执行日历，而不是把普通任务压缩成单行日期。顶部保留 7 天日期带和“选题 → 制作 → 发布 → 复盘”阶段条；每天按时间纵向显示发布执行卡：时间、平台/账号、内容标题、当前节点状态、负责 Agent、唯一下一动作。失败、待重审和需人工介入事项优先展示。卡片详情回答三个问题：当前在哪一步、为什么停下/依据是什么、用户现在唯一应该做什么。

### 助手高频入口

快捷问题围绕移动端用户打开工作台时最常见的决策：

- 本周最需要我决定的 3 件事是什么？
- 哪些任务会影响本周发布目标？
- 哪条内容卡在素材、制作或验收？
- 今天有哪些高意向询盘要跟进？
- 4 个 Agent 现在分别在做什么？

回答必须以当前账号的真实任务、Agent、排期和询盘数据为上下文；涉及执行时给出可进入对应卡片的行动入口，不能把建议描述成已经执行。
