# 灵枢社媒图片生产工作流优化 PRD v1

> 状态：产品优化方案，待评审后进入开发
>
> 更新日期：2026-10-22
>
> 适用范围：灵枢社媒内容系统中的静态图片生产，包括产品主视觉、社媒单图、轮播封面及后续扩展的多页图片
>
> 关联基线：`PRD-灵枢AI当前系统-v3.md`、`PRD-社媒内容制作工作流-v1.md`、`PRD-灵枢AI全系统UI设计规范-v2-2026-10-09.md`

## 0. 核心结论

图片生产不是独立的“AI 画图工具”，而是灵枢内容经营主链中的一种交付能力。它必须复用同一内容任务、企业事实、产品、素材、灵感参考、发布包和效果复盘，不能形成一套与视频生产平行的主数据和业务链。

图片生产内部允许使用“无外部参考的原创生产”和“基于参考图的爆点迁移”两种策略，但这只是系统内部的生产选路。用户统一在内容创作首页操作；后台再按自由创作即时任务、爆款参考或数字员工周任务识别任务来源，不能把它们做成三个并列前端入口。用户不需要理解模型、提示词或技术路线。

固定责任边界如下：

- 经营 Agent 决定为什么做、面向谁、发到哪里以及用什么指标验证。
- 编导 Agent 是爆点判断、保留与替换策略、图片导演方案和最终创意放行的唯一责任 Agent。
- 内容 Agent 负责选素材、选生产能力、编译生成规格、生成、局部修复和技术质检，不得自行改变核心主张或批准自己的最终结果。
- 工具与 Worker 负责提取、计算、执行和保存证据，不负责解释“为什么会爆”。
- 用户只在产品事实、目标实质变化、权利风险和最终成品验收时介入。

任何未经真实输出检查、硬质量门检查和用户验收的图片都只能是草稿，不能成为可发布成品。

## 1. 产品目标

### 1.1 核心目标

1. 让不懂设计、提示词和模型的企业用户，只需确认产品、传播目标和必要事实，就能获得可交付的社媒图片。
2. 让图片作品继续进入发布包、平台发布、数据监控和下一轮内容规划，而不是生成后成为孤立文件。
3. 对参考图执行“身份剥离后的爆点机制迁移”：保留有证据支持的注意、理解、信任、情绪和转化机制；替换产品、品牌、原文案、人物身份及受权利保护的具体表达。
4. 用版本化数据合同连接每个生产节点，使任务可恢复、可重试、可审计，页面关闭后不丢失进度。
5. 用独立评估而不是生成模型自评证明产品一致性、事实一致性、文字正确性、平台规格和原创边界。

### 1.2 用户只需要理解的四个阶段

后台可拆分为多个执行节点，但客户界面只展示四个业务阶段：

1. 明确内容：确认产品、目标和交付规格。
2. 系统策划：系统分析事实、素材和参考图，形成图片方案。
3. 生产与检查：系统生成候选图并完成质量检查和必要返工。
4. 验收与交付：用户确认最终版本，再进入下载、发布包和数据回收。

每个状态只显示一个主要动作。客户界面不展示模型、供应商、提示词、哈希、内部任务号或 Worker 名称；这些信息只保留在受权限控制的技术详情和审计记录中。

### 1.3 成功标准

- 内容创作首页启动的即时创作、爆款裂变和数字员工周任务，均创建或恢复同一个 `ContentTask` 下的图片生产对象；灵感中心不再作为新的主生产入口。
- 企业事实只来自企业知识，创作素材只引用“我的素材”，不在图片工作台复制文件或创建私有素材库。
- 参考图中的每个关键爆点都有可定位的图像证据、判断理由、置信度、迁移策略和成品验收方法。
- 强制产品图、Logo 或证据图不可读取时明确阻断，不允许静默移除后继续生成。
- 任何硬质量检查为 `fail` 或 `uncertain` 时，不得批准为正式成品。
- 生成、检查、返工和审批均保存版本、输入引用和结果引用；刷新或离开页面后能够恢复。
- 已批准图片可生成对应平台的发布包；未批准图片只能以“草稿”身份下载。
- 发布后的真实指标能够回流到本次使用的爆点因素，但相关性不能自动升级为因果结论。

## 2. 产品边界与分类方式

### 2.1 图片任务属于统一经营主链

```text
经营目标或即时需求
→ ContentTask
→ 企业事实与我的素材
→ 可选灵感参考
→ 图片导演方案
→ 图片生产与独立质检
→ 用户验收
→ 发布包与平台发布
→ 指标回流与下一轮计划
```

图片任务不建立独立账号、独立产品、独立素材、独立发布状态或独立指标口径。

### 2.2 四个维度必须分开

当前图片类型中混合了题材、交付形态和技术格式。目标产品按四个正交维度记录：

| 维度 | 示例 | 决定什么 |
| --- | --- | --- |
| 业务题材 `topicType` | 产品亮点、品牌新闻、趋势、实验对比、工厂信任 | 要讲什么 |
| 交付物 `deliverableType` | 产品主视觉、社媒单图、轮播封面、信息图 | 画面承担什么任务 |
| 生产策略 `productionStrategy` | 复用素材、资产合成、参考生成、辅助画面生成 | 内容 Agent 怎样生产 |
| 交付规格 `deliverySpec` | 平台、比例、语言、数量、文件格式 | 最终交付怎样使用 |

“原创生产／爆点迁移”属于参考策略，不再替代上述四个维度。

### 2.3 首期范围

首期正式支持：

- 产品主视觉；
- 社媒单图；
- 轮播封面。

轮播多页、GIF 动态海报和复杂信息图在相同任务合同上扩展，但在相应渲染、版本和质量门没有完整实现前，不作为可正式交付能力展示。

### 2.4 不在本期范围

- 不承诺“必然爆款”或输出虚构爆款概率。
- 不把单张高播放参考图直接解释为因果证据。
- 不提供绕过版权、商标或平台审核的复刻能力。
- 不允许 AI 生成内容承担未经证实的功效、认证、客户案例或产品外观证明。
- 不在图片工作台内实现社媒账号连接、发布排期和指标看板，只与对应系统传递稳定对象。

## 3. 与灵枢其他系统的关系

### 3.1 唯一主数据关系

| 相关系统 | 图片生产读取 | 图片生产写回 | 禁止行为 |
| --- | --- | --- | --- |
| 周计划／即时内容任务 | `ContentTask`、目标账号、受众、CTA、预算、截止时间、实验变量 | 图片生产状态、最终作品引用、阻断原因 | 新建第二份业务 Brief 或脱离任务生成孤立图片 |
| 企业知识 | 企业、品牌、产品、买家、卖点、事实凭证的版本快照 | 仅写入本次引用关系；新事实须走企业知识确认流程 | 在图片任务中复制或静默改写产品事实 |
| 我的素材 | 产品图、Logo、场景图、证据图、历史可用成品及分析结果 | 使用履历、成品版本、实际使用角色 | 把文件复制到图片任务私有目录作为新主数据 |
| 灵感中心 | 参考图片、来源、权利边界、采集时间、平台表现及分析版本 | “用于哪次任务”的引用和后续真实表现 | 只保存标题或临时 URL，丢失原参考快照与来源 |
| 内容制作工作台 | 当前任务、节点状态、候选版本、质量报告 | 用户修改、版本选择、最终验收 | 在页面内重新计算另一套策略或状态 |
| 交付与发布 | 已批准作品、平台规格、文案、版本和校验摘要 | 发布包引用、发布凭证、平台内容 ID | 把下载成功当作发布成功 |
| 内容监控 | 发布内容的真实指标、来源与时间窗 | 因素表现观察、实验结果 | 把播放量相关性直接写成爆点因果结论 |
| 队列、额度与审计 | 租户、幂等键、预算、能力可用性 | 任务运行、供应商回执、成本、失败和重试记录 | 以前端长请求代替持久任务，或在结果未知时重复扣费生成 |

### 3.2 目标对象关系

`ContentTask` 是用户可见的唯一内容任务，`ImageProductionRun` 是它的图片生产子对象。现有 `SocialImageCreationTask` 应演进为 `ImageProductionRun` 的合同实现，而不是继续成为第二个业务任务根。

```text
ContentTask
├── BusinessContextSnapshot
├── EnterpriseFactSnapshot
├── AssetBindings
├── ImageProductionRun
│   ├── ReferenceAnalysis
│   ├── HookFactorSpec
│   ├── ImageDirectorBrief
│   ├── ImageExecutionPlan
│   ├── GenerationJobs
│   ├── CandidateVersions
│   ├── QualityReports
│   └── ApprovalDecision
└── DeliveryPackage / PublicationPackage / PerformanceObservations
```

## 4. 责任与决策边界

| 角色 | 可以决定 | 必须输出 | 不可以决定 |
| --- | --- | --- | --- |
| 灵小枢／任务编排器 | 创建或恢复任务、推进节点、聚合阻断和下一步 | 唯一任务上下文、节点状态、用户下一步 | 创作爆点、选择模型、批准成品 |
| 经营 Agent | 业务目标、账号、受众、平台、CTA、预算、成功指标和实验边界 | `ImageBusinessContext` | 构图、素材、模型和提示词 |
| 编导 Agent | 核心主张、爆点作用、保留／替换策略、创意方案、验收标准和最终创意放行 | `ImageHookFactorSpec`、`ImageDirectorBrief`、`ImageReviewDecision` | 伪造指标因果；指定供应商；批准事实错误的画面 |
| 内容 Agent | 素材候选、生产路线、模型能力、生成规格、候选版本和局部返工 | `ImageExecutionPlan`、`ImageRenderSpec`、`ImageRepairPlan` | 改写经营目标、事实、核心主张或自行批准最终成品 |
| 媒体分析 Worker | OCR、检测、分割、显著性、色彩、构图和参考相似度计算 | 带区域和置信度的机器证据 | 判断“为什么会爆”或调整因素重要性 |
| 质量评估 Worker | 文件、尺寸、OCR、身份、Logo、安全区、权利与相似度检查 | `ImageQualityReport` | 修改创意方案或把未知项判为通过 |
| 指标与平台 Worker | 同步平台表现、账号基线和实验结果 | `ImagePerformanceEvidence` | 把相关性写成因果，或直接修改爆点策略 |
| 用户 | 确认事实变化、目标降级、权利风险和最终作品 | `ImageApprovalDecision` | 无需选择模型、提示词或内部生产路线 |

编导 Agent 是爆点判断的唯一责任 Agent，但不能只凭模型直觉。工具先提供证据，编导 Agent 再做解释；最终由独立质量检查和编导复核共同放行，内容 Agent 不得自评自批。

## 5. 节点间稳定工作的数据规则

### 5.1 所有节点输出使用统一信封

每个正式输出对象都必须包含以下字段：

| 字段 | 要求 |
| --- | --- |
| `schemaVersion` | 明确合同版本；消费者不支持时阻断，不静默忽略关键字段 |
| `id` | 对象稳定 ID |
| `tenantId` | 租户隔离键 |
| `contentTaskId` | 统一内容任务 ID |
| `productionRunId` | 图片生产运行 ID |
| `version` | 单调递增版本；已批准版本不可覆盖 |
| `status` | `ready / running / completed / needs_review / stale / blocked / failed / outcome_unknown` 之一 |
| `inputRefs` | 上游对象 ID、版本和哈希，不只保存自由文本摘要 |
| `createdBy` | Agent、Worker、用户或系统身份 |
| `createdAt / updatedAt` | ISO 8601 时间 |
| `contentHash` | 规范化内容哈希，用于检测输入变化和幂等复用 |
| `evidenceRefs` | 事实、素材、参考帧、检测或指标证据引用 |
| `warnings / blockingReasons` | 警告与阻断分开；阻断必须有稳定原因码 |

### 5.2 交接规则

1. 下游只消费状态为 `completed` 且合同版本受支持的上游对象。
2. 输入对象内容或版本变化时，下游旧结果标记为 `stale`，不能继续作为当前批准依据。
3. 媒体文件通过稳定 `assetId + contentHash + version` 引用；临时 URL 只用于展示，不作为生产身份。
4. 每个外部生成请求必须带 `idempotencyKey`，保存供应商请求 ID 和回执；`outcome_unknown` 先对账，不能直接重提。
5. 每个节点必须保存结构化输出；自由文本只能作为说明，不能代替验收字段。
6. 硬检查的 `uncertain` 与 `fail` 都会阻断批准；系统不可把“未检查”投影为“通过”。
7. 所有返工必须引用来源版本、失败项和目标区域，生成新版本，不覆盖旧版本。
8. 任务状态来自节点真实结果，不使用前端计时器或人为百分比推断。

### 5.3 任务状态

主状态建议收敛为：

```text
draft
→ planning
→ ready_to_generate
→ queued
→ generating
→ quality_checking
→ review_required
→ repairing（可循环）
→ approved
→ delivered
```

异常状态为 `blocked`、`failed` 和 `outcome_unknown`。`approved` 必须由显式用户验收产生；自动检查通过只能进入 `review_required`。

## 6. 固定图片生产节点

### 节点 0：创建或恢复统一任务

**主责：** 灵小枢／任务编排器。

**输入：** 周计划任务、即时任务或灵感中心入口；当前租户、用户、账号和已有 `ContentTask`。

**工具负责：** 查找幂等键和已有任务；校验租户与权限；读取现有节点状态；锁定同一任务的并发写入。

**AI 负责：** 识别用户是继续原任务、基于参考图创作，还是创建新图片交付物；不生成创意内容。

**输出：`ImageProductionRunRef`**

- `contentTaskId`
- `productionRunId`
- `entrySource`
- `requestedDeliverableType`
- `currentNode`
- `resumeToken`

**门禁：** 同一入口重试必须返回同一运行对象；身份或租户不一致时阻断。

### 节点 1：业务需求标准化

**主责：** 经营 Agent。

**输入：** `ContentTask`、账号策略、周计划或即时需求、用户本轮补充。

**工具负责：** 读取企业默认平台、语言、比例、时区、账号和截止时间；验证枚举、数量与平台规格。

**AI 负责：** 将自然语言需求归一为一个明确传播目标，识别核心受众、目标动作和成功指标；不决定画面或模型。

**输出：`ImageBusinessContext`**

- `objective`
- `topicType`
- `deliverableType`
- `productRefs`
- `enterpriseFactSnapshotRef`
- `audience`
- `ownedAccountId / accountDraftId`
- `platforms`
- `targetAction`
- `successMetrics`
- `deliverySpec`
- `budgetAndDeadline`
- `fieldsToConfirm`

**门禁：** 产品身份、目标或交付规格存在实质歧义时进入 `needs_review`；平台、语言和比例可以继承默认值，但必须保存来源。

### 节点 2：企业事实与素材解析

**主责：** 企业知识服务、素材 Worker；内容 Agent 负责角色建议。

**输入：** `ImageBusinessContext`、产品 ID、企业事实版本、“我的素材”查询结果。

**工具负责：**

- 读取企业、品牌、产品和买家快照；
- 校验文件存在性、可读性、MIME、尺寸、透明通道和内容哈希；
- 做 OCR、Logo、产品、人物和场景识别；
- 记录来源、授权范围、产品关联和素材版本；
- 检测重复文件和过期引用。

**AI 负责：** 为素材建议 `product / logo / scene / evidence / style_only` 角色，判断哪些事实需要视觉证明，指出素材缺口；不得修改企业事实。

**输出：`ImageAssetManifest`**

- `enterpriseFactSnapshotRef`
- `assets[] { assetId, version, contentHash, role, required, readable, dimensions, rights, observedSubjects, ocr, confidence }`
- `requiredEvidence`
- `missingCapabilities`
- `prohibitedClaims`

**门禁：** 被标记为 `required` 的产品、Logo 或证据素材不可读取时必须阻断；不能通过删除 `productIds` 或素材引用继续生成。

### 节点 3：参考图来源与表现证据冻结

**主责：** 灵感中心与指标 Worker。无外部参考的原创任务可跳过。

**输入：** 参考图 ID 或用户上传参考图、来源页面、采集记录、平台指标快照。

**工具负责：** 保存原图快照、来源、采集时间、感知哈希、权利状态、平台、账号、发布时间和可获得的真实表现；按同账号、同平台、相近时间和相近主题计算相对表现。

**AI 负责：** 判断参考是否与当前目标相关，说明它承担整体结构、视觉钩子、证明方式或 CTA 中哪一种参考作用；不据播放量直接认定因果。

**输出：`ImageReferenceSnapshot`**

- `referenceId`
- `sourceUrl / sourceRecordId`
- `imageAssetRef`
- `platform / account / publishedAt`
- `rightsPolicy`
- `performanceEvidence[]`
- `relativePerformance`
- `referencePurpose`
- `fingerprint`

**门禁：** 爆点迁移任务必须有可读取的主参考快照；只有标题、描述或失效 URL 不得进入下一节点。

### 节点 4：参考图客观元素拆解

**主责：** 媒体分析 Worker；多模态 AI 只做语义补充。

**输入：** `ImageReferenceSnapshot`。

**工具负责：**

- OCR 与文字区域定位；
- 主体检测、分割、占比和遮挡计算；
- Logo、人物、产品与场景识别；
- 显著性热区和第一注意点估计；
- 构图网格、留白、层级、对齐和安全区计算；
- 主色、强调色、对比度、亮度和光线方向分析；
- 字体类别、字号关系和图形装饰区域识别。

**AI 负责：** 给工具区域补充可观察的语义名称，识别主体关系、情绪、信息阅读顺序和图片承担的传播功能；必须区分观察事实与解释。

**输出：`ImageElementInventory`**

- `canvas`
- `regions[] { regionId, bbox, layerRole, observedContent, toolScores, evidenceRef }`
- `ocrBlocks[]`
- `saliencyOrder[]`
- `composition`
- `colorAndLighting`
- `informationHierarchy`
- `observations[]`
- `analysisConfidence`

**门禁：** 关键区域必须有坐标和证据引用；工具无法识别的部分标记 `unknown`，不得由 AI 补造。

### 节点 5：爆点因素判断

**主责：** 编导 Agent。

**输入：** `ImageBusinessContext`、`ImageElementInventory`、`ImageReferenceSnapshot.performanceEvidence`、历史实验和账号策略。

**工具负责：** 提供区域、显著性、OCR、相对表现、重复模式和时间窗等证据；校验 AI 引用的证据真实存在。

**AI 负责：** 判断哪些因素可能影响注意、理解、证明、信任、情绪或转化；合并作用重复的因素，只保留对本次任务最重要的 4 个，最多 5 个；给出可迁移性、因果置信度和判断理由。辅助因素和装饰因素进入普通视觉描述，不进入爆点清单。

爆点数量采用“默认 4 个、硬上限 5 个、不为凑数补写”的规则：

1. 优先保留第一眼注意、核心信息理解、可信证明、行动转化四类中对当前目标贡献最大的因素；
2. 第 5 个因素只有在承担独立作用、证据充分且不能被前 4 个合并时才允许输出；
3. 同一区域、同一作用或同一验证方法的近义因素必须合并；
4. 证据不足时可以少于 4 个，并明确记录缺口，禁止为了满足数量伪造判断。

**输出：`ImageHookFactorSpec`**。每个因素至少包含：

- `factorId / regionRefs`
- `priorityRank`，取值为 `1–5` 且不得重复
- `category`
- `observableDescription`
- `causalRole`
- `importance`
- `evidenceRefs`
- `analysisConfidence`
- `causalConfidence`
- `effectStatus`
- `transferability`
- `validator`

`effectStatus` 只能是：

- `validated_hook`：已有客户账号单变量实验支持；
- `supported_hypothesis`：有相对表现、重复模式或平台行为证据支持；
- `visual_hypothesis`：只有单图视觉证据，尚无传播数据验证。

**门禁：** `ImageHookFactorSpec.factors` 不得超过 5 个；没有 `evidenceRefs` 的因素不得进入爆点清单；第 5 个因素必须具有与前 4 个不同的 `causalRole` 或独立验证方法；单张高表现图片最多支持 `visual_hypothesis` 或 `supported_hypothesis`，不能写成已验证因果。

### 节点 6：保留、替换与创新策略

**主责：** 编导 Agent；规则引擎检查权利和品牌边界。

**输入：** `ImageHookFactorSpec`、`ImageAssetManifest`、品牌规范和权利策略。

**工具负责：** 检测参考品牌 Logo、水印、人物身份、原文案和受保护素材；校验每个关键区域已获得策略；检查相互冲突的策略。

**AI 负责：** 把每个因素分为以下策略，并为替换项提出新的表达：

- `lock`：作用和可观察状态必须保留；
- `equivalent`：不复制具体像素，但功能与感知等价；
- `bounded`：允许在明确范围内变化；
- `replace_identity`：替换产品、品牌、人物或主体身份；
- `prohibit_reuse`：原文件、Logo、水印、文案或无权素材不得进入成品；
- `free`：没有证据表明影响结果，可按品牌风格创新。

**输出：`ImageAdaptationSpec`**

- `factorPolicies[]`
- `keepHooks[]`
- `innovationPoints[] { replaceElement, reason, newDirection, requiredAssets, differenceRequirement }`
- `excludedElements[]`
- `originalityConstraints`
- `brandConstraints`

**门禁：** 产品、品牌、原文案和无权素材必须有 `replace_identity` 或 `prohibit_reuse` 策略；不得把整张参考图或所有可见细节设为 `lock`。

### 节点 7：图片导演方案与图文合同

**主责：** 编导 Agent。

**输入：** `ImageBusinessContext`、`ImageAssetManifest`、`ImageAdaptationSpec`、已验证企业事实。

**工具负责：** 校验文本长度、必需事实引用、禁用词、平台安全区和交付规格；检查引用对象版本是否仍有效。

**AI 负责：** 形成图片的叙事与视觉方案，包括核心主张、标题层级、图文关系、主体、构图、视觉证明、风格边界和可观察验收条件。

**输出：`ImageDirectorBrief`**

- `objective / singleCoreClaim`
- `headline / supportingText / caption / cta`
- `requiredFacts / prohibitedInferences`
- `visualMustShow / visualMustNotImply`
- `compositionIntent`
- `imageTextRelation`
- `visualProof`
- `brandAndOriginalityRules`
- `acceptanceCriteria[]`
- `factorSpecRef / adaptationSpecRef`

**门禁：** 每个关键要求必须可观察、可检测或可人工判断；“高级感”“爆款感”等抽象词不能单独作为验收条件。

### 节点 8：执行计划与能力选路

**主责：** 内容 Agent。

**输入：** `ImageDirectorBrief`、`ImageAssetManifest`、当前生成／合成／排版能力、预算和截止时间。

**工具负责：** 返回模型与模板能力、支持的比例、输入限制、预计成本、队列状态和历史成功率；检查素材可访问性。

**AI 负责：** 为每个画面目标选择 `reuse_existing / compose_assets / reference_generate / generate_supporting`，决定候选数量、图层结构、素材用途和降级路径；不得降低编导验收标准。

**输出：`ImageExecutionPlan`**

- `productionStrategy`
- `selectedAssetRefs[]`
- `assetRoles[]`
- `renderRoute`
- `candidateCount`
- `layerPlan`
- `estimatedCost / estimatedDuration`
- `fallbackRoutes[]`
- `unmetCriteria[]`

**门禁：** 所有必需验收条件都必须有可执行路线；无法满足时退回编导 Agent 降级目标或进入 `blocked`，不能静默换掉核心产品与证据。

### 节点 9：模型无关规格编译与供应商适配

**主责：** 内容 Agent；规格编译器和规则引擎共同校验。

**输入：** `ImageExecutionPlan`、`ImageDirectorBrief`、素材稳定引用和目标模型能力。

**工具负责：** 计算精确像素尺寸、裁切和安全区；生成素材可访问句柄；验证模型限制；生成幂等键；冻结本次输入哈希。

**AI 负责：** 将导演方案编译为模型无关视觉指令，再由供应商适配层转换为提示词、负向约束、参考强度和图层指令；不得把提示词作为唯一生产规格。

**输出：`ImageRenderSpec`**

- `width / height / aspectRatio`
- `assetInputs[] { assetId, version, contentHash, role }`
- `layoutConstraints`
- `textLayers`
- `subjectConstraints`
- `factorTargets[]`
- `negativeConstraints`
- `providerAdapterVersion`
- `seedPolicy`
- `idempotencyKey`
- `inputHash`

**门禁：** 规格中的比例必须对应真实像素；例如 `4:5` 不得降为方图。强制素材引用与上游哈希不一致时重新规划。

### 节点 10：持久化生成与候选入库

**主责：** 生成 Worker。

**输入：** 已验证的 `ImageRenderSpec`。

**工具负责：** 后台排队、提交供应商、保存请求 ID、轮询或接收回调、下载结果、病毒与文件检查、计算哈希、保存成本和回执、写入素材存储。

**AI 负责：** 仅由选定的图像模型执行生成；任务编排 AI 不在此节点重新改写目标。

**输出：`ImageCandidateSet`**

- `jobId / providerReceipt`
- `status`
- `candidates[] { candidateId, artifactRef, version, width, height, contentHash, renderSpecRef }`
- `cost / timing`
- `generationWarnings`

**门禁：** 页面关闭不影响任务；超时但供应商结果未知时写入 `outcome_unknown` 并先对账，不立即重复提交。

### 节点 11：技术与事实质量检查

**主责：** 质量评估 Worker；与生成模型独立。

**输入：** `ImageCandidateSet`、`ImageRenderSpec`、`ImageAssetManifest`、`ImageDirectorBrief`、`ImageAdaptationSpec`。

**工具负责：**

- 文件可解码、尺寸、比例、清晰度和色彩空间；
- 产品和包装与实际输入参考的视觉一致性；
- Logo、标签和可见文案 OCR；
- 产品、人物与关键主体可见性；
- 文本溢出、对比度、平台安全区；
- 禁止事实、禁用词和必需文案；
- 参考结构相似度与禁止复用检测；
- 每项保存区域、分数、阈值和证据图。

**AI 负责：** 多模态检查工具难以确定的语义一致性、画面是否暗示错误事实、图文是否相互证明；低置信度必须输出 `uncertain`。

**输出：`ImageQualityReport`**

- `candidateId / candidateHash`
- `checks[] { key, verdict, severity, checker, score, threshold, region, evidenceRefs, note, repairSuggestion }`
- `hardGatePassed`
- `recommendedAction`

**门禁：** `product_identity` 必须同时核对实际生成输入与输出像素，不能仅因任务绑定了产品 ID 就判通过。任一硬检查为 `fail` 或 `uncertain` 时，`hardGatePassed=false`。

### 节点 12：独立创意审稿

**主责：** 编导 Agent；不能由内容 Agent 或生成模型完成。

**输入：** 候选图、`ImageQualityReport`、`ImageDirectorBrief`、参考图证据和因素规格。

**工具负责：** 并排展示参考、候选、区域标注、差异和失败项；校验审稿结论引用的因素与证据存在。

**AI 负责：** 判断核心主张是否清楚、爆点机制是否实现、创新替换是否成立、品牌表达是否一致以及是否值得交给用户；输出 `accept_for_user_review / repair / regenerate / block`。

**输出：`ImageReviewDecision`**

- `decision`
- `candidateId`
- `passedCriteria[] / failedCriteria[]`
- `factorResults[]`
- `problemRegions[]`
- `reasonCodes[]`
- `repairInstructions[]`
- `reviewConfidence`

**门禁：** 硬质量门未通过时不能选择 `accept_for_user_review`。审稿必须指出失败条件和区域，不能只写“效果不好”。

### 节点 13：定向返工与版本迭代

**主责：** 内容 Agent。

**输入：** `ImageReviewDecision`、来源候选、图层图或原生成规格。

**工具负责：** 根据目标区域选择局部重绘、图层排版、重新生成或文字层修复；保留未受影响图层；记录版本差异和成本。

**AI 负责：** 将失败项转为最小修改指令，判断局部修复是否足够；如果整体创意错误则重新生成，不能无限局部打补丁。

**输出：`ImageRepairPlan` 和新 `ImageCandidateSet`**

- `fromVersion / toVersion`
- `failedCheckRefs`
- `targetRegions / targetLayers`
- `repairMethod`
- `preservedLayers`
- `instruction`
- `attempt / maxAttempts`

**门禁：** 新版本必须重新经过节点 11 和 12。达到预算、时间或重试上限时进入 `needs_review` 或 `blocked`，不得伪装完成。

### 节点 14：用户验收与版本冻结

**主责：** 用户；系统负责展示与记录。

**输入：** 通过硬质量门和编导审稿的候选版本、简化质量摘要、版本差异和平台预览。

**工具负责：** 确认版本未过期、记录用户身份与时间、生成不可变成品引用；拒绝时保存原因并回到返工节点。

**AI 负责：** 用业务语言解释本版保留的爆点、完成的创新替换和仍需用户知晓的限制；不诱导用户批准。

**输出：`ImageApprovalDecision` 和 `ApprovedImageArtifact`**

- `decision: approved / rejected`
- `approvedCandidateId / version / contentHash`
- `approvedBy / approvedAt`
- `qualityReportRef / directorReviewRef`
- `usageRestrictions`

**门禁：** 未经显式批准、存在待确认事实、使用模拟事实或硬检查未通过时，不能生成正式成品状态。

### 节点 15：交付、发布与效果回流

**主责：** 经营 Agent、交付服务、平台与指标 Worker。

**输入：** `ApprovedImageArtifact`、帖子文案、平台规格、目标账号和发布授权状态。

**工具负责：** 生成平台适配文件、缩略图、发布包和校验清单；记录下载、发布凭证、平台内容 ID、指标来源与时间窗。

**AI 负责：** 在不改动已批准事实与图片的前提下给出平台文案适配和下一轮实验建议；根据真实表现提出假设，不直接改写原爆点结论。

**输出：`ImageDeliveryPackage` 和 `ImagePerformanceObservation`**

- `artifactRef / approvedVersion`
- `platformVariants[]`
- `publicationPackageRefs[]`
- `publicationEvidenceRefs[]`
- `metricSnapshots[]`
- `factorObservations[]`
- `nextExperimentSuggestion`

**门禁：** 下载、生成发布包和发布成功是三个不同状态。没有平台回执、公开链接或经审核人工凭证时，不得显示“已发布”。

## 7. 爆点判断的有效性保障

### 7.1 三层有效性

| 层级 | 要证明什么 | 主要责任者 | 通过条件 |
| --- | --- | --- | --- |
| 事实有效 | 图片中实际有什么、在哪里、占比多少 | 媒体分析 Worker | OCR、区域、显著性、主体和颜色等均有机器证据 |
| 推理有效 | 为什么该因素可能影响注意、理解、信任或转化 | 编导 Agent＋规则校验 | 每条结论绑定证据、作用、策略、置信度和验收方法 |
| 市场有效 | 该因素是否真的改善业务指标 | 指标 Worker＋经营 Agent | 历史相对表现或客户账号单变量实验支持 |

### 7.2 不允许的判断方式

- 输出超过 5 个爆点，或把装饰细节、近义描述拆成多个爆点。
- 为凑满 4 个而补写没有证据的因素；证据不足时应如实少报并记录缺口。
- 只根据图片整体观感输出“高级”“有冲击力”而没有区域和证据。
- 根据单条高播放内容宣布某元素是已验证因果。
- 把显著性最高等同于转化贡献最高。
- 让同一个生成模型既产图又独立批准自己的结果。
- 将工具无法判断的项目自动设为通过。

### 7.3 核心因素结构示例

```json
{
  "factorId": "factor-product-number-01",
  "regionRefs": ["region-product", "region-headline"],
  "category": "attention_and_benefit",
  "observableDescription": "大尺寸产品主体与短数字标题形成第一视觉焦点",
  "causalRole": ["attention", "understanding"],
  "importance": "critical",
  "effectStatus": "visual_hypothesis",
  "analysisConfidence": 0.91,
  "causalConfidence": 0.42,
  "evidenceRefs": ["saliency-01", "ocr-02", "bbox-product-01"],

    "productAreaRatio": [0.45, 0.6],
    "headlineWordCountMax": 8
  },

}
```

## 8. 质量门与批准规则

### 8.1 硬质量门

以下项目在适用时必须通过：

- 产品身份一致；
- 包装、标签和关键产品结构可见；
- Logo 与品牌表达正确；
- 可见文案 OCR 与批准文本一致；
- 产品事实和画面暗示一致；
- 核心主张与画面一致；
- 文本不溢出；
- 平台安全区与真实尺寸正确；
- 必需主体可见；
- 禁止复用内容未进入成品。

### 8.2 软质量项

参考结构相似度、审美一致性、色彩协调、候选偏好和实验变量可作为软质量项。软质量项影响排序和审稿，但不能覆盖硬质量失败。

### 8.3 正式批准条件

只有同时满足以下条件才能把任务设为 `approved`：

1. 当前版本所有适用硬检查均为 `pass`；
2. 不存在 `fieldsToConfirm`；
3. 编导 Agent 决策为 `accept_for_user_review`；
4. 用户显式批准当前版本；
5. 当前版本输入引用、文件哈希与检查报告一致；
6. 内容不是模拟事实，或交付用途明确限制为内部草稿。

硬检查的 `uncertain` 不能由最终用户的一次“确认成品”自动覆盖。系统必须由具备证据的工具复检，或由有权限的人工质检者写入带身份、时间、区域和理由的 `human` 检查结果，将该项明确解析为 `pass` 或 `fail` 后，才能继续批准。

## 9. 客户端体验要求

### 9.1 页面结构

- 使用统一内容制作任务上下文，不再建立第二个图片首页或第二套历史记录。
- 媒体预览是工作台主视觉，使用真实宽高比和统一媒体状态组件。
- 后台 16 个节点只投影为“明确内容、系统策划、生产与检查、验收与交付”四个业务阶段。
- 已知总量才显示真实进度；未知总量显示当前节点，不虚构百分比。
- 阻断原因出现在发生问题的字段或阶段内，固定操作区只保留保存状态和唯一主操作。
- 客户可查看“保留了什么、替换了什么、为什么”，但不展示模型提示词和内部评分细节。

### 9.2 用户主要动作

| 状态 | 唯一主操作 |
| --- | --- |
| 缺少产品或关键事实 | 确认产品与事实 |
| 缺少强制产品图或证据图 | 选择或上传对应素材 |
| 方案已形成 | 开始制作 |
| 正在生成或检查 | 查看当前进度 |
| 需要用户验收 | 确认当前版本 |
| 用户拒绝 | 提交修改要求 |
| 已批准 | 下载成品或进入发布包 |

### 9.3 草稿与成品

- 未批准版本下载时必须显示“草稿”，并在元数据或文件名中保留草稿标记。
- 只有 `ApprovedImageArtifact` 可以进入正式交付包和发布包。
- 用户批准后再修改必须创建新版本；原批准版本保持不可变，直到用户批准新版本取代它。

| `qualityChecks` | 拆为独立 `ImageQualityReport`，检查必须绑定真实候选像素和证据 |
| `repairInstructions` | 保留；强制引用失败检查、区域、来源版本和新版本 |
| `layerGraph` | 继续用于可编辑合成结果；非分层结果也必须保留等价的生成规格和区域分析 |
| `publishable` | 不再由前端或单次预检直接设置，只由批准条件统一计算 |

## 11. 开发优先级

### P0：形成可信且可恢复的完整闭环

1. 将图片运行绑定到统一 `ContentTask`，补齐深链与恢复。
2. 建立通用节点信封、版本、哈希、输入引用和幂等规则。
3. 建立 `ImageAssetManifest` 强制素材可读门禁，删除任何静默清空产品引用的降级路径。
4. 建立参考图客观拆解、爆点因素和保留／替换结构化合同。
5. 将生成改为后台持久任务，支持 `outcome_unknown` 对账。
6. 修正所有比例到真实像素映射，至少覆盖 `1:1 / 4:5 / 9:16 / 16:9`。
7. 建立绑定真实候选像素的产品、OCR、事实、安全区和尺寸检查。
8. 增加编导审稿与用户批准接口；未批准输出只允许作为草稿。
9. 已批准作品接入现有交付包、发布包和历史作品系统。

### P1：提升可控创作与返工效率

1. 多候选生成与并排比较。
2. 通用图层图与自然语言局部修改。
3. 自动生成区域级修复计划并限制返工范围。
4. 灵感中心参考图表现证据与相对表现接入。
5. 版本差异、成本和质量变化可视化。

### P2：建立真实效果学习

1. 将已发布图片的真实指标回流到因素观察。
2. 支持客户账号单变量图片实验。
3. 形成只供召回和辅助判断的 `CreativePatternMemory`。
4. 只有重复证据或实验支持时，才提升因素的因果置信度。

## 12. 验收标准

### 12.1 链路验收

- 从周计划、即时任务和灵感中心进入，均能创建或恢复同一图片任务。
- 每个节点均能通过 `inputRefs` 追溯上游对象和版本。
- 页面刷新、关闭后重开和跨端恢复均不会重复生成或丢失结果。
- 供应商超时结果未知时不会立即发起重复扣费任务。

### 12.2 参考分析验收

- 参考图每个关键区域有坐标、机器观察和置信度。
- 每个爆点因素都有作用、证据、重要性、因果置信度、策略和成品验证器。
- 每次分析默认输出 4 个、最多 5 个核心爆点；相同作用已合并，装饰因素不进入爆点清单。
- 产品、品牌、原文案和无权内容均被明确替换或禁止复用。
- 无真实传播证据时，界面和数据均显示“爆点假设”，不显示“已验证有效”。

### 12.3 生产与质量验收

- 强制产品图不可读时任务阻断，不能无产品参考继续生成。
- `4:5` 等比例的实际像素、预览和下载文件一致。
- 产品一致性检查核对实际生成输入和输出像素，不以数据库绑定代替视觉检查。
- 任一硬检查为 `fail` 或 `uncertain` 时无法批准。
- 修复产生新版本，旧版本、差异和质量报告均可查询。

### 12.4 用户与下游验收

- 用户只看到四个业务阶段、真实状态和唯一主操作。
- 用户能理解本版保留的爆点机制和完成的创新替换。
- 未批准图片明确标记为草稿，不能进入正式发布包。
- 批准版本能生成平台发布包；发布凭证和指标回流到同一内容任务。

## 13. 决策结果

本 PRD 将图片生产定义为灵枢统一内容经营系统中的专业生产能力，而不是独立 AI 作图页。研发实现时应优先完成稳定对象、责任边界、证据和审批闭环，再扩展更多图片类型、模板和供应商。生成数量、模型数量或模板数量不能替代可恢复、可验证和可交付。
