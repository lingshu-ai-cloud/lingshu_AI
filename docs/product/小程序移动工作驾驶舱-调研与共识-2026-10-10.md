## 四、产品定义建议（待确认）

定位：灵枢移动工作驾驶舱。用户打开后能够回答：本周推进到哪里、各 Agent 正在做什么、哪里受阻、需要我做什么、已经产出了什么。

建议底部四个入口：总览、Agent、本周任务、拍摄。账号与企业切换放到页头菜单。拍摄下收纳原有任务筛选和创建功能。

### 总览

信息顺序：本周摘要 → 需要我处理 → Agent 当前工作 → 最新成果。

- 周摘要：已完成/计划任务数、进行中、受阻、待确认、数据更新时间。
- 待处理：具体任务、原因、对周目标的影响、唯一主操作。
- Agent 摘要：角色、当前任务、当前阶段、最近一次真实事件。
- 成果：可打开的脚本、视频或其他已保存交付物。

### Agent

每个 Agent 显示职责、状态、当前任务、已保存结果、最近事件时间、下一交接对象。状态建议区分执行中、排队、等待依赖、等待用户、自动恢复、失败、空闲。

角色存在不等于正在运行；没有活跃任务时显示空闲。实际任务执行与角色状态分别表达，不把角色数量当成后台并发。

### 本周任务

按任务展示目标、负责人/Agent、截止时间、阶段、结果和阻塞原因；可筛选全部、进行中、受阻、待确认、已完成。详情用节点时间线展示过程与证据。

周完成率只统计本周计划范围，保留计划版本；手动任务明确标注来源。任务完成、内容发布、经营效果分开统计。

### 首版范围建议

先做真实状态、周进度、阻塞原因、结果查看与原拍摄上传串联。计划确认、验收、退回修改、局部重试作为下一步候选，逐项确认后接入。

## 五、UI 风格建议（待确认）

沿用仓库现有“明亮、克制、可信”风格，吸收 Linear 的紧凑层级与飞书的待处理动线。

- 品牌绿 `#117F51`，背景 `#F6F8F5`，白色内容面，分隔线 `#DFE8E1`。
- 暖杏色用于需要人工介入；失败配明确文字和错误图标。
- 连续摘要带、清晰分组列表、适量卡片；任务详情采用纵向节点时间线。
- 状态同时用文字与图标；避免用机器人动效暗示实际执行。
- 单屏突出一个主操作，触控区域建议至少 44px。
- 无数据、加载失败、离线缓存和过期状态分别表达；缓存显示最后同步时间。
- 进度来自真实完成节点，不使用随时间增长的模拟百分比；没有可靠预计时间时明确未知。

### 两种滑动交互需分开设计（建议，待确认）

1. **浏览卡片**：左右滑切换 Agent 或工作事件。滑动仅切换内容，不改变任务状态；卡片露出下一张边缘，并显示当前位置与总数，点击查看详情。
2. **处理事项**：参考 Outlook，待处理列表滑动露出“稍后提醒”“关注”等快捷操作。审批、发布、预算调整保留明确按钮，不把浏览动作当成业务确认。

候选趣味交互：

- Agent 值班卡：每张包含角色、当前任务、阶段、真实更新时间、已保存成果和主动作；卡面可看见接下来还有别的角色。
- 工作播报卡：一条卡片讲清“刚完成什么/为什么卡住/需要我做什么”，点击展开证据；按重要性整理，提供全部任务入口。
- 本周成果翻阅：左右切换已完成视频/脚本，展示所属任务和真实完成时间。
- 任务详情底部抽屉：打开细节，关闭后回到原卡片位置。

整页仅保留一种横向滑动语义，避免 Agent 横滑、任务横滑和整页横滑相互冲突；先选一个主交互试做。

### 底栏模式及应用建议（待确认）

底栏承载稳定的一级目的地；待拍/已上传这类状态放进页面内筛选。“拍摄”若是一次动作可成为快捷按钮，若承载拍摄任务、上传历史和创建功能则适合作为一级页面。

| 候选 | 建议底栏 | 适用重点 | 取舍 |
| --- | --- | --- | --- |
| A：工作信息流 | 工作 / Agent / 本周 / 我的 | 有趣的工作播报与 Agent 卡片 | 拍摄放“工作”快捷入口及缺素材任务卡；不再独立占栏 |
| B：保留现场拍摄 | 工作 / Agent / 任务 / 拍摄 | 同时覆盖外出查看与拍摄上传 | 企业与个人设置放页头；最接近原有功能连续性 |
| C：待办优先 | 总览 / 待办 / 任务 / 我的 | 高频审批、验收、补资料 | Agent 放总览滑卡与任务详情，缺少独立团队入口 |

当前倾向先讨论 B：让“工作”首页采用 ONE 式播报与横滑卡片，Agent 页负责完整角色状态，任务页默认本周，拍摄保留。若用户主要是负责人且拍摄低频，可选 A。

以上底栏均是本项目候选方案，不是竞品现有标签。

## 九、第三轮：三 Tab 结构已确定

### 2026-10-10 已确认方向（替代此前四栏建议）

- 一级导航共三个可切换 Tab，默认进入中间 Tab。
- 中间首屏上部是工作播报：本周任务总数、完成件数、已发视频、曝光、询盘。数据可点击下钻，询盘进入对话列表，视频进入视频列表。
- 中间首屏下部希望接入现有 Agent 日历看板，点击任务卡查看当前进展。是否及如何复用需核实，不把意向写为已完成能力。
- 左侧是重要事项卡片，探索左滑/右滑处理，由产品设计归纳各类事项的共同交互。
- 右侧是语音助手，参考用户提供的 HeyGen 助手与通知截图；支持类似手机对话助手的体验。
- 截图参考点：白色留白、助手形象与问候、建议问题、底部文字/麦克风输入、对话/通知切换。参考截图不构成对 HeyGen 移动产品能力的验证。

### 具体设计提案（以下仍待确认）

底栏：`待处理 / 工作 / 助手`，工作默认选中。独立 Tab 不通过整页横滑切换，避免与事项卡横滑冲突。底栏持续可见；详情使用抽屉或独立详情页。

#### 中间：工作

1. 页头：企业、周范围、本周/上周切换、最近同步时间。
2. 两组播报：执行（本周任务数、已完成数）；经营（已发布、曝光、询盘）。每个数据都有明确标签和点击入口。
3. Agent 动态摘要：例如“内容 Agent 正在合成视频；编导 Agent 等待素材”，进入关联任务详情；可展开所有 Agent 状态，保持原有“查看所有 Agent”的目标。
4. 内容排期：默认周视图，顶部七天日期条，下方为选中日期的纵向任务卡；点击日期切换列表，上一周/下一周用明确按钮。可展开月视图作日期定位。
5. 拍摄上传作为页头加号/快捷动作，并由缺素材卡直达相关任务；原待拍、已上传、创建功能收纳至拍摄任务页。

手机日历不把桌面七列密集看板等比缩小：保留日期与任务关联，改为日期条+当天卡片。任务卡显示计划时间、标题、负责 Agent、阶段、受阻原因或待处理项。点击打开同一份任务详情（当前节点、已保存成果、最近事件、下一步）。

代码核实：`src/components/AgentWorkspace.tsx` 有“工作日历”；另有 `src/components/publishing/CalendarPlanner.tsx` 的内容发布日历及 `SmartBusinessDashboard.tsx` 的12周运营日历。需要确认用户指哪一种，并核实任务/排期/运行事件的关联；不能混淆计划与真实执行。

数据口径候选：

- 周任务：属于所选企业周计划的任务，已完成按验收/完成权威状态统计；计划版本及取消任务处理需确定。
- 已发视频：平台确认发布成功；区分独立视频数与跨账号发布次数，主卡建议独立视频数，详情显示发布次数。
- 曝光：所选周时间窗口内真实曝光；平台仅有播放量时单列播放量，不冒充曝光。缺失与零值分开，详情列平台与同步时间。
- 询盘：所选周新进入且符合业务定义的询盘，建议按会话去重；新联系人、询盘会话、消息数量不能混用。
- 下钻列表继承企业、周范围和统计状态筛选，支持返回原位置。

#### 左侧：待处理

统一事项模型：对象、原因、影响、建议动作、截止时间、负责 Agent、当前权限、处理状态。

| 事项类型 | 卡片内容 | 右滑后打开的处理界面 | 完成依据 |
| --- | --- | --- | --- |
| 周计划待确认 | 目标、产量、预算与主要变更 | 计划摘要与确认按钮 | 服务端确认计划版本 |
| 脚本/视频待验收 | 预览、检查结果、需要决定什么 | 查看结果，确认或填写修改要求 | 验收结果保存成功 |
| 缺素材/资料 | 缺什么、影响哪个任务 | 拍摄、上传或补资料表单 | 入库并关联成功；是否满足依赖由后端判断 |
| 发布待授权/账号异常 | 内容、账号、时间、阻塞原因 | 发布确认或支持的账号处理流程 | 权限及业务动作验证成功 |
| 询盘待跟进 | 客户摘要、诉求、待答内容 | 对话详情与回复草稿 | 实际回复成功或明确转交 |
| 执行失败待恢复 | 失败节点、已保存结果、重试影响 | 可用恢复选项与费用说明 | 后端已受理恢复；不冒充任务完成 |
| 排期冲突/临近超期 | 原排期、影响、候选方案 | 日期/时间选择与变更确认 | 新排期保存成功 |

公约数建议：左滑=稍后处理（选择提醒时间，不解决、不删除）；右滑=现在处理（打开该事项处理界面，不直接审批/发送）；点卡=只看详情。底部始终提供“稍后”“处理”可点击按钮，手势是同一动作的快捷入口。

交互反馈：拖动时露出动作文字，达到阈值再松手触发；不够阈值回弹。稍后可撤销，延期事项保留到“稍后”列表；依然受阻/超时的事项仍影响首页统计。受理成功、处理中、已解决分开表达，服务端失败不把事项移成完成。外部状态改变时更新原卡，不产生重复事项。

排序：会阻塞后续的事项、临近截止项优先，其余按业务优先级与时间；自动恢复中的任务默认是播报，不混入必须用户处理的卡堆。无事项显示真实空态及返回工作入口。

#### 右侧：助手

首页：灵小枢形象与问候、3个与当前业务有关的建议问题、文字输入和麦克风。建议问题例如“这周还差哪些任务？”“哪条视频需要我处理？”“今天有哪些新询盘？”

对话状态：未录音、录音中、识别中、待发送、响应中、播放中、失败；识别出的文字可编辑再发送，随时取消，权限拒绝后可以打字。语音答复可停止，文字答复始终保留。

回答由企业权限内真实数据支持；带任务、视频、对话等可点击结果卡。执行指令先返回明确操作卡，缺少信息时追问，成功后给可追溯的业务结果。授权、发送、发布等操作不从模糊语音直接提交。

对话/通知在助手页顶部切换，通知从第二张参考图借鉴列表层级与未读点。只有需要操作的事件同步进入左侧待处理，其余完成播报保留在通知；两处使用同一事件关联，阅读不等于解决。系统公告与任务事件分组，避免混淆。

## 十三、理想产品效果（设计建议，待讨论确认）

### 用户的一次使用

用户在外出途中打开小程序：十秒内读到这周完成了什么、下一项交付是什么、哪里卡住、今天有没有必须本人决定的事。点一条受阻任务，看到最近的真实动作、已产出的内容、缺少的条件和预计下一步。处理一张视频发布确认卡，预览视频和发布账号，确认后看到“已提交审批，待执行”；随后收到“已发布”或“发布失败”的真实结果。向助手说“把明天的视频提前到今天”，助手展示会影响哪些排期、账号与任务，必要时请求一次明确确认，然后把操作交给后台持续执行；用户可以离开页面，回来查看结果。

### 三个 Tab 的职责

- **待处理：做决定。** 排序综合截止时间、业务损失、是否阻塞后续任务、本人可执行权限和真实风险。每卡说明“是什么 / 为什么需要你 / 建议方案 / 决定后的影响”，并有成果预览或证据入口。左划选择稍后时间，右划展开处理；最终按钮随业务含义变化，如批准发布、退回修改、补拍素材、重新授权、查看失败原因。处理成功才退出队列，失败保留上下文并可重试。
- **工作：看进展与结果。** 首屏用一句话解释本周情况，指标提供统一统计区间与来源并可下钻。Agent 状态给出当前工作、最近更新时间、阻塞条件和下一步；日历用七日条加当日任务列表，内容跨制作、验收、排期、发布、复盘共用同一任务身份。所有数字与列表可互相核对。
- **助手：推进工作。** 能理解用户当前企业、所看的任务和已有工作记录；回答给出证据和跳转入口。操作型请求形成真实后台命令，展示影响范围、必要确认、执行中状态和最终结果；持续任务不会随着手机切后台而消失。语音先识别为可修改文本，识别失败提供文字退路。

### 通用底层应提供的契约

统一账号和企业作用域、任务身份、人工事项与业务状态分离、跨页面版本号、幂等命令、后台持续队列、持久化稍后时间、进度事件与通知、指标区间和来源、权限与可执行动作投影。页面操作要能追踪“用户请求 → 接收 → 后台执行 → 成果/失败”，不能把 HTTP 接收成功等同于业务完成。

### 当前实现与理想效果的距离

当前已具备入口、真实接口连接代码、部分审批和任务操作、队列与账号级稍后；仍需补统一周指标契约、所有工作台来源的内容日历、完整询盘对话、结构化业务表单与助手执行结果回流，并做真实账号和微信真机联调。这些未验证前不视为可上线。上面交互和底层契约是设计建议，不能当成用户已确认的全部范围。
