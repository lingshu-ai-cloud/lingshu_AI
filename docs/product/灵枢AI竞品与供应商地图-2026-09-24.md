# 灵枢 AI 竞品与 AI 产品/供应商地图

> 价格快照：2026-09-24。币种保留官网币种；“起”表示最低公开付费档或代表性 API 单价；年付折算、促销、税费、地区价和企业折扣可能不同，采购前应再次核价。

## 1. 先说结论

灵枢不是单一的“AI 文案工具”或“社媒排程工具”，更接近一套面向制造业出海的 **AI 社交获客运营系统**：企业事实与目标 → 市场/竞品采集 → 选题与编导 → 图文/视频/数字人生产 → 审核 → 发布与投放 → 互动/询盘 → 客户分层与销售跟进 → 订单与复盘记忆。

因此，竞品需要分成三层看：

1. **业务结果层**：OKKI、询盘云、HubSpot、Salesforce、11x，争夺的是线索、询盘和销售结果。
2. **运营工作台层**：Sprout Social、Planable、ServiceNow、UiPath、Microsoft Agent 365，争夺的是任务、审批、编排与治理入口。
3. **能力供应层**：Qwen、Gemini、Seedance、MiniMax、HeyGen、Apify 等，是灵枢可以组合和替换的能力供应商，不应该反过来定义灵枢产品。

仓库现状对应的主链路是：

- **已接入/已配置**：Qwen / DashScope、Gemini、Seedance / ModelArk、MiniMax、HeyGen、Apify、yt-dlp。
- **平台能力**：YouTube、Meta、TikTok、抖音、WhatsApp，以及 Meta Ads、Google Ads。
- **当前最值得建立备选的能力**：DeepSeek（低成本文本）、Firecrawl（网页知识采集）、ElevenLabs（海外语音）、Runway / Veo（视频质量标杆）、Salesforce / Intercom（线索到客服结果闭环）。

这里的“已接入/已配置”只表示仓库已经存在代码、环境变量或交付文档，不等于所有能力都已在生产环境启用；例如视频生成仍受功能开关和租户预算控制。

“市面上所有”在本报告中定义为：**灵枢端到端链路中，值得采购、API 集成、替换测试或持续对标的国内外主流产品**。不纳入纯娱乐应用、没有稳定商业接口的套壳产品、重复度极高的小工具和纯研究模型。

## 13. 建议的采购/集成优先级

### P0：继续作为当前实现的主链路/首选供应商

- Qwen：默认文本、脚本、分析。
- Gemini：视觉/视频理解和复杂多模态补位。
- Seedance：视频生成主供；务必保留租户预算、分辨率成本和失败回滚。
- MiniMax：中文/多语配音、音色克隆；可顺带评估 H3 视频备份。
- HeyGen：正式数字人；继续强化授权、私有人物隔离和分钟成本。
- Apify + yt-dlp + FFmpeg：采集/下载/转码底座；严格限制抓取范围、频率和 Cookie 来源。

### P1：用小样本 AB 测试，不急着全面采购

1. DeepSeek：验证批量分类、摘要、标签和低风险内容能否显著降本。
2. Firecrawl：验证企业官网/竞品网站的结构化采集质量。
3. ElevenLabs：用英语、西语、阿语各做 20 条脚本，对比 MiniMax 的自然度和成本。
4. Runway、Veo、Hailuo：每家固定同一组 20 个镜头，与 Seedance 比首轮可用率、失败率、平均重做次数和每条合格视频成本。
5. Intercom Fin / Salesforce Agentforce：研究“按解决结果/按动作计价”和询盘转人工机制，暂不必采购。

### 持续对标，但当前不建议直接采购

- ServiceNow、UiPath、Microsoft Agent 365：学习企业治理、审批、异常和可观测性。
- Sprout Social、Planable、Frame.io：学习运营台、内容审批和视频审核。
- HubSpot、Salesforce、OKKI、询盘云、11x：学习线索到成交的结果表达、动作建议和归因。
- Brandwatch、Talkwalker、Sprinklr：学习大客户舆情与治理；在灵枢没有规模化客户需求前成本过重。

## 14. 采购时统一比较的 8 个指标

不要只比较官网单价。每个供应商都应按同一份表记录：

1. 首轮可用率：无需人工重做即可进入审核的比例。
2. 单个“合格结果”成本，而不是单次调用成本。
3. P50/P95 时延、并发和限流。
4. 失败是否计费、退款和重试规则。
5. 中国内地/海外地区可用性和数据驻留。
6. 输入数据是否用于训练、保留周期和删除能力。
7. 商用权、人物/声音授权、水印和平台发布限制。
8. API 稳定性、版本弃用周期、日志和账单粒度。

这样可以避免“模型单价很低，但要重做三次才可用”的假性低成本，也能防止能力供应商变化反过来绑架灵枢的产品路线。
