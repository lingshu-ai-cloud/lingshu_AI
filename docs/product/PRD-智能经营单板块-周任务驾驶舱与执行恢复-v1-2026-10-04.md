# 智能经营单板块 PRD：采集、计划、周任务驾驶舱与执行恢复 v1.3

> 版本：v1.3
> 日期：2026-10-06
> 状态：持续优化；已确认采集与计划后端优先，后端验收后再调整前端交互
> 产品范围：智能经营单个板块
> 覆盖链路：采集范围 → 对标账号与爆款视频入池 → 账号对标打法 → 周计划生成与确认 → 内容分配 → 制作执行 → 异常恢复 → 周复盘

## 1. 文档结论

智能经营需要从“展示若干计划和 Agent 状态”升级为一套用户可以直接管理本周经营结果的执行驾驶舱。用户进入页面后，应在一屏内回答以下问题：

1. 本周计划产出多少内容，包含哪些形式和时长。
2. 内容如何分配到账号、平台、预算和发布时间。
3. 每条内容参考了哪个账号和哪条视频，选择依据是什么。
4. 每条内容预计花多少钱，实际已经花多少钱。
5. 每条内容当前做到哪里，什么时候开始，预计什么时候完成。
6. 当前允许并行多少任务，为什么某条任务仍在排队。
7. 每个 Agent 当前负责什么，任务之间如何交接。
8. 发生卡点后系统会自动恢复还是需要用户处理。
9. 任务失败后可以从哪个节点重试，会保留什么，预计增加多少费用。

产品不使用缺少依据的“爆款成功率”。在积累足够真实样本前，页面展示可解释的生产把握、发布把握和经营表现把握，并明确数据充分度。

### 1.1 2026-10-05 已确认补充决定

- 智能经营增加全局开关；关闭只影响新计划，不取消运行中任务和历史。
- 周任务改为两步：先生成不调用编导/内容模型的免费总纲，再由用户明确启动 Agent 详细预分析。
- 每条内容固定展示“爆款视频预览”和“素材组合预览”，两个预览都能下钻到真实业务页面。
- 缺必须素材、待拍未回填、授权未知或预算超限时，任务不能开始。
- 只有智能经营采用“左侧全部账号与四个平台账号，右侧独立任务卡”的布局；不提供快捷视图，其他模块不增加账号栏。
- 保留经营总览、账号矩阵、内容队列、数据复盘四个现有 Tab。
- 不新增独立数字员工板块；节点、来源、结果和下一步直接进入现有“我的 4 个 Agent 现在在做什么”。
- 内容制作默认保留“我的创作”，保留清晰的“进入制作”入口。

### 1.2 2026-10-06 采集阶段补充决定

- 智能经营的业务起点改为采集：先取得对标账号和爆款视频，并写入灵感大屏，再生成周任务总纲和详细计划。
- 采集范围采用两种互斥主模式：围绕一个行业覆盖不同语言／地区，或围绕一个语言国家覆盖该市场的相关行业场景。单次采集不能同时放宽两个维度。
- 中词场景簇成为日常采集主体，重点覆盖真实用户痛点、产品卖点、采购顾虑和证明方式；大词只负责低频发现，小词只负责任务级证据补充。
- TikTok 成为主要采集阵地；YouTube 取消全量宽泛采集，只保留低额度、定向的账号与视频补充。
- 灵感大屏的服务端结果必须明确分为“爆款视频”“对标账号”“我的素材”三类，并支持各自独立筛选、统计和引用。
- 采集无需用户逐次确认，但只能在已确认的经营市场、行业、语言和采集预算内运行；越界或超预算必须阻断。
- 本轮实施顺序固定为：先扩展现有服务端发现范围、采集运行、分类与入池接口，再调整灵感大屏和智能经营前端；不另建与现有发现链路平行的系统。

### 1.3 2026-10-06 计划制定与确认补充决定

- 账号矩阵继续决定“经营哪些平台、每个平台有哪些自有账号、每个账号承担什么角色”，但不能再直接等同于内容计划。
- 每个起号期自有账号必须绑定一个主对标账号版本，并从其更新节奏、内容方向、系列栏目和视听风格生成可执行的账号打法；周任务再从该打法选择具体对标视频。
- “高度模仿”指高一致度复用更新频次、栏目比例、内容结构、镜头语法、节奏和证明顺序，不复制对方原片、台词、人物、商标、音乐或未经证实的产品事实。
- 经营 Agent 先用确定性规则生成免费计划总纲：目标、总条数、平台、自有账号、主对标账号、发布节奏、预算上限和建议待拍素材；该步骤不消耗生成式 Agent token。
- 用户确认总纲和详细预分析预算后，经营 Agent 才向编导 Agent 发出逐槽位分析任务；经营 Agent 合并编导结论后生成逐条主题、具体参考视频、素材组合、制作路线、成本和截止时间。详细计划完成后再进行一次整周确认，由经营 Agent 向内容 Agent 正式派单并启动生产。
- 建议用户拍摄的专属产品素材默认是“增强项”，不是当周制作硬门槛；每条待拍任务必须同时准备可执行的已有素材／AIGC 兜底路线。
- Agent 的任务级排期、依赖、计划开始时间、计划完成时间、成本预留和发布截止时间由后台维护；前端不展示内部排程表，只展示用户需要理解的完成时间、发布窗口和卡点。
- 所有内容默认使用最高可用质量档 `premium`。预算不足时优先减少产量或请求增加预算，不允许静默降为低质量路线；“能用尽用”不等于对同一步骤重复调用多个供应商。

### 1.4 2026-10-06 Agent 计划权补充决定

- 经营 Agent 是唯一计划责任人和派单者。它首先确定哪天生产／发布几条、发到哪个平台的哪个自有账号，以及数量、预算和截止时间。
- 经营 Agent 向编导 Agent 发出分析任务；编导 Agent 只返回主对标账号、具体视频、内容结构、选题建议和可迁移边界，不创建正式内容排期，也不直接指挥内容 Agent。
- 经营 Agent 将编导分析结论写入自己的详细内容选题排期，形成新的权威计划版本，再向内容 Agent 下发执行任务。
- 内容 Agent 读取的是经营 Agent 下发的内容项和排期，同时引用编导分析作为制作依据；不能把编导建议直接当作已授权任务。
- 编导结论变化时，必须先回到经营 Agent 重新计算数量、账号、日期、预算和依赖，再产生计划新版本；不得直接修改内容 Agent 正在执行的任务。

## 2. 背景与现状

当前系统已经具备周计划、账号矩阵、逐条内容计划、制作项目、供应商费用回执、正式任务队列、分级重试和数字员工任务状态，但用户体验仍存在断层：

- 周计划可以先于稳定采集证据出现，导致对标账号和爆款视频更像事后补充，而不是计划输入。
- 现有采集仍容易扩大到宽泛 YouTube 结果；TikTok 主阵地、中词主供给和采集范围版本尚未形成统一后端约束。
- 对标账号缺少稳定的 B2B／B2C／不确定分类和排除状态，消费品牌卖货账号容易混入 B2B 企业的参考池。
- 灵感大屏中的爆款视频、对标账号和我的素材还不是三个可独立查询、统计和引用的权威集合。
- 周计划总量、内容队列总量和手动单项任务混在不同页面，口径不易理解。
- 对标账号和参考标题可见，但不能直接核对原视频、账号、播放数据和匹配依据。
- 逐条预计成本可能为空，实际成本只在供应商对账后出现，缺少费用构成说明。
- “匹配度”容易被误解为成功率，但它只表示计划与参考内容的相关程度。
- 内容队列显示阶段进度，但详细制作现场的下钻入口没有形成稳定闭环。
- 后端已有客户、账号和任务类型并发限制，普通用户看不到已用槽位、排队原因和预计开始时间。
- 后端可区分网络异常、余额不足、内容拒绝、输入缺失、系统故障和供应商待对账，前端仍主要显示一行失败原因。
- 后端支持重试、跳过、人工完成和重新规划，但智能经营新界面缺少统一恢复入口。
- 全局消息中心主要提醒范围、计划和授权变化，任务受阻、重试耗尽和等待验收没有完整覆盖。

## 3. 产品目标

### 3.1 用户目标

- 用户不需要逐次配置采集任务，系统能在已确认范围内先完成采集，并说明当期聚焦的行业或语言国家。
- 用户进入周计划前看到的对标账号、爆款视频和素材均来自可核对记录，而不是计划生成时临时拼接的文字。
- 进入智能经营后 10 秒内理解本周产量、分配、预算和整体风险。
- 在单条内容卡片上直接看到对标依据、成本、进度、卡点和下一步。
- 不进入管理后台也能理解当前并发能力和排队原因。
- 异常发生后明确知道“系统正在恢复”还是“需要我处理”。
- 失败恢复时优先复用已通过产物，避免用户担心全部重做和重复花费。

### 3.2 业务目标

- 提高有效对标账号比例、TikTok 有效视频入池率和中词结果采用率。
- 降低 D2C 卖货账号混入 B2B 对标池、宽泛 YouTube 结果占用预算和无证据计划的比例。
- 降低周计划确认后的重复询问和误操作。
- 降低重复提交、整条重做和无效模型调用成本。
- 缩短任务从受阻到恢复的时间。
- 提升周计划内容完成率、验收率和真实发布率。
- 为后续账号预算优化和下一轮计划提供统一、可追溯的数据基础。

### 3.3 技术目标

- 采集范围、查询单元、运行游标、结果分类和周计划引用均由服务端持久化并版本化。
- 周计划生成必须经过服务端 `CollectionReadiness`，不能由前端或模型自行判断采集是否足够。
- 周计划、手动内容任务、制作项目、供应商回执和正式执行队列使用同一份前端投影。
- 页面只显示服务端持久化状态，不以浏览器内存推断权威任务状态。
- 并发、重试、阻塞和供应商对账状态均可被普通用户理解。
- 所有重试操作具备幂等键，并明确失效的下游产物范围。

## 4. 非目标

- 本期不承诺内容一定爆款或一定获得询盘。
- 不把参考视频匹配度包装成经营成功概率。
- 不向普通用户暴露模型密钥、供应商请求体、内部 Worker ID 或错误堆栈。
- 不允许通过“人工完成”伪造真实平台发布、客户发送或供应商结算。
- 不因为发布账号未连接而阻止内容制作；账号问题仅阻塞真实发布。
- 不自动扩大预算、账号范围、市场范围或真实发布授权。

## 5. 核心对象与口径

| 对象 | 定义 | 计数口径 |
| --- | --- | --- |
| 采集范围版本 | 当期行业／市场模式、平台比例、语言、词簇和预算的不可变快照 | 每次范围或策略变化创建新版本 |
| 对标账号 | 通过范围校验、可供编导持续观察的平台账号 | 同一平台账号只计 1 个，保留候选、通过和排除状态 |
| 爆款视频 | 带真实来源、指标时间和账号关系的可引用视频 | 同一平台视频只计 1 条，不因多个词命中重复计数 |
| 我的素材 | 企业权威素材库的可检索索引 | 不复制素材文件；按稳定素材 ID 与版本引用 |
| 主对标账号策略 | 一个自有账号在当前阶段主要学习的账号打法 | 一个自有账号每个有效打法版本只能有 1 个主对标账号 |
| 经营排期骨架 | 经营 Agent 确定的日期、数量、平台、自有账号、预算和发布截止槽位 | 每个周计划版本有 1 份权威骨架；编导 Agent 不得修改 |
| 编导计划分析 | 编导 Agent 针对某个排期槽位返回的对标证据、选题与结构建议 | 每次分析版本化；只是决策输入，不计为内容任务 |
| 经营派单记录 | 经营 Agent 基于已确认计划向内容 Agent 发布的执行授权 | 每个内容执行任务必须且只能对应 1 条有效派单记录 |
| 周计划内容 | 当前周计划版本冻结的内容订单 | 一条内容订单计 1 条，不包含手动单项任务 |
| 周内容项 | 一条需要被生产的母内容，绑定账号打法和具体参考视频 | 可产生多个平台版本和发布任务，但母内容只计 1 条 |
| 建议待拍任务 | 能提升产品真实性但拥有可执行兜底路线的拍摄建议 | 默认不阻塞；用户选择强制实拍后才阻塞对应内容项 |
| Agent 内部排期 | 权威执行任务的责任、依赖、计划时间和成本安排 | 不作为用户任务数量；每次重排产生新版本 |
| 手动单项任务 | 用户在内容制作中单独创建的任务 | 单独标记来源，可进入统一队列，但不计入周计划产量 |
| 平台版本 | 同一创意针对不同平台、语言或账号生成的版本 | 每个需要单独制作或发布的版本计 1 个版本 |
| 发布任务 | 一个版本发布到一个账号的一次动作 | 一个账号一次发布计 1 次 |
| 预计成本 | 计划确认时按制作路线、语言、镜头和模型估算的金额 | 不等于实际结算，不包含未明确分配的投放费 |
| 实际成本 | 已取得供应商结算回执并完成对账的金额 | 未对账不得标记为实际成本 |
| 生产把握 | 由素材完整度、模型可用性、预算、历史技术通过率决定 | 只说明能否顺利产出，不代表经营效果 |
| 发布把握 | 由账号连接、权限、授权和平台预检决定 | 只说明能否完成发布 |
| 经营表现把握 | 由对标证据、账号历史、内容形式和同类结果决定 | 样本不足时必须显示“数据不足” |

## 6. 采集阶段：对标账号、爆款视频与素材供给

### 6.1 产品定位与前后依赖

采集不是周计划里的一个可选动作，而是智能经营开始运行后的第一段正式流程：

`已确认企业事实与经营范围 → 采集范围版本 → 采集任务 → 分类与去重 → 灵感大屏 → 周任务总纲 → Agent 详细预分析`

后端必须先形成可追溯的采集结果，周任务才能引用对标账号、爆款视频和可用素材。原始采集记录未完成分类、来源失效或不符合经营范围时，不能被计划当作真实依据。

### 6.2 两种采集范围模式

| 模式 | 固定维度 | 扩展维度 | 适用情况 |
| --- | --- | --- | --- |
| 行业矩阵 `industry_matrix` | 一个明确行业或产品大类 | 多语言、多国家／地区 | 企业面向多个海外市场，希望寻找同一行业在不同市场的内容表达 |
| 市场聚焦 `market_focus` | 一个语言国家或明确市场 | 该市场内与企业产品相关的场景、买家和内容形式 | 企业先集中验证一个国家市场或一个语言区 |

规则：

- 编导 Agent 根据已确认的企业事实、经营目标和账号定位给出当期采集模式建议，由经营 Agent 在授权范围内选择并写入策略版本，不要求用户逐次确认。
- 每个周期只能有一个主模式；需要切换时为现有 `SocialCrawlStrategy` 与 `SocialMarketKeywordSet` 创建新版本，不能覆盖上一周期的范围和结果。
- 行业、产品、市场、语言均来自已确认事实版本；模型推测只能作为候选，不能直接扩大采集边界。
- 每次运行记录选择理由、引用的事实版本、预算上限和计划版本，便于后续复盘采集是否有效。
- 现有范围审批字段继续保留，但审批依据改为经营开关与已确认授权：范围没有越界时由经营 Agent 写入 `approvedBy: business_agent` 和授权引用，不再要求用户每周重复确认。
- 用户手动扩大国家、语言、平台、预算或产品范围时，才通过统一决策卡产生新的用户授权版本。

### 6.3 大词、中词和小词的新分工

| 层级 | 新定位 | 默认资源占比 | 运行方式 |
| --- | --- | --- | --- |
| 大词／发现词 | 冷启动和周期性发现新关系 | 10%–15% | 低频、限量运行；不直接决定周计划 |
| 中词／场景簇 | 用户痛点、产品卖点、采购顾虑、应用场景和证明方式的组合 | 70%–80% | 日常主要供给，持续根据采用率和有效率调整 |
| 小词／证据词 | 为具体选题、镜头动作或产品证明补证 | 10%–15% | 由编导任务按需触发，不做长期全量采集 |

资源占比是默认策略，不是写死常量。后台可根据有效入池率、被周计划采用率、重复率和单位有效结果成本调整，但必须保存调整原因和策略版本。

中词不是单纯的产品名或营销词。每个中词场景簇至少要包含“真实问题／顾虑”与“产品卖点／证明方式”之一，并保留其来自企业资料、客户原话或公开内容的依据。

### 6.4 平台优先级

- TikTok 默认获得不低于 70% 的采集任务与结果额度，是发现短视频表达、账号打法和起量内容的主阵地；没有其他已验证来源时，剩余额度继续归 TikTok。
- YouTube 默认不高于 10%，禁止继续进行全平台宽泛抓取；只用于指定账号、明确中词、长视频证据或 TikTok 结果不足时的定向补充。
- Instagram 与 Facebook 合计最多保留 20% 的定向实验额度；没有稳定采集能力或有效率不足时可以为 0，不能为了凑平台比例运行无效任务。
- 平台比例可以按企业经营市场配置，但调整必须产生新策略版本，不能在运行中静默改变。
- 平台返回字段不同，后端必须保存原始指标及采集时间；不能把不同平台指标换算成伪造的统一播放表现。
- TikTok 采集失败时不能无条件扩大 YouTube 范围作为兜底；系统应先报告缺口，再按授权策略决定是否补充。

### 6.5 灵感大屏三类结果

服务端对外提供三类独立集合，同时保留统一的来源和引用关系：

| 分类 | 核心对象 | 必备信息 | 可被谁引用 |
| --- | --- | --- | --- |
| 爆款视频 | 平台视频记录 + `SocialCandidateEvidence` 查询投影 | 平台视频 ID、账号、链接、封面、真实指标、采集时间、语言／地区、内容标签、分析状态 | 编导分析、周计划、内容任务 |
| 对标账号 | `competitor_accounts` + `SocialAccountTrackingDecision` 查询投影 | 平台账号 ID、主页、账号类型、行业、主要市场／语言、内容特征、候选／通过／排除状态 | 账号矩阵、采集范围、周计划依据 |
| 我的素材 | 企业素材记录 + `OwnedMaterialIndex` 查询投影 | 企业素材 ID、媒体类型、产品／场景标签、权利状态、可用性、更新时间 | 素材组合预览、内容制作、待拍补齐 |

三类对象不能只靠前端标签临时区分。后端接口必须支持按 `itemType`、平台、行业、市场、语言、账号类型、产品、权利状态和分析状态筛选。

同一视频可以属于一个对标账号，但不能因此重复计数；同一企业素材可以被多条任务引用，但每次引用都要保存素材版本和权利状态快照。

### 6.6 后端权威对象

| 对象 | 作用 | 关键约束 |
| --- | --- | --- |
| `SocialCrawlStrategy` + `SocialMarketKeywordSet` | 复用现有发现范围，新增主模式、企业事实版本和平台额度约束 | 不可原地覆盖；继续持久化到现有 `social_discovery_scopes` |
| `SocialInspirationCollectionRun` | 复用现有采集运行，补齐幂等键、分页检查点、尝试次数和费用检查点 | 继续写入 `social_discovery_runs`，不再新增平行运行表 |
| `SocialDiscoverySeed`、`SocialSceneCluster`、`SocialContentSearchUnit` | 分别承载大词、中词和小词，并编译成实际平台查询单元 | 保留父级场景簇、来源证据与策略版本 |
| `SocialAccountTrackingDecision` | 复用现有账号候选、试跑、跟踪、观察和停止状态 | 补充经营类型、排除原因和采集证据；不另建第二套账号决策真相 |
| 平台视频记录 + `SocialCandidateEvidence` | 复用现有视频记录和候选证据，形成爆款视频查询投影 | 平台视频唯一去重；指标带采集时间，不伪造缺失字段 |
| 企业素材记录 + `OwnedMaterialIndex` 投影 | 从现有素材权威记录构建“我的素材”查询索引 | 只保存索引与稳定引用，不复制素材文件或权利真相 |
| `CollectionReadiness` | 新增只读服务端投影，判断免费总纲与付费预分析能否开始 | 由上述权威对象计算，不由浏览器保存或回传结论 |

周计划只保存这些对象的稳定引用和版本，不复制账号介绍、播放量或素材权利状态作为另一份事实。

### 6.7 任务状态与恢复

采集任务统一状态：

1. `scheduled`：已按经营周期排期。
2. `collecting`：平台采集中。
3. `classifying`：去重、分类和范围校验中。
4. `ready`：结果已进入灵感大屏，可供周计划引用。
5. `partial`：部分结果可用，但仍有平台、词簇或分页失败。
6. `blocked`：授权、预算、限流或范围问题等待处理。
7. `failed`：分级重试耗尽。
8. `cancelled`：用户或系统取消后停止后续分页。

后端要求：

- 分页游标、已采集平台对象 ID、分类结果和费用必须逐批保存，进程中断后从最近游标继续。
- 同一平台对象使用稳定唯一键去重；重试不得重复写入、重复下载或重复付费分析。
- 网络超时和平台限流采用延迟重试；账号授权失败、预算不足和范围非法立即阻断。
- `partial` 结果可以进入灵感大屏，但周计划必须知道证据覆盖不完整，不能展示为“采集完成”。
- 采集不逐次弹出确认；只有即将越过已确认平台、市场或预算边界时才需要决策卡。

### 6.8 周计划准入

经营 Agent 请求编导 Agent 开始周计划分析前，服务端必须先生成 `CollectionReadiness`：

- 当期采集范围版本有效。
- 至少存在达到配置阈值的可用对标账号和爆款视频。
- 主要中词场景簇具有有效结果，且重复率、失效率未超过阈值。
- 对标视频能够回溯到平台、账号、采集时间和原链接。
- 我的素材能够返回权利状态和可用性；缺素材时生成明确缺口，而不是假定可以制作。

默认冷启动建议阈值为：3 个通过范围校验的对标账号、12 条不同视频、至少覆盖 3 个中词场景簇。阈值可以按行业调整，但必须版本化。未达到阈值时，系统输出“采集缺口”，允许生成免费任务总纲草案，但不能启动付费详细预分析。

### 6.9 后端阶段验收

1. 创建经营周期后，系统能复用现有发现对象自动生成唯一的新范围版本，并说明采用哪种范围模式。
2. 新采集运行中，TikTok 默认任务额度不低于 70%，YouTube 不高于 10%，且 YouTube 不产生宽泛全量任务。
3. 中词场景簇占主要查询额度；大词和小词均不能反向挤占日常供给。
4. 采集进程中断后从已保存游标继续，同一视频和账号不重复入库。
5. 爆款视频、对标账号和我的素材可分别查询、统计，并能从周计划引用回原记录。
6. 不符合经营范围或分类尚未完成的结果不能成为正式周计划依据。
7. 未达到采集准入阈值时，系统返回具体缺口，不静默生成虚假的对标依据。
8. 每次范围、额度和词簇调整都能追溯到策略版本与调整原因。

## 7. 计划制定阶段：从账号矩阵到逐条内容

### 7.1 计划输入与职责边界

计划链路的唯一指挥关系是：

`经营 Agent 生成数量／账号／日期骨架 → 编导 Agent 分析对标账号与视频 → 经营 Agent 合并分析并形成详细选题排期 → 内容 Agent 按经营排期执行`

其中：

- 经营 Agent 拥有计划权：决定哪天几条、哪个平台、哪个自有账号、预算、优先级、完成截止时间和发布窗口。
- 编导 Agent 拥有分析权：判断主对标打法、具体参考视频、可迁移结构、选题建议、镜头意图和风险，但没有派单权。
- 内容 Agent 拥有制作执行权：读取经营 Agent 已冻结的任务排期，并把编导结论作为制作依据，不接受编导 Agent 的直接任务命令。

计划制定必须同时读取五类权威输入：

1. 经营目标与预算：本周希望获得的业务结果、计划产量和生产预算。
2. 自有账号矩阵：平台、账号定位、目标受众、产品职责、语言和发布能力。
3. 主对标账号快照：账号定位、更新节奏、系列栏目、风格指纹和相对表现基线。
4. 爆款视频与分析：具体内容方向、钩子、证明方式、镜头节奏和可迁移边界。
5. 素材与生产能力：企业自有素材、授权素材、待拍可能性、AIGC 能力和容量。

账号矩阵只负责回答“在哪些平台、用哪些自有账号经营”；主对标账号打法回答“每个账号应该长期像谁、按什么节奏和方向更新”；逐条内容计划回答“本周具体做什么、参考哪条视频、用什么素材和路线完成”。三层对象必须分别版本化，不能继续把账号数量直接投影成没有内容依据的周任务。

服务端分别保存三个阶段产物：

1. `OperatingScheduleSkeleton`：经营 Agent 生成的数量、账号、日期、预算和发布截止骨架。
2. `DirectorPlanningAnalysis`：编导 Agent 针对骨架槽位给出的证据化分析建议，不具备执行授权。
3. `WeeklyOperatingPackage`：经营 Agent 合并分析后生成的唯一权威详细选题排期，也是内容 Agent 的唯一任务来源。

### 7.2 单一主对标账号策略

每个处于起号期或账号修复期的自有账号，必须绑定一个 `SocialBenchmarkAccountSnapshot` 作为主对标账号，并保存到该自有账号的 `AccountPlaybook` 新版本中。

选择主对标账号必须满足：

- 与自有账号的平台、目标市场、语言、受众和商业模式相符。
- 至少有足够的近期内容形成稳定更新节奏、栏目结构和风格指纹。
- 至少存在多条已经完成内容级分析的代表视频，不能只因单条高播放视频晋级。
- 其内容形式能够由当前素材、拍摄条件和 AIGC 能力实现。
- 账号身份、原视频和内容分析均有稳定版本引用。

起号期默认把 80%–90% 的内容额度分配给主对标打法，10%–20% 留给单变量实验。实验位只能改变一个因素，例如钩子、时长或证明方式，不能同时混入多个账号的风格。若用户明确要求纯跟随期，可将主对标占比提高到 100%，但仍必须遵守事实、版权、人物和品牌替换边界。

一个自有账号同一计划版本只能有一个主对标账号。其他账号只能作为辅助证据来源，不能在同一条内容中无解释地拼接多个账号的风格。

### 7.3 账号模仿打法

在现有 `AccountPlaybook` 中新增版本化的 `benchmarkStrategy`，至少冻结以下内容：

| 维度 | 计划需要保存的内容 |
| --- | --- |
| 主对标 | `primaryBenchmarkAccountSnapshotRef`、选择原因、适用周期和数据时间 |
| 更新节奏 | 每周发布数、工作日分布、连续更新与系列间隔 |
| 内容方向 | 栏目／主题支柱及其占比，哪些属于固定方向，哪些属于实验方向 |
| 内容形式 | 口播、产品展示、工厂过程、测试、对比、案例等系列格式 |
| 视频规格 | 主要时长区间、镜头数量区间、前三秒类型、字幕密度和 CTA 位置 |
| 视听风格 | 构图、场景、运镜、节奏、旁白方式、音乐使用和封面规则 |
| 证明顺序 | 痛点、产品、过程、证据、信任和转化信息的出现顺序 |
| 转化方式 | 评论、私信、主页链接、表单或 WhatsApp 等已验证承接入口 |
| 模仿边界 | 可复用的结构、必须替换的事实／素材／身份，以及禁止复制的元素 |
| 实验比例 | 主对标内容占比、实验内容占比和本周唯一实验变量 |

该打法必须来自 `SocialBenchmarkAccountSnapshot` 和多条 `SocialReferenceContentAnalysis`，不能由模型仅凭账号简介生成。数据不足时账号打法状态为 `blocked`，返回缺少的内容样本或分析层级。

### 7.4 逐条内容计划

继续以现有 `WeeklyOperatingPackage` 作为唯一权威周计划，不新增另一套周计划表。在 `SocialWeeklyContentPackage` 中补充版本化 `contentItems`；现有 `publicationTasks` 继续负责“哪个版本发到哪个账号”，并通过 `motherContentId` 指向内容项。

每个内容项至少包含：

- 内容项 ID、经营目标引用、计划版本和来源账号打法版本。
- `issuedBy: business_agent`、经营排期骨架引用和编导分析版本引用；编导分析只能作为依据，不能成为任务签发者。
- 自有平台、账号、语言、发布时间窗和发布前截止时间。
- 主对标账号快照、一个主参考视频分析、最多两个辅助参考视频分析。
- 内容栏目、主题、钩子、证明方式、CTA、预计时长和版本数量。
- 需要保持一致的账号级特征，以及本条视频允许变化的唯一实验变量。
- 企业事实引用、产品引用和禁止出现的未经确认声明。
- 素材组合计划、建议待拍任务、现有素材／AIGC 兜底路线。
- `qualityTier: premium`、预计成本、成本上限和预算预留引用。
- 编导分析、内容生产、质检、审批和发布任务引用，以及经营 Agent 对各节点的最终派单记录。

单条内容必须具备完整的 `SocialReplicationReferenceChain`：主对标账号快照 → 具体参考内容分析 → 视频精确分析／时间点 → 自有账号打法。链路不完整时不能进入详细制作计划。

### 7.5 计划分配顺序

经营 Agent 按以下顺序形成计划，不能先生成标题再补账号和参考：

1. 从经营目标、预算和生产容量得出本周可承诺的最高质量产量。
2. 按账号矩阵确定平台、自有账号和每个账号的内容数量。
3. 按日期和发布窗口创建 `OperatingScheduleSkeleton`，明确“哪天、几条、哪个平台、哪个自有账号”，但暂不生成具体选题。
4. 为每个自有账号锁定当前 `AccountPlaybook` 和主对标账号快照，并由经营 Agent 为每个内容槽位创建编导分析任务。
5. 编导 Agent 从已入池视频中分析适合该槽位的主参考视频、选题方向、钩子、证明结构、可迁移因素和制作风险；无合格参考时只返回采集缺口，不直接创建内容任务。
6. 经营 Agent 汇总 `DirectorPlanningAnalysis`，按照数量、账号、日期、预算和发布截止重新校验，决定每个槽位最终采用哪个选题和参考视频。
7. 经营 Agent 将企业产品、事实和素材能力映射到编导结论，生成详细内容项、素材缺口、待拍建议、AIGC 路线、预计成本和后台排期。
8. 经营 Agent 校验账号发布能力、预算、事实、素材兜底和截止时间后，签发新的 `WeeklyOperatingPackage` 版本，并向内容 Agent 创建执行任务。

编导 Agent 可以建议“本周应该多做某一类内容”，但不能自行增加任务数量、改变账号或修改日期。经营 Agent 可以采用、调整或拒绝建议，并必须在计划版本中记录处理结果和原因。

计划不能因为对标账号每周发布 20 条，就在企业容量只支持 6 条时虚构 20 条任务。系统模仿对方的比例、节奏结构和栏目顺序，再按自己的产能等比例映射。

### 7.6 高度模仿的边界

允许高一致度复用：

- 发布频率和栏目占比。
- 视频时长区间、镜头数量、前三秒钩子类型和信息出现顺序。
- 系列化结构、证明方式、字幕密度、节奏、CTA 位置和画面功能。
- 已被分析为可迁移的内容机制。

必须替换或重新制作：

- 原视频文件、逐字台词、音乐、人物身份、声音、商标、包装和店铺元素。
- 对方的产品事实、客户案例、价格、认证和效果声明。
- 没有授权的素材，以及内容分析标记为不可迁移的元素。

计划中的“模仿一致度”只衡量是否遵循已冻结打法，不代表播放量或经营成功概率。

### 7.7 计划后端验收

1. 每个起号期自有账号都有且只有一个主对标账号快照引用，其他参考被明确标记为辅助。
2. 账号打法能够从多条真实内容计算更新节奏、栏目比例和风格规则，数据不足时失败关闭。
3. 免费总纲先产生经营排期骨架；编导分析必须绑定骨架槽位，且只能写入分析结果，不能创建、签发或修改内容执行任务。
4. 权威周任务包由经营 Agent 合并编导结论后生成，同时包含内容项和发布任务，每条发布任务都能回溯到内容项、账号打法和对标证据。
5. 每个内容执行任务必须存在 `issuedBy: business_agent` 和有效派单记录，并引用其学习的编导分析版本；直接由编导产生的执行任务必须被拒绝。
6. 每个内容项只有一个主参考视频，不能把多个账号的风格无依据混合。
7. 自有账号产能低于对标账号频次时，系统按比例映射，不超量创建任务。
8. 参考链路、事实引用、素材兜底、成本上限或发布时间缺失时，详细计划不能激活。
9. 修改主对标账号、内容数量、预算、发布账号或已采用的编导结论会创建新的周任务包版本，并明确失效的下游任务。

## 8. 计划呈现、用户确认与后台排期

### 8.1 两步生成

计划继续采用两步，但重新明确每一步的职责：

**第一步：免费计划总纲**

- 由经营 Agent 角色通过确定性规划服务生成，不调用生成式模型。
- 输出本周目标、总内容数、总时长、平台与自有账号分配、每个账号的主对标账号、更新节奏、主要内容形式、预算上限和建议待拍数量。
- 允许显示栏目级方向，不生成逐条脚本、分镜、精确视频分析或供应商任务。
- 用户第一次确认的是经营边界和详细预分析预算上限，不是正式生产授权，也不是每个内部 Agent 节点。

**第二步：经营 Agent 详细计划**

- 用户确认总纲后，经营 Agent 依据排期骨架为每个内容槽位发出编导分析任务。
- 编导 Agent 返回具体参考视频、内容主题、钩子、证明方式、分镜意图和风险，但不生成内容 Agent 的执行任务。
- 经营 Agent 对编导结论进行采用、调整或拒绝，再与素材、授权、技术能力、Premium 路线和容量校验结果合并，形成唯一详细内容选题排期。
- 详细计划完成后生成待确认的不可变版本；用户第二次按整周确认后，经营 Agent 才向内容 Agent 签发执行任务。内容 Agent 学习已引用的编导分析，在经营排期限定内完成素材组合、口播、镜头、合成和质检，不得自行改变内容数量、账号、主题或发布时间。
- 未通过素材兜底、预算、事实或发布窗口校验的内容保持阻塞，不能进入付费制作。

### 8.2 待拍任务与素材回填

系统在详细计划前检查“我的素材”，把只有企业自己能提供、无法可靠用开源或通用素材替代的画面生成待拍建议，例如真实产品外观、包装、接口、生产过程、质量检测和企业人物。

每个待拍任务必须包含：

- 对应内容项、产品、镜头功能、拍摄说明、时长、比例和最晚回填时间。
- 为什么建议实拍，以及实拍后能提升哪一项证据或可信度。
- 当前已有素材／AIGC 兜底路线、兜底预计成本和质量差异。
- `blocking: false` 的默认状态；只有用户主动选择“本条必须使用我的实拍”后才成为阻塞项。
- 上传后的素材 ID、权利状态、质检结果和被哪个内容计划版本采用。

计划激活时已有素材和 AIGC 路线必须足够支持本周全部内容。用户在 `materialFreezeAt` 前回填合格素材时，系统为内容执行计划创建新版本并优先替换兜底素材；超过冻结时间后不打断已经付费制作的任务，素材进入下一条兼容内容或下一周计划。

### 8.3 后台 Agent 排期

复用现有 `WeeklyExecutionTask` 作为真实执行单元，并为每个任务增加内部排期快照；不另建一套脱离执行任务的 Agent 待办表。

每个排期项至少保存：

- 周任务包、内容项、发布任务和账号引用。
- 经营排期骨架、编导分析版本和经营派单记录；内容执行节点的 `issuedBy` 必须为 `business_agent`。
- 阶段：采集、编导、素材准备、生成、质检、审批、发布或复盘。
- 责任 Agent、依赖任务、优先级和可并行组。
- 最早开始、计划开始、计划完成、最晚完成和发布前截止时间。
- 预计耗时、预计成本、预算预留和质量档位。
- 当前状态、重排原因、实际开始／完成时间和结果引用。

经营 Agent 从发布窗口向前倒排：发布预检与审批 → 质检 → 合成 → 生成 → 素材冻结 → 编导分析。调度器同时考虑客户、账号、任务类型和供应商并发；上游延误时只重排受影响分支，并由经营 Agent 写入新排期版本。内容 Agent 或编导 Agent 发现无法按计划执行时，只上报阻塞与可选方案，不直接篡改已冻结排期。

前端必须展示用户可理解的完整步骤、责任 Agent、预计耗时、预计起止时间、实际起止时间和卡点；Worker ID、租约、内部并行组和模型调用顺序仍保持为后台可观测数据。首版默认时间如下，后续可用企业真实执行分位数校准，不允许前端模拟平滑增长：

| 顺序 | 执行步骤 | 责任人 | 默认预计耗时 | 用户可见结果 |
| --- | --- | --- | --- | --- |
| 1 | 生成任务总纲 | 经营 Agent | 15 分钟 | 目标、数量、账号、日期、预算；`tokenCost: 0` |
| 2 | 采集对标账号与视频 | 经营 Agent 编排采集工具 | 每账号 60 分钟 | 采集运行、真实来源和入池数 |
| 3 | 服务端评分与筛选 | 编导 Agent | 每内容槽位 20 分钟 | B2B／DTC 分类、分数、通过／复核／拒绝 |
| 4 | 编导拆解对标结论 | 编导 Agent | 每内容槽位 45 分钟 | 对标账号、视频、结构、风格和迁移边界 |
| 5 | 合并详细内容排期 | 经营 Agent | 每内容槽位 15 分钟 | 爆款视频预览、素材组合预览、账号与发布窗口 |
| 6 | 核对素材与授权 | 内容 Agent | 每条 20 分钟 | 现有素材、待拍建议、授权和 Premium AIGC 兜底 |
| 7 | 生成口播与脚本 | 内容 Agent | 每条 30 分钟 | 可核对脚本与事实引用 |
| 8 | 生成逐镜分镜 | 内容 Agent | 每条 35 分钟 | 逐镜目标、画面、口播、时长和验收标准 |
| 9 | 匹配或生成素材 | 内容 Agent | 每条 45 分钟 | 逐镜素材、来源和权利状态 |
| 10 | 合成、配音与渲染 | 内容 Agent | 每条 90 分钟 | 成片、字幕、配音和供应商回执 |
| 11 | 事实、画面、音频与版权质检 | 质检 Agent | 每条 25 分钟 | 通过项、失败项和受影响镜头 |
| 12 | 按质检结果局部返工 | 内容 Agent | 预留 30 分钟 | 仅替换失败镜头，保留已通过产物 |
| 13 | 成片确认 | 用户 | 预留 10 分钟 | 统一内容审批决策卡 |
| 14 | 发布到目标账号 | 发布 Agent | 每条 10 分钟 | 平台发布回执或可恢复错误 |
| 15 | 回传表现与线索 | 经营 Agent | 每账号 60 分钟 | 播放、互动、询盘、成本和对账状态 |
| 16 | 周复盘与下轮建议 | 经营 Agent | 45 分钟 | 目标完成度、止损／加码建议和下轮计划输入 |

### 8.4 最高档 AIGC 策略

所有新内容项默认保存 `qualityTier: premium`，路线选择遵循：

- 在当前能力、权利和预算允许时，优先使用最高质量的图像、视频、数字人、配音、字幕、修复、放大和质检能力。
- “能用尽用”指启用对最终质量有明确贡献的能力，不代表同一步骤同时向多个付费供应商重复提交。
- Premium 路线在计划阶段一次性计算成本上限并预留预算；真实费用仍以供应商回执对账。
- 预算不足时，经营 Agent 优先减少内容数量、减少非必要版本或请求增加预算，不能静默降为标准档。
- 最高档能力不可用时，任务进入 `blocked` 或明确的降级决策卡；只有用户授权降级后才改变质量策略。
- 已受理的付费任务继续使用原供应商任务 ID 恢复，不能因排期变化重复提交。

### 8.5 用户确认与版本冻结

用户确认页必须集中展示：

- 本周经营目标、产量、总时长和主要形式。
- 每个平台、每个自有账号的内容数量与发布时间窗。
- 每个自有账号的主对标账号、模仿栏目、更新节奏和实验比例。
- 生产预算、Premium 路线预计成本、投放预算和最大授权金额。
- 建议待拍任务数量、回填截止时间，以及“不上传仍可完成”的兜底说明。
- 本周最晚完成时间、首条预计完成时间和计划发布区间。

计划只有两个整周级确认点：

1. **生成详细计划**：确认免费总纲、详细预分析预算上限和 Agent 开始分析；不授权内容生产或真实发布。
2. **激活本周计划**：确认由经营 Agent 合并编导结论后形成的逐条内容、素材兜底、Premium 制作预算和发布边界，冻结 `WeeklyOperatingPackage` 新版本，再由经营 Agent 向内容 Agent 派单并启动生产。

两个确认点都只确认整周，不要求逐条任务重复点选。以下变化必须重新确认：增加预算、增加发布数量、更换自有账号、扩大平台／市场、改变真实发布授权或将非阻塞待拍改为强制实拍。内部 Agent 排期微调、同预算内的供应商切换和不改变内容事实的局部恢复不要求再次确认。

### 8.6 计划确认阶段验收

1. 免费总纲不调用生成式模型，但能稳定给出目标、产量、账号分配、主对标账号、节奏、预算和待拍建议数量。
2. 用户只经历“生成详细计划”和“激活本周计划”两个整周确认点，不逐条确认内部任务；激活后生成后台任务图。
3. 未上传建议素材时，本周全部内容仍有可执行兜底路线；上传后能在冻结时间前进入对应内容执行计划。
4. 编导 Agent 的输出只能进入 `DirectorPlanningAnalysis`，经营 Agent 未合并并签发前，内容 Agent 不能获得可执行任务。
5. 每个后台任务都有责任 Agent、阶段、依赖、计划完成时间、预计成本和最终发布账号／窗口；内容执行任务还必须有经营派单记录。
6. Premium 质量策略覆盖所有内容；预算不足时减少产量或阻断，不静默降档。
7. 用户看不到内部 Worker 排程，但能看到可信的预计完成时间、发布时间和延误原因。
8. 重复确认、刷新或后台恢复不会重复创建任务、重复预留预算或重复提交供应商。

## 9. 信息架构

智能经营保留四个一级视图，并强化每个视图的职责：

1. **经营总览**：本周执行驾驶舱、产量、预算、并发、异常和 Agent 实况。
2. **账号矩阵**：内容如何分配到账号、账号定位和对标来源。
3. **内容队列**：每条内容的计划依据、成本、进度、卡点和恢复动作。
4. **数据复盘**：真实账号结果、计划完成率、成本结果和下一轮建议。

周计划详情继续作为弹层存在，负责确认计划版本和启动授权；执行中的实时状态不再塞回周计划弹层。

## 10. 经营总览：周任务驾驶舱

### 10.1 周计划摘要

顶部固定显示：

- 周计划名称、周期、版本和状态。
- 经营目标、目标市场、经营指标和授权方式。
- 周计划内容数，不包含手动单项任务。
- 原创数、平台版本数和计划发布数。
- 计划总时长和主要内容形式。
- 生产预算、投放预算、预计制作成本、已结算成本和剩余预算。

若不同数据源出现数量不一致，页面必须显示“计划口径待同步”，并列出差异，不能静默选择其中一个。

### 10.2 执行状态摘要

固定展示六项：

- 排队中。
- 制作中。
- 待验收。
- 需要处理。
- 已完成。
- 已取消。

点击任一数字进入内容队列，并自动应用对应筛选。

### 10.3 并发状态

显示普通用户可理解的有效并发：

- 当前客户：已用 / 上限。
- 当前账号：已用 / 上限；无指定账号时显示“未分配账号任务”。
- 周计划任务类型：已用 / 上限。
- 当前执行 Worker：活跃槽位 / 当前 Worker 上限，仅作为系统吞吐参考。

排队项必须显示命中的第一条限制，例如：

> 当前客户并发已满（2/2），前方还有 3 条任务；有槽位后自动开始。

普通用户不能修改并发上限；管理员继续在客户管理后台设置。

### 10.4 Agent 协同

四个 Agent 卡片显示：

- 当前状态：等待、工作中、等待用户、失败、完成。
- 当前任务名称和内容对象。
- 已完成任务数 / 本轮任务总数。
- 最近更新时间。
- 下一步交接对象。

页面文案必须区分“Agent 角色状态”和“真实后台并发槽位”，不得用“4 个 Agent 运行中”暗示系统同时运行 4 个模型任务。

## 11. 账号矩阵：内容分配与对标依据

### 11.1 账号分配表

每个账号显示：

- 平台、账号名称和连接状态。
- 账号定位、目标受众和主推产品。
- 本周内容条数和占总产量比例。
- 账号预算和分配依据。
- 内容形式、语言和计划发布日期。
- 已完成、制作中、受阻数量。

### 11.2 对标账号

每个对标账号显示：

- 账号名称、头像或平台默认图标。
- 平台和账号主页链接。
- 被本周计划引用的内容数量。
- 最近一次数据更新时间。

### 11.3 逐条对标视频

每条计划内容显示：

- 参考视频缩略图、标题和原链接。
- 对标账号及账号主页链接。
- 播放量或其他真实指标及其采集时间。
- 匹配度和匹配因素。
- 精确分析状态。
- 若没有可用参考，明确显示“按产品与账号策略生成”，不伪造参考视频。

## 12. 内容队列：单条任务卡

### 12.1 卡片固定信息

每条任务卡必须显示：

- 来源：周计划或手动单项。
- 内容标题、产品、平台、账号、语言和发布时间。
- 内容形式、数量和预计时长。
- 计划版本、目标和授权方式。
- 对标账号、参考视频和计划依据。
- 预计成本、实际成本、重试预留和投放预算分配。
- 当前阶段、进度、最近更新时间和预计完成时间。
- 当前 Agent 和下一交接节点。

### 12.2 进度节点

内容制作不再合并成含糊的“素材与生成”节点，统一展示以下用户节点：

1. 核对素材与授权：内容 Agent，约 20 分钟。
2. 生成口播与脚本：内容 Agent，约 30 分钟。
3. 生成逐镜分镜：内容 Agent，约 35 分钟。
4. 匹配或生成逐镜素材：内容 Agent，约 45 分钟。
5. 生成配音与字幕：内容 Agent，约 30 分钟。
6. 生成数字人口播或人物镜头：内容 Agent，约 60 分钟。
7. 剪辑、合成与成片渲染：内容 Agent，约 90 分钟。
8. 事实、画面、音频与版权质检：质检 Agent，约 25 分钟。
9. 按质检结果局部返工：内容 Agent，最多预留 30 分钟。
10. 用户确认成片：用户，预留 10 分钟。

状态包括：待开始、排队、进行中、自动恢复、等待用户、失败、已完成、已取消。

进度百分比只能根据已完成节点计算；未知时长不能显示平滑增长的模拟百分比。

### 12.3 制作现场下钻

点击“查看制作进度”后打开当前任务的制作现场，不切换到无关的经营总览。制作现场显示：

- 当前节点和任务状态。
- 已保存的脚本、素材匹配、口播、字幕、成片和质检结果。
- 最近任务事件。
- 当前卡点和恢复动作。
- 返回智能经营时保持原筛选和滚动位置。

## 13. 成本展示

### 13.1 单条成本结构

每条内容显示：

- 计划制作成本。
- 已预留金额。
- 自动重试预留。
- 已结算实际成本。
- 投放预算，仅在已明确分配时显示。

成本状态：待核算、已估算、已预留、供应商待结算、已结算、对账异常。

### 13.2 成本交互

- 预计成本与实际成本必须使用不同标签和颜色。
- 重试前显示可能增加的费用。
- 供应商已经受理但状态未知时显示“正在对账”，不能再次扣费或重复提交。
- 页面不把周计划总预算平均分摊后冒充单条预计成本。

## 14. 成功把握

### 14.1 三类把握

每条内容分别显示：

1. **生产把握**：高、中、低或数据不足。
2. **发布把握**：高、中、低或等待预检。
3. **经营表现把握**：高、中、低或数据不足。

### 14.2 评分依据

生产把握至少考虑：

- 强制素材是否齐全。
- 模型和账号额度是否可用。
- 当前路线近期技术成功率。
- 镜头数量、语言数量和数字人依赖。
- 是否存在未解决的质量问题。

发布把握至少考虑：

- 账号连接状态和权限。
- 内容、账号和授权范围是否一致。
- 平台预检结果。
- 计划时间是否有效。

经营表现把握至少考虑：

- 是否有真实对标内容。
- 对标内容分析是否完整。
- 账号同形式历史表现。
- 内容与账号定位、产品、市场的匹配程度。
- 同类内容样本量。

### 14.3 数据充分度

- 样本不足时不得显示百分比。
- 只有经过校准并满足最小样本量后，才可以显示概率区间，例如“预计 55%–70%”。
- 页面必须允许展开查看影响因素和数据更新时间。

## 15. 异常中心与恢复

### 15.1 异常分类

| 分类 | 系统行为 | 用户动作 |
| --- | --- | --- |
| 网络超时 | 自动分级重试 | 可等待，也可取消尚未受理的任务 |
| 系统故障 | 自动延迟重试 | 重试耗尽后可重试当前节点 |
| 供应商已受理待对账 | 只查询原任务，不重复提交 | 等待或申请人工核对 |
| 余额或预算不足 | 立即阻塞 | 充值、调整预算或更换路线 |
| 内容拒绝 | 立即阻塞 | 修改文案、素材或生成要求 |
| 缺素材/资料 | 立即阻塞 | 直达企业中心或素材库补齐 |
| 质量失败 | 保留已通过节点 | 查看修改要求并局部返工 |
| 账号或授权问题 | 保留成片，只阻塞发布 | 连接账号或重新授权 |

### 15.2 恢复动作

按照影响范围从小到大提供：

1. 重试当前节点。
2. 只重做失败镜头或失败语言。
3. 更换素材、模型或参考视频后继续。
4. 从脚本或分镜节点重新开始。
5. 重新规划单条内容。
6. 重新规划本周同类内容。
7. 跳过并继续，不允许用于伪造真实发布和发送完成。

每个动作必须显示：保留结果、失效结果、预计新增成本、是否需要重新审批。

## 16. 提醒机制

### 16.1 页面内提醒

- 经营总览固定显示“需要处理”数量。
- 有阻塞项时，页面顶部显示最紧急异常及唯一主动作。
- 内容队列支持“只看需要处理”。

### 16.2 全局消息中心

新增通知类型：

- 任务需要输入。
- 自动重试中。
- 自动重试已耗尽。
- 供应商任务正在对账。
- 内容等待验收。
- 周任务完成。

每条通知必须包含任务名称、原因、系统已做动作、用户下一步和业务页面直达链接。

### 16.3 降噪规则

- 同一任务同一异常只产生一条未读通知，状态变化时更新或追加事件。
- 自动重试未耗尽时不反复弹窗。
- 只有需要用户操作、达到重试上限或进入验收时使用明显提醒。

## 17. Agent 调度说明

### 17.1 用户可见原则

用户需要看到“谁负责、为什么排队、下一步交给谁”，不需要看到内部进程名和锁 ID。

### 17.2 调度规则

- 经营 Agent 负责目标、采集边界、预算、账号、数量、日期和计划版本，为现有 `SocialCrawlStrategy` 创建当期不可变版本，并独占 `OperatingScheduleSkeleton`、`WeeklyOperatingPackage` 和派单记录的写权。
- 编导 Agent 先负责中词场景簇、对标账号与爆款视频的采集编排和范围校验，再针对经营排期槽位输出选题、参考视频、脚本结构和分镜意图的分析结论。编导 Agent 只有分析结果写权，没有正式排期和派单权。
- 经营 Agent 对编导结论进行采用、调整或拒绝，将被采用的结论补入详细内容选题排期，完成版本冻结和用户确认后再向内容 Agent 派单。
- 内容 Agent 只负责执行经营 Agent 签发的内容任务，读取“我的素材”索引和已引用的编导分析，完成素材组合、口播、字幕、渲染和质检。它不直接接收编导 Agent 的命令。
- 客服 Agent 负责把已脱敏的客户问题、采购顾虑和线索结果反馈给下一周期的中词候选，并继续负责线索分层、跟进草稿和客户触达。
- 编导 Agent 只有在 `CollectionReadiness` 达标后才能启动付费详细预分析；不达标时先追加采集或输出采集缺口。
- 有依赖关系的任务按依赖执行；独立分支可以同时推进。
- 内容任务由正式数据库队列调度，并受客户、账号和任务类型并发上限约束。
- 调度优先保证客户间公平，再按计划优先级、发布时间和入队时间排序。
- 编导或内容 Agent 遇到采集缺口、素材缺口、预算冲突或截止时间冲突时，将结构化阻塞返回经营 Agent；只有经营 Agent 可以重排或创建新计划版本。

### 17.3 不允许的表述

- 不把 Agent 角色数量当作后台并发数量。
- 不把“等待外部结果”展示成 Agent 持续占用模型。
- 不把计划排期展示成真实发布成功。

## 18. 权限与安全

- 普通用户只能查看有效并发和本企业任务，不能修改租户并发策略。
- 管理员修改并发上限必须记录操作者和时间。
- 重试、跳过、人工完成和重新规划必须写入审计记录。
- 涉及真实发布、客户发送和商业承诺的动作继续使用统一决策卡。
- 任务恢复导致计划、内容哈希或授权范围变化时，原发布授权失效并要求重新确认。

## 19. 数据与接口要求

采集后端至少提供：

- `collectionScope`：当前采集范围版本、主模式、行业／市场、语言、平台比例、词簇版本、预算和来源事实版本。
- `collectionRuns`：采集任务状态、平台、查询层级、分页游标、尝试次数、已用预算、部分结果和阻塞原因。
- `collectionReadiness`：是否允许生成免费总纲、是否允许启动付费详细预分析，以及仍缺少的账号、视频、词簇或素材覆盖。
- `inspirationSupply`：爆款视频、对标账号和我的素材的分类查询、统计与稳定引用。
- `collectionDecisions`：平台比例、词簇额度、排除账号和范围切换的版本化决策记录。

接口职责建议：

- 读取当前范围及历史版本。
- 由经营周期创建一次幂等采集运行；浏览器重复请求不能重复创建。
- 读取运行进度、部分结果、失败单元和下一次重试时间。
- 按三类结果及其筛选条件分页查询灵感供给。
- 读取周计划采集准入；准入失败必须返回结构化缺口，不能只返回一段错误文字。
- 保存账号候选的通过／排除状态及原因；历史周计划继续引用当时版本。

计划后端至少提供：

- `accountBenchmarkStrategies`：每个自有账号的主对标账号快照、账号打法版本、模仿比例、栏目分布、更新节奏和模仿边界。
- `operatingScheduleSkeletons`：由经营 Agent 签发的数量、日期、平台、自有账号、预算和发布截止槽位。
- `directorPlanningAnalyses`：编导 Agent 针对排期槽位返回的对标证据、选题、结构、镜头意图、风险和采集缺口，明确标记为非执行授权。
- `businessDispatchRecords`：经营 Agent 对编导结论的采用决定，以及向内容 Agent 签发的计划版本、任务边界和幂等键。
- `weeklyContentItems`：权威周任务包内逐条内容及其账号、主参考视频、辅助证据、素材计划、质量策略、成本和发布时间。
- `shootingSuggestions`：非阻塞待拍建议、兜底路线、素材冻结时间和回填采用状态。
- `executionSchedule`：与 `WeeklyExecutionTask` 一一对应的内部责任 Agent、阶段、依赖、计划时间、成本预留和发布截止时间。
- `qualityPolicy`：固定为 `premium` 的默认质量策略、可用能力、不可用原因、预算校验和显式降级决策。

计划接口必须支持：

- 幂等生成免费总纲；相同经营目标、账号矩阵、采集范围和容量版本得到同一个草案。
- 在用户确认总纲后，由经营 Agent 针对排期槽位幂等启动编导预分析；重复点击、刷新和进程恢复不能产生第二套任务。
- 编导分析写入接口只接受 `DirectorPlanningAnalysis`，不具备创建或修改 `WeeklyOperatingPackage`、`WeeklyExecutionTask` 和派单记录的权限。
- 经营 Agent 合并编导分析时必须保存采用、调整或拒绝结果及原因；同一骨架版本、分析版本集和策略版本只生成一个待确认周任务包。
- 内容 Agent 执行任务创建接口必须验证已确认的周任务包、`issuedBy: business_agent` 和有效派单幂等键；缺任一项都拒绝入队。
- 通过 `expectedVersion` 确认或修订周任务包，避免覆盖用户正在查看的旧版本。
- 根据素材回填事件，在冻结时间前创建内容执行计划新版本；冻结后路由到下一兼容任务。
- 读取用户可见的预计完成与发布时间投影；内部排程详情只向管理员和后台 Worker 开放。

前端智能经营总览需要一份服务端聚合投影，至少包含：

- `collectionSummary`：范围版本、主模式、平台分配、运行状态和结果数量。
- `collectionReadiness`：免费总纲与付费详细预分析的独立准入状态。
- `inspirationSupplySummary`：爆款视频、对标账号、我的素材三类数量和缺口。
- `benchmarkStrategySummary`：每个自有账号的主对标、模仿栏目、更新节奏和实验比例。
- `weeklySummary`：周计划产量、版本、时长、形式和预算。
- `shootingSuggestionSummary`：建议待拍数量、回填截止时间、是否阻塞和兜底说明。
- `deliveryForecast`：首条预计完成、本周最晚完成、计划发布区间和延误风险；不包含内部 Worker 排程。
- `contentQueue`：周计划和手动任务的统一队列，并保留来源字段。
- `executionCapacity`：当前客户、账号、任务类型和 Worker 槽位。
- `contentConfidence`：三类把握、因素和数据充分度。
- `blockers`：异常分类、是否自动恢复、下一次重试时间和可用动作。
- `notifications`：可直达业务页面的提醒。

队列任务至少返回：

- `queueStatus`、`queuePosition`、`queuedAt`、`startedAt`、`estimatedStartAt`。
- `attempt`、`maxAttempts`、`retryClass`、`nextAttemptAt`。
- `accountLimit`、`taskTypeLimit`、`tenantLimit` 和命中的限制。
- `providerState`，但不返回敏感供应商请求数据。

## 20. 埋点与效果指标

核心埋点：

- 查看周计划详情。
- 打开对标视频或账号。
- 打开制作进度。
- 查看异常详情。
- 执行恢复动作。
- 收到提醒后进入任务。
- 计划确认、任务验收和发布确认。

效果指标：

- 对标账号有效率，以及抽样复核后的 B2B 账号准确率。
- D2C 账号误入 B2B 长期对标池的比例。
- TikTok 有效视频入池率、YouTube 定向补充有效率和单位有效结果成本。
- 中词场景簇的有效入池率、周计划采用率和连续无结果率。
- 重复视频／账号拦截率，以及采集中断恢复后的重复付费率。
- 从经营周期创建到 `CollectionReadiness` 达标的时间。
- 自有账号主对标覆盖率，以及主对标在计划周期内的稳定率。
- 周内容项参考链完整率、主对标打法一致率和单变量实验合规率。
- 建议待拍任务回填率、冻结时间前采用率，以及无上传情况下的兜底成功率。
- Premium 路线覆盖率、因预算减少的内容数量和显式降级授权率。
- 后台计划完成时间与实际完成时间偏差、发布截止时间达成率。
- 周计划确认率。
- 任务按周完成率。
- 平均异常恢复时间。
- 重复提交率。
- 整条重做率与局部返工率。
- 预计成本与实际成本偏差。
- 通知到处理的转化率。

## 21. 可访问性与响应式要求

- 状态不能只依赖颜色，必须同时显示文字和图标。
- 所有进度、异常和成功把握提供可读文本。
- 弹层支持 Esc 关闭、焦点锁定和关闭后焦点恢复。
- 移动端周任务表切换为分组卡片，主操作始终可见。
- 开启减少动态效果后，旋转和脉冲改为静态状态。

## 22. 里程碑与验收标准

### 里程碑一：采集后端成为周计划前置（当前优先）

范围：

- 扩展现有 `SocialCrawlStrategy`、`SocialMarketKeywordSet`、`SocialInspirationCollectionRun`、关键词图和账号跟踪决策，并新增只读 `CollectionReadiness`。
- 实现行业矩阵与市场聚焦两种互斥范围模式。
- 将中词设为主要采集供给，并落实 TikTok 主采集、YouTube 定向补充的服务端约束。
- 实现分页游标保存、平台对象去重、分级重试、预算阻断和中断恢复。
- 对爆款视频、对标账号和我的素材提供三类可独立查询的权威数据接口。

验收：

- 同一经营周期重复触发只产生一个有效采集范围版本和一个幂等运行。
- 默认平台额度满足 TikTok 不低于 70%、YouTube 不高于 10%，且 YouTube 不运行宽泛全量查询。
- 采集中断后从已保存游标继续，账号和视频不重复入库。
- 三类灵感供给均能按租户隔离查询，并返回稳定引用与数据版本。
- 采集不足时返回结构化缺口，不能把未分类候选交给周计划。

### 里程碑二：主对标账号与逐条计划后端

范围：

- 周计划服务强制读取 `CollectionReadiness` 和稳定灵感引用。
- 为每个起号期自有账号绑定唯一主对标账号快照，并扩展现有 `AccountPlaybook.benchmarkStrategy`。
- 从主对标账号的多条内容生成更新节奏、栏目占比、视频规格、视听风格、证明顺序和模仿边界。
- 由经营 Agent 先生成 `OperatingScheduleSkeleton`，再针对每个槽位派发编导分析；编导 Agent 只生成 `DirectorPlanningAnalysis`。
- 由经营 Agent 合并编导结论并保存采用决策，形成唯一详细内容选题排期。
- 扩展唯一权威 `SocialWeeklyContentPackage`，增加逐条 `contentItems`，并保持与现有 `publicationTasks` 的稳定引用。
- 免费任务总纲使用确定性规划，不调用生成式模型；详细预分析绑定具体对标视频和完整参考链。
- 周计划、详细预分析和内容任务共同保存采集范围、账号打法、对标视频、素材及企业事实版本。

验收：

- 每个自有账号只有一个主对标账号；数据不足时账号打法失败关闭。
- 每条周任务可追溯到采集范围、账号打法、主对标账号、一个主参考视频、素材版本和计划版本。
- 采集阈值未达标时只允许生成免费总纲草案，不允许启动付费详细预分析。
- 账号容量低于对标频次时能够按比例映射，不超量创建任务。
- 更换主对标账号、预算、内容数量或发布账号时创建新的周任务包版本。
- 编导分析接口尝试直接创建内容任务时被权限拦截；不存在“编导 Agent → 内容 Agent”的直接派单边。
- 已采用的编导结论变化时，经营 Agent 生成计划新版本，旧派单不会被静默篡改。

### 里程碑三：素材兜底、Agent 排期与 Premium 后端

范围：

- 为每个建议待拍任务生成已有素材／AIGC 兜底路线、回填截止时间和采用规则。
- 扩展现有 `WeeklyExecutionTask`，保存责任 Agent、阶段、依赖、计划开始／完成时间、预计成本和发布截止时间。
- 内容执行任务必须保存经营派单记录、周任务包版本和编导分析版本，并校验 `issuedBy: business_agent`。
- 实现从发布时间向前倒排、容量冲突检查、受影响分支重排和排期版本记录。
- 所有内容默认 `qualityTier: premium`，计划阶段完成成本上限与预算预留。
- 不满足 Premium 预算时减少数量或阻断；供应商任务不因排期变化重复提交。

验收：

- 用户不上传建议素材时，本周全部内容仍有可执行生产路线。
- 在素材冻结时间前上传的素材进入对应执行计划新版本，冻结后不打断已付费任务。
- 每个执行任务都有后台责任人、时间、成本和目标发布账号／窗口。
- 每个内容 Agent 任务都能回溯到经营派单、经营排期骨架和所学习的编导分析；任一引用缺失时不得执行。
- Premium 不可用或预算不足时明确阻断，不静默降档。
- 重复确认、恢复和重排不重复建任务、预留预算或提交供应商。

### 里程碑四：采集、计划与确认前端

范围：

- 在不改变智能经营四个现有 Tab 的前提下，展示采集模式、平台分配、运行状态和采集缺口。
- 灵感大屏提供爆款视频、对标账号、我的素材三类入口及分类筛选。
- 免费总纲集中呈现目标、产量、账号分配、主对标账号、更新节奏、Premium 预算和建议待拍素材。
- 用户一次确认后进入详细计划；周任务卡展示具体参考视频、素材组合和预计完成／发布时间。
- 前端只展示用户相关时间和卡点，不暴露内部 Agent 排程表。

验收：

- 用户能看清当前聚焦范围、每个账号跟谁学、为什么这样分配，以及本周具体要做什么。
- 用户能分别核对爆款视频、对标账号和我的素材，并从计划下钻到真实记录。
- 用户明确知道待拍任务是建议还是硬门槛，以及不上传时系统使用什么兜底路线。
- 一次确认冻结版本；需要重新确认的变化与后台自动重排被清楚区分。

### 里程碑五：执行恢复、可信建议与调度优化

范围：

- 完善周任务驾驶舱、制作进度下钻、有效并发、排队原因和异常中心。
- 接入重试、局部重做、补资料、跳过、重新规划和全局消息提醒。
- 上线三类成功把握及数据充分度，增加预算风险和下一轮分配建议。
- 使用采集采用率、真实发布、成本和账号表现优化下一轮平台、词簇、对标账号和内容额度。

验收：

- 供应商已受理任务不会因恢复操作重复提交。
- 数据不足时不显示伪概率，每个把握等级都能展开查看真实依据。
- 用户能解释每条任务为何排队、为何受阻、系统是否正在恢复以及下一步由谁处理。
- 下一轮建议能回溯到采集版本、账号打法版本、本周真实完成、成本和账号表现。

## 23. 发布与回滚

- 五个里程碑分别通过服务端状态测试、接口契约测试、前端契约测试和构建检查后合并。
- 里程碑一至三验收通过前，不开始本轮采集与计划相关前端重构；已有页面继续保持兼容读取。
- 新增投影字段保持向后兼容；字段缺失时前端展示“暂不可用”。
- 新通知类型启用失败时不影响原任务执行。
- 并发和重试规则沿用服务端权威配置，前端只负责解释，不在浏览器中重新计算调度决定。
- 本文档不授权部署；部署继续遵循仓库部署约定。
