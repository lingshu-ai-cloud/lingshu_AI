# 爆款复刻管线 3：Seedream + Seedance 产品与技术基线

- 文档状态：开发基线
- 日期：2026-10-08
- 适用范围：爆款复刻模式中的人物口播与人物演绎分镜
- 唯一正式生成路线：**Seedream 目标人物参考图 + Seedance 全模态 `reference_video` A-roll**
- 关联页面：口播替换与确认、分镜匹配与制作、成片渲染和导出
- 上位规则：`PRD-社媒视频智能生产与爆款复刻系统-v1.md`、`爆款复刻模式-内容制作三页面全链路.md`

## 1. 产品结论

管线 3 不把爆款复刻理解为“按原视频固定秒数逐段重生成”，而是把参考视频重建为一份可编辑、可重跑、可局部复用的制作工作流。参考视频提供表达结构、语义顺序、镜头功能和节奏依据；企业人物、产品、品牌、授权声音和事实材料提供新的内容身份。

正式链路为：

```text
参考视频分析
  → 冻结口播与产品映射
  → 语义锚点和分镜制作计划
  → 真人参考视频合规处理与 motion guide
  → Seedream 目标人物参考图
  → Seedance 全模态 reference_video 人物 A-roll
  → 按实测素材时长重排时间轴
  → 字幕、B-roll、动效、音乐和音效编排
  → 自动质量检查与自动回填
  → 本地合成和导出
```

本阶段只开发和验收管线 3。纯 HeyGen、Seedream + HeyGen 不属于本文范围；不得为了兼容旧路线而降低管线 3 的数据模型、交互或质量门。

管线 3 的最高规格不是“从一张首帧猜完整段运动”。正式方案同时向 Seedance 提供：

- Seedream 生成并通过身份检查的目标人物参考图，用于锁定企业人物身份、造型和必要的产品身份；
- 经合规处理的 `reference_video`，用于提供可观察的人物动作、走位轨迹、运镜轨迹、动作节拍及口播表演节奏；
- 确认口播、目标语言、语速、语义锚点和禁止变化项。

现有“目标首帧 + 文本提示词 + Seedance 图生视频”只属于兼容路径或降级路径。它可以生成近似口播和自由动作，但由于没有动态参考条件，不能标记为“高保真动作复刻”“参考运镜复刻”或“走播复刻成功”。

## 2. 核心原则

### 2.1 语义锚点是时间线的稳定主键

口播中的词、短语、句子和叙事节拍构成语义锚点。字幕、B-roll、特效、音效和镜头功能绑定语义锚点，不绑定不可变的绝对秒数。

每个锚点至少包含：

- 稳定 `anchorId`；
- 原口播与确认后口播；
- 所属叙事节拍与分镜；
- 词级或句级相对时间；
- 关联产品、人物和事实来源；
- 需要触发的字幕、B-roll、动效和音效事件；
- 原片时间只作为参考证据，不作为生成结果的强制时长。

当 A-roll 实际时长改变时，系统重新计算锚点的绝对时间，所有关联轨道随锚点移动。

### 2.2 工作流可重跑

每次爆款复刻保存结构化 `ReplicationWorkflowSpec`，而不是只保存最终 MP4。工作流至少描述：

```ts
interface ReplicationWorkflowSpec {
  workflowId: string;
  sourceReferenceVersion: string;
  confirmedSpeechVersion: string;
  presenterVersion: string;
  productIdentityVersions: string[];
  narrativeBeats: NarrativeBeat[];
  semanticAnchors: SemanticAnchor[];
  shotRecipes: ShotRecipe[];
  captionRecipe: CaptionRecipe;
  brollBindings: TrackBinding[];
  effectBindings: TrackBinding[];
  audioBindings: TrackBinding[];
  planVersion: string;
}
```

修改人物、产品、语言、口播或单个镜头时，系统只使依赖该输入的节点失效。未受影响且仍通过版本校验的候选继续复用。

### 2.3 Plan 与 Build 分离

`Plan` 是无付费生成的确定性阶段，必须先回答：

- 要生成多少张 Seedream 目标人物参考图；
- 哪些真人参考段可以直接使用，哪些必须生成去身份 motion guide；
- 要生成多少段 Seedance 视频；
- 哪些候选可直接复用；
- 哪些短句需要合并成 4–15 秒语义段；
- 每段的目标人物、产品、语言、动作和构图；
- 分段预计时长、分辨率、单价、预计费用与总费用；
- 哪些输入或授权尚未满足。

`Build` 只执行用户已启动且仍在预算内的计划。提交供应商前复核计划版本、输入资产版本、授权和预算锁；超出预算不得静默降级或继续扣费。

### 2.4 生成素材与最终编排解耦

- Seedream 负责生成符合企业人物、产品和参考构图约束的目标人物参考图；参考图可以对应起始状态，也可以包含生成方案所需的身份视图。
- motion guide 处理层负责从真人参考视频提取并保存动作、走位、相机运动和节拍证据，同时去除不应向下游传播的原人物身份信息。
- Seedance 使用目标人物参考图、合规 `reference_video`、确认口播和结构化运动契约生成人物 A-roll。
- 字幕、B-roll、贴纸、转场、音乐和音效由时间轴及本地渲染器编排。
- Seedance 不承担最终字幕和包装，避免 A-roll 返工导致整片重做。

### 2.5 动态参考必须与身份参考分离

真人参考视频包含两类性质不同的信息：

1. 可迁移的表演和镜头信息：身体运动、走位、姿态变化、动作顺序、速度曲线、相机方向、景别变化、节拍和构图关系；
2. 不应默认复用的身份信息：原人物人脸、声音、身体特征、服装细节、个人标识及其他可识别特征。

进入 Seedance 前必须满足以下任一条件：

- 对参考视频具有允许人物形象、动作和视频衍生使用的明确授权，并把授权范围、有效期和资产版本写入任务；
- 先生成不含原人物可识别身份的 motion guide，再把该 motion guide 作为 `reference_video`。motion guide 应尽可能只保留骨架／姿态、身体中心轨迹、轮廓运动、相机运动、深度／遮挡关系和时间节拍，不保留可还原的脸、原声、品牌或个人标识。

公开竞品视频可用于分析爆款结构，不自动获得向生成供应商上传真人影像或制作人物衍生内容的权限。无法证明授权、也无法生成合格去身份 motion guide 时，该分镜不得进入全模态参考视频生成；系统可以降级为首帧图生视频，但必须明确显示“自由演绎”，不得显示“参考动作已复刻”。

### 2.6 实际素材时长驱动时间轴

数字人分镜一旦采用并回填 Seedance 视频，分镜坑位时长必须与视频可解码的实际时长完全一致：

```text
slot.duration = adoptedMaterial.measuredDuration
trimStart = 0
trimEnd = adoptedMaterial.measuredDuration
speed = 1
```

系统不得通过慢放、加速、截断或拉伸让素材适配旧坑位。当前分镜之后的分镜、字幕、B-roll、动效和音频事件按语义锚点顺延或重排。重新采用另一个候选时，以新候选的实测时长重新计算。

### 2.7 采用即自动回填

通过自动质量门并被采用的候选直接回填分镜，不要求人工确认首帧或成片验收。失败候选保留诊断证据并只重做失败节点。涉及授权失效、预算超限、无法确认产品身份或供应商结果不确定时，任务进入明确阻断状态。

## 3. 工作流节点

```mermaid
flowchart LR
    A[参考视频与逐镜分析] --> B[确认口播与身份映射]
    B --> C[语义锚点]
    C --> D[Plan：分段、复用、预算与门禁]
    D --> E[参考视频授权或去身份 motion guide]
    E --> F[Seedream 目标人物参考图]
    F --> G[参考图自动质量门]
    G --> H[Seedance 全模态 reference_video A-roll]
    H --> I[媒体探测与动态复刻质量门]
    I --> J[候选采用与自动回填]
    J --> K[按实测时长重排多轨时间线]
    K --> L[本地渲染与导出]
```

### 3.1 语义段规划

系统按照语义完整性、同一人物、同一场景和连续动作合并口播。Seedance 单段必须满足供应商允许的时长范围；当前基线为 4–15 秒。低于 4 秒的短句优先与相邻且语义、场景和人物一致的句子合并，不用减速填满。超过 15 秒时，按可验证的动作阶段拆段；仅在同一已确认分镜内部、且能证明连续状态时使用上一段合格末帧续接。

每段保存原句范围、确认口播、语言、预计时长、动作契约、构图约束和包含的语义锚点。语言从确认口播和项目语言得到，提示词不得固定为中文。

### 3.2 动态参考与 `MotionReplicationSpec`

参考视频先按已确认的物理镜头边界切段。不能把包含硬切、换机位或跨场景的片段作为一个连续动作参考。每个动作参考段形成版本化 `MotionReplicationSpec`：

```ts
interface MotionReplicationSpec {
  version: string;
  sourceVideoRef: string;
  sourceVideoHash: string;
  referenceMode: 'authorized_video' | 'deidentified_motion_guide';
  authorizationRef?: string;
  motionGuideRef?: string;
  motionGuideHash?: string;
  durationSeconds: number;
  camera: {
    mode: 'locked' | 'pan' | 'tilt' | 'dolly' | 'truck' | 'orbit' | 'handheld' | 'follow';
    direction: string;
    trajectory: Array<{ phase: number; x: number; y: number; scale: number; roll?: number }>;
    stabilization: string;
  };
  presenter: {
    bodyCenterTrajectory: Array<{ phase: number; x: number; y: number; scale: number }>;
    facing: string;
    walkDirection: string;
    gaitBeats: Array<{ phase: number; event: string }>;
    actionBeats: Array<{ phase: number; action: string; anchorId?: string }>;
  };
  occlusionAndDepth: string[];
  startState: string;
  endState: string;
  evidence: Array<{ timeSeconds: number; frameRef: string; observation: string }>;
}
```

这里的 `phase` 是 0–1 的归一化运动进度。采用相位而不是绝对秒数，允许目标口播与参考片段时长不完全相同，同时保持动作先后、走位方向和运镜节拍。motion guide、轨迹文件、参考片段、检测器版本和所有证据哈希都必须进入生成节点输入指纹。

“走播”必须明确区分：固定机位下人物走动、人物基本固定时相机运动、相机跟随人物移动。跟随走播同时包含人物世界运动与相机相对运动，不能只用一句自然语言“边走边说”代替。

### 3.3 Seedream 目标人物参考图

输入包括参考视频本镜构图证据、当前已发布人物版本、企业产品身份图，以及必要时的企业场景参考。系统保持镜头功能、起始景别、构图、光线、人物起始姿态和产品槽位，同时替换原人物、原产品、品牌和 Logo。

目标人物参考图必须记录输入版本、提示词、模型、费用、输出哈希和质量报告。相同构图只有在人物、产品、场景和镜头要求兼容时才允许复用，不因视觉相似自动跨分镜共用。

参考图质量门只证明人物／产品身份、造型、背景和起始构图满足要求，不能证明动态运镜或走播已经复刻。动态结论必须在 Seedance 视频生成后依据连续视频证据给出。

### 3.4 Seedance 全模态 `reference_video` A-roll

Seedance 正式输入使用已通过质量门的目标人物参考图、授权参考视频或去身份 motion guide、确认口播、项目语言、`MotionReplicationSpec` 和镜头约束。生成提示按运动阶段编译，例如起步、主运动和收势，并把动作节拍绑定语义锚点：说到指定词时开始走动、转身、展示产品或停下。任务创建、轮询、恢复和下载使用稳定幂等键；网络超时或状态不明时先查询原任务，不重复提交付费任务。

只有供应商请求和回执能够证明本次任务真实使用 `reference_video` 时，候选才能标记为全模态参考视频结果。仅上传首帧、仅传文本中的运镜描述或从首帧自由生成，都必须记录为 `first_frame_i2v_fallback`。

输出下载后必须以媒体探测结果写入真实时长、帧率、尺寸、画幅、音轨和内容哈希。供应商回执中的声明值不能代替本地解码结果。

### 3.5 多轨重排与渲染

时间轴至少包含：

- A-roll；
- 字幕；
- B-roll；
- 图形与贴纸；
- 音效；
- 语音与 BGM。

绑定在语义锚点上的事件根据 A-roll 内词级或句级对齐更新位置；绑定镜头边界的转场随分镜起止时间更新；纯绝对时间事件必须显式标记并在重排后检查冲突。

## 4. 候选、版本与局部复用

每个生成节点都产出候选，而不是覆盖唯一结果：

```ts
interface WorkflowCandidate {
  candidateId: string;
  nodeId: string;
  source: 'motion_guide' | 'seedream' | 'seedance' | 'library' | 'render';
  materialId: string;
  inputFingerprint: string;
  status: 'running' | 'passed' | 'failed' | 'stale';
  qualityReportId?: string;
  measuredDuration?: number;
  estimatedCost: number;
  actualCost?: number;
  createdAt: string;
}
```

复用必须同时满足：

1. 候选输入指纹与当前工作流依赖版本一致；
2. 素材仍属于当前租户且可读取；
3. 人物和产品授权仍有效；
4. 质量报告满足当前门槛；
5. 候选未被更新的任务结果替代。

采用关系必须同时记录 `candidateId` 和 `materialId`。较早完成的历史任务不能覆盖较新的已采用候选；恢复旧草稿时重新校验输入指纹和素材实测时长。

## 5. 自动质量门

自动质量门用于发现明显失败，不把正常的表演差异判成失败。至少检查：

- 文件可下载并完整解码；
- 时长、尺寸、画幅、帧率和音轨有效；
- 人物身份与授权版本一致；
- 产品及包装身份没有被替换或明显变形；
- 语言与确认口播一致，口播没有缺句或多句；
- 口型、冻结、异常慢动作和大段静止在容许范围内；
- 关键动作起点、过程和终点可见；
- 画面没有残留原人物、原品牌或原产品身份。

对于标记为全模态参考视频复刻的候选，还必须单独检查四类动态指标：

1. **走位轨迹**：比较人物身体中心、尺度、朝向、出入画位置、起停点和转身节点。不同素材时长先按 0–1 运动相位或动态时间规整对齐，再比较轨迹方向、关键节点顺序和归一化位置误差；不得因为素材时长改变而要求逐秒位置相同。
2. **运镜轨迹**：使用背景特征、光流、单应性或等价的确定性视觉证据，区分锁定、推拉、横移、摇移、环绕、手持和跟随；比较方向、累计幅度、速度曲线、起止稳定段、抖动和背景几何连续性。不得用整帧运动量代替运镜方向与轨迹判断。
3. **动作节拍**：检查动作起点、阶段顺序、关键接触、峰值和结束状态，并核对动作事件与语义锚点的相对关系。五张均匀采样帧只能用于发现明显错误，不能证明连续动作完成。
4. **语速与表演节奏**：依据实际音轨 ASR／词级时间码计算起说延迟、有效口播时长、词速、停顿分布、句尾拖长和音画对齐；与确认口播的目标语速及参考视频的节奏区间比较。禁止通过整段慢放、拉伸或异常停顿迁就计划时长。

建议将质量结果拆为 `presenter_path`、`camera_motion`、`camera_subject_coupling`、`action_beats`、`gait_and_foot_contact`、`start_end_composition`、`background_geometry` 和 `speech_pacing`。固定机位口播、人物走动、纯运镜和相机跟随人物使用不同阈值；阈值由真实样本校准并记录版本。

检测器没有足够帧、轨迹或音频证据时返回 `unknown`，不能自动记为通过。只有本文定义的必检项均有可追溯证据并满足自动通过门槛，候选才可自动采用回填；否则任务进入明确的阻断或人工复核状态。人工复核结果不能反向伪造成自动检测通过。

模型语义判断只作为质量证据之一；媒体探测、确定性规则和版本校验不得交给模型代判。质量门阈值需要用真实样本校准，不能因参考视频动作更快或构图有差异就直接拒绝可用结果。

失败后只重新运行失败节点及其下游失效节点。自动重试必须受预算和次数上限约束。

## 6. 状态机与恢复

推荐工作流状态：

```text
draft
  → planned
  → blocked | build_ready
  → building
  → quality_checking
  → partially_completed | completed | failed
  → rendering
  → rendered
```

节点级状态独立保存。页面刷新、浏览器关闭或 Worker 重启后，从后端任务和候选恢复，不能依赖前端内存。恢复时遵循：

- 已成功且可复用的节点不重复付费；
- 状态不明的供应商任务先轮询原任务；
- 输入版本变化后只使受影响节点及下游变为 `stale`；
- 完成候选自动回填时同步写入采用关系和时间轴编辑；
- 所有状态变化保留任务 ID、时间、费用和失败原因。

## 7. 页面交互

### 7.1 管线入口

分镜制作页将管线 3 作为统一入口呈现为“Seedream + Seedance 爆款复刻”。普通用户看到人物、产品、语言、动作、预算和任务状态；模型名、供应商任务 ID 和诊断信息放在技术详情中。

### 7.2 Plan 预览

执行前集中展示：

- 待生成目标人物参考图、motion guide 和视频段数；
- 自动合并或拆分后的语义段；
- 可复用候选及节省费用；
- 各段预计时长、清晰度和费用；
- 总预算、已用预算和剩余预算；
- 当前阻断项。

### 7.3 执行反馈

每个分镜显示计划、执行、质检、回填和重排状态。完成后直接在分镜和时间轴中展示结果。失败时说明失败节点、原因、是否产生费用以及下一步动作，不要求用户理解供应商内部状态码。

数字人结果采用后，时长、速度、入点和出点由素材事实锁定；用户更换候选会触发重新计算，而不是手工拉伸素材。

## 8. 安全、授权与对象存储

- 人物参考必须属于当前企业私有存储，并关联有效授权人物版本。
- 产品参考必须来自当前企业产品身份资产，并保存版本与内容哈希。
- 供应商读取的目标人物参考图和 `reference_video` 必须使用受控、限时、可审计的公网 HTTPS 地址或供应商可信资产引用；不得依赖 localhost。
- 未获衍生授权的外部真人参考不能原样上传供应商。其去身份 motion guide 只有通过不可还原身份检查后才能作为动态条件；原外部媒体仍不能直接回填为生产素材。
- 日志和前端不得暴露 API Key、签名地址或跨租户资源路径。
- 人物、产品、提示词、模型、任务 ID、生成标识和费用均进入审计记录。

## 9. 当前基础与开发缺口

### 9.1 已有基础

- 爆款参考视频、确认口播、产品映射和逐镜草稿；
- Seedream 目标首帧请求、素材入库、输入版本和预算检查；
- Seedance 任务创建、轮询、恢复、下载及基础媒体检查；
- 按句生成、候选、质量报告、素材回填和局部重试的主体结构；
- 数字人采用素材的实际时长、完整区间和原速渲染规则；
- 生成任务幂等、租户隔离和历史任务覆盖保护的部分能力。

其中现有动态生成主要是首帧 I2V：以原片首帧／Seedream 目标首帧和文本动作描述提交 Seedance，再用整帧运动差、停帧差异及少量采样帧做粗粒度检查。这套实现可以作为兼容或降级基础，但没有证明实际传入全模态 `reference_video`，也没有独立的人物走位轨迹、相机轨迹、动作节拍和语速检测，因此不属于本文定义的最高规格管线 3。

### 9.2 本轮必须完成

1. 建立持久化 `ReplicationWorkflowSpec` 和语义锚点模型。
2. 将 Plan 与 Build 分开，生成前返回分段、复用、门禁和成本明细。
3. 实现 4 秒以下相邻短句的语义合并，以及 15 秒以上的受约束拆段。
4. Seedance 提示词按项目语言生成，移除固定中文口播假设。
5. 建立真人参考视频授权门禁和去身份 motion guide 生产、存储及审计链路。
6. 持久化 `MotionReplicationSpec`，从参考段提取人物走位、相机轨迹、动作阶段、遮挡深度和节拍证据。
7. 接入并验证 Seedance 全模态 `reference_video` 请求，保存供应商实际接收动态参考的请求与回执证据；首帧 I2V 单独标为降级路线。
8. 建立人物轨迹、相机轨迹、人物—相机耦合、动作节拍和语速的独立质量检测器及版本化阈值。
9. 将 Seedream、motion guide、Seedance、字幕、B-roll、动效和音频表示为独立工作流节点及依赖。
10. 采用 Seedance 候选后，以实测时长重排所有相关轨道并自动回填。
11. 接通供应商可读取的受控对象存储地址，并校验人物资产可用状态。
12. 前端收口为单一管线 3 入口、Plan 预览、生成规格标记和节点级执行反馈。
13. 完成当前草稿一个指定走播分镜的真实端到端验收，再扩展到整片。

## 10. 验收标准

### 10.1 单镜真实链路

使用当前爆款复刻草稿中的一个人物分镜验证：

1. Plan 正确识别语言、人物、产品、语义段、模型调用和预计费用；
2. 参考视频具备明确衍生授权，或已生成不能还原原人物身份的 motion guide；
3. Seedream 使用正确的参考构图证据和企业身份资产，生成合格目标人物参考图；
4. Seedance 只提交一次可追踪的真实任务，请求与回执能够证明实际使用全模态 `reference_video`；
5. 输出可完整播放，口播语言和内容正确；
6. 人物走位方向、起停点、关键动作顺序与 motion guide 一致，未出现滑步、漂移或异常冻结；
7. 运镜类型、方向、幅度和人物—相机跟随关系达到该镜头的版本化阈值，背景无明显几何跳变；
8. 起说延迟、词速、停顿和句尾节奏达到目标范围，没有慢放或时间拉伸；
9. 质量门通过后无需人工验收即可采用和回填；
10. 分镜时长精确等于下载视频的实测时长，速度为 1，使用完整视频；
11. 后续分镜及字幕、B-roll、动效和音频事件正确顺延；
12. 刷新页面后采用关系、时长、任务和费用仍一致；
13. 重新运行时能复用未变化的合格候选，不产生重复费用。

### 10.2 自动化契约

至少覆盖：

- 语义锚点在素材时长变化后的时间重算；
- 短句合并和长段拆分边界；
- Plan 不触发付费调用；
- Build 的预算、授权、版本和幂等门禁；
- 历史任务不能覆盖新候选；
- 采用候选与 `materialId` 一致性；
- 素材实测时长优先于计划时长和原片时长；
- 非中文项目不会得到固定中文提示词；
- 未授权真人参考视频不能进入供应商请求；
- 去身份 motion guide 不包含可还原的原人物人脸、原声或个人标识；
- 全模态候选有实际 `reference_video` 请求与回执证据，首帧 I2V 不会被误标为最高规格；
- 走位、运镜、动作节拍和语速分别产生可追溯的质量结论；
- 浏览器刷新及任务恢复不会重复提交供应商任务。

## 11. 完成定义

管线 3 只有在一个真实分镜完成以下闭环后才能称为跑通：

```text
Plan 可解释且预算明确
→ 真人参考视频已获授权或完成去身份 motion guide
→ Seedream 目标人物参考图成功
→ Seedance 全模态 reference_video A-roll 成功
→ 走位、运镜、动作节拍和语速有独立证据并通过
→ 自动质量门通过
→ 自动采用并回填
→ 实测时长驱动多轨重排
→ 页面恢复一致
→ 可渲染导出
→ 重跑能够复用候选且不重复付费
```

单独证明 Seedream 可出图、Seedance 首帧 I2V API 可返回视频、文本提示中包含运镜描述或模拟测试通过，都不能替代上述端到端结论。
