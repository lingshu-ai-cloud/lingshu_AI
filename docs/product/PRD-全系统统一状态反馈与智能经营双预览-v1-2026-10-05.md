# 全系统统一状态反馈与智能经营双预览 PRD v1.0

> 日期：2026-10-05
> 状态：已确认，按里程碑开发
> 范围：全系统 UI/UX 统一规则、智能经营、内容制作入口
> 设计基线：采用 Buffer 的“账号列表 + 独立内容卡片”信息架构，以及 Zapier 的“明确触发结果、当前步骤、失败恢复”反馈方式；不复制品牌视觉与商标元素。

## 1. 产品结论

全系统的交互必须持续回答五个问题：

1. 我刚才的操作是否被系统收到。
2. 系统已经产出了什么可用结果。
3. 任务现在进行到哪个节点。
4. 哪个问题阻止了任务继续，以及谁需要处理。
5. 下一步能做什么，完成后会得到什么。

状态不再只是颜色或一句“处理中”。每个业务对象统一显示“结论、来源、结果、下一步、更新时间”；每个写操作统一经历“提交中、已受理、执行中、完成或需处理”。激励来自真实经营成果，不使用虚构积分或成功率。

## 2. 全系统统一组件

### 2.1 状态胶囊

| 状态 | 统一文案 | 视觉 | 必须附带的信息 |
| --- | --- | --- | --- |
| 草稿 | 待确认 | 灰色 | 下一步主操作 |
| 排队 | 已排队 | 蓝灰 | 排队原因；有真实数据才显示位置 |
| 进行中 | 制作中 / 执行中 | 蓝绿，当前节点可旋转 | 当前节点、已完成结果、更新时间 |
| 自动恢复 | 正在自动恢复 | 蓝色 | 第几次重试、保留了什么 |
| 等待用户 | 需要你处理 | 琥珀色 | 唯一主动作、阻塞范围 |
| 等待审批 | 等待确认 | 紫色 | 决策内容、成本与外部影响 |
| 完成 | 已完成 | 绿色 | 可用成果、完成时间、下一步 |
| 失败 | 执行失败 | 红色 | 失败类型、是否扣费、重试起点 |
| 暂停 | 已暂停，可恢复 | 灰蓝色 | 暂停节点、恢复后的起点 |
| 取消 | 已取消 | 灰色 | 已保留成果、不可逆影响 |

颜色不能作为唯一信息。所有状态必须同时显示文字与图标；减少动态效果模式下，旋转改成静态标记。

### 2.2 统一任务卡

任务卡最多分为五层，避免一行一个大框造成页面冗长：

1. 标题行：任务名、来源、状态、更新时间。
2. 核心结果：产品、平台、账号、时长、条数、成本。
3. 证据或预览：图片、视频、素材组合、业务来源。
4. 进度或卡点：当前节点、阻塞原因、自动恢复状态。
5. 操作区：一个主操作，最多两个次操作。

同一页面采用双列或三列栅格；需要横向比较的任务使用紧凑表格。只在用户进入详情后展示完整日志。

### 2.3 统一操作回执

- 点击后立即锁定当前按钮并显示“正在提交”，防止连点重复执行。
- 服务端返回任务编号后才显示“已受理”；不能在浏览器本地提前显示成功。
- 长任务回执必须说明“可以离开页面，任务会继续”，并给出“查看进度”。
- 失败回执必须说明是否创建任务、是否产生费用、已保留什么，以及重试会从哪里开始。
- 页面刷新后从正式任务数据库恢复，不退回到未提交状态。

推荐成功文案：

> 已受理《产品演示短视频》，正在排队。脚本、素材选择与逐镜结果会自动保存，可以离开本页。

推荐失败文案：

> 素材组合未通过检查，本次未启动付费制作。已保留任务总纲与参考视频；补齐 1 项产品素材后可从预分析继续。

### 2.4 统一决策卡

内容审批、发布确认、客户触达和报价确认使用同一结构：

- 决策标题和业务对象。
- Agent 建议与证据来源。
- 预计成本、外部影响和不可逆动作。
- 用户可见成果。
- “确认执行”“退回修改”两个主决策；高风险动作增加范围摘要。

## 3. 全系统页面布局

### 3.1 智能经营

仅智能经营采用左侧账号栏：

- 第一项为“全部账号”。
- 按真实平台顺序显示 YouTube、Instagram、Facebook、TikTok。
- 每个平台下直接列出已连接账号及任务数。
- 不显示“快捷视图”，不显示系统不存在的平台。
- 右侧保留现有四个 Tab：经营总览、账号矩阵、内容队列、数据复盘。
- 每条内容使用独立任务卡，不把多条任务压进一个杂乱的大框。

### 3.2 内容制作

- 默认页仍为“我的创作”，不覆盖现有制作工作台。
- 历史/任务卡保留显眼的“进入制作”入口。
- 所有内容任务使用同一展示模型：用户手动添加的单项任务与周计划任务不再使用两套样式。
- 内容制作页面不增加账号左栏。

### 3.3 企业中心、客户、投放及其他页面

- 不增加账号左栏。
- 企业中心使用完整度卡与待办列表，缺产品图、价格、证书或市场信息时直达对应编辑位置。
- 客户、报价、投放与内容卡均使用统一状态胶囊和决策卡，不新造同义状态。

## 4. 智能经营两步生成

### 4.1 全局开关

智能经营页头显示开关。

- 关闭后不再生成新的周任务总纲或 Agent 详细预览。
- 已运行任务、历史数据和已保存结果不取消、不删除。
- 再次开启后允许继续生成新周期。

### 4.2 步骤 1：免费任务总纲

第一步不调用编导 Agent 与内容 Agent，不产生模型费用，只读取已确认业务数据并生成：

- 经营目标、市场和周期。
- 账号与平台分配。
- 本周产量、内容方向、主要形式和总时长。
- 预算、频次、授权方式和计划版本。
- 每条内容的产品、主题、账号、平台、预计成本和来源血缘。

用户可先修改总纲。任何会影响内容、账号、产品或预算的修改，都必须使旧的详细预览失效。

### 4.3 步骤 2：Agent 预分析

用户明确点击后，编导 Agent 和内容 Agent 前置执行：

1. 编导 Agent 核对爆款参考，生成并冻结脚本/分镜。
2. 内容 Agent 查询同一企业事实版本，匹配真实产品素材和授权。
3. 系统检查待拍、素材空缺、数字人授权、账号范围和预算。
4. 结果保存到任务数据库；刷新、返回上一步或后台进程重启后继续读取同一结果。

按钮必须显示预计耗时，并说明模型费用以真实供应商回执为准；没有真实账单前不显示虚假金额。

## 5. 单条内容的双预览

### 5.1 爆款视频预览

展示：

- 真实缩略图、标题、对标账号和播放数据。
- 前三秒钩子与分镜结构摘要。
- 参考来源和分析状态。
- “打开对应爆款分析”深链。

没有可核验参考时显示“产品原创”或“缺少参考”，不得生成假的爆款缩略图、播放量或账号。

### 5.2 素材组合预览

展示：

- 已锁定素材的缩略图、名称、类型和授权状态。
- 每条待拍任务和可回填位置。
- 缺素材、授权未知、预算超限等卡点。
- “打开素材与待拍任务”深链。

只要存在必须素材空缺、待拍未回填、授权未知或预算超限，任务显示“任务不能开始”，确认按钮不可用。

### 5.3 效果表达

- 不显示没有统计依据的“爆款成功率”。
- 有足够历史样本时才显示按时完成率。
- 发布前仅显示效果置信度：中、低、数据不足，并列出原因。
- 预计成本和已结算成本严格分开。

## 6. Agent 实况

不新增独立“数字员工”板块。直接在现有“我的 4 个 Agent 现在在做什么”中补充：

- 当前节点。
- 来源。
- 当前结果。
- 下一步。
- 更新时间与任务下钻入口。

Agent 卡表示角色协同，不等同于后台并发数量。真实并发、客户/账号/任务类型限额和排队原因在生产实况中单独展示。

## 7. 任务恢复规则

- 网络超时：指数退避自动重试。
- 余额不足：停止重试，提醒补充余额或更换方案。
- 内容拒绝：保留前序结果，进入人工调整，不用相同提示词盲重试。
- 系统故障：按任务类型分级重试，超过上限转人工。
- 供应商已受理但本地中断：先用供应商任务号对账，禁止重新提交。
- 暂停：完成当前安全检查点后停止，可从检查点恢复。
- 取消：终止未受理工作，保留已完成结果和真实费用记录。

## 8. 验收标准

1. 智能经营开关关闭后无法生成新总纲和新详情，历史与运行中任务仍可见。
2. 第一步生成总纲时不调用编导/内容模型；第二步必须由用户明确触发。
3. 双击第二步只执行一次；刷新后仍看到生成中、已就绪或受阻状态。
4. 用户修改总纲后，旧双预览自动失效并要求重新生成。
5. 每条周任务同时显示爆款视频预览和素材组合预览，且可深链到对应业务页。
6. 存在素材空缺或待拍任务时，卡片明确显示不能开始，并禁止启动制作。
7. 页面不显示虚构成功率、虚构预览或未对账成本。
8. 智能经营以外页面没有账号左栏；现有四个智能经营 Tab 不改变。
9. “我的 4 个 Agent 现在在做什么”展示节点、来源、结果和下一步，不新增重复板块。
10. 内容制作默认“我的创作”，并保留“进入制作”入口。

## 9. 里程碑

- M1：全局开关、账号左栏、四 Tab 保持不变、内容卡密度调整。
- M2：免费总纲与 Agent 详情拆分、持久化双预览、卡点准入。
- M3：Agent 实况四字段、业务深链、手动任务与周计划任务统一显示。
- M4：任务队列、幂等、分级重试、暂停/取消/恢复和供应商对账联调。
- M5：类型检查、合同测试、生产构建和浏览器视觉验收。
