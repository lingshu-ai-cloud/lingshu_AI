# 周 Agent 生产环境接入验收

## 当前结论

周任务图、倒排、共享素材屏障、返工恢复、三渠道客服自动执行、审批和受控发布已在本地集成回归中通过。该证据证明代码链路可执行，不证明某个生产租户已经完成账号授权或真实外发。

当前工作区未加载生产环境变量。运行 `scripts/check-weekly-agent-production-readiness.ts` 的结果为 `ready: false`，七项静态门禁全部阻塞：PostgreSQL 业务数据源、发布原子租约、BullMQ/Redis、生产鉴权、Meta OAuth、Instagram 发布许可、TikTok Direct Post 许可。

## 部署前只读预检

在生产应用容器中加载真实环境变量后运行：

```bash
node --import tsx scripts/check-weekly-agent-production-readiness.ts
```

检查器只返回能力状态和原因码，不返回数据库、Redis 或平台密钥。退出码 `0` 才代表静态配置和数据库原子租约满足发布前提；退出码 `1` 时不得启动真实发布或自动私信。

必须同时满足：

1. `DATA_BACKEND=postgres`，数据库连接可用，且 `durable_operation_leases` 存在有效、立即生效的三键唯一索引。
2. `QUEUE_BACKEND=bullmq`，Redis 使用生产持久实例。
3. 本地鉴权降级关闭。
4. Meta OAuth 已配置，Instagram 内容发布 scope 已经平台批准并显式开启。
5. TikTok 应用已获得 Direct Post 批准，再将 release mode 设为 `approved`。

## 租户运行时证据

静态预检通过后，仍需在同一已登录租户内逐项读取并冻结以下证据：

- 当前周包、版本及完整执行图；
- WhatsApp 已连接账号和明确授权的测试收件人；
- Messenger 已连接 Page、PSID 范围与定时授权；
- Instagram 专业账号、IGSID 范围与定时授权；
- 发布账号 token、provider capability receipt 和平台回执读取权限；
- 每条母版的真实素材、成片、G4/G5/G6、用户批准和发布 assignment。

不得用本地 fixture、预览任务卡、账号名称或 OAuth 配置存在来替代这些持久证据。

## 最小真实验收顺序

1. 只读加载一个专用验收租户及其当周包，确认 Z 或 H 来源配额与冻结版本一致。
2. 对三个客服渠道分别执行 preflight，确认人工接管、窗口、授权与 recipient scope 均允许。
3. 使用明确授权的测试收件人，各渠道只发送一条测试消息；保存 provider receipt 后重复执行，确认发送次数仍为一。
4. 选用一条已批准的验收视频，读取平台发布能力；由用户最终批准后执行一次真实发布。
5. 模拟 provider lost response，只查询原 attempt，确认不会创建第二次发布。
6. 回读平台 post ID、状态和指标归因，再解锁 M8 周复盘。

真实消息和发布属于外部动作。执行第 3、4 步前必须具备用户指定的测试收件人、验收账号和最终发布授权。
