## 2. 已确认的开发方向与主链

采用“保留执行能力、调整计划衔接”的方式，复用已有脚本、语音、素材处理、供应商适配、合成、任务恢复及交付能力。

针对口播驱动的视频，主链为：

**口播与对标结构 → 实际语音与校准 → 分镜定时与执行计划 → 按标签匹配或生产素材 → 合成与检查 → 预览、修改与交付。**

| 节点 | 输入 | 输出 |
|---|---|---|
| ① 口播与对标结构 | 用户目标、企业信息、对标视频及逐镜标签 | 改写后的口播、保留的对标分镜槽、句子与槽位对应关系 |
| ② 实际语音与校准 | 当前口播及声音配置 | 实际音频与逐句时间校准结果 |
| ③ 分镜定时与执行计划 | 句槽关系、实测语音时间、分镜标签 | 当前时间线、逐槽处理路线与执行任务 |
| ④ 按标签匹配或生产素材 | 分镜标签、主题、槽位时间及可用能力 | 已匹配或已制作的素材；尚需拍摄的任务；受阻后的用户上传请求 |
| ⑤ 合成与检查 | 当前时间线、实际音频及可用素材 | 可预览的候选成片与实际执行结果 |
| ⑥ 预览、修改与交付 | 当前候选及用户操作 | 修改记录、接受结果及可读取的交付文件 |

六个节点是业务阶段，不意味着六个独立 Agent、六个队列或逐节点人工确认。

## 3. 新版分镜匹配与生成标准

### 3.1 按对标视频的分镜标签选路

严格按照对标视频的逐镜标签决定素材匹配或制作路线，保留原分镜槽的数量、顺序和口播对应关系。

每句改写后的口播对应一个或多个既定槽。内容 Agent 按槽执行，不自行拆合、增删或重排对标分镜槽。时间根据实际语音校准，不因语速变化另起一套分镜结构。

### 3.2 真人人物口播素材

当分镜标签为真人人物口播时，有以下处理方式：

1. 走真人人物口播的技术栈制作。
2. 列入待拍任务。
3. 由用户指定某一个素材并上传。

前两种方式优先。只有任务受阻时，才采用第三种方式，向用户请求指定和上传素材，不将用户上传作为默认前置要求。

选择规则已确认：本地已有录入且绑定授权的数字人素材时，走真人口播制作技术栈；没有时列入待拍任务。已存在授权数字人但执行能力受阻时，保留真实阻塞并恢复原任务，不擅自换人物或重复付费。用户指定素材上传仍仅作为任务受阻后的兜底。

待拍任务是尚待获取实物素材的任务，不等于已经生成镜头或完成成片。其余可执行节点按实际依赖推进，缺失素材按真实状态展示。

### 3.3 非真人口播素材

非真人口播素材包括工厂实拍、产品实拍、D to C 等，**只要求主题匹配，即可用于生成成片**。

- 工厂标签对应工厂主题素材。
- 产品标签对应产品主题素材。
- D to C 等标签按其对应主题匹配。

不因对标画面出现了某个人或某个动作，就把这些细节追加为本次必须满足的要求。主题匹配后，不再叠加其他对标视觉相似条件作为素材采用或生成准入门槛。

找不到匹配主题的素材时，列为待补素材任务，其他可执行部分继续；不自动换成不匹配主题的素材，不把尚缺素材的整条视频标为完成。

这里“生成成片”包括采用匹配素材进行剪辑合成，不等于每个槽都必须调用模型重新生成素材。

### 3.4 规则边界

分镜匹配只判断：**对标分镜是什么标签，应进入哪类路线；非真人口播素材是否匹配该主题。**

模型、规则或编导不能在上述标准之外，自行增加分镜视觉要求。后续若用户提出新标准，再明确修改本文和对应执行规则。

时间线、文件读写、任务版本、素材使用权限和供应商回执用于正确执行及恢复，不追加为分镜视觉匹配标准；全局视频生成门禁统一按下述第 3.5 节，不保留与其冲突的旧预算、次数或额外批准要求。本文更新不自动改变已运行任务或现行代码。

### 3.5 唯一全局视频生成门禁

用户原文：**“所有全局生视频的门禁全部删除，只留下唯一一条：30秒、15块以内都可以生。”**

本轮产品要求：时长不超过 **30 秒**、费用不超过 **人民币 15 元**，同时满足即可生成。不再要求逐次新增付费批准，不另设返工次数门槛，也不将旧门禁换名继续保留。超过该边界不自动生成；此处的批准简化针对视频生成，不等于授权发布、部署或生产数据迁移。

计算口径已确认：**30 秒按整条成片时长计算；15 元按整条成片累计费用计算，包含此前镜头生成和后续返工。** 不是每个镜头、每次请求或每个返工版本各有 15 元；同一成片的重试、恢复及版本更新不重置已发生费用。

每次新生成或返工前，核对该成片累计费用与本次预计费用：预计累计不超过 15 元时自动审批并执行，不额外要求用户确认；预计累计超过 15 元时，不自动审批或提交该返工任务，转到用户端供用户选择。恰好 15 元仍属于自动执行范围。

| 累计已发生费用 | 本次返工预计费用 | 预计累计费用 | 处理 |
|---|---|---|---|
| 14 元 | 0.8 元 | 14.8 元 | 自动审批返工 |
| 14 元 | 1 元 | 15 元 | 自动审批返工 |
| 14 元 | 1.2 元 | 15.2 元 | 不自动审批，转用户端选择 |

用户端应显示关联成片与待返工分镜、返工原因、累计已发生费用、本次预计费用、预计累计及超额金额，供用户明确决定是否追加费用继续返工。用户尚未决定或不继续时，保留已有产物和待处理任务，不偷偷提交、自动提高额度或重做整片。用户同意后的执行范围绑定其确认的返工任务及费用，不解释为后续无限额授权。

执行记录、费用事实、已有结果复用与未知请求对账仍需准确保存；这些用于准确计算同一累计额度，不作为新增批准流程。并发任务须把已经提交但尚未结算的费用占用计入同一成片，避免多个分镜分别看到同一余额而超支；未知支出不得按零清空，结算时避免重复计数。本次预计值不是已结算实付金额，两者分别展示。

## 4. 口播、时间线与素材的衔接

区分三种时间：

| 时间 | 作用 |
|---|---|
| 对标时间 | 提供原视频的口播与分镜结构、粗时间关系 |
| 成片时间 | 根据当前实际语音校准，确定口播和既定槽在成片中的位置 |
| 素材时间 | 被采用素材内部的截取窗口，与成片位置分别记录 |

语音前可以搜索和整理候选素材；语音后确定最终槽位时间、素材截取和受时长影响的制作任务。

同一份最终时间线供素材处理、人物音频切片、字幕及渲染使用。记录关系应能追溯：口播版本 → 实际音频 → 校准记录 → 分镜槽时间 → 素材及执行任务 → 当前成片。

一个槽不必对应一次付费请求；已有执行器能够复用母片或已完成结果时，可以复用，但不改变对标分镜槽的对外结构。

## 5. 分工与输入输出整理方式

| 责任方 | 本方案中的职责 |
|---|---|
| 编导侧 | 根据对标结构和本次企业信息改写口播，整理分镜标签及句槽关系，不另加分镜视觉要求 |
| 内容 Agent | 按既定标签逐槽选路、匹配主题素材或安排制作；处理受阻情况，不自行增加匹配条件 |
| Worker / 执行器 | 执行已确定的语音、素材处理、制作、剪辑、渲染和保存操作，记录真实结果并恢复任务 |
| 用户 | 提供任务目标；任务受阻时按需要指定和上传素材；通过正常入口预览、提出修改和接受当前成片 |

后续逐节点梳理输入、输出、领取条件、完成状态、受阻原因、恢复与费用记录，不把整理输入输出变成重新引入旧匹配标准。

## 8. 六个节点的最新确认

### ① 口播改写

竞品品牌名称、产品名称和竞品独有资质等相关关键词必须替换。替换使用本企业实际信息；无对应资质时移除或改写该表述，不把竞品资质转写为本企业拥有。改写后自动继续，不增加用户确认步骤。

### ② 实际语音与校准

用户明确本节点不设语音质量门槛：不对漏读错读、声音一致性、停顿差异等另设质量分数、阈值或自动返工条件。实际音频和校准仍作为下游输入；音频或时间数据缺失属于任务尚未完成，按实际错误恢复，不能伪造精确时间。这一必要输入条件不是重新增加语音质量验收。后续若在成片检查或用户验片中发现口播错漏，按用户最新确认列为必须修复的问题，不因本节点无独立质量门槛而忽略。

### ③ 槽位与精确时间

必须明确每句口播与既定槽位的对应关系，并使用实际口播语音时间轴，经语音校准取得精确时间戳。该输出直接用于下一步素材匹配、截取与生成任务定时，不以对标粗时间代替。

### ④ 两类素材及标签缺口

按第 3 节区分真人人物口播和非真人口播素材；非真人口播素材只按主题匹配。真人人物口播是否走技术栈，由本地是否已有录入且绑定授权的数字人素材决定；没有则待拍。

标签缺失时先自动补充分析，仍无法确定再询问用户，不猜标签执行。这是分析结果补齐，不让用户逐镜填写额外视觉要求。

### ⑤ 成片检测：音画同步与字幕样式抽检

以下为用户最新确认，替换此前字幕内容、字幕起止时间及字幕完整显示/裁切检查方案，不保留为并行门槛。

#### 音画同步

画面切点对应最终槽位时间线，局部及全片累计时间偏移容差均为 **0.3 秒**；不另做嘴形评分。超限先定位剪辑或合成原因，不默认重新生成语音或镜头。

已接入0.3秒判定和实际测量端口合同；生产测量适配及正常页面验收尚未完成，不宣称实链通过。

#### 字幕仅检查字体、字号、颜色

不检查字幕内容，不进行错字、漏句、重复等文本比对；不检查字幕与实测句子的起止偏移、字幕完整显示或裁切。不把字幕时间检查借音画同步之名重新加入。

字幕样式检测对照本条视频采用的字体、字号和颜色，优先沿用现有渲染配置，不新增样式选择步骤或设置页面；实际配置值由开发侧核对。不擅自新增内容、美观、位置、行数、对比度等检查项目。

抽检规则：

1. 在整个视频中任意抽取两帧，仅检测上述三项样式。抽到无字幕画面时，重新抽取有字幕的帧；无字幕帧不计作样式失败，也不占本轮有效样本。整片都没有字幕时，任务显示受阻，在详情中说明无字幕并等待用户介入或确认。
2. 两帧都通过：字幕样式项通过，不再抽第三帧。
3. 两帧中任意一帧不通过，或两帧都不通过：再抽取第三帧。
4. 第三帧通过：本项通过；第三帧仍不通过：本项受阻，等待用户介入或确认。不采用“累计两帧失败就直接判定失败”或“必须三帧全过”等其他规则。
5. 保留当前成片版本、抽样帧及各项结果，用于任务详情读回；用户确认必须针对实际验看的当前版本。

受阻时必须同时体现在两个正常产品入口：

- **Agent 周任务表格**：该项任务显示“受阻”。
- **任务详情**：定位到字幕样式检查节点，显示“需要用户介入或确认”，展示抽样帧及字体/字号/颜色的不通过项。等待用户处理或明确确认，不自动标记通过、整片重做或付费重试。

#### 与此前问题修复范围的关系

此前用户确认的无法播放、漏镜、实际口播错漏及音画时间错位仍需修复；“字幕明显错误”在本轮自动检测中按上述样式抽检范围执行，不扩展为字幕内容或字幕时间检查。用户验片主动指出的其他问题仍可按对应节点修改。

必须修复不等于必须重新生成整片或重新付费；确需生成视频时只按第 3.5 节计算生成边界，不追加逐次付费批准或返工次数门禁。先定位原因：时间问题修剪辑/合成，实际口播错漏修受影响口播及相关时间线，镜头问题才重新匹配或生成该槽。字幕样式受阻按用户介入/确认流程处理。

### ⑥ 用户验片与交付

**联调阶段必须由当前用户明确确认接受当前成片，才算交付完成；不能由 Agent 自动代为接受。** 这是成片接受边界，不要求制作过程中每个节点都询问用户。

允许用户接受剩余偏差，但不自动略过第⑤节点中必须修复的问题或受阻状态；字幕样式抽检受阻可由用户处理或明确确认，不能由 Agent 代确认。客户/用户验片后，有镜头问题则回到对应分镜重新生成或重新匹配，其他问题按原因局部修复，并重做受影响的合成；无问题则由用户直接接受、下载和归档。不要求消除所有非关键偏差后才能接受，也不把修改默认扩大为整片重做。用户确认应绑定其实际验看的成片版本，修改后的新版本重新验看和接受。

## 9. 标签可能缺失的代码核对

这是静态代码排查，尚未定位到某个实际任务的根因。

- [benchmarkAnalysis.ts](../../shared/benchmarkAnalysis.ts) 读取上游 `gemini.scriptDetails15s` 的逐镜 `materialType`。未知或不支持的值会规范化为 `unknown`；明确传入 `unknown` 时会保留，不用推断强行覆盖。
- 历史记录可能没有该字段，程序尝试从既有画面描述推断；描述不足时仍返回 `unknown`。有具体画面但不属于专门类型时可归为 `general`，它不等于缺标签。
- 缺少分类依据也会标记待补齐，即使已有一个标签；“标签缺失”和“标签存在但依据缺失”应分别展示。
- [socialContentAssetSupply.ts](../../shared/socialContentAssetSupply.ts) 还存在从供给请求、参考及视觉描述再次分类的路径，无法判定时也返回 `unknown`。因此不一定是编导漏写，也可能是上游分析、历史数据或字段传递不完整。
- 当前 `consumer_demo` 显示为 D2C，可作为核对用户 D to C 素材标签的现有字段线索；不据此增加人物或动作匹配要求。

后续实现应检查上游结果和实际字段传递，再执行用户已确认的自动补分析策略；不能只给编导提示词追加“必须填标签”就声称问题已解决。

## 10. 节点输入输出与接续合同

六个节点不等于六次模型推理。编导负责口播和结构，内容 Agent 负责在既定槽内实现，确定性的校准、时间计算、渲染及抽检由 Worker 执行。复用现有 brief、baseline、execution plan、job/checkpoint、artifact 与接受回执，不另建一套平行任务系统。

| 节点 | Agent / 执行器输入 | 输出与完成条件 | 受阻及接续 |
|---|---|---|---|
| ① 编导口播与结构 | 对标逐镜分析及标签、原口播、本企业资料 | 企业口播版本、固定槽及标签、句槽对应；改写后自动继续 | 标签缺口先补分析；仍不确定才询问用户。竞品专属信息不得冒用 |
| ② 语音与校准 | 当前口播版本、句子/槽关系、声音配置 | 可读取实际音频、内容哈希、校准记录与时间轴；不新增口播质量评分 | 数据未返回则按原任务恢复，不伪造时间；结果进入③ |
| ③ 内容侧定时与计划 | 实际语音及校准、固定句槽关系、对标标签、可用素材/授权数字人 | 每槽时间及其来源、主题、处理路线、任务身份；下游可以直接消费 | 缺人物待拍，缺主题素材待补；缺校准先修输入，不用平均时间假装实测 |
| ④ 内容侧匹配与制作 | 当前槽及时间、标签/主题、现有候选、累计费用 | 采用媒体与截取区间、生成/拍摄/补素材任务、回执和费用 | 超15元转用户选择；已完成结果保留，其他独立工作按真实依赖推进 |
| ⑤ 合成与检查 | 当前时间线、音频、各槽素材、实际字幕样式 | 当前候选及其哈希、0.3秒同步结果、2/3帧样式报告 | 按已定规则修复或受阻；周表和详情需要显示节点原因及介入操作 |
| ⑥ 用户验片与交付 | 当前候选与检查结果、用户修改/接受动作 | 对应槽的修订任务，或绑定当前版本的接受和交付结果 | 不代用户接受；修改版本后重新验看，下载/归档与接受版本一致 |

所有交接至少关联租户、task/run/job、槽位、输入版本及哈希、实际产物、结果状态、下一责任方。完成必须有可消费结果，不能仅返回“已完成”。修改时只使受影响的结果失效；已有产物、费用与未知请求先核对再继续。
