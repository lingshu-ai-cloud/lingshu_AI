# 1014 周任务—Agent 协作—成片交付链条开发基线

> 日期：2026-10-14
> 状态：开发执行中
> 范围：周任务、编导 Agent、内容 Agent、持久队列、LangGraph、成片验收与交付
> 原则：不降低生产门禁，不用页面状态冒充生产事实，不用测试夹具冒充真实成片。

## 1. 当前结论

底层单条内容制作具备素材匹配、数字人/AIGC、FFmpeg 合成、局部修复、成片质检和交付导航能力。审计确认周任务到内容生产的服务端接棒逻辑有效：此前 16 节点测试停在 `content_production=pending`，原因是旧测试夹具缺少当前生产门禁要求的逐镜分类证据，被严格参考分析门禁正确拦截，并非生产调度器回归。

当前验证结果：

- Agent 内容生产交接合同：5/5 通过；
- 制作、局部修复、重新渲染和质检测试通过；
- 成片资源和交付导航测试通过；
- 客户分层与跟进草稿测试通过；
- 更新为合格逐镜证据后，16 节点整链测试完整通过，且显式验证 `viral_analysis → content_mode_routing → content_production`；
- 本地运行环境尚未启用 Starter Worker、定时发布 Worker，视觉质检 Python 依赖也未就绪。

历史 MP4 和自动化测试证明单条制作底座与代码级接棒可用，但仍不能证明当前本机能自动产出真实成片。当前运行环境明确关闭 Starter Worker 和定时发布 Worker，且缺少视觉质检 Python 能力；因此“代码链通过”和“真实运行链就绪”必须分开表述。

## 2. 理想产品效果

用户确认周计划后，系统只创建一个权威周运行，并将每条内容拆成独立生产任务：

1. 经营 Agent 冻结目标、数量、账号、预算、发布时间和成功标准；
2. 编导 Agent 完成参考分析、脚本、分镜、账号风格和验收标准；
3. 编导 Agent 输出不可变、带版本和哈希的 `ProductionPlan v1`；
4. 内容 Agent 只读取该计划，完成素材/能力路由和逐镜制作；
5. 缺客户实拍素材时生成结构化 `ReshootRequest`，其他内容继续运行；
6. 付费调用前一次性返回当前内容全部硬缺口和冻结预算；
7. 内容 Agent 完成逐镜生产、合成和技术质检；
8. 编导 Agent 验收表达、账号风格与计划一致性；
9. 成片以 `FinishedFilmArtifact` 进入待验收队列，绑定文件哈希、时长、输入/清单哈希和质检回执；
10. 用户验收后生成平台发布包。账号或发布授权缺失只阻塞发布，不阻塞成片生产。

统一用户进度固定为：爆款分析、脚本确认、素材匹配、口播与字幕、数字人生成、视频合成、成片质检。节点完成必须指向真实产物或不可变回执。

## 3. 目标技术架构

采用三层结构，不新增第四套平行编排：

### 3.1 确定性业务状态机

负责周/月计划、预算、账号、授权、依赖、发布时间、人工接管和最终业务状态。数据库是唯一事实来源，LLM 不决定状态迁移。

### 3.2 持久任务队列

负责唯一入队、租约、fencing、并发、暂停、恢复、重试、对账和 dead letter。本地继续使用现有 durable queue，生产使用 BullMQ/Redis；任务只携带稳定身份，不携带可漂移的完整业务对象。

### 3.3 小而明确的 LangGraph

每条内容一个图，不创建覆盖整周的超级图：

- 编导图：经营上下文 → 参考分析 → 脚本 → 分镜 → 账号风格检查 → 冻结 ProductionPlan；
- 内容图：预检 → 素材与能力 → 首帧/关键帧 → 数字人/AIGC → 单镜质检 → 合成 → 成片质检 → 人工验收 → 交付；
- 客服图：真实会话 → 阶段/风险 → 回复草稿 → 商业承诺检查 → 审批 → 发送 → 平台回执。

LangGraph 负责节点内部编排和人工中断；周任务负责决定做什么；队列负责可靠执行；数据库负责事实。

## 4. 统一交接合同

Agent 之间禁止依赖自然语言“默认接棒”，统一交换版本化产物：

- 经营 Agent → `WeeklyContentItem` → 编导 Agent；
- 编导 Agent → `ProductionPlan v1` → 内容 Agent；
- 内容 Agent → `FinishedFilmArtifact` → 编导/经营验收；
- 内容 Agent → `ReshootRequest` → 小程序待拍；
- 经营 Agent → `PublicationPackage` → 发布 Worker；
- 客服 Agent → `QualifiedInquiry` → 经营 Agent。

所有交接产物至少包含：

```ts
{
  artifactId: string;
  artifactType: string;
  tenantId: string;
  runId: string;
  taskId: string;
  version: number;
  inputHash: string;
  outputHash: string;
  createdByAgent: string;
  createdAt: string;
  evidenceRefs: string[];
}
```

`ProductionPlan v1` 还必须冻结 content/scene/product/presenter 身份、脚本与分镜版本、参考分析修订、逐镜来源路线、预算、供应商选择和稳定请求键。

固定一条低成本真实任务，保存周计划 ID、ProductionPlan 哈希、图 thread ID、节点检查点、供应商请求/费用回执、MP4 SHA-256、质检回执、人工验收和交付产物 ID。连续完成三次，其中至少一次中断恢复和一次单镜重做，才认定链路稳定。

执行状态（2026-10-14）：验收机制已落地，真实三轮尚未记为通过。

## 9. Agent 周任务小时历产品共识

主视图继续使用周小时历。日历必须表达真实任务、真实状态和真实交付物，不把计划占位、等待时间或页面推断冒充生产事实。

### 9.1 统一三行任务卡

所有任务卡使用同一种三行结构，不按任务时长设计多套尺寸：

1. 第一行：任务类型、负责 Agent、右上角真实状态；
2. 第二行：真实任务主题或交付物名称；
3. 第三行：执行窗口与当前阶段。

影片生产卡的内容名称只能读取冻结的 `ProductionPlan`、已确认脚本或已确认选题。前端禁止临时编造“视频 01”“卖点视频”等名称；上游内容尚未冻结时，显示“选题等待编导确认”等真实等待原因。

### 9.2 时间和状态语义

- 当前时间之前且已有权威完成回执的任务，在右上角显示绿色勾；
- 当前时间之前但没有完成证据的任务显示“逾期”，不得按时间自动完成；
- 当前执行、等待人工、阻塞、未来计划和取消分别使用清晰且互斥的状态表现；
- Agent 类型只使用左侧色条或小标签，卡片主色用于表达状态；
- 当前时间显示横向时间线，过去区域适当降低饱和度，但逾期任务保持突出；
- 发布、拍摄、人工验收使用精确时间；异步生产只显示短启动/执行窗口和预计完成时间，不能用六小时长卡表示供应商等待。

### 9.3 排期约束

- 同一 Agent 的任务不得重叠；
- 同一内容的采集、编导、生产、质检、验收和发布按依赖顺序排列；
- 默认通过错开开始时间避免同一时刻堆叠卡片；
- 只有无法重新安排且确实并行的不同 Agent 任务才允许并列；
- 日历日期范围必须与当前周计划范围一致；
- 真实任务数、计划占位数、待人工数和逾期数分别统计，计划占位不计入真实任务。

### 9.4 周目标与每日滚动生产

周计划只冻结本周目标、产能、重点产品、平台、预算、发布频率、内容类型比例和人工确认边界，不在周一一次性生产整周内容。

每天形成独立滚动闭环：

1. 增量采集上次采集之后的新对标视频，并更新已有内容的表现；
2. 分析当天趋势和有效结构；
3. 结合企业产品事实确定当日选题；
4. 编导 Agent 生成并冻结脚本、分镜和验收标准；
5. 内容 Agent 在短执行窗口内生产成片；
6. 完成技术质检、编导验收和必要的人工确认；
7. 进入当天或后续最佳时段的发布队列；
8. 将播放、互动和询盘结果反馈给下一日采集与选题。

每天只生产当天所需内容和少量次日储备。已验收并进入发布队列的内容保持稳定；当天新趋势只能调整尚未冻结的后续内容。每日采集采用增量与去重策略，保留来源、发布时间、采集时间、分析版本和历史采用记录。

### 9.5 2026-10-14 实现进度

- 执行任务按“账号 + 发布日”生成每日增量采集，冻结增量范围、去重策略和当日发布任务集合；
- 同一内容在不同日期复用时，每天分别生成新的采集、评分和编导决策，不沿用周一分析结果；
- 脚本任务强制依赖当日编导结果，后续分镜、生产、质检、验收和发布保持依赖链；
- 每条发布任务生成独立的当日数据回收任务，结果作为下一日采集和选题输入；
- 小时历统一三行卡片，真实任务和计划占位分层显示，完成、进行中、逾期使用独立状态；
- 产品合同测试覆盖真实任务计数、计划空槽、待人工、逾期、同 Agent 冲突、每日采集与生产。

## 10. 一对一生产现场闭环开发与测试排期（2026-10-15）

### 10.1 产品理想效果

周任务中的每一条真实执行任务必须一对一拥有一个持久化生产现场。日历卡片只负责定位任务；点击卡片后统一进入该任务的生产现场，再从生产现场进入知识补齐、参考采集、编导、素材、成片制作、质检、人工验收、发布、客服承接或复盘页面。

生产现场必须满足以下合同：

- 稳定身份由 `tenantId + programId + packageId + packageVersion + executionTaskId` 唯一确定；
- 一条执行任务只能有一个生产现场，一个生产现场只能归属一条执行任务；
- 任务创建成功时同步创建生产现场，不能等用户点击时临时拼装；
- 生产现场记录当前任务、上下游任务、真实阻塞原因、已有业务对象引用和可执行动作；
- 上游尚未冻结当日选题、脚本、分镜或成片时，只显示真实等待关系，不预造内容任务、成片、发布回执或成功状态；
- 任务状态变化后，生产现场以执行任务和权威业务对象重新对账，不维护第二套独立业务状态；
- 历史周包可执行显式补建，但读取接口不得偷偷写数据；
- 灰色计划占位不是生产现场，也不得计入真实任务闭环覆盖率。

生产现场阶段统一为：`等待上游`、`可执行`、`执行中`、`等待人工`、`阻塞`、`已完成`、`已取消`。页面至少展示任务身份、负责智能体、冻结时间、依赖、阻塞、业务引用、最近回执和下一步动作。

### 10.3 测试矩阵与放行门槛

1. **持久化合同**：创建、恢复、重入、部分写入回滚、历史补建、分页完整性、唯一索引。
2. **身份与权限**：租户、项目、周包、版本、任务五层完全匹配；登录身份变化时拒绝迟到响应。
3. **状态对账**：阻塞、排队、租约执行、等待人工、成功、失败、取消和 dead letter 均映射到唯一生产现场阶段。
4. **业务引用**：只接受数据库中真实存在且归属一致的内容任务、运行、成片、账号、会话、复盘和回执引用。
5. **导航闭环**：每张真实卡进入生产现场；生产现场返回日历时恢复原卡位置；领域动作进入现有真实页面。
6. **每日生产链**：每日增量采集 → 当日主题 → 脚本/分镜 → 素材/制作 → 质检/验收 → 发布 → 数据回收；周一经营准备在首日生产前，周日复盘在全周发布与回收后。
7. **故障恢复**：上游缺失、Worker 重启、供应商未知结果、回写失败、人工中断、输入漂移、重试和取消均不可制造重复任务或重复付费。
8. **真实性门槛**：受控测试只证明代码路径；实际供应商调用、MP4、发布和平台回执必须保存真实身份与哈希，不能用模拟数据冒充通过。

放行条件：`生产现场数 = 真实执行任务数`、孤儿数为 0、重复数为 0、所有卡片均可进入、所有业务引用可回查、全链卡点清单全部关闭。若真实外部能力因凭据、授权或费用未启用，评审结论必须保持“外部验收阻塞”，不能写成上线完成。
