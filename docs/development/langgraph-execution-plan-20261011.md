# LangGraph 加强版实施计划

## 启动前提

总合并分支固定最新本地源码快照与传入 872f2595。功能、安全、生产恢复和构建验证完成后，需明确既有超长文件架构债的处理范围。当前没有开始运行代码迁移，也未添加 LangGraph 依赖。

## 接入边界

新周生产链路为 createDefaultWeeklyExecutionAdapters → createSocialWeeklyProductionAdapter → Starter198 编排 → content_execution_jobs。优先在 socialContentProductionQueue 的 executePersistedProduction runner 边界接入；不只修改旧 advanceOneProject 路径。

保留外层 DurableContentExecutionWorker 的持久化租约、并发限制、重试分类、暂停/取消及数据权限作用域。不得让图另起一套供应商重试循环。现有 ContentProviderReceipt 继续作为已付费操作的对账依据，业务产物和审核记录继续作为交付事实依据。

## 并行责任分配

1. 执行基础：运行身份、状态 schema、LangGraph 图、checkpoint 持久化及序列化验证。节点边界与现有阶段映射明确，不把现有单体函数包装后声称逐镜恢复已完成。
2. 生产接入：固定执行器选择、现有队列 runner 接入、供应商适配器与审核/版本门槛。旧运行留在原执行器，新运行按开关选择一次；重启不得因开关变化改换执行器。
3. 故障验证与状态投影：跨进程恢复、供应商接受后写入失败、租户隔离、并发领取、人工改方案、审批重启和现有 API 投影。与既有页面契约复用，不自动通过审核。
4. 主 Agent：依赖和锁文件、跨模块整合、代码审查、最终测试与额度记录。

上述为后续 Agent 任务划分，不表示它们已经开始实施。

## 第一段交付

先完成运行基础及受控单链路验证，记录实际额度和未完成项目。复用 TypeScript、Express、现有数据库和供应商端口，不改写普通 CRUD。默认开关关闭，不自动部署或调用真实付费供应商。

运行身份必须绑定 tenantId、taskId、runId、方案版本和图版本。checkpoint 只保存必要状态与产物引用。恢复权限、当前方案与供应商状态必须重新核查；未知提交状态进入对账，不能盲目新建。

首段额度上限沿用提议的单份周额度 15%；起止读数是账户共享消耗，不能精确归因。本段达到预算或验证检查点后报告具体完成范围，不能把基础骨架称为生产迁移完成。

## 验收门槛

- 重启恢复同一运行，不重复创建付费任务。
- 单镜头失败保留有效结果，重做必要范围。
- 人工审核跨重启有效，调用者租户与方案版本校验有效。
- 修改方案有明确失效范围，不复用失效产物。
- 重复请求/队列重投只有一个执行器，租约丢失停止副作用。
- 现有 GET 状态查询保持只读，成功以业务证据判断。
- 模糊供应商回执不自动重发，不绕过素材/产品/人物身份校验。
- 新代码满足架构边界，功能开关关闭时现有行为回归通过。

生产标准单链路还需真实受控验收，不能仅凭 mock 和构建宣布生产可用。
