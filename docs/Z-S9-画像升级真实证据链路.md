# Z-S9 画像升级建议

本链路读取当前项目真实自有账号、已发布平台视频及其播放、点赞、转发、评论快照。账号存在、制作库存、未发布视频不构成升级证据。平台、发布时间、采样时间和观察时长与四项数值一起展示；真实零值保留，未知不转换为零。尚未定义自动判定强弱的阈值，服务不自动判断增长停滞或获客能力。

经营用户明确选择依据并填写判断理由：调性清晰且增长停滞选择自有40%/外部60%；历史素材不足或互动表现弱选择20%/80%。40/60另需原自有视频的真实不可变编导handoff证明调性；四项指标不完整、调性缺凭据时保留缺口。理由是用户运营判断，四项互动数据不证明获客效果。

建议与用户确认记录绑定当前周包版本、实际证据hash和唯一下一周开始日。确认及消费重新核验实际视频、快照和handoff；数据漂移需重新审查建议。下一周已存在任务包不能再消费升级。下一周create显式提交profileUpgradeRef，服务取得真实receipt后生成有基础周包；当前项目route和当前周包100%外部来源不修改，当前周revision也拒收升级引用。

## 登录切换与回执核验

建议读取、提交与确认都绑定原周包范围和发起时登录。即使组件尚未重新渲染，登录变化后的迟到返回也不能刷新原页面或解除待核验状态。API 回执同样核验发起与返回时的授权身份；确认响应丢失不自动重复提交，只读查询原建议。4 项定向测试通过，覆盖实际异步确认回执在切换登录后被拒绝且仅发起一次请求；该证据不代替真实租户浏览器与下一周创建验收。

## 创建结果只读查回

下一周创建显式提交稳定请求身份、IANA 时区及每条新发布目标。服务保存实际升级消费凭据，绑定原确认、创建者、输入摘要、新任务包身份和初版发布目标。客户端在结果未知时只读查询该请求；没有查到仍保持未知，不猜任务包、不自动重发创建。服务拒绝复制旧发布身份、旧日期及旧素材/承接绑定，并核验明确目标与权威配额生成目标逐项对应。真实服务夹具已验证创建后只读查回与客户端回执解析；此测试没有激活周包或执行平台发布。前端完整下一周目标配置/建包入口仍待接入。

## 新周规划不能借用旧周容量

新生成的经营规划快照记录实际 `planningWeekStart`。周包创建/修订时，如输入目标周与该快照的实际规划周不同，服务拒绝保存，要求重新生成目标周规划。旧快照没有该字段时仍保留“未知”，不根据当前日期补写。新周建包前端必须取得目标周的新规划并校验其日期；当前周已冻结的目标、来源比例及发布身份不被修改。
