## 验证及后续接入

```bash
node --import tsx scripts/verify-licensed-materials.ts
```

验证器串行进行文件哈希、实际视频流解码、10 帧基础画面检查和源片区间覆盖验证；生成 `verification.json` 与抽帧，不调用模型、配音、业务数据库或外部发布接口。

追加 `--render` 可调用实际渲染器串行生成两条 25 秒技术验收片（9:16、16:9）。每个镜头烧录第三方行业示意声明，使用真实源片区间，并按原成片门槛检查至少三组差异画面、50% 清晰帧和完整视频流时长。每次使用独立 `render-check-*` 目录，成功或失败均保存 MP4 和 `render-verification.json`。这两条片无配音，不调用业务工作流，不能算原冻结订单或完整端到端验收通过。

```bash
node --import tsx scripts/verify-licensed-materials.ts --render
```

清单提供两条各 25 秒的行业示意选段方案（为 20 秒目标预留时长余量），跨两条统一游标，源片区间不重复、原速、不定格补长。此方案仅证明素材覆盖，不保证未知配音长度，也不是最终成片三场景质检。

下一步应以“第三方授权行业示意”新建/修订素材型内容订单，保留来源与用途，文案或画面说明行业示意。不要用 `DIGITAL_EMPLOYEE_E2E_OWNED_VIDEO` 或企业产品上传入口直接装入本包：现有入口会把上传素材标成企业自有。

原冻结的产品实拍订单未被修改，付费端到端验收未重跑，尚不能据此宣布原订单、两条成片或功能上线验收通过。接入时还需让授权来源和“非产品证据”标记贯穿选材、脚本、审批及导出，并保持原成片门禁。
