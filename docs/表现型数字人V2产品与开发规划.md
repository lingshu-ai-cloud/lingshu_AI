# 灵枢表现型数字人 V2 产品与开发规划

更新日期：2026-09-03

状态：P1.4 内部验收已通过；三语成片和服务器可信门禁已闭环，商业发布仍需替换为企业完整授权人物并完成规模化回归
前置版本：数字人第一版（口型闭环）

阶段性样片记录见《表现型数字人V2-P0验收报告》。复查确认该样片仅证明离线分段口型与合成实验可运行，不能证明网页、服务器、多动作 Worker 和真实表现力门禁已经形成产品闭环；当前版本不得标记为可灰度或可上线。

## 0. 当前已落地能力与使用边界（2026-09-03）

本节只记录已经进入代码并通过对应合同/单元检查的能力，不把“接口可用”写成“成片验收完成”。截至本次更新，中文、英文、西班牙语三条完整 15 秒数字人成片尚未全部产出并完成人工质量复核，因此不得据此宣称三语样片、商业灰度或上线验收已经通过。

### 0.1 已落地的基础能力

- **多语种原子分镜批处理**：同一分镜可由一个请求提交多个语言变体；租户、人物、授权用途、音频、时间区间、脚本、表演计划、动作和输入签名全部校验成功后，服务器才一次性发布所有新增子任务。任一变体校验失败时不写入半批任务；每个语言仍保留独立子任务、状态、签名、重试和结果，8GB 本地 GPU Worker 继续逐个领取，不把“批处理”误解为显存并发。
- **Windows→WSL 中文 TTS 安全传输**：服务端把口播正文按 UTF-8 编码为 Base64，并使用 `--text-base64` 交给本地 Qwen3-TTS Runner；Runner 严格执行 Base64 与 UTF-8 解码，同时兼容既有 `--text` 调用。合同测试以真实 WSL 进程验证中文字符数、UTF-8 字节数和 SHA-256，输出与日志不回显口播正文。该能力证明中文传输链路已修复，不代表三语完整成片已验收。
- **生产授权门禁**：单任务与批任务在创建前均校验人物 `productionReady`、`rightsStatus=商业授权有效`、明确的 `usagePurpose`、用途范围、租户归属和授权确认；动作片段必须属于同一人物且覆盖相同用途。任一条件不满足即拒绝创建，不能依靠前端提示绕过。
- **安全渲染与签名下载**：服务器从租户素材索引重新解析时间线，不信任浏览器传入的任意素材 URL；渲染清单使用租户、任务、画幅、时长和清单 SHA-256 形成短期授权，并只暴露同源、租户隔离的素材代理。渲染只读取已保存的不可变清单；输出文件限制在租户发布目录，并通过带时效签名且强制下载的地址返回，不向网页暴露本地绝对路径。

### 0.2 默认人物 6548010 的严格边界

当前默认人物 `avatar-pexels-6548010-v1`（素材编号 6548010）仅用于内部技术演示和管线调试。其素材记录即使显示 `commercial_cleared` 或 `productionReady=true`，授权用途仍被限定为 `internal_preview`；`productionReady` 只说明素材技术预检可进入其已授权用途，绝不扩大授权范围。

- 禁止用于客户交付、付费投放、自然社媒发布或对外商业宣传；
- 禁止用人物姓名、台词、字幕、封面或上下文暗示其本人认可、推荐或代言灵枢、房地产项目及任何商品；
- 内部样片应明确标注“AI 生成 / 内部技术演示 / 非真人代言”，且不得被销售或运营误取为正式资产；
- 创建 `customer_delivery`、`paid_media` 或 `organic_social` 任务时，服务端用途门禁必须拒绝该人物，不能由人工勾选临时放行。

### 0.3 正式生产必须使用企业自有人物 IP

客户交付和正式发布默认且必须使用企业自有人物 IP，即企业自有员工、签约模特或另有明确书面商业授权的人物资产；平台示例人物和来源不明的公开视频不能替代。人物母片、动作片段、声音、肖像、台词合成、使用地域、使用期限、客户交付、付费媒体与社媒发布等权利必须形成可审计的版本快照，并由服务端按本次任务用途逐项校验。缺少企业自有人物 IP 或证据不足时，只能停留在内部预览，禁止降级绕过后继续生产。

## 1. 产品结论

数字人第一版已经打通网页、服务器、本地 GPU Worker、口型生成、质量门禁和结果回流，但当前实现属于“保留原动作的视频口型替换”，不能根据脚本产生新的眉眼、头部、手势和身体动作。

V2 不继续把 MuseTalk 当作完整数字人引擎，也不直接把大型全身生成模型作为商业主链。推荐采用可分层回退的混合生产方案：

`脚本表演规划 → 人物动作素材匹配 → 可选表情/头姿增强 → 口型同步 → 绿幕/场景合成 → 表现力质量门禁 → 分镜回填`

当前 RTX 5060 8GB 的默认生产模式为“授权真人动作模板 + MuseTalk/LatentSync 口型”。生成式半身、全身方案在独立高显存 Worker 上验证成熟后再灰度接入。

### V2 产品目标

- 用户逐分镜选择“数字人口播”后，无需额外配置即可得到与脚本语义匹配的表情、动作和场景。
- 同一人物在不同分镜中能够自然切换讲解、微笑、点头、强调、指向、计数和 CTA 等表现。
- 保留人物身份、声音、授权、脚本、动作来源、引擎版本和质量结果的完整追溯链。
- 生成失败时自动换动作、降低强度或回退稳定方案，不向客户返回不合格结果。
- 不改变现有分镜卡、脚本、配音、字幕、成片和发布流程。

### 非目标

- V2 第一阶段不承诺从单张照片稳定生成任意全身复杂动作。
- 不要求用户理解或选择底层模型、随机种子、绿幕参数和质量阈值。
- 不在本阶段执行服务器部署。
- 不允许使用授权不清晰的人物、声音、动作模板或非商业模型权重。

## 2. 用户交互

数字人入口只在脚本生成后的“素材匹配”阶段出现：

```text
当前分镜画面来源

[ 素材画面 ]   [ 数字人口播 ✓ ]

人物：[头像] 云栖置业顾问 · 首选人物    更换
状态：正在按脚本生成表情、动作和场景……
```

交互规则：

1. 用户点击“数字人口播”后，系统立即使用企业知识库中的首选人物并在后台生成当前分镜。
2. “更换”只打开人物资产库；选择人物后自动重做当前分镜。
3. 人物选择器内提供二级操作“应用到全部数字人分镜”，不增加常驻按钮。
4. 上传、授权、设为首选、人物表演包管理只在企业知识库完成，创作页不重复出现。
5. 脚本、配音、人物或表演计划变化时，只使受影响分镜失效并重新生成。
6. 正常状态只显示“生成中 / 已就绪”；自动纠偏过程静默执行。
7. 多次自动纠偏仍失败时，显示明确原因并允许用户更换人物或改用普通素材。
8. 预览后仅保留“调整表现”入口，提供“更自然 / 更有感染力 / 换一个动作”，不暴露专业参数。
9. 点击“数字人口播”只预生成当前分镜；最终仍由现有“生成成片”动作等待并复用合格结果，不新增数字人专属生成按钮，也不自动导出整片。
10. 人物解析优先级固定为“分镜覆盖 > 当前项目人物 > 企业首选人物”。“应用到全部”只修改当前项目；企业首选人物后续变化不能污染已创建项目。
11. 每个任务保存人物、表演包和授权的不可变版本快照，禁止运行中的任务跟随资产库最新状态漂移。

后台状态：

`待生成 → 规划表演 → 选择动作 → 等待本地算力 → 本地 GPU 生成 → 场景合成 → 质量检测 → 已就绪`

本地 Worker 离线或无满足能力的 Worker 时，页面必须显示“等待本地算力 / 暂不可用”，不能无限静默。

## 3. 人物资产升级：从单视频到人物表演包

用户看到的仍是一个人物 IP，系统内部拆分为人物身份与多个动作片段。

### 3.2 推荐人物母片标准

- 原生 9:16，推荐 1080×1920、25 或 30 fps、H.264。
- 胸部以上中近景为主，人物始终位于画面安全区。
- 固定焦距、固定曝光、固定白平衡和稳定灯光。
- 同一表演包保持同一衣着、机位、人物尺度、构图和背景条件。
- 优先绿幕；也允许干净静态背景自动分割。
- 一个人物表演包至少覆盖：自然讲解、微笑、点头、强调、左右指示、计数、CTA、自然待机。
- 单条动作建议 5–12 秒，动作前后保留可拼接的中性姿态。
- 嘴和脸无遮挡；不做快速转身、手穿脸和出画动作。
- 原始录音只用于动作分析，正式生成时丢弃并使用已确认配音。
- 人物、声音、动作和商品均必须有明确授权记录。

### 3.3 最简录制与导入

企业知识库支持两种方式：

1. P0 上传多条已经人工精选和分类的人物动作视频；
2. P1 上传一条 60–90 秒标准录制视频，由系统自动完成动作切分、标签、循环点、进出姿态、绿幕缓存和质量预检。

人物卡只展示“自然讲解、强调、指向、CTA”等能力标签，不向普通用户暴露底层片段列表。

## 4. 脚本到表演计划

现有脚本已经包含环境、景别、运镜、构图、动作和台词信息。V2 应保留这些结构化字段，并在服务器生成版本化的表演计划，禁止本地 Worker 自由猜测。表演规划必须发生在最终 TTS/配音、字词级时间戳和情绪韵律确认之后；任何音频或时间戳变化都应使对应表演计划和数字人结果失效。

```ts
interface DigitalHumanPerformancePlan {
  version: 'performance-v1';
  preset: 'natural' | 'professional' | 'commerce';
  beats: Array<{
    startMs: number;
    endMs: number;
    intent: 'hook' | 'problem' | 'benefit' | 'proof' | 'transition' | 'cta';
    emotion: 'neutral' | 'friendly' | 'confident' | 'concerned' | 'excited';
    intensity: number;
    expression: 'neutral' | 'slight_smile' | 'brow_raise' | 'concern' | 'firm';
    head: 'hold' | 'nod_once' | 'tilt' | 'turn';
    gaze: 'camera' | 'left' | 'right' | 'product';
    gesture: 'none' | 'open_palm' | 'emphasis' | 'point_left' | 'point_right'
      | 'count_one' | 'count_two' | 'count_three' | 'product_hold' | 'cta';
    motionClipId?: string;
  }>;
  scene: {
    mode: 'source' | 'chroma' | 'segmented';
    backgroundMaterialId?: string;
    camera: 'locked' | 'push_in' | 'pull_out' | 'pan_left' | 'pan_right';
  };
}
```

### 4.1 规划约束

- 每个短分镜最多一个主要手势和一个微表情，避免过度表演。
- 动作峰值对齐关键词、数字、转折或 CTA，不能说完后才做动作。
- 相邻数字人分镜不能重复同一动作片段。
- 同一动作在 15 秒内原则上不重复；动作不足时优先使用不同循环区间和不同运镜。
- 表情强度默认自然，房地产、B2B 等信任型场景不得使用夸张表演。
- 找不到可信动作时回退到自然讲解模板，不允许随机生成无关动作。
- 场景只能来自已授权的企业素材或平台场景模板；无法匹配时回退品牌安全默认棚景或人物原背景，不在 P0 凭空生成场景。
- `product_hold` 仅在源动作素材真实持有已授权同款商品时可选；商品替换和复杂手物交互不属于 P0。

### 4.2 房地产脚本示例

| 台词语义 | 表情 | 动作 | 场景/运镜 |
|---|---|---|---|
| “预算有限也别急” | 轻度关切 | 轻微摇头、开放手势 | 中景锁定 |
| “核心板块三大优势” | 自信、眉眼抬升 | 三点计数 | 地图叠层、缓慢推进 |

| “现在私信领取报价” | 轻微微笑 | 身体前倾、邀请手势 | CTA 卡片进入 |

## 5. 生成流水线

### 5.1 稳定模式（默认，8GB）

1. 校验人物、声音、动作片段和场景授权。
2. 按音频时间戳生成 `PerformancePlan`。
3. 在当前人物表演包内检索动作片段并检查相邻重复。
4. 选择安全进出点，执行有限时间伸缩和呼吸点切分。
5. 使用 MuseTalk 1.5 或 LatentSync 1.5 做片段级口型。
6. 对绿幕/分割人物执行背景替换、人物居中和虚拟运镜。
7. 在呼吸点或 B-roll 遮切点完成片段拼接。
8. 执行口型、身份、动作、手部、抠像、构图和音频质量门禁。
9. 失败时按回退矩阵自动纠偏，仅重新生成失败分镜。

### 5.2 增强模式（8GB 技术验证）

- 对缺少自然表情的片段，使用 LivePortrait motion template 或 Ditto 驱动眉眼、视线和轻微头姿。
- 表情/头姿驱动在口型生成之前完成，避免二次处理破坏嘴型。
- LivePortrait 不默认叠加在所有真人动作片上，只用于静态头像或表情不足片段。
- 商业上线前必须替换或取得默认 InsightFace 检测权重的商用授权。

### 5.3 生成式模式（高显存 Worker）

- 24GB 及以上 Worker 优先验证 EchoMimicV3 Flash 和 InfiniteTalk 的半身表现力；24GB 只是起测配置，不承诺达到生产速度或质量。
- 复杂全身动作、人物替换和商品交互在更高显存环境评估 Wan-Animate 类方案。
- 生成式模式必须通过同一任务协议和质量门禁；失败自动回退稳定模式。
- 不因模型升级改变前端交互和素材回流方式。

能力边界必须对产品和验收保持一致：阶段一按脚本切换不同的授权真人动作模板，不是凭空生成全新身体动作；阶段二才增加生成式眉眼和头姿；阶段三才验证复杂身体动作和手物交互。

### 5.4 多语种一次配置、逐语言独立生成

用户在任一分镜选择“数字人口播”并选择人物 IP 后，系统读取 AI 创作已经生成的全部目标语种版本，后台为每个语种分别生成数字人分镜和完整成片。用户只配置一次人物，不得要求逐语言重复选择。

当前已落地 `POST /studio/digital-human/job-batches` 作为分镜级原子扇出入口：一个请求包含同一 `storyboardSlotId` 的多个语言变体，所有变体完成统一前置校验后才用一次持久化替换发布新增任务。它解决的是“同一分镜多语言状态一致地进入队列”，不是把多个语言合并成一个视频任务；本地 Worker 仍按子任务串行处理，每种语言的音频、脚本、表演计划、输入签名和结果均独立保存。

各语种共享：

- 人物 IP、人物版本和授权快照；
- 分镜 ID、基础叙事结构和场景/构图意图；
- 钩子、卖点、证明、CTA 等表演语义；
- 当前人物可用的动作资产库。

各语种必须独立生成或重算：

- 本地化口播脚本与最终配音；
- 句级、词级时间戳和停顿；
- 动作触发时间、动作片段长度和安全切点；
- 数字人口型；
- 字幕内容、断行、字体回退和安全区；
- 分镜时长与最终成片。

禁止直接复用中文时间戳、仅替换音轨或对不同语言做明显音频/动作强拉伸。翻译导致时长变化时，系统应按目标语言重新选择合适长度的动作片段，调整 B-roll、自然停顿或切点。

推荐任务模型：

```ts

  sharedSnapshot: {

    storyboardStructureHash: string;
    performanceIntentVersion: string;

  variants: Array<{
    locale: string;
    localizedScriptHash: string;
    voiceId: string;
    voiceoverMaterialId: string;
    timingHash: string;
    shotJobs: DigitalHumanV2JobInput[];
    outputStatus: 'queued' | 'running' | 'review' | 'ready' | 'failed';
    outputMaterialId?: string;
  }>;
}
```

不同语言任务相互隔离：一个语言失败只能重试该语言的失败分镜，不能覆盖其他语言已通过的结果。页面仍使用现有多语种版本结构展示并下载中文、英文、西班牙语等独立 MP4，不新增一套数字人语言配置 UI。

### 6.4 已落地：Windows→WSL 中文 TTS 传输

`server/lib/localQwenTts.ts` 不再把中文口播明文直接放入 Windows→WSL 的命令行参数，而是按 UTF-8 编码后传入 `--text-base64`。`scripts/qwen3-tts-local.py` 使用严格 Base64 校验和 UTF-8 解码恢复文本，并保留 `--text` 兼容旧调用；异常编码 fail-closed，不进入模型推理。

轻量合同测试通过真实 `wsl.exe → python3` 边界传入中文，只核对字符数、UTF-8 字节数和 SHA-256，不打印原文。后续日志、错误详情和运维页面同样不得记录口播正文或可直接访问的带签名素材地址。

### 6.5 已落地：安全渲染与签名下载

渲染入口已采用“服务端重建清单 → 清单摘要签名 → 不可变快照渲染”的边界：

1. 浏览器只提交素材 ID 和剪辑意图，服务器按当前租户重新解析素材、配音、封面和 BGM；任意外部 URL、其他租户素材和本地路径不会直接进入 ffmpeg。
2. 授权令牌绑定任务 ID、租户、画幅、时长和 manifest SHA-256，并设置过期时间；本地渲染只接受保存过的不可变 manifest，忽略浏览器后续篡改的数据。
3. 素材通过同源、租户隔离且 `private, no-store` 的代理读取；对象存储凭据和本地文件路径不进入前端清单。
4. 成片文件名和路径均经过白名单及目录边界校验，下载接口返回租户签名 URL、`Content-Disposition: attachment` 和私有缓存策略。

以上说明安全边界已经落地，但不等于某个语言版本的视觉、口型或表演质量已经通过第 9 节验收。

## 7. 质量门禁与自动纠偏

### 7.1 硬门禁

- 输出为 9:16 H.264/AAC，可播放且音画时长一致。
- 口型同步、音画偏移、嘴部跳变和人脸检测通过现有模型校准阈值；多脸率只能作为双嘴风险代理，不能代替双嘴人工复核。
- 人物身份稳定，不出现脸型、发型、服装和肤色突变。
- 不出现黑帧、冻结、明显循环接缝和面部遮罩边缘。
- 绿幕无明显绿边、透明闪烁和人物脚底/身体漂浮。
- 授权状态不完整时禁止进入正式成片。
- 正式任务必须使用企业自有人物 IP，并且人物母片与所选动作同时覆盖本次 `usagePurpose`；`productionReady` 不能替代用途授权。
- 默认人物 `avatar-pexels-6548010-v1` 仅覆盖 `internal_preview`，不得进入客户交付、投放、社媒发布，也不得暗示真人代言。

### 7.2 表演有效性门禁

- 时长超过 3 秒的数字人分镜至少出现一次非嘴部有效变化。
- 15 秒验收片至少包含两个不同的语义表演事件，其中至少一个为手势，并包含一次明显表情变化。
- 脚本计划的语义事件必须命中；没有主要手势的长讲解段仍应保持自然眨眼、视线或头部微动，但不得为了过门禁强行增加动作。
- 相邻分镜不得重复同一动作片段。
- 语义动作应在对应关键词附近触发；初始允许窗口为 ±600ms，后续以标注集校准。
- 表情和头姿曲线不得持续高频抖动。
- 生成式片段出现手指、商品或遮挡异常时直接拒绝，不以综合分抵消硬错误。

身份、眨眼、动作幅度等模型分数必须使用验证集校准阈值，禁止把未经验证的固定分数直接当作商业标准。

### 7.3 成片实测证据与发布判定

完整 15 秒成片使用 `scripts/validate-digital-human-performance.py` 生成 `digital-human-performance-observation-v2` 报告。门禁遵循以下证据边界：

- 编排清单只提供语义段落和关键词时间锚点，不再把清单中的 `gesture`、`composition` 或 `actionPeakMs` 当成成片事实。
- 镜头/构图数来自最终视频帧的颜色直方图和结构变化；非嘴部运动与最长静止来自人物区域帧差、姿态和非嘴部面部关键点。
- 手势种类与相邻重复来自最终视频的肩、肘、腕和手指状态聚类；动作峰值先从实测运动曲线提取，再与清单中的关键词时间比较。
- 多脸率、人脸漏检率和对齐后 FaceMesh 几何离群率是身份稳定的可行代理，但几何代理不是人脸识别 embedding。
- 仅在任务明确使用绿幕/抠像时执行绿边检测；非绿幕成片必须输出 `not_applicable`，不得伪造 `false` 检测结果。
- 当前模型不能可靠排除第二张生成嘴和复杂手指畸形；这两项以及声音/人物匹配必须输出 `pending/approved/rejected` 人工结论。未审核时状态为 `requires_human_review`，不得标为发布通过。

机器报告必须包含 `gate_input`、采样覆盖率、阈值、指标来源、逐项检查、失败原因和人工复核原因。`passed=true` 只允许出现在自动门禁无失败且必需人工复核均为 `approved` 的情况下；自动项干净但人工复核未完成时只能是 `automated_passed=true`。

人工复核记录必须与 manifest 分开保存并包含明确决定，例如：

```json
{
  "reviewer": "qa-user-id",
  "reviewedAt": "2026-09-02T12:00:00Z",
  "doubleMouth": "approved",
  "complexHands": "approved",
  "voiceMatch": "approved"
}
```

CLI 使用 `--human-review <review.json>` 载入记录；不提供记录时三项均为 `pending`。`--chroma-key auto|yes|no` 用于声明绿边检测适用性，默认 `auto` 只读取明确的抠像声明，禁止依据画面里“看起来没有绿色”推断已经完成检测。
任何 `approved` 结论若缺少 `reviewer` 或 `reviewedAt`，门禁必须 fail-closed，不能用不可审计的布尔值解锁发布。

当前初始阈值为：15 秒容差 14.5–15.5 秒、人物区人脸覆盖率不低于 95%、姿态覆盖率不低于 35%、连续非嘴部静止不超过 4 秒、至少 2 个实测动作峰值、动作峰值相对关键词不超过 900ms、多脸率不超过 1%。上线前必须用标注回归集重新校准，不能把该初始值当作跨人物商业阈值。

### 7.4 自动纠偏顺序

1. 更换动作安全区间或生成随机种子；
2. 选择同一人物的另一条匹配动作片段；
3. 降低表情和动作强度；
4. 关闭表情生成，保留真实动作模板和口型；
5. 回退经过验证的自然讲解模板；
6. 仍不合格则标记需确认，禁止静默回退普通素材或返回劣质数字人。

## 8. 分阶段开发计划

以下为依赖顺序和里程碑划分；具体工期需在人物素材、许可证、模型和本机 benchmark 明确后估算，不作为上线日期承诺。

### 迭代 0：基线与测试集

目标：建立可重复对比的 V1 基线。

- 固定房地产 15 秒验收脚本、配音、人物和场景。
- 保存第一版口型闭环结果及完整质量报告。
- 建立人工评分表：自然度、语义贴合、感染力、身份、口型、手部、场景。
- 确认人物及声音仅用于内部测试或已获商业授权。

完成条件：相同输入能够重复生成 V1，并可与后续版本并排盲评。

### 迭代 1：人物表演包

目标：把单视频人物资产升级为可检索的动作集合。

- 新增人物身份与动作片段数据模型。
- 企业知识库支持多动作上传、人工标签和首选人物。
- 完成动作质量、进出姿态、绿幕和授权预检。
- 创作页继续只展示人物 IP，不暴露片段复杂度。

完成条件：一个人工精选、授权完整的人物至少具备 8 类可用动作，系统能稳定检索并预览每类片段。

### 迭代 2：脚本表演规划与动作编排

目标：让脚本真正决定表情、手势、场景和运镜。

- 生成版本化 `PerformancePlan`。
- 实现动作检索、去重复、节拍对齐、安全切点和有限时间伸缩。
- 扩展任务协议、幂等签名和 Worker 状态。
- 实现绿幕场景合成、人物保护区和虚拟运镜。

完成条件：同一人物对不同脚本能稳定选择不同动作；脚本、动作或场景变化会正确触发重做。

### 迭代 3：分镜级生成与表现力门禁

目标：交付第一条真正存在动作和表情变化的 V2 成片。

- 逐动作片段执行 MuseTalk/LatentSync 口型。
- 实现转场、B-roll 遮切和连续性控制。
- 增加身份、动作、表情、手部、绿幕和语义对齐检测。
- 实现自动纠偏及分镜级回退。
- 创作页增加极简生成状态和“调整表现”。

完成条件：房地产 15 秒验收片通过第 9 节全部标准。

### 迭代 4：人物表演包自动化

目标：减少企业构建人物资产的人工成本。

- 支持导入一条 60–90 秒标准录制视频。
- 自动完成镜头切分、动作候选、情绪/景别标签、循环区间和进出姿态分析。
- 人工确认后才写入正式表演包，不允许模型标签直接获得商用状态。
- 缓存绿幕抠像或人物分割结果并执行边缘质量预检。

完成条件：同一录制素材的自动候选覆盖人工基准动作，错误标签可以快速修正且不污染已发布表演包版本。

### 迭代 5：表情与头姿增强 A/B

目标：验证轻量模型能否在不损害身份和口型的前提下增加神态。

- 接入 LivePortrait motion template；并行评估 Ditto。
- 替换或核证所有非商业检测权重。
- 对自然讲解、微笑、疑问、强调和 CTA 建立驱动模板。
- 与纯真人动作模板版本进行盲评。

完成条件：增强版自然度和感染力显著提升，且身份、口型、抖动和失败率不劣于稳定模式；否则不进入默认生产链。

### 迭代 6：高显存生成式 Worker

目标：验证半身生成在复杂动作和场景上的增益。

- 24GB 以上本地 Worker A/B 测试 EchoMimicV3 Flash、InfiniteTalk。
- 评估速度、显存、长视频连续性、身份、手部和许可证。
- 接入 Worker 能力路由和失败回退。
- 不改变前端和服务器任务接口。

完成条件：在固定测试集上稳定超过动作模板方案后才允许灰度使用。

## 9. V2 首条成片验收标准

房地产 15 秒口播必须同时满足：

1. 至少三个清晰语义段落；
2. 至少两种不同的主要手势；
3. 至少一次明显且自然的非嘴部表情变化；
4. 至少两种场景、构图或运镜表现；
5. 相邻分镜不重复同一动作；
6. 长讲解段保持自然眨眼、视线或头部微动，不为追求频率强行增加手势；
7. 关键动作在对应语句附近触发；
8. 无双嘴、身份漂移、卡帧、抠像闪烁、手部或商品明显异常；
9. 人物居中、默认 9:16、字幕和 CTA 不遮挡脸部；
10. 口型、音色、人物年龄和性别匹配；
11. 人物、声音、动作、场景和商品授权完整；
12. 首条工程样片由至少 5 名独立评审与第一版盲评，至少 70% 更偏好 V2，且自然度、语义贴合和感染力均无明显短板。

任一硬门禁失败均不得以综合分通过。

首条样片只证明工程链路成立，不代表商业泛化。进入客户灰度前，还必须在至少两个授权人物、多个不同房地产/带货脚本组成的小型回归集上重复通过，报告逐项通过率、人工评分分布、自动回退率和最终失败率。

## 11. 测试要求

自动测试：

- 表演计划结构、版本和确定性；
- 动作标签匹配、去重复和缺失回退；
- 表现力报告必填字段、fail-closed、自动通过与人工复核状态分离；
- 合成帧 fixture 验证真实切镜、动作峰值、连续静止、姿态聚类和绿边检测，禁止从 manifest 复制视觉结论；
- 幂等签名随人物、脚本、动作、场景变化；
- Worker 能力路由、租约、重试和旧结果防覆盖；
- 人物与动作资产租户隔离；
- 授权不完整阻止正式生成和发布；
- 分镜级失败不污染其他分镜；
- 自动纠偏次数和最终结果可追踪。

视觉回归：

- 固定输入生成接触表和关键帧；
- 检查嘴部、眼睛、头姿、手势、绿幕边缘和切镜连续性；
- 保存模型、驱动模板、随机种子和质量报告，保证问题可复现。

人工审核：

- 人物身份和声音匹配；
- 表情是否自然；
- 动作是否符合语义且不过度；
- 手部、商品和遮挡关系；
- 场景、光线和运镜是否像完整广告，而非拼接演示。

商业回归集至少覆盖两个人物、多种语速、含数字/转折/CTA 的不同脚本和动作不足回退场景；首条样片的单次成功不能代替回归集结果。

多语种回归至少覆盖中文、英文、西班牙语。同一项目只选择一次人物后，必须得到三条独立 MP4；每条分别验证目标语言、配音、口型、字幕、动作时序、人物身份、场景构图、授权和旧结果隔离。不得通过复用中文口型或只替换音轨完成测试。

表现力门禁回归命令：`python scripts/validate-digital-human-performance.test.py` 验证确定性合成 fixture；`npx tsx server/lib/digitalHumanPerformanceQualityGate.test.ts` 验证服务端 fail-closed、必填字段和人工复核状态；真实成片仍须在数字人 WSL 模型环境中运行完整 CLI，单元测试不能替代实际 MP4 解码验收。

## 12. 风险与决策

| 风险 | 影响 | 应对 |
|---|---|---|
| 当前只有 8GB 显存 | 大型半身/全身模型无法稳定生产 | 默认动作模板模式；高显存模型走独立能力 Worker |
| 动作模板不足 | 重复、机械、语义不匹配 | 每人物至少 8 类动作；相邻去重；安全回退自然讲解 |
| 多片段拼接跳变 | 人物位置、手势和光线突变 | 统一录制标准、进出姿态特征、呼吸点/B-roll 遮切 |
| 表情增强损害身份 | 脸型和嘴型漂移 | 仅对缺失片段使用；先表情后口型；身份硬门禁 |
| 绿幕边缘异常 | 发丝绿边、漂浮和闪烁 | 预生成抠像缓存、边缘时序检测、必要时回退原背景 |
| 模型或依赖不可商用 | 无法商业发布 | SBOM、许可证白名单、替换非商业检测权重 |
| 过度表演 | 失去房地产/B2B可信度 | 默认 natural；每分镜一个主动作；限制强度和重复 |
| 旧任务覆盖新选择 | 用户换人物后结果错位 | 完整幂等签名、版本检查、回传前服务器复核 |

## 13. 技术选型原则与参考

- [MuseTalk](https://github.com/TMElyralab/MuseTalk)：继续作为稳定口型引擎；代码 MIT、官方说明模型可商用，但测试素材和第三方依赖需单独核证。
- [LatentSync 1.5](https://github.com/bytedance/LatentSync)：可在 8GB 做口型 A/B；1.6 官方要求更高显存。
- [LivePortrait](https://github.com/KlingAIResearch/LivePortrait)：适合表情和头姿模板；代码 MIT，但官方说明默认 InsightFace 模型非商业，必须替换或另行授权。
- [EchoMimicV3 Flash](https://github.com/antgroup/echomimic_v3)：官方要求约 12GB，可作为 24GB Worker 的半身生成候选。
- [InfiniteTalk](https://github.com/MeiGen-AI/InfiniteTalk)：适合后续验证音频驱动的视频续写和半身表现，不进入当前 8GB 主链。
- [Wan2.2 / Wan-Animate](https://github.com/Wan-Video/Wan2.2)：适合高显存环境的动作重演与人物替换，不作为当前桌面 Worker 默认模型。

所有候选模型在进入实现前必须固定到具体 commit、权重版本和许可证快照，并记录本机/目标 Worker 的速度、峰值显存、输出质量和第三方依赖 SBOM；README 中的显存与商用说明只用于候选筛选，不能直接视为上线承诺。

## 14. 开发启动顺序

正式开工时严格按以下顺序推进：

1. 固定 V1 对照样片和验收脚本；
2. 完成人物表演包数据模型与首个人物的 8 类授权动作；
3. 打通 `PerformancePlan → 动作检索 → Worker`，先不接任何新生成模型；
4. 生成第一条多动作房地产样片并补齐表现力门禁；
5. 稳定模式验收通过后再接 LivePortrait / Ditto A/B；
6. 只有在 24GB 以上 Worker 准备好后，才启动生成式半身模型验证。

第一条 V2 合格成片是 P0 的结束条件，不以“代码已完成”代替视频效果验收。

## 15. 页面调整规划

### 15.1 总体信息架构

不新增“数字人”侧栏入口，也不把数字人做成与现有创作流程割裂的独立工具。数字人是“人物口播分镜”的一种画面来源，人物资产由企业统一管理，生成任务在后台执行，最终结果继续进入现有预览、成片和发布链路。

本阶段页面影响范围如下：

| 页面/区域 | 调整级别 | 主要调整 | 明确不做 |
|---|---|---|---|
| 企业知识库 → 人物资产 | 大 | 从单视频列表升级为人物 IP 与人物表演包管理 | 不在创作页重复上传、授权和配置模型 |
| AI 智能创作 → 脚本与声音 | 小 | 显示各目标语言的配音与数字人生成就绪情况 | 不增加数字人模式、模型和动作参数 |
| AI 智能创作 → 成片制作 → 素材匹配 | 大 | 逐分镜选择素材画面或数字人口播，默认人物自动生成并可更换 | 不改左侧分镜卡，不增加授权勾选和人物视频上传 |
| AI 智能创作 → 预览/输出版本 | 中 | 按语言展示独立成片状态、预览、失败重试和下载 | 不新增数字人专属导出流程 |
| 我的创作 | 小 | 展示数字人、多语言和局部失败状态 | 不复制完整编辑器和资产管理能力 |
| 定时任务 → 运行队列（管理员） | 中 | 增加本地数字人 Worker、GPU、磁盘和任务队列状态 | 不向普通客户暴露机器、模型和运维参数 |
| 内容发布 | 极小 | 只接收已通过授权与质量门禁的语言版本 | 不改变现有发布编排和账号选择流程 |
| 质量评测、集成中心、灵感中心、脚本库 | 无 | 保持现状 | 不把数字人成片质检混入销售回复评测，不把本地 Worker 混入社媒集成 |

### 15.2 企业知识库：人物资产

“人物资产”仍是唯一的人物 IP 管理入口。列表卡片由“人物视频”升级为“人物 IP”，卡片至少显示：

- 人物名称、头像、启用状态和“首选人物”标记；
- 商业授权状态与有效期，不显示敏感合同正文；
- 表演包完整度，例如“8/8 类动作可用”；
- 支持语言和已绑定音色；
- 最近预检结果，以及是否允许正式生产。

点击人物卡片打开详情抽屉，不新建页面。抽屉分为“基础信息、表演素材、声音与语言、授权与预检”四个区块：

1. 基础信息管理人物名称、头像、默认构图、安全区和启停状态；
2. 表演素材支持批量上传或引导录制多个授权视频，并按自然讲解、微笑、点头、强调、指向、计数、转折和 CTA 分组；
3. 声音与语言显示已授权音色、支持语言和试听，不要求每个人物必须绑定唯一音色；
4. 授权与预检保存人物、声音和动作素材的授权快照，执行人脸、帧率、清晰度、构图、绿幕边缘和动作可用性预检。

只有“已启用、授权有效、预检通过”的人物才能出现在创作页人物选择器中。`internal_test`、授权过期或素材不完整的资产不得用于正式导出。设置首选人物只影响新项目；已有项目继续使用创建时保存的人物与表演包快照。

### 15.3 AI 智能创作：脚本与声音

保持现有步骤、脚本卡、分镜结构、语言切换和配音交互不变。只增加一个紧凑的语言就绪摘要，例如：

```text
中文  配音已就绪
English  配音已就绪
Español  等待生成
```

该区域不提前询问是否使用数字人。系统在后台为每个目标语言保存独立的 TTS、句词级时间戳和字幕数据，等用户在“素材匹配”选择数字人口播后再扇出数字人任务。某一语言的配音失败只阻止该语言，不影响其他语言继续创作。

### 15.4 AI 智能创作：成片制作与素材匹配

左侧现有分镜卡和中间画布不改。右侧当前分镜只保留一个必要决策：

```text
当前分镜画面来源

[ 素材画面 ]  [ 数字人口播 ]

人物：[头像] 云栖置业顾问 · 首选人物    更换
中文 已就绪  English 生成中  Español 等待本地算力
```

交互细则：

1. “自动匹配空分镜”始终可点击；普通素材不足时仍可尝试匹配，其可用性不能被数字人授权或 GPU 状态错误禁用。
2. 用户点击“数字人口播”后立即使用“分镜覆盖 > 项目人物 > 企业首选人物”的解析结果，并为当前分镜的全部目标语言创建独立任务。
3. 页面不出现上传人物视频、授权勾选、模型选择、口型引擎、绿幕参数或 GPU 配置。
4. “更换人物”打开企业人物资产选择器；选中后自动重做当前分镜的全部语言版本。选择器内提供二级操作“应用到全部数字人分镜”。
5. 后台自动规划语义段、动作、表情、场景、口型和字幕；正常只显示“生成中 / 已就绪”。等待超过阈值时显示“等待本地算力”，不能让用户误以为页面卡死。
6. 已生成结果支持“调整表现”，选项仅为“更自然 / 更有感染力 / 换一个动作”；提交后只重做当前人物、分镜和语言的受影响结果。
7. 失败时给出用户可执行的原因，例如“人物表演素材不足”“西班牙语配音失败”“本地算力离线”，并提供“重试 / 更换人物 / 改用素材画面”。
8. 用户切回“素材画面”后取消尚未开始的数字人任务，已完成结果保留为缓存但不参与正式成片。

“还需匹配 N 个分镜”和底部原有下一步按钮继续按最终有效画面来源计算，不另设数字人专属按钮。

### 15.5 预览与输出版本

复用现有语言版本和输出版本结构，每个语言版本独立显示：

- 数字人分镜完成数/总数；
- 配音、口型、字幕、动作和成片质量门禁状态；
- 生成中、已通过、待复核、失败等状态；
- 预览、仅重试失败语言、下载或进入发布。

项目顶部只显示聚合状态，例如“3 个语言版本：2 个已完成，1 个生成中”。中文完成后可立即预览或下载，不等待西班牙语；失败重试也不得覆盖已通过的其他语言结果。最终按钮仍沿用现有“生成成片”和发布动作，由后台等待或复用已经合格的数字人分镜。

### 15.6 我的创作

创作记录增加紧凑标签和进度，不新增新的数字人作品类型：

```text
数字人口播 · 3 个语言版本
2 个已完成 · 1 个待重试
人物：云栖置业顾问（任务快照）
```

用户可打开已有创作、预览已完成语言、下载结果或重试失败语言。列表必须允许“部分完成”，不能因为一个语言失败把整个项目显示为失败。历史项目显示任务创建时的人物快照，人物资产库后续改名、停用或更换首选人物不应篡改历史记录。

### 15.7 定时任务：管理员运行队列

在现有“定时任务”运行队列中增加管理员可见的“本地数字人算力”卡片，而不是污染社媒集成中心。卡片显示：

- Worker 在线/离线、最后心跳和能力版本；
- GPU 型号、显存占用、当前并发和排队任务数；
- D 盘剩余空间、临时文件水位和磁盘告警；
- 当前任务阶段、耗时、重试次数与最近失败原因；
- 暂停接单、恢复接单和仅重试失败任务等安全运维操作。

普通客户只看到“生成中 / 等待本地算力 / 失败”的业务状态，不得看到本地 IP、文件路径、显卡驱动、模型目录或其他租户任务。

### 15.8 内容发布与不调整页面

内容发布页仅增加发布前校验：当前语言 MP4 必须已完成，人物/声音/动作授权快照有效，且硬质量门禁通过。未通过时返回创作页对应语言和分镜，不在发布页修数字人。

以下区域保持不动：

- 侧栏导航和三步创作流程；
- 创作设置页；
- 左侧分镜卡、脚本正文编辑方式和普通素材卡；
- 灵感中心、脚本库、销售回复质量评测、试点看板；
- 社媒集成中心和账号授权流程。

数字人的自动质量报告放在成片版本详情和管理员任务详情中。现有“质量评测”服务于销售回复安全与准确性，产品语义不同，不合并入口。

### 15.9 页面状态与验收

页面必须覆盖以下状态：无可用人物、首选人物可用、人物授权过期、表演包不足、Worker 离线、任务排队、逐语言生成、部分语言完成、自动纠偏中、人工待复核、失败可重试和全部完成。

P0 页面验收标准：

1. 用户从脚本生成到逐分镜选择数字人，不需要理解任何模型或上传参数；
2. 首选人物自动应用，更换人物不超过两次点击；
3. 选择一次人物即可为中文、英文、西班牙语分别生成并查看独立状态；
4. 分镜卡、普通素材匹配、成片和发布主流程不发生结构性变化；
5. 一个语言或一个分镜失败时，其他合格结果可继续预览和下载；
6. 页面刷新、切换语言或重新进入项目后，人物快照和真实任务状态不丢失；
7. 普通用户界面不出现上传人物视频、授权勾选、GPU、模型、文件路径等内部细节；
8. 管理员能够在运行队列定位 Worker 离线、磁盘不足、模型失败和任务重试问题。

## 16. 当前版本页面改造清单与落地顺序

本节以 2026-09-02 本地最新版和真实用户点击结果为准。当前已经能够登录、进入 AI 创作、生成脚本并进入“脚本与声音”，但一次 15 秒中文房地产测试实际生成约 25.4 秒，且部分分镜混入英文兜底句。这说明“页面能前进”不等于生产链路合格：脚本时长、目标语言、配音、数字人任务和最终成片必须使用同一份版本化数据，且每一步都要有阻断错误结果的门禁。

### 16.1 页面范围总表

| 页面 | 优先级 | 当前状态 | 本版本必须调整 | 页面验收结果 |

| 定时任务 → 本地数字人算力 | P0（管理员） | 本地 Worker 可运行，但网页缺少完整可观测性 | 增加在线状态、心跳、能力版本、GPU/磁盘、队列、任务阶段、重试和暂停接单 | Worker 离线、磁盘不足或模型失败能在管理员页面定位；普通客户看不到本地敏感信息 |

### 16.2 明确不调整的页面和结构

- 不新增独立“数字人”侧栏入口；数字人继续作为人物口播分镜的一种画面来源。
- 不改变左侧分镜卡、中间画布、三步创作流程和普通素材匹配方式。
- 灵感中心、脚本库、销售回复质量评测、试点看板、账号管理和社媒集成不承载数字人配置。
- 创作设置页不提前询问“真人实拍/数字人”，避免用户在脚本尚未生成时做无依据选择。
- 创作页不再上传人物视频，不显示授权勾选、GPU、模型、绿幕或本地路径；这些只属于企业资产管理或管理员运维。

### 16.3 P0 开发顺序

1. 先修“创作设置 → 脚本与声音”的时长与语言一致性，保证 15 秒中文不会生成 25 秒或混入英文兜底句。
2. 完成人物资产生产可用性判定：母片、动作片段、授权和预检必须形成一个不可变人物版本快照。
3. 完成素材匹配页逐分镜数字人选择、首选人物自动应用、人物更换和逐语言任务扇出。
4. 打通服务器任务、远端队列和本地 GPU Worker 的心跳、领取、断点重试、结果回传与二次质量门禁。
5. 完成逐语言成片组装和输出状态，真实点击生成中文、英文、西班牙语三条完整 MP4。
6. 最后补齐管理员运行队列，并以浏览器刷新、断网恢复、Worker 重启和磁盘告警进行异常验收。

### 16.4 页面级完成定义

页面改造不能以“按钮已经显示”作为完成标准。只有以下四层同时通过，才允许将对应页面标记为完成：

1. 交互层：普通用户无需理解模型参数，操作路径符合第 2 节约定；
2. 数据层：刷新和重新登录后，人物、语言、分镜与任务状态均从服务器恢复；
3. 生产层：页面显示的状态来自真实本地 GPU 任务，而非前端模拟或固定提示；
4. 结果层：输出文件经过授权、口型、身份、动作、手部、绿幕、音频、字幕和 9:16 门禁，并能在现有成片/发布链路继续使用。
